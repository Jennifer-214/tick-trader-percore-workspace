## Problem statement

`/parity-check` 2026-05-09 HIGH-2 + MEDIUM-1:

> v5.14.0 adds 5 Ridge cfg fields parsed + stored in ControllerConfig,
> used at StrategyParameters:928-930, but NOT added to
> StampInferenceCfgInputs — operator can train with ridge_lambda=0.15
> and infer with ridge_lambda=0.25, diverging silently.

> v5.14.1.B adds 5 composite-cfg fields but does NOT add them to stamp
> body — operator can change freshness_tau_secs, capacity_target_dollars,
> rmse_baseline between training and inference without detection.

Pattern matches v5.9.5b production-caller field-population gap class.
Both Ridge and composite cfg fields are inference-affecting (they
change prediction-to-decision math) but they sneak past the stamp-body
parity protection v5.9.2b established for the original 9 inference cfg
fields.

## Design

**Pattern (Surface G stamp body extension):**

1. Extend `StampInferenceCfgInputs` struct with 12 new fields
2. Update in-process `stamp_write_for_model` emit code to populate all
   12 fields (using `has_*=1` when cfg is non-default, else `has_*=0`)
3. Update `verify_model_stamp` to parse 12 new fields with `has_*=0`
   forward-compat default
4. Mirror in `tools/stamp_model.sh` (bash CLI) so external stamps
   produce bytewise-identical canonical body
5. Add verifier check: when `has_*=1`, compare stamp value vs current
   cfg; WARN on drift via `ModelStampResult` struct (`r.valid=0` +
   `r.reason[]` per v5.9.2b pattern; 3-tier strict mode: 0=warn,
   1=refuse, -1=skip — note: actual cfg values per
   `cfg.held_out_gate_strict` at ControllerConfig.hpp:605)
6. Add tests: round-trip stamp emit → verify → drift detection

**Surface G discipline (per CLAUDE.md item 15):**
- `MODEL_FORMAT_VERSION` UNCHANGED (stays 6 — last bumped v5.10.0)
- Legacy stamps (without these fields) load fine — verifier defaults
  `has_*=0`, skips drift check
- New stamps (post-v5.14.1.B.3) populate all 12 fields; verifier checks
  on load
- No NEW retrain required; new stamps overwrite at next train cycle

**Bundling rationale:** PARITY-004 (Ridge) + PARITY-005 (composite) are
the same class of fix (Surface G stamp body extension) and touch the
same files. Bundling = ONE plan, ONE ship, ONE round-trip test pass.
Splitting would double the surface area review.

### Step 3 — Update verify_model_stamp parser

Add 12 fields to forward-compat parser. Default `has_*=0` for legacy

### Step 4 — Add drift verifier checks

Following the v5.9.2b pattern, add per-field checks when `has_*=1`.
**Use `ModelStampResult` struct (NOT a return-code constant)** —
`verify_model_stamp` returns `ModelStampResult` (defined at
`ML_Headers/ModelInference.hpp:1174`). Refusal pattern:

```cpp
struct ModelStampResult { int valid; char reason[256]; ... };
```

Refusal: `r.valid = 0; snprintf(r.reason, sizeof(r.reason), ...);`

Per-field check pattern:

```cpp
if (stamp_body.has_ridge_params) {
    if (stamp_body.ridge_lambda != cfg.ridge_lambda) {
        // 3-tier behavior per cfg.held_out_gate_strict:
        //   0 = WARN (default; logs + continues)
        //   1 = refuse load (sets r.valid=0 + r.reason[])
        //  -1 = skip (no warn, no refuse — operator suppression)
        if (cfg.held_out_gate_strict == 1) {
            r.valid = 0;
            snprintf(r.reason, sizeof(r.reason),
                "ridge_lambda mismatch: stamp=%.6g cfg=%.6g",
                stamp_body.ridge_lambda, cfg.ridge_lambda);
            return r;
        } else if (cfg.held_out_gate_strict == 0) {
            fprintf(stderr, "[stamp] WARN ridge_lambda drift: stamp=%.6g cfg=%.6g\n",
                    stamp_body.ridge_lambda, cfg.ridge_lambda);
        }
        // -1 = silent skip
    }
    // ... 4 more Ridge fields ...
}
// ... same shape for composite ...
```

Total: 10 new drift checks (5 Ridge + 5 composite).

Plan-trace-deps 2026-05-09 caught initial draft using non-existent
`STAMP_VERIFY_REFUSED` constant; corrected to `ModelStampResult`
struct pattern above.
