## Why this ship exists

Caramel's original design intent for `bandit_algorithm` was a 4-5 state enum supporting **ghost training** — one algorithm operational (drives arm selection), the other shadow-learning (updates posterior/weights from same rewards without driving decisions). This is a research-grade pattern that allows A/B comparison without putting test capital at risk on the experimental arm.

The architecture for ghost training was BUILT (always-init'd `thompson_bandits[]` at `CoreModelZoo.hpp:1134` — the comment "safe to leave at zero in that mode" is exactly the shadow-state-waiting-to-be-activated scaffolding). What's missing:

### Finding #1 — Thompson reward-update loop NEVER FIRES in production

`Thompson_Update` (defined at `ML_Headers/ThompsonBandit.hpp:183`, fully tested at `tests/controller_test.cpp:23056-23574`) is **never called from any production code path**. The reward attribution sites:

| Site | File:line | Today's behavior |
|---|---|---|
| Slow-path lookback reward (buy-side) | `CoreModelZoo.hpp:1341` | Only `Bandit_Update(&ezoo->bandits[regime], ...)` |
| Trade-close reward (buy-side) | `CoreModelZoo.hpp:1402` | Only `Bandit_Update` |
| Exit-side reward attribution | `ControllerEventLoop.hpp:1731` | Only `Bandit_Update(&ezoo->exit_bandits[regime], ...)` |

In `cfg=1 THOMPSON` mode, `thompson_bandits[]` is READ for arm selection (via `BanditAlgo_Thompson_Apply` at `BanditAlgorithmRegistry.hpp:121`) but never updated by realized rewards. Thompson posteriors stay frozen at prior values forever. The mode is effectively-broken — the bandit picks arms based on the initial prior with no learning.

In `cfg=2 BOTH` mode, Thompson logs `chosen_arm` for telemetry (per `StrategyParameters.hpp:962-966`) but the underlying state is still frozen.

This is the exact same recurring class the `/ml-audit` cfg↔ML surface audit caught — capability exists in code but a critical wire is missing. Class 24 codification at `.F.4c.1` will document this pattern; this ship closes the specific instance.

### Finding #2 — Current 3-state enum doesn't express ghost-training semantics

Current `FOREACH_BANDIT_ALGORITHM` at `BanditAlgorithmRegistry.hpp:87-90`:

```cpp
X(EXP3,     0, BanditAlgo_Exp3_Apply,     "Exp3-IX (default; bytewise-identical to pre-v5.14.10)")
X(THOMPSON, 1, BanditAlgo_Thompson_Apply, "Bayesian Thompson sampling; non-stationary-friendly")
X(BOTH,     2, BanditAlgo_Both_Apply,     "Run both for parallel-training A/B telemetry (cfg=2)")
```

Mapped against Caramel's intended design:

| Operator intent | Current state | Mapping |
|---|---|---|
| 0: Exp3 op only, no Thompson | 0 (EXP3) | ✓ exact match (Thompson state frozen → effectively no-Thompson) |
| 1: Exp3 op, Thompson ghost-training | (none) | gap — current 2 (BOTH) only logs Thompson chosen_arm; doesn't update posterior |
| 2: Thompson op only, no Exp3 ghost | 1 (THOMPSON) but broken | partial — Thompson drives but doesn't learn (no reward update) |
| 3: Thompson op, Exp3 ghost-training | (none) | gap — Exp3 currently updates in all modes (so it IS shadow-learning), just no mode where Thompson drives + Exp3 shadow is explicit |
| 4: Both blended output (experimental) | (none) | gap — current BOTH is A/B telemetry, not blended weights |

Bytewise back-compat preserved: legacy `cfg=0` keeps current EXP3 semantics exactly.

### D. Per-state dispatch matrix (the critical correctness work)

Update reward attribution sites at `CoreModelZoo.hpp:1341/1402` + (option B) `ControllerEventLoop.hpp:1731`:

```cpp
// Pseudocode at reward attribution sites
const int algo = config->bandit_algorithm;

// EXP3 update — fires in states 0, 1, 3 (EXP3 operational OR Exp3 shadow)
//                does NOT fire in state 2 (Thompson only, Exp3 frozen)
// Branchless mask: bit set means "Exp3 updates this state"
constexpr uint8_t EXP3_UPDATE_MASK = (1<<0) | (1<<1) | (1<<3) | (1<<4);
const bool exp3_updates = (EXP3_UPDATE_MASK >> algo) & 1u;
if (exp3_updates) Bandit_Update(&ezoo->bandits[regime], a, reward_bps);

// THOMPSON update — fires in states 1, 2, 3, 4 (Thompson operational OR Thompson shadow)
//                   does NOT fire in state 0 (EXP3 only, Thompson frozen)
constexpr uint8_t THOMPSON_UPDATE_MASK = (1<<1) | (1<<2) | (1<<3) | (1<<4);
const bool thompson_updates = (THOMPSON_UPDATE_MASK >> algo) & 1u;
if (thompson_updates && BITMAP_IS_SET(ezoo->init_flags, MASK_EZOO_THOMPSON_READY)) {
    Thompson_Update(&ezoo->thompson_bandits[regime], a, reward_bps);
}
```

Masks codify the dispatch matrix at compile time. State 0 preserves bytewise-pre-v5.14.10 EXP3-only behavior. State 1 (the new ghost-training "Exp3 op + Thompson shadow") adds Thompson update without disturbing arm selection. State 4 (BLENDED) updates both.

Slow-path cost: ~2-3ns added per reward attribution event when Thompson updates fire (a single posterior update). Reward attribution is sparse (per trade close + per slow-path lookback rewarded record), not per-tick — negligible total budget impact.

### E. `BanditAlgo_Blended_Apply` (new state-4 dispatch FN)

```cpp
static inline void BanditAlgo_Blended_Apply(BanditState* exp3,
                                              ThompsonBanditState* thompson,
                                              int n_arms,
                                              double* weights_out,
                                              int* chosen_arm_out) {
    // Compute Exp3 weights (probabilities)
    double exp3_w[ENSEMBLE_HORIZON_MAX];
    Bandit_GetProbabilities(exp3, exp3_w);
    
    // Compute Thompson softmax-of-posteriors (continuous weights instead of one-hot argmax)
    double thompson_w[ENSEMBLE_HORIZON_MAX];
    Thompson_GetSoftmaxWeights(thompson, n_arms, thompson_w);  // NEW — see below
    
    // Blend: weights = (1-α) * exp3 + α * thompson
    // α from cfg.bandit_blend_alpha (defaults 0.5)
    double alpha = /* read from cfg at slow-path snapshot time */;
    for (int a = 0; a < n_arms; ++a) {
        weights_out[a] = (1.0 - alpha) * exp3_w[a] + alpha * thompson_w[a];
    }
    
    // Renormalize (defensive)
    double sum = 0.0;
    for (int a = 0; a < n_arms; ++a) sum += weights_out[a];
    if (sum > 0.0) for (int a = 0; a < n_arms; ++a) weights_out[a] /= sum;
    
    // chosen_arm = argmax for telemetry (matches Exp3/Thompson convention)
    int best = 0; double bestw = weights_out[0];
    for (int a = 1; a < n_arms; ++a) if (weights_out[a] > bestw) { best = a; bestw = weights_out[a]; }
    *chosen_arm_out = best;
}
```

Requires NEW helper `Thompson_GetSoftmaxWeights` in `ML_Headers/ThompsonBandit.hpp` — converts posteriors to continuous weights via softmax(posterior_mean / temperature). Temperature defaults 1.0; could be a separate cfg knob if blend instability emerges in paper-test.

## Step 1 — Foundation primitives

### 1.A — `Thompson_GetSoftmaxWeights` helper in `ML_Headers/ThompsonBandit.hpp`

Adds posterior → continuous-weight conversion needed by state 4 (BLENDED). Pattern: softmax(posterior_mean / temperature) over arms, normalized to sum to 1.0. Temperature constant 1.0 initially; cfg knob deferred to follow-up if blend instability observed.

### 1.B — `bandit_dispatch_mask.hpp` (constexpr dispatch matrix)

Single source of truth for "which state updates which algo." Used at all reward-attribution sites; closes Class 18 mirror.

```cpp
#pragma once
#include "BanditAlgorithmRegistry.hpp"

// EXP3 update fires in states 0, 1, 3, 4 (states where Exp3 either drives or shadows).
// THOMPSON update fires in states 1, 2, 3, 4 (states where Thompson either drives or shadows).
constexpr uint8_t BANDIT_EXP3_UPDATE_MASK     = (1u<<0) | (1u<<1) | (1u<<3) | (1u<<4);
constexpr uint8_t BANDIT_THOMPSON_UPDATE_MASK = (1u<<1) | (1u<<2) | (1u<<3) | (1u<<4);

static_assert(FOREACH_BANDIT_ALGORITHM_COUNT == 5,
    "bandit_dispatch_mask.hpp masks assume 5 states; update on enum expansion");

static inline bool bandit_exp3_updates_in_state(int algo) {
    return (algo >= 0 && algo < FOREACH_BANDIT_ALGORITHM_COUNT)
        && ((BANDIT_EXP3_UPDATE_MASK >> algo) & 1u);
}

static inline bool bandit_thompson_updates_in_state(int algo) {
    return (algo >= 0 && algo < FOREACH_BANDIT_ALGORITHM_COUNT)
        && ((BANDIT_THOMPSON_UPDATE_MASK >> algo) & 1u);
}
```

## If something goes wrong

- **Thompson posteriors NaN/Inf in production:** check `Thompson_Update`'s precision-update formula against reward magnitude; clamp reward_bps to [-1e4, 1e4] before passing to Thompson_Update if extreme rewards observed (defensive)
- **Determinism regression:** verify `thompson_rng_seed` is read at slow-path snapshot time + bypassed correctly in state 0 (where Thompson_Update doesn't fire); rng_seed change shouldn't affect bytewise-identical state-0 output
- **Legacy stamp refusal:** if drift check rejects legacy `bandit_algorithm=2` stamps because new value 2 = THOMPSON instead of BOTH, audit the value-mapping carefully. **The plan keeps value 2 = THOMPSON intentionally** (matching Caramel's intent semantics: "Thompson only, no Exp3 ghost"); legacy stamps with `bandit_algorithm=2` had meant "BOTH" which now corresponds to `bandit_algorithm=1` (Exp3 op + Thompson ghost). Alternative: keep value 2 = BOTH = (legacy alias for) state 1 EXP3_OP_THOMPSON_GHOST. **Decide at audit gate.**
- **Blended state instability:** state 4 may produce degenerate weights when Thompson posteriors are very tight (low variance → softmax peaks at one arm). If observed, add a temperature parameter (`bandit_blend_temperature` cfg) to soften the Thompson softmax.

## Amendment 2026-05-14 — Per-core override + metadata-driven dispatch (operator directive)

Caramel's post-draft direction:

> "both meant blended output as experimental, its not hugely important right now, what is important is getting this setup so something like that is easy to add in the future, and that this is extensible per engine core, so each core could run something different. like these should be per engine core settings, not global"

Two design upgrades land in this ship as a result. Both align with the framework discipline meta-principle (CLAUDE.md item 31) — invest upfront so future state-row additions become 1-row mechanical changes, and per-core asymmetry becomes a first-class operator surface.

### Upgrade 1 — Per-core `bandit_algorithm` override (closes per-core asymmetry gap)

Each core gets its own bandit_algorithm choice. Use case Caramel named: core 0 runs Exp3 + Thompson ghost (state 1, conservative research), core 1 runs pure Thompson (state 2, validation), core 2 runs blended (state 4, experimental). Different cores can hold different positions in the research/prod risk spectrum simultaneously.

**Cfg surface:**

```
core_0_bandit_algorithm=1     # Exp3 op + Thompson ghost
core_1_bandit_algorithm=2     # Thompson only
core_2_bandit_algorithm=4     # Blended experimental
# core_3 omitted → inherits global cfg.bandit_algorithm
```

**Storage challenge:** the existing PerCoreOverrides convention is "0 = inherit" for INT-typed overrides (`ControllerConfig.hpp:258`). For `bandit_algorithm`, 0 IS a valid value (EXP3). Two pattern options to resolve:

| Option | Shape | Trade-off |
|---|---|---|
| (a) Sentinel value | Reserve `BANDIT_ALGO_INHERIT = 255` (or -1); per-core field uses sentinel for "inherit" | Simple; back-compat-safe; eats one enum slot (256 → 255 max future states; non-issue at 5 today) |
| (b) Override-set bit alongside value (recommended) | `core_overrides[i].bandit_algorithm_override` (storage) + bit in `core_overrides[i].scalar_override_set` (presence flag) | Generalizes to ANY scalar INT/INT_ENUM cfg field needing per-core override; reusable framework primitive |

**Pick (b)** for framework discipline. Add a new X-macro `PER_CORE_OVERRIDE_SCALAR_DOMAINS` (sister to `PER_CORE_OVERRIDE_BITMAP_DOMAINS` at `ControllerConfig.hpp:247`):

```cpp
// PER_CORE_OVERRIDE_SCALAR_DOMAINS — sister to bitmap variant for INT/INT_ENUM scalar overrides.
// Each row generates: value field + has_override bit (in a shared override_presence bitmap) +
// parser auto-flow + resolver auto-flow.
#define PER_CORE_OVERRIDE_SCALAR_DOMAINS(X) \
    X(bandit_algorithm,   int, BANDIT_ALGO_EXP3)
// Future rows:
//   X(strategy_id,        int, STRATEGY_AUTO)
//   X(some_other_enum,    int, SOME_DEFAULT)
```

The macro generates:
- `core_overrides[i].bandit_algorithm_override` field
- Bit in `core_overrides[i].scalar_override_presence` bitmap
- `_PARSE_OV_SCALAR_DOMAIN` parser auto-flow (matches `core_<N>_<name>=` keys)
- `_RESOLVE_OV_SCALAR_DOMAIN` resolver auto-flow (`resolved = presence_bit ? override_value : global`)
- Settings panel per-core tab row generator (TBD — depends on `.F.4c.1` polish ship)

**Resolver semantics** (matches existing bitmap variant at `ControllerConfig.hpp:1287-1298`):

```cpp
// Pseudocode in ControllerConfig_ResolveForCore (replaces direct cfg.bandit_algorithm read at slow-path sites):
int resolved_bandit_algo = global.bandit_algorithm;  // default to global
const auto& ov = global.core_overrides[core_id];
if (ov.scalar_override_presence & MASK_SCALAR_OV_bandit_algorithm) {
    resolved_bandit_algo = ov.bandit_algorithm_override;
}
// Slow path uses resolved_bandit_algo; hot path reads from cached params (already per-core via existing seqlock).
```

The resolved value lands in the per-core cached params (already wired for hot-path read at `GateParameters.hpp`). NO hot-path change — the resolution happens at slow-path rebuild + writes through the existing parameter seqlock.

### Upgrade 2 — Metadata-driven dispatch matrix (closes extensibility gap)

The original plan's `BANDIT_EXP3_UPDATE_MASK` + `BANDIT_THOMPSON_UPDATE_MASK` hardcoded constants are a Class 18 mirror in waiting — every new state added must update BOTH the enum row AND the mask constants. Operator directive: "easy to add in the future" → upgrade to **per-state metadata in the X-macro row itself**.

**Upgraded `FOREACH_BANDIT_ALGORITHM` shape:**

```cpp
// Per-state metadata columns: which posteriors update (exp3_up, thompson_up) +
// which array drives arm selection (drives = "EXP3" / "THOMPSON" / "BLENDED").
// Adding a new state = 1 row; masks auto-compute via X-macro reductions.
#define FOREACH_BANDIT_ALGORITHM(X) \
    /*  name                       value  apply_fn                      exp3_up  thompson_up  drives    doc */                            \
    X(  EXP3,                      0,    BanditAlgo_Exp3_Apply,         1,       0,           EXP3,     "Exp3-IX op only; Thompson frozen at prior")             \
    X(  EXP3_OP_THOMPSON_GHOST,    1,    BanditAlgo_Exp3_Apply,         1,       1,           EXP3,     "Exp3 op; Thompson posteriors shadow-update")            \
    X(  THOMPSON,                  2,    BanditAlgo_Thompson_Apply,     0,       1,           THOMPSON, "Thompson op only; Exp3 weights frozen")                 \
    X(  THOMPSON_OP_EXP3_GHOST,    3,    BanditAlgo_Thompson_Apply,     1,       1,           THOMPSON, "Thompson op; Exp3 weights shadow-update")               \
    X(  BLENDED,                   4,    BanditAlgo_Blended_Apply,      1,       1,           BLENDED,  "Exp3 + Thompson contribute jointly (experimental)")
```

**Auto-computed masks via X-macro reduction:**

```cpp
// Per-state update masks — auto-computed from the metadata columns.
// Adding a 6th state = 1 row → masks update automatically.

#define _BANDIT_EXP3_MASK_BIT(name, val, fn, exp3_up, thompson_up, drives, doc) \
    | (((uint8_t)exp3_up) << val)
constexpr uint8_t BANDIT_EXP3_UPDATE_MASK = (uint8_t)0 FOREACH_BANDIT_ALGORITHM(_BANDIT_EXP3_MASK_BIT);
#undef _BANDIT_EXP3_MASK_BIT

#define _BANDIT_THOMPSON_MASK_BIT(name, val, fn, exp3_up, thompson_up, drives, doc) \
    | (((uint8_t)thompson_up) << val)
constexpr uint8_t BANDIT_THOMPSON_UPDATE_MASK = (uint8_t)0 FOREACH_BANDIT_ALGORITHM(_BANDIT_THOMPSON_MASK_BIT);
#undef _BANDIT_THOMPSON_MASK_BIT

// Compile-time sanity: at least one update must fire per state (no dead states).
#define _BANDIT_STATE_UPDATE_OR(name, val, fn, exp3_up, thompson_up, drives, doc) \
    static_assert((exp3_up) || (thompson_up), \
        "BANDIT_ALGORITHM state " #name " updates neither Exp3 nor Thompson — would be a dead state");
FOREACH_BANDIT_ALGORITHM(_BANDIT_STATE_UPDATE_OR)
#undef _BANDIT_STATE_UPDATE_OR
```

Adding a hypothetical state 5 (e.g., `EXP3_DRIVES_BOTH_GHOST_TRAINED_AGAINST_DIFFERENT_REWARD_SIGNAL`) becomes literally one row added to `FOREACH_BANDIT_ALGORITHM` with appropriate metadata. The masks recompute. The dispatch sites (`bandit_exp3_updates_in_state` + `bandit_thompson_updates_in_state` helpers) work unchanged. The static_assert catches dead states. Class 18 mirror closed structurally.

**Selector dispatch via metadata:** the `drives` column is informational today (the `apply_fn` already encodes which posterior drives arm selection). It becomes useful when future states need finer dispatch (e.g., a state that drives via Thompson but renormalizes via Exp3 confidence — possible future research mode).
