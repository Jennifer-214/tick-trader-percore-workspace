## CRITICAL findings (convergent across 3+ audits OR ship-blocking design errors)

### CRITICAL-1 — STAMP_BOUND derived filter cutover is its own ship (5/5 audits raise)

**Sources:** `/parity-check` CRITICAL-1 + CRITICAL-2 (most concrete); `/trace-deps` GAP-A + GAP-E; `/readiness` HIGH-1 + HIGH-2; `/merge-scan` F2 + F3; `/dod-audit` Class 21.

**The structural problems** (cumulative):

1. **Preprocessor cannot filter X-macro rows by metadata bit value at expansion time.** Plan's `FOREACH_STAMP_BOUND_CFG_DERIVED(X)` is preprocessor-infeasible as written. Workable shapes: (a) runtime walk over `g_cfg_field_descriptors[]` filtering on `(metadata_flags & STAMP_BOUND) != 0`, (b) per-row STAMP_YES/NO Y3 dispatch token column, (c) PRE/POST split per CLAUDE.md item 22. Each option changes the descriptor schema or adds runtime cost. Plan picks none.

2. **Only 1 of 24 legacy STAMP_BOUND rows (`ml_buy_threshold`) is currently in FOREACH_CFG_FIELD.** Derived filter at .F.4c would return 1 entry, breaking the HMAC chain immediately.

3. **The 23 missing rows decompose as:**
   - **11 FPN<F> doubles** not migrated at .F.4b (ridge_lambda, ridge_cost_penalty, ridge_min_ic_floor, confidence_freshness_tau_secs, confidence_capacity_target_dollars, confidence_capacity_kappa, confidence_rmse_baseline, winsor_pct_low/_high, risk_full_size_threshold, risk_min_size_threshold) — cohort partners of the ints
   - **3 ints migration-eligible** (`risk_degradation_curve`, `bandit_algorithm`, `trading_mode`)
   - **4 bitmap-resident bools** in `cfg.ml_cfg_flags` (`ridge_within_horizon`, `ridge_across_horizons`, `confidence_composite_enabled`, `exit_blender_mode`) — plan's Step 2 anti-pattern says EXCLUDE these from registry, but derived filter still needs to see them in stamp body
   - **5 other rows** (counted differently by different audits — needs verification)

4. **12+ consumer sites for FOREACH_STAMP_BOUND_CFG across 10 files** (per /trace-deps enumeration): drift check (CoreModelZoo.hpp:242), struct gen (ModelInference.hpp:1198/1642/1787), parser (:1400), auto-populate (StampBoundCfgRegistry.hpp:223-250), helper (StampHelper.hpp:150), count tests (controller_test.cpp:23321-23351), CfgDriftCheckRegistry.hpp:190. Cutover touches all of them.

5. **Layer 5b hash lock methodology absent.** Predecessor `.F.4b` synthesis HIGH-3 explicitly DEFERRED Layer 5b to `.F.4c` so int rows could lock something meaningful. Plan body has no procedural spec for the fixture / compute site / `LOCKED_STAMP_BOUND_DERIVED_HASH_V5_15_5_F4` constant storage / regeneration policy.

6. **No committed v5.14-era stamp fixture** for round-trip HMAC regression test (live model stamps exist at `models/classification/*/barrier.json.stamp` but not anchored in `tests/`).

7. **HMAC wire-format byte preservation at risk.** `FOREACH_STAMP_BOUND_CFG` is the current single-source-of-truth for stamp body emit order; reshuffling via metadata-bit-filtered walk changes byte order → HMAC chain breaks for ALL existing stamps.

**Convergent recommendation across audits:** defer STAMP_BOUND derived filter to **`.F.4d`** (or a new sibling `.F.4c.5` or `.F.4i`). The non-STAMP_BOUND INT/INT_ENUM/BOOL migration is genuinely mechanical and can ship at `.F.4c` as a clean ~150-200 LOC structural sub-ship.

### CRITICAL-4 — INT_ENUM string-token parsing is a behavior regression (2 audits)

**Sources:** `/trace-deps` GAP-D; `/dod-audit` blocking gap.

Legacy parser at `ControllerConfig.hpp:2048-2074` (and 4+ similar sites) accepts **operator-friendly token strings** like `bandit_algorithm=THOMPSON`, `barrier_blend_mode=BLEND`, `risk_degradation_curve=LINEAR`, `engine_arch=per_core_slow` — uses `BanditAlgorithm_FromString` / `BarrierBlendMode_FromString` / `DegradationCurve_FromString` + warns on invalid.

**Registry's `atoi(val)` strips this** → operator's `bandit_algorithm=THOMPSON` parses as 0 (Exp3-IX), silently changing behavior.

**Fix options:**
- (a) Add `from_string_fn` function-pointer column to descriptor — **BLOCKED: schema LOCKED at .F.4b**.
- (b) Pre-check `val` against `desc.payload.as_int_enum.labels[]` linearly before atoi; fall to atoi if no match. ~10 LOC in `tt::cfg_parse_field` INT_ENUM branch. **Recommended.**
- (c) Exclude these specific fields from registry migration (defer to .F.4d when string parsing infrastructure exists).
- (d) Force operator to type integers — operator-UX regression (per § 10 Operator UX family).

## HIGH findings (should resolve before coding)

### HIGH-1 — KIND_INT_ENUM clamp must read `as_int_enum.count`, not `as_int.clamp_*`

**Sources:** `/trace-deps` GAP-C.

Shipped `tt::cfg_parse_field` integer branch uses `as_int.clamp_min/max`. INT_ENUM rows would also clamp via `as_int.clamp_min/max` if those are set per-row to `[0, count-1]` — workable. But `desc.payload` is a union; INT_ENUM rows write `as_int_enum.count/labels/default_val`, NOT `as_int.clamp_*`. Reading the wrong union member is UB.

**Fix:** add `if (desc.kind == KIND_INT_ENUM) { clamp to [0, desc.payload.as_int_enum.count); fall to default_val on out-of-range }` branch inside the integer path. ~5 LOC.

### HIGH-2 — Cohort discipline: 11 FPN<F> doubles must migrate alongside the STAMP_BOUND ints

**Sources:** `/merge-scan` F3.

Per CLAUDE.local.md 2026-05-11 cohort rule: when a new cfg field has 2+ semantic siblings (`ridge_*`, `confidence_*`, etc.), audit cohort; all-eligible siblings migrate together. Splitting the cohort across ships (ints at .F.4c, doubles at .F.4d) breaks the discipline.

**Resolves to:** since CRITICAL-1 already defers all STAMP_BOUND to .F.4d, cohort discipline is preserved when both groups migrate together at .F.4d.

### HIGH-4 — Test count baseline drift (1822 → 3118)

Plan Step 7 line 357 says ≥1822; current is 3118 (verified via build output tail). Amendment notice mentions correction but verification gate list not updated.

### HIGH-5 — `model_verify_strict` tri-state vs INT_ENUM `[0, count)` clamp

**Sources:** `/dod-audit` HIGH.

`model_verify_strict` is documented as `-1` (auto: strict in live, lenient in paper), `0` (lenient), `1` (strict). INT_ENUM `[0, count)` clamp would force `-1` to `0`, silently disabling auto-detect behavior.

**Fix:** classify as KIND_INT (signed, clamp range `[-1, 1]`) NOT KIND_INT_ENUM. Document the tri-state semantics. Or extend INT_ENUM to support negative anchors (~10 LOC; one-off).

### HIGH-6 — INT storage-width audit absent

**Sources:** `/readiness` MED-5.

Cfg fields span int8/16/32/64 + uint8-uint64 (e.g., `param_max_age_ticks` uint64_t, `model_max_age_hours` uint32_t). Plan's `INT(default, min, max)` clamp uses int64_t; per-field static_assert that the clamp range fits the destination type's range is absent.

**Fix:** add `static_assert(sizeof(decltype(cfg.name)) <= 8)` companion + clamp uses `std::numeric_limits<decltype(cfg.name)>::max()` as upper bound. Per CLAUDE.md item 20 bitmap-overflow precedent.
