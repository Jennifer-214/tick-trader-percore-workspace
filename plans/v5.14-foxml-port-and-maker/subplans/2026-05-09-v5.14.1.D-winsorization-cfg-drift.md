## Why winsorization + Option B

Winsorization clips per-feature values to [low_pct, high_pct] percentile
bounds computed from training data. Sits in the feature pipeline BEFORE
mean/std normalization. XGBoost (or any model) sees post-clipped+
normalized features in both training + inference — symmetry preserved.

**Reduces noise:** flash crashes, exchange glitches, fat-finger trades
no longer drive tree splits to extreme leaves.

**Reduces overfitting:** training-time feature distribution matches
inference-time distribution more tightly.

**Crypto specifics:** fat-tailed return distributions are normal. BTC
has ~5σ daily moves multiple times per year. Smaller coins do it weekly.
Without winsor, model behavior diverges between calm + chaos regimes.

**Why Option B (cfg-bound + drift) over Option A (sidecar arrays only):**
- Operator wants knobs to tune percentiles by data noise level
  (0.5% for clean BTC; 1-5% for noisier alts)
- Without cfg drift detection, training/inference percentile mismatch
  goes undetected → silent prediction shift
- We just built FOREACH_STAMP_BOUND_CFG registry in v5.14.1.B.3 — using
  it costs ~1 line in the registry per cfg field; not using it leaves
  a known gap for v5.15+ to close

```cpp
// has confidence_freshness_tau + risk_pct (existing pattern). Add 2

struct CoreOverride<F> {

    FPN<F> winsor_pct_high_override;  // 0 = use global

```

**Lookup pattern** (matches existing `confidence_freshness_tau` per-core pattern):

```cpp
// At scaler emit + drift check sites:

    !FPN_IsZero(cfg.core_overrides[core_id].winsor_pct_low_override)
    ? cfg.core_overrides[core_id].winsor_pct_low_override
    : cfg.winsor_pct_low;
```

CFG_PARSE_FPN entries + defaults init at the existing composite cfg block.
Per-core override parser uses existing `CFG_PARSE_PER_CORE_FPN` macro
that handles `core_<N>_winsor_pct_low=...` syntax.

**Use case (operator workflow):** train 3 buy_signal models with
different winsor settings, point each `core_N_model_dir` at a
different model dir, optionally override `core_N_winsor_pct_low/high`
to MATCH the cfg used at training time → drift check passes per-core
→ no spurious WARN at boot when running heterogeneous models.

### Step 3 — FeatureStandardizer struct + binary format extension

File: `ML_Headers/FeatureStandardizer.hpp`

```cpp
// Bump magic (clean break with v0 format; legacy sidecars refused)
static constexpr uint32_t SCALER_MAGIC_V0 = 0xFE5C1AE2u;  // pre-v5.14.1.D
static constexpr uint32_t SCALER_MAGIC    = 0xFE5C1AE3u;  // v5.14.1.D+

struct FeatureStandardizer {
    int      has_scaler;
    uint64_t registry_hash;
    uint32_t num_features;
    double   stddev_floor;
    double   mean[NUM_REGISTERED_FEATURES];
    double   stddev[NUM_REGISTERED_FEATURES];
    // v5.14.1.D — winsorization bounds (per-feature percentile clips)
    uint8_t  has_winsor_bounds;
    double   winsor_low[NUM_REGISTERED_FEATURES];
    double   winsor_high[NUM_REGISTERED_FEATURES];
};

static constexpr size_t SCALER_BODY_BYTES =
    sizeof(uint32_t)                              // magic
  + sizeof(uint32_t)                              // num_features
  + sizeof(uint64_t)                              // registry_hash
  + sizeof(uint32_t)                              // stddev_floor (Q32)
  + sizeof(double) * NUM_REGISTERED_FEATURES      // mean[N]
  + sizeof(double) * NUM_REGISTERED_FEATURES      // stddev[N]
  + sizeof(uint8_t)                               // has_winsor_bounds
  + sizeof(double) * NUM_REGISTERED_FEATURES      // winsor_low[N]
  + sizeof(double) * NUM_REGISTERED_FEATURES;     // winsor_high[N]
```

For 34 features: 564B (v0) → 1129B (v1; +565B).

### Step 4 — Init + Persist + Load extensions

`FeatureStandardizer_Persist`:
- After existing stddev[] write, append `has_winsor_bounds` byte
- Append `winsor_low[]` then `winsor_high[]` arrays

  regenerate via Run Full Validation to upgrade"
- Read new fields after stddev[]
- SHA verify covers full body

### Step 5 — Apply path with branchless winsor

```cpp
static inline int FeatureStandardizer_Apply(const FeatureStandardizer* sc,
                                              float* features, int n) {
    if (!sc || !sc->has_scaler) return 0;
    if (n <= 0 || (unsigned)n > NUM_REGISTERED_FEATURES) return -1;

    double floor = (sc->stddev_floor > 0.0) ? sc->stddev_floor : SCALER_STDDEV_FLOOR;

    // v5.14.1.D — branchless winsor clip BEFORE scale.
    // When has_winsor_bounds=0: bounds default to ±INFINITY → fmin/fmax
    // pass through unchanged (zero observable cost; fmin(x, +inf) = x).
    // Compiler emits maxsd + minsd on x86 (2 instructions, no branch).
    for (int i = 0; i < n; ++i) {
        double in   = (double)features[i];
        // Clip to [low, high] — branchless via fmin/fmax
        double clipped = fmin(fmax(in, sc->winsor_low[i]), sc->winsor_high[i]);
        double sd      = fmax(sc->stddev[i], floor);
        double diff    = clipped - sc->mean[i];
        double out     = diff / sd;
        features[i] = (float)out;
    }
    // Existing post-apply finite check (unchanged)
    for (int i = 0; i < n; ++i) {
        if (!isfinite(features[i])) return -1;
    }
    return 0;
}
```

**Latency analysis:** 2 extra fmin/fmax per feature = ~2-4 ns × N
features ≈ ~70-140ns total at N=34. Slow-path; well within budget.
When `has_winsor_bounds=0`, defaults are ±INFINITY → fmin/fmax pass-
through (no cost difference vs no-winsor case). Effectively zero cost
on legacy paths.

### Step 6 — BacktestEngine RFV: fit + persist

Inside the RFV training pipeline (BacktestEngine.hpp `Backtest_RunFullValidation`):

After mean[] + stddev[] are computed from training data, add winsor fit:

```cpp
// v5.14.1.D — fit winsor percentiles per-feature (Option B; cfg-tunable)
double pct_low  = FPN_ToDouble(cfg.winsor_pct_low);
double pct_high = FPN_ToDouble(cfg.winsor_pct_high);
if (pct_low > 0.0 && pct_high < 1.0 && pct_low < pct_high) {
    fit_winsor_percentiles(scaler, training_features, n_samples, pct_low, pct_high);
    scaler.has_winsor_bounds = 1;
}
```

`fit_winsor_percentiles` is a NEW helper (~30 LOC) that:
- For each feature i: collect column values, sort, take pct_low * N
  and pct_high * N indices → winsor_low[i] / winsor_high[i]
- Uses partial-sort or nth_element for O(N) per feature

## Latency analysis

**Hot path: UNTOUCHED.** Winsor lives in slow-path FeatureStandardizer_Apply.

**Slow-path:**
- Apply: +2 fmin/fmax per feature × N=34 features ≈ +70-140ns total
  per inference cycle (slow-path; 100us budget)
- has_winsor_bounds=0 + bounds=±INFINITY: fmin/fmax pass-through;
  zero observable cost difference (compiler may even optimize the
  comparisons away if bounds are constexpr-known infinities)

**Boot-time:**
- Sidecar Load: +565 bytes read (~negligible)
- SCALER_BODY_BYTES grows: 564 → 1129 (still tiny)

**HOT_PATH_CHANGELOG entry:** SLOW-PATH ADDITION; +70-140ns when
winsor enabled; ~0ns when disabled (default has_winsor_bounds=0 +
±INFINITY bounds = pass-through). Documented as v5.14.1.D entry.

## Operator-facing notes

- **Default behavior unchanged:** winsor cfg fields default to 0.005 +
  0.995 BUT `has_winsor_bounds=0` until BacktestEngine RFV explicitly
  fits + sets it. Existing scalers (re-loaded post v5.14.1.D) load
  with the new format BUT have_winsor_bounds=0 from Init defaults.
  Apply is a no-op pass-through. Zero observable behavior change for
  operators who don't run RFV.
- **Activation requires retrain:** to enable winsor, operator runs
  Run Full Validation. Resulting scaler sidecar has has_winsor_bounds=1
  + the fitted bounds. Stamp body has winsor_pct_low + winsor_pct_high.
- **Legacy sidecar refusal:** old SCALER_MAGIC_V0 sidecars refused
  at load with clear error. Operator regenerates via RFV. One-time
  inconvenience; aligned with Surface G discipline at sidecar level.
- **Cfg drift detection:** if operator changes winsor_pct_low between
  training + inference, drift fires at model load. 3-tier behavior:
  warn (default) / refuse (held_out_gate_strict=1) / silent skip
  (held_out_gate_strict=-1).
