### Class 21 — Multiple parallel descriptors (STAMP_BOUND derived filter)

**This is the BIGGEST architectural blocker.** Plan Step 5 (line 363) lists "STAMP_BOUND derived filter cutover" as a single line item in the sprint state. The plan body itself doesn't elaborate on the deprecation strategy.

**Reality:** `FOREACH_STAMP_BOUND_CFG` (`ML_Headers/StampBoundCfgRegistry.hpp:99-176`) has **12+ consumer sites across 10 files**:

- `ML_Headers/ModelInference.hpp:1191,1198,1206,1260,1400,1637,1642,1787` (struct gen × 2, emit, parser, init walk × 2)
- `ML_Headers/StampBoundCfgRegistry.hpp:227` (STAMP_CFG_AUTOPOPULATE)
- `ML_Headers/StampHelper.hpp:150` (populate_inference_cfg_inputs)
- `ML_Headers/CfgDriftCheckRegistry.hpp:190` (drift check appendix)
- `ML_Headers/CoreModelZoo.hpp:242` (drift comparison walk)
- `MemHeaders/CfgDerivedInferenceCfgRegistry.hpp:25` (sister registry references)
- `MemHeaders/ArchFieldDriftRegistry.hpp:10,29` (cross-references)
- `tests/controller_test.cpp:3832,21937,22402,23321-23353,24514-24696` (12+ test sites)

**Findings:**

1. The legacy registry is **load-bearing** for: stamp body emit ordering (Surface G forward-compat), HMAC-locked wire bytes, parser branches in `verify_model_stamp`, drift checks at boot, AUTOPOPULATE production callers.
2. "Derived filter" presumably means: walk `FOREACH_CFG_FIELD` filtered by `MetadataFlag::STAMP_BOUND` to produce stamp-binding metadata.
3. To achieve byte-identical wire output, the derived filter must produce the SAME ordering and SAME `has_*` semantics as the legacy registry — order is HMAC-locked.
4. `confidence_window` (int) is in stamp registry but NOT in the plan's INT cohort. Several legacy STAMP_BOUND ints (`ridge_within_horizon`, `ridge_across_horizons`, `confidence_composite_enabled`, `exit_blender_mode`, `risk_degradation_curve`, `bandit_algorithm`, `trading_mode`) — most are **BITMAP_BIT entries reading from `ml_cfg_flags`** with ternary normalization. These cannot trivially migrate to a `KIND_INT` row because their `get_cfg` is a `BITMAP_IS_SET(...) ? 1 : 0` expression, not a direct field read.

**Verdict — Class 21:** **RED.** Plan body massively underscopes the cutover. The "Layer 5b hash lock" mentioned in task T.F.4c.5 is necessary but the plan offers no design for how the derived filter preserves byte-identity with the legacy registry. Promoting `MetadataFlag::STAMP_BOUND` to the SINGLE source of truth requires:

- Order-preservation strategy (registry order ≠ legacy emit order today)
- BITMAP_BIT handler (some entries read bitmap bits via ternary, not direct field)
- emit_when handler (some entries have complex emit_when predicates: `BITMAP_ANY(cfg.ml_cfg_flags, MASK_ML_CFG_RIDGE_WITHIN_HORIZON | MASK_ML_CFG_RIDGE_ACROSS_HORIZONS)`)
- 12 consumer migrations (or back-compat shim)
- Layer 5b CI hash test gold values regenerated

This is its own ship-sized refactor, not a single task at the end of an INT/BOOL migration ship.

## INT_ENUM parser routing — CRITICAL plan-vs-reality gap

Plan body (Step 1 lines 107-118) shows `int v = atoi(val);` for INT_ENUM parsing.

**Reality of legacy INT_ENUM parsers:**

| Field | Legacy parser | atoi-only sufficient? |
|---|---|---|
| `bandit_algorithm` (ControllerConfig.hpp:2440) | `BanditAlgorithm_FromString` (string OR int) | NO — accepts "EXP3"/"THOMPSON"/"BOTH" tokens |
| `barrier_blend_mode` (:2063) | `BarrierBlendMode_FromString` (string OR int) | NO — accepts "LEGACY"/"BLEND"/"DOMINANT"/... tokens |
| `risk_degradation_curve` (:2048) | `DegradationCurve_FromString` (string OR int) | NO — accepts "OFF"/"LINEAR"/"EXP"/"STEP" tokens |
| `engine_arch` (:2610) | Custom string compare ("centralized"/"per_core_slow") OR int | NO — string-only path |
| `engine_mode` (:2601) | Custom string ("single_core"/"sharded") OR int | NO — string-only path |

The plan's example INT_ENUM rows (`bandit_algorithm`, `risk_degradation_curve`, `engine_arch`, `barrier_blend_mode`) **CANNOT migrate via plain `atoi(val)` without losing the string-token parser support**. Operator-facing cfg files use `bandit_algorithm=THOMPSON` and `engine_arch=per_core_slow` — these break under `atoi`.

**Required fix to plan:** the INT_ENUM tt:: branch must accept either int OR string-token via `FromString`-helper dispatch. This needs either:
1. A per-field `from_string_fn` function pointer in the `as_int_enum` payload, or
2. The descriptor's `labels[]` array used for string-token reverse lookup (case-insensitive match) at parse time.

Neither option is in the plan. **This is BLOCKING.**
