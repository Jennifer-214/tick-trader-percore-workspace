## Coding-time discoveries from prior session(s)

### D-1: engine_version[16] truncation contract was undocumented (Caramel-caught)

- **Catalyst:** 2 pre-existing test failures (v5.8.6 + v5.8.8) Caramel suspected were ship-relevant. Investigation revealed `ModelStampResult::engine_version[16]` silently truncates current `ENGINE_VERSION_STRING "5.15.5.F.4d.1.B.2"` (18 chars) to "5.15.5.F.4d.1.B" — strcmp fails. Failures started at `.B.0` when sub-tag version era pushed past 15-char usable capacity.
- **Resolution:** documented [16] truncation as INTENTIONAL design (field used for cross-major version check + display; not bit-identity verification). Wire body retains full string (HMAC chain unaffected). Tests v5.8.6 + v5.8.8 updated to `strncmp(..., 15)` matching documented contract. NET test delta: 3235 PASS + 2 FAIL → 3237 PASS + 0 FAIL.
- **Lesson:** "pre-existing environmental" hand-wave can mask real ship-relevant bugs. Caramel's domain knowledge surfaced this; pure compaction-based handoffs would have missed.

### D-2: 5th FOREACH_GATE_CFG_FLAG consumer X-macro (`_PARSE_OV_BITMAP_ROW_gate`) caught at build time

- **Catalyst:** Step 0.5d.a.0 5→6 col sig migration enumerated 4 consumer X-macros via initial grep. After landing the 4, build broke with error referencing 5th consumer (`_PARSE_OV_BITMAP_ROW_gate` at `ControllerConfig.hpp:2943`) which the initial grep missed (different naming convention).
- **Resolution:** added `_PARSE_OV_BITMAP_ROW_gate` to 6-arg sig (sister to `.B.2` `_PARSE_OV_BITMAP_ROW_ml` migration).
- **Lesson:** Meta-gap M1a (sister-registry parity verification) discipline catches this PRE-CODING via comprehensive consumer enumeration. Validates the discipline.

### D-3: Step 1.5 INFERENCE_CFG_AUTOPOPULATE swap blocked by Step 1.6.3 struct-gen

Build still GREEN but `feedback_audit_canonical_sister_before_new_infra` instincts surfaced the issue: framework consumer writes UNPREFIXED `inf.<name>` fields; legacy walker writes PREFIXED `inf.inference_cfg_<name>` fields; the prefixed fields exist on inf struct at HEAD (via FOREACH_STAMP_BOUND_MODEL_CONST POST_CFG) but unprefixed don't (until Approach A unconditional struct-gen lands at Step 1.6.3).
