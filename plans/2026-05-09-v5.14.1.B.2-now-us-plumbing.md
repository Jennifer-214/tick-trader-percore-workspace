## Problem statement

`/parity-check` 2026-05-09 CRITICAL-2:

> v5.14.1.B adds `clock_gettime(CLOCK_MONOTONIC)` to the composite
> confidence compute path (`StrategyParameters.hpp:1116`), which
> returns wall-clock time non-deterministically, breaking the v5.9.2
> replay-determinism contract: "same backtest tick file → bytewise
> identical predictions across runs".

Today's symptom: `cfg.confidence_composite_enabled=1` in backtest →
two runs of identical tick CSV → different `now_us` → different
freshness decay → different composite scalar → different sizing →
different P&L curves. Operator can't compare strategy tunings.

**Caveat:** Since v5.14.1.B.1, composite is functional in production
(PARITY-002 + PARITY-003 fixed). But it's still NON-DETERMINISTIC in
backtest. v5.14.1.B.2 closes that gap.

---

## Design

**Architectural principle (CLAUDE.local.md): boundary-stable refactor.**
The "boundary" here is `ML_BuildParameters` signature. Adding `now_us`
as a parameter at this boundary touches:
- 1 function signature (add param)
- 2 callers (live + backtest)
- 0 internal struct shapes
- 0 cfg fields

**Single-direction dependency:** caller knows the context (live vs
backtest), passes correct `now_us`:
- Live: `clock_gettime(CLOCK_MONOTONIC)` at the slow-path entry
- Backtest: `current_hist_tick.timestamp_us` (deterministic)

`ML_BuildParameters` consumes the parameter. No internal `clock_gettime`
calls. Replay-determinism contract restored.

## Implementation plan

### Step 1 — Add `now_us` parameter to ML_BuildParameters

File: `Strategies/StrategyParameters.hpp`

```cpp
// BEFORE:
template <unsigned F>
inline void ML_BuildParameters(
    const ControllerConfig<F>* config,
    /* existing args */,
    GateParameters<F>* out);

// AFTER:
template <unsigned F>
inline void ML_BuildParameters(
    const ControllerConfig<F>* config,
    /* existing args */,
    uint64_t now_us,                 // v5.14.1.B.2 NEW (PARITY-001)
    GateParameters<F>* out);
```

Inside body, replace:
```cpp
struct timespec ts;
clock_gettime(CLOCK_MONOTONIC, &ts);
uint64_t now_us = (uint64_t)ts.tv_sec * 1000000ull + (uint64_t)ts.tv_nsec / 1000ull;
conf_now = ConfidenceScorer_ComputeComposite(conf_scorer, now_us);
```

with:
```cpp
conf_now = ConfidenceScorer_ComputeComposite(conf_scorer, now_us);
```

Remove `<ctime>` include if no other consumer needs it (audit first).

  (~50-100ns vDSO)

  uint64 parameter pass-through (~50-100ns vDSO + 0 incremental)

  call eliminated)
