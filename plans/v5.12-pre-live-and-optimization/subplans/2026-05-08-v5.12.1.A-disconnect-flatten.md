## Theme

Live capital is gated on this ship. Currently the engine reconnects
on WS dropouts via `reconnect_delay=5s` (`DataStream/BinanceCrypto.hpp:68`,
`:614-621`) but has no flatten policy if the dropout extends. Open
positions stay on the exchange (TP/SL orders rest there); engine
flies blind until reconnect resolves. Risk: market moves through
both bracket levels (gap) during the dropout, OR operator wants to
manually flatten but engine state-of-truth is stale.

Fix: producer-thread publishes `last_ws_tick_us`; slow-path checks
gap; if `>= cfg.ws_dead_time_flatten_threshold_secs`, fire
`OMS_FlattenAll` via the drainer surface. On reconnect, engine
refuses new entries for `cfg.recovery_delay_secs` while it
reconciles via REST `/api/v3/account` using existing
`Reconcile_ParseOpenOrders` (`CoreFrameworks/Reconcile.hpp:188`).

## Phase B — `OMS_FlattenAll` + slow-path staleness check (`v5.12.1.A.2`)

**Goal:** New OMS helper that submits market exits for all open
positions across all cores. Slow-path (per-core, every poll cycle)
reads `last_ws_tick_us`, computes gap, fires flatten if gap exceeds
threshold.

**Step 0:** Add `OMS_FlattenAll` adjacent to `OMS_DrainSubmit` at
`CoreFrameworks/OrderManager.hpp:728`:

```cpp
// CoreFrameworks/OrderManager.hpp adjacent to line 728
// v5.12.1.A: emergency-flatten all open positions. Called from slow-
// path when WS staleness threshold breached. Returns count of orders
// submitted. NON-BLOCKING — orders enter the standard drainer queue.
template <unsigned F>
inline int OMS_FlattenAll(OrderManagerState<F>* oms,
                          int num_cores,
                          int reason_code) {
    // Iterate active positions in portfolio bitmap; for each active
    // slot, push a market-exit TradeEvent to the drainer queue. The
    // drainer (existing OMS_DrainSubmit caller) consumes it next cycle.
    // Sets oms->flatten_pending = 1 so subsequent slow-path cycles
    // know to refuse new entries until reconciled.
    // ... (implementation iterates portfolio.active bitmap; for each
    //      bit, builds a market-close TradeEvent; pushes to drain ring;
    //      logs Health_Log(WARN) with reason_code)
    // Returns count of orders pushed (0 if no open positions).
}
```

**Slow-path call site:** New function
`EventLoop_CheckWsStaleness(state, cfg, now_us)` adjacent to
`EventLoop_TimeExitOneCore` at
`CoreFrameworks/ControllerEventLoop.hpp:2641`:

```cpp
// CoreFrameworks/ControllerEventLoop.hpp adjacent to :2641
// v5.12.1.A: WS staleness emergency-flatten gate. Called from slow-
// path schedule (any core's slow-path will detect staleness; the
// first one to detect it wins the flatten via atomic CAS on
// flatten_pending).
template <unsigned F>
inline int EventLoop_CheckWsStaleness(EventLoopState<F>* state,
                                      const ControllerConfig<F>& cfg,
                                      uint64_t now_us) {
    if (!cfg.ws_dead_time_flatten_enabled) return 0;
    uint64_t last = state->last_ws_tick_us.load(std::memory_order_acquire);
    if (last == 0) return 0;  // pre-warmup: no flatten on cold start
    uint64_t gap_us = now_us - last;
    uint64_t threshold_us =
        (uint64_t)cfg.ws_dead_time_flatten_threshold_secs * 1000000ULL;
    if (gap_us < threshold_us) return 0;
    // CAS to win the flatten among multiple cores
    int expected = 0;
    if (!state->oms->flatten_pending.compare_exchange_strong(
            expected, 1, std::memory_order_acq_rel)) {
        return 0;  // another core already won
    }
    return OMS_FlattenAll(state->oms, state->num_cores, /*reason*/1);
}
```

**Cfg fields** (add to `CoreFrameworks/ControllerConfig.hpp` — locate
adjacent to `kill_switch_*` cfg block):
- `int ws_dead_time_flatten_threshold_secs;` (default 60)
- `int ws_dead_time_flatten_enabled;` (default 0; flips to 1 before
  live deployment)

**Cfg parser sites:**
- Default initialization in `ControllerConfig_Defaults` (existing
  function, around `:909-1176`)
- Parser in `ControllerConfig_Parse` (existing, around `:1396`)

**`oms->flatten_pending`:** new atomic int field on `OrderManagerState`
(adjacent to existing `kill_switch_tripped` at e.g. `:2541`-area in
ControllerEventLoop's kill-switch site → indicates the canonical
location). Initialized 0 in `OrderManager_Init`.

**Tests** (+3):
1. cold-start (`last_ws_tick_us == 0`) → no flatten (warmup respected)
2. within-threshold (gap = 39s, threshold = 60s) → no flatten
3. over-threshold (gap = 61s) → `OMS_FlattenAll` fires; orders enter
   drainer queue; `flatten_pending = 1`

**Sub-ship gate:** Tests pass; `tools/calls_graph_diff.sh` shows new
function additions only (no hot-path edits). Tag `v5.12.1.A.2`.

## Phase C — Recovery refusal + reconcile wiring (`v5.12.1.A.3`)

**Goal:** After flatten fires, refuse new entries for
`cfg.recovery_delay_secs`. On reconnect, kick a reconcile via REST
`/api/v3/account` to get the actual position state from exchange.

**Step 0:** Add cfg field `int recovery_delay_secs;` (default 30) to
`CoreFrameworks/ControllerConfig.hpp`. Add `recovery_until_us` field
(uint64_t) to `OrderManagerState` adjacent to `flatten_pending`
(populated by `OMS_FlattenAll` as `now_us + recovery_delay_secs *
1e6`).

**Strategy gate site:** `Strategy_BuildParameters`
(`Strategies/StrategyParameters.hpp:1070`) — extend the existing
predicate that gates entry on kill_switch / halt_reason to ALSO gate
on `now_us < recovery_until_us`. When in recovery window, set the
GateParameters' `BUY_BLOCKED` flag with `SHALT_RECOVERY` reason
(NEW SHALT code; X-macro entry).

**SHALT code addition** (per CLAUDE.md item 13):
- `Strategies/StrategyInterface.hpp` SHALT enum block around `:262`:
  `X(RECOVERY,        "recovery",         "post-flatten recovery window — new entries blocked")`

**Reconcile wiring:** `EngineSharded.hpp:1306` already calls
`Reconcile_ParseOpenOrders` for an existing reconcile path. Hook the
flatten-recovery completion to the same surface — when the existing
reconcile completes, clear `oms->flatten_pending = 0` and unblock
new entries.

**Tests** (+2):
1. Post-flatten recovery refusal (within `recovery_delay_secs`) →
   new entries blocked, `SHALT_RECOVERY` set.
2. Recovery expiry (after `recovery_delay_secs`) → entries unblocked
   IF reconcile completed (else stay blocked).

**Sub-ship gate:** integration test (synthetic disconnect → flatten
→ reconnect → reconcile → recovery clears).

**Tag:** `v5.12.1.A`. Operator-validation: manual `kill -STOP`
on producer thread mid-paper-run, observe flatten fires after 60s,
unblock after reconcile.
