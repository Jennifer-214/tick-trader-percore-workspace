### Step 0.5 — Fix exit_predictor buy_class_idx aliasing (CRITICAL GAP from /plan-check + /merge-scan audit)

**FUNCTIONAL BUG IF NOT FIXED:** `CoreModelZoo_TryLoadRole` post-load
sets `buy_class_idx` for buy_signal/barrier/regime models (per v5.11.62
tactical aliasing) but **skips exit_predictor entirely**. With Path 3
(exit_predictor uses PEAK_VALLEY_STABLE 3-class labels), models would
default to `buy_class_idx=0` (VALLEY class) instead of needed
`buy_class_idx=1` (PEAK class). Exit predictor would predict the WRONG
class — fire exits on valleys instead of peaks. **Silent semantic
inversion.**

File: `ML_Headers/CoreModelZoo.hpp` around line 1233-1280 area where
existing role-aliasing happens for buy_signal/barrier/regime.

Add post-load assignment for exit_predictor mirroring barrier pattern:
```cpp
// v5.13.0 (audit gap-close 2026-05-08): exit_predictor uses
// PEAK_VALLEY_STABLE 3-class labels (Path 3) — same as barrier.
// Set buy_class_idx=1 to extract PEAK class probability (which the
// engine interprets as "exit imminent" for sell-side predictions).
// Mirrors the v5.11.62 barrier-role aliasing pattern.
for (int h = 0; h < ezoo->exit_predictor_count; ++h) {
    ModelHandle<F> *m = &ezoo->exit_predictor[h];
    // Only set when model uses 3-class barrier labels (per stamp body).
    // Defensive: stamp body's label_kind dispatch determines extraction.
    if (m->stamp_label_kind_is_barrier_3class) {  // verify field name
        m->buy_class_idx = 1;
    }
}
```

Implementation note: verify the exact field name for label_kind on
ModelStamp body when reading the existing barrier path code. The
flag-or-field check should mirror exactly what the barrier role does.

**Test:** load an exit_predictor model with PEAK_VALLEY_STABLE labels;
verify `m->buy_class_idx == 1` post-load; verify Model_Predict returns
class-1 probability (not class-0).

### Step 3 — MLStrategy exit-side prediction

File: `Strategies/MLStrategy.hpp` (or wherever MLStrategy_Adapt lives)

Decision: SLOW-PATH-ONLY integration. Hot path UNTOUCHED. The exit
prediction runs at slow-path cadence; if exit-imminent, slow-path
calls OMS_PushSubmit directly (no hot-path-visible flag).

Alternative considered + rejected: hot-path branch via new
GATE_FLAG_EXIT_REQUESTED. Rejected per CLAUDE.md item 18 (slow-path
latency reduction priority + hot-path UNTOUCHED invariant).

Insertion point: `MLStrategy_Adapt` body, after existing buy-side
prediction completes. Pseudocode:
```cpp
// v5.13.0 — exit-side prediction. Gated on cfg + ensemble availability +
// position open for this core's slot. SLOW-PATH-ONLY; no hot-path impact.
if (config->use_exit_model
    && state->ensemble_zoo
    && state->ensemble_zoo->exit_predictor_count > 0
    && core_has_open_position(controller, slot)) {

    int regime = controller->cores[slot].regime_state.current;
    BanditState *exit_bandit = nullptr;  // wired in v5.13.4
    // For v5.13.0 (without bandit wiring): uniform-weight blend.
    float blended_exit_prob = 0.0f;
    int n = state->ensemble_zoo->exit_predictor_count;
    for (int h = 0; h < n; ++h) {
        ModelHandle<F> *m = &state->ensemble_zoo->exit_predictor[h];
        if (!Model_IsLoaded(m)) continue;
        blended_exit_prob += Model_Predict_Normalized(
            m, features, num_features) / (float)n;
    }

    if (blended_exit_prob > FPN_ToDouble(config->exit_threshold)) {
        // Fire early exit. Mark for v5.13.4 reward attribution.
        FPN<F> qty = oms->portfolio.positions[slot].quantity;
        FPN<F> price_fpn = FPN_FromDouble<F>(current_price);
        OMS_PushSubmit(oms, (int16_t)slot, ORDER_MARKET_SELL,
                        qty, FPN_Zero<F>(), FPN_Zero<F>(),
                        STRATEGY_ML, price_fpn);
        controller->cores[slot].strategy_halt_reason = SHALT_EXIT_PREDICTED;
        controller->cores[slot].last_exit_was_predicted = 1;  // for .4 attribution
    }
}
```

Note: `last_exit_was_predicted` is a NEW field on CoreContext. See
sub-step.

### Step 4 — Per-slot last_exit_was_predicted (PARTIALS-AWARE)

**GAP-CLOSE (audit 2026-05-08):** under `partial_exit_enabled=1`, each
core has 2 portfolio slots (legs A + B at slot indices `2*core_id+0`
and `2*core_id+1`). MLStrategy might fire exit on leg A independently
of leg B. Per-CORE flag would over-trigger reward attribution.
**Per-slot tracking from day 1.**

File: `CoreFrameworks/OrderManager.hpp` (OrderManagerState struct)

Add field adjacent to existing per-slot tracking arrays:
```cpp
// v5.13.0 — per-slot flag set by MLStrategy when exit_predictor fires
// the exit on this specific slot. Consumed by v5.13.4's reward
// attribution (drainer post-fill in HandleFill). Cleared after
// attribution (single-use flag per trade).
//
// PARTIALS-AWARE: indexed by portfolio slot (0..MAX_PORTFOLIO_POSITIONS-1)
// not core_id. Under partials, slot 2c+0 and 2c+1 are independent legs;
// each can have its OWN predicted-exit attribution.
uint8_t last_exit_was_predicted[MAX_PORTFOLIO_POSITIONS];
```

Init to all-zero in OrderManager_Init. MLStrategy writes to slot index
when exit fires; HandleFill reads + clears post-attribution.

Why on OMS not EventLoopState: HandleFill (drainer thread) needs read
access; OMS is the natural home for fill-time per-slot state (mirrors
existing portfolio.positions[slot] indexing).
