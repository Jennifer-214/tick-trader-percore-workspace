## Step 1 — Add 3 tt:: dispatch specializations (~150 LOC)

**File:** `CoreFrameworks/CfgFieldDispatch.hpp` (extend existing file from `.F.4b`)

### KIND_INT parser:
```cpp
template <> inline void cfg_parse_field<CfgFieldDescriptor::KIND_INT>(
        void* cfg_root, const CfgFieldDescriptor& desc, const char* val) {
    char* target_base = cfg_dispatch_target<CfgFieldDescriptor::KIND_INT>(cfg_root, desc.lives_in_struct);
    int64_t v = strtoll(val, nullptr, 10);
    v = std::clamp(v, desc.payload.as_int.clamp_min, desc.payload.as_int.clamp_max);
    // Storage size detection via field_idx → sidecar table OR encode in metadata flag
    // For .F.4c: assume target is int32_t; adjust later if 16-bit fields are needed
    *reinterpret_cast<int32_t*>(target_base + cfg_field_offset(desc)) = (int32_t)v;
}
```

**Storage-size handling:** the cfg struct has fields of various integer widths (int8_t, int16_t, int32_t, int64_t, uint_*). The dispatcher writes to whatever the field declares. Two implementation options:

- **Option A:** add `int_width: uint8_t` field to descriptor payload (8/16/32/64); dispatch via switch
- **Option B (recommended):** match field width via `sizeof` at compile time via template magic; templates instantiated per field via FIELD_IDX

Choose Option A for simplicity; Option B if Option A's switch becomes a hot-path concern (unlikely — parser is boot-time).

### KIND_INT_ENUM parser:
```cpp
template <> inline void cfg_parse_field<CfgFieldDescriptor::KIND_INT_ENUM>(
        void* cfg_root, const CfgFieldDescriptor& desc, const char* val) {
    char* target_base = cfg_dispatch_target<CfgFieldDescriptor::KIND_INT_ENUM>(cfg_root, desc.lives_in_struct);
    int v = atoi(val);
    // Validate ∈ [0, count) — silently clamp on invalid (or WARN + use default; decide per-field)
    if (v < 0 || v >= desc.payload.as_int_enum.count) {
        v = desc.payload.as_int_enum.default_val;
        // Optionally log warning: invalid enum value for field
    }
    *reinterpret_cast<int*>(target_base + cfg_field_offset(desc)) = v;
}
```

### KIND_BOOL parser:
```cpp
template <> inline void cfg_parse_field<CfgFieldDescriptor::KIND_BOOL>(
        void* cfg_root, const CfgFieldDescriptor& desc, const char* val) {
    char* target_base = cfg_dispatch_target<CfgFieldDescriptor::KIND_BOOL>(cfg_root, desc.lives_in_struct);
    int v = atoi(val);
    *reinterpret_cast<uint8_t*>(target_base + cfg_field_offset(desc)) = (v != 0) ? 1 : 0;
}
```

```cpp
        FILE* fp, const void* cfg_root, const CfgFieldDescriptor& desc) {

}

// KIND_BOOL save:
template <> inline void cfg_save_field<CfgFieldDescriptor::KIND_BOOL>(
        FILE* fp, const void* cfg_root, const CfgFieldDescriptor& desc) {
    const char* target_base = cfg_dispatch_target<CfgFieldDescriptor::KIND_BOOL>(
            const_cast<void*>(cfg_root), desc.lives_in_struct);
    uint8_t v = *reinterpret_cast<const uint8_t*>(target_base + cfg_field_offset(desc));

}

// KIND_INT_ENUM render (ImGui::Combo):
template <> inline bool cfg_render_field<CfgFieldDescriptor::KIND_INT_ENUM>(
        void* val_ptr, const CfgFieldDescriptor& desc) {
    int* v = static_cast<int*>(val_ptr);
    return ImGui::Combo(desc.label, v, desc.payload.as_int_enum.labels, desc.payload.as_int_enum.count);
}

// KIND_BOOL render (ImGui::Checkbox):
template <> inline bool cfg_render_field<CfgFieldDescriptor::KIND_BOOL>(
        void* val_ptr, const CfgFieldDescriptor& desc) {
    bool b = (*static_cast<uint8_t*>(val_ptr) != 0);
    bool changed = ImGui::Checkbox(desc.label, &b);
    if (changed) *static_cast<uint8_t*>(val_ptr) = b ? 1 : 0;
    return changed;
}
```

## Anti-patterns to avoid

- **Don't migrate bitmap-resident bool fields here.** The 5 FOREACH_*_CFG_FLAG bitmap registries (LIFECYCLE/GATE/ML/RISK/OPS) handle their own bool fields. Only SCALAR uint8_t bools enter the universal registry.
- **Don't add INT_ENUM labels inline in the X-macro.** Compound literal lifetime / C++20 compatibility risk. Declare named static label arrays + reference by name.
- **Don't change INT field storage width.** Cfg struct's int fields are int32_t / int64_t / uint16_t etc. The descriptor's int_width metadata (or template dispatch) handles the per-field width; don't widen anything at this ship.
- **Don't add CI script yet.** `.F.4c` still has the manual parser remainder for STRING. Reverse-drift CI script lands at `.F.4d` after manual sites are gone.

---

## If something goes wrong

- **Build fails on label array compound literal:** declare named static arrays instead. Macro emits the array NAME reference, not inline literal.
- **INT roundtrip fails (bytes differ):** field width mismatch. Verify descriptor's int_width metadata matches cfg struct field type. Add static_assert on per-field width.
- **INT_ENUM dropdown shows wrong labels:** `as_int_enum.labels[]` array indexed incorrectly. Verify label array order matches enum value order.
- **Backtest determinism breaks:** unlikely (no semantic changes), but possible if INT clamp ranges differ from manual parser. Audit each migrated INT field's clamp values vs original manual parse code.
- **Rollback:** `git reset --hard pre-v5.15.5.F.4c` (anchor at Step 0).
