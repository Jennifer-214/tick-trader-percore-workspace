# v5.1 — Per-Core Data-Plane Decoupling (Sub-Plan)

Closes the redefined-as-audit Phase A from the v5.0 master plan.
Goal: each engine fully **owns** its rolling/regime/flow state.

## Current state (v5.0.x)

|---|---|---|---|
| `rolling_short / long / medium / baseline` | `RollingStats<F>` × 4 | Producer slow-path body | Per-core slow-paths |
| `regime_ror` | `RORRegressor<F>` | Producer slow-path body | Per-core slow-paths |
| `ema_price` | `FPN<F>` | Producer slow-path body | Per-core slow-paths |
| `cumdelta_state` | `CumDeltaState<F>` | Producer slow-path body | ML feature pack |
| `tick_rate_state` | `TickRateState<F>` | Producer slow-path body | ML feature pack |
| `book_imb_history` | `BookImbHistory<F>` | Producer slow-path body | Regime classifier |
| `flow_state` | `FlowState<F>` | Producer slow-path body | ML feature pack |

## Target state (v5.1.0)

Each `CoreContext<F>` gains `slow_state`:

```cpp
template <unsigned F>
struct CoreSlowState {
    RollingStats<F>    rolling_short;
    RollingStats<F>    rolling_long;
    RollingStats<F>    rolling_medium;
    RollingStats<F>    rolling_baseline;
    RORRegressor<F>    regime_ror;
    FPN<F>             ema_price;
    CumDeltaState<F>   cumdelta_state;
    TickRateState<F>   tick_rate_state;
    BookImbHistory<F>  book_imb_history;
    FlowState<F>       flow_state;
    LargeTradeState<F> large_trade_state;
    SpreadState<F>     spread_state;
};
```

Initialization mirrors current producer-scope inits. Located in `CoreContext_Init`.

## Single-writer rule (clarified per readiness check)

State splits by update cadence:

**Per-tick fields** (`ema_price`, `cumdelta_state`, `flow_state`,
`large_trade_state`, `tick_rate_state`):
- Updated in producer's `fan_out` per tick.
- Producer is single-writer of each `state.cores[c].slow_state` per-tick
  field. fan_out loops c=0..N and writes each copy.

**Per-cadence fields** (`rolling_short`, `rolling_long`, `rolling_medium`,
`rolling_baseline`, `regime_ror`, `book_imb_history`, `spread_state`):
- Updated at slow-path cadence (every poll_interval ticks).

| Arch | Per-tick writer | Per-cadence writer |
|---|---|---|
| centralized | Producer fan_out (loops c=0..N) | Producer slow-path (loops c=0..N) |
| per_core_slow | Producer fan_out (loops c=0..N) | Per-core slow-path c writes own |
| backtest | Linear iteration, single thread | Linear iteration, single thread |

**Reader of `state.cores[c].slow_state`**:
- centralized: producer (single thread, no race)
- per_core_slow: per-core thread c reads its own slow_state. Per-tick
  fields are cross-thread reads (producer→thread c), accepted as
  eventually consistent (`memory_order_relaxed`). Per-cadence fields
  are same-thread (no race).
- backtest: single thread (no race).

**Cross-thread access is bounded** to per-tick fields in `per_core_slow`,
matching today's eventual-consistency semantics for shared-RollingStats
reads, but now with per-engine targets (no cross-engine sharing).
Documented as Invariant B in CLAUDE.md.

## Helper

```cpp
template <unsigned F>
inline void EventLoop_UpdateRollingStateOneCore(
    EventLoopState<F>* state, int c,
    FPN<F> price,
    /* depth/flow/spread inputs from shared sources */) {
    auto& s = state->cores[c].slow_state;
    RollingStats_Push(&s.rolling_short, price);
    RollingStats_Push(&s.rolling_long, price);
    // ... etc.
}
```

Called by each architecture's slow-path entry. Train-serve parity is
structural — same helper, same state struct, three callers.

## Strategy (order of edits)

1. **Add `CoreSlowState<F>` struct** to ControllerEventLoop.hpp. Include all 12 fields + zero-init in CoreContext_Init. Build → green (no consumers yet).
2. **Add `EventLoop_UpdateRollingStateOneCore` helper**. Callable but no callers. Build → green.
3. **Add per-core inits to ALL three callers** (centralized producer, per-core slow-path lambda, backtest driver). Build → green. Per-core state populated but unused.
4. **Update Regime_ComputeSignals signature** to accept per-core state (or pass core_id and have it read state.cores[c].slow_state). Update all callers. Build → green. Now per-core state is the read source.
5. **Remove producer-scope shared state vars** from EngineSharded.hpp. Build → red until step 4 fully landed. Build → green.
6. **Run parity_harness** — backtest features must be byte-identical pre/post refactor.
7. **Run controller_test** — all 704 must still pass.
8. **Run live engine** synthetic mode for 5 min, verify GUI shows expected values, no warnings.

## Acceptance criteria

- All 12 fields moved per-core.
- `EngineSharded_Run` no longer declares producer-scope rolling/regime/flow vars.
- `parity_harness` returns 0 (training-data byte-identical before vs after).
- `controller_test` 704/704 pass (or 780/780 if item 2 lands first).
- Live synthetic run shows correct regime classification.
- Live BTCUSDT run shows correct slope/R²/regime values across all cores.

## Rollback

- Tag `pre-data-plane-decouple` at v5.0.5 head before starting.
- If parity harness fails: bisect to first broken commit, fix in place.
- If live regression: `git revert` is clean since refactor is mechanical.

## Out of scope (future)

- **Per-core window sizes**: per-core override `core_N_rolling_window`
  becomes possible after this refactor. Add as a v5.1.x enhancement
  if a use case shows up. The struct supports it (per-core windows
  are independent), but the cfg field + parser is separate work.
- **Per-core data feeds**: each core consumes its own tick stream from
  the SPSC ring rather than shared producer pushes. Significant
  redesign; not needed for current goals.
