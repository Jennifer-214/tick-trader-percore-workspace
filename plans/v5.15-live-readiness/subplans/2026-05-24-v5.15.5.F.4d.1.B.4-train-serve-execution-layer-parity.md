### Decision H — Helper signature: reference for non-nullable; pointer for explicit-nullable (REFINED v1.6 per O1)

`&` reference for NON-NULLABLE args (cfg + state + oms + tick_ring + core + FPN values). Type-safe; communicates "this arg is always present" at type level.

`*` pointer EXPLICITLY for NULLABLE args (zoo_ptr + ezoo_ptr in BootPerCore — null when non-ML core OR LIVE aligned_alloc failed). Pointer signals nullability at type level; documented at helper.

NOT permitted: nullable arg via `&` reference + sentinel value (e.g., empty struct). NOT permitted: pointer for non-nullable (would mask "this could be null" surprise — anti-pattern shape).

5 helpers use this discipline:
- `ApplyBnbDiscount(cfg&)` — 1 non-null ref
- `BootGlobal(cfg& + state& + oms&)` — 3 non-null refs
- `BootPerCore(cfg& + c + state& + tick_ring& + core& + zoo* + ezoo* + FPN)` — 4 non-null refs + 2 nullable ptrs + 2 PODs (v1.6 O1 — 8 args; v1.7.1 H2.B corrected typo: was "5 refs + 2 ptrs + 1 POD"; actual is cfg/state/tick_ring/core = 4 refs, zoo/ezoo = 2 ptrs, c/core_balance = 2 PODs)
- `SlowPathCycleOneCore(cfg& + c + state& + oms& + price + ts_us)` — 3 non-null refs + 3 PODs
- `SlowPathCycleAllCores(cfg& + state& + oms& + price + ts_us)` — 3 non-null refs + 2 PODs

**Why the refinement (v1.6 O1):** Original Decision H "no pointers" was too restrictive — couldn't express "this CoreModelZoo may not exist (non-ML core)" without ugly sentinel-empty-struct hack. Pointer + explicit nullability is the cleaner contract for genuinely-optional args. Anti-pattern is hidden nullability (pointer for non-nullable; ref-with-sentinel for nullable) — explicit nullability via `*` is the discipline.
