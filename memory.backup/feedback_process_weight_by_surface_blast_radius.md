Process weight (plan body / `/precoding-audit-gate` / heavy in-depth planning) scales with a surface's **blast-radius**, not its size.

- **Engine repo (capital / determinism / wire-format / hot-path) = HEAVY.** A flaw is silent, expensive, hard to reverse → plan body + audit gate + heavier-default posture earned.
- **Workspace / skill / doc apparatus = LIGHT.** A flaw is visible prose, reversible, no capital/determinism on the line → DOGFOOD-and-iterate is the validation mode, NOT pre-gates. "It's harder to introduce issues here."

**Why:** 2026-06-02, building the skill-consult meta-discipline, I mis-applied capital-code gravity to skill *prose* — called a 20-skill consult-stage edit "HIGH-RISK, propagates-a-flaw-20×" and proposed a plan-body + audit-gate before any edits. Caramel corrected it: worst case here is a one-line markdown fix; reserve heavy in-depth planning for the actual engine repo. The error was treating **breadth** (20 files) as **blast-radius** (severity × irreversibility × is-it-capital) — they're orthogonal; a wide doc edit is low-blast.

**How to apply:** Before choosing process weight, ask *"can a flaw on THIS surface be silent + irreversible + capital/determinism-bearing?"* Yes → heavy (engine-repo ceremony: plan body + audit gate). No → light: just implement + dogfood; let use surface the problems. The FLOOR stays non-zero even when light — the cheap **deterministic** checks still run on the apparatus (`check_session_docs.sh` doc/index/citation sweep); only the expensive **judgment** gates are reserved for the engine. Light ≠ careless; light = validate-by-use instead of validate-by-pre-gate. This is the LIGHT end of the same spectrum [[feedback_heavier_default_audit_posture_for_capital]] anchors at the HEAVY end (capital + inverse-coverage); within-a-surface scope-tiering is [[feedback_tiered_audit_discipline_per_plan_scope]]. Operator-explicit "just implement" is the legitimate skip per [[feedback_never_skip_thoroughness_unless_explicit]].

**⚠️ NOT A CARVE-OUT — THE RULE FOR THIS SURFACE (upgraded 2026-07-20, D-411/T13). A fact-PRODUCER or shared VERIFIER gets ENGINE-GRADE treatment, full stop.** The wording below said "despite the apparatus plane", which framed it as an EXCEPTION — and an exception has to be RECALLED to apply. It wasn't: Caramel corrected me on this surface on 2026-07-18 (recorded below), and again on 2026-07-20 (*"treat this with the same importance as the engine code"*). Second recurrence at the same surface despite codified memory IS the M7 signal, so it escalated to STRUCTURE: **T13** in the `tools/CLAUDE.md` T-index (a fact-producer ships unit tests, wired, alongside) + the spec `meta-disciplines/toolchain-test-tier-model.md`. This memory now keeps the WHY; the invariant carries the obligation. What the second recurrence cost: 23 selftest wrappers existed and 8 fired; running the rest found FOUR RED guards, two on capital/determinism surfaces (TECH_DEBT-265). Original framing preserved below because its reasoning is right — only its status changed.

**Carve-out — a fact-PRODUCER or shared VERIFIER is correctness-critical DESPITE living on the apparatus plane.** The "apparatus = light" heuristic breaks for a tool whose OUTPUT other surfaces trust. The doc-intelligence toolchain (`check_cache_layout` / the `[DERIVED]`-writers / `foxtag`) is **one-producer-N-consumers**: a wrong `[SIZE]`/`[STRADDLE]` fact silently fans out to the CI gate AND the plugin AND the doc-viewer at once — and a lie inside the tool built to *prevent* lies is the worst kind (self-undermining + inherited by every consumer). So the discriminator *"can a flaw be silent + hard-to-reverse?"* answers **YES** here even though it's "just a Python tool in `tools/`" and touches no capital. **Why (the refinement event):** 2026-07-18 I called the `check_cache_layout` DERIVED-write increment "dev-plane, light posture"; Caramel corrected — *"run the full readiness, it's correctness critical, it is the toolchain."* **Rule:** a fact-producer / shared-verifier / anything N consumers INHERIT → full ceremony, regardless of plane. The 2026-06-02 skill-prose case still stands and is not in tension: a leaf **CONSUMER** edit (skill markdown, a doc that only reads facts) is light; a **PRODUCER** the consumers read is not. The axis that flipped my read: "apparatus vs engine" is the wrong cut — "produces-facts-others-trust vs consumes-facts" is the right one.

**Second refinement (2026-07-19) — the KNOWLEDGE BASE is itself a fact-producer, so doc/ledger/ID rot ranks with engine debt, not below it.** Caramel, on folding the citable-ID triage into `E.1.2.B` `0.2`: *"tech debt building up in the workspace is almost worse than the actual engine code, because it leads to dated and rotted information, and we cant make decisions with that."* The 2026-07-18 carve-out covered fact-producing **tools**; this extends the same axis to the **content**. A stale MASTER banner, a `TECH_DEBT` ID cited but never defined, an ID enrolled twice with divergent meanings (`M9`; `D-1`..`D-13`) — each is a *wrong fact* that every downstream plan inherits, including the plans written to fix the engine. **Engine debt degrades the product; knowledge-base debt degrades the DECISION INPUTS**, and a decision made on rotted information is not recoverable by re-reading the code — you don't know to go look. It is also *quieter* than engine debt: a bad `[SIZE]` fails a gate, but an ambiguous `D-7` just silently resolves to whichever file the reader opened. **Rule:** treat SSoT-integrity work (ledger homing, ID uniqueness, index currency, disposition flipping) as load-bearing, not housekeeping — it earns real increment scope, not leftover time. This does NOT re-heavy leaf consumers: editing skill prose is still light. The cut stays produces-vs-consumes; what changed is recognizing that ledgers, indexes, and decision logs sit firmly on the *produces* side.
