## 1. CONFIRMED ground truth (the settled shape — do NOT re-litigate)

**The v10 per-node wire block = EXACTLY 1944 bytes**, 37 wire ops (36 `fwrite` == 36 `fread` + 1
confidence delegate call), in `CoreFrameworks/ShardedSnapshotPersist.hpp` save `:172-261` / load-read
`:436-488` / load-commit `:499-589`. Byte-order table (per-node-block-relative offsets):

- Rows 1-3 SCALAR (strategy_id / resolved_strategy_id / strategy_state_kind, u8 each) → **row 4 = 1B PAD** (zero-written)
- Rows 5-20 SCALAR (balances/counters/Money) — `node_dd_pct` is **row 20 @ off 172** (the v11 drop target)
- **Row 21 = BIT** (`node_kill_tripped` via `MASK_NODE_STATE_KILL_TRIPPED`, 1-byte extract) → **row 22 = 3B PAD** (zero-written)
- Row 23 SCALAR (node_ks_trips_total)
- Rows 24-30 = `regime_state` (7 fields, hand-inlined field-by-field, **NOT a registry today**) → 36B wire
- Rows 31-33 = `pnl_feeder` (`price_samples[8]` + head + count, hand-inlined) → 136B wire
- **Rows 34-36 = the 3 interleave doubles** (`staged`/`active`/`last_confidence`) @ wire off 368-392
- Row 37 = `confidence` **DELEGATE** (`ConfidenceScorer_FieldwiseWrite`, 7 registry rows) = 1552B

**The D-110 trap is real + pinpointed:** the 3 doubles sit at *struct* offset `ControllerEventLoop.hpp:347-349`
(BEFORE `node_peak_balance` `:467`) but at *wire* offset 368-392 (AFTER feeder, BEFORE confidence).
**Emission order = `fwrite`-call order, NOT struct-declaration order.** Any registry emitting struct
order silently hoists 24 bytes. The ordered registry must encode wire order by construction.

**Delegate sub-blocks are field-by-field, never blob** (blob diverges: regime 48B struct vs 36B wire;
confidence 528B/window blob vs 520B/window field-wise = +24B across 3 windows). This discipline is
load-bearing and currently correct.

**Commit dispositions:** `NO_COMMIT` set = **exactly `{strategy_id, strategy_state_kind}`** (the
v5.11.15 leak fields — read off wire for offset-correctness, deliberately not applied); every other
real field COMMITs. Confidence commit has a **derived-recompute tail** (`RecomputeRunningSums` @ `:588`)
for the off-wire `rmse.sum_squared_errors`. The ExecutionCore re-activation finalizer (`:618-687`)
stays hand-written OUTSIDE the registry (reads committed `resolved_strategy_id` + positions).

**The build shape (all 5 agents converge):**
- Tuple `X(NAME, TYPE, STORAGE_KIND, STORAGE_MASK, COMMIT_KIND)`; `STORAGE_KIND ∈ {SCALAR,BIT,PAD,DELEGATE}`,
  `COMMIT_KIND ∈ {COMMIT,NO_COMMIT}`; `STORAGE_MASK` overloaded = bit-mask (BIT) / delegate-family-token
  (DELEGATE) / pad-width (PAD) / 0 (SCALAR). **This is sufficient — NO H18 sidecar needed** for the
  current field set (kill = STORAGE_KIND=BIT, OMS-proven; recompute folds inside the DELEGATE).
- **`OmsFieldRegistry.hpp` is the RICHER precedent to mirror, not `NodeCtxInitRegistry.hpp`** — OMS already
  ships the full 4-phase PERSIST view (SAVE→DECLARE→READ→COMMIT, `:475-598`) + a persist count-lock
  (`_PERSIST_COUNT==10`, `:371-384`) + `static_assert(false)` forcing-functions for un-designed combos.
  The DECLARE→READ→COMMIT split is the structural key to NO_COMMIT (READ consumes wire bytes even when
  COMMIT no-ops → offset stays correct).
- `regime_state` + `pnl_feeder` → field-by-field sub-registries mirroring `FOREACH_CONFIDENCE_PERSIST_FIELD`,
  each with its own `_PERSIST_COUNT` static_assert (==7 regime, ==3 feeder, ==7 confidence — the last
  is MISSING today, must be added).
- **Persist-layout hash = the primary forcing function** (reuse `tt::fnv1a`, `FeatureRegistry.hpp:604-606`,
  walking `(name:type:kind)` per row + INTO delegates); count-locks are local tripwires.
- **Layered runtime gate** (I5): frozen hex-TEXT golden (masked header timestamp) + registry-driven
  full-poison distinct-per-field fixture + exact per-field value round-trip + positive control + wire-length

## Verdict: GO on the ship — but the forcing-function architecture is INVERTED from D-297/D1

**The wire reproduction is byte-sound** (A2: all 6 byte-identity claims SURVIVE; 1944B independently re-derived + probe-compiled). Byte-identical-to-v10 is achievable. **But the A-pass materially revises the SAFETY-NET architecture the synthesis locked (D-297/D1 = "layout-hash as PRIMARY forcing function").**

### The headline (A1 decisive, A4 corroborating): the hash is MIS-LABELED "primary" — INVERT it
- **A1 PROVED the constexpr hash compiles** (GCC 16.1.1 + clang 22.1.6, C++17, engine's real flags, IDENTICAL hash) with **~10x depth margin + ~2500x ops margin** — immune to registry growth (depth scales with longest field NAME, not row count). So I-gotcha #9 is resolved: the primitive is viable.
- **BUT its marginal value is NARROW**, and it carries a false-green cascade: because the hash checks the registry only against ITSELF, if built while ANY wire op is still hand-written (the 3 interleave doubles, or before macro-gen), it emits a **FALSE GREEN** — certifying self-consistency while the hand-written emitter drifts. Labeling it "primary" invites building it FIRST — exactly backwards.
- **The load-bearing PRIMARY trio (all proven OMS precedent, zero new risk):** (a) **macro-generated SAVE/READ/COMMIT** emitter (dropping a wire `fwrite` ⟺ dropping a row ⟺ caught — this is what actually closes finding-3b, the dropped delegate CALL, TRANSITIVELY, not the hash); (b) **per-registry `_PERSIST_COUNT` count-locks** (add the missing confidence `==7`, `regime ==7`, `feeder ==3`); (c) **frozen hex-TEXT golden** (the byte-truth net).
- **A4's structural teeth (the D-208/M7 close):** mechanically couple **golden↔version** — register the layout signature in `identifier_ledger.txt` next to `SHARDED_SNAPSHOT_VERSION` + add a **paired-bump rule** to `check_identifier_retirement.py` (signature changes ⟹ version MUST bump same-commit, else RED). Turns "regen the golden without bumping" from a convention into a mechanical RED. Applies regardless of whether the signature is the constexpr hash or a tool-computed digest.
- **The hash's ONLY marginal value over {macro-gen + count-lock + golden + paired-bump}** = compile-time detection of the count-neutral NAME-swap *before the test runs*. Narrow, and contingent on 3 spec-locks.

### If the constexpr hash is KEPT, 3 MANDATORY spec-locks (all A1-compile-proven)
1. **Per-row sequential `fnv1a(str, h)`** — NOT a single concatenated `"name:type:kind|…"` string (that recurses to depth = total length → RED build at default `-fconstexpr-depth=512`; the engine sets no override).
2. **Name-INCLUSIVE** — a type/size-only hash COLLIDES on this ship's exact v11 Money→Money swap (drop `node_dd_pct` + add `partner_pending_pnl` = MISS). The name is load-bearing, not decoration. (Accepts a false-positive on a cosmetic wire-neutral rename → needless golden regen; safe direction.)
3. **Walk-INTO delegates** — an opaque delegate token misses every sub-field drop.
Plus: build the hash ONLY AFTER macro-gen is complete (the false-green rule), and give failures a human-readable ledger dump, not a bare `static_assert(h==0x…)`.

### A1's simpler alternative (Option to weigh): DROP the constexpr hash
Replace it with a **Python codegen/CI layout-audit tool** (sibling to `check_meta_registry.py` / `check_identifier_retirement.py`): walks the registry text, emits a human-readable diff ("row `node_dd_pct` dropped, `partner_pending_pnl` added"), enforces name-inclusion + walk-into by construction, sidesteps the constexpr risk + spec-lock #1 entirely. Trade-off: loses "can't forget — it's in the build." Best-of-both = keep the compile-time COUNT-LOCK (in-build tripwire) + this tool (human-readable layout audit at the /readiness/ship gate) + the paired-bump.
