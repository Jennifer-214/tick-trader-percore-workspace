## Why this ship exists

1. **Math win** — Crypto markets are non-stationary; alpha decays; regime shifts. Thompson posterior sampling provides natural exploration via Bayesian updates → may outperform Exp3-IX (deterministic exponential weights) for adaptive arm selection. Worth paper-testing.

2. **Valid parallel-training via cfg=2** — discovered during pre-coding consult: this codebase grades each ensemble arm's prediction independently against actual price movement (see `CoreModelZoo.hpp:881-882` — `per-arm reward (direction match) → calls Bandit_Update`). That makes per-arm reward signal observable regardless of which arm was selected, eliminating the counterfactual problem that normally invalidates parallel-training designs. cfg=2 lets Thompson learn from same per-arm signal as Exp3 in parallel; CHOICES diverge over time; offline analysis answers "which algo would have driven better aggregate PnL."

3. **Future-proofing via FOREACH_BANDIT_ALGORITHM registry** — UCB1, EXP4, Bayesian linear bandit are all foreseeable next-step algorithms. Registry retrofit NOW means each future addition = 1 row + 1 compute fn. Per `feedback_overengineering_boundary_when_future_easier`.

4. **Adjacent debt absorbed** — TECH_DEBT-010 (FOREACH_CALIB_LOG_COL registry; closes via .D), TECH_DEBT-011 (PerCoreSnap layout discipline; substantially closes via .0), TECH_DEBT-027 (locale pinning gap in Bandit_SaveJSON; opportunistic in .C).

## Why both algorithms; why dual mode (revised with per-arm-reward insight)

| | Exp3-IX (current) | Thompson sampling (new) |
|---|---|---|
| Strategy | Exponential weights, deterministic | Bayesian, randomized |
| Best for | Stationary reward distributions | Non-stationary / noisy rewards |
| Convergence | Faster | Slower but more natural exploration |
| Replay determinism | Yes (deterministic update math) | Yes (seeded mt19937_64 + own Box-Muller) |
| Cost per slow-path cycle | ~50ns | ~80ns |
| Memory | ~0.5KB per BanditState | ~0.4KB per ThompsonBanditState |

**cfg=2 dual mode validity:** per-arm reward observability (each ensemble arm's prediction is independently graded against actual price; see `CoreModelZoo.hpp:881-882`) means both bandits can learn from the same per-arm signal stream simultaneously. Exp3 drives ACTUAL trading decisions; Thompson's chosen_arm is logged but doesn't act. Both update their state from the same per-arm reward observations. Their CHOICES diverge over time; offline analysis answers the A/B question.

This is the rare setting where shadow-training is mathematically valid (rewards observable for ALL arms each cycle, not only the selected one).

## Latency analysis

**Hot path:** UNTOUCHED. p99 ≤500ns target unaffected. Verified via `tools/calls_graph_diff.sh` post-ship.

**Slow path** (per ML cycle; budget 100µs):

| cfg | Cost | % of budget |
|---|---|---|
| 0 (Exp3 default) | ~5ns dispatch lookup overhead | 0.005% |
| 1 (Thompson only) | ~85ns (8 mt19937 draws + Box-Muller pairs + argmax) | 0.085% |
| 2 (Both) | ~140ns (Exp3 + Thompson + per-fill telemetry) | 0.14% |

**Cache:** unified bandit telemetry cluster occupies 3 cache lines (192 bytes per core). Writer-side invalidations: 1-3 lines per ML cycle depending on cfg. Reader-side fetches: 1-3 lines per GUI frame. ~60 cache misses/sec/core for cfg=1 or cfg=2 on reader side — negligible vs existing per-cycle write traffic.

**Replay determinism:** Thompson uses seeded mt19937_64 with cfg-set seed (default 42). Identical seed + identical reward sequence → identical sample sequence. **Own Box-Muller using raw `mt19937_64::operator()` 64-bit output** — NOT std::normal_distribution which is libstdc++-implementation-defined. SHA-256-locked sample-trace snapshot test in v5.14.10.A enforces cross-binary cross-version reproducibility.
