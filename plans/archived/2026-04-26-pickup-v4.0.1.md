want" questions for live testing.

  what live would behave like, set `starting_balance=10.0`.
- **`use_real_money`** — confirm this is `0` for paper. v4.0
  tested only paper mode tonight.
- **API keys** — only matter when `use_real_money=1`. Check whatever
  env var or cfg path the BinanceAdapter expects. Live trading was
  NOT exercised tonight; first live run is its own validation event.
- **`models/` directory** — doesn't exist yet (no models trained).
  Setting `core_N_strategy=ml` without a model loads zero models →
  ML_BuildParameters falls through to SimpleDip with `strategy_id=ML`.

- **`foxml_suite` config** — uses `backtest.cfg`, not `engine.cfg`.
  Editing per-core overrides in `engine_gui` Settings won't change
  backtest behavior. Different files by design.

## Production-ready checklist (before real money)

These should all be green before flipping `use_real_money=1`:

1. **Train a model end-to-end**, save it to `models/`, point
   `core_0_model_dir=models/<name>` in engine.cfg, restart engine_gui.
   Confirm Per-Core ML panel shows model loaded + non-zero predictions.
2. **30-min paper session** with mixed strategies (e.g., Core 0=DIP,
   Core 1=MR, Core 2=MOM, Core 3=ML if model trained). Confirm:
   - Trades fire on each core
   - Buy Gate panel shows per-core gates
   - Per-Core Strategy hot-swap can flip a core mid-session (when
     position closed)
   - Settings panel per-core edits actually take effect (TP/SL diff
     between cores)
3. **Shutdown stress** — Ctrl+C in terminal AND window-X separately.
   Both should kill within ~1s. If either hangs, there's another
   blocking sleep somewhere.
4. **Kill switch wiring** — set a tight `ks_max_drawdown_pct` (e.g.,
   2%), force a loss in paper mode, confirm cores stop trading. Then
   restart and confirm KS state resets correctly.
5. **Notify** — set `notify_command=` to something audible, force a
   trade, confirm alert fires.
6. **Reconnect** — disconnect Wi-Fi for 10s while running, confirm
   engine reconnects + alert fires.

## What I'm watching for in the next session

If anything weird shows up, these are my first suspects:

- **Hot path latency regressed?** v4.0.1 added ~1ns to BG_Evaluate
  (branchless direction select). p99 was 40-400ns before. Should
  still be well under 500ns. If it's now 1000ns+, something else
  broke.
- **ML core not firing?** Most likely: model_handle is null (model
  failed to load). stderr shows the load result at boot — check that.
- **Per-core overrides not taking?** Hot-reload is wired but the
  rebuild only happens once per slow-path cycle (default 8 ticks).
  Wait a few seconds after editing.
- **Settings panel shows stale values?** Settings_Load runs once on
  first frame. If you edited engine.cfg externally, restart
  engine_gui to re-load.
