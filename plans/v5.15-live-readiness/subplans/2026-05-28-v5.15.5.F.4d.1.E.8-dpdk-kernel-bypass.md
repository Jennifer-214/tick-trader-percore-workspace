# v5.15.5.F.4d.1.E.8 — DPDK / Onload kernel-bypass networking

**Status:** v0.1 DRAFT.
**Risk:** HIGH (substantial restructure; userspace TCP/IP; hardware NIC poll)
**Effort:** ~10-14 days focused
**Hot path:** TOUCHED (entire I/O substrate)

---

## TL;DR

**End-game on commodity hardware.** Replace kernel-side I/O (io_uring + kTLS from `.E.4`) with full userspace networking via DPDK (Data Plane Development Kit) OR Onload (Solarflare's transparent userspace TCP). ~5× tick-to-wire latency improvement (~10-20μs → ~3-5μs).

**Three major changes:**

1. **Userspace TCP/IP stack.** DPDK provides primitives; engine builds minimal TCP/IP on top OR uses Onload's transparent socket interception.

2. **Hardware NIC poll mode.** NIC RX/TX rings polled directly from userspace (no kernel context switch; no interrupts).

3. **TLS in userspace** (since kTLS bypassed). Hand-rolled TLS 1.3 + AES-GCM in userspace (or OpenSSL with custom socket BIO that goes to DPDK).

**This is the practical limit on commodity x86_64.** Below ~3-5μs tick-to-wire requires custom hardware (FPGA / smart NIC ASIC).

---

## Decision: DPDK vs Onload

**DPDK:**
- Open-source; vendor-neutral (Intel + Mellanox + others)
- Substantial engineering investment (rewrite networking layer)
- Maximum control + tunability
- ~2 weeks engineering

**Onload (Solarflare/AMD):**
- Proprietary; requires Solarflare hardware
- Transparent socket interception (LD_PRELOAD; no code change)
- Quick integration
- ~1 week engineering
- Hardware vendor lock-in

**Decision: DPDK preferred for open-source AGPL alignment; Onload fallback if Solarflare hardware available.**

Operator chooses via cfg: `networking.userspace_stack = kernel | dpdk | onload`. Cfg-driven fallback if hardware unavailable.

## Architecture deep-dive

### DPDK initialization + per-node queues

```cpp
// CoreFrameworks/DPDKNetworking.hpp (NEW)

struct DPDKEnvironment {
    uint16_t num_ports;
    uint16_t num_queues_per_port;
    rte_mempool* mbuf_pool;                  // packet buffer pool
};

int DPDK_Init(int argc, char** argv) {
    // Initialize DPDK EAL (Environment Abstraction Layer)
    int ret = rte_eal_init(argc, argv);
    if (ret < 0) return -1;

    // Configure NIC ports (typically just port 0)
    uint16_t port_id = 0;
    rte_eth_conf port_conf = {};
    port_conf.rxmode.mq_mode = RTE_ETH_MQ_RX_RSS;     // Receive Side Scaling
    port_conf.rx_adv_conf.rss_conf.rss_hf = RTE_ETH_RSS_TCP | RTE_ETH_RSS_UDP;

    rte_eth_dev_configure(port_id, MAX_NODES, MAX_NODES, &port_conf);

    // Per-node RX/TX queues
    for (uint16_t q = 0; q < MAX_NODES; ++q) {
        rte_eth_rx_queue_setup(port_id, q, 1024,
                                rte_eth_dev_socket_id(port_id), nullptr, mbuf_pool);
        rte_eth_tx_queue_setup(port_id, q, 1024,
                                rte_eth_dev_socket_id(port_id), nullptr);
    }

    rte_eth_dev_start(port_id);
    return 0;
}

// Per-node trading flow uses own RX/TX queues
struct NodeDPDKContext {
    uint16_t port_id;
    uint16_t queue_id;                        // matches node_id
    rte_mempool* mbuf_pool;

    // Userspace TCP/IP state per-node
    TCPState tcp_state;
    UserspaceTLSState tls_state;
};

// Submit via DPDK (replaces io_uring send)
int DPDK_SendTCPPayload(NodeDPDKContext* ctx, const void* data, size_t len) {
    rte_mbuf* mbuf = rte_pktmbuf_alloc(ctx->mbuf_pool);

    // Build TCP segment + TLS-encrypt payload + Ethernet header
    UserspaceTCP_BuildSegment(&ctx->tcp_state, &ctx->tls_state, mbuf, data, len);

    // Send (zero-copy; hardware DMA)
    uint16_t nb_sent = rte_eth_tx_burst(ctx->port_id, ctx->queue_id, &mbuf, 1);
    if (nb_sent != 1) {
        rte_pktmbuf_free(mbuf);
        return -1;
    }
    return 0;
}

// Per-node poll for incoming packets
void DPDK_PollRX(NodeDPDKContext* ctx, NodeState<F>& node) {
    rte_mbuf* bufs[BURST_SIZE];
    uint16_t nb_recv = rte_eth_rx_burst(ctx->port_id, ctx->queue_id, bufs, BURST_SIZE);

    for (uint16_t i = 0; i < nb_recv; ++i) {
        // Parse Ethernet + IP + TCP + TLS-decrypt
        const void* payload;
        size_t payload_len;
        UserspaceTCP_HandleSegment(&ctx->tcp_state, &ctx->tls_state, bufs[i],
                                   &payload, &payload_len);

        // Dispatch payload to node's WS frame handler
        WSFrame_HandleRecv(node, payload, payload_len);

        rte_pktmbuf_free(bufs[i]);
    }
}
```

### Userspace TLS

```cpp
// CoreFrameworks/UserspaceTLS.hpp (NEW)

struct UserspaceTLSState {
    // TLS 1.3 state machine
    enum { HANDSHAKE_INIT, HANDSHAKE_DONE, ESTABLISHED } state;

    // Session keys (after handshake)
    uint8_t client_write_key[32];
    uint8_t server_write_key[32];
    uint8_t client_iv[12];
    uint8_t server_iv[12];

    // Record sequence numbers
    uint64_t client_seq;
    uint64_t server_seq;
};

// TLS 1.3 record encrypt (AES-GCM)
int UserspaceTLS_EncryptRecord(UserspaceTLSState* tls,
                                const void* plaintext, size_t plaintext_len,
                                void* ciphertext, size_t* ciphertext_len) {
    // AES-GCM with client_write_key + IV derived from client_iv XOR client_seq
    uint8_t nonce[12];
    memcpy(nonce, tls->client_iv, 12);
    *(uint64_t*)(nonce + 4) ^= htobe64(tls->client_seq);

    // Use hardware AES-NI for encryption (~1-3μs for typical record)
    AES_GCM_Encrypt(tls->client_write_key, nonce, plaintext, plaintext_len, ciphertext);

    tls->client_seq++;
    return 0;
}
```

### Cfg-driven networking stack selection

```cpp
// engine.cfg:
// networking.userspace_stack = kernel | dpdk | onload

enum NetworkingStack {
    NETWORKING_KERNEL,    // io_uring + kTLS (from .E.4)
    NETWORKING_DPDK,      // DPDK userspace
    NETWORKING_ONLOAD,    // Solarflare Onload (transparent)
};

void Engine_InitNetworking(NetworkingStack stack) {
    switch (stack) {
        case NETWORKING_KERNEL:
            // .E.4 path; existing
            EngineInit_PrewarmTlsSessions();
            break;
        case NETWORKING_DPDK:
            // Initialize DPDK environment
            DPDK_Init(0, nullptr);
            // Per-node DPDKContext
            for (each node) {
                DPDK_SetupNodeContext(&node->dpdk_ctx);
            }
            break;
        case NETWORKING_ONLOAD:
            // Onload is transparent; sockets work normally
            // Just LD_PRELOAD onload library at startup
            // Standard socket() calls intercepted; routed via Onload userspace stack
            break;
    }
}
```

## Honest risks

### R1 — DPDK substantial engineering investment
Userspace TCP/IP is non-trivial; many edge cases.

**Mitigation:** Start with minimal TCP (just what exchange protocols need); incremental complexity; comprehensive test suite.

### R2 — NIC hardware compatibility
Not all NICs support DPDK well; performance varies.

**Mitigation:** Test on operator's actual hardware; document supported NICs in DEPLOYMENT_GUIDE; cfg fallback to kernel.

### R3 — Userspace TLS correctness
Reimplementing TLS is RISKY; cryptographic bugs catastrophic.

**Mitigation:** Use OpenSSL with custom BIO that goes to DPDK (delegates crypto to OpenSSL); only handshake state machine in custom code; thoroughly tested.

### R4 — Debugging difficulty
Userspace networking is opaque; no kernel tcpdump.

**Mitigation:** DPDK rte_pdump or custom packet capture; latency tracing via TSC; thorough integration tests.

### R5 — Resource consumption
DPDK requires hugepages + dedicated CPU cores + isolated.

**Mitigation:** Production-mode topology config; documented requirements; refuses start if resources unavailable.

### R6 — AGPL compatibility
DPDK is BSD-licensed; AGPL-compatible. Verify.

**Mitigation:** License audit at integration time.
