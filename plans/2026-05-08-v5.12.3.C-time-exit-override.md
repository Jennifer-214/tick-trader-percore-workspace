## Theme

Add `cfg.core_<N>_time_exit_ticks` per-core overrides, supplementing
the existing global `cfg.time_exit_ticks`. Allows different strategy
holds per core (e.g., AUTO-mode core might hold longer than DIP core
in a mixed paper-test). Aligns with Phase 4's mixed paper-test
strategy comparison.

---

## Implementation (single-step, no sub-tags)

### Step 0: Cfg field

Add to `CoreFrameworks/ControllerConfig.hpp` adjacent to the
`core_risk_pct[16]` array at `:654`:

```cpp
// v5.12.3.C: per-core time-exit override.
// 0 = use global cfg.time_exit_ticks (default; preserves current behavior).
// >0 = override; this core exits after this many ticks regardless of strategy default.
int core_time_exit_ticks[16];   // MAX_EXECUTION_CORES
```

Defaults init at `:1176` area:
```cpp
for (int i = 0; i < 16; ++i) cfg.core_time_exit_ticks[i] = 0;  // 0 = use global
```

Cfg parser at `:1396` area — mirror existing `core_<N>_risk_pct`
parser pattern. Parse `core_<N>_time_exit_ticks=<int>`.

### Step 1: Read override in `EventLoop_TimeExitOneCore`

Site: `CoreFrameworks/ControllerEventLoop.hpp:2641`. Modify the
existing time-exit predicate:

```cpp
// v5.12.3.C: per-core override before falling back to global
int max_age_ticks = cfg.core_time_exit_ticks[c];
if (max_age_ticks == 0) max_age_ticks = cfg.time_exit_ticks;
// ... existing code uses max_age_ticks instead of cfg.time_exit_ticks
```

Branchless if compiler vectorizes the `cmov` (likely yes — single
predicate). Otherwise one branch per core-cycle on slow path
(acceptable; not hot path).

**Tick basis check** (v5.11.65 awareness): `EventLoop_TimeExitOneCore`
operates on the engine tick counter, not wall-clock. v5.11.65 added
`Position.entry_timestamp_us` for wall-clock hold across restart;
that's a SEPARATE concept (display + cross-restart continuity).
This ship's override stays on the existing tick basis (consistent
with how `cfg.time_exit_ticks` is interpreted today).

### Tests (+3)

1. Per-core override fires at correct tick (core 2 hold = 5000
   ticks, others = global 1000 — verify core 2 holds correctly)
2. Per-core 0 → global behavior preserved (default unchanged)
3. Mixed cores (some override, some don't) all work independently

### Verification gate

- All tests pass
- Default cfg (all overrides = 0) → bytewise output preserved on
  10M-tick replay
- Operator-validation: paper-trade with mixed cores
  (`core_0_time_exit_ticks=500`, `core_1_time_exit_ticks=2000`,
  others default) — exit-time histograms differ correctly
