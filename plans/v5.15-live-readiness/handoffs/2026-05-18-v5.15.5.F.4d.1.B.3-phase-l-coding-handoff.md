## § 5. Pre-coding concerns (NOT blocking — observations during coding)

### 5.1 Wire-format byte preservation under Phase L X-macro auto-gen

Phase L uses framework's `populate_stamp_cfg_from_derived` which is byte-preserving by construction. Step 1.6.4 CHANGES THE EMIT SOURCE from caller-supplied `inf` to engine-side `cfg`. Tests that pre-populated `inf` need migration to cfg setup. **Sister benefit:** extensibility test pattern REPLACES those tests with X-macro walker that auto-validates per-row round-trip; net effect is test consolidation, not just migration.

### 5.2 CLI flag naming reconciliation at L2 coding-time

Bash script `tools/stamp_model.sh:109-147` uses kebab-case flags; master cfg registry uses snake_case. Decision deferred to L2 coding-time. Recommended: standardize on snake_case + deprecation alias layer in CLI binary main() that translates kebab→snake with one-line stderr warning. Operator scripts using legacy kebab flags continue working during retention (TECH_DEBT-110 deletion target).

**Verify first via:** read `tools/stamp_model.sh:109-147` getopt loop to enumerate which flags are kebab vs snake.

### 5.3 Stamp body source-of-truth semantic shift (inf → cfg)

When Step 1.6.4 migrates emit from inf-driven to cfg-driven:
- **Pre-migration:** "Stamp captures whatever the CALLER populated in inf" (test-friendly)
- **Post-migration:** "Stamp captures whatever's in cfg at emit time" (production-correct; cfg IS the source of truth)

Per `DESIGN_SPECS/framework-patterns/cfg-derived-consumer-framework.md` v1.3 § "Emit-side source-of-truth discipline". Tests that pre-set inf for migrated consumers will silently pass build BUT may produce false-positive test pass when checking stale inf values vs cfg-at-emit-time values.
