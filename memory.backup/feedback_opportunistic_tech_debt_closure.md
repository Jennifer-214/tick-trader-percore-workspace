When new work touches a surface that ALSO carries tracked tech-debt, the close-vs-leave call is decided by **marginal cost / subsumption — NOT mere surface-adjacency**:

- **SUBSUMED / trivially-completed** — the new work already did ~90%, you built the primitive, closing it is ≈zero extra cost → **CLOSE it in the same ship.** Leaving an easy close open is just deferred debt ([[feedback_no_defer_for_effort]]).
- **Merely ADJACENT** — same surface / same theme, but a *distinct* deliverable with its own code + test + trigger → **cross-link + leave tracked + refresh the entry.** Force-closing every adjacent item is how a focused task balloons.

**Why this framing, and what it is NOT:**
- NOT "the `.E` plan closes every tech-debt item" — that balloons `.E` (82 OPEN items; `.E` is foundational rework, per [[project_e_series_is_vision_convergence_not_scope_balloon]]).
- NOT a new "scan at close" rule — `/readiness` **Check 25** already scans the ship's surface-area tech-debt at close and forces an explicit decide. This is the sharper DURING-the-work trigger layered on top: of the items Check 25 surfaces, the *subsumed* ones get closed now, the *distinct* ones get tracked.
- It is the considered answer to "should every subplan close as much tech-debt as possible?" → yes, but bounded by subsumption, not adjacency.

**Worked examples (the dead-code / identifier-retirement codification, 2026-06-02):**
- **CLOSED (subsumed):** the dead `fp2_to_mag_fpn` helper — removing it was zero-marginal-cost while already editing `FixedPointN.hpp`. Closed in the same pass.
- **LEFT TRACKED (adjacent):** `TECH_DEBT-151` #8 (promote `calls_graph_diff` to a pre-commit orphan-guard) — same pre-commit surface + same dead-code theme as the new Check H, but a DISTINCT guard (function-orphans ≠ identifier-reuse), its own negative-self-test, and a specific `.E.1`-prep trigger (it must exist *before* `.E.1`'s orphan-generating rename). Cross-linked (renumbered to Check I) + left tracked — NOT force-closed.
- **LEFT TRACKED (adjacent):** `TECH_DEBT-152` (enroll bitmap bits + cfg-field names into the identifier guard) — distinct parser branches; paced enrollment per [[feedback_close_the_class_vs_migrate_every_site]].

**BIDIRECTIONAL — the discriminator also governs DEFER-the-NEW-fix, not just CLOSE-the-tracked-item (added 2026-06-11):** the subsumption-not-adjacency test decides whether a NEWLY-FOUND fix may DEFER to a later plan, exactly as it decides whether to close an existing tracked item.
- **SUBSUMED → defer is legitimate** — the later plan's DESIGN would REDO this exact fix (replaces / re-derives the thing), so doing it now = do-it-twice. A genuine separate deliverable with a pre-existing design. (e.g. parser decimal-exactness IS the D-123 venue-ingest rework.)
- **DURABLE → close NOW** — the later plan merely CARRIES the fix THROUGH: it renames/relocates it (the `.E.1` Core→Node rename does this to ALL ~100 files) but does NOT redo it. A durable fix is NOT subsumed; deferring it saves nothing and just accumulates capital debt. (e.g. a single-source helper, a captured return-value, a sign-clamp guard — `.E.1` would just rename them.)
- **The test:** *"would the later plan's DESIGN REDO this fix, or CARRY IT THROUGH?"* — NOT "does the plan edit this file?" Surface-overlap ("the rework touches restore / FlattenAll / parser") is ADJACENCY — the #1 false defer-license. Folding the finding into the plan is TRACKING ([[feedback_fold_findings_into_destination_plan]]); it does NOT defer the fix.

**STRUCTURE/FUNCTION adjacency, NOT file-location, is the INCLUSION boundary (added 2026-06-15, the A6 trainer-floor fold-in):** the marginal-cost/subsumption test operates on whether the candidate shares the ship's STRUCTURE + FUNCTION — the same predicate, the same concern, the same guard — at ~zero marginal cost; it does NOT stop at the file/directory boundary. A6's trainer-emit floor (`StampHelper.hpp`, producer-side) is a DIFFERENT file from the A6 ingress (`CoreModelZoo.hpp`, consumer-side), yet it calls the SAME `barrier_is_corrupt` predicate for the SAME corrupt-model-guard purpose → SUBSUMED by structure+function (the 3rd call site is ~zero marginal cost) → it FOLDS INTO the A6 ship. Drawing the in-scope line at file-location would have left the producer seam un-guarded (a corrupt model could still be EMITTED), splitting ONE concern across two ships for no reason. The test is *"same structure+function, ~zero marginal cost?"* — NOT *"same file?"*. This is the INCLUSION-direction complement of the subsumption test (the rest of this memory governs CLOSE-vs-leave + DEFER-vs-now; this governs PULL-IN-vs-leave-for-its-own-ship). Operator: *"we should probably fold this in because it's technically adjacent by structure and function."* Sister: [[feedback_single_source_of_truth_discipline]] (the shared predicate IS why it's one concern).

**Sprint-purpose lens (`.E`):** the `.E` sub-sprint EXISTS to shift to a durable long-horizon architecture, CLOSE OUT tech debt, and IDENTIFY+PATCH failure points. Newly-found capital-bug fixes left OPEN on an adjacency-defer directly contradict the sprint's own thesis — the findings ARE the failure points `.E` is for. Default = CLOSE; defer carries the burden of proving genuine subsumption.

**Worked ANTI-example (the rule getting IGNORED — the 2026-06-11 codification trigger):** the `.E.0.10` Net-1 adversarial money-hunt found 8 capital findings; the agent DEFERRED all 8 to `.E.1`/D-123 citing "the rework touches that surface" = pure ADJACENCY. Operator caught it twice ("we arnt leaving tech debt open are we?" + "the whole point of `.E` is closing debt + patching failure points"). Re-test under durable-vs-subsumed: only A2/A4 decimal-exactness is genuinely SUBSUMED by D-123's pre-existing design (defer + data-loss-stop now); A1/A3/A5/A6/A7/A8 are DURABLE → closed in-ship. The fold-into-the-plan (correct tracking) had been mistaken for fix-defer.

**How to apply:** when `/readiness` Check 25 surfaces surface-area tech-debt at a ship, classify each — subsumed → close now; adjacent → cross-link + refresh. Don't leave a subsumed item open; don't force-close a distinct one. Sister to [[feedback_future_headache_vs_optimization_scope_framework]] (close anti-pattern instances at ship; defer pure-perf) and [[feedback_design_once_maintain_forever]] (design once — and that includes closing the easy adjacent debt while you're there).
