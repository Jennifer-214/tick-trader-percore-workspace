But the **shape of the bug** is broader — a recurring Class 21 instance at the consumer-template-fn level. Plan body Phase D Step 0.5d.d patches THIS instance; the structural fix prevents the recurrence class.

### Recurrence vectors

Drift will recur every time:

1. **New consumer template fn added** (e.g., future `reconcile_from_derived`) — author must remember to walk all 4 registries; sister-cohort discipline operator-memory-dependent
2. **New registry added to the cohort** (e.g., future `FOREACH_LIFECYCLE_CFG_FLAG` with STAMP_BOUND_CFG_DERIVED rows) — all existing consumers need new walker; sister-extension operator-memory-dependent
3. **New metadata bit activates a new cohort** (e.g., AFFECTS_STAMP_PARITY for training-side stamps) — new family of consumers needs same coverage discipline

The bug existed at HEAD because incremental ship-by-ship extension (`.B.1`: 2 walkers per consumer; `.B.2`: extended populate_stamp + drift_check with ml_cfg_flag; `.B.3`: extended populate_stamp with gate_cfg_flag) didn't apply the discipline uniformly. populate_inf fell behind in 2 ships' worth of extensions.

## 2. Class 21 closure precedent in this codebase

Per `DOCS/RECURRING_BUG_PATTERNS.md` Class 21 (line 1371-1404): "Multiple parallel descriptors for similar surfaces." The canonical closure shape is **ONE single source of truth + many consumer views that walk it uniformly** with compile-time enforcement.

**Reference precedent — Class 18/21 closure at boot/backtest/hot-swap surfaces (v5.14.2.E.1):**

> The class extinguished structurally for the model-load surface area by v5.14.2.E.1's `EnsembleModelZoo_PostLoadSetup` + `CoreModelZoo_PostLoadSetup` helpers + `FOREACH_ENSEMBLE_POST_LOAD` / `FOREACH_SINGLE_ZOO_POST_LOAD` X-macro registries. Adding a new post-load step is ONE line in the registry; boot, backtest, hot-swap inherit automatically. Compile-time enforced inclusion at all sites; bypass impossible.

Same shape applies to the cfg-derived consumer drift. The structural fix is an action-parameterized walker macro family where the meta-macro is the single source of truth for cohort coverage; consumers can't omit a registry because the meta-macro expands to all 4 walker invocations regardless of consumer.

## 3. Pattern shape (the proposed fix)

**Build a parameterized X-macro walker family in `MemHeaders/CfgGateRegistry.hpp`** that abstracts the 4-registry walk + per-row gate logic into a shared mechanism; consumers supply per-row action macros via token-paste-by-naming-convention.

```cpp
// In MemHeaders/CfgGateRegistry.hpp — NEW walker macro family

// Per-scope X-macro names follow convention: X_<CONSUMER>_<SCOPE>
// where SCOPE ∈ {PER_CORE, GLOBAL, ML_CFG_FLAG, GATE_CFG_FLAG}

// Meta-macro — single source of truth for STAMP_BOUND_CFG_DERIVED cohort coverage:
// Consumer passes BASE token (e.g., X_INFERENCE_CFG_POPULATE); macro pastes the 4 scope suffixes.
#define FOREACH_STAMP_BOUND_DERIVED_COHORT(BASE_X_MACRO)                            \
    FOREACH_PER_CORE_CFG_FIELD(BASE_X_MACRO##_PER_CORE)                             \
    FOREACH_GLOBAL_CFG_FIELD(BASE_X_MACRO##_GLOBAL)                                 \
    FOREACH_ML_CFG_FLAG(BASE_X_MACRO##_ML_CFG_FLAG)                                 \
    FOREACH_GATE_CFG_FLAG(BASE_X_MACRO##_GATE_CFG_FLAG)

// Structural enforcement: consumer MUST define all 4 X-macros (PER_CORE / GLOBAL / ML_CFG_FLAG /
// GATE_CFG_FLAG) for FOREACH_STAMP_BOUND_DERIVED_COHORT to compile. Missing any X-macro = compile error
// at that FOREACH expansion site. Drift impossible.
```

**Naming convention note:** `FOREACH_STAMP_BOUND_DERIVED_COHORT` matches codebase convention (`FOREACH_*` for X-macro registries) rather than `WALK_*` as initially sketched. Could enroll in `FOREACH_REGISTRY` meta-registry per H15 + H19 if treated as a meta-walker.

### Per-consumer X-macro definitions (the action functors)

Each consumer defines 4 X-macros following the naming convention. Internal body identical to current per-consumer-per-registry walker (verbatim):

```cpp
// Consumer 1: populate_inference_cfg_from_derived
template <unsigned F, typename InfT>
inline void populate_inference_cfg_from_derived(InfT& inf, const ControllerConfig<F>& cfg) {
    (void)inf; (void)cfg;

    #define X_INFERENCE_CFG_POPULATE_PER_CORE(STORAGE_T, KIND_TOKEN, name, label, section, meta, payload, tooltip, applies_strat, applies_op, applies_regime, applies_risk, lives_in_struct) \
        if constexpr (((meta) & CfgFieldDescriptor::STAMP_BOUND_CFG_DERIVED) != 0) {           \
            constexpr size_t _idx = FIELD_IDX_PER_CORE_##name;                                  \
            const bool _gate = cfg_gate::lookup_populate(_idx, /*is_per_core*/true, cfg);       \
            tt::cfg_populate_inf_field(cfg.name, inf.name, inf.has_##name, _gate);              \
        }

    #define X_INFERENCE_CFG_POPULATE_GLOBAL(STORAGE_T, KIND_TOKEN, name, label, section, meta, payload, tooltip, applies_strat, applies_op, applies_regime, applies_risk, lives_in_struct) \
        if constexpr (((meta) & CfgFieldDescriptor::STAMP_BOUND_CFG_DERIVED) != 0) {           \
            constexpr size_t _idx = FIELD_IDX_GLOBAL_##name;                                    \
            const bool _gate = cfg_gate::lookup_populate(_idx, /*is_per_core*/false, cfg);      \
            tt::cfg_populate_inf_field(cfg.name, inf.name, inf.has_##name, _gate);              \
        }

    // NEW per refactor: ml_cfg_flag bitmap-bit walker (currently MISSING at HEAD)
    #define X_INFERENCE_CFG_POPULATE_ML_CFG_FLAG(NAME, legacy_field, display_label, section, metadata_flags, doc) \
        if constexpr (((metadata_flags) & CfgFieldDescriptor::STAMP_BOUND_CFG_DERIVED) != 0) { \
            const int _bit_val = BITMAP_IS_SET(cfg.ml_cfg_flags, MASK_ML_CFG_##NAME) ? 1 : 0;  \
            inf.has_##legacy_field = 1;                                                         \
            inf.legacy_field = _bit_val;                                                        \
        }

    // NEW per refactor: gate_cfg_flag bitmap-bit walker (currently MISSING at HEAD)
    #define X_INFERENCE_CFG_POPULATE_GATE_CFG_FLAG(NAME, legacy_field, display_label, section, metadata_flags, doc) \
        if constexpr (((metadata_flags) & CfgFieldDescriptor::STAMP_BOUND_CFG_DERIVED) != 0) { \
            const int _bit_val = BITMAP_IS_SET(cfg.gate_cfg_flags, MASK_GATE_CFG_##NAME) ? 1 : 0; \
            inf.has_##legacy_field = 1;                                                         \
            inf.legacy_field = _bit_val;                                                        \
        }

    FOREACH_STAMP_BOUND_DERIVED_COHORT(X_INFERENCE_CFG_POPULATE)

    #undef X_INFERENCE_CFG_POPULATE_PER_CORE
    #undef X_INFERENCE_CFG_POPULATE_GLOBAL
    #undef X_INFERENCE_CFG_POPULATE_ML_CFG_FLAG
    #undef X_INFERENCE_CFG_POPULATE_GATE_CFG_FLAG
}
```

Consumer 2 (`populate_stamp_cfg_from_derived`) + Consumer 3 (`drift_check_from_derived`) follow same shape — each defines 4 X-macros + invokes `FOREACH_STAMP_BOUND_DERIVED_COHORT(X_<base>)` once. Current populate_stamp_cfg per-registry walker bodies (lines 263-321) become the X-macro bodies verbatim; current ml_cfg_flag walker for drift_check (line 383) becomes that X-macro's body. The missing walkers (ml_cfg_flag + gate_cfg_flag for populate_inf; gate_cfg_flag for drift_check) get NEW X-macros following the same shape.

### Why structural enforcement actually works

The compile-time enforcement is **token-paste-by-convention**: `FOREACH_STAMP_BOUND_DERIVED_COHORT(X_INFERENCE_CFG_POPULATE)` expands to four `FOREACH_<REGISTRY>(X_INFERENCE_CFG_POPULATE_<SCOPE>)` invocations, where each FOREACH then invokes the named X-macro. If the consumer doesn't define `X_INFERENCE_CFG_POPULATE_ML_CFG_FLAG`, the preprocessor expansion produces undefined identifier in the macro body — **compile error at the FOREACH expansion site**.

Drift impossibility:
- Consumer **cannot** silently skip a registry. The meta-macro expands to 4 walker invocations unconditionally.
- The 4 X-macros must exist by naming convention. Missing one = compile fail.
- The X-macros themselves can be no-op for legitimate skip-cases (consumer documents rationale), but the skip is EXPLICITLY VISIBLE.

## 4. Alternatives considered

**Alternative β1: Single C++ template fn parameterized by an Action functor (no X-macro).** Requires runtime field access via descriptor offset → re-introduces Class 23 anti-pattern (typed access via offset). REJECTED.

**Alternative β2: Three independent walker bodies + CI tool checking coverage parity.** What my prior session-E proposal was. Adds discipline layer + CI tool; drift catchable but possible. The action-parameterized walker is structurally simpler AND prevents the bug class. REJECTED per Class 21 closure precedent.

**Alternative β3: Refactor to use `CFG_FIELD_FOR_EACH_SET_BIT` (per `metadata-bit-driven-derived-filter-framework.md` Option E).** Works for runtime-typed access (GUI render reads descriptor metadata). Doesn't apply to cfg-derived consumers needing compile-time field access (cfg.name / inf.name / handle.name). REJECTED per type-safety constraint.

**Alternative β4: Manual sister-extension only (the option α from prior consult).** Extend populate_inf + drift_check to walk missing registries; no walker family. Patches THIS instance; future drift catchable only by audit discipline. REJECTED per `feedback_structural_fix_for_recurring_class`.

## 6. Risk + mitigation

| Risk | Mitigation |
|---|---|
| Wire-format byte preservation under refactor (populate_stamp_cfg is the load-bearing emit walker) | X-macro bodies are VERBATIM copies of current walker bodies; emit order preserved by FOREACH walker semantics (same registry → same order); Layer 5b invariants `tests/wire_format_invariants.hpp` I1-I5 catch any regression; Step 1.6.7.5 v1 LOAD test catches HMAC drift |
| Per-scope X-macro signature mismatch (per-core/global have 13-tuple; ml_cfg_flag/gate_cfg_flag have 6-tuple) | Per-scope X-macros take per-scope signature verbatim; the action functor IS scope-specific; matches current walker-body-per-scope pattern at HEAD (populate_stamp_cfg lines 263/278/297/313) |
| Preprocessor naming convention fragility (typo in BASE token = silent dispatch to undefined macros) | Compile-time error at FOREACH expansion site catches typos immediately; very low risk |
| Macro expansion debuggability | `#undef` at end of each consumer fn limits macro scope; compiler error messages identify the FOREACH site cleanly; X-macros are domain-standard in this codebase |
| Step 0.5d.d obviation (Task #3 sub-step) | The refactor INCLUDES the gate_cfg_flag walker addition for populate_inf + drift_check; Step 0.5d.d sub-steps .b/.c (parser dispatch + consumer migration decision) remain separate concerns |

1. **Per-scope X-macro signature handling** — per-core/global X-macros take 13-tuple signature; ml_cfg_flag/gate_cfg_flag take 6-tuple signature. Per-scope X-macro definitions vary by signature shape. This matches current per-registry walker structure at HEAD (populate_stamp_cfg has 4 separate X-macro walkers with per-registry signatures) — not a new concern, just scoped-out implementation detail.

2. **Naming convention** — `FOREACH_STAMP_BOUND_DERIVED_COHORT` matches codebase convention (`FOREACH_*` for X-macro registries) and is the recommended name. Alternative `WALK_ALL_STAMP_BOUND_DERIVED` was initial sketch but breaks naming convention. CLAUDE.md table mentions `FOREACH_*` registry-shaped artifacts get enrolled in `FOREACH_REGISTRY` per H15 + H19; this meta-macro likely qualifies.
