## DOD analysis

### Cluster placement
- DriftOverride: 8 bytes; cache-line packs 8 entries per 64B line → dense per-FIELD_IDX array
- `g_global_drift_overrides[FIELD_IDX_GLOBAL_END]` + `g_per_core_drift_overrides[FIELD_IDX_PER_CORE_END]` — dense arrays (mostly zero-init); ~2KB total for 213 fields × 8 bytes; fits in L1
- RegistryRosterEntry: 40 bytes; ~2 entries per cache line; ~25 rows × 40 bytes ≈ 1KB
- ManualFieldInventoryEntry: 24 bytes; ~2.5 entries per cache line

### Branchless dispatch
- Sidecar lookup: array index + mask-compute (H20-compliant)
- Default-on-zero semantic: `has_override = 0` → use defaults; `has_override = 1` → use sidecar values; branchless via `(value & override_mask) | (default & ~override_mask)`

### Cache layout
- All 3 bit-packed structs are read-only static; constant-pool placement
- Sidecar arrays accessed during drift check (slow path); ~213 entries × 8 bytes = 1.7KB; warm in L1 after first drift check

### Bit-packing per H14
- DriftOverride.flags: 5 bits used / 3 bits reserved (severity + category + compare_kind + has_override packed)
- RegistryRosterEntry.flags: 6 bits used / 2 bits reserved (LEVEL 4-bit + WIRE_FORMAT_KIND 2-bit)
- ManualFieldInventoryEntry.kind: 3 bits used / 5 bits reserved (CATEGORY 3-bit; future expansion via reserved bits)
