# v5.9.5c — Bash CLI parity for stamp body inference cfg

**Date:** 2026-05-02
**Branch:** `feat/v5.9-ml-hardening`
**Predecessor:** v5.9.5b (in-process emit wired)
**Effort estimate:** ~1.5h
**Hot path:** UNTOUCHED (CLI tool + tests only)

## Context

v5.9.5b closed the in-process emit gap: `Backtest_RunFullValidation`
now populates all 10 inference cfg fields in `StampInferenceCfgInputs`
from `data->config_used` + `label_type`. But the **bash CLI tool**
(`tools/stamp_model.sh`) was extended in v5.9.4a only for
`--model-num-outputs`; the 8 v5.9.2b cfg fields + the v5.9.3a scaler
fields were never added to the CLI.

Result: bash-stamped models lack 8 cfg fields that suite-stamped
models now have. Asymmetric production paths.

## Scope

Add 8 missing CLI flags to `tools/stamp_model.sh` matching
`StampInferenceCfgInputs`:

1. `--confidence-threshold-scale` (double)
2. `--barrier-gate-enabled` (int 0/1)
3. `--confidence-hard-block-threshold` (double)
4. `--held-out-fraction` (double)
5. `--freshness-tau` (double)
6. `--bandit-blend-ratio` (double — gates `has_bandit`)
7. `--fee-rate-maker` (double)
8. `--fee-rate-taker` (double — both fees together gate `has_fees`)

Plus:
- Conditional canonical body emit: only emit lines when value is set
  (matches in-process `has_*` gating)
- Field ordering: must match in-process canonical body byte-exact
  (HMAC signature is order-sensitive)
- Update `usage()` help text

## Rollback

If a bash field's canonical body emit doesn't byte-match the
in-process emit (HMAC mismatch), revert to `pre-v5.9.5c`. Bash CLI
falls back to v5.9.4a behavior (only --model-num-outputs supported);
no behavior loss for operators using suite path.

## Why this should ship before merging to main

- Closes parity asymmetry between two production paths.
- Mechanical work; well-scoped; low risk.
- Sprint should end with full parity, not partial.

## Why NOT to wait for v5.10

- Bash CLI is documented in `DOCS/ML_TRAINING.md` (extended in
  v5.9.3c with scaler-aware training section); operators may use
  it for manual stamps. Asymmetric protection = footgun.
- v5.10 work (Idea #12 enforcement) builds on top of full
  observability; v5.9.5c lays the groundwork.
