## Lessons learned

### The LOW-1 macro hygiene foot-gun (caught + fixed pre-build)

The `/dod-audit` flagged `OMS_PERSIST_COMMIT_BIT` ending with `do { } while (0);` (trailing `;` emits a null statement after the do-while). My first instinct was "drop the trailing `;`" — but the FOREACH expansion produces a SEQUENCE of statements at the call site, and `do{}while(0)` without `;` followed by the next field's commit statement would be a hard syntax error.

The correct fix was to unify `OMS_PERSIST_COMMIT_DIRECT` and `OMS_PERSIST_COMMIT_BIT` to `{ }` compound-block form, matching the existing `OMS_PERSIST_DO_SAVE` shape. Both are now self-terminating compound statements; FOREACH expansion produces a clean sequence.

**Lesson:** macro hygiene fixes that change the EXPANSION SHAPE need to consider HOW the macros are stitched together at the call site (FOREACH-walk vs single-call). Always trace through one expansion before applying the "obvious" idiom fix.

### Cross-record vs per-record bit-packing (caught at design time)

The pre-coding synthesis suggested extracting `FillRecord.was_win` to an OMS-level `was_win_bitmap` (per-slot byte → 1 bit per slot in a uint16_t). On review against CLAUDE.md item 20 ("DO NOT bit-pack ACROSS records"), this would have introduced cross-record cache traffic — the consumer at ControllerEventLoop.hpp:1430-1432 reads `rec.was_win` 3× alongside other FillRecord fields in the same cache line load.

By contrast, `last_exit_was_predicted[16]` was ALREADY a top-level cross-record array; bit-packing it to a uint16_t bitmap is allowed (memory compaction within the same access pattern, not cross-record extraction).

**Lesson:** the cross-record-vs-per-record distinction is the load-bearing check, not the K-state count. `was_win` got rejected for S3b; `last_exit_was_predicted` got accepted. Both decisions documented in the .C.2 close commit message.

### Caramel's "single clock cycle decode" instinct from first principles

During .C.2.1 design discussion, Caramel asked: "could 2 bits hold 4 states? 3 bits hold 8?" — first-principles reasoning from binary counting to information-theoretic minimum encoding (Shannon's source coding). This conversation produced:
- `DESIGN_SPECS/multi-bit-state-encoding-pattern.md` — full design with 7 branchless inference primitives, parallel multi-slot decode, width-independence note
- CLAUDE.local.md going-forward rule (set 2026-05-13)
- TECH_DEBT-041 codebase audit entry
- First application via `OmsExitPredictorMetaRegistry.hpp`

**Lesson:** ad-hoc design discussions that derive a pattern from first principles deserve immediate formalization (DESIGN_SPEC + going-forward rule + TECH_DEBT entry) so the insight doesn't evaporate. The pattern itself + 1 field-tested application is a reusable substrate for future ships.
