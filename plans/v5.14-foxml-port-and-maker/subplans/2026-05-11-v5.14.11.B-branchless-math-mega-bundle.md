## Why this subplan exists (scope expansion mid-.B)

Original .B was 3 AVX-512 vectorization sites + tests (~250 LOC). During implementation, Caramel pushback surfaced three structural concerns:

1. **Unnecessary branches in Cholesky AVX-512** (`if (j > 0)` / `if (i > 0)` guards) — variable latency violates CLAUDE.md item 18 ("Slow-path latency reduction is a priority going forward; aim to MINIMIZE slow-path branches + cycles in every ship"). Mask handles edge case correctly; guards were unnecessary defensive code.

2. **FPN padding regression** (FracDiff `same input → bytewise identical` test failed after .B added ~600 bytes to RidgeWeights stack layout) — latent FPN<F=64> bug exposed: struct has 4 bytes of UB padding after `int32_t sign`; memcmp picks up non-deterministic bytes.

3. **Discipline gap** — no DESIGN_SPEC explicitly covers "math kernels on slow path must be branchless + constant-iter". The pattern was implicit in v5.11.7's Bandit_GetProbabilities + CLAUDE.md item 18 but never codified for math kernels specifically.

Caramel framing 2026-05-11: *"can we design structural fixes that are reusable going forward, that make things easier to design and maintain?"*

The mega-bundle responds to that: structurally extinguishes both bug classes + codifies 2 new reusable DESIGN_SPECS + enforces them via skill tooling + audits ML_Headers/ math kernels + wider engine slow-path audit + cache-aligns RidgeWeights hot fields.
