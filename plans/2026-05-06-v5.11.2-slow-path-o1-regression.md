## Theme

`RollingStats_Push` (slow path, runs every ~100 ticks) currently does O(W=128) work every call:
- Iterates ring buffer to compute 5 sums (price_sum, volume_sum, sum_xy, sum_y2, vol_sum_xy)
- Iterates again to compute price_min, price_max, volume_max
- Calls `FPN_DivNoAssert` for averages (slow: long division on FPN<F>)

Audit Part 2 identifies:
1. **O(1) running sums** — biggest absolute win. Replace O(W) recompute with maintain-on-insert sums (subtract evicted, add new).
2. **Reciprocal LUT for 1/n** — replace `FPN_DivNoAssert(sum, n_fp)` with `FPN_Mul(sum, recip[n])`. ~10× faster.
3. ~AVX-512 FPN<256>/FPN<512> wide math~ — defer; engine uses FPN<64> on slow path (no wide types currently).
4. **Cache-line padding** — separate read-heavy outputs (price_avg, etc.) from write-heavy ring buffer state.
5. ~Branchless wrap~ — already branchless (`count += (count < W)` saturating mask). Cosmetic, skip.

**Plus a master-plan-flagged risk: bitwise drift.** O(1) running sums can accumulate FPN saturation differences over millions of ticks vs O(W) recompute. Mitigation: **periodic resync** every 100k ticks → force full O(W) recalculation to clear drift.

**Expected wins:**
- Phase 2.A (reciprocal LUT): ~50-100ns per Push call (3 division → multiplication conversions)
- Phase 2.B (cache-line padding): closes false-sharing class; ~5-15ns reduced GUI-thread invalidation traffic
- Phase 2.C (O(1) sums): ~3-5µs per Push call (W=128 iteration → constant work). **Biggest absolute slow-path win.**

Slow path runs every 100 ticks; per-tick amortized: ~30-50ns. Combined with hot path: contributes to overall p99 reduction by removing slow-path-induced drainer queue depth.

## Phase 2.A — Reciprocal LUT for `1/n` (`v5.11.2.A`)

**Audit:** Part 2.3 — `RollingStats_Push` calls `FPN_DivNoAssert(price_sum, n_fp)` for averages. FPN division is iteratively branch-heavy and slow (~100ns for FPN<64>). For `n` in {2..W=128}, precomputed reciprocals enable `FPN_Mul(sum, recip[n])` (~10ns).

**Step 0:** Create `ML_Headers/ReciprocalLUT.hpp` with a runtime-init LUT (FPN division isn't constexpr-friendly, so init at engine boot via static initialization).

**File:line targets:**
- `ML_Headers/ReciprocalLUT.hpp` (NEW) — LUT struct + accessor
- `ML_Headers/RollingStats.hpp:202-203` — replace `FPN_DivNoAssert(price_sum, n_fp)` for `price_avg` and `volume_avg`
- `ML_Headers/RollingStats.hpp:215` — replace `FPN_DivNoAssert(ss_total, n_sq)` (n² division — won't fit in LUT directly; either build n² LUT or reuse n LUT twice)

**Code shape:**
```cpp
// ReciprocalLUT.hpp
#pragma once
#include "../FixedPoint/FixedPointN.hpp"

namespace tt {

template <unsigned F, unsigned W>
struct ReciprocalLUT {
    FPN<F> values[W + 1];  // values[n] = 1.0 / n; values[0] = sentinel zero
};

// Compute the LUT at boot (via Meyer's singleton — thread-safe in C++11+).
template <unsigned F, unsigned W>
inline const ReciprocalLUT<F, W>& GetReciprocalLUT() {
    static const ReciprocalLUT<F, W> lut = []() {
        ReciprocalLUT<F, W> l{};
        FPN<F> one = FPN_FromDouble<F>(1.0);
        l.values[0] = FPN_Zero<F>();
        for (unsigned i = 1; i <= W; ++i) {
            l.values[i] = FPN_DivNoAssert(one, FPN_FromInt<F>(i));
        }
        return l;
    }();
    return lut;
}

} // namespace tt
```

**RollingStats_Push call site update:**
```cpp
const auto& recip = GetReciprocalLUT<F, W>();
rs->price_avg  = FPN_Mul(price_sum, recip.values[n]);
rs->volume_avg = FPN_Mul(volume_sum, recip.values[n]);
// For n²: chain two muls
FPN<F> recip_n_sq = FPN_Mul(recip.values[n], recip.values[n]);
rs->price_variance = FPN_Mul(ss_total, recip_n_sq);
```

**Verification:**
- Test: bytewise equality between `FPN_Mul(sum, recip[n])` and `FPN_DivNoAssert(sum, n_fp)` for n=2..128 with random sums. (Accept ≤ 1-LSB tolerance — division and reciprocal-mul can disagree at the ULP level due to fixed-point rounding; verify the rounding is bytewise-stable across runs.)
- Replay-determinism: run v5.9.2 test pre+post; output may differ by ≤1 ULP per division. **Regenerate the replay-determinism baseline if so**, document in commit.

**Risk:** Medium. ULP-level differences between division and reciprocal-multiplication may break replay-determinism's bytewise check. Mitigation: pre-bench the difference on a synthetic 10k-tick replay; if non-zero divergence, decide whether to (a) ship with new baseline, (b) skip this phase.

**Sub-ship gate:** `./build.sh test` 1653/0 + LUT round-trip test passes + replay-determinism either matches OR has new bytewise-stable baseline. Tag `v5.11.2.A`.

## Phase 2.B — RollingStats cache-line padding (`v5.11.2.B`)

**Audit:** Part 2.4 — RollingStats stores read-heavy outputs (price_avg, price_slope, etc.) adjacent to write-heavy state (head, count, ring buffers). GUI thread reads outputs while engine writes to all → false sharing.

**Step 0:** Reorder RollingStats struct to separate output cluster from internal-state cluster.

**File:line target:** `ML_Headers/RollingStats.hpp:35-69` (struct definition).

**New layout:**
```cpp
template <unsigned F, unsigned W = 128> struct RollingStats {
    static_assert(W > 0 && (W & (W - 1)) == 0, "W must be power of 2");

    // ── CACHE LINE 0+ (READ-HEAVY OUTPUTS) ──
    // Read by strategies, regime detector, GUI thread. Engine writes once
    // per slow-path cycle. False sharing closed by isolating from
    // write-heavy fields below via alignas(64).
    FPN<F> price_avg;
    FPN<F> price_slope;
    FPN<F> price_r_squared;
    FPN<F> price_variance;
    FPN<F> price_stddev;
    FPN<F> price_min;
    FPN<F> price_max;
    FPN<F> volume_avg;
    FPN<F> volume_slope;
    FPN<F> volume_max;
    FPN<F> volume_delta;
    FPN<F> vwap;
    FPN<F> vwap_deviation;
    // 13 × FPN<64>=24B = 312 bytes ≈ 5 cache lines
    // Padded to next 64-byte boundary so write-heavy fields don't share with last output line:
    alignas(64) int _pad_outputs[1];  // marker; alignas implicitly pads up

    // ── CACHE LINE N+ (WRITE-HEAVY INTERNAL STATE) ──
    // Mutated every Push by engine; not read externally.
    int head;
    int count;
    FPN<F> buy_volume_sum;     // running sums (update every Push)
    FPN<F> sell_volume_sum;
    FPN<F> pv_sum;
    FPN<F> vol_sum;
    // v5.11.2.C: O(1) running regression sums (added in Phase 2.C)
    // FPN<F> price_sum, price_sum_y2, price_sum_xy, volume_sum, vol_sum_xy;

    // ── RING BUFFERS (large, only iterated during periodic resync) ──
    FPN<F> price_buf[W];
    FPN<F> volume_buf[W];
    FPN<F> pv_buf[W];
    int side_buf[W];
};
```

## Phase 2.C — O(1) running sums + periodic resync (`v5.11.2.C`)

**Audit:** Part 2.2 — biggest absolute slow-path win. `RollingStats_Push` iterates W=128 samples to compute 5 sums every call. Replace with maintain-on-insert: subtract evicted contribution, add new contribution. ~128× speedup on the regression-sums step.

**Master plan technical consideration #2:** "O(1) running sums can accumulate floating-point or fixed-point bitwise drift over millions of ticks compared to a full O(W) recalculation." **Mitigation: periodic resync — every 100,000 ticks, force a full O(W) recalculation to clear any cumulative rounding or precision errors.**

**Math** (verified for both saturating phase count<W and steady phase count==W):

For sample-index-dependent sum (sum_xy where i is the sample's age):
- count<W: `sum_xy_new = sum_xy_old + (count_new - 1) * p_new`
- count==W: `sum_xy_new = sum_xy_old - (sum_y_old - p_evicted) + (W-1) * p_new`

For order-independent sums (sum_y, sum_y2, vol_sum_xy where i wraps differently):
- All count: `sum_y_new = sum_y_old - p_evicted + p_new` (with p_evicted=0 during warmup)

**Step 0:** Promote local sums in RollingStats_Push to persistent struct fields:
- `FPN<F> price_sum` (was `price_sum` local)
- `FPN<F> price_sum_y2` (was `price_sum_y2` local)
- `FPN<F> price_sum_xy` (was `price_sum_xy` local)
- `FPN<F> volume_sum` (was `volume_sum` local)
- `FPN<F> vol_sum_xy` (was `vol_sum_xy` local)
- `uint64_t total_pushes` (counter for periodic resync)
- `FPN<F> p_min_running`, `FPN<F> p_max_running`, `FPN<F> v_max_running` (min/max can't be O(1) directly — see below)

**min/max problem:** unlike sums, min/max can't be O(1) updated when the previous min/max evicts (don't know what the next-min is). Two approaches:
- **Approach A:** Keep min/max as O(W) — only iterate when the evicted sample equals min or max. Saves work on most pushes.
- **Approach B:** Maintain a deque-based monotonic queue → O(1) amortized. More code complexity.

**Recommend Approach A**: most pushes don't evict the min/max sample, so we get O(1) typical with O(W) worst-case occasional iteration.

**Step 1:** Restructure RollingStats_Push:
```cpp
template <unsigned F, unsigned W>
inline void RollingStats_Push(RollingStats<F, W>* rs, FPN<F> price, FPN<F> volume, int is_buyer_maker = 0) {
    // 1. Capture eviction state BEFORE overwrite
    bool was_full = (rs->count == (int)W);
    int evict_idx = rs->head;
    FPN<F> p_evicted = was_full ? rs->price_buf[evict_idx] : FPN_Zero<F>();
    FPN<F> v_evicted = was_full ? rs->volume_buf[evict_idx] : FPN_Zero<F>();
    int side_evicted = was_full ? rs->side_buf[evict_idx] : 0;

    // 2. Capture old sums (needed for sum_xy delta calculation)
    FPN<F> old_sum_y = rs->price_sum;
    FPN<F> old_sum_v = rs->volume_sum;

    // 3. O(1) sum updates
    rs->price_sum    = FPN_AddSat(FPN_SubSat(rs->price_sum, p_evicted), price);
    rs->price_sum_y2 = FPN_AddSat(FPN_SubSat(rs->price_sum_y2, FPN_Mul(p_evicted, p_evicted)), FPN_Mul(price, price));
    rs->volume_sum   = FPN_AddSat(FPN_SubSat(rs->volume_sum, v_evicted), volume);

    int count_new = rs->count + (rs->count < (int)W);
    if (was_full) {
        // sum_xy_new = sum_xy_old - (old_sum_y - p_evicted) + (W-1) * p_new
        rs->price_sum_xy = FPN_AddSat(
            FPN_SubSat(rs->price_sum_xy, FPN_SubSat(old_sum_y, p_evicted)),
            FPN_Mul(FPN_FromInt<F>((int64_t)(W - 1)), price));
        rs->vol_sum_xy = FPN_AddSat(
            FPN_SubSat(rs->vol_sum_xy, FPN_SubSat(old_sum_v, v_evicted)),
            FPN_Mul(FPN_FromInt<F>((int64_t)(W - 1)), volume));
    } else {
        // sum_xy_new = sum_xy_old + (count_new - 1) * p_new
        rs->price_sum_xy = FPN_AddSat(rs->price_sum_xy,
            FPN_Mul(FPN_FromInt<F>((int64_t)(count_new - 1)), price));
        rs->vol_sum_xy = FPN_AddSat(rs->vol_sum_xy,
            FPN_Mul(FPN_FromInt<F>((int64_t)(count_new - 1)), volume));
    }

    // 4. Directional volume + VWAP (existing logic — these were already O(1))
    // ... (preserve existing buy_volume_sum, sell_volume_sum, pv_sum, vol_sum updates) ...

    // 5. Write new sample to ring buffer
    rs->price_buf[rs->head]  = price;
    rs->volume_buf[rs->head] = volume;
    rs->head  = (rs->head + 1) & ((int)W - 1);
    rs->count = count_new;

    // 6. min/max (Approach A: only iterate if evicted = current min/max)
    if (was_full && (FPN_Equal(p_evicted, rs->price_min) || FPN_Equal(p_evicted, rs->price_max))) {
        // Recompute min/max from full ring buffer (O(W) but rare)
        FPN<F> p_min = rs->price_buf[0];
        FPN<F> p_max = rs->price_buf[0];
        for (int i = 1; i < (int)W; ++i) {
            p_min = FPN_Min(p_min, rs->price_buf[i]);
            p_max = FPN_Max(p_max, rs->price_buf[i]);
        }
        rs->price_min = p_min;
        rs->price_max = p_max;
    } else {
        // O(1) update: include new price
        rs->price_min = FPN_Min(rs->price_min, price);
        rs->price_max = FPN_Max(rs->price_max, price);
    }
    // (similar for v_max)

    // 7. Periodic resync — every 100k pushes, force full O(W) recalculation
    // Catches any FPN saturation drift that would compound over time.
    rs->total_pushes++;
    if (rs->total_pushes % 100000 == 0) {
        RollingStats_Resync(rs);  // helper that does a full O(W) recompute
    }

    // 8. Compute derived outputs (avg, variance, slope, R²) using the LUT from Phase 2.A
    if (rs->count < 2) return;
    int n = rs->count;
    const auto& recip = GetReciprocalLUT<F, W>();
    FPN<F> n_fp = FPN_FromInt<F>((int64_t)n);
    int64_t n_l = (int64_t)n;
    FPN<F> sum_x  = FPN_FromInt<F>(n_l * (n_l - 1) / 2);
    FPN<F> sum_x2 = FPN_FromInt<F>(n_l * (n_l - 1) * (2 * n_l - 1) / 6);

    rs->price_avg  = FPN_Mul(rs->price_sum,  recip.values[n]);
    rs->volume_avg = FPN_Mul(rs->volume_sum, recip.values[n]);
    // ... (existing slope / variance / R² formulas, using FPN_Mul instead of FPN_Div) ...
}

// Helper: full O(W) recompute. Called every 100k pushes + at warmup boundary.
template <unsigned F, unsigned W>
inline void RollingStats_Resync(RollingStats<F, W>* rs) {
    int n = rs->count;
    rs->price_sum    = FPN_Zero<F>();
    rs->price_sum_y2 = FPN_Zero<F>();
    rs->price_sum_xy = FPN_Zero<F>();
    rs->volume_sum   = FPN_Zero<F>();
    rs->vol_sum_xy   = FPN_Zero<F>();
    int start = (rs->head - n + (int)W) & ((int)W - 1);
    for (int i = 0; i < n; ++i) {
        int idx = (start + i) & ((int)W - 1);
        FPN<F> p = rs->price_buf[idx];
        FPN<F> v = rs->volume_buf[idx];
        FPN<F> i_fp = FPN_FromInt<F>((int64_t)i);
        rs->price_sum    = FPN_AddSat(rs->price_sum, p);
        rs->price_sum_y2 = FPN_AddSat(rs->price_sum_y2, FPN_Mul(p, p));
        rs->price_sum_xy = FPN_AddSat(rs->price_sum_xy, FPN_Mul(i_fp, p));
        rs->volume_sum   = FPN_AddSat(rs->volume_sum, v);
        rs->vol_sum_xy   = FPN_AddSat(rs->vol_sum_xy, FPN_Mul(i_fp, v));
    }
}
```

## Open questions / explicit deferrals

1. **Replay-determinism vs reciprocal-mul ULP differences.** Phase 2.A may introduce ≤1 ULP differences vs FPN_DivNoAssert. **Pre-coding spike (~30min): bench 1000 random sums; measure max ULP difference.** If zero, ship as-is. If non-zero, decide: (a) accept new baseline + commit message documents, (b) skip Phase 2.A, (c) investigate higher-precision reciprocal storage.

2. **AVX-512 wide FPN math (audit Item 3) — DEFERRED.** Engine uses FPN<64> on slow path (default cfg). FPN<256>/<512> vectorization only matters if/when wide types come into use. Revisit when v5.10.0b's FPN-end-to-end deepens or new strategies need wider precision.

3. **Branchless wrap (audit Item 5) — SKIPPED.** Current `count += (count < W)` is already branchless via the comparison-as-mask pattern. Audit's `std::min<int>` rewrite is cosmetic; same instruction count.

4. **min/max O(1) approach.** Plan uses Approach A (re-iterate when evicted equals current min/max — O(W) worst-case rare). Approach B (monotonic deque) is O(1) amortized but requires more state. If Approach A's worst case turns out to be common in practice (e.g. monotonically rising prices means evicting the min every push), revisit.

5. **Periodic resync frequency.** Plan uses 100,000 pushes (~3 hours at 100-tick poll_interval). Could be tighter (10k) or looser (1M). 100k is the master plan's recommendation; keep unless drift bench shows otherwise.
