- **BUT the body does NOT specify WHICH allowlist mechanism — MUST-SPECIFY.** There are two precedents and they are NOT equal:
  - `calls_graph_diff_baseline.txt` (verified): a plain `grep -vf` subtraction FILE. Its own header says "New entries should NEVER be added by routine work" — but that is a CONVENTION, not machine-enforced; nothing STOPS the file growing. A grep tool that does `subtract(allowlist.txt)` can silently grow if someone appends a line to dodge a RED.
  - `scan_class_44_cfg_orphan.py` `KNOWN_COHORT` (verified): a FROZEN in-tool set; adding a member is a code edit that `--strict` + the `missing` check make conspicuous. This IS shrink-forcing.
  - The body (Phase B.2) says "KNOWN-PENDING allowlist … shrinking-only, never-growing" but leaves the IMPLEMENTATION open ("Sizing comes from the I-class pass"). If it lands as a plain `.txt` subtraction (the calls_graph precedent, the easier path), "never-growing" is a CONVENTION = rot-prone. **Required: the H7/H20 allowlist MUST use the frozen-set + `--strict` + `missing`-shrink-tracking mechanism (Class-44 precedent), NOT a plain subtraction file.** Specify this at the dive.
