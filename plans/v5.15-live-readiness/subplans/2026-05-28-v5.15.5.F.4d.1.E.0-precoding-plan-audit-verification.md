## Findings ingestion + pre-`.E` safety net (Job B)

`.E.0` does TWO jobs. **Job A** (the rest of this plan) audits the `.E` *plan bodies* — are they sound, do they apply canonical discipline, does cross-ship integration hold. **Job B** (this section) ingests the findings from a SEPARATE read-only engine audit and stands up a regression safety net BEFORE `.E` coding. The two are independent: Job A audits plans; Job B audits + locks down the *current engine*.

This implements **DD-5** (synthesis, 2026-05-28): proceed with `.E` (the usability win) **gated behind a correctness net** (the de-risk). Not pure-proceed, not pure-pause.

### Why Job B exists

A multi-pass READ-ONLY audit of the current engine produced **141 net-new findings** (2 CRITICAL, 38 HIGH, 63 MEDIUM, 38 LOW); durable, self-contained record at `plan_checks/E.0-audit-reports/pre-implementation-findings/_SESSION-CONTEXT.md`. **These bugs are in the engine TODAY, independent of `.E`.** `.E.1` is a ~5,000-site Core→Node rename + a concurrency-model change (per-node drainer absorption) — a massive mechanical + structural change. Without locking current correct behavior in tests FIRST, a regression introduced by the rework could pass silently. Job B's deliverable: every real finding gets a concrete fix-design assigned to the ship that rewrites its surface, AND current correct behavior is frozen under test so the rework can't regress it without the build going red.

### The 3-way finding classification (the crux)

Every CONFIRMED finding routes to exactly one of:

| Class | Meaning | Test / fix timing | Examples |
|---|---|---|---|
| **PERSIST** | behavior `.E` KEEPS | write **characterization test NOW (before `.E`)**; the `.E.1` rename renames the symbols, the **assertions stay** → guards the rework | `FPN_Sqrt<64>` determinism, fee/accounting correctness, regime-given-input, parser byte-equivalence; H1-H20 CI invariant checks |
| **CHANGES-BY-DESIGN** | behavior `.E` intentionally ALTERS | write the **NEW-invariant test AS PART of** the ship that changes it | `conc-5` drainer-SPSC → `.E.1` deletes the drainer; new invariant = "per-node `submit_queue` single-producer" |
| **fix-now-in-current-code** | `.E` won't touch it | fix where it lives | `live-bc-1` Binance global-vs-US endpoint split |

PERSIST characterization tests ARE the safety net. CHANGES-BY-DESIGN tests would be thrown away if written now (the behavior is about to change) — they belong to the ship that changes the behavior.

### Enforcement hierarchy (why findings won't rot — per `_SESSION-CONTEXT` §7.5)

A filed finding gets forgotten. The GUARANTEE, strongest first:

1. **CI checks + regression tests** — machine-enforced; a reintroduced bug breaks the build with zero memory required. This is the real guarantee (and the codebase's own gradient: compile-time/CI > runtime > convention).
2. **Plan-body required-reading link** — `findings_sidecar:` frontmatter + D-52 cite; `/capture-audit` verifies. Forces a human to see them.
3. **Per-ship `/precoding-audit-gate` input** — the gate (already fired before every HIGH-RISK ship) checks the findings were addressed.

**Do NOT mistake "findings filed" for "findings handled."** The sidecars are the record; the guarantee is #1 + #2.

### The 2 CRITICALs (do not lose; do not skip on assumption)

- **`conc-5`** — multi-producer race on the per-core `submit_queue` SPSC ring (drainer thread + per-core slow thread both push → single-producer invariant violation). **LIKELY closed by `.E.1`'s drainer absorption** (slow-path becomes the sole producer) — but that is an INFERENCE, not an explicit `.E.1` guarantee. **VERIFY at `.E.1` design + `./build.sh tsan` stress; do NOT skip the fix on the assumption it auto-closes.** (CHANGES-BY-DESIGN → new-invariant test lands in `.E.1`.)
- **`live-bc-1`** — user-data WS at Binance GLOBAL while orders/listen-key use Binance US (endpoint split breaks live fills). `.E` won't auto-fix → **fix in current code** (confirm via config/code trace; likely no build).

### Discipline (do not violate)

1. NO canonical engine-CODE changes during this ship — fixes land at each ship's coding time. Job B writes tests / CI tooling + plan amendments only (`hot_path: UNTOUCHED` holds).
2. Codification into formerly-rename-owned files (`RECURRING_BUG_PATTERNS` / `DESIGN_SPECS` / `TECH_DEBT` / `PARITY` / `.E` plan bodies / `E-MASTER-REFERENCE`) is now SAFE — `.D.1` shipped (`dc37b24`), clearing the collision.
3. Runtime-confirmation on disposable clones only.
4. Finding line-numbers are pre-rename — cite by symbol + structure, not line.
5. NEW anti-pattern Classes number from **37** (36 = `.D.1`'s).

## Honest risks (with worked examples)

### R1 — Audit findings volume substantial; planning effort exceeds estimate

**Risk:** 7 plan bodies × 5 audits = 35 audit firings. Each surfaces 0-20 findings. Total findings could be 50-200+. Operator triage + plan body amendments could exceed 3-5 days.

**Worked example:** Cycle 1 surfaces 87 findings across plans. Operator triages 60% FIX-NOW (52 amendments needed), 30% ACCEPT WITH RATIONALE (26), 10% DEFER (9). Applying 52 amendments takes ~2 days. Cycle 2 still surfaces 15 findings (slower-converging than expected). Total `.E.0` effort: 7-10 days vs estimated 3-5.

**Mitigation:**
- Per-plan parallel triage (operator triages multiple plans simultaneously)
- Auto-categorize findings via similarity (cluster fixes; batch-apply where possible)
- Time-box per-plan amendments (24h max per plan; surface remaining as deferred)
- Per `feedback_iteration_spiral_signals_audit_meta_gap`: if cycle 3 needed, surface META gap immediately

**Severity:** MED-HIGH (effort estimate risk; well-mitigated by triage discipline)

### R2 — Cross-ship integration finds load-bearing inconsistency

**Risk:** Cross-ship verification finds that `.E.X`'s assumption about `.E.Y` substrate is WRONG. Either `.E.Y` plan needs amendment OR `.E.X` design needs rethinking.

**Worked example:** `.E.4` assumes per-node io_uring receives WS frames from .E.3's persistent connection. `.E.3` plan documents per-cluster shared WS connection. Inconsistency: `.E.4` plan says "per-node WS" but `.E.3` plan says "per-cluster WS". Cross-ship audit catches this; operator triages: amend `.E.3` plan body OR amend `.E.4` plan body.

**Mitigation:**
- Each plan's forward-promises section is auditable against successor plans
- Operator triage decides which side amends
- Decision log captures the choice
- Worst case: substantial plan body revision needed (1-2 days additional)

**Severity:** MED (catches design issues before catastrophic coding)

### R3 — Audit reveals canonical sister gaps

**Risk:** Audit finds that a plan introduces NEW infrastructure that should have extended canonical sister. Per `feedback_audit_canonical_sister_before_new_infra`, plan must be amended to extend not parallel.

**Worked example:** `.E.5` audit finds that NEW SubAccountRateLimit struct is parallel to existing per-core rate-limit pattern in `.E.1`. Should have extended `.E.1`'s pattern. `.E.5` plan body amended to merge.

**Mitigation:**
- Pre-coding catch (vs post-coding which would require code rewrite)
- Operator triage per `feedback_proportionate_response_to_audit_findings`
- Decision log captures the merge decision

**Severity:** MED (catches at right time; well-mitigated)

### R4 — Plan body amendments break already-accepted decisions

**Risk:** Operator amends a plan body to address audit finding; amendment contradicts an earlier accepted decision (D-XX in decision log).

**Worked example:** D-15 says "cluster framing adopted". `.E.6` audit finding suggests "merge cluster + node concept for non-sub-account exchanges". Amendment would contradict D-15.

**Mitigation:**
- Decision log conflict check: every amendment proposal cross-referenced against existing D entries
- Conflicts → operator-triage decision; either supersede D-X or reject amendment
- New decision log entries (D-XX) document the supersession

**Severity:** LOW (operator-aware via decision log)

### R5 — `.E.0` itself becomes blocked by indecisive triage

**Risk:** Operator over-thinks each finding; triage takes weeks; sub-sprint coding never starts.

**Worked example:** Operator triages 50 findings; each requires deep discussion; triage takes 3 weeks. Sub-sprint coding delayed indefinitely.

**Mitigation:**
- Time-box triage (1 day max per plan body)
- Default action: if uncertain, FIX-NOW (per `feedback_no_defer_for_effort`)
- Operator can DEFER to v5.16+ for non-critical findings
- `.E.0` ship-close hard deadline: 5 days max; remaining findings DEFERRED to `.F` audit sweep

**Severity:** LOW (mitigated by time-boxing)

### R6 — Runtime-confirmation inconclusive for a CRITICAL (Job B)

**Risk:** `conc-5` is a race; tsan + stress may not deterministically reproduce it (races are timing-dependent). An INCONCLUSIVE result is neither confirmation nor refutation.

**Worked example:** tsan stress runs 10× clean; the race is real but narrow. Treating "couldn't reproduce" as "refuted" would silently drop a CRITICAL.

**Mitigation:** INCONCLUSIVE ≠ refuted. For `conc-5` specifically, the structural argument carries it: `.E.1`'s drainer absorption makes the slow-path the sole `submit_queue` producer — VERIFY at `.E.1` design that the 2nd producer is genuinely removed, and land the single-producer invariant test in `.E.1` regardless of whether tsan reproduced the race. Don't skip the fix on an unreproduced race.

**Severity:** MED (it's a CRITICAL; mitigated by structural verification at `.E.1`)
