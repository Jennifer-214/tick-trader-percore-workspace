## Phase B — Composition in `Model_Predict` (`v5.12.3.A.2`)

**Goal:** Modify `Model_Predict` body at
`ML_Headers/ModelInference.hpp:507` to compute the linear combo when
`num_classes_active > 1`.

```cpp
// ML_Headers/ModelInference.hpp Model_Predict body, around :527-535
// (where existing buy_class_idx extraction happens)
//
// v5.12.3.A: composite signal extraction
if (m->num_classes_active > 1) {
    float composite = 0.0f;
    for (uint8_t i = 0; i < m->num_classes_active; ++i) {
        int   cls = m->target_classes[i];
        float w   = m->class_weights[i];
        // defensive: clamp out-of-bounds class to 0
        if (cls < 0 || cls >= num_classes) continue;
        composite += w * out_result[cls];
    }
    return composite;
}
// existing single-class path: out_result[buy_class_idx]
return out_result[m->buy_class_idx];
```

`num_classes` here is the model's actual class count, accessible via
the model's metadata (existing infrastructure). The defensive clamp
ensures out-of-range `target_classes[i]` → contribution = 0 (no
undefined-read).

**Boundary semantics:** weights can be any float (including
negative). No normalization required. Strategy code consumes the
returned float as a "buy probability" — operator's responsibility to
ensure weights sum makes sense for downstream comparison against
`confidence_threshold`.

**Tests** (+5):
1. default-path bytewise preserved (single-class behavior unchanged)
2. 2-class linear combo (P(class_4) - P(class_0) on synthetic 5-class
   output produces expected sign + magnitude)
3. weight-sum non-1 (no normalization required, raw linear combo)
4. target_class out-of-bounds clamp (defensive; out-of-range index
   contributes 0)
5. strategy code unchanged (`git diff Strategies/` empty post-ship)

**Tag:** `v5.12.3.A.2`.
