## Theme

Currently flat `risk_pct` per position regardless of prediction
confidence. Model says P(buy)=0.95? Same 5% as P(buy)=0.51. This is
inefficient capital allocation — high-conviction predictions should
size up, barely-above-threshold should size down.

**Critical caveat:** mis-calibrated model + size scaling = amplified
losses. So this ship lands the INFRASTRUCTURE only (cfg field +
multiplier plumbing). **Activation gated on Phase 4.B** which
measures calibration via paper-test data. If model is well-calibrated
(predicted-P=0.7 wins 70% of the time), flip
`cfg.risk_scale_by_confidence=1` in production. If poorly calibrated,
keep at 0; don't amplify mis-calibrated predictions.

### Step 1: Multiplier plumbing in Strategy_BuildParameters

Site: `Strategies/StrategyParameters.hpp:1070`
(`Strategy_BuildParameters` dispatcher). The dispatcher calls
strategy-specific build functions which produce a `GateParameters`
with `risk_pct` already set per-core.

**After** the strategy-specific build returns, multiply the effective
risk_pct by a confidence-derived factor. Branchless via mask-select.

```cpp
// v5.12.1.D: confidence-aware sizing. Branchless: factor depends on
// mode; mode==0 → factor==1.0 (no change to current behavior).
//
// Confidence p comes from MLStrategy's predict path; non-ML strategies
// (DIP, MOMENTUM, EMA_CROSS) pass p=1.0 (no adjustment).
double p = ctx.confidence;          // already populated by strategy
double thresh = (double)cfg.confidence_threshold;  // ML-side cfg
double raw_factor = (p - thresh) / (1.0 - thresh);
raw_factor = (raw_factor < 0.0) ? 0.0 : (raw_factor > 1.0 ? 1.0 : raw_factor);

double linear_factor    = raw_factor;
double quadratic_factor = raw_factor * raw_factor;
double identity_factor  = 1.0;

// branchless mode dispatch:
double factor = (cfg.risk_scale_by_confidence == 1) ? linear_factor
              : (cfg.risk_scale_by_confidence == 2) ? quadratic_factor
                                                    : identity_factor;

// apply to GateParameters' risk_pct:
out_params->risk_pct = FPN_Mul<F>(
    out_params->risk_pct,
    FPN_FromDouble<F>(factor));

// Hard cap at the cfg.risk_pct max — no upsize beyond cfg value
// (already enforced by the caller's `risk_pct` setting; factor ∈ [0,1]
// guarantees no upsize as long as raw_factor ≤ 1.0).
```

### Step 2: Non-ML strategy compatibility

Non-ML strategies (DIP, MOMENTUM, EMA_CROSS) don't produce a
`confidence` value. The dispatcher must default `ctx.confidence = 1.0`
for non-ML cores so the factor computes to 1.0 (no change).

**Site:** `Strategy_BuildParameters` dispatcher entry (around `:1070`).
After the per-core context is populated but before the strategy-
specific build is called:

```cpp
// v5.12.1.D: non-ML strategies don't populate ctx.confidence; default
// to 1.0 so the post-build risk multiplier is a no-op for them.
if (ctx.strategy_id != STRATEGY_ML) {
    ctx.confidence = 1.0;
}
```

### Tests (+3)

1. **mode=0 baseline:** ML strategy build with P=0.95 → out_params.risk_pct
   bytewise == cfg.risk_pct. Current behavior preserved.
2. **mode=1 linear:** ML strategy with P=0.95, threshold=0.50 →
   factor = 0.90 → out_params.risk_pct = cfg.risk_pct × 0.90.
   With P=0.51 → factor ≈ 0.02. With P=0.50 (at threshold) → factor
   = 0.0 (no entry; should already be blocked by predicate but
   verify the math).
3. **mode=2 quadratic:** ML strategy with P=0.95 → factor = 0.81;
   P=0.51 → factor ≈ 0.0004. Steeper rolloff.

## Accounting for next ships

**Phase 2 (slow-path opt):** orthogonal. None of 2.A/B/C/D touch
`Strategy_BuildParameters` confidence path.

**Phase 3.A (composite-signal extractor):** the `confidence` value
passed into this ship's multiplier comes from `Model_Predict`'s
output. Phase 3.A extends Model_Predict to compute composite signals
via target_classes/class_weights; the OUTPUT semantics stay the
same — `confidence` is still a [0,1] probability. No interaction
with this ship's multiplier logic.

**Phase 3.B (mixed-output normalizer):** ditto — normalizer maps
heterogeneous outputs to [0,1] BEFORE the multiplier sees them. No
interaction.

**Phase 4.B (calibration measurement):** consumes this ship's
infrastructure. Paper-test runs in mode=0; logs (predicted_p,
realized_outcome) pairs; computes calibration curve; if calibrated
within tolerance, operator flips cfg to mode=1 in production.
