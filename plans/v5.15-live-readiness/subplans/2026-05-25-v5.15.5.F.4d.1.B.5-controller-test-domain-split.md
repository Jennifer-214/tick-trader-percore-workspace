### Decision C — Build system shape (H2 amended 2026-05-25)

**The "umbrella links object files" framing in v1.0 was load-bearing-underspecified.** Each TU can only have ONE `int main()` — so 5 sub-domain .cpp files can't each have main() AND be linked into the umbrella binary together (linker conflict).

Decision tree for the actual shape:

| Option | Mechanism | Verdict |
|---|---|---|
| **(a) Function-exposed sub-files + thin main wrappers** | Each sub-file has `void RunTests_<domain>()` (NO main); 5 thin `*_main.cpp` wrappers (each ~5 LOC: `#include + int main() { RunTests_X(); return tests_failed; }`); umbrella `controller_test_main.cpp` calls all 5 RunTests_X functions | **CHOSEN** |
| (b) Renamed-main sub-files | Each sub-file has `int controller_test_<domain>_main()` (renamed); 5 sub-binaries built from per-sub thin wrappers calling the renamed main; umbrella wraps all 5 | rejected — uglier naming, same complexity |
| (c) Test registration framework | Each sub-file calls `RegisterTest("name", fn)` into global runner; all binaries link a runner | rejected — requires test framework rewrite; current `TEST_SECTION` macro doesn't have registration semantics |
| (d) Header-only sub-files | Sub-files are `.hpp` containing test sections inline; each sub-binary `.cpp` `#include`s + has main | rejected — breaks "tests live in .cpp" convention; preprocessor expansion at compile time |

**Rationale for (a):** Preserves `./build/controller_test` invocation (back-compat); enables per-domain parallel test runs; aligns with multi-binary precedent (`depth_recorder_test`, `parity_harness`). Sub-files have clean function-name interface (`void RunTests_engine()` etc.); main wrappers are 5-LOC each (~25 LOC total in `tests/wrappers/`).

**File structure:**
```
tests/
  test_common.hpp                         ← shared helpers (TEST_SECTION macro, check macros, fixtures)
  controller_test_engine.cpp              ← contains void RunTests_engine() with all engine-domain TEST_SECTION blocks
  controller_test_features.cpp            ← void RunTests_features()
  controller_test_stamps.cpp              ← void RunTests_stamps()
  controller_test_ml.cpp                  ← void RunTests_ml()
  controller_test_misc.cpp                ← void RunTests_misc()
  wrappers/
    controller_test_engine_main.cpp       ← #include + int main() { RunTests_engine(); return tests_failed; }
    controller_test_features_main.cpp     ← ...
    controller_test_stamps_main.cpp       ← ...
    controller_test_ml_main.cpp           ← ...
    controller_test_misc_main.cpp         ← ...
    controller_test_main.cpp              ← umbrella main; calls all 5 RunTests_X(); reports total
  test_common_decls.hpp                   ← forward-declares void RunTests_engine() etc. for umbrella wrapper
```

**CMakeLists.txt update:** 6 new test targets (5 sub-binaries + 1 umbrella). Each sub-binary links exactly its own sub-file `.cpp` + wrapper `.cpp` + `test_common.hpp` deps. Umbrella links all 5 sub-files + umbrella wrapper.

**Tests-failed counter discipline (M-3 amendment 2026-05-25):** `test_common.hpp` declares **`inline int tests_failed = 0;`** (C++17 inline-variable; linker dedupes across TUs into single storage). Each `RunTests_X()` increments this single counter. Sub-binaries return its value as exit code. Umbrella sums automatically (single shared counter across all linked TUs).

**Why NOT TU-local static:** `static int tests_failed = 0;` in a header gives EACH TU its own counter (each .cpp #including the header has its own private storage). Sub-binary `main()` would see only its own RunTests_X's count + lose visibility into shared state across sub-files. WRONG mechanism for this requirement.

**Why NOT non-inline global with `extern` in header + definition in one .cpp:** Functionally correct but requires a dedicated `.cpp` file just for the definition (uglier; one more TU). C++17 `inline int` is the cleaner mechanism that achieves the same single-definition-across-TUs semantic with no extra file.

**Why NOT thread-local:** Tests run single-threaded in our framework; thread-local adds overhead + breaks the counter semantic (each thread would have own count).

`inline int tests_failed = 0;` is the correct + minimal mechanism.

**C++17 inline-variable semantics clarification (amended 2026-05-27 per pre-coding audit synthesis — design-philosophy + parity-check convergent finding):**

C++17 `inline int` in a header has a SUBTLE semantic that matters here. Two scenarios:

| Scenario | Counter behavior |
|---|---|
| **5 INDEPENDENT sub-binaries** (each built from its own sub-file + wrapper main; ran separately as `./build/controller_test_engine`, `./build/controller_test_features`, etc.) | Each sub-binary is its own PROGRAM with its own single `inline int tests_failed` storage. The sub-binary sees only the assertions its `RunTests_X()` ran. ✓ Correct (each binary reports its own count) |
| **1 UMBRELLA binary** (single binary linking all 5 sub-file object files + umbrella wrapper main; ran as `./build/controller_test`) | Linker dedups the `inline int` across all 5 TUs into ONE storage instance per program. All 5 `RunTests_X()` increment the SAME counter. Umbrella sees total. ✓ Correct (umbrella reports 3,215) |

**Why `static int` in a header would BREAK this:** `static int tests_failed = 0;` gives each TU its OWN private storage. The umbrella binary would have 5 separate private counters, one per linked sub-file. Each `RunTests_X()` would increment ITS OWN counter; umbrella main wouldn't see them. Result: silent test-count corruption.

**Why `extern int` + separate `.cpp` definition** is functionally equivalent but adds a needless TU just to hold the definition. `inline int` is the cleaner single-mechanism approach.

**FUTURE-MAINTAINER WARNING:** If anyone later refactors this back to `static int` (e.g., "to match other files") — they will SILENTLY break test counting across sub-binary aggregation. This is a Class 14-adjacent silent-correctness bug. Per `feedback_motivated_collaborator_for_caramel`: codify the discipline. NEW memory rule `feedback_cfg_field_categorization_at_registry_add_time.md`-sister `feedback_cpp17_inline_variable_for_shared_state_across_tus.md` lands at ship close (per Task #14 — library-of-knowledge contribution).

### Pre-extract disciplines (amended 2026-05-27 per pre-coding audit synthesis)

Three MANDATORY disciplines apply across all Phase B + C + D steps. Defined once here; cross-referenced from individual Steps.

**Discipline 1 — Conditional-compile guards migrate atomically with guarded blocks (per /test-strength-audit HIGH finding):**

The current `controller_test.cpp` contains at least 2 conditional-compile blocks wrapping test assertions:
- Line 10618: `#if __has_include("../Strategies/private/EmaCross.hpp")` wraps EmaCross presence-vs-absence test branches
- Line 15943: `#ifdef LATENCY_PROFILING` wraps latency-only test branches

When extracting a test block wrapped in `#ifdef` / `#if`, extract the ENTIRE guard + guarded block together. Verify post-extract that each `#if...#endif` is fully contained within ONE sub-file (not split across source + destination). Splitting a guarded block across files would cause asymmetric assertion counts between umbrella + sub-binary OR compile errors from dangling `#else`/`#endif`.

Post-Phase B grep verification: `rg '#ifdef|#if defined|#if __has' tests/controller_test_*.cpp` — every match must be fully contained within ONE sub-file (paired `#if...#endif` in same file).

**Discipline 2 — Helper hygiene: delete old static counters AT test_common.hpp creation (per /test-strength-audit MED finding):**

At Phase B Step B.1 (`test_common.hpp` creation), DELETE the existing `static int tests_passed = 0;` + `static int tests_failed = 0;` declarations from `controller_test.cpp:76-77` IMMEDIATELY. Do NOT leave them as fallback during transition. Each sub-file `.cpp` MUST `#include "test_common.hpp"` as the FIRST `#include` after header guards.

Pre-Phase-C grep verification: `rg 'static int tests_failed' tests/` must return ZERO results. If any match — the old declarations are still present somewhere and will create a Class 14-adjacent silent test-count corruption (per Decision C C++17 inline-variable clarification above).

**Discipline 3 — CMakeLists.txt uniform compile flags across ALL test binaries (per /test-strength-audit MED finding):**

At Phase B Step B.1 + B.2 (initial CMakeLists.txt update) + Phase D Step D.1 (final umbrella refactor): ALL 5 sub-binaries (`controller_test_engine` / `_features` / `_stamps` / `_ml` / `_misc`) + umbrella (`controller_test`) MUST use IDENTICAL compile flags:
- Same `-D` macro definitions (e.g., `LATENCY_PROFILING`, `USE_XGBOOST`, `USE_NATIVE_128`)

- Same `-O` optimization levels
- Same C++ standard flag (`-std=c++17`)

Per-binary flag variation would cause Discipline 1 conditional-compile guards to evaluate differently across binaries → silent asymmetric coverage.
