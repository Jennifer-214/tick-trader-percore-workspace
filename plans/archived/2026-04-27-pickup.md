### 2. Snapshot bug fix verification

The two bugs that surfaced live in engine_gui this session:

- **Time-exit underflow** — symptom was log spam:
  `[sharded] core N: time-exit (held 18446744073709536760 ticks, gain -X.X%)`
  with held count near 2^64. Fix: `b86b17f` adds defensive guard
  `if (entry_t > now_tick) reset + skip`.

- **Zombie positions** — symptom was positions visible in Positions
  panel that wouldn't exit even with price clearly below SL.
  Root cause: snapshot saved Position fields but not ExecutionCore
  hot-path mirrors (active=0, live_sl=0). Fix: `777f843` adds
  re-activation loop in `ShardedSnapshot_Load`.

After reboot:
- Watch for the new log line: `[snapshot] re-activated N
  ExecutionCore(s) from restored positions — hot-path SG/TP/SL
  gates armed`
- Watch that time-exit log entries no longer have the 2^64 held
  count
- If positions go below SL, they should now exit normally

### 3. Partial exits opt-in smoke test (when ready)

Default `cfg.partial_exit_enabled=0` means partials don't fire even
in this build — hot path runs the dual-leg comparisons but masks
results. To exercise the actual partial-exit behavior:

1. Set `partial_exit_enabled=1` in `engine.cfg`
2. Confirm `num_execution_cores ≤ 8` (validation refuses otherwise)
3. Restart `engine_gui`
4. Look for boot log:
   `[partial-exits] enabled: N cores using 2N slots (legs A+B), TP1 exits 50% of qty`
5. When trades fire, verify Trade History shows TWO entries per
   trade signal (leg A + leg B), and exits fire independently
   (TP1 closes leg A while leg B keeps running until TP2 or shared
   SL)

**Deferred items in partial exits** (won't work yet, documented):
- `breakeven_on_partial=1` semantics (slow path should ratchet
  leg B's SL to entry_price after leg A's TP1 — currently leg B's
  SL stays at the original shared SL)
- Snapshot persistence of leg-B fields (snapshot v8 doesn't include
  them — a snapshot taken with both legs active won't fully restore
  leg B; failure mode is "leg B closes at next live tick that hits
  its TP/SL" which matches single-leg semantics)
