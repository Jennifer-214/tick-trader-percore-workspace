## Theme

v5.10 design Idea #2. Labels (8 types in `label_table[]` at
`Backtest/LabelFunctions.hpp:276-293`) are currently hand-maintained.
Apply the v5.8.x X-macro pattern (FOREACH_FEATURE / FOREACH_STRATEGY)
to labels: structural changes flip a `LABEL_REGISTRY_HASH()` →
load-time refusal of stamps trained on different label set.

Currently the only label drift protection is the v5.9.2a snapshot
tests for label-fn bodies. Function-body changes ARE caught; X-macro
structural changes (adding/removing/reordering labels) are NOT
caught by stamps today.

## Items

### #2 — FOREACH_TARGET retrofit (3-4h)

**Phase 1 — X-macro definition (1h):**

Replace `label_table[]` with X-macro driven dispatch. Each label
gets:
- numeric ID (compatible with existing LABEL_* constants)
- short name (cfg parser key)
- display name (GUI label)
- description (operator tooltip)
- function pointer (existing Label_*)
- num_classes (binary=0, regression=1, multiclass=N)

```cpp
#define FOREACH_TARGET(X) \
    X(LABEL_WIN_LOSS,           "win_loss",     "Win/Loss",      "...",  Label_WinLoss,           0) \
    X(LABEL_BARRIER,            "barrier",      "Barrier",       "...",  Label_Barrier,           0) \
    X(LABEL_FORWARD_PNL,        "forward_pnl",  "Forward P&L",   "...",  Label_ForwardPnl,        1) \
    X(LABEL_REGIME,             "regime",       "Regime",        "...",  Label_Regime,            4) \
    X(LABEL_VOL_BARRIER,        "vol_barrier",  "Vol Barrier",   "...",  Label_VolBarrier,        0) \
    X(LABEL_WILL_PEAK,          "will_peak",    "Will Peak",     "...",  Label_WillPeak,          0) \
    X(LABEL_WILL_VALLEY,        "will_valley",  "Will Valley",   "...",  Label_WillValley,        0) \
    X(LABEL_PEAK_VALLEY_STABLE, "peak_valley_stable", "Peak/Valley/Stable", "...", Label_PeakValleyStable, 3)

// Generate label_table[] from the X-macro:
#define X(id, short, full, desc, fn, nc) { id, short, full, desc, fn, nc },
static const LabelDef label_table[] = { FOREACH_TARGET(X) };
#undef X
```

`LabelType_NumClasses` etc. continue to read from `label_table[]`,
no change.

**Phase 2 — LABEL_REGISTRY_HASH (30 min):**

Constexpr FNV-1a hash over the X-macro entries (mirrors
`FEATURE_REGISTRY_HASH()`). Changes to label set → hash flips.

```cpp
constexpr uint64_t LABEL_REGISTRY_HASH() {
    uint64_t h = 0xcbf29ce484222325ULL;
    #define X(id, short, full, desc, fn, nc) \
        h = fnv1a_str(h, short); h ^= (uint64_t)id; h ^= (uint64_t)nc;
    FOREACH_TARGET(X)
    #undef X
    return h;
}
```

**Phase 3 — Stamp body integration (1h):**

Add `label_registry_hash` field to stamp body (Surface G pattern,
position **20** in canonical order — position 19 already taken by
grid_member_count from v5.10.0a-final, see ModelInference.hpp:1420):

- `StampInferenceCfgInputs.has_label_registry_hash` + value
- `stamp_write_for_model` emits when has_*=1
- `verify_model_stamp` parses
- `ModelStampResult.label_registry_hash` populated

**Phase 4 — Load-time refusal (30 min):**

In `verify_model_stamp` (similar to feature_registry_hash check at
line 920-934), compare stamp's label_registry_hash to current build's
`LABEL_REGISTRY_HASH()`:

- Match → proceed
- Mismatch + has_*=1 → refuse with "label set drift; retrain
  required"
- has_*=0 (legacy stamp) → WARN with "label drift NOT verified"

**Phase 5 — Tests (1h):**

- Round-trip: stamp emits hash, verifier accepts matching hash
- Mismatch: stamp says hash A, build says hash B → refuse
- Legacy: stamp without field → warn
- X-macro consistency: dispatcher table matches macro entries
