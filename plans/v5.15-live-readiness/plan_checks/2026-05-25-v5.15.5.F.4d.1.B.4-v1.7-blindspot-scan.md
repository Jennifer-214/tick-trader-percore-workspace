## Findings

### B-CRIT-1 — D1-B SCOPE/CONSUMER STATE-STRUCT MISMATCH (per Critical Verification 2 in skill prompt)

**Severity:** CRIT-LOUD (compile fail OR runtime semantic mismatch when corrected)

**The plan body internal contradiction at v1.7:**

Phase B Step B.3 body call site (plan body line 640):
```cpp
if (BITMAP_IS_SET(state.cores[c].gate_state.flags, MASK_BREAKEVEN_ON_PROFIT)) {
    EventLoop_BreakevenOnProfitOneCore(state, cfg, current_price, c);
}
```

Phase B Step B.3a registry row addition (plan body line 651):
```cpp
X(ENGINE_WIDE, BREAKEVEN_ON_PROFIT,
  BITMAP_IS_SET((_gate_cfg).lifecycle_cfg_flags, MASK_LIFECYCLE_CFG_BREAKEVEN_ON_PROFIT),
  "breakeven-on-profit lifecycle event...")
```

**The contradiction:**

`scope=ENGINE_WIDE` in the row means the bit goes onto `EventLoopState.global_gate_state.flags` (per SlowPathGateRegistry.hpp:203-207 — `GlobalGateState` is the engine-wide cache). The plan body header comment line 656 even says "per `scope=ENGINE_WIDE`: cached on `EventLoopState.global_gate_state` (NOT per-core `CoreContext<F>.gate_state`)".

But Step B.3 body call reads from `state.cores[c].gate_state.flags` which is `CoreContext<F>.gate_state` = `SlowPathGateState` = the PER_CORE cache. ENGINE_WIDE scope's AUTOPOPULATE walker (X_AUTOPOP_ENGINE_WIDE_DISPATCH_PER_CORE = SKIP per registry line 146) **never populates the per-core gate_state with BREAKEVEN_ON_PROFIT**. So `BITMAP_IS_SET(state.cores[c].gate_state.flags, MASK_BREAKEVEN_ON_PROFIT)` would **always return 0** for ENGINE_WIDE-scoped masks read against PER_CORE state.

**Loud vs silent:**

This will compile cleanly. `MASK_BREAKEVEN_ON_PROFIT` is generated by the registry walker regardless of scope (per X_GEN_GATE_MASK at line 167) so the macro reference resolves. The runtime behavior is **silent always-OFF**: BREAKEVEN_ON_PROFIT will never fire from SlowPathCycleOneCore regardless of cfg flag state. PARITY-032 closure FAILS by-construction.

**Root cause:**

The plan body conflates two architectural choices that v1.7 needs to pick exactly one of:

- **Option α (ENGINE_WIDE scope; current Step B.3a):** Row stays ENGINE_WIDE. Body call must read `state.global_gate_state.flags` (or pass GlobalGateState ref into SlowPathCycleOneCore). Caller-side wiring: AUTOPOPULATE_ENGINE_WIDE fires once per slow-path entry (sister to existing call sites at ControllerEventLoop.hpp:2335 + :3555).

- **Option β (PER_CORE scope):** Row becomes PER_CORE. Body call as-written reads `state.cores[c].gate_state.flags`. Caller-side wiring: AUTOPOPULATE_PER_CORE fires per-core (sister to existing call sites at StrategyParameters.hpp where LADDER_ACTIVE / CONFIDENCE_ENABLED are populated; controller_test.cpp:21645+ verifies). BUT: BREAKEVEN_ON_PROFIT cfg lives in cfg.lifecycle_cfg_flags (a GLOBAL field, no per-core override per controller_test.cpp:22662 which confirms "no override → inherits global default"). PER_CORE scope is intended for cfg with per-core overrides; using it for a global-only cfg works mechanically (predicate just reads same global value N times) but is misleading.

**Sister precedent inspection:**

LADDER_ACTIVE (PER_CORE scope) at SlowPathGateRegistry.hpp:72-74 reads `(_gate_cfg).risk_degradation_curve` + `(_gate_cfg).ml_cfg_flags` — both can have per-core overrides via ControllerConfig_ResolveForCore.

WS_FLATTEN_ACTIVE (ENGINE_WIDE) at SlowPathGateRegistry.hpp:114-117 reads `(_gate_cfg).risk_cfg_flags` MASK_RISK_CFG_WS_DEAD_TIME_FLATTEN_ENABLED — global cfg with no per-core override; correctly ENGINE_WIDE.

**BREAKEVEN_ON_PROFIT precedent fit:** `cfg.lifecycle_cfg_flags` has per-core override surface (`cfg.core_overrides[i].lifecycle_cfg_flags_override` at controller_test.cpp:22646+) — semantically COULD be per-core via override. But the existing `EventLoop_BreakevenOnProfit` wrapper at ControllerEventLoop.hpp:3799 reads ONLY `cfg.lifecycle_cfg_flags` (no per-core resolution loop), so the "production semantic of breakeven" is currently global-only. Option α (ENGINE_WIDE) preserves bytewise-identical math at extract per the v1.6 O2 discipline.

**Action required (operator decides):**

1. **Option α (preferred per O2 bytewise-identical preservation):** Amend Step B.3 body to `BITMAP_IS_SET(state.global_gate_state.flags, MASK_BREAKEVEN_ON_PROFIT)` (or pass GlobalGateState ref to SlowPathCycleOneCore signature; or read via `state` already in scope). Amend signature documentation to note SlowPathCycleOneCore reads global_gate_state for BREAKEVEN_ON_PROFIT. Add caller-side AUTOPOPULATE_ENGINE_WIDE wiring inside slow-path-cycle entry (sister to ControllerEventLoop.hpp:2335 pattern; verify call-site already populates global_gate_state before per-core thread reads it OR add new populate call to plan body).

2. **Option β:** Change row scope to PER_CORE. Plan body keeps current body call. Note in registry row comment that this differs from existing breakeven semantic (currently global-only at ControllerEventLoop.hpp:3799) BY DESIGN — closure path enables per-core overrides for the first time. Add test that core override for lifecycle_cfg_flags_override correctly toggles per-core breakeven fire.

3. **Option γ (architectural punt):** Drop D1-B; revert to the existing wrapper call at ControllerEventLoop.hpp:3796-3804 (`EventLoop_BreakevenOnProfit(state, cfg, current_price)`); call it ONCE per slow-path cycle inside SlowPathCycleAllCores (NOT OneCore — wrapper already iterates `state->registered_count`). This bypasses the registry pattern entirely; loses the cached-bit branchless optimization (~5ns per cycle for cohorts with flag UNSET — negligible). Closes PARITY-032 by-construction without registry surface change.

**This is the SINGLE pre-coding blocker.** Phase B Step B.2 unlock should NOT proceed until operator chooses α / β / γ.

### B-HIGH-1 — MASK_BREAKEVEN_ON_PROFIT semantic near-duplicate with MASK_LIFECYCLE_CFG_BREAKEVEN_ON_PROFIT

**Severity:** HIGH-SILENT (cohabitation; future readability)

`LifecycleCfgFlagRegistry` defines `MASK_LIFECYCLE_CFG_BREAKEVEN_ON_PROFIT` (the source-of-truth cfg flag at bit position 2 per controller_test.cpp:22212). The plan body Step B.3a generates `MASK_BREAKEVEN_ON_PROFIT` (the cached gate-state bit). Names are distinct (no compile collision per Pillar B2) but **semantic near-duplicate** — both encode "is breakeven_on_profit enabled?". Future contributor sees two masks; unclear which to use where.

**Mitigation:**

1. Rename gate-state bit to `MASK_GATE_BREAKEVEN_ON_PROFIT` (or `MASK_BEOP_ACTIVE` matching LADDER_ACTIVE convention) — makes "cached gate bit" distinguishable from "cfg source-of-truth bit" by name.

2. Add comment at Step B.3a row indicating "cached predicate evaluation of MASK_LIFECYCLE_CFG_BREAKEVEN_ON_PROFIT for branchless per-cycle gating".

3. Document at Step B.5 unit tests: which assertions test the cached-bit (MASK_BREAKEVEN_ON_PROFIT) vs the cfg-bit (MASK_LIFECYCLE_CFG_BREAKEVEN_ON_PROFIT).

**Sister precedent:** LADDER_ACTIVE (cached) reads `risk_degradation_curve` enum + `MASK_ML_CFG_CONFIDENCE_COMPOSITE_ENABLED` (cfg bit); naming asymmetry is OK there because the cached bit composes two source values. For BREAKEVEN_ON_PROFIT the cached bit is 1:1 with a single cfg bit — naming should reflect the redundancy (cached form).
