## New anti-pattern class candidate (per Caramel pushback #3 meta-question)

### Class 31 (NEW PROPOSED) — Wire-format duplicate-key emit from sister registries

**Surface:** wire-format stamp emit (live + training-time).

**Symptom:** stamp body contains two wire keys carrying the same semantic value (e.g., `bandit_algorithm=4` AND `inference_cfg_bandit_algorithm=4`). Downstream parsers may take first/last value; wire format size grows; HMAC chain unaffected (both keys deterministic).

**Root cause:** Sister registry adds rows that duplicate canonical entries already in primary walker registry. Both walkers fire at emit; both keys present in canonical body.

**Detection:**
