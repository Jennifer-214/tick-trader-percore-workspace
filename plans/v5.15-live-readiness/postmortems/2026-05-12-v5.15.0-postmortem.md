## What shipped

### v5.15.0.A — ModelHandle struct rewrite (~150 LOC migration; ~100 LOC struct rewrite)

- 14 `uint8_t has_*` direct fields → 1 `uint64_t has_flags` bit-packed via the SHARED `MASK_<name>` constants from `StampBoundModelConstRegistry.hpp` (Option C from /dod-audit HIGH-2 — same bit positions as ModelStampResult + StampInferenceCfgInputs; parser dispatch table writes BOTH structs' has_flags from ONE mask column).
- Stamp-derived value fields auto-generated via `FOREACH_STAMP_BOUND_MODEL_CONST` X-macro walk with `STAMP_HANDLE_GEN_<presence>` token-paste dispatch. INCLUDE entries land on handle; SKIP_HANDLE filtered (parser-only fields: feature_scaler_present boolean, grid_member_*, label_registry_hash, feature_mask, held_out_fraction, expected_* 4 fields).
- Net result: 33 INCLUDE fields on ModelHandle (was 26 manual). 7 new auto-flowed fields: `scaler_fit_data_hash`, `removal_reasons_csv`, 5× `environment_*`. Operators get richer model lineage forensics for free.
- Field-name unification: prefixed legacy names dropped in favor of canonical wire-key names. `stamp_xgb_max_depth` → `xgb_max_depth`; `stamp_inf_confidence_threshold_scale` → `inference_cfg_confidence_threshold_scale`; `stamp_label_*` → `label_*`; `stamp_scaler_sha256` → `scaler_sha256`; `stamp_build_flags_hash` → `build_flags_hash`; `stamp_model_num_outputs` → `model_num_outputs`. ModelStampResult, StampInferenceCfgInputs, and ModelHandle now share field-name parity across the parse/emit/runtime boundary.
- `alignas(64)` on ModelHandle + 4-cluster layout:
    - **HOT cluster** (cache line 1 — 64B): `handle`, `backend`, `num_features`, `num_outputs`, `buy_class_idx`, `scaler_load_failed`, `normalizer`, `num_classes_active`, `_hot_pad0`, `normalizer_param`, `has_flags`, `_hot_pad1[4]` filling padding. Used at every Model_Predict inference.
    - **HOT-2 cluster** (cache line 2 — 64B): `target_classes[8]` + `class_weights[8]` for composite-signal extractor.
    - **WARM cluster**: `scaler` (FeatureStandardizer, ~600B; read during inference for feature normalization).
    - **COLD cluster**: X-macro-generated stamp-derived fields (read at boot-WARN / GUI panel surfaces). `model_path[256]` + `training_fingerprint[65]` at the very end.
- Explicit padding fields `_hot_pad0 = 0` (int16) and `_hot_pad1[4] = {0,0,0,0}` (4× int32) per CLAUDE.md item 27 — preserves byte-determinism for HMAC chain + memcmp.
- 4 static_asserts: `sizeof % 64 == 0`, `alignof == 64`, `offsetof(has_flags) < 64` (in HOT), `offsetof(target_classes) == 64` (HOT-2 boundary).

### v5.15.0.B — verify_model_stamp parser refactor (~120 LOC → ~30 LOC dispatch + 4 exceptions)

- 24 PRE_CFG manual `else if (strcmp(key, "...") == 0)` branches → 1 X-macro walk over `FOREACH_STAMP_BOUND_MODEL_CONST_PRE_CFG`. Mirrors the POST_CFG pattern from v5.14.8.A.merged.4.
- Per-type dispatch via `tt::stamp_parse_field<T>` templated helper (CLAUDE.md item 23) — handles char[N] strncpy / floating point parse / unsigned strtoull / signed atoi uniformly.
- 4 manual exceptions preserved as standalone branches BEFORE the X-macro chain (preempt the dead else-ifs from the registry walk):
    - `feature_scaler_present`: normalizes truthy → 1 / falsy → 0 (vs raw atoi cast which preserves non-1 truthy values).
    - `build_flags_hash`, `label_registry_hash`, `feature_mask`: hex-encoded uint64 (stamps emit "%016lx"); default `tt::stamp_parse_field<uint64_t>` uses base 10 strtoull.
- Future enhancement (deferred): extend registry tuple with a `parser_base` column (10 or 16) so hex fields auto-flow. Documented in TECH_DEBT-003 closure entry.

## What worked

1. **Pre-coding audit gate was load-bearing.** The locked Option C bit-position-sharing decision (from /dod-audit HIGH-2) meant ModelHandle.has_flags shares MASK_<name> with ModelStampResult — no parallel namespace, no parser-table column duplication. Catching this at plan-time saved hours of post-coding refactor.
2. **Step 0 inventory.** The pre-coding 84-site grep inventory caught the ModelValidation.hpp + FeatureRegistryOverlay.hpp:158 sites that an earlier narrower grep had missed. Per-site cross-off discipline prevented v5.14.post1-class missed-site recurrence.
3. **Brace-init Model_Init.** Replacing ~50 lines of explicit field zero-inits with `*m = ModelHandle<F>{};` + 5 non-zero overrides matches the ModelStampResult{} discipline at verify_model_stamp:1316. Default-member initializers on padding fields make padding determinism automatic.
4. **Sister-struct field-name parity.** ModelStampResult + StampInferenceCfgInputs already used canonical names; migrating ModelHandle to match closed the asymmetry. Every site that wrote `handle->stamp_X = sr.X` became `handle->X = sr.X` — natural single-source-of-truth across the parse → runtime path.
5. **Audit-driven sub-plan.** /readiness file:line corrections (BacktestEngine.hpp:1039 not :1147; BacktestPanels.hpp:2847 not :3206) saved Step 0 grep cycles during coding.

## What surprised

1. **HOT cluster size math was wrong on first pass.** Static_assert `offsetof(target_classes) == 64` failed because HOT cluster ended at offset 52 (12 bytes short of full cache line). Fix: widened `_hot_pad1` from `int32_t = 0` (4B) to `int32_t[4] = {0,0,0,0}` (16B). Static_assert caught this at compile time — discipline-pattern caught the layout drift before it could land as a silent bug.
2. **Scope of value-field rename surface (~124 sites) exceeded inventory (~84 has_* sites).** The Step 0 inventory only enumerated has_* references; the canonical-name rename added ~124 value-field reader sites. Net ~150-208 unique line edits. Manageable but ~2.5x the inventory estimate. For future X-macro migrations, both `has_X` AND `X` patterns should be enumerated.
3. **STAMP_MODEL_CONST_AUTOPOPULATE_ONE has no production callers today** (verified via grep). The `emit_when` and `get_value` columns in `FOREACH_STAMP_BOUND_MODEL_CONST_PRE_CFG` are dead text — they reference `inf->has_X` field names that no longer exist on `StampInferenceCfgInputs` (which now uses bit-packed has_flags). Worth a follow-up cleanup ship to either wire up callers OR delete the dead AUTOPOPULATE_ONE infrastructure. Tracked informally; not a sprint blocker.
4. **TryLoadRole copy block is a structural-fix candidate.** The ~50 LOC copy block in `CoreModelZoo_TryLoadRole` (post-verify_model_stamp) does `if (STAMP_HAS(sr, X)) { handle->X = sr.X; STAMP_SET(*handle, X); }` 14 times. Identical pattern; ripe for a `STAMP_HANDLE_COPY_FROM_RESULT(handle, sr)` companion macro mirroring `STAMP_MODEL_CONST_AUTOPOPULATE`. Captured as a FUTURE OPPORTUNITY comment in the migrated block; not in v5.15.0 scope. ~30 LOC follow-up.

## Decoupling-roadmap positioning

**POSITIONING: ⬆️ POSITIVE — X-macro stamp body + bit-packed has_flags advance the mmap-friendly wire format goal.**

- ModelHandle.has_flags as uint64_t bitmap is mmap-friendly (stable byte layout; no pointer chasing).
- Canonical wire-key field names across all 3 structs (parse / emit / runtime) mean a future external-process consumer (e.g., GUI service decoupled from engine) reads the same field names the engine writes. No translation table needed.
- Data-driven parser (.B refactor) supports cross-version compatibility — adding a new key to the registry auto-flows to all consumers; old engines silently ignore unknown keys via the existing `else` chain.

No anti-breadcrumbs introduced. No mutex / callback / in-process-only state added.
