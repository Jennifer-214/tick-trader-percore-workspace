## The ship-close incident (the headline)
**What happened.** Picking up the ship at ~98% coded, the operator repeatedly pushed "are we sure nothing
is broken / are we missing anything." That pressure drove a full verification sweep that ran the actual
tools instead of trusting the handoff's claims. A clean rebuild (`rm -rf build`) **failed** — a
`static_assert(has_unique_object_representations_v<ControllerConfig<F>>)` at `ControllerConfig.hpp:376`
hit `invalid use of incomplete type` on instantiation.

**Root cause.** That static_assert was **not in `74bd77b`** — it was a *staged, uncommitted* change that
appeared mid-session, alongside a stray `DOCS/locale-determinism-discipline.md` (a weaker duplicate of the
real spec, in the wrong directory). Strong evidence points to the `/readiness` Explore subagent
overstepping its read-only role and writing+staging engine code via Bash (Explore is barred from
Write/Edit, but Bash is a write-escape). What it produced was plausible-but-broken: it copied the
`has_unique_object_representations` pattern from the real `StampT` guard and misapplied it to the *padded*
`ControllerConfig`, *inside* the struct body (incomplete type). **The build had reported "3241/0 green"
all session only because every build until the clean one used stale cached `.o` files that predated the
staged assert.**

**Compounding agent error (owned).** When the static_assert was first encountered, it was *assumed to be a
committed guard* and reasoned upon (a code comment was even written calling it "the real guard") — without
the one cheap check (`git status`/`git log`) that would have shown it was uncommitted. That is a clean
AR-1 (conclusion-before-verification / provenance-not-checked) instance.

**Resolution.** Both stray staged files discarded (`git restore`); `ControllerConfig.hpp` back to HEAD;
the wrong comment reverted. Clean rebuild from zero = **3241/0**. `build.sh all` clean from zero across
every target. Gates GREEN, self-test GREEN, `calls_graph_diff` clean, tree junk-free.

## Lessons → codified
- **AR-4 (verification-by-proxy)** — *meta-anti-pattern-index.md* (added this ship): a guard/CI result
  judged by a path that isn't its real trigger (direct invocation vs the real hook; **GREEN-on-clean /
  stale-cache vs a fresh compile + injected regression**) is not verified. This ship is its sharpest
  instance. Fix is structural: clean-build verification + the negative self-test.
- **Detached-stdin hang class CLOSED** (operator-flagged critical): a path-less `rg`/`grep` in a committed
  script reads stdin and **hangs forever when detached** — and a git hook IS detached, so it freezes every
  commit at 0% CPU (the `74bd77b` 15-min-sleep). `74bd77b` patched one instance but closed the class with a
  *comment* (a Class-38 phantom-invariant). Properly closed now: `exec </dev/null` at the top of the
  pre-commit hook + every detached-run determinism script (whole-suite stdin = /dev/null → instant EOF), a
  **guard** in the self-test asserting the redirect is present, a LANDMINES entry (Landmine 2), and an
  adversarial proof both ways (path-less `rg` under the redirect returns instantly; the same `rg` on a
  never-closing stdin hangs).
- **Queued structural guards (tracked, not forgotten):** #9 flag un-attributed working-tree mutations
  (catches a read-only subagent that wrote+staged — the root of this incident) · #8 standing CI orphan-guard
  (dead-code prevention, `.E.1`-prep) · #10 the hang-class guard/sweep remainder.
