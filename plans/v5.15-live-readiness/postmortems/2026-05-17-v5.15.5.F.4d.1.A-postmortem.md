## Lessons captured

### Lesson 1 — `/merge-scan` caught a structural mistake the original plan didn't see
Path γ correction emerged from `/merge-scan` Phase 0 audit. Original `.A` v1.2 proposed building parallel walker macros that duplicated existing `FOREACH_METADATA_BIT` + `cfg_compute_mask` + `CFG_FIELD_FOR_EACH_SET_BIT` infrastructure (since `.F.4c.3`). The plan author missed it; the audit caught it. **Validates pre-coding audit gate discipline as load-bearing — not "nice to have"; routinely catches structural mistakes that would have shipped.**

### Lesson 2 — Phase 2 Level 4 codebase pattern survey surfaced 3 more sister DRIFT-MAJOR specs
D4 audit dimension found that `sidecar-override-pattern-for-registry-auto-flows.md` + `meta-registry-pattern-for-codebase-registry-discipline.md` + `multi-bit-state-encoding-pattern.md` all had aspirational Stage 3 ACTIVE / INVARIANT status claims at `.F.4d` ship close that didn't reconcile with actual code. **Pattern recognition: specs drafted at planning time + code shipped at different ship + no reconciliation step = systematic drift.** TECH_DEBT-089 (DESIGN_SPECS spec-vs-code drift audit cadence) opened to codify periodic reconciliation discipline.

### Lesson 3 — Auto-pick principle codified as collaboration discipline
Caramel pushback: "how do i know your using the optimal design pattern and not just giving me the easiest to implement or the one youve seen the most?" → codified `feedback_auto_pick_future_oriented.md` + CLAUDE.local.md going-forward rule. **Operating principle: auto-pick future-oriented when trade-off clear; surface only genuine ambiguities; never punt with "your call" framing on auto-decidable decisions.** Applied throughout Path γ+ v2 triage (Option D over Option C; cli_explain fix at `.A` vs defer; stamp_emit delete at `.A` vs defer).

### Lesson 4 — Per-sub-ship audit-update-implement-ship cycle prevents endless planning loops
Caramel insight: "i guess this prevents endless planning loops, probably a good idea". Codified in CLAUDE.local.md. **Cycle's discipline: audit ENOUGH to make THIS sub-ship structurally sound; bank rest as TECH_DEBT for future cycles.** Natural shipping boundary forces forward motion; without it, Level 5/6/7 audits would find more sister drifts indefinitely.

### Lesson 5 — `check()` signature + linkage interaction
Original draft of `wire_format_invariants.hpp` declared `extern void check(const char*, bool)` causing ambiguity with `static void check(const char*, int)` in `controller_test.cpp`. Fix: removed forward declaration; moved `#include "wire_format_invariants.hpp"` to file scope AFTER `check()` static fn definition (line ~88). Inline helper now resolves `check()` at compile time via translation-unit visibility. **Pattern for future header-only test helpers: include AFTER framework's static fns are defined; rely on translation-unit visibility, NOT forward decl.**

### Lesson 6 — TECH_DEBT-092 effectively closed by C++ duplicate-symbol detection
Original spec called for X_GEN_* namespace collision static_assert. On implementation, recognized that `X_GEN_GLOBAL_MASK` + `X_GEN_PER_CORE_MASK` auto-generate `g_<reg>_cfg_<lname>_mask` symbols — if FOREACH_METADATA_BIT + FOREACH_LIVES_IN_STRUCT ever share an lname, the C++ compiler ALREADY errors with "redefinition of g_..._mask". The discipline is structurally satisfied by existing machinery; static_assert layer redundant. **TECH_DEBT-092 entry kept as documentation; status updated.**
