## CRITICAL parity findings — coding blockers + Caramel decision points

### Parity Finding 1 — § C.3 PART 1 drift gates use per-field STAMP_BITs that don't exist

**Plan body has** (lines 296/302/308/314/320 of amended plan):

```cpp
gate_when: STAMP_HAS(*h, inference_cfg_bandit_algorithm)        // ← per-field bit
gate_when: STAMP_HAS(*h, inference_cfg_thompson_mu_prior)       // ← per-field bit
gate_when: STAMP_HAS(*h, inference_cfg_thompson_precision_prior) // ← per-field bit
gate_when: STAMP_HAS(*h, inference_cfg_thompson_precision_obs)   // ← per-field bit
gate_when: STAMP_HAS(*h, inference_cfg_thompson_exp3_blend_alpha) // ← per-field bit
```

**Reality (verified at `ML_Headers/StampBoundModelConstRegistry.hpp:511-548`):** The `StampHasFlagBit` enum is MANUAL, not auto-generated from POST_CFG registry. Only the GROUP bit `STAMP_BIT_inference_cfg = 0` (line 514) exists. Per-field bits for these new fields would need to be EXPLICITLY ADDED to the enum + MASK constants. Adding 5 new per-field bits is contrary to the v5.15.5.A.7 precedent which used the group bit.

**Result if shipped as-is:** Build failure at compile time — `MASK_inference_cfg_bandit_algorithm` undefined in `STAMP_HAS` macro expansion.

**Fix:** Change all 5 drift rows to use group bit, sister to `.A.7` cohort at `CfgDriftCheckRegistry.hpp:276-288`:

```cpp
gate_when: (STAMP_HAS(*h, inference_cfg) && BITMAP_IS_SET(cfg.ml_cfg_flags, MASK_ML_CFG_BANDIT_ENABLED))   // group bit + ml-side filter
```

Special case for `thompson_exp3_blend_alpha`: gate_when is `(STAMP_HAS(*h, inference_cfg) && cfg.bandit_algorithm == 4)` — BLENDED-state filter on top of group bit.

**Resolution: simple plan body fix; ~5 minutes; mechanical correctness, no design change.** Recommend: APPLY.

### Parity Finding 2 — § C.3 PART 2 POST_CFG rows DUPLICATE wire emission of 4 pre-existing cfg fields

**Plan body adds 5 POST_CFG rows** in § C.3 PART 2 — generating wire keys `inference_cfg_bandit_algorithm=N`, `inference_cfg_thompson_mu_prior=X.X`, etc.

**Reality (verified at `ML_Headers/StampBoundCfgRegistry.hpp:163-170`):** 4 of those 5 fields (`bandit_algorithm` + 3 `thompson_*`) ALREADY EMIT to wire via `FOREACH_STAMP_BOUND_CFG` since v5.14.10.B. Their wire key today: `bandit_algorithm=N` (NOT `inference_cfg_bandit_algorithm=N`). Inline drift loop at `CoreModelZoo.hpp:225-247` already walks `FOREACH_STAMP_BOUND_CFG` and compares `sr.bandit_algorithm` vs `cfg.bandit_algorithm` per-model-load.

**The 5th field** (`thompson_exp3_blend_alpha`) is NEW at `.F.4c.4`; it has NO existing FOREACH_STAMP_BOUND_CFG row, so adding a POST_CFG row for it is the canonical (non-duplicative) path.

**The decision split** is what to do with the 4 pre-existing fields:

#### Option A — Accept dual-emission (current plan amendment direction; recommended)

- Keep all 5 POST_CFG rows (4 dual-emit + 1 new)
- Keep all 5 drift-check rows (with Finding 1 group-bit fix applied)
- Keep all 5 cfg→inf wiring rows
- Stamps post-`.F.4c.4` carry BOTH wire keys for the 4 pre-existing fields (`bandit_algorithm=N` + `inference_cfg_bandit_algorithm=N`)
- Legacy v5.14.10.B-v5.15.5.F.4c.3 stamps still load (parser tolerates absent keys; existing CFG-registry path still emits)
- Document the dual-emission EXPLICITLY in cfg.example + tooltip + plan body so operator inspecting stamps isn't confused

**Pros:**
- Structural Class 18 walker rows (CfgDriftCheckRegistry) use the canonical `h->inference_cfg_X` shape — matches `.A.7` cohort precedent (lines 276-291)
- PARITY-026 fully closes structurally (moves from inline-only drift coverage to inline + structural; structural drift is the canonical shape)
- Future bandit/thompson cfg fields auto-flow via same pattern
- No back-compat break

**Cons:**
- Wire format slightly noisier — every stamp carries duplicate keys for 4 cfg fields
- Verifier reads both keys without complaint, but operator inspecting a stamp file sees redundant entries (~5 extra lines per stamp; ~150 bytes; negligible disk-wise but operator-confusing)
- Eventually wants a sunset ship to REMOVE the legacy FOREACH_STAMP_BOUND_CFG rows for bandit/thompson — requires MODEL_FORMAT_VERSION bump + forced retrain (deferred indefinitely)

**Mitigation:** add prominent comment block at `FOREACH_STAMP_BOUND_CFG` lines 163-170 marking those rows as "deprecated; superseded by FOREACH_STAMP_BOUND_MODEL_CONST_POST_CFG `inference_cfg_*` mirror at `.F.4c.4`; sunset scheduled for vN+1+ with MODEL_FORMAT_VERSION bump." TECH_DEBT entry tracks sunset.

#### Option B — Single-emit; reuse existing wire path (parity agent's recommendation)

- DROP § C.3 PART 2 POST_CFG rows for 4 pre-existing fields (keep only `thompson_exp3_blend_alpha`)
- DROP § C.4 cfg→inf wiring rows for 4 pre-existing fields (keep only `thompson_exp3_blend_alpha`)
- Restructure § C.3 PART 1 drift rows for 4 pre-existing fields to use `sr.X` path (via parsed stamp result) instead of `h->inference_cfg_X` — different drift check infrastructure than CfgDriftCheckRegistry canonical
- Reframe PARITY-026 closure as "extend inline drift loop coverage" not "add structural Class 18 walker rows"

**Pros:**
- Clean wire format; single wire key per cfg
- No legacy wire-key deprecation needed

**Cons:**
- Drift check infrastructure is mixed — 4 rows use `sr.X` (different shape), 1 row (`thompson_exp3_blend_alpha`) uses `h->inference_cfg_X` (canonical shape)
- PARITY-026 closure becomes partial — fields remain only in inline-loop drift coverage; not in CfgDriftCheckRegistry canonical structural shape
- Future bandit/thompson cfg additions face a fork — which shape? — increases drift-check shape complexity
- Doesn't move 4 fields to canonical `inference_cfg_*` mirror taxonomy
- More invasive amendment (4 sections need restructuring vs Finding 1's simple gate-condition fix)

#### Option C — Full migrate; not dual-emit; requires MODEL_FORMAT_VERSION bump

- DELETE 4 bandit/thompson rows from `FOREACH_STAMP_BOUND_CFG`
- ADD 5 POST_CFG rows (parallel to Option A direction)
- Keep all drift + cfg→inf wiring
- BREAKS wire format byte preservation for v5.14.10.B-v5.15.5.F.4c.3 stamps (operator must retrain)

**Verdict: not recommended** unless we want a hard break. Bumps MODEL_FORMAT_VERSION; forced retrain; operator pain disproportionate to benefit. Defer indefinitely.

#### Recommendation

**Option A.** Reasoning:
- Finding 1 fix is the only structural change needed (~5 min apply); rest stays
- Matches plan body's current amendment direction (POST_CFG rows already drafted in § C.3 PART 2)
- PARITY-026 structurally closed via canonical Class 18 walker shape
- Preserves wire format back-compat (operator doesn't need to retrain)
- Sunset of legacy FOREACH_STAMP_BOUND_CFG rows logged as TECH_DEBT (deferred indefinitely; not a coding-time concern)
- Operator-visible dual-emission documented explicitly so it's not a silent surprise

**Caramel's call. Option A is the lowest-friction path; Option B is structurally minimalist but requires substantial re-amendment; Option C breaks back-compat.**
