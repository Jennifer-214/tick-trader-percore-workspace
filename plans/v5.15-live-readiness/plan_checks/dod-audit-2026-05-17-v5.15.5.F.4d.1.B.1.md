## Findings (severity-ordered)

### MEDIUM-1 — Sidecar `cfg_gate_lookup` linear-scan branchless claim needs concretization
- **Surface:** sidecar examples § Step 1 lines 41-72 ("CfgGateEntry struct" + comment "Branchless: linear scan over FOREACH_CFG_GATE sparse entries")
- **Pattern:** sidecar-override-pattern-for-registry-auto-flows.md § Option D + branchless-dispatch-discipline.md (H20)
- **Symptom:** sidecar example shows pseudo-struct `CfgGateEntry { row_idx; gate_fn; }` + comment "compiler generates equivalent jump-table" — but actual lookup shape is unwritten. The canonical sidecar pattern at `.F.4d` (FOREACH_DRIFT_OVERRIDE per `sidecar-override-pattern...md` Option D) used **sparse array indexed by FIELD_IDX** (`g_global_drift_overrides[FIELD_IDX_GLOBAL_END]` zero-initialized, branchless O(1) lookup with `.has_override` flag). The .B.1 sidecar comments suggest linear scan + fn-pointer table, which is a **different shape** with branch + indirect call. At slow-path/stamp-emit cadence cost is negligible BUT the inconsistency may surface as drift later when the 2nd gate-type sidecar lands. Per H20: branchless preferred even when nominally slower — fn-pointer indirect call introduces variance.
- **Suggested fix:** sidecar example § Step 1 should mirror the FOREACH_DRIFT_OVERRIDE canonical shape exactly: `CfgGate g_per_core_cfg_gates[FIELD_IDX_PER_CORE_END] = {0}; CfgGate g_global_cfg_gates[FIELD_IDX_GLOBAL_END] = {0};` indexed by parent's FIELD_IDX, populated via X-macro reduction at file scope. Lookup at consumer = single load from `.rodata` (branchless O(1)). No fn-pointer; gate expression encoded as bitmap mask reference per multi-bit-state-encoding-pattern.md or as 8-bit "gate_kind" enum dispatched branchlessly.
- **Effort estimate:** ~20 min sidecar doc concretization; no code change yet (Step 1 NEW file).
- **Cross-references:** sidecar-override-pattern-for-registry-auto-flows.md Option D lines 76-98, branchless-dispatch-discipline.md Pattern 2

### MEDIUM-2 — Sidecar lookup type erasure breaks H13 (Class 23 anti-pattern echo)
- **Surface:** sidecar examples § Step 1 lines 64-67 (`bool (*gate_fn)(const ControllerConfig<auto>&);`)
- **Pattern:** type-trait-dispatch-via-tt-namespace.md (closes Class 23 via "no void*+offset / no type-erased reinterpret_cast")
- **Symptom:** `ControllerConfig<auto>` is not valid C++17/20 — `auto` template parameter requires C++20 abbreviated function template AND only valid in fn parameter lists, not pointer-to-fn types. More critically, **the entire fn-pointer approach loses template type information** for `F` (ControllerConfig<F>), forcing a non-template gate fn signature OR per-F instantiation of every gate fn. Echoes the Class 23 anti-shape (type-erased dispatch via fn-pointer table over typed templated state).
- **Suggested fix:** drop fn-pointer column entirely; use **gate_kind enum + branchless dispatch via mask reduce** per multi-bit-state-encoding-pattern (canonical at FOREACH_DRIFT_OVERRIDE). Gate expressions like `BITMAP_IS_SET(cfg.ml_cfg_flags, MASK_ML_CFG_BANDIT_ENABLED)` encode as small enum (`GATE_BANDIT_ENABLED=1`, `GATE_RIDGE_ANY=2`, `GATE_COMPOSITE=3`, `GATE_DEFAULT=0`) → branchless lookup table per-kind reading bitmap-domain masks directly from `cfg.ml_cfg_flags`. Same canonical shape as multi-state-dispatch-with-per-state-update-metadata.md.
- **Effort estimate:** ~30 min sidecar doc + Step 1 amendment; encode 4-5 gate-kinds as enum + small per-kind dispatch table.
- **Cross-references:** multi-bit-state-encoding-pattern.md, multi-state-dispatch-with-per-state-update-metadata.md, type-trait-dispatch-via-tt-namespace.md H13

### MEDIUM-3 — Consumer macros build duplicate per-core + global walker bodies (mirror anti-pattern echo)
- **Surface:** sidecar examples § Step 2 lines 89-101, 106-117, 122-146 (each consumer macro has TWO `CFG_FIELD_FOR_EACH_SET_BIT` blocks — one for per_core, one for global, with parallel bodies)
- **Pattern:** structural-fix-preferred-decision-framework.md + autopopulate-pattern-for-production-caller-class.md
- **Symptom:** Each of 3 consumer macros has structurally identical per-core + global walker pair. Per Class 18 mirror discipline: if 3 consumer macros × 2 walker variants = 6 nearly-identical loop bodies, fix in one consumer's body needs mirroring at 6 sites. Same shape that `decision-time-data-binding-pattern.md`'s "registries optimize for ADDING; principle+sweep optimizes for ELIMINATING" warns against — mechanicalizing the mirror entrenches it.
- **Suggested fix:** extract `CFG_WALK_DERIVED(bit_lname, body)` helper macro that takes the per-row body once + emits both per_core and global walks:
```c
#define CFG_WALK_DERIVED(bit_lname, idx_var, descriptors_ref, body) \
    CFG_FIELD_FOR_EACH_SET_BIT(g_per_core_cfg_##bit_lname##_mask.words, idx_var, { \
        const auto& descriptors_ref = g_per_core_cfg_field_descriptors[idx_var]; body; }); \
    CFG_FIELD_FOR_EACH_SET_BIT(g_global_cfg_##bit_lname##_mask.words, idx_var, { \
        const auto& descriptors_ref = g_global_cfg_field_descriptors[idx_var]; body; });
```
Then consumer macros become ~3-5 LOC each. Closes mirror class at consumer-macro layer.
- **Effort estimate:** ~30 min sidecar amendment.
- **Cross-references:** structural-fix-preferred-decision-framework.md, decision-time-data-binding-pattern.md § "framework-selection criteria"

### MEDIUM-4 — DRIFT_CHECK_AUTOPOPULATE inner branches violate H20 branchless discipline
- **Surface:** sidecar examples § Step 2 lines 126-133 + 138-145 (`if (_gate) { ... if (_drifted) { BITMAP_SET + drift_count_ref++ } }`)
- **Pattern:** branchless-dispatch-discipline.md H20 + DRIFT_CHECK gate is slow-path/load-time cadence
- **Symptom:** Two nested if-branches per row. The drift check is slow-path (load-time), so cost is low absolute — but the discipline per H20 (added v5.15.5.F.4c.3 WIP2d-1.B.0d) is "branchless preferred for SP/HP data-dependent dispatch EVEN WHEN NOMINALLY SLOWER" — mask code optimizes better; branches inject variance.
- **Suggested fix:** mask-select instead of branch:
```c
const uint64_t _drifted_mask = -(int64_t)(_gate & _drifted);
*(failure_flags) |= (FAILURE_MASK_cfg_inference_drift & _drifted_mask);
(drift_count_ref) += (uint32_t)(_drifted_mask & 1);
```
Pattern 3 (mask-select for binary cheap-both-sides) per branchless-dispatch-discipline.md.
- **Effort estimate:** ~15 min sidecar amendment.
- **Cross-references:** branchless-dispatch-discipline.md Pattern 3, H20
