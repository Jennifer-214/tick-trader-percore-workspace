## The TD-202 close (this session — the gate earned its tokens)

The asan ship-gate surfaced a pre-existing (Ship-B-vintage) heap-use-after-free in the OMS async event-log writer. The inherited framing was "few-line, test-only Init harden." A **3-I → 3-A `/precoding-audit-gate`** (the dedicated audits, run as skills) **broke that framing**:

- The asan ring-UAF **is** test-only (the test's double-`Init` clobbers `writer_thread_active` while the writer runs → the guarded `Free` join no-ops → free-under-live-writer). Fix: **quiesce-first `OrderEventLog_Init`** + in-class-init the lifecycle atomics `{0}` (the guard's pre-Init read must be defined on default-init OMS sites). **RBP Class 50** (re-init/reset defeats the thread-join lifecycle).
- But the gate found a **production, on-by-default sibling**: `OrderEventLog_Reset` (paper-reset) `fclose`/`fopen`s `disk_file` while the live writer + drainer touch it — a 3-way race — **plus** a `LoadFromDisk` no-integrity-gate that folds a scrambled record into the warm-restart balance. Both **folded to `.E.1`** (the single-owner-`disk_file` rework), not patched static.
- The gate **refuted** the naive Reset fix (a drainer-thread `pthread_join` = ~100× the ≤10µs budget, H8).

## Lessons (codified, not just noted)

- **Fix toward the future trajectory, not the static present** (operator-directed) — a fix to code a documented future ship will rework must be a forward-compatible **foundation increment** toward that destination, never a patch the rework discards. NEW DESIGN_SPEC + memory + `/precoding-audit-gate` & `/decision-check` arming (the subagent classes now carry it as a standing lens) + going-forward rule.
- **A verification gate must run a binary built from CURRENT source.** Dogfooding the V-class on TD-202's own fix exposed that `run_all_tests --full` ran a **months-old `build_asan/`** (ubsan jumped 3246→3632 once rebuilt fresh — the staleness was systemic, across both lanes, for many ships). STRUCTURAL fix: `run_sanitizer_suite.sh` now rebuilds each lane from current source before running. (`.E.0.6` clean-rebuild lesson, now enforced at the sanitizer gate.) The V-class spec → v1.1 (sanitizer-freshness load-bearing).
- **The V-class (post-implementation verification) earned its keep twice this session** — it caught (1) a wrong test-fix assumption (removing the re-init left the async writer live → 4 fee-reads raced; `StopAsyncWriter` is the correct quiesce) and (2) the stale-binary masking — both *before* "done."
- **Run the dedicated audit skills, not armed prompts** — the 3-I→3-A gate (real `/trace-deps` + `/hft-audit` + the adversarial trio) surfaced the production sibling + the recovery hole that an armed general agent would have missed.
