# v5.15.5.F.4d.1.E.0.2 — Meta-error-tracking subsystem

**Status:** v0.1 DRAFT (2026-05-29). **Branch:** `feat/v5.15-live-readiness`. **Build it FRESH** (next focused session) — the design is scoped here; rush-building foundational tracking-infra in a close-tail is the exact anti-pattern it exists to catch.

## TL;DR

Non-code errors (audit-reasoning, planning, doc/workspace-hygiene) currently lack the single-catalog + scan parity that CODE anti-patterns have (`RECURRING_BUG_PATTERNS` Classes 1-36 + `/bug-check`). They're DISPERSED across M1-M7, B14-B19, `/capture-audit`, `/metadata-audit`, sister-cohort-completeness, and `feedback_*` memories. This ship gives them a HOME with parity: **a META anti-pattern catalog + three enforcement mechanisms (a propagation scan + a session-close harvest + a hardened pre-coding gate that consumes the catalog)** — ONE coherent subsystem, built together (per D-75). Prioritized BEFORE the `.E` pipeline (D-76) because it's process-foundation that protects every downstream ship (cascade-audit catches `.E.1`-rename propagation misses; the harvest catches each ship's meta-errors; the hardened gate makes the catalog + memory corpus *executable* against every plan).

**v0.2 adds Piece 4 (the hardened `/precoding-audit-gate`) + the heavier-default audit posture (D-77) + the calibration approach + the apparatus-complete definition-of-done (D-78).** The unifying idea: the memory corpus stops being a passive reference and becomes an **executable, self-reinforcing loop** — memory → catalog (indexes it) → gate (consumes it as checks) → harvest (surfaces new shapes) → memory. The loop is closed BEFORE the highest-yield ship (`.E.1`'s ~5,000-site rename) so it protects the riskiest coding. **This whole subsystem IS the apparatus that gates `.E.1`+ implementation** — no implementation until the guard-matrix shows no HOLE for the touched surface. Empirical mandate for the heavier default: the majority of the existing codebase was light-pass-audited and `.E.0` surfaced 141 findings (D-77).

**No engine code.** Doc + `SKILL.md` + CI tooling only.

## The four pieces (design them together — shared schema)

### Piece 1 — the META catalog (the index)
A unified catalog of non-code recurring error-shapes, parity with `RECURRING_BUG_PATTERNS`.
- **Open design decision A — relationship to existing structures (the crux; resolve FIRST):** M1-M7 (audit-methodology gaps) + B14-B19 (impl-blindspots) ALREADY catalog meta-shapes. Does this catalog (a) AGGREGATE/INDEX them (a meta-index pointing to M/B + adding org/workspace shapes), or (b) introduce a NEW numbered class-series (e.g. "MetaClass-1..N") for org/planning/workspace shapes specifically, with M/B as siblings? **DECIDED (a) — an INDEX** (aggregate/point-to M1-M7 + B14-B19 + the workspace-hygiene checks; add the missing org/planning/workspace shapes as NEW entries; do NOT re-number or duplicate M/B) — per canonical-sister + framework-diminishing-returns (firmed at `.E.0.2` planning 2026-05-29; low-risk, same don't-duplicate logic applied all session). The index SCHEMA details (entry fields; how the harvest writes + the cascade-audit reads it) resolve at build.
- **Decision B — location:** `DESIGN_SPECS/meta-disciplines/meta-anti-pattern-index.md` (or `DOCS/`?). Frontmatter-tagged like the rest.
- **Seed entries (this session):** enumerate-set-before-categorical-claim (codified as memory; M8-candidate) · memory-link-convention-drift (kebab vs filename slug) · over-generalized-spec-definition (the determinism gate "all-ops native==generic" — an enumerate-set instance) · cascade-not-propagated (= sister-cohort) · stale-index-pointer.

### Piece 2 — cascade-audit (the propagation scan) → `/capture-audit` Check 12
On a decision/spec/definition amendment, grep its key terms across plans/handoffs/decision-logs/memories → flag un-propagated references.
- **Canonical-sister:** EXTEND `/capture-audit` (Check 9 sister-cross-ref is nearest; NOT a new `/cascade-audit` skill — would duplicate drift-check machinery; `/dependency-chain-trace` is code-symbol-only).
- **M7 escalation** for `sister-cohort-amendment-completeness` (cascade-misses recurred `.E.0.1` close → manual propagation).
- **Open design decision C — detection (the hard part):** the check must know WHAT was amended (which term/definition) to grep. Likely: diff-detect a changed decision/spec/definition block (`<!-- D/C/F -->` sentinel / `## ` heading / frontmatter `name:`) → extract its title/key-terms → grep the doc corpus → flag refs in un-amended files. Define the false-positive surface (a term legitimately referenced in many places without needing update).

### Piece 3 — close-out harvest (the population mechanism) → `/close-session` Stage
At session close, reflect: "what recurring meta-shapes did this session's pushbacks/errors surface?" → catalog them.
- **Canonical-sister:** EXTEND `/close-session` with a Stage (NOT a new skill).
- **Judgment-laden, NOT mechanical:** unlike Check 11's forward-promise grep, meta-error detection can't be pure-grepped → a STRUCTURED-REFLECTION stage (prompts + checklist), not a scan. Prompts (draft): "Did operator pushback surface a recurring shape (not just a one-off fix)? Did I make a reasoning/planning/workspace error this session? Did a definition change need manual propagation? → name the shape + add/point-to a catalog entry."
- **Rationale:** `feedback_operator_pushback_as_audit_signal` § generative dimension (pushback-past-"done" is generative; the session's own errors are the highest-signal seed corpus — `.E.0.1` close: 3/5 seeds from one hour of pushback).

### Piece 4 — the hardened `/precoding-audit-gate` (the catalog made executable) → EXTEND `/precoding-audit-gate`

The gate's job is *consistent* correctness, but today it's STOCHASTIC (LLM subagents; same gate, different findings run-to-run → operator does multiple passes). Fix = apply the D-70 enforcement ladder to the gate ITSELF + make it a CONSUMER of this subsystem's catalog + the memory corpus. **Empirically grounded** (operator 2026-05-29): the majority of the existing codebase was light-pass-audited and `.E.0` surfaced 141 findings → the default posture must be HEAVIER (D-77).

- **Heavier-default posture (D-77).** Raise the default tier; the LIGHT pass is an EARNED exception (refines `feedback_tiered_audit_discipline_per_plan_scope`). Decision rule: **audit weight ∝ inverse deterministic coverage** — HEAVY where the guard-coverage-matrix has a HOLE (the LLM pass is the only guard for that surface), LIGHT where a Tier-1/2 deterministic guard (CI gate / `static_assert` / golden-master / determinism+replay) is already the floor. The matrix tells you where the holes are; heavy goes there.
- **Deterministic Stage-0 (mechanize-down).** Before any LLM agent spawns, run the existing Python checkers (`check_plan_body_symbol_existence` / `check_plan_body_tests_section` / `check_forward_promise_audit`) as ground truth, so mechanizable checks never rest on a stochastic agent noticing them. Inventory remaining LLM-only-but-mechanizable checks (findings_sidecar wiring, cross-ship-invariant presence, frontmatter completeness) → migrate down incrementally.
- **Catalog/memory as checks.** The gate reads this subsystem's META catalog + the memory corpus (Classes 1-36 + M1-M7 + B14-B19 + the `feedback_*` rules) → every cataloged shape becomes a check the gate runs. As the catalog grows (via the Piece-3 harvest), the gate auto-gains coverage — the memory→catalog→gate→harvest loop.
- **Quorum on the highest-risk dimension.** For HIGH-RISK ships, run the single most consequential lens (correctness/parity) as N independent agents; a finding counts only if ≥k agree → kills the variance on the part that matters most (the multiple-passes pain).
- **Verification + completeness-critic pass.** A follow-on agent adversarially re-checks each CRITICAL/HIGH (real vs plausible-but-wrong) AND asks "what surface did no audit cover?" — catches false positives AND false negatives a find-only gate can't.
- **Calibration, NOT abstract design (D-78).** Build/tune against REAL ships: **backward** — mine shipped `.D.1`/`.B.8` plans + postmortems + handoffs for "what the gate passed but we caught later" (the empirical gap-spec); **forward** — `.E.0.1` as the live calibration bench (the way `/plan-dive` was calibrated on `.E.1`; `.E.0.1` is foundation + independently protected by its own deterministic gates → safe bench). NO gold-plating against imagined gaps.
- **Canonical-sister:** EXTEND `/precoding-audit-gate` (its Stage-4 synthesis already cross-refs DESIGN_SPECS; add the catalog/memory ingestion + Stage-0 + quorum + verification pass). NOT a new skill.
- **Open design decision D — quorum k-of-N + which dimension(s) + the Stage-0 checker set + the catalog-ingestion schema** (shared with Pieces 1-3). Resolve at build; default lean: k=2-of-3 on the correctness/parity lens for HIGH-RISK.

## Honest risks
- **R1 — catalog duplicates M/B.** Mitigation: Decision A FIRST; lean INDEX (aggregate, don't re-number) per canonical-sister.
- **R2 — Check 12 detection is unbuildable-mechanically** (extracting "the amended term" is hard). Mitigation: start semi-mechanical (flag changed decision/spec blocks + prompt manual grep) → mechanize incrementally; even the semi-mechanical version beats memory-only.
- **R3 — harvest becomes ceremony** (every close lists trivial "meta-errors"). Mitigation: prompt for RECURRING shapes worth cataloging, not one-offs; yield-as-signal (track catalog growth; if it's all noise, tighten the prompt).
- **R4 — building it rushed (the irony).** Mitigation: THIS plan exists so the build is deliberate, not close-tail-crammed.
- **R5 — gate hardening over-engineers / never terminates** ("harden the hardening?"). Mitigation: the apparatus-complete DoD above IS the bound — build to guard-matrix-no-HOLE for the touched surface, then stop and code; the ratchet handles the rest incrementally. Calibrate against real ships, not imagined gaps (D-78).
- **R6 — quorum/verification pass balloons cost.** Mitigation: quorum ONLY on the highest-risk dimension for HIGH-RISK ships (not every lens, not every ship); the coverage-gated rule means light/skip where deterministic guards already cover, so the heavy spend goes only to the HOLE surfaces.
