## Why this ship matters

Without v5.13.1: operator wanting heterogeneous mixed-output ensemble
(e.g., regression at h=50000 + binary at h=1000 + 3-class at h=7500)
must run Multi-Horizon trainer THREE TIMES (one per label_kind).
Tedious and easy to mis-coordinate.

With v5.13.1: ONE training run with per-horizon label_kind selection.
Bandit blends across types via v5.12.3.B+E normalizer.

**This is operator-side convenience, not engine functionality.**
v5.12.3.B+E runtime works regardless. v5.13.1 just smooths the
training workflow.

## Implementation plan

### Step 0 — Inspect Multi-Horizon panel current state

```bash
grep -n "Multi-Horizon\|multi_horizon\|label_kind\|ImGui::Combo.*label" \
    Backtest/BacktestPanels.hpp | head -20
```

Identify:
- Where the uniform label_kind dropdown lives
- How horizon list is currently rendered
- Where the trainer driver (mh_per_horizon_*_worker) reads label_kind

### Step 1 — Per-horizon dropdown + side selector

Each row in the horizon table gets its own label_kind dropdown.
The training config gains:
```cpp
int label_kind_per_horizon[ENSEMBLE_HORIZON_MAX];
int training_side;  // 0 = buy, 1 = exit (or use enum)
```

Top-level "side" radio button or dropdown in the panel header
selects buy vs exit for the entire training run. (Operator runs
trainer twice for both sides — once with side=buy, once with
side=exit. Future v5.13.X Training Queue panel batches this.)

### Step 2 — Trainer driver wires per-horizon label_kind + side

Each call to the per-horizon worker passes the SPECIFIC label_kind
for that horizon. Output path derivation:
```cpp
const char *side_dir = (cfg.training_side == 0) ? "buy_signal" : "exit_signal";
char output_path[512];
snprintf(output_path, sizeof(output_path),
         "%s/%s/horizon_%d/model.json",
         cfg.ml_model_dir_base, side_dir, horizon_ticks);
```

Stamp body records both `label_kind` (already the case) and
`side` (NEW informational field via Surface G `has_side` flag).

### Step 3 — Tests

- Multi-Horizon config with [3-class, regression, binary] for 3
  horizons trains 3 models with respective label_kinds
- Each stamp body records its own label_kind (verifiable via
  `verify_model_stamp` round-trip)
- Loader populates `normalizer` per stamp correctly (regression →
  NORM_REGRESSION, etc.)
- Side selector: side=buy routes to `models/buy_signal/horizon_<N>/`
- Side selector: side=exit routes to `models/exit_signal/horizon_<N>/`
- v5.13.0 loader picks up exit-side models from
  `cfg.exit_signal_model_dir` after side=exit training run completes
- Stamp body `has_side` Surface G flag; legacy stamps without flag
  load with default side=buy (backward compat)
