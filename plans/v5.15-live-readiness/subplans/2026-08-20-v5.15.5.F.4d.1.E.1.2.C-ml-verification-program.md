## Problem statement

Every layer of the ML loop is *advertised* and *test-green*, and almost none of it has ever run end-to-end in production shape. The investigation measured, at HEAD:

1. **The exit-bandit reward update is DEAD on every production path — live and backtest — and has been since v5.14.1.F.** The `EventLoop_DrainPostFill` fan passes 10 positional args into `EventLoop_DrainPostFillOneCore`'s 12-param signature; a v5.14.1.F mid-signature insertion (`confidence_ic_variant` at position 9) silently shifted every later binding: the cfg exit flag lands in the IC-variant param, the fee constant `0.001` truncates into `int exit_bandit_enabled` (= 0, always), and `node_cfg` stays nullptr (Thompson forced to EXP3 on the drainer). **Compiled-probe-proven** (bandit report H-1) and **independently re-derived** by the backtest agent (Defect 2). Worse than dead: flipping `exit_bandit_enabled=1` in LIVE would set the IC variant out-of-range → constant 0.0 IC → guaranteed drift-floor breach → with `auto_kill_on_drift=1`, **spurious per-node auto-kill** — the flag poisons a capital safety control instead of enabling learning. D-423's "reward half works" premise was false when written.
2. **PARITY-043:** the cfg-derived stamp cohort is **36 fields** (measured; not "~30"); all 36 declared on ModelHandle, **33 written by nothing** — the family has 4 of its 5 walkers; the sr→handle copy walker was never built. With `bandit_enabled` now defaulting ON, two REFUSE_STRICT rows fire falsely on **every** model load at a default cfg.
3. **PARITY-044:** exit-side training routes to a tree nothing loads, with buy-role filenames, side-blind labels, a parsed-never-read cfg pointer, and no side marker anywhere — while the serve side already walks co-located `exit.json` slots that nothing produces. The exit-bandit loop has **no production model source**.
4. **The live train path emits NO scaler and no stamp scaler binding** (both sides): the only scaler producer is `train_model_worker_fn`, which is **dead code** (zero callers since v5.11.44; the Train Model button routes through the multi-horizon worker). The v5.9.3 scaler verification chain is unreachable from the GUI. The Save Run block is dead UI (gated on a flag only the dead worker sets).
5. **At HEAD there is NO functioning train↔serve cfg-parity gate at all** (PARITY-042 vacuous + PARITY-043 false-firing + ensemble loads skip the drift walk entirely + single-zoo boot hardcodes `secret=nullptr` so Shape-B loads never HMAC-verify). cfg-parity currently rests entirely on keeping `backtest.cfg ≡ engine.cfg`.

**End goal:** the complete loop — train (buy AND exit) → stamp → load → predict → trade → attribute → learn → persist → reload — runs end-to-end, in backtest and paper, with every gate that guards it non-vacuous, and with the false-noise layers removed. The E series resumes on that verified base.

**Acceptance (per leg, all re-derivable):**
- **Leg 0:** a seam-level regression test drives the production wrapper with `exit_bandit_enabled=1` through a synthetic fill and asserts `exit_bandits[r].pulls` moved (the exact blind spot the leaf-level test C.3c leaves); `confidence_ic_variant` reaches OneCore un-perturbed; backtest completion writes all four bandit-state files.
- **Leg 1:** operator completes the buy-side protocol (report: `e2e-verification-protocol.md`) with Shape A (HMAC-verified) — trained model loads with `[model] … ok (signature verified…)`.
- **Leg 2:** a default-cfg model load emits ZERO `INFERENCE_CFG` drift lines whose stamp carried the key (round-trip test against PRODUCTION emit, never the `:15582` fixture); the trained-without-feature catch still fires (that gate is intentional).
