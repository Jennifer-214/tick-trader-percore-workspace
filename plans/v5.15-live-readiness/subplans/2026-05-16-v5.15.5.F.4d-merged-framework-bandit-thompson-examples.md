## § F architectural decision: ezoo + core_cfg lookup at `real_on_exit_calibration`

**Problem:** `real_on_exit_calibration` body at `CoreFrameworks/OrderManager.hpp:661` has `oms`, `o`, `fill_price`, `net`, `total_fee` in scope. It needs to ALSO access `ezoo` (for telemetry like `last_predicted_thompson_arm` + per-arm `thompson_bandits[regime].mu_post[ARM]`) + `core_cfg` (for `thompson_exp3_blend_alpha`). Neither is currently in scope.

**Options considered:**

| Option | Description | Pros | Cons |
|---|---|---|---|
| A | `void* ezoo_ref` + `const void* core_cfg_ref` fields on `OrderManagerState<F>`; set at boot wiring site; cast in real_on_exit_calibration body | Sister to existing `void* ensemble_handle` pattern at `CoreContext` (EngineSharded.hpp:1061); O(1) inline access; ML-agnostic via void* (OmsState stays in CoreFrameworks/); per-core isolation natural | Adds 16B to OmsState (2 void*); cast at consumer site (compiler optimizes) |
| B | Extend Pattern 5 sink-fn signature to accept `ezoo` + `core_cfg` params: `void (*on_exit_calibration)(OrderManagerState<F>*, Order<F>*, FPN<F>, FPN<F>, FPN<F>, void* ezoo, const void* core_cfg)` | Most explicit; no state pollution | Wide blast radius (sink-fn callsite at OrderManager.hpp:1174 + boot wiring at :1467 + sister sinks `on_entry_fill_emit` + `on_exit_fill_emit` similar params for symmetry — even if they don't need them); changes sink-fn typedef in CoreFrameworks/ |
| C | Global state lookup via `engine.cores[oms->core_id]->ezoo` | No state pollution | Couples OmsState to engine-global state; not testable in isolation; harder to mock |

**CHOSEN: Option A.** Rationale:
- Sister to existing `void* ensemble_handle` precedent at CoreContext — same shape, same justification (ML type can't be visible in CoreFrameworks/ without circular include; void* + cast is canonical)
- Per-core isolation natural (each oms gets its own ezoo + core_cfg pointers; multi-core engine has 16 oms instances each pointing to its own pair)
- Minimal blast radius — only 2 new fields + 1 boot wiring site update + 1 cast at consumer
- Testable via mocks: test fixture can construct minimal MockOms + MockEzoo + MockCfg + wire pointers

### F.3 — Extended `real_on_exit_calibration` body (replaces existing body at OrderManager.hpp:661-682)

```cpp
template <unsigned F>
inline void real_on_exit_calibration(OrderManagerState<F>* oms, Order<F>* o,
                                      FPN<F> fill_price, FPN<F> net, FPN<F> total_fee) {
    const int pslot = (int)o->core_id;
    const FPN<F> entry_price_snap = oms->portfolio.positions[pslot].entry_price;
    const FPN<F> qty_snap         = oms->portfolio.positions[pslot].quantity;
    const uint64_t ts_us = (uint64_t)
        std::chrono::duration_cast<std::chrono::microseconds>(
            std::chrono::system_clock::now().time_since_epoch()).count();
    const double entry_d_calib = FPN_ToDouble(entry_price_snap);
    const double exit_d_calib  = FPN_ToDouble(fill_price);
    const double gain_pct      = entry_d_calib > 0.0
        ? (exit_d_calib - entry_d_calib) / entry_d_calib * 100.0 : 0.0;
    const double notional_d    = entry_d_calib > 0.0
        ? entry_d_calib * FPN_ToDouble(qty_snap) : 0.0;
    const double pnl_bps       = notional_d > 0.0
        ? FPN_ToDouble(net) / notional_d * 10000.0 : 0.0;
    const uint8_t pred_flag    = (uint8_t)BITMAP_IS_SET(oms->last_exit_predicted_bitmap, BITMAP_BIT_U16(pslot));
    const double pred_p        = oms->last_exit_predicted_p[pslot];
    (void)total_fee;

    // v5.15.5.F.4d Step 7 § F — decode bandit context from Order::flags_packed bits 17-25 (Pattern 4
    // decision-time-bound; sister to MASK_ORDER_PRE_RESOLVED at bit 16). Branchless shift + mask.
    const int bandit_active_state = MBS_OrderBanditActiveState(*o);
    const int bandit_regime       = MBS_OrderBanditRegime(*o);
    const int bandit_chosen_arm   = MBS_OrderBanditChosenArm(*o);

    // v5.15.5.F.4d Step 7 § F — per-slot bandit reward from FOREACH_OMS_PER_SLOT_FIELD sibling array
    // (added at Step 7 § N.2; written at HandleFill SELL).
    const double reward_bps_attributed = oms->bandit_reward_bps[pslot];

    // v5.15.5.F.4d Step 7 § F — cast ezoo_ref / core_cfg_ref to typed pointers for ML-side access.
    // Nullptr-defensive (test fixtures may construct oms without wiring pointers; cfg=BLENDED telemetry
    // simply emits 0 placeholder in that case).
    auto* ezoo     = static_cast<EnsembleModelZoo<F>*>(oms->ezoo_ref);
    auto* core_cfg = static_cast<const PerCoreCfg<F>*>(oms->core_cfg_ref);

    // Telemetry — null-coalesced to 0.0 / 0 for safety
    const int    thompson_telemetry_arm    = ezoo     ? ezoo->last_predicted_thompson_arm                           : 0;
    const double thompson_exp3_blend_alpha = core_cfg ? FPN_ToDouble(core_cfg->thompson_exp3_blend_alpha)            : 0.0;

    // Per-arm Thompson state (telemetry; null-coalesced via ezoo ? : 0.0). bandit_regime bounds-clamped
    // defensively to NUM_REGIMES range (cfg parser clamps but defensive belt-and-suspenders).
    const int regime_clamped = (bandit_regime >= 0 && bandit_regime < NUM_REGIMES) ? bandit_regime : 0;
    double exp3_probs[BANDIT_MAX_ARMS] = {0};
    if (ezoo) Bandit_GetProbabilities(&ezoo->bandits[regime_clamped], exp3_probs);

    CALIB_LOG_EMIT_ROW(oms->calibration_log_file);
}
```

### M.1 — Add FOREACH_BANDIT_ARM + FOREACH_PERARM_CALIB_COL helper macros

At `DataStream/CalibLogColRegistry.hpp` BEFORE the FOREACH_CALIB_LOG_COL definition:

```cpp
// v5.15.5.F.4d Step 8 § M — per-arm parameterization meta-macros for calib log per-arm cols.
// FOREACH_BANDIT_ARM enumerates 0..ENSEMBLE_HORIZON_MAX-1 explicit arm indices for matrix-reduce.
// Auto-extends when ENSEMBLE_HORIZON_MAX changes (currently 8; static_asserted).
#define FOREACH_BANDIT_ARM(X) X(0) X(1) X(2) X(3) X(4) X(5) X(6) X(7)
static_assert(ENSEMBLE_HORIZON_MAX == 8, "FOREACH_BANDIT_ARM assumes 8 arms; update when ENSEMBLE_HORIZON_MAX changes");

// FOREACH_PERARM_CALIB_COL enumerates per-arm column families. Each combines with each arm idx
// via matrix-reduce to produce 4 × 8 = 32 per-arm column rows in FOREACH_CALIB_LOG_COL.
// Template parameter ARM is substituted in expansion. Truncate-by-n_arms via ezoo nullptr-coalesce.
#define FOREACH_PERARM_CALIB_COL(X) \
    X(exp3_w,         "%.6f", exp3_probs[ARM]) \
    X(thompson_mu,    "%.6f", (ezoo ? ezoo->thompson_bandits[regime_clamped].mu_post[ARM]        : 0.0)) \
    X(thompson_prec,  "%.6f", (ezoo ? ezoo->thompson_bandits[regime_clamped].precision_post[ARM] : 0.0)) \
    X(thompson_pulls, "%u",   (ezoo ? (unsigned)ezoo->thompson_bandits[regime_clamped].total_pulls[ARM] : 0u))
```

### M.2 — Matrix-reduce expansion appended to FOREACH_CALIB_LOG_COL

```cpp
// In FOREACH_CALIB_LOG_COL macro body, APPEND after existing 9 legacy cols + 4 singleton cols.
// Matrix-reduce: for each arm in FOREACH_BANDIT_ARM, expand each family in FOREACH_PERARM_CALIB_COL.

#define _PERARM_COL_FOR_ARM(arm_idx) \
    X(exp3_w_arm##arm_idx,        "%.6f", exp3_probs[arm_idx]) \
    X(thompson_mu_arm##arm_idx,   "%.6f", (ezoo ? ezoo->thompson_bandits[regime_clamped].mu_post[arm_idx]        : 0.0)) \
    X(thompson_prec_arm##arm_idx, "%.6f", (ezoo ? ezoo->thompson_bandits[regime_clamped].precision_post[arm_idx] : 0.0)) \
    X(thompson_pulls_arm##arm_idx, "%u",  (ezoo ? (unsigned)ezoo->thompson_bandits[regime_clamped].total_pulls[arm_idx] : 0u))

// FOREACH_BANDIT_ARM expansion sites; need to disable the X macro temporarily during this
// (FOREACH_BANDIT_ARM passes its own X arg into _PERARM_COL_FOR_ARM):
FOREACH_BANDIT_ARM(_PERARM_COL_FOR_ARM)
#undef _PERARM_COL_FOR_ARM
```

**Hmm — there's a macro-expansion ordering concern here.** The X-macro pattern uses `X` as the consumer's parameter name; nesting `FOREACH_BANDIT_ARM(_PERARM_COL_FOR_ARM)` inside the parent `FOREACH_CALIB_LOG_COL(X)` macro body would re-expand X recursively, which doesn't work. **Alternative implementation: hand-write 32 rows.** Less elegant but mechanically correct + still 1-row-to-add if a 9th arm lands. Decision at coding time per "evaluate on design philosophy not LOC" — hand-write is simpler + auditable.

## Sidecar lessons (for future sidecar authors)

This is the first canonical of the sub-plan-sidecar-files rule (set 2026-05-16 in CLAUDE.local.md). Lessons:

1. **Architectural decisions get their own section with options table** — § F above shows the right shape: 3 options + pros/cons table + chosen + rationale. Future-coder doesn't re-derive.
2. **Code samples should compile in isolation** when possible (with sufficient context) so coder can paste-and-adapt rather than re-write from scratch.
3. **Macro-expansion gotchas warrant explicit callouts** — § M.2 documents the X-macro nesting concern + recommended fallback (hand-write vs auto-gen). Without this note, coder would discover the issue + waste time.
4. **Test fixture promotion** is its own concern; documenting the minimal-construction pattern (real OrderManagerState<F> + Order<F>) saves coder from over-engineering OR under-mocking.
5. **Cross-references back to main plan body sections** keep the relationship clear (§ F here references § F there; main body has WHY, sidecar has WHAT).
