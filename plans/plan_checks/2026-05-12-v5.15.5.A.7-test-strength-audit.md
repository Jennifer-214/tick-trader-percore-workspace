**What landed:** ML_BuildParameters mode-dispatch compute:
- Constant-iter inner loop over 8 arms (CLAUDE.md item 26 pattern)
- Gate per arm: `gate = (i < primary_count) ? 1.0 : 0.0 × BITMAP_IS_SET(arms_with_barriers_mask, ...)`
- Compute blend (Σ wᵢ · barrierᵢ) + dominant (argmax)
- Mode-dispatch via MODE_FLAGS[] lookup (BarrierBlendModeRegistry)

**Commit message:** "Dispatch compute MUST happen INSIDE weighted block scope."

**Finding:** controller_test.cpp has ZERO tests for:

1. LEGACY mode dispatches to cfg.ml_tp_pct (fallback path works)
2. BLEND mode computes weighted-sum blend barrier correctly
3. DOMINANT mode selects argmax arm barrier correctly
4. BOTH_BLEND_DRIVES mode returns blend + sets shadow counter
5. BOTH_DOMINANT_DRIVES mode returns dominant + sets shadow counter
6. Out-of-range mode defaults to LEGACY (bounds-check)
7. Arms without barriers (arms_with_barriers_mask bit unset) contribute zero to blend
8. Constant-iter loop is gate-safe (no branch misprediction leak per CLAUDE.md item 18)

**Risk:** Branchless dispatch code is correct (compiles, 3006 tests pass), but functional contract for each of 5 modes is undocumented. Future refactor could subtly break mode logic without test breakage.

**Severity:** YELLOW (dispatch exists and builds; per-mode functional test coverage = 0/5 modes).

**Recommendation for A.7:** Add dedicated test block (e.g., "v5.15.5.A.4: ML_BuildParameters mode-dispatch"):

- Mock cfg.barrier_blend_mode = each of 5 values

- Assert per-mode output (blend vs dominant vs legacy)

### C.3: Mode-Dispatch per-Mode Functional Contract (Anchor A.4 logic)

```cpp
{
    // === Test A.4.1: LEGACY mode fallback ===
    ControllerConfig<64> cfg = ControllerConfig_Default<64>();
    cfg.barrier_blend_mode = 0; // LEGACY
    cfg.ml_tp_pct = FPN_FromFloat(0.15f);
    
    EnsembleModelZoo<64> ezoo;
    EnsembleModelZoo_Init(&ezoo);
    
    // Mock primary 3 arms, barriers set on arms 0-2
    ezoo.primary_count = 3;
    BITMAP_SET(ezoo.arms_with_barriers_mask, BITMAP_BIT_U8(0));
    BITMAP_SET(ezoo.arms_with_barriers_mask, BITMAP_BIT_U8(1));
    BITMAP_SET(ezoo.arms_with_barriers_mask, BITMAP_BIT_U8(2));
    
    // Mode-dispatch compute (calls ML_BuildParameters internally)
    FPN result_tp = ML_BuildParameters_DispatchBarrier(&ezoo, cfg, /*use_dominant=*/0);
    check("v5.15.5.A.4: LEGACY mode returns cfg.ml_tp_pct unchanged",
          result_tp == cfg.ml_tp_pct);
    
    // === Test A.4.2: BLEND mode computes weighted sum ===
    cfg.barrier_blend_mode = 1; // BLEND
    ezoo.per_arm_barriers[0].tp = FPN_FromFloat(0.10f);
    ezoo.per_arm_barriers[1].tp = FPN_FromFloat(0.20f);
    ezoo.per_arm_barriers[2].tp = FPN_FromFloat(0.30f);
    
    // Inject known weights: [0.5, 0.3, 0.2] (normalized)
    // Expected blend = 0.5*0.10 + 0.3*0.20 + 0.2*0.30 = 0.05 + 0.06 + 0.06 = 0.17
    
    result_tp = ML_BuildParameters_DispatchBarrier(&ezoo, cfg, /*use_dominant=*/0);
    check("v5.15.5.A.4: BLEND mode computes weighted-sum barrier",
          fabs(FPN_ToDouble(result_tp) - 0.17) < 1e-3);
    
    // === Test A.4.3: DOMINANT mode selects argmax arm ===
    cfg.barrier_blend_mode = 2; // DOMINANT
    // Arm 2 has max weight (0.2) → should return per_arm_barriers[2].tp = 0.30
    
    result_tp = ML_BuildParameters_DispatchBarrier(&ezoo, cfg, /*use_dominant=*/1);
    check("v5.15.5.A.4: DOMINANT mode selects argmax arm barrier",
          fabs(FPN_ToDouble(result_tp) - 0.30) < 1e-3);
    
    // === Test A.4.4: Arms without barriers gated to zero ===
    BITMAP_CLR(ezoo.arms_with_barriers_mask, BITMAP_BIT_U8(1)); // Arm 1 no barrier
    cfg.barrier_blend_mode = 1; // BLEND
    
    // Expected blend (with arm 1 gated out) = 0.5*0.10 + 0.0*0.20 + 0.2*0.30 = 0.05 + 0 + 0.06 = 0.11
    
    result_tp = ML_BuildParameters_DispatchBarrier(&ezoo, cfg, /*use_dominant=*/0);
    check("v5.15.5.A.4: BLEND gates out arms without barriers",
          fabs(FPN_ToDouble(result_tp) - 0.11) < 1e-3);
}
```
