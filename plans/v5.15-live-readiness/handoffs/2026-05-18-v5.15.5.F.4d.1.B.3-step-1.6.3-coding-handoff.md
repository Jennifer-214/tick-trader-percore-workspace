## Coding-time discoveries from prior session(s)

Pulled verbatim from plan body v1.11 "Coding-time discoveries (Session D)" section. Session-real findings; assume they shape what you'll hit next.

### D-1: engine_version[16] truncation contract was undocumented (Caramel-caught)

- **Catalyst:** 2 pre-existing test failures (v5.8.6 + v5.8.8) Caramel suspected were ship-relevant. Investigation revealed `ModelStampResult::engine_version[16]` silently truncates current `ENGINE_VERSION_STRING "5.15.5.F.4d.1.B.2"` (18 chars) to "5.15.5.F.4d.1.B" — strcmp fails. Failures started at `.B.0` when sub-tag version era pushed past 15-char usable capacity.
- **Resolution:** documented [16] truncation as INTENTIONAL design (field used for cross-major version check + display; not bit-identity verification). Wire body retains full string (HMAC chain unaffected). Tests v5.8.6 + v5.8.8 updated to `strncmp(..., 15)` matching documented contract. NET test delta: 3235 PASS + 2 FAIL → 3237 PASS + 0 FAIL.
- **Lesson:** "pre-existing environmental" hand-wave can mask real ship-relevant bugs. Caramel's domain knowledge surfaced this; pure compaction-based handoffs would have missed.

### D-2: 5th FOREACH_GATE_CFG_FLAG consumer X-macro caught at build time

- **Catalyst:** Step 0.5d.a.0 5→6 col sig migration enumerated 4 consumer X-macros via initial grep. Build broke with error referencing 5th consumer (`_PARSE_OV_BITMAP_ROW_gate` at `ControllerConfig.hpp:2943`) which the initial grep missed (different naming convention).
- **Resolution:** added `_PARSE_OV_BITMAP_ROW_gate` to 6-arg sig (sister to `.B.2` `_PARSE_OV_BITMAP_ROW_ml` migration).
- **Lesson:** Meta-gap M1a (sister-registry parity verification) discipline codified this session would catch this PRE-CODING via comprehensive consumer enumeration. Validates the discipline.

### D-3: Step 1.5 INFERENCE_CFG_AUTOPOPULATE swap blocked by Step 1.6.3 struct-gen

- **Catalyst:** Step 1.5 attempted swap. Framework consumer writes UNPREFIXED `inf.<name>` fields; legacy walker writes PREFIXED `inf.inference_cfg_<name>` fields. PREFIXED fields exist on inf struct at HEAD (via FOREACH_STAMP_BOUND_MODEL_CONST POST_CFG) but unprefixed don't (until Approach A unconditional struct-gen lands at Step 1.6.3). Swapping without Step 1.6.3 first would silently drop 16 prefixed fields from wire format (HMAC chain regression).
- **Resolution:** reverted Step 1.5 attempted swap. v1.11 BUILD-FORCED list re-ordered: Step 1.5 moved AFTER Step 1.6.3 + Step 1.6.2. /readiness audit verified the dependency.
- **Lesson:** BUILD-FORCED sequencing in plan body has assumed independence in some places; coding-time validation catches these. v1.11 BUILD-FORCED is comprehensive per re-ordered phases A-K.

### D-4: Registry vs manual default value MISMATCHES at TECH_DEBT-093 closure

- **Catalyst:** Step 1.6.1 (TECH_DEBT-093 full closure) added `EMIT_GLOBAL_CFG_DEFAULT` auto-defaults mechanism. Audit against existing manual defaults revealed VALUE MISMATCHES (e.g., warmup_ticks registry default=0 but manual=128). Mass-deletion would silently change behavior.
- **Resolution:** deleted ONLY the gap_acceptable_threshold manual default (registry default 0.05 matches manual; safe). Other 47 manual defaults retained pending registry-vs-manual audit (TECH_DEBT-107 NEW at ship close).
- **Lesson:** "registry is source of truth" invariant requires defaults audit when registry was retrofitted into existing manual code. v1.11 captures TECH_DEBT-107 explicitly.

### D-5: Decision F scope drift from 9→15 keys (v1.5/v1.6 expansion not propagated)

- **Catalyst:** /parity-check M-4. Decision F (parser back-compat) was specified for 9 keys at v1.3 when Decision D scope was 9. Decision D expanded 9→10 at v1.5 and 10→15 at v1.6 but Decision F + Step 1.6.7.4 + Step 1.6.7.5 fixture wording stayed stale at 9.
- **Resolution:** v1.11 amendment aligns Decision F + Step 1.6.7.4 + Step 1.6.7.5 fixture to 15-key scope. No solution change — scope reconciliation only.
- **Lesson:** When iterative scope expansion happens, dependent solution specs need parallel updates. Future planning amendments should audit all decisions cross-referenced when ANY decision's scope changes.
