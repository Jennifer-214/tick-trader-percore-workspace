### The locked ③ design (the "config compiler")
- **One validation pass** collects EVERY problem in the cfg as a **compiler-style readout** (errors + warnings), and a **clean compile gates the run**. One-pass fixing, not stop-on-first.
- **ERRORS block the run** (unknown key · bad node index · unparseable value); **WARNINGS proceed but are listed** (clamped out-of-range value · deprecated-recognized key).
- **A clean compile (no errors) gates EVERY fresh start — live boot AND backtest** (operator-confirmed: a backtest on a silently-defaulted typo gives misleading numbers). Hot-reload + GUI = **WARN-keep-old** (can't fail-to-start a running engine). **NEVER `exit()` inside `ControllerConfig_Load`** (3 independent cascade confirms: kills a running engine on a hot-reload typo + crashes the GUI's `Settings_Load:887` call) — flag-based (`cfg_load_fault_flags` bitmap in `ControllerConfig`, cold boot-flags region next to `live_capital_cfg_conflict`).
- **Mechanism: KEY-MATCH-based fault** (a fault = "no parser branch matched this key," NOT "no field got written" — else clamped/defaulted values over-fire). Aligns with the sibling precedent `ConfigField_Set` (already returns 0 on an unknown key, `controller_test.cpp:18376`). Fixed-buffer readout (H1 no-heap; cap ~32 + "…and N more").
- **Output: terminal readout + a `config_error_log` file** — NOT a GUI banner (the GUI hard-deprecates at E.2; terminal+file is headless-aligned, persisted/recallable, surface-agnostic for the future CLI backtest).
- **Plus:** delete the 2 GUI brick rows (`SettingsPanel.hpp:456` `num_execution_nodes_PLACEHOLDER` + `:669` `confidence_freshness_tau`) · co-house the two ⊆ guards (parser-keys ⊆ registry · **GUI-recognized ⊆ engine-recognized**, read-side) in `check_per_node_registry_integrity.py` with `--selftest` teeth · the `fgets` line-buffer fix (size ~320 + clean overflow error — fixes a latent silent-truncation bug) · Cores→Nodes GUI terminology + "Node N" tabs · the migration-hint in the readout.
