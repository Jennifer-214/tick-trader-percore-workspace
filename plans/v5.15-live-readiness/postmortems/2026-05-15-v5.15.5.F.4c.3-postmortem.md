## Deferred items (logged TECH_DEBT; not introduced regressions)

1. **Compile-time SubmitCommand required-field enforcement (option A refined; awaits C++20 concepts).** C++17 friend-scope rules block the clean "private default ctor + friend" structural close pattern when `OrderManagerState<F> oms{};` value-inits the SPSC ring slot array (each slot is a SubmitCommand; value-init happens in caller's scope, not SPSCRing's scope, so friend declaration doesn't grant access). Sink-fn-pointer alternative would require SPSC rework — disproportionate risk. C++20 concepts (`requires` clauses on Submit fn templates) gives compile-time enforcement cleanly. Scheduled for post-`v5.15` umbrella C++20 upgrade ship.

2. **Full branchless OnEvent body via Portfolio + TradeLog mask-param refactor (alternative to Pattern 5).** Option B from r-2 discussion. Would convert Portfolio_OpenSlot / CloseSlot / TradeLog_RecordEntry / RecordExit to accept `bool apply` mask param + internal store gating. Pattern 5 sink-fn-pointer (chosen approach) is structurally equivalent at the boundary (callsite branchless) without the API-surface explosion. Mask-param refactor remains a TECH_DEBT option for cases where Pattern 5 doesn't fit (e.g., single-callsite + state changes mid-run).

3. **Reconcile ReconcileTrade exchange-fee-from-source corner case.** Closed at B.1 for live + recently-FILLED Orders via bitmap-search. Fully-released Orders (FILLED + slot reclaimed before Reconcile fires; rare, bounded by slot churn dynamics) fall back to `cfg.cores[0]`. Carrying actual exchange-reported fee in ReconcileTrade itself would close the corner; scheduled for next Reconcile-touching ship.

4. **C++20 upgrade ship.** Post-`v5.15` umbrella. Brings designated init, `[[likely]]/[[unlikely]]` attributes, `<bit>` library, concepts. Decoupled from architectural work for latency-regression triage clarity. Architectural framework codified at B.1 is mechanism-agnostic — C++20 features become cleaner implementation, not redesign.

## Lessons learned

### When tests fail, trace to architecture before fixing fixtures

The 4 failing tests at start of r-4 (2 baseline + 2 introduced by r-2) initially looked like fixture-migration noise. Root-cause trace led to the DrainPostFill-recompute-from-cfg gap — a real architectural issue. Fixing it via OMS::last_exit_fee[] sibling array closed both the visible tests AND closed a latent correctness bug (DrainPostFill would have used WRONG fee_rate if cfg changed between HandleFill SELL and DrainPostFill). Tests pass because behavior is now correct, not because assertions were weakened.

**Principle:** failing tests are diagnostic signals. Trace before fixing.

### Branchless wins on p99 even when nominally slower (Caramel's stated principle)

Throughout this ship: every conversion of `if/else` to mask-select or fn-pointer dispatch added ~3-10ns per fill on the drainer thread. Average-cycle cost went UP. But p99 went DOWN because mispredict variance was eliminated. For HFT determinism (H8 budget), p99 wins.

**Principle:** in a deterministic-execution system, predictable cost > optimistic average. Apply branchless to SP/HP data-dependent dispatch even when nominally slower.

### File ordering matters for template fn-pointer dispatch

Pattern 1 dispatch table (`g_fill_dispatch<F>[4]`) initially placed AFTER `OrderManager_HandleFill` caused redefinition errors via incomplete forward-decl semantics. Fix: place handlers + table BEFORE the consumer fn. Same applies to Pattern 5 fn-pointer fields requiring noop fn fwd decls before struct definition.

**Principle:** in template-heavy C++, lexical order matters for fn-pointer + struct field interactions. Plan file structure accordingly.

### Document deferred items with concrete scope, not vague intent

Each deferred item above has: WHAT (concrete scope), WHY (C++17 / time / dependency constraint), WHEN (which future ship picks it up). Vague "fix later" deferrals rot; specific scope-defined deferrals get picked up cleanly.
