## Cross-audit findings (synthesized)

Each finding shown once, with the audit lens (DOD / Merge / Dust) that surfaced it.

### TIER 1: Clear structural wins — must-do for .C

**S1. Rule 4 HOT/WARM/COLD tier reorganization with static_assert(offsetof) locks** (DOD HIGH-1 + HIGH-3 combined)
- Current `OrderManagerState` body has tier mixing scattered across `:152-418` (orders → adapter → result rings → Portfolio/balance/fee_rate → last_fill[] → partial_exit_enabled → flatten_pending → trade_log → event_log → total_* atomics → last_seen_trade_id). At least 5 distinct tier transitions interleaved.
- Target: explicit HOT cluster (line 0) → WARM cluster (alignas 64 anchor on `last_fill[0]` or first WARM-on-fill field) → COLD cluster (alignas 64 anchor on `adapter` or boot-set field). Plus separate CROSS-THREAD clusters for atomics.
- **Cost:** ~80-120 LOC reorder + 5-6 `static_assert(offsetof)` locks + 2-3 `alignas(64)` cluster anchors.
- **Win:** Drainer's cold-cache cycle path collapses from scattered ~1-page reads to clustered ~5-7 cache lines per cycle. Estimated ~30-100 ns/cycle savings cold-cache; less when L1-warm.
- **Risk:** MEDIUM-LOW. Reorder is bytewise-SAFE per LOW-1 finding below.
- **DESIGN_SPECS applied:** `cache-layout-discipline-for-hot-side-structs.md` Rule 4 + ND3 decision-first + Rule 7 per-cycle access budget.

**S2. Cross-thread atomic cluster isolation via 2× `alignas(64)` clusters** (DOD HIGH-2 — ND1 pattern)
- Identified cross-thread atomic groups that should be alignas-isolated:
  - **Observability counters** (`total_submitted/filled/rejected` at `:370-372` + `event_log.ring_full_spins/realloc_failed/log_full_drops` inside `event_log`): writer = drainer + async-writer-thread; reader = snapshot publisher at 60 Hz. Currently co-located with `event_log` ending + `last_seen_trade_id` (boot scalar) — false-sharing penalty per GUI publish.
  - **Safety CAS state** (`flatten_pending` + `recovery_until_us` at `:337-344`): writer = N slow-paths via CAS; reader = slow-path predicate. Currently between `kill_switch_tripped` (non-atomic) and `trade_log` (cold pointer). Slow-path CAS invalidates drainer's view of neighbor fields.
- Target: extract into `alignas(64) struct OmsObservabilityCounters { ... }` + `alignas(64) struct OmsSafetyCAS { ... }`.
- **Cost:** ~25-35 LOC.
- **Win:** Eliminates ~30-80 ns false-sharing penalty per GUI publish × 60 Hz + per slow-path CAS. Aggregate ~3-5 µs/sec wasted drainer-thread bandwidth.
- **DESIGN_SPEC applied:** `cross-thread-snapshot-publish-cluster-isolation.md` (ND1) — 3rd application; field-validates the pattern beyond .B.2's CoreContext + EventLoopState applications.

**S3. Boolean cohort bit-packing (4 flags + 2 per-slot bitmaps)** (DOD MEDIUM-1)
- Struct-level cohort: `live_trading` (line 165, int), `partial_exit_enabled` (line 314, uint8 + _pad_pe[7]), `kill_switch_tripped` (line 325, uint8 + _pad_ks[7]), `event_log_mode` (line 359, int). All hold 0/1; scattered with manual padding.
- Per-slot arrays: `last_exit_was_predicted[16]` (line 280, uint8[]) + `FillRecord.was_win` (per-slot byte).
- Target: single `uint8_t oms_state_flags` bitmap via `FOREACH_OMS_STATE_FLAG` registry (4 entries; 4 bits headroom) + uint16 `exit_predicted_bitmap` + uint16 `was_win_bitmap`.
- **Cost:** ~30-40 LOC (registry + accessors + ~12 site rewrites).
- **Win:** ~50-60 B saved + branchless multi-flag check via mask AND. Per-slot bitmap enables `while(mask) { __builtin_ctz }` iteration symmetric with existing `last_closed_mask` pattern — eliminates byte-array indexed reads in `ControllerEventLoop.hpp:1551, 1555, 1556`.
- **DESIGN_SPEC applied:** `bitmap-flag-api.md` Variant 6 (per-struct decision-state cohort; canonical from .B.3). 2nd application of Variant 6.

**S4. Canonical `oms.partial_exit_enabled` consolidation** (Merge HIGH-1 — Class 18 structural close)
- `oms.partial_exit_enabled` is set-once-at-init at `EngineSharded.hpp:886` ("Set once at init — toggle requires snapshot v3 reload"). But drainer-path code STILL re-derives via `BITMAP_IS_SET(cfg.lifecycle_cfg_flags, MASK_LIFECYCLE_CFG_PARTIAL_EXIT_ENABLED)` at 5 sites (`EngineSharded.hpp:1351, 2014, 2391, 2549, 3514`).
- Target: replace all drainer-path uses with `oms.partial_exit_enabled` (canonical source; documented at `OrderManager.hpp:308-313`).
- **Cost:** ~15 min mechanical rg+replace + verify.
- **Win:** Closes a drift hazard (Class 18 mirror — runtime mutation could create cfg vs oms inconsistency). ~3-5 cycles per use avoided (cfg cache miss → oms cache hit).
- **DESIGN_SPEC applied:** CLAUDE.md item 19 (structural-fix-preferred); aligns with existing canonical-mirror discipline.

**S5. Extract `OrderManager_AccountMakerTakerFee(oms, is_maker, fee)` helper** (Dust MEDIUM + Merge MEDIUM-1)

## NEW DESIGN_SPEC candidates (from audit)

**NC1. `raii-destructor-with-cluster-reorg-interaction.md`** (NEW; DOD audit)
- Pattern: how to reorganize a struct's field tiers when the struct has a RAII destructor that references fields by name (CLAUDE.md item 11 exception rule). The destructor accesses fields via member names, so reorder is safe as long as the destructor's referenced fields stay live.
- Trigger: first cluster reorg of an `OrderManagerState`-style struct in this codebase. Lightweight — 50-80 LOC doc.
- Cross-ref: `cache-layout-discipline-for-hot-side-structs.md` + CLAUDE.md item 11.

**NC2. `spsc-ring-embedded-in-hot-struct-cluster-discipline.md`** (NEW; DOD audit)
- Pattern: when N `SPSCRing<T, K>` structs are embedded fields, their alignas(64) head/tail provide per-ring isolation, but RING-INTERNAL alignas does NOT prevent the embedded ring's `head` from sharing a line with the PRECEDING field in the enclosing struct.
- Trigger: OMS has 3 + N submit_queues embedded SPSCRings; verify each ring's preceding field doesn't share its line.
- Cross-ref: ND1 + SPSCRing.hpp:78. Lightweight — 60-100 LOC doc.

## Proposed scope shape — 3 OPTIONS for operator decision

### OPTION A: Minimal .C (TIER 1 only) — ~250-350 LOC

S1 (tier reorg) + S2 (atomic clusters) + S3 (bitmap) + S4 (partial_on canonical) + S5 (fee helper) + S6 (trivial cleanup).

**Pros:** Captures all structural wins; bench gate verifies no slowdown; matches .B's "high-impact structural-only" shape; ~5-7h ship + 1h verification.
**Cons:** Leaves the small cleanup wins (T1 hoists + T2 comments) for later — accumulates technical debt fast.

### OPTION B: TIER 1 + TIER 2 — ~350-500 LOC ← RECOMMENDED

All of A + T1 (small hoists/caches) + T2 (phase-artifact comment cleanup).

**Pros:** Captures the cumulative drainer wins + dramatically improves reader clarity. Reduces TODO/stale-comment noise that would surface in the NEXT audit. Still bounded scope.
**Cons:** Slightly larger commit; comment cleanup churn affects diff readability.

### OPTION C: TIER 1 + TIER 2 + select TIER 3 — ~500-700 LOC

All of B + D3 (Order<F> internal reorg; cheap) + D6 (promote TODOs to TECH_DEBT ledger). Defer D1/D2/D4/D5 to follow-up ships.

**Pros:** Captures EVERYTHING that can ship safely without bench-gate risk.
**Cons:** Larger blast radius; the audit's MEDIUM/LOW items have fewer test-coverage anchors than the HIGH ones.

### My recommendation: OPTION B

S1-S6 must-do (structural foundation) + T1/T2 (cumulative small wins) = clean .C ship. Defer the bigger TECH_DEBT-012 conversion + function-size splits + FillRecord SoA→AoS to focused follow-up ships where each gets its own bench gate + audit cycle. Order<F> internal reorg (D3) can land in .D since it's a minor reorg of a related struct.

Sister consideration: .D (FlowFeatures) + .E (ConfidenceScorer) inherit the .C patterns. If we ship .C minimal (Option A), they're patternless when their turn comes. Option B field-validates the patterns enough that .D + .E become routine.
