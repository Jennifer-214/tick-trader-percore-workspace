## Architecture deep-dive

### Decision: FIX vs TWS proprietary

**FIX (Financial Information eXchange) protocol:**
- Industry standard for institutional trading
- Well-documented (publicly available spec)
- Multiple open-source libraries (QuickFIX C++)
- IBKR supports FIX 4.4 for institutional accounts
- Sequence-based + ordered + reliable

**TWS proprietary:**
- IBKR's own API (Trader Workstation)
- Stateful session protocol
- More widely supported (retail accounts; IB Gateway)
- Less standardized; IBKR-specific quirks

**Decision: FIX preferred if available; TWS fallback.**

Operator chooses via cfg: `auth_flavor = fix_session | tws_session`. Both supported in IBKRAdapter.

### IBKRAdapter implementation

```cpp
// DataStream/IBKRAdapter.hpp (NEW)

enum IBKRAuthFlavor {
    IBKR_AUTH_FIX_SESSION,
    IBKR_AUTH_TWS_SESSION,
};

template<typename F>
struct IBKRAdapter {
    IBKRAuthFlavor auth_flavor;

    // FIX or TWS connection state
    union {
        FIXSessionState fix;
        TWSSessionState tws;
    } session;

    // FA structure (optional)
    bool fa_structure_enabled;
    char fa_account_id[32];
    char fa_sub_accounts[MAX_FA_SUB_ACCOUNTS][32];

    // Metadata
    static constexpr bool supports_subaccounts = true;  // via FA
    static constexpr uint32_t rate_per_minute = 3000;   // 50/sec × 60; conservative
};

// tt:: specializations route based on auth_flavor
template<typename F>
int tt::submit_order<IBKRAdapter<F>>(IBKRAdapter<F>& adapter, const SubmitCommand<F>& cmd) {
    if (adapter.auth_flavor == IBKR_AUTH_FIX_SESSION) {
        return FIXSubmit(adapter, cmd);
    } else {
        return TWSSubmit(adapter, cmd);
    }
}
```

### FIX session management

```cpp
// CoreFrameworks/FIXSession.hpp (NEW)

struct FIXSessionState {
    char sender_comp_id[32];
    char target_comp_id[32];
    char endpoint[256];

    // Sequence numbers (CRITICAL)
    std::atomic<uint64_t> next_outgoing_seqnum;
    std::atomic<uint64_t> last_incoming_seqnum;

    // Connection state
    int socket_fd;
    SSL* ssl_state;
    std::atomic<uint8_t> session_state;     // LOGGED_OUT / LOGGING_ON / LOGGED_ON / DISCONNECTING

    // Heartbeat
    uint64_t heartbeat_interval_us;          // typically 30s
    std::atomic<uint64_t> last_received_us;
    std::atomic<uint64_t> last_sent_us;

    // Message store (for recovery)
    PersistentMsgStore msg_store;            // mmap'd; survives crashes
};

void FIXSession_Logon(FIXSessionState* sess) {
    // Send Logon message (35=A)
    FIXMessage msg;
    msg.SetMsgType("A");
    msg.SetField(98, "0");                  // EncryptMethod=None (TLS handles)
    msg.SetField(108, sess->heartbeat_interval_us / 1000000);  // HeartBtInt

    SendMessage(sess, msg);
    sess->session_state.store(LOGGING_ON, std::memory_order_release);
}

void FIXSession_HandleResendRequest(FIXSessionState* sess, FIXMessage& msg) {
    uint64_t begin_seqnum = msg.GetIntField(7);
    uint64_t end_seqnum = msg.GetIntField(16);

    // Resend from message store
    for (uint64_t seq = begin_seqnum; seq <= end_seqnum; ++seq) {
        FIXMessage stored = sess->msg_store.Retrieve(seq);
        ResendMessage(sess, stored);
    }
}

void FIXSession_HandleSequenceGap(FIXSessionState* sess, uint64_t expected, uint64_t received) {
    if (received > expected) {
        // Gap detected; send ResendRequest
        FIXMessage resend_req;
        resend_req.SetMsgType("2");
        resend_req.SetField(7, expected);     // BeginSeqNo
        resend_req.SetField(16, received - 1); // EndSeqNo (0 = "all remaining")
        SendMessage(sess, resend_req);
    } else if (received < expected) {
        // Possible duplicate; check PossDup flag
        if (msg.GetBoolField(43)) {  // PossDupFlag
            // Ignore duplicate
            return;
        } else {
            // Protocol error; disconnect + logon again
            FIXSession_Disconnect(sess);
            FIXSession_Logon(sess);
        }
    }
}
```

### FA structure support

```cpp
// IBKR Financial Advisor structure
// Master account "U12345" manages N client sub-accounts "U67890", "U54321", etc.
// Per-cluster cfg has list of sub-accounts; per-node binds to one

// configs/clusters/ibkr/cluster.cfg:
// fa_structure_enabled = 1
// fa_master_account = U12345
// fa_sub_accounts = U67890, U54321, U99999, U11111

// configs/clusters/ibkr/nodes/node_0/core.cfg:
// subaccount_id = 0  → resolves to U67890

void IBKRAdapter_RouteToSubAccount(IBKRAdapter<F>& adapter, uint32_t subaccount_id,
                                    FIXMessage& msg) {
    // Add Account field to FIX message
    if (adapter.fa_structure_enabled) {
        msg.SetField(1, adapter.fa_sub_accounts[subaccount_id]);  // Account
    }
}
```

## Honest risks

### R1 — FIX library dependency
QuickFIX is heavy; custom minimal library is engineering investment.

**Mitigation:** Start with QuickFIX (~1500 LOC integration); evaluate if minimal library justified post-`.E.7`.

### R2 — IBKR-specific protocol quirks
TWS proprietary protocol is less standardized; edge cases.

**Mitigation:** Prefer FIX if institutional account available; TWS fallback documented.

### R3 — Multi-asset class complexity
Symbol notation varies dramatically across asset classes.

**Mitigation:** Per-asset-class parser; operator-facing symbols documented per asset class.

### R4 — FA structure operational complexity
Optional; only used by FA operators; adds plumbing.

**Mitigation:** Cfg-driven; default disabled; well-documented when enabled.

### R5 — Sequence number management
Lost sequence = lost messages = financial loss. CRITICAL.

**Mitigation:** Persistent message store (mmap'd; crash-survives); resend on gap; thorough testing.
