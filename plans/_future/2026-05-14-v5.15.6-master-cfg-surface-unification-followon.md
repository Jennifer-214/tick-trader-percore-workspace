## Anti-patterns to avoid (cross-cutting)

- **Don't introduce a parallel descriptor** for any of the 3 cfg files. Use `lives_in_struct` discriminator (per CLAUDE.local.md "Going-forward rule: cross-file cfg surfaces use lives_in_struct" + Class 21 from `DOCS/RECURRING_BUG_PATTERNS.md`).
- **Don't merge struct definitions yet** (Phase 2 deferred to v5.16+ per TECH_DEBT-053). Keep ControllerConfig / BacktestCfg / ControllerCfg / SecretsCfg / TrainingCfg separate; route via discriminator.
- **Don't ship secrets handling without security audit.** v5.15.6.B's verification gate REQUIRES external/team review of the secret-handling discipline. Skipping = security risk.
- **Don't add KIND_RANGE_* unless training actually needs it.** Audit at v5.15.6.C Step 1; if training cfg has no hyperparameter sweeps, defer KIND_RANGE_* to a future ship when actual need arises.
- **Don't skip cfg.example auto-gen.** Operators need the example files; manual maintenance reintroduces cfg.example_doc_gap class.
