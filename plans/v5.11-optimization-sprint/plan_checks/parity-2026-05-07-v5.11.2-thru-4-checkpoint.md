## Section J — Observability Surface Coverage

**Summary:** v5.11.3.C added two new observability counters (ring_full_spins, writer_realloc_failed_count) not surfaced to GUI.

**Finding:** **MEDIUM GAP**
- **Counters defined:** OrderEventLog.hpp lines 161-162 (both atomic, GUI-readable).
- **Where written:** 
  - ring_full_spins (line 280): fetched in Append spin-loop when ring full.
  - writer_realloc_failed_count (line 306): fetched in AsyncWriterRoutine when OrderEventLog_ApplyEvent fails.
- **Where read:** Only in test assertions (controller_test.cpp:13921).
- **NOT surfaced in PerCoreSnap:** No fields added to EngineTUI.hpp::PerCoreSnap (checked lines 958-1098).
- **NOT surfaced in ML Status Panel:** MLStatusPanel.hpp does not read these counters.
- **NOT surfaced in GUI Health Log:** No log entries emit ring_full_spins or writer_realloc_failed state.

**Impact:** Silent failure mode — the writer thread can hit sustained ring-full condition (producer outpacing writer disk I/O) or realloc OOM (entries[] can't grow to absorb event burst) and the operator has **zero visibility**. Disk health degrades → tail variance spikes, but operator only sees latency numbers without knowing the async log writer is bottleneck.

**Recommended fix (MEDIUM effort, 30-45 min):**
1. Add two new fields to PerCoreSnap (EngineTUI.hpp):
   - `uint64_t async_log_ring_full_events` — count of Append calls that spun waiting for ring space
   - `uint32_t async_log_writer_realloc_failures` — count of OOM during async drain
2. In TUI_CopySnapshotSharded, copy these from oms->event_log for the "representative" core (global OMS state, surface on first core with is_ml=1).
3. In MLStatusPanel or Health Log, emit WARN if either counter > 0.
4. CLI tool: expose `--show-async-log-stats` to print counters at boot.

**Severity:** MEDIUM — observability gap, not silent prediction drift. Operator workflow friction if writer thread becomes bottleneck; would require slow log disk to trigger, which is rare in production but possible.

**Cross-ref:** v5.9 parity audit identified similar "failure mode without observability" as MEDIUM (PerCoreSnap field-init discipline). Pattern applies here — new async infrastructure needs distinct observability surface.

**Verdict:** GAP (Section J) — ring_full_spins + writer_realloc_failed NOT exposed to operator.
