## 2. Typing lock (D-380 + D-382)

1. **Single-doc plain JSON.** Machine bus; byte-deterministic; zero new dep.
2. **Uniform record-set TABLE** `{schema, rows}` — schema = the fixed field-layout (X-macro-registry shape); name-as-column; sorted.
3. **Schema-as-DATA registry** — one language-neutral JSON file both C++ + Python read (via foxtag's EXISTING `json_parse`, `foxtag_layout.hpp:71`); never a per-language hardcode.
4. **Comments-only-never-code** — `codegen` live-only; tooling never writes engine logic.
5. **CRUX (D-382): `foxtag grammar --json` emits a COMPLETE self-describing envelope**, frame data-driven off the registry + one envelope definition. **SSoT = the `Version.hpp` model:** foxtag (C++) and `toolio.py` (Python) are two READERS of one source (registry + envelope-def), not two truths. Only each language's ~10-line read-and-fill routine exists per-side — irreducible (each language must be able to emit), parity-gated.

## 3. Concrete shapes (the build)

### 3a. The envelope — `foxtag grammar --json` (the 1st canonical), O3 payload
```json
{ "envelope_version":"1.0", "kind":"grammar", "schema_version":"v1.0",
  "payload_schema_version":"grammar/1",
  "producer":{"tool":"foxtag","version":"<TOOLCHAIN_VERSION>","command":"grammar","args":["--json"]},
  "status":{"ok":true,"code":0,"findings":[]},
  "target":{"paths":[],"git_head":"<.git/HEAD read>"},
  "payload":{
    "categories":  {"schema":["name"], "rows":[["CAPITAL_BEARING"],["HOT_PATH"]]},
    "ref_subcats": {"schema":["name"], "rows":[["DECISION"],["POSTMORTEM"]]},
    "concern":     {"schema":["name"], "rows":[["DETERMINISM"],["LATENCY"]]},
    "surface":     {"schema":["name"], "rows":[["HOT_PATH"],["SLOW_PATH"]]},
    "unit_types":  {"schema":["name","closable"], "rows":[["FUNCTION",true],["STRUCT",true],["FILE",false],["ASSERT",false]]},
    "openers":     {"schema":["name"], "rows":[["FUNCTION"],["STRUCT"]]}
  } }
```
- **O3** = the 4 fence/vocab sets (CI/AI value; all real `Grammar` members `foxtag.hpp:220-226`, already parity-counted) **+ the node-model set** `unit_types`+`openers` (from the free fns `foxtag.hpp:230,234`; already parity-consistent with Python — both 10-incl-`ASSERT`). This is the set the plugin actually hardcodes → emitting it kills the mirror.
- `unit_types` carries a **`closable`** column (I-3/F7): the plugin's END-closer scan needs closable-vs-light, else it keeps hardcoding it. `openers` (the 7 closable) is emitted too for directness.
- **`status.findings`** is the universal findings channel; empty for a pure producer. A `verdict` is `kind:"verdict"` + populated `status.findings` + empty payload (spec §1) — NOT a payload table.

### 3b. The registry — `tools/lib/toolio_schemas.json` (language-neutral SSoT)
```json
{ "grammar/1": {"tables": {"categories":["name"],"ref_subcats":["name"],"concern":["name"],
                           "surface":["name"],"unit_types":["name","closable"],"openers":["name"]}},
  "verdict/1": {"table": ["file","line","severity","message","kind"]} }   // the status.findings ENTRY schema (the gates' TARGET; no producer @ 0.1.5)
```
Add/evolve a kind = a row. Read by C++ (`json_parse`) AND Python (`json.loads`). `derived_axes`/`ladder` deferred (no producer).

### 3c. One envelope definition + emit/read (the "two readers, one source")
```python
# tools/lib/toolio.py — Python emitter/reader; the C++ twin in foxtag.hpp reads the SAME registry+def
def emit(kind, payload, *, producer, git_head, findings=()):
    schema = load_registry()[schema_ver(kind)]      # reads toolio_schemas.json (the SSoT)
    validate(payload, schema)                        # rows conform to declared columns → else FAIL LOUD
    return wrap(kind, payload, producer, git_head, findings)   # fills the ONE envelope frame
def read(env): return env["payload"]                 # ONE reader walks {schema, rows} for ANY kind
```
C++ side: **promote `json_parse`/`JVal` from `foxtag_layout.hpp` UP into `foxtag.hpp`** (behavior-identical move; I-1/Q2-2) so the core grammar path + the leaf both reach one reader — no include cycle, no reader-mirror.

### 3d. `cmd_grammar` (C++) — counts → O3-SETS-in-envelope
- Today (`foxtag_main.cpp:127-131`): prints 4 `.size()` counts. New: `--json` builds the 6 O3 tables and emits the envelope via the C++ emit routine (reads the registry).
- **Fixes:** call `unit_types()`/`openers()` (the free fns) — NOT `g.unit_types` (**does not compile**; not a `Grammar` member). Thread `--json` into `cmd_grammar` (sig `+ bool json`; dispatch `:255`) — a 2-line change (today the flag is parsed `:216` but not passed). `git_head` = a ~15-line `.git/HEAD` filesystem read (foxtag has `<filesystem>`; NO `git` subprocess in the core). Bare `grammar` (no flag) stays byte-identical (parity `:69` green).

### 3e. `foxtag_client.grammar()`
```python
def grammar():                                       # extends the existing client (subprocess+JSON, D-352)
    out,_ = _run(["grammar","--json"]); return json.loads(out) if out.strip() else {}
```

### 3f. `.toolbus/` — DEFERRED out of 0.1.5 (substrate ≠ cache)
**No `.toolbus/` in 0.1.5.** Grammar is cheap + session-stable → a file-cache is premature infra. The plugin reads grammar via **subprocess-at-attach** (`foxtag grammar --json`, its chosen transport `plan:74`; atomic-by-construction; dodges the gitignore-leak / cross-repo-path / torn-read / Landmine-5 traps). `.toolbus/` (D-377 STANDS) lands at **`0.4`/`0.5`** with its first genuine consumer — the VOLATILE `layout--<target>.json` (re-running clang hurts) — and lands WITH: atomic **temp-then-rename** writes + a **workspace-repo** `tools/.gitignore` entry (the file physically lands in the workspace repo through the `tools/` symlink — the engine `/tools` ignore does NOT cover it).
