## Decisions (operator-decided)

<!-- D/C/F: D-1 -->
**D-1: Architecture choice — Architecture E++.** Per-core sub-accounts + multi-exchange substrate + headless service + io_uring + WS-API + DPDK (end-game). Phased delivery option D (~6-9 weeks; 8 sub-ships). Pursuing perfect-architecture path; time-irrelevant; ego-flex motivation accepted.
<!-- STATUS: landed -->

<!-- D/C/F: D-2 -->
**D-2: Account topology — real sub-accounts preferred (canonical mode).** Virtual partition becomes fallback for exchanges without sub-account support (Alpaca, IBKR retail). Sub-account isolation is structurally stronger (Binance-enforced); per-core failure domain at economic layer.
<!-- STATUS: landed -->

<!-- D/C/F: D-3 -->
**D-3: Multi-exchange — yes, FOREACH_EXCHANGE registry from day one.** Framework substrate lands at `.E.1` even though only Binance wired. Future exchanges (Alpaca, IBKR, future) become 1-row-in-registry additions. Per-core bound to one exchange (Mode 1 from earlier exploration); cleanest model.
<!-- STATUS: landed -->

<!-- D/C/F: D-4 -->
**D-4: Headless service architecture — folded into `.E.2` (not deferred to `.E.7`).** Engine binary stripped of GUI; runs as systemd service 24/7. State published via mmap'd shared memory; commands via Unix domain socket. Multiple concurrent read-only viewers OK. Crash recovery via mmap'd state file. SSH-tunneled UDS for remote attach (no HTTPS; SSH baked-in security wins).
<!-- STATUS: landed -->

<!-- D/C/F: D-5 -->
**D-5: Per-core config files — separate folders per core (no template inheritance).** Each core gets `configs/cores/core_<id>/{core.cfg, strategy.cfg, ml.cfg, observability.cfg, notes.md}`. Self-contained; copy-paste-friendly; independent versioning. Replaces monolithic engine.cfg for per-core surfaces. X-macro FOREACH_PER_CORE_CFG_FIELD registry still drives parser schema; just file I/O layer changes.
<!-- STATUS: landed -->

<!-- D/C/F: D-6 -->
**D-6: ML training goes headless — `foxml-train` CLI tool.** Replaces foxml_suite GUI for production training. Config-file-driven (full training pipeline reproducible from one cfg). foxml_suite either deprecated or demoted to "exploration playground." Jupyter notebooks for interactive ML exploration; CLI for production.
<!-- STATUS: landed -->

<!-- D/C/F: D-7 -->
**D-7: GUI focus reduced — viewer becomes pure read-only + command sender.** Engine doesn't depend on GUI being running. fox-tui (native ncurses-style; reads mmap directly) becomes primary monitoring interface. fox-cli for control commands. Existing Dear ImGui GUI can stay as one of multiple viewers but no longer privileged.
<!-- STATUS: landed -->

<!-- D/C/F: D-8 -->
**D-8: Hot-reload — both layers (config + strategy code).** Layer 1 (config reload via SIGUSR1; slow→hot seqlock update of parameters) lands `.E.2`. Layer 2 (.so reload via dlopen; per-core slow-path swaps function pointer atomically) lands `.E.X` (power-user feature; later ship). Both compatible with H7 (hot path branchless via cached pointer) + H3 (atomic-only; no mutex).
<!-- STATUS: landed -->

<!-- D/C/F: D-9 -->
**D-9: Public repo stays public (FoxML_Trader_v2 = AGPL).** Architecture isn't competitive secret; execution + tuning is. Hedge-fund visibility per `user_public_work_attracts_hedge_funds` retained. Gitignore tightened for new operator-specific surfaces (per-core configs in `configs/cores/`; secrets; runtime state). Private deployment repo (separate; future) if needed for operator-specific custom strategies.
<!-- STATUS: landed -->

<!-- D/C/F: D-10 -->
**D-10: SSH preferred over HTTPS for operator control channel.** Public-key auth + encrypted transport + no certificate management. Local UDS direct; remote SSH-tunneled UDS. HTTPS dropped from scope. Prometheus `/metrics` HTTP endpoint exists for Grafana scrape but no auth (firewall + SSH-tunneled scraper).
<!-- STATUS: landed -->

<!-- D/C/F: D-11 -->
**D-11: Monitoring — Grafana (remote/historical) + custom TUI (local/real-time) — both, complementary.** Engine emits metrics in mmap (TUI reads zero-copy) + Prometheus exposition format (Grafana scrapes via HTTP endpoint). Operator runs Prometheus + Grafana separately as standard infrastructure. No vendor lock-in.
<!-- STATUS: landed -->

## Findings / Discoveries

<!-- D/C/F: F-1 -->
**F-1: BinanceAdapter worker thread already exists as canonical sister.** Investigation revealed the existing CoreFrameworks/BinanceAdapter.hpp pattern (~`worker_count` workers; HMAC signing; REST submit) IS exactly the "API client thread" Architecture A would build. Architecture D extends this rather than parallels — adapter is the canonical sister for the future multi-exchange substrate.
<!-- STATUS: noted (informs `.E.1` plan body — extend BinanceAdapter pattern, don't build new) -->

<!-- D/C/F: F-2 -->
**F-2: Known existing KS race resolved as side-effect of Architecture E.** Producer thread reads `oms.balance` while drainer writes it (audit 2026-04-09 Async.hpp:432-442 known race). Coordinator-as-single-writer pattern + seqlock-published account state under E closes this race structurally. Free bonus from the architecture work.
<!-- STATUS: noted (capture in `.E.1` plan body Bug Classes section; closes pre-existing race in addition to Class 26 + Class 27) -->

<!-- D/C/F: F-3 -->
**F-3: Architecture E's latency analysis — removes drainer middleman; net latency IMPROVES vs current.** Current submit path has ~10-100μs p99 latency variance from drainer cycle + adapter polling. E removes drainer hop entirely; per-core direct-call into adapter. Saves ~drainer-cycle worth of variance. NOT a regression vs current; improvement.
<!-- STATUS: noted (`.E.1` plan body Verification gate item: latency baseline measurement; verify no regression at .E.1; expect improvement at .E.2 WS-API ship; expect substantial improvement at .E.3 io_uring) -->

<!-- D/C/F: F-4 -->
**F-4: Theoretical on-box latency floor on commodity x86_64 ~3-5μs tick-to-wire** with DPDK + kTLS + SHA-NI + isolcpus + hugepages + C-state-disabled. Below that requires custom hardware (FPGA / smart NIC). End-game `.E.8` ships the DPDK piece.
<!-- STATUS: noted (informs `.E.8` plan body scope at draft time) -->

<!-- D/C/F: F-5 -->
**F-5: Network dominates latency by 3 orders of magnitude.** Architecture changes save microseconds; colocation saves milliseconds. Architecture work is for VARIANCE reduction (p99 stability) + structural correctness; colocation is for raw mean latency. Both matter; different axes.
<!-- STATUS: noted (informs `.E` postmortems framing — sell architecture as variance + structural; sell colocation as mean reduction) -->

<!-- D/C/F: F-6 -->
**F-6: Binance WebSocket API for order submission is biggest single-step latency win.** Persistent `/ws-api/v3` connection eliminates TCP+TLS handshake per submit; saves ~15-25ms per submit vs REST-per-request. Lands at `.E.3`. Biggest concrete improvement of the sub-sprint.
<!-- STATUS: noted (`.E.3` is highest-ROI ship by single-step latency improvement) -->
