### 2. Critical gap: exit_predictor buy_class_idx configuration

**GAP IDENTIFIED** — /readiness Check 19 audit step

The plans cite `CoreModelZoo_TryLoadRole` with role="exit" (line 1233). The existing code LOADS the exit models but **does NOT configure `buy_class_idx` on the exit_predictor handles after loading**.

**Current behavior (lines 1255-1294):**
- `EnsembleModelZoo_LoadFromCfg` sets `buy_class_idx` for:
  - `buy_signal`: all handles set to `buy_class_idx=0`
  - `barrier`: set to `1` if `num_outputs >= 2` (PEAK_VALLEY_STABLE 3-class aliasing)
  - `regime`: set to `0`
  - `primary_*` handles: pointer + class mirroring
- **exit_predictor: NO buy_class_idx configuration after load**

**Why this matters:**
- If exit models are 3-class (PEAK_VALLEY_STABLE reused per Path 3), we need `buy_class_idx=1` to extract the peak probability (same as barrier)
- v5.13.0 uses `Model_Predict_Normalized` which relies on the handle's normalizer + buy_class_idx
- Missing config → exit models default to `buy_class_idx=0` → predicts VALLEY prob instead of PEAK prob → exit timing inverted

**Master plan rationale (p.27-29):** "Path 3 (path-based role discrimination): No new FOREACH_TARGET row (LABEL_REGISTRY_HASH stays unchanged). Operator trains sell-side models with EXISTING Multi-Horizon trainer, output to `models/exit_signal/*.json`. Loader already wired (CoreModelZoo.hpp:1233 populates `ezoo->exit_predictor[]` from `models/exit/*.json` paths)."

The "already wired" claim is INCOMPLETE — wired for LOADING but NOT for class-index aliasing.

**Resolution:**
v5.13.0.A must include a Step 0.5:
```
Step 0.5 — exit_predictor buy_class_idx configuration

After EnsembleModelZoo_LoadFromCfg populates exit_predictor[], add
explicit buy_class_idx setup for each loaded handle:

    for (int i = 0; i < ezoo->exit_predictor_count; ++i) {
        // Exit models reuse PEAK_VALLEY_STABLE 3-class labels
        // (same as barrier). Extract peak probability.
        ezoo->exit_predictor[i].buy_class_idx =
            (ezoo->exit_predictor[i].num_outputs >= 2) ? 1 : 0;
    }

This mirrors the existing barrier aliasing (CoreModelZoo.hpp:1280-1281)
and ensures Model_Predict_Normalized correctly extracts the exit
probability on 3-class models.

Add audit check: grep CoreModelZoo.hpp for the ABOVE pattern on
exit_predictor array BEFORE Step 1 cfg work starts. Patch if missing.
```

**Verdict impact:** Raises v5.13.0 to YELLOW (GAP must fix). v5.13.4 inherits YELLOW since it depends on v5.13.0 field correctness.
