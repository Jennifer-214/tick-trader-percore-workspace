## Why this subplan exists

Three concerns share the same hot-swap + cfg-default surface:

1. **Strict defaults when `trading_mode=LIVE`.** Operator setting
   `trading_mode=live` should auto-tighten safety: `model_verify_strict`
   0→1 (STRICT); `reconcile_mode` WARN→STRICT. Explicit operator overrides
   STAY honored — only unset defaults flip.

2. **TECH_DEBT-005 hot-swap strict-mode unification — via shadow-load.**
   The audit (PARITY-023 HIGH) caught a fatal flaw in the original
   capture-pointer-and-revert design: `EnsembleModelZoo_Free` destroys
   data IN-PLACE, so captured pointers point at freed memory after the
   swap. The proper fix is the **shadow-load pattern** (new
   DESIGN_SPECS doc): allocate NEW state into separate memory + load +
   validate, atomically swap pointer ONLY after validate succeeds,
   then Free the old state. Pre-swap state is untouched on validate
   failure — rollback is impossible because there was never a moment
   when the active pointer was invalid.

3. **`alignas(64)` retrofit on EnsembleModelZoo + CoreModelZoo.** Audit
   surfaced these structs lack explicit alignment despite containing
   `RidgeWeights<F>` (AVX-512 vectorized per CLAUDE.md item 25) and
   `ModelHandle<F>` (gains `alignas(64)` in v5.15.0). Heap allocation
   via `malloc` gives only 16-byte alignment; embedded cache-aware
   members lose their alignment guarantee. Shadow-load uses
   `aligned_alloc(64, sizeof(T))` to fix this for new allocations;
   struct itself must declare `alignas(64)` so the request is
   actually satisfied.

## .C — Shadow-load refactor of `EnsembleHotSwap.hpp`

### Step 0: read current EnsembleHotSwap structure

```bash

```

Current shape (per audit findings):

- This is the broken in-place pattern shadow-load replaces

### Step 1: introduce `HotSwap_ShadowLoad_Ensemble`

In NEW `CoreFrameworks/HotSwap.hpp` (consumes the shadow-load pattern;
canonical first reference per DESIGN_SPECS/feature-patterns/shadow-load-state-transition-pattern.md):

```cpp
#ifndef HOT_SWAP_HPP
#define HOT_SWAP_HPP
#include <stdlib.h>     // aligned_alloc, free
#include "../ML_Headers/NodeModelZoo.hpp"
#include "../ML_Headers/EnsembleHotSwap.hpp"

// v5.15.4 — shadow-load hot-swap for EnsembleModelZoo.
// Pattern: shadow-load-state-transition-pattern.md (DESIGN_SPECS).
//
// Reclamation strategy A (single-owner): per-core slow-path thread is
// the SOLE owner of state.cores[c].ensemble_handle (hot-path uses
// cached cycle parameters via seqlock; never reads ensemble_handle).
// So Free of old ezoo is safe immediately after atomic swap.
//
// Returns: 0 = success (new ezoo active); -1 = OOM; -2 = load failed;
// -3 = strict validate failed.
//
// On any nonzero return, state.cores[c].ensemble_handle is UNCHANGED
// from pre-call value; caller can continue using pre-swap ezoo.
template <unsigned F>
int HotSwap_ShadowLoad_Ensemble(
    EngineShardedState<F>& state,
    int core_idx,
    const ControllerConfig<F>& cfg,
    const char* new_path,
    int backend) {

    // 1. Allocate NEW ezoo (pre-swap state UNTOUCHED).
    // aligned_alloc(64) per v5.15.4.B EnsembleModelZoo alignas(64) requirement.
    EnsembleModelZoo<F>* new_ezoo =
        (EnsembleModelZoo<F>*)aligned_alloc(64, sizeof(EnsembleModelZoo<F>));
    if (!new_ezoo) return -1;
    EnsembleModelZoo_Init(new_ezoo);

    // 2. Load into new_ezoo (pre-swap UNTOUCHED).
    int load_rc = EnsembleModelZoo_LoadFromDir(
        new_ezoo, cfg, core_idx, new_path, backend);
    if (load_rc != 0) {
        // Load failed — Free new; pre-swap untouched
        EnsembleModelZoo_Free(new_ezoo);
        free(new_ezoo);
        return -2;
    }

    // 3. Strict validate (any boot-time invariants).
    if (cfg.model_verify_strict) {
        int n = new_ezoo->barrier_count + new_ezoo->buy_signal_count
              + new_ezoo->regime_count;
        for (int i = 0; i < n; ++i) {
            ModelHandle<F>* h = /* iterate handles */ nullptr;  // resolved at impl
            if (h && !h->backend /* invalid handle */) {
                EnsembleModelZoo_Free(new_ezoo);
                free(new_ezoo);
                return -3;
            }
        }
    }

    // 4. EnsembleModelZoo_PostLoadSetup (re-run boot init that LoadFromDir doesn't do)
    EnsembleModelZoo_PostLoadSetup(new_ezoo, cfg, core_idx,
                                   /* num_outputs */, /* exit_num_outputs */);

    // 5. ATOMIC swap pointer.
    EnsembleModelZoo<F>* old_ezoo = (EnsembleModelZoo<F>*)__atomic_exchange_n(
        &state.cores[core_idx].ensemble_handle,
        (void*)new_ezoo,
        __ATOMIC_ACQ_REL);

    // 6. Free old (now detached; no reader can acquire it via container).
    //    Single-owner reclamation strategy: writer = reader = same per-core thread.
    if (old_ezoo) {
        EnsembleModelZoo_Free(old_ezoo);
        free(old_ezoo);
    }
    return 0;
}

template <unsigned F>
int HotSwap_ShadowLoad_SingleZoo(
    EngineShardedState<F>& state,
    int core_idx,
    const ControllerConfig<F>& cfg,
    const char* new_path,
    int backend) {
    /* parallel structure for CoreModelZoo */
    CoreModelZoo<F>* new_zoo =
        (CoreModelZoo<F>*)aligned_alloc(64, sizeof(CoreModelZoo<F>));
    if (!new_zoo) return -1;
    CoreModelZoo_Init(new_zoo);

    /* load + validate via existing CoreModelZoo_TryLoadRole flow */
    int load_rc = /* equivalent to existing inline logic at EngineSharded.hpp:2923-2924 */;
    if (load_rc != 0) {
        CoreModelZoo_Free(new_zoo);
        free(new_zoo);
        return -2;
    }

    CoreModelZoo<F>* old_zoo = (CoreModelZoo<F>*)__atomic_exchange_n(
        &state.cores[core_idx].model_handle,
        (void*)new_zoo,
        __ATOMIC_ACQ_REL);
    if (old_zoo) {
        CoreModelZoo_Free(old_zoo);
        free(old_zoo);
    }
    return 0;
}

#endif  // HOT_SWAP_HPP
```

## Data-Oriented Design pass (replaced; broken HotSwapSnapshot design abandoned)

| DOD concern | Implementation |
|---|---|
| **alignas(64) container structs** | EnsembleModelZoo + CoreModelZoo gain `alignas(64)` + sizeof%64==0 static_asserts; member ModelHandle (v5.15.0 alignas(64)) + RidgeWeights (AVX-512 vectorized per item 25) get correctly-aligned addresses inside |
| **aligned_alloc(64) for heap allocations** | Shadow-load uses `aligned_alloc(64, sizeof(T))` not `malloc(sizeof(T))`. Standard C11 API; `free()` compatible per spec. |
| **Padding determinism** | Trailing `uint8_t _trailing_pad[N] = {0}` to make sizeof%64==0; explicit init prevents UB per CLAUDE.md item 27 |
| **Atomic exchange pointer** | `__atomic_exchange_n(ptr, new, __ATOMIC_ACQ_REL)` — single instruction on x86_64 for aligned 8-byte pointers; lock-free; readers see old OR new, never torn |
| **No struct invented for snapshot** | Shadow-load uses local variables (`new_ezoo`, `old_ezoo` pointers); no `HotSwapSnapshot` struct needed — fix the v5.15.4 plan-draft's failed design |
| **Reclamation strategy** | Strategy A (single-owner): per-core slow-path thread is sole owner of state.cores[c].ensemble_handle; Free immediately after atomic exchange is safe |
| **ControllerConfigKeyExplicit bitmap** | uint16_t bitmap with MASK_CFG_KEY_* constants; same pattern as CLAUDE.md item 20 (FOREACH_*_CFG_FLAG bitmaps); placement near reconcile_mode sibling cluster at ControllerConfig.hpp:865 area; 2 bytes; reuses existing alignment slot |
| **Latency impact (CLAUDE.md item 17)** | Hot-swap is RARE-EVENT operator-triggered; not on per-tick path. Shadow-load cost: 1 aligned_alloc(64) + 1 sizeof(EnsembleModelZoo)≈40KB write-zero (Init) + load_from_dir (filesystem I/O dominates) + 1 atomic_exchange (~1ns) + 1 Free. Total ~ms per swap; rare event. NO HOT_PATH_CHANGELOG entry. |
| **Branchless discipline (CLAUDE.md item 18)** | shadow-load is happy-path branch-rare; normalize uses bitmap AND-mask (BITMAP_IS_SET); no scattered cfg-flag checks |
| **Cohort audit** | trading_mode + reconcile_mode + model_verify_strict cohort verdict CORRECT (all uint8 enum, NOT BIT_FLAG-eligible); ControllerConfigKeyExplicit is a new bitmap cohort (~3-10 expected future tracked keys); migrate from start per CLAUDE.local.md going-forward rule 2026-05-11 |

## DoubleBufferedAtomic<T> template — explicit defer

Original v5.15.4 draft proposed template-extracting BinanceDepth's
double-buffer pattern. **Audit re-analysis 2026-05-12:** HotSwap's
threading model is single-owner (writer = reader = same per-core
slow-path thread; hot-path doesn't read ensemble_handle directly). So
`__atomic_exchange_n` on pointer suffices; double-buffer overhead is
unnecessary.

**Defer to v5.16+ via TECH_DEBT-035** (engine→viewer mmap'd snapshot
exposure) where genuine cross-thread sharing exists. BinanceDepth's
existing pattern stays as canonical reference for the future template
extraction.
