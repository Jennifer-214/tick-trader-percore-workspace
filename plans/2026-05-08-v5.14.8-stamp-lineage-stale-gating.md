## Implementation plan

### Step 1 — Stale-model age check (.A)

File: `ML_Headers/CoreModelZoo.hpp` (LoadFromCfg or _TryLoadRole)

```cpp
// v5.14.8.A — stale-model gate. Reads stamp's training_timestamp,
// computes age in hours, applies cfg policy.
inline int CoreModelZoo_CheckStaleModel(
    const ModelHandle<F>* m,
    uint64_t now_us,
    uint64_t max_age_hours,
    int strict_mode) {
    if (max_age_hours == 0) return 0;  // disabled
    if (m->stamp.training_timestamp_us == 0) return 0;  // legacy stamp
    uint64_t age_us = now_us - m->stamp.training_timestamp_us;
    uint64_t age_hours = age_us / (3600ULL * 1000000ULL);
    if (age_hours > max_age_hours) {
        Health_LogCriticalRateLimited(
            "[stale_model] %s is %lluh old > max %lluh",
            m->stamp.run_name, age_hours, max_age_hours);
        return strict_mode ? -1 : 0;  // REFUSE in strict; WARN otherwise
    }
    return 0;
}
```

Cfg field: `cfg.model_max_age_hours` (default 0 = disabled).

### Step 2 — Stale-feature gating per-feature (.A)

File: `ML_Headers/FeatureRegistry.hpp`

Extend FOREACH_FEATURE row metadata with `max_staleness_minutes`
(0 = disabled; per-feature operator-tunable).

```cpp
#define FOREACH_FEATURE(X) \
    /* old: X(name, version, ComputeFn) */ \
    /* new: X(name, version, ComputeFn, max_staleness_minutes) */ \
    X(price_avg, 1, Compute_PriceAvg, 0)  /* always-fresh; rolling */ \
    X(book_imbalance, 1, Compute_BookImbalance, 5)  /* depth WS may stall */ \
    /* ... */
```

In `Features_PackAll`:
```cpp
for each feature i:
    if (feature_max_staleness_minutes[i] > 0) {
        uint64_t age_min = (now_us - feature_last_update_us[i]) / 60000000ULL;
        if (age_min > feature_max_staleness_minutes[i]) {
            features[i] = 0.0f;  // stale → 0 sentinel
            stale_feature_events_total++;
            continue;
        }
    }
    features[i] = ComputeFn(...);
```

**Note:** This extends FOREACH_FEATURE with a new column → bumps
FEATURE_REGISTRY_HASH (hash includes the new column). Operator
must retrain. Document as deliberate exception OR keep new column
out of hash (special-case the hash to read only name+version).

**Decision needed at code time:** include max_staleness in hash or
not? Recommendation: NOT in hash (it's runtime config, not
training-time semantics). Operator's training data + Compute fn
are unchanged; a different staleness threshold doesn't change
what the model learned.

(scaler refit but stamp not updated → drift class).

## Latency analysis

**Stale-model:** Boot-only. ~1 µs per model (clock + subtraction).

**Stale-feature:** Slow-path inference cost. Per-feature
`if (max_staleness > 0)` check + 1 timestamp compare = ~2ns per
feature. For NUM_REGISTERED_FEATURES=20 → ~40ns extra slow-path
cost. Cfg-default `max_staleness_minutes=0` for all features
preserves bytewise behavior.

**Scaler fingerprint + removal_reasons + env meta:** Boot-only.
String parses; sub-µs.

**Hot path:** UNTOUCHED.

**HOT_PATH_CHANGELOG entry:** SLOW-PATH ADD for stale-feature
(~40ns per Features_PackAll call when configured); rest are
boot-only.
