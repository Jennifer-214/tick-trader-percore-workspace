Caramel runs **correctness-first, not agile.** She values correctness + planning over everything else and is deliberately shifting AWAY from move-fast / break-stuff / ship-fast. Speed is essentially never the deciding factor; getting it right + planning beat shipping velocity every time. She wants this discipline (incl. "never skip thoroughness") FORMALIZED into the reusable `workspace-template` so it carries across every project in the ecosystem, not re-derived per project.

**Why:** capital/HFT + public-AGPL quality bar; a wrong-but-fast answer on money code is worse than a slow-but-right one. Stated explicitly 2026-06-02 ("we aren't running agile here, we're running correctness first"; "i value correctness and planning over everything else tbh").

**How to apply:** default to the deliberate, planned, verified path; never trade correctness for speed; when execution starts flailing (e.g. repeated failed attempts), STOP and slow down rather than push through; surface decisions + ASK rather than rush.
