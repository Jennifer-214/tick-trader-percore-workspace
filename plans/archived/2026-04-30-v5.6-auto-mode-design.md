# v5.6 — AUTO mode improvements (design pass)

**Filed:** 2026-04-30 (post-v5.5.4)
**Status:** design TODO, not started
**Trigger:** v5.5.4 paper test surfaced two AUTO-mode shortcomings that
need a deliberate design pass, not a quick fix.

## Items to address

### 1. Trade log records raw strategy_id ("AUTO") instead of resolved sub-strategy

User's trade history shows "AUTO" in the strategy column for every
AUTO-core trade — loses visibility into which sub-strategy (MR / MOM
/ EMA / DIP) actually fired the trade.

**Where the bug lives:**
- `EngineSharded.hpp:~1704` — `drain_with_submit` lambda passes
  `state.cores[slot].strategy_id` (raw) to `OMS_PushSubmit`.
- `EngineSharded.hpp:~1798` — `drain_manual_closes` lambda same.
- The OMS stores it on the order, the trade log writes it from there.

**Easy version:** swap raw → resolved in the two Submit sites.
- Pro: 5-line change.
- Con: loses the "this was an AUTO core" signal — trades look
  indistinguishable from a hard-configured MR/MOM core.

**Better version:** record BOTH the raw + resolved. CSV gets a new
column, GUI Trade History panel renders as "AUTO(MR)" or "MOM" etc.
- Pro: full information preserved.
- Con: requires CSV schema bump, OMS Order field add, log reader
  + panel updates. ~2-3h.

**Best version:** also record resolved-at-EXIT (could differ from
resolved-at-ENTRY if AUTO transitioned mid-position). Two columns:
entry_strategy, exit_strategy. Tells the full story.
- Pro: full forensics on regime-transition behavior.
- Con: more invasive — both E and X rows need new fields. ~3-4h.

**Recommendation:** start with the easy version for v5.6.0; if the
"AUTO" signal turns out to matter, escalate to the better version
in v5.6.1.

### 2. live_tp / live_sl don't refresh on AUTO regime transition

User intuited it correctly: "buy gate and exit marks may get
corrupted and not persist." They DO persist — they don't update —
which is the issue.

**Mechanism:**
- AUTO core 2 opens a position under MR (RANGING regime). Hot path
  sets `live_tp = entry × (1 + mr_tp_pct)` from cached_params at
  fill time.
- AUTO transitions to MOM (TRENDING). Slow path now produces MOM
  params. cached_params updates via seqlock.
- BUT `live_tp` / `live_sl` were stamped at entry — they don't
  re-derive from the NEW cached_params.
- Position keeps MR's exit levels even though MOM is now the active
  strategy.

**Design questions:**
1. SHOULD live_tp refresh on regime transition? Some traders argue
   no — the position was opened with one thesis, exit it with the
   same. Others argue yes — adapt to the new regime.
2. If yes, on EVERY tick or only on transition? Per-tick is
   wasteful; per-transition needs a way for hot path to know
   "fresh" levels are available.
3. What about positions opened pre-warmup or pre-snapshot-restore?
   live_tp may already be stale from a prior session.

**Suggested approach:**
- Add `cfg.regime_transition_refreshes_levels` (default: 0 = off,
  preserve current behavior).
- When set, slow-path on regime transition: write a "refresh
  request" flag in pending_params (one bit). Hot path sees flag,
  re-derives live_tp / live_sl from cached_params at next entry-
  active tick.
- Decouples the policy decision from the implementation — easy to
  flip on/off for A/B testing.

**Effort:** ~3-5h. Touches hot path (one new flag check) so needs a
HOT_PATH_CHANGELOG entry + branchless impl.

## Out of scope for v5.6

- Multi-symbol routing under AUTO
- Per-symbol regime detection
- AUTO meta-strategy (regime-of-regimes) — that's v6+ territory

## When to start

After v5.5.4 paper testing converges (user confirms no more
"TP-too-tight on AUTO" pattern). If users report the trade history
"AUTO" label is confusing in the meantime, jump straight to item 1.
