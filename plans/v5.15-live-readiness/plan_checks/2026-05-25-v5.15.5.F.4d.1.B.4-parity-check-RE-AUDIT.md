## NEW concerns surfaced

### NEW CONCERN #1 — PARITY-031 closure underspecified: which core `c` for per-tick feature-collect?

**Severity:** MED

**Where:** Decision F (Step C.4.5)

**Issue:** Plan body says "Backtest feature collector reads `state.cores[c].regime_state` directly (sister to live discipline at EngineSharded:3194)". But the backtest feature-collect lambda fires from `drv->on_slow_path()` callback (ShardedBacktestDriver:393) which is invoked ONCE per tick, NOT once per core. The live sister at EngineSharded:3194 is INSIDE the per_core_slow per-core thread (so `c` is the thread's own slot index) — there's no ambiguity.

In backtest, the callback context has NO core index — `void on_slow_path(void* ctx, drv, tick, tick_index)` signature lacks `core_idx`. The current code uses single `fc->regime_state` exactly BECAUSE there's no per-core notion in this callback. The line-638 comment ("Sharded has no central regime field — each core may run a different strategy. Default 0 — Past Runs / regime histograms should treat sharded results as regime-agnostic") explicitly acknowledges this is unresolved.

**Options to disambiguate at Phase B:**
1. Add `core_idx` parameter to `on_slow_path` signature + invoke callback N times per tick (true per-core feature collection)
2. Pick canonical "core 0" as the regime source for feature collection (matches current `sample_regimes[i] = 0` semantic; documents that feature collection is core-0-canonical)
3. Iterate `state.cores[c].regime_state` to compute majority/mode regime per tick (regime-agnostic preserved; explicit instead of single fc field)

**Recommendation:** Plan body Step C.4.5 should explicitly choose 1/2/3 before Phase B unlock. Default = option 2 (lowest delta; preserves current sample_regimes=0 semantic). If option 1 (per-core callback), that's a bigger refactor than ~15 LOC delta claimed.

### NEW CONCERN #2 — Double-fire risk at Step C.4 migration: AllCores wrapper + existing ShardedBacktestDriver centralized calls

**Severity:** MED-HIGH (silent accounting/state corruption if not addressed)

**Where:** Phase C Step C.4 migration of `ShardedBacktest_RunTick`

**Issue:** ShardedBacktestDriver:378-383 currently fires:
```cpp
EventLoop_TimeExit(drv->state, drv->oms, *drv->config, ...);     // centralized form
EventLoop_TrailingSLRatchet(drv->state, *drv->config, ...);     // centralized form  
EventLoop_BreakevenOnProfit(drv->state, *drv->config, ...);    // centralized form
```

The centralized forms (ControllerEventLoop:3796 `EventLoop_BreakevenOnProfit`) ALREADY fan to OneCore N times internally. If backtest is migrated to call `EngineCommon_SlowPathCycleAllCores` which ALSO contains TimeExitOneCore + TrailingSLRatchetOneCore + BreakevenOnProfitOneCore (per Step B.2a OneCore body spec) **AND** ShardedBacktestDriver:378-383 lines are NOT deleted, we get DOUBLE-FIRE for all 3 helpers:
- TimeExit fires 2× → max_hold_ticks counted 2× per tick → premature time exits
- TrailingSLRatchet fires 2× → ratchet level advanced 2× per tick → SL set tighter than designed
- BreakevenOnProfit fires 2× → harmless idempotent (max-only composition) but wasted cycles

**Resolution:** Plan body Step C.4 needs EXPLICIT deletion clause for ShardedBacktestDriver:378-383 lines (these 3 calls become subsumed by SlowPathCycleAllCores wrapper). Currently Step C.4 reads "Migrate `ShardedBacktest_RunTick` slow-path body to call `EngineCommon_SlowPathCycleAllCores` once per tick" — the word "Migrate" implies replacement but doesn't enumerate which lines get deleted.

**Recommendation:** Amend Step C.4 to: "Migrate `ShardedBacktest_RunTick` slow-path body to call `EngineCommon_SlowPathCycleAllCores` once per tick. **DELETE ShardedBacktestDriver.hpp:378-383** (3 centralized helpers — EventLoop_TimeExit + EventLoop_TrailingSLRatchet + EventLoop_BreakevenOnProfit — now subsumed by AllCores wrapper's OneCore fan). **DELETE EngineSharded.hpp:1925-1955** centralized-arch path inside producer slow-path body (same 3 centralized helpers — now subsumed by AllCores wrapper for CENTRALIZED arch caller path)."

Also flag: EngineSharded.hpp CENTRALIZED arch (engine_arch != per_core_slow) also calls the 3 centralized helpers at :1932/:1934/:1940 — same double-fire concern at the live centralized caller. Plan body should specify how CENTRALIZED-arch caller path migrates (call AllCores wrapper instead of inline centralized helpers).
