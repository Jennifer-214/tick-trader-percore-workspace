The tool classifies each hit:

| Classification | Detection signature | Action |

```markdown
## Glossary

Canonical terminology source-of-truth for the post-`.E` architecture. All other docs cross-reference this section; never duplicate definitions. New terms introduced anywhere in the codebase MUST be added here.

### Deployment hierarchy

**Deployment** — The engine instance (whole). One process; one binary; one OS-level systemd unit. Owns ≥1 cluster. The unit of operator-level start/stop/restart.

**Cluster** — Per-exchange grouping within a deployment. Owns producer thread + exchange adapter + sub-account pool + rate budget + WS user-data connection + per-cluster credentials + per-cluster market-hours enforcement. Failure-isolated from other clusters (per-cluster kill flag halts only that cluster's trading). One cluster = one exchange.

**Node** — Logical trading unit within a cluster. Bound 1:1 to a sub-account on its cluster's exchange. Owns slow + hot pthread pair on dedicated CPU resources (typically 2 CPU cores). Owns its own strategy + ML model + risk parameters + portfolio slot + flow-of-funds. Per-node failure domain at economic layer (exchange-enforced via sub-account isolation).

**ExecutionCore** — Runtime hot-path execution context within a Node. Per-thread CPU-execution unit; bound to one CPU core via isolcpus. The CPU-execution-context concept; distinct from "Node" (deployment unit). Canonical name preserved (NOT renamed during Core→Node sweep).

**CPU core** — Hardware concept; physical processor core. References stay "CPU core" (never "node"). One Node typically uses 2 CPU cores (slow + hot pthread pair).

### Threading concepts

**Producer thread** — Single thread per cluster. Reads exchange WS feed; parses ticks; fans-out to per-node SPSC rings; replicates ema_price; publishes GUI/viewer state. Pre-`.E` was global single producer; post-`.E.1` per-cluster (one producer per cluster).

**Drainer thread** — DEPRECATED post-`.E.1` per drainer absorption. Pre-`.E.1` was global single thread running `OMS_DrainSubmit` + `OrderManager_Tick` + `DrainPostFill`. Post-`.E.1` these responsibilities absorb into per-node slow-path; no separate drainer.

**Aggregator** — Single global thread. Reads per-node state via seqlock; computes per-cluster + global totals; sets hierarchical kill flags. Read-only with respect to per-node state (per-node writes; aggregator reads). Per-fill event-sourced atomic_fetch_add updates running aggregate (per D-54); periodic cycle is integrity-verification only.

**Hot path** — Per-node per-tick execution context. Branchless (H7). Strict latency budget (≤500ns p99 per H8). Reads cfg via seqlock-cached parameters; emits TradeEvent on rare branch.

**Slow path** — Per-node per-poll-interval execution context. Computes rolling state, regime classification, strategy parameters; writes via seqlock to hot-path cfg. Strict latency budget (≤100μs p99 per H8).

### Economic concepts

**Sub-account** — Exchange-enforced economic isolation unit. One Node bound 1:1 to one sub-account. Structurally stronger than virtual partition (exchange enforces; not internal accounting). Canonical isolation mode for exchanges supporting sub-accounts (Binance). For exchanges without sub-accounts (Alpaca retail, IBKR retail), virtual partition is the fallback.

**Capital allocation** — Cluster-level distribution of capital across Nodes. `reserve_pct` keeps deployment-wide buffer; `max_per_node_pct` caps any single Node's exposure. Aggregator enforces at submit time.

### Build / runtime artifacts

**fox-engine** — Headless engine binary; runs as systemd service (production) or direct launch (dev). State published via mmap; commands via Unix domain socket. Replaces pre-`.E` `engine_gui` binary (archived to `legacy/`).

**fox-tui** — Read-only terminal viewer (notcurses). Reads mmap state directly; zero-copy. Vi-style keybinding.

**fox-cli** — Command sender to engine via UDS. Replaces pre-`.E` in-engine GUI controls.

**foxml-train** — Headless ML training CLI. Config-file-driven. Replaces pre-`.E` `foxml_suite` GUI binary (archived to `legacy/`).

**fox-supervisor** — DEFERRED to v5.16+. Future meta-controller binary.

### Architecture mode flags

**`mode = backtest | paper | live | shadow`** — Per-node operating mode. backtest = synthetic data; paper = real data + simulated fills; live = real submission; shadow = real submission with kill-switch override (future colo testing).

**`topology.mode = dev | production`** — Deployment-wide thread scheduling. dev = OS-scheduled (works on 8-core laptop); production = strict isolcpus + nohz_full + per-thread CPU pinning. Same binaries; topology cfg toggles.

### Version concepts

**ENGINE_VERSION_STRING** — Per-ship internal version; high-velocity (one bump per ship). Stamped into HMAC body. Shown in TUI.

**SOFTWARE_VERSION_STRING** — Platform milestone version; coarse-grained (one bump per substantial milestone). Starts at `v0.1.0` for full `.E` end-game.
```
