# v5.15.5.F.4d.1.B.5 through .B.11 — body-content enumeration sweep

## TL;DR

**VERDICT: RED-WITH-CONVERGENT-META-GAP.**

`.B.5` through `.B.11` plans claim to be "mechanical reorgs / mechanical pattern applications" of file-size split discipline. **They are not.** The sweep finds:

- **Pervasive fabricated spec content** at the boundary-decision layer in EVERY plan body in scope. Test count claims, panel boundary claims, sub-file split boundaries, build-system precedent shape, function symbol references — most of the *sub-file boundary specifications* in `.B.5`-`.B.10` cite labels/symbols/structures that do not exist in current HEAD.
- **Helper-extract anti-pattern doesn't apply directly to these plans** — they are file-split plans, not helper-extract plans (that was `.B.4`'s shape, with the `EngineCommon_*` extracts). HOWEVER an exact-analog gap shape DOES apply: **sub-file boundary enumeration** is the file-split-plan equivalent of "helper signature enumeration." Just as `.B.4`'s helper signature spec underspec'd the body inputs, `.B.5`-`.B.10`'s sub-file boundary spec underspec the source file's actual section structure.
- **`.B.4` v1.7.2 re-verification finds no new spec-vs-reality gaps introduced by `.B.5-.B.11` Class 34→Class 32 fix** (the v1.2 amendments to `.B.11` were correct; Class 32 metadata in workspace matches plan claims).

The META-gap shape this surfaces is NOT "helper signature underspec'd" (that was `.B.4`'s shape). It is:

**META-GAP CANDIDATE M6 — "planning-time spec content fabricated from inference rather than grounded in source read."**

Three distinct instances now stack:
1. `.B.4` v1.5 D1: fabricated symbol `OrderManager_RegisterCore` (vs actual `EventLoopState_RegisterCore`) — symbol inferred from architectural pattern, not grep'd.
2. `.B.4` v1.7 CRITICAL D1-B: scope/state mismatch (`state.cores[c].gate_state.flags` PER_CORE vs `state.global_gate_state.flags` ENGINE_WIDE) — scope inferred from intent, not verified against canonical sister.
3. `.B.4` v1.7.3 → now (the trigger that prompted this sweep): helper signature 6 args spec'd but body needs ~11 inputs — body content inferred, not enumerated.

And NOW added by this sweep, instance #4:
4. `.B.5-.B.10` sub-file boundaries fabricated from inferred panel/function names — boundaries inferred from architectural intent, not from source structure.

**The disciplines `feedback_verify_symbol_existence_at_plan_drafting_time` (Stage 6 codified at `.B.4` v1.7 D3) + `feedback_audit_canonical_sister_before_new_infra` exist but are NOT being applied to plan bodies at draft time — only at audit time after multiple amendment cycles.**

The structural fix for THIS gap class (which spans plan-draft → audit-detect-on-N-th-cycle): **codify pre-draft sweep discipline. Before drafting plan body sub-file boundaries / function signatures / build system claims, comprehensive grep + read of current HEAD must produce a CSV / table of actual structure. Plan body then references THAT enumeration, not free-text inferred labels.**
