## The two incidents (both caught in-session, both structurally closed)

### 1. The doc executor double-renamed (REAL incident)

`check_doc_rename_classification.py` (the `.D.1` executor, reused per gate S-7) matched tokens UNANCHORED (`re.escape(token)`, case-insensitive). Built for `per-core`→`per-node` (value ⊅ key), it was silently non-idempotent for `FPN`→`FPN_Binary` (value ⊃ key): re-encountering already-renamed text produced `FPN_Binary_Binary`, and — worse — it matched `FPN` inside `FPN_*` FUNCTION names in doc prose, corrupting non-goal identifiers (`FPN_DivNoAssert`→`FPN_Binary_DivNoAssert`, `CFG_PARSE_FPN`→`CFG_PARSE_FPN_Binary`) across **28 doc files** including live skill descriptions. The spec's own Phase-1 substring matrix had recorded `FPN` ⊂ `FPN_Binary` — verified for the GREP, never for the TOOL. **The grep and the tool are different matchers.**

**Closure:** lookaround boundary anchoring in the executor (`(?<![A-Za-z0-9_]) … (?![A-Za-z0-9_])` — preserves hyphen-prose matching, kills word-char-adjacent matches) + **idempotency PROVEN** (second `--apply` = 0 new) + all 28 files repaired (one reverse-sed pair + git-restore of the committed spec) + `rename-ship-methodology.md` Phase 5 gains the mandatory executor-vs-matrix check, the idempotency proof step, and the self-referential-doc exclusion rule. The next rename ship inherits the guard.

### 2. The `rg -rln` phantom (self-inflicted verification lie)

During incident-1 triage, damage greps were typo-flagged `rg -rln`/`rg -rn` — rg's `-r` takes a VALUE, so these parsed as `--replace ln` / `--replace n`: **display-only substitution of the matched span in rg's own output**. The "evidence" then showed tokens shrinking (`FPN_Binary_Binary` → `ln` → `n`) across successive greps — a perfect simulation of an unknown live rewriter mutating files, escalated to a stop-the-line question to the operator. Her "no, I wasn't editing" cracked it: files were never mutating; the VERIFIER's invocation was transforming its own printout. Real damage remained exactly the incident-1 set.

**Lesson (meta-anti-pattern candidate for the `/close-session` harvest):** *verify the verifier's invocation* — when verification output is surprising, the first suspect list must include the verification command itself (flag parsing, display transforms, cwd, ignore-rules). Sister to AR-4 (verification-by-proxy) and `feedback_run_doc_ci_tools_first_never_hand_verify`'s "transient empty output → RETRY" clause.
