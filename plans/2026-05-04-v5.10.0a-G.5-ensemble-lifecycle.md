## Theme

v5.10.0a.G.3 shipped the `EnsembleModelZoo` struct + `_LoadFromCfg`
loader. v5.10.0a.G.4 shipped the dispatch helper + MLStrategyState
ensemble_zoo pointer. THIS sub-ship wires engine boot to allocate
the per-core ensemble zoo, auto-detect horizons from disk, and
assign the pointer.

After G.5: a multi-horizon model bundle on disk → engine loads N
models at boot → MLStrategy_BuySignal dispatches via Model_Predict_Ensemble
(G.4 selection logic) automatically. No cfg fiddling beyond
core_N_model_dir.

## Items

### #1 — EnsembleModelZoo_AutoDetectFromDir helper (~45min)

New helper in `ML_Headers/CoreModelZoo.hpp`. Scans
`<base_dir>_horizon_*` siblings, verifies stamps via existing
`verify_model_stamp`, populates ensemble at correct member_idx slots.

```cpp
template <unsigned F>
inline int EnsembleModelZoo_AutoDetectFromDir(
    EnsembleModelZoo<F>* ezoo,
    const char* base_dir,             // e.g. "models/test_case3_run"
    int backend,
    /* held-out gate args, same as LoadFromCfg */ ...);
```

Implementation:
- `glob` or directory scan for `<base_dir>_horizon_*` patterns
- For each candidate: extract horizon_ticks from suffix
- Try load via existing `CoreModelZoo_TryLoadRole` + verify stamp
- If stamp's `has_grid_member_count == 1`: validate count consistency
  across siblings (all must agree on grid_member_count)
- Populate ezoo->barrier[grid_member_idx] etc.
- Return total horizons loaded; sets `ezoo->active = 1` if ≥ 1

**Validation:**
- Empty `base_dir` → no-op, return 0
- Mismatched `grid_member_count` across siblings → log error + skip
  inconsistent siblings (load only those that agree)
- Missing stamps on candidates → load anyway with warn (legacy
  multi-train pre-G.2 might not have grid_member_count stamped)

### #2 — Per-core lifecycle in BacktestSharded_Run + EngineSharded_Run (~1h)

Both engines already allocate per-core `CoreModelZoo<F> ml_zoos[]`
statically. Mirror that pattern for `EnsembleModelZoo`:

```cpp
static EnsembleModelZoo<BACKTEST_FP> ml_ensemble_zoos[MAX_EXECUTION_CORES];
```

Per-core init flow:
1. `CoreModelZoo_Free(&ml_zoos[i])` then `CoreModelZoo_Init(&ml_zoos[i])` (existing)
2. `EnsembleModelZoo_Free(&ml_ensemble_zoos[i])` then `EnsembleModelZoo_Init(&ml_ensemble_zoos[i])`
3. If `cfg.core_strategies[i] == STRATEGY_ML`:
   - Existing CoreModelZoo load (single-model path)
   - **NEW:** if `cfg.core_model_dir[i][0]` non-empty AND
     `cfg.horizon_count > 0` (or per-core override):
     `EnsembleModelZoo_AutoDetectFromDir(&ml_ensemble_zoos[i],
        cfg.core_model_dir[i], backend, ...)`
   - If ezoo->active: log "[ensemble] core %d: %d horizons loaded"
4. Post-MLStrategy_Init: assign pointer
   ```cpp
   if (ml_ensemble_zoos[i].active)
       state.cores[i].ml_strategy.ensemble_zoo = &ml_ensemble_zoos[i];
   ```

**EngineSharded_Run mirrors this exactly** (live engine; same wiring).

### #4 — Per-regime warmup priors loader (+30min, fold from /plan-check 2026-05-04)

When stamp body has per-regime val_acc fields (FUTURE — added by
trainer-side ship in v5.10.0a.next), use them as `Bandit_Init` priors
instead of uniform. Load path is forward-compat: missing fields →
uniform (current behavior).

Load logic in G.5 lifecycle (after AutoDetectFromDir populates models):

```cpp
// Forward-compat: read per-regime val_acc from each loaded stamp.
// If ALL N stamps have has_per_regime_val_acc=1, use as bandit prior.
// Otherwise (any missing), fall back to uniform.
double prior_weights[NUM_REGIMES][ENSEMBLE_HORIZON_MAX] = {};
bool   prior_complete = true;
for (int h = 0; h < ezoo->buy_signal_count; ++h) {
    ModelStampResult sr = verify_model_stamp(<path_h>, ...);
    if (!sr.has_per_regime_val_acc) {
        prior_complete = false;
        break;
    }
    for (int r = 0; r < NUM_REGIMES; ++r) {
        // Higher val_acc → higher initial weight; offset from baseline 0.5
        prior_weights[r][h] = std::max(0.0, sr.per_regime_val_acc[r] - 0.5);
    }
}
if (prior_complete) {
    // Pass to _InitBandits as priors (G.7 extension)
    EnsembleModelZoo_InitBandits(ezoo, eta, min_warmup,
                                  /*priors=*/&prior_weights[0][0]);
} else {
    // Uniform init (current behavior)
    EnsembleModelZoo_InitBandits(ezoo, eta, min_warmup, /*priors=*/nullptr);
}
```

**v5.10.0a.next ship will add:**
- `StampInferenceCfgInputs.has_per_regime_val_acc` flag + `per_regime_val_acc[NUM_REGIMES]` array
- Trainer-side: G.1 worker computes per-regime accuracy from WF folds
  (using WalkForwardFoldResult's regime classification per-fold)
- Stamp body emit + parse (canonical position 21 — after v5.10.0d's
  position 20)

For G.5: implement the READER side defensively (priors used IF
present; else uniform). Trainer side comes later. Operators get fast
convergence the moment they retrain with v5.10.0a.next.

## Risk register

| Risk | Mitigation |
|---|---|
| `glob`/directory scan fails on weird paths | Use `opendir/readdir`; gracefully skip unreadable entries |
| Memory bloat: 8 horizons × 4 roles × ModelHandle ≈ 1.6GB | Operator opt-in via cfg.horizon_list; default empty = no allocation |
| Multi-core: each core has its own ensemble_zoo, ~6.4GB across 4 cores | Document; same opt-in story |
| Race on ensemble_zoo pointer assignment | Single-writer at boot; pointer never reassigned post-Init within session |
