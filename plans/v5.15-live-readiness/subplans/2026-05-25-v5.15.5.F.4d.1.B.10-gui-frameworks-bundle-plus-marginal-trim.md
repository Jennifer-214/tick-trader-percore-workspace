### Decision D — Marginal-4 TRIM evaluation policy (general)

For each of the 4 marginal headers (OrderManager / SettingsPanel / StrategyParameters / ModelInference):

**TRIM evaluation procedure:**

1. **Inspect for dead code** — deprecated functions, unused branches, commented-out code blocks, dead helper fns
2. **Inspect for redundant comments** — duplicated explanations, outdated TODOs (move to TECH_DEBT if real), oversized inline doc-blocks (move pattern-worthy ones to sister DESIGN_SPEC)
3. **Estimate trim LOC potential** — if achievable trim ≥ `(current_LOC - 1500)`, proceed with TRIM
4. **If TRIM insufficient** — escalate to SPLIT in same ship per Decision F.a
5. **If TRIM insufficient + SPLIT not natural** — accept EXEMPTION per Decision F.b

**TRIM order (L5 amended 2026-05-25):**

|---|---|---|---|---|

### Decision F — Marginal-4 fallback policy (M6 amended 2026-05-25)

What if TRIM AND split-without-cohesion-loss BOTH fail for a marginal header?

**Fallback hierarchy:**

| Level | Action |
|---|---|
| 1. TRIM (default) | Remove cruft; bring under threshold |
| 2. SPLIT (escalation) | Apply subfolder pattern; sub-file boundaries from natural cohesion |
| 3. EXEMPT (last resort) | Accept over-threshold; document rationale per `file-size-split-discipline.md` § Skip when |
| 4. DEFER (last-ditch) | If exemption isn't justified, defer to NEW ship `.B.10.1`; document at ship close |

**Exemption criteria (when Level 3 applies):**
- Single-purpose monolithic file (like `Limits.hpp` exemption precedent)
- Auto-generated content (split happens at generation, not at file level)
- Split would create more cross-ref overhead than current monolithic state (per `file-size-split-discipline.md` § Skip when)

**For each marginal header, expected outcome:**

| Header | Expected level | Rationale |
|---|---|---|
| OrderManager.hpp | Level 1 (TRIM) | 1.03× over; ANY trim brings under |
| SettingsPanel.hpp | Level 1 (TRIM) | 1.2× over; cruft typical of GUI panel files; trim achievable |
| StrategyParameters.hpp | Level 1-2 (TRIM, maybe SPLIT) | 1.2× over; per-strategy dispatch is cohesive; TRIM likely sufficient |
| ModelInference.hpp | Level 1-2 (TRIM, possibly SPLIT) | 1.3× over; `verify_model_stamp` parser is bulk; CLEANUP-001 fold-in could trim 100s of LOC |

**Hard rule:** No marginal header gets Level 4 (defer) unless ALL 1-3 fail with documented reasoning. Per `feedback_no_defer_for_effort`: defer is last-ditch only.
