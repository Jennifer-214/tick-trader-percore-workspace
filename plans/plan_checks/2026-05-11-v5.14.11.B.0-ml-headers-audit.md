# v5.14.11.B.0 — ML_Headers/ math-kernel audit findings

**Date:** 2026-05-11
**Scope:** branchless + constant-iter compliance audit of math kernels in `ML_Headers/`
**Reference patterns:** `branchless-math-kernel-pattern.md` + `struct-padding-determinism-pattern.md` (both written in this sub-tag)

---

## Audit methodology

For each math-kernel file in `ML_Headers/`:
1. Grep for inner reduction loops with non-MAX_* bounds (`for (int k = 0; k < n; ...)` where n is runtime variable)
2. Grep for `if` statements inside reduction loops (potential branchy math)
3. Read struct definitions for implicit padding (when struct used in memcmp/hash/serialize)

---

## Findings classification

- **CRITICAL** — bytewise determinism violation in a contract-locked surface; must fix
- **HIGH** — variable-iter inner reduction that should be constant-iter per new pattern
- **MEDIUM** — latent padding bug in struct used in byte-equivalence context
- **LOW** — per-call-stable variable-iter (acceptable per CLAUDE.md item 18; branch predictor handles)
- **INFO** — pattern compliance verified

---

## Findings

### F1 (CRITICAL — to fix in .B.1) — Cholesky_Solve AVX-512 has `if (j > 0)` and `if (i > 0)` guards

**File:** `ML_Headers/RidgeBlender.hpp` (Cholesky_Solve AVX-512 WIP from pre-.B.0; restored to .A scalar state in .B.0 commit; AVX-512 re-added in .B.1 with correct branchless pattern)
**Class:** branchless-math-kernel-pattern violation (introduced in v5.14.11.B WIP before Caramel pushback 2026-05-11)
**Status:** **FIX IN .B.1** — rewrite Cholesky to constant-8 scalar + pre-zero invariant; no explicit AVX-512 in Cholesky (compiler auto-vec via `-O3 -march=native`)

### F2 (MEDIUM — to fix in .B.2 alongside FPN) — ThompsonBanditState has 4 bytes implicit padding

**File:** `ML_Headers/ThompsonBandit.hpp` (struct ThompsonBanditState)
**Layout:**
```
mu_post[8]:        64 bytes (offset 0..63)
precision_post[8]: 64 bytes (offset 64..127)
total_pulls[8]:    32 bytes (offset 128..159; uint32_t per arm)
n_arms:             4 bytes (offset 160..163; int)
[IMPLICIT 4B PADDING — offset 164..167; uninit]
mu_prior:           8 bytes (offset 168..175; double; needs 8-byte align)
precision_prior:    8 bytes (offset 176..183)
precision_obs:      8 bytes (offset 184..191)
rng_state:          8 bytes (offset 192..199; uint64_t)
```
**Class:** struct-padding-determinism-pattern violation (latent)
**Current impact:** Thompson_SaveJSON serializes field-by-field (NOT bytewise); padding latent but doesn't break anything yet
**Future risk:** if anyone adds a `memcmp` / SHA-256 / wire-format usage of ThompsonBanditState, the latent bug surfaces (same class as FPN regression)
**Status:** **FIX IN .B.2** — add `int32_t _padding = 0;` after `n_arms` (1 line; same struct size; same field offsets for subsequent fields). Safe migration.

### F3 (INFO) — BanditState has no implicit padding (well-aligned by accident)

**File:** `ML_Headers/BanditLearning.hpp` (struct BanditState)
**Status:** No fix needed. Member ordering happens to avoid padding gaps. Document via static_assert (optional; future-proof; could fold into .B.4 as a sanity invariant).

### F4 (LOW — acceptable per CLAUDE.md item 18) — Multiple kernels use per-call-stable `n_arms` / `n` iteration bounds

**Files:**
- `BanditLearning.hpp:97, 127, 133, 169, 172` (n_arms loops; n_arms ≤ BANDIT_MAX_ARMS=8, per-call stable)
- `ThompsonBandit.hpp:150, 261` (n_arms loops; same)
- `ConfidenceScore.hpp:86, 89, 109, 124, 175` (n / r->count loops; per-call stable)
- `ROR_regressor.hpp:79` (reg->count; per-call stable)
- `FlowFeatures.hpp:110` (k; per-call stable)

**Classification:** per CLAUDE.md item 18 sub-clauses (b/c/d), per-call-stable variable iter is acceptable — branch predictor handles consistent direction. The pattern from `branchless-math-kernel-pattern.md` applies STRICTLY to **inner reductions with variable bounds that vary WITHIN a single call** (like Cholesky's `for (k = 0; k < j; ++k)` where j increments per outer iter).

**Status:** **NO FIX NEEDED.** These are loop bounds tied to a per-call-stable size; not the recurring class.

### F5 (INFO) — Branchy math sites in BanditLearning/ThompsonBandit/ConfidenceScore are LEGITIMATE state-machine branches, not math-kernel inner branches

**Files + counts:**
- BanditLearning.hpp: 11 branchy sites (mostly early-exit fallbacks: `if (sum_w <= 0.0)`, `if (prob_sum > 0.0)`)
- ThompsonBandit.hpp: 2 branchy sites
- ConfidenceScore.hpp: 8 branchy sites

**Classification:** Legitimate per CLAUDE.md item 18 sub-clauses — error-path fallbacks, degenerate-state guards, state-machine dispatches. Not the branchless-math-kernel-pattern violation type.

**Status:** **NO FIX NEEDED.**

### F6 (INFO) — Bandit_GetProbabilities follows v5.11.7 byte-determinism + branchless within vector block

**File:** `ML_Headers/BanditLearning.hpp:139-200`
**Status:** Compliant per existing v5.11.7 discipline. Now formally covered by `avx512-byte-determinism-pattern.md` (Rule 8 to be added in .B.4 for "branchless within vectorized block").

### F7 (forward-looking) — UpdateOnline + BuildCorr AVX-512 to be added in .B.3 must follow branchless pattern

**File:** `ML_Headers/RidgeBlender.hpp` (RidgeBlender_UpdateOnline + refactored RidgeBlender_BuildCorr)
**Status:** **WRITE IN .B.3** following branchless-math-kernel-pattern + avx512-byte-determinism-pattern. Use uniform masks across 8 lanes; no `if` guards inside vectorized blocks.
