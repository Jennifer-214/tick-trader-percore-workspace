## Phases

### Phase A — Unified init-time mmap arena (~1.5 days)

Goal: eliminate `malloc` / `new` for the ~5 large structs allocated at
engine boot. Single `mmap(MAP_PRIVATE | MAP_ANONYMOUS | MAP_POPULATE)`
arena owns all of them; per-call sub-allocations bump-pointer from the
arena. Single munmap on shutdown.

**Step 0 (mechanical):** create `MemHeaders/InitArena.hpp` with:
```cpp
struct InitArena { uint8_t* base; size_t size; size_t used; };
InitArena InitArena_Create(size_t bytes);
void* InitArena_Alloc(InitArena* a, size_t bytes, size_t align);
void InitArena_Destroy(InitArena* a);  // munmap
```

Bump-pointer alloc; alignment via `(used + align - 1) & ~(align - 1)`.
No reuse / no free of individual allocs — entire arena lifetime
matches engine lifetime.

**Sites converted** (total bump-pointer allocations at boot):
- `PortfolioController_Init` rolling_long → `InitArena_Alloc(arena, sizeof(RollingStats<F, 512>), alignof(RollingStats<F, 512>))`
- `PortfolioController_Init` rolling_medium → same pattern
- `PortfolioController_Init` rolling_baseline → same pattern
- `PortfolioController_Init` cumdelta_state → same pattern
- `EventLoopState_Init` per-core slow_state[N] → same pattern (one alloc per
  core; arena holds NUM_CORES × sizeof(CoreSlowState<F>))
- `StrategyLifecycle.hpp:134` strategy state factories → same pattern via
  X-macro update (placement-new on arena slot)

**Sizing:**
```
RollingStats<64, 512>   ≈ 12 KB
RollingStats<64, 256>   ≈  7 KB
RollingStats<64, 1024>  ≈ 24 KB
CumDeltaState<64>       ≈  1 KB
CoreSlowState<64>       ≈ 30 KB × 16 cores = 480 KB
StrategyState (per type) ≈ 1-4 KB × 5 strategies × 16 cores = ~320 KB
                         total ≈ 850 KB. Round up to 1 MB.
```

`mmap(NULL, 1*1024*1024, MAP_POPULATE)` at engine boot. Pre-faulted.
Symmetric to the v5.11.5.C OrderEventLog mmap pattern.

**Tests:**
- `InitArena_Alloc` returns 16-byte-aligned pointers (or whatever alignof(T) requires)
- Multiple allocs return distinct non-overlapping ranges
- `arena.used` advances monotonically
- Destroy munmaps cleanly (verify by running under valgrind / asan in v5.11.6.A.test)
- All existing 1747 tests still pass post-conversion (load-bearing — engine init unchanged in semantics)

**Tag:** `v5.11.6.A` (rollback anchor `pre-v5.11.6.A` if needed).

### Phase B — PoolAllocator bootstrap from mmap (~0.5 day)

Goal: replace `PoolAllocator.hpp:47` `calloc` with mmap-backed
zeroed memory. Eliminates one libc dependency at engine boot.

**Step 0 (mechanical):** edit `MemHeaders/PoolAllocator.hpp:47`:
```cpp
// BEFORE:
pool->slots = (CurrentOrder<F> *)calloc(capacity, sizeof(CurrentOrder<F>));

// AFTER:
size_t bytes = capacity * sizeof(CurrentOrder<F>);
pool->slots = (CurrentOrder<F>*)mmap(nullptr, bytes,
    PROT_READ | PROT_WRITE,
    MAP_PRIVATE | MAP_ANONYMOUS | MAP_POPULATE,
    -1, 0);
if (pool->slots == MAP_FAILED) pool->slots = (CurrentOrder<F>*)calloc(capacity, sizeof(CurrentOrder<F>));
pool->capacity_bytes = bytes;  // new field for munmap on Free
```

`MAP_ANONYMOUS` zero-fills automatically — no separate memset needed.

Add `pool->capacity_bytes` to the PoolAllocator struct so Free can
munmap symmetrically.

**Tests:**
- PoolAllocator init still produces a zeroed buffer (existing test
  if any; otherwise add: read first few slots are all-zero post-Init)
- `PoolAllocator_Free` munmaps cleanly
- Existing 1747 tests pass

**Tag:** `v5.11.6.B`.

## What this DOESN'T cover (deferred to future)

- Hugepage-backed arena (`MAP_HUGETLB`). Documented for future via
  cfg flag. v5.11.6 uses 4KB pages.
- BuddyAllocator integration as the arena backend (currently
  bump-pointer is sufficient given init-time-only allocs and known
  total size). Buddy is overkill for static-lifetime workloads.
- DataStream TLS internal allocations — those are inside OpenSSL and
  not under our control without replacing OpenSSL itself.

These are captured in `plans/2026-05-07-deferred-items.md` if they
become load-bearing.
