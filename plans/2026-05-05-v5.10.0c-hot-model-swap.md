# v5.10.0c — Hot model swap (live model reload without restart)

**Date:** drafted 2026-05-02; ships after v5.10.0b
**Branch:** `feat/v5.10.0c-hot-swap` (new)
**Predecessor:** v5.10.0b
**Effort estimate:** 2-3 days
**Hot path:** UNTOUCHED (model swap is slow-path; inference reads via RCU)

## Theme

v5.10 design Idea #13. Live engine reloads a model when operator
selects a new one in engine_gui's Model Dir Combo (v5.9.5f) without
requiring a process restart. Mirrors the existing strategy-hot-swap
RCU pattern (`swap_strategy_requested[]` in TUISharedState).

## Items

### #13 — `swap_model_path_requested[]` per core (2-3 days)

**Wiring (mirrors strategy hot-swap at SettingsPanel.hpp:923, 940):**

1. **TUISharedState extension** — add fields:
   ```cpp
   uint8_t swap_model_path_requested[MAX_EXECUTION_CORES];  // 1 = pending swap
   char    pending_model_path[MAX_EXECUTION_CORES][256];
   ```

2. **engine_gui Settings panel** — "Apply (live)" button next to
   Model Dir Combo (v5.9.5f). On click: set the per-core fields
   atomically. UI shows "swap pending..." until consumer responds.

3. **Engine consumer** (in slow-path tick loop):
   ```cpp
   if (__atomic_load_n(&shared->swap_model_path_requested[core_id],
                        __ATOMIC_ACQUIRE)) {
       const char* new_path = shared->pending_model_path[core_id];

       // Position-handling decision (cfg-driven):
       //   acknowledge_hot_swap_with_open_positions=0 → wait for close
       //   acknowledge_hot_swap_with_open_positions=1 → swap immediately
       int has_open = portfolio_has_position_for_core(core_id);
       if (has_open && !cfg.acknowledge_hot_swap_with_open_positions) {
           // hold; will retry next slow-path
           continue;
       }

       // Atomic load: build new ModelHandle, verify stamp, swap pointer
       ModelHandle<F> new_handle = {};
       Model_Init(&new_handle);
       int rc = CoreModelZoo_TryLoadRole(&new_handle, new_path, ...);
       if (rc <= 0) {
           // refused; clear request, log
           __atomic_store_n(&shared->swap_model_path_requested[core_id], 0,
                             __ATOMIC_RELEASE);
           Health_LogCriticalRateLimited("[hot_swap] core %d REFUSED: %s\n",
                                          core_id, sr.reason);
           continue;
       }

       // Old handle freed after grace period (one slow-path cycle)
       Model_Free(&old_handle);
       *active_handle_ptr = new_handle;

       __atomic_store_n(&shared->swap_model_path_requested[core_id], 0,
                         __ATOMIC_RELEASE);
       fprintf(stderr, "[hot_swap] core %d swapped to %s\n", core_id, new_path);
   }
   ```

4. **Position-handling cfg field**:
   - `acknowledge_hot_swap_with_open_positions` (int, default 0)
   - 0 = wait for position close before swap (safer)
   - 1 = swap immediately, open positions exit on whatever model fires
        (operator opt-in)

5. **ML Status panel** — add row showing pending swap state:
   "Hot-swap pending: → models/aggressive/buy_signal.bin (waiting for
   position close)"

6. **Atomic sequencing** — compare-and-swap to ensure only one swap
   per cycle. If operator clicks Apply twice fast, second click
   replaces the first pending request, doesn't queue.

## Risk register

| Risk | Mitigation |
|---|---|
| Model swap mid-position-open uses different math for entry vs exit | Default `acknowledge_hot_swap_with_open_positions=0` blocks until close |
| Atomic ordering bug → ghost predictions from old model after swap | Single-writer (slow-path) frees old handle AFTER swap commits; hot path reads via stable pointer |
| Operator races: two clicks → undefined behavior | Atomic store overwrites pending; only the latest survives |
| Memory leak: old handle not freed | Add tracked counter; assert in tests |

## Rollback

If hot-swap proves unstable, revert to `pre-v5.10.0c`. Operators
fall back to restart-engine-with-new-cfg workflow (v5.9.5f's static
Model Dir Combo + cfg restart).

## Out of scope

- Hot-swap of strategy + model together (v5.11+; orchestration)
- Hot-reload of cfg fields beyond model_path (v5.11+; broader RCU)
- Cross-machine swap coordination (v5.11+; if/when distributed)
