### Step 0 — Audit overlay concept feasibility


If overlay pattern partially exists → align with it. If absent →

### Step 1 — Define overlay-patch sidecar format

File: `tools/feature_overlay.py` (NEW, Python trainer side)

Sidecar format (`<model>.overlay.json`):
```json
{
  "version": 1,
  "base_registry_hash": "0x<hex>",
  "overlays": [
    {"feature_name": "ror_slope", "lookback_override": 256},
    {"feature_name": "vwap_dev", "disabled": true}
  ]
}
```

Trainer computes:
- Layer-1 = base FEATURE_REGISTRY_HASH (existing)
- Layer-2 = SHA256(canonicalized overlay JSON)
- Layer-3 = SHA256(layer1 || layer2)

Writes all three to stamp body.

### Step 2 — C++ side: load + verify overlay sidecar

File: `ML_Headers/FeatureRegistryOverlay.hpp` (NEW)

```cpp
struct FeatureOverlay {
    char overlay_path[256];
    char layer2_hash_hex[65];   // SHA256 → 64 hex chars + null
    char layer3_hash_hex[65];
    int  num_overlays;
    int  loaded;                 // 0 = no overlay (stamp's
                                  //     has_overlay_hash=0 path)
};

inline int FeatureOverlay_Load(FeatureOverlay* fo,
                                const char* path);
inline int FeatureOverlay_VerifyAgainstStamp(
    const FeatureOverlay* fo,
    const char* stamp_overlay_hash,
    const char* stamp_effective_hash,
    int strict_mode);  // 0=warn, 1=refuse
```

### Step 3 — Stamp body extensions (Surface G)

Two new fields in stamp body emit + verify:
- `has_overlay_hash` (uint8_t) + `overlay_hash[65]` (char)
- `has_effective_hash` (uint8_t) + `effective_hash[65]` (char)

Legacy stamps: both `has_*` = 0 → loader skips overlay check
entirely (single-layer FEATURE_REGISTRY_HASH check is sole
protection, as today).

**Field-emission pattern (clarified per v5.14.3 audit):**
Use **manual emit + parse pattern** (mirror v5.14.2.E.2.B architectural
fields, NOT FOREACH_STAMP_BOUND_CFG). Reasoning:
- Fields are sidecar-derived (computed from FeatureOverlay JSON), not
  cfg-bound. Don't fit FOREACH_STAMP_BOUND_CFG which auto-pulls from
  ControllerConfig.
- Only 4 fields in current scope; manual is bounded.
- When sidecar-derived field count grows to 5+, refactor to a parallel
  registry `FOREACH_STAMP_BOUND_SIDECAR(X)` (sister to TECH_DEBT-006's
  FOREACH_STAMP_BOUND_MODEL_CONST recommendation).
- Add discipline comment in `ModelHandle` + `StampInferenceCfgInputs`
  near the new fields listing the 5 sites that must stay in sync
  (init, parser, emit, populator, VerifyExpected dual-path read).

### Step 4 — Boot-time loader integration (CALL-SITE ENUMERATION + HELPER EXTRACTION)

**Per v5.14.3 audit (Class 18 prevention; same shape as PARITY-009/010/011/012):**

Extract `FeatureOverlay_PostLoadVerify<F>(zoo, ezoo, cfg, ...)` helper
following v5.14.2.E.1's `EnsembleModelZoo_PostLoadSetup` /
`CoreModelZoo_PostLoadSetup` precedent. Helper iterates per-handle
(buy_signal/barrier/regime/exit for single-zoo; same × N horizons for
ensemble). For each handle with `has_overlay_hash`, loads the
`<model>.overlay.json` sidecar + computes layer-2 + layer-3 + compares
+ WARN/REFUSE per `cfg.held_out_gate_strict`.

Helper signature (placement: `ML_Headers/FeatureRegistryOverlay.hpp`):

```cpp
template <unsigned F>
inline int FeatureOverlay_PostLoadVerify(
    const CoreModelZoo<F>* zoo,
    const EnsembleModelZoo<F>* ezoo,
    const ControllerConfig<F>& cfg,
    int core_id,
    int strict_mode);
// Returns: 0=ok / -1=refuse / >0=count of mismatched handles
```

**Six call sites** (must all invoke helper; symmetry test verifies):

- Layer-2 hash stability: same overlay JSON (different field order) →
  same SHA256 (canonicalization works)
- Layer-3 = SHA256(layer1 || layer2) verified
- Stamp body round-trip: write all three hashes → parse → bytewise

- Loader: stamp has overlay hash + matching sidecar → PASS

  check skipped
