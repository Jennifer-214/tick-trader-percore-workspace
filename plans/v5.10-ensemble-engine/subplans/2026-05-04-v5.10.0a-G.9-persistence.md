# v5.10.0a.G.9 — Bandit state persistence (load/save bandit_state.json)

**Date:** drafted 2026-05-04
**Branch:** `feat/v5.10-foundation`
**Predecessor:** v5.10.0a.G.8
**Effort estimate:** ~1-2h
**Hot path:** UNTOUCHED (load at boot, save at intervals + shutdown)

## Theme

Bandit weights are valuable — they encode "what horizons work for
THIS asset/regime/market." Without persistence, they reset to
uniform every restart, wasting hours of learning. G.9 persists per-
core bandit state to a JSON sidecar in the model bundle dir.

State also flows train→backtest: backtest can load deployed weights
as priors, simulating "what an operator actually runs with."

## Items

### #1 — JSON serialize/deserialize for BanditState (~45min)

Add to `ML_Headers/BanditLearning.hpp`:

```cpp
// Save BanditState array (one per regime) to JSON file
inline int Bandit_SaveJSON(const BanditState* bandits, int n_regimes,
                            const char* path,
                            const char* model_bundle_sha256_hex);

// Load BanditState array from JSON; returns 1 if loaded + valid,
// 0 if missing/corrupt/sha-mismatch (caller falls back to uniform)
inline int Bandit_LoadJSON(BanditState* bandits, int n_regimes,
                            const char* path,
                            const char* expected_model_bundle_sha256_hex,
                            int n_arms);
```

JSON shape:
```json
{
  "format_version": 1,
  "saved_at_ts_ns": 1234567890123,
  "model_bundle_sha256": "<64-char hex>",
  "n_regimes": 4,
  "n_arms": 5,
  "regimes": [
    {
      "regime_id": 0,
      "regime_name": "RANGING",
      "weights": [0.18, 0.42, 0.25, 0.10, 0.05],
      "n_updates": 12340,
      "arm_names": ["h100", "h500", "h1000", "h1500", "h2000"]
    },
    {
      "regime_id": 1,
      "regime_name": "TRENDING",
      "weights": [0.05, 0.10, 0.20, 0.30, 0.35],
      "n_updates": 8200,
      "arm_names": ["h100", "h500", "h1000", "h1500", "h2000"]
    },
    ...
  ]
}
```

Atomic write via fopen(tmp) + write + close + rename (matches stamp
persistence pattern).

### #2 — Save triggers (~30min)

Three places to call `Bandit_SaveJSON`:
1. **Per N updates:** in `Bandit_Update` (or its caller) — track total
   updates per ezoo; every `cfg.ensemble_bandit_save_interval` updates
   (default 5000), flush. Single-thread per-core arch keeps this safe.
2. **Engine clean shutdown:** signal handler / Ctrl-C → walk all
   ezoos → save each. Existing engine has shutdown hooks (e.g.
   `BacktestSharded_Run` final cleanup); add ezoo save there.
3. **Save Run button** (foxml_suite): when operator saves a run, copy
   the per-core bandit_state.json into the run dir alongside model
   files (`models/<run_name>/bandit_state.json`).

### #3 — Load trigger (~20min)

In `EnsembleModelZoo_AutoDetectFromDir` (G.5), AFTER auto-detect
populates models, call:
```cpp
char bandit_path[400];
snprintf(bandit_path, 400, "%s/bandit_state.json", base_dir);
char expected_sha[65];
compute_model_bundle_sha256(ezoo, expected_sha);
int loaded = Bandit_LoadJSON(ezoo->bandits, NUM_REGIMES,
                              bandit_path, expected_sha, n_arms);
if (!loaded) {
    // Missing or sha-mismatch → uniform init via _InitBandits (G.7)
    EnsembleModelZoo_InitBandits(ezoo, cfg.ensemble_bandit_eta,
                                   cfg.ensemble_min_warmup_predictions);
    fprintf(stderr, "[ensemble] bandit state not loaded (missing or "
                    "sha-mismatch); starting uniform.\n");
} else {
    fprintf(stderr, "[ensemble] loaded bandit state from %s\n", bandit_path);
}
```

### #4 — Model bundle SHA-256 helper (~15min)

Helper that computes SHA over concatenated model file SHAs:
```cpp
template <unsigned F>
inline void EnsembleModelZoo_ComputeBundleSha(
    const EnsembleModelZoo<F>* ezoo, char* hex_out, size_t hex_cap);
```
Iterates loaded handles, concats their model.sha256_hex, hashes the
concat. Matches the "scaler_sha256" pattern in v5.9.3a.

### #7 — Backtest replay-determinism explicit test (~30min, perf optimization #6)

Critical test for the entire ensemble pipeline: run a backtest TWICE
with identical inputs (same data, same prior bandit_state.json, same
seed) → verify final bandit weights bytewise-identical AND final
metrics bytewise-identical.

```cpp
// Test G.9.6: Backtest replay-determinism with ensemble active.
// Verifies bandit updates are deterministic given same input sequence.

// Setup: small synthetic dataset (10k ticks); train 3 horizons; export
// initial bandit_state.json (uniform priors).
char prior_path[] = "/tmp/v5100aG9_replay_prior.json";
write_uniform_bandit_state(prior_path, 3 /*horizons*/);

// Run 1
BacktestResults r1;
BacktestResults_Init(&r1);
BacktestRunConfig run_cfg = make_run_cfg();
strncpy(run_cfg.bandit_state_prior_path, prior_path, 400);
Backtest_Run(&r1, &run_cfg, ...);
char post_run1_path[] = "/tmp/v5100aG9_replay_post1.json";
Bandit_SaveJSON(/* core 0's bandits */, NUM_REGIMES, post_run1_path,
                /* bundle_sha */);

// Run 2 (identical inputs)
BacktestResults r2;
BacktestResults_Init(&r2);
strncpy(run_cfg.bandit_state_prior_path, prior_path, 400);  // same prior
Backtest_Run(&r2, &run_cfg, ...);
char post_run2_path[] = "/tmp/v5100aG9_replay_post2.json";
Bandit_SaveJSON(/* core 0's bandits */, NUM_REGIMES, post_run2_path,
                /* bundle_sha */);

// Assert: post-run bandit states bytewise identical
check("v5.10.0a.G.9: ensemble replay-determinism (bandit weights match)",
      files_bytewise_identical(post_run1_path, post_run2_path));

// Assert: realized P&L bytewise identical (catches non-determinism
// in the inference path itself)
check("v5.10.0a.G.9: ensemble replay-determinism (final P&L match)",
      r1.stats.total_pnl == r2.stats.total_pnl);
```

**Why this matters:** bandit updates are a sequence of multiplicative
operations; floating-point addition isn't perfectly associative; if
ANY non-determinism leaks in (thread scheduling, uninitialized
memory, etc.) the weights diverge over the run. Bytewise-equal
weights = deterministic ensemble pipeline. Operator's
backtest-to-deployment confidence depends on this.

## Risk register

| Risk | Mitigation |
|---|---|
| Concurrent save (multi-core) clobbers same file | Each core saves to `core_<N>/bandit_state.json`; per-core paths; no shared file |
| JSON parse errors on hand-edited files | Defensive parser; on parse fail, return 0 (uniform reset) with WARN |
| Stale bandit weights vs new model | Bundle SHA mismatch → reset; tested in G.9.3 |
| Atomic write fails (disk full) | Existing fopen+rename pattern returns error; bandit state stays in memory; warn-only |
| Save frequency thrashing disk | save_interval=5000 default; with typical 1 update/poll = 1 save per 500K ticks ≈ 1 save/hour |

## Verification

- Run engine for N predictions; bandit_state.json appears at
  `<base_dir>/bandit_state.json`
- Restart engine; stderr "loaded bandit state from <path>"; weights
  match prior session
- Edit JSON externally with bad SHA; restart; "sha-mismatch; starting
  uniform" + uniform weights
- Backtest with `bandit_state_prior_path=<live_run>/bandit_state.json`
  → backtest log "loaded prior weights"; backtest results reflect
  deployed-weights performance
