## Why this exists

`v5.14.0` `RidgeBlender_BuildCorr` recomputes the N×N correlation matrix from scratch every Ridge cycle (~1µs at N=8, K=64). On most cycles the prediction history barely changes — only the newest record is novel. Online incremental updates with O(N²) per-record cost + bounded-window numerical stability provide ~10× per-cycle latency reduction on the cfg=1 path.

Beyond the headline incremental optimization, the ship absorbs adjacent architectural improvements (per Caramel "harder upfront for easier future" + structural-fix-preferred rules):

1. **Unified math kernel** — `FinalizeCorrFromSums` shared by refactored `BuildCorr` and online path eliminates two parallel correlation-formula implementations (anti-mirror discipline)
2. **Ridge cohort cfg-flag migration** — intra-family inconsistency eliminated (4 booleans → bitmap)
3. **Class 18 mirror prevention** — `BuildHistoryFromRing` + `OnlineCycleStep` extracted helpers replace identical loops at buy + exit dispatch sites
4. **Cholesky AVX-512** — ~200ns savings on every Ridge cycle (cfg=0 + cfg=1)
5. **Dead code cleanup** — `last_compute_us` (never populated, never read) removed

### Step 2 — sliding-window UpdateOnline + shared FinalizeCorrFromSums

```cpp
// Per-record update. Cost: O(N²) outer-product accumulation.
// When window not yet full (count < K): standard sum-of-squares add.
// When window full: replace oldest record's contribution with new (drop-add).
//
// Defensive bounded-input guard at entry: predictions must be in [0,1]
// for the sum-of-squares numerical-stability argument to hold (cancellation
// error ε × max(sum_xx) ≤ ε × K × X² → ~1.4e-14 for K=64, X=1). BARRIER
// ensembles produce sigmoid outputs (naturally [0,1]); the assert catches
// non-BARRIER misconfigurations that could blow accumulator magnitudes.
// Compiled out in release builds; debug builds catch silent misconfigurations.
// Per /parity-check re-audit LOW recommendation 2026-05-11.
template <unsigned F>
inline void RidgeBlender_UpdateOnline(RidgeWeights<F>* rw,
                                       const float* predictions_new,
                                       const float* predictions_oldest_or_null,
                                       int n_models) {
    // Defensive bounded-input guard
    for (int i = 0; i < n_models; ++i) {
        assert(predictions_new[i] >= 0.0f && predictions_new[i] <= 1.0f);
        if (predictions_oldest_or_null) {
            assert(predictions_oldest_or_null[i] >= 0.0f &&
                   predictions_oldest_or_null[i] <= 1.0f);
        }
    }
    // ... update logic (see Step 2 implementation in v5.14.11.A)
}

// Convert running sums → correlation matrix.
// Shared by refactored BuildCorr AND online cycle.
// Cost: O(N²) at finalize time.
template <unsigned F>
inline void RidgeBlender_FinalizeCorrFromSums(double corr_out[MAX_RIDGE_MODELS][MAX_RIDGE_MODELS],
                                                const double sum_x[MAX_RIDGE_MODELS],
                                                const double sum_xx[MAX_RIDGE_MODELS][MAX_RIDGE_MODELS],
                                                uint64_t window_count,
                                                int n_models);
```

Replacement math (when window full):
```
delta_x_i = predictions_new[i] - predictions_oldest[i]
sum_x[i] += delta_x_i
sum_xx[i][j] += predictions_new[i] * predictions_new[j]
              - predictions_oldest[i] * predictions_oldest[j]
```

Finalize math (sum-of-squares form):
```
mean[i] = sum_x[i] / K
var[i]  = sum_xx[i][i] / K - mean[i]^2
cov[i][j] = sum_xx[i][j] / K - mean[i] * mean[j]
corr[i][j] = cov[i][j] / sqrt(var[i] * var[j])
```

Numerical-stability bound: predictions bounded to [0, 1] (typical sigmoid output) + K=64 → max(sum_xx) ≤ 64 → cancellation error ε × 64 ≈ 10^-14. PARITY 1e-9 contract: 5 orders of magnitude headroom.

### Step 3 — refactored BuildCorr using sum-of-squares + shared finalize

```cpp
// Refactored: single-pass sum-of-squares accumulation + call FinalizeCorrFromSums.
// Algebraically equivalent to v5.14.10's 3-pass form within ~1e-13 (different
// IEEE-754 operation order). PARITY contract reframed to tolerance 1e-9
// over the v5.14.10 → v5.14.11 boundary.
template <unsigned F>
inline void RidgeBlender_BuildCorr(double corr_out[MAX_RIDGE_MODELS][MAX_RIDGE_MODELS],
                                     const float* predictions_history,  // K × N flat
                                     int n_history,
                                     int n_models) {
    double sum_x[MAX_RIDGE_MODELS]    = {0};
    double sum_xx[MAX_RIDGE_MODELS][MAX_RIDGE_MODELS] = {{0}};

    // Single pass: accumulate sum_x[i] + sum_xx[i][j] in one walk.
    for (int k = 0; k < n_history; ++k) {
        for (int i = 0; i < n_models; ++i) {
            double xi = (double)predictions_history[k * n_models + i];
            sum_x[i] += xi;
            for (int j = 0; j < n_models; ++j) {
                double xj = (double)predictions_history[k * n_models + j];
                sum_xx[i][j] += xi * xj;
            }
        }
    }

    RidgeBlender_FinalizeCorrFromSums(corr_out, sum_x, sum_xx, n_history, n_models);
}
```

### Step 7 — Cholesky_Solve AVX-512 (D)

File: `ML_Headers/RidgeBlender.hpp:121-179`

Inner k-reductions vectorize cleanly:
```cpp
#if defined(__AVX512F__)
// Vector mul + scalar reduce preserves L-to-R order for byte-determinism
// per v5.11.7 discipline (DESIGN_SPECS/avx512-byte-determinism-pattern.md).
// j ≤ N=8, max 7 iterations → fits AVX-512 with mask.
__mmask8 mask = (__mmask8)((1u << j) - 1u);
__m512d li = _mm512_maskz_loadu_pd(mask, &L_out[i][0]);
__m512d lj = _mm512_maskz_loadu_pd(mask, &L_out[j][0]);
__m512d prod = _mm512_mul_pd(li, lj);
// Scalar reduce — L-to-R order matches scalar baseline bit-for-bit
double prod_arr[8];
_mm512_mask_storeu_pd(prod_arr, mask, prod);
double s = sigma[i][j];
for (int k = 0; k < j; ++k) s -= prod_arr[k];
#else
// Scalar fallback (current behavior; byte-determinism reference)
double s = sigma[i][j];
for (int k = 0; k < j; ++k) s -= L_out[i][k] * L_out[j][k];
#endif
```

**Partial-vectorization decision (per `avx512-byte-determinism-pattern.md` Rule 5; PARITY-019 RESOLVED):**

Applied to:
1. **Diagonal `L[i][i]` computation (inner k-loop)** — VECTORIZED. Row access `L_out[i][k]`; row-load template fits.
2. **Forward solve `L y = μ` (inner k-loop)** — VECTORIZED. Row access `L_out[i][k]`; same template.
3. **Back solve `L^T w = y` (inner k-loop)** — STAYS SCALAR. Column access `L_out[k][i]` (strided in row-major storage); row-load template doesn't apply. Alternatives considered + rejected:
   - L^T scratch during decomp: extra ~32 ops + 512B; net negative (decomp cost > ~1ns back-solve saving)
   - `_mm512_i64gather_pd`: ~10ns gather latency > ~7ns scalar serial chain for N=8
   - Column-major restructuring: invasive; doesn't justify <50ns gain

   Partial vectorization is canonical pattern application per Rule 5 (scalar fallback is the byte-determinism reference). Back-solve scalar path is bytewise-deterministic to itself + serves as reference for the 2 vectorized sites' SHA-256 lock tests.

Cost: ~150-200ns saving per Ridge cycle (2 vectorized sites; cfg=0 + cfg=1). Back-solve scalar overhead unchanged from v5.14.10.
