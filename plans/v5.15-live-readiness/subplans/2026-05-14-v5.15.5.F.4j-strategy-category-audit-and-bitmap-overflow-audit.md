## Why this sub-ship exists (decision rationale 2026-05-14)

Per `categorical-tag-applicability-pattern.md` Rule 4 ("Promoted from observed clustering, not invented"): category vocabulary must be GROUNDED in code reality. `.F.4b` shipped with **initial CORE + SPECIFIC categories** as placeholders; this sub-ship is the audit pass that validates + refines them.

Two structurally separate but parallel audits handled in one sub-ship for efficiency:

1. **Strategy categorical audit** — read every `Strategies/*.hpp`; identify which cfg fields each strategy reads; cluster shared capabilities into categories; populate `applies_to_strategy_cat` for all cfg rows.
2. **Bitmap overflow audit** — read every `FOREACH_*` registry paired with a bitmap field; verify static_assert overflow guard is present; add missing guards; flag near-overflow bitmaps for type-upgrade.

Both are audit-pass ships; both close structural classes (categorical vocabulary lock-in + silent-bitmap-truncation class). Convenient to combine.

```cpp
// Strategies/StrategyCategories.hpp — FINAL after .F.4h audit

#pragma once
#include <cstdint>

enum StrategyCategory : uint32_t {
    // ─── CORE tier (stable across major versions) ───
    STRAT_CAT_STATIC_RULES         = 1u << 0,   // SimpleDip, EmaCross
    STRAT_CAT_REGRESSION_DRIVEN    = 1u << 1,   // Momentum (uses ROR)
    STRAT_CAT_ML                   = 1u << 2,   // MLStrategy + variants
    STRAT_CAT_ONLINE_LEARNING      = 1u << 3,   // updates weights per-cycle (bandit + ridge)

    // ─── SPECIFIC tier (stable across minor versions) ───
    STRAT_CAT_USES_BANDIT          = 1u << 4,
    STRAT_CAT_USES_THOMPSON        = 1u << 5,   // requires USES_BANDIT
    STRAT_CAT_USES_RIDGE           = 1u << 6,
    STRAT_CAT_USES_CONFIDENCE      = 1u << 7,
    STRAT_CAT_LONG_ONLY            = 1u << 8,
    STRAT_CAT_LONG_AND_SHORT       = 1u << 9,
    STRAT_CAT_REGIME_AWARE         = 1u << 10,
    STRAT_CAT_USES_DEPTH_DATA      = 1u << 11,
    STRAT_CAT_USES_FLOW_DATA       = 1u << 12,
    // ... (audit-driven additions) ...

    // ─── EXPERIMENTAL tier (may be removed; aliased on removal) ───
    // (none initially; reserved bits 24-31 for future EXPERIMENTAL categories)

    STRAT_CAT_ALL                  = 0xFFFFFFFFu,
};

// Overflow guard (per bitmap-overflow-protection-discipline.md):
static_assert(STRAT_CAT_USES_FLOW_DATA < (1ull << 32),
              "StrategyCategory overflowed uint32_t — upgrade to uint64_t or split orthogonal axes");
```

Lock the bit assignments. **Reordering or removing existing bits = breaking change** requiring alias-on-rename pattern (per spec Rule 3).

## Step 6 — Bitmap-overflow audit pass across existing registries (~2 hr)

**Spawn third Explore agent** for the bitmap-overflow inventory:

> **Audit scope:** find every `FOREACH_<X>` macro in the codebase + identify its paired bitmap field. For each pair:
>
> 1. Compute current bit count via FOREACH_X walk (count entries)
> 2. Identify the bitmap field type (uint8_t / uint16_t / uint32_t / uint64_t)
> 3. Check if a `static_assert(FOREACH_X_COUNT_VALUE <= sizeof(X_flags_type) * 8)` exists in the same header
> 4. Report:
>    - REGISTRY: name, header path, entry count
>    - BITMAP: field name, type, current capacity
>    - GUARD: present / missing
>    - HEADROOM: bits remaining
>    - PRIORITY: HIGH (≤3 bits headroom) / MEDIUM (4-8 headroom) / LOW (>8 headroom)
>
> Output: structured table at `plans/plan_checks/2026-05-14-v5.15.5.F.4h-bitmap-audit.md`.
>
> Suspected bitmap pairs to start with (verify + extend):
> - FOREACH_ML_CFG_FLAG ↔ `ml_cfg_flags`
> - FOREACH_GATE_CFG_FLAG ↔ `gate_cfg_flags`
> - FOREACH_LIFECYCLE_CFG_FLAG ↔ `lifecycle_cfg_flags`
> - FOREACH_OPS_CFG_FLAG ↔ `ops_cfg_flags`
> - FOREACH_RISK_CFG_FLAG ↔ `risk_cfg_flags`
> - FOREACH_FAILURE_MODE ↔ `failure_flags` (BIT_FLAG storage-class entries only)
> - FOREACH_CORE_STATE_FLAG ↔ `core_state_flags`
> - FOREACH_PER_CORE_STATE_FLAG ↔ `per_core_state_flags`
> - FOREACH_OMS_STATE_FLAG ↔ `oms_state_flags`
> - FOREACH_EZOO_INIT_FLAG ↔ `ezoo_init_flags`
> - FOREACH_CFG_DRIFT_CHECK ↔ `drift_flags_at_load`
>
> Per `DESIGN_SPECS/bitmap-overflow-protection-discipline.md` — apply the pattern's detection signature.

After Explore agent returns the audit report:

1. **Add missing static_asserts** to each registry header lacking one (use the template from the spec)
2. **Upgrade type widths** for HIGH-priority bitmaps (≤3 bits headroom):
   - uint8_t → uint16_t (cheap; rarely affects cache layout)
   - uint16_t → uint32_t (verify cache impact for hot-path structs)
   - uint32_t → uint64_t (significant cache impact for hot-path structs; profile if hot)
3. **For each MEDIUM-priority bitmap, log a TECH_DEBT entry** noting expected upgrade trigger (e.g., "ml_cfg_flags has 4 bits headroom; upgrade to uint32_t when adding the 13th MASK_*")

// Test 1: no orphan strategy categories

    uint32_t declared_cats = 0;
    #define X_DECLARED(name, cats) declared_cats |= cats;
    FOREACH_STRATEGY(X_DECLARED)
    #undef X_DECLARED

    // Every defined STRAT_CAT_* (except _ALL) should be in declared_cats
    constexpr uint32_t all_defined = 
        STRAT_CAT_STATIC_RULES | STRAT_CAT_REGRESSION_DRIVEN |
        STRAT_CAT_ML | STRAT_CAT_ONLINE_LEARNING |
        STRAT_CAT_USES_BANDIT | STRAT_CAT_USES_THOMPSON |

        STRAT_CAT_REGIME_AWARE | STRAT_CAT_USES_DEPTH_DATA |
        STRAT_CAT_USES_FLOW_DATA;

    check("Test 1: no orphan strategy categories",
          (declared_cats & all_defined) == all_defined);
}

// Test 2: no orphan cfg fields (every row's applies_to_strategy_cat is non-zero)
{
    bool all_have_strategy_cat = true;
    #define X_CHECK_STRAT(kind, name, label, section, meta, payload, tooltip, \
                          strat, op_mode, regime, risk, requires_cfg, lives_in) \
        if ((strat) == 0) all_have_strategy_cat = false;
    FOREACH_CFG_FIELD(X_CHECK_STRAT)
    #undef X_CHECK_STRAT

    check("Test 2: every cfg field has non-zero applies_to_strategy_cat",
          all_have_strategy_cat);
}

// Test 3: strategy capability self-consistency
{
    bool consistent = true;
    #define X_CONSISTENCY(name, cats) \
        if ((cats) & STRAT_CAT_USES_THOMPSON) { \
            if (!((cats) & STRAT_CAT_USES_BANDIT)) consistent = false; \

        } \
        if ((cats) & STRAT_CAT_ONLINE_LEARNING) { \
            if (!((cats) & STRAT_CAT_ML)) consistent = false; \
        }
    FOREACH_STRATEGY(X_CONSISTENCY)
    #undef X_CONSISTENCY

    check("Test 3: strategy capability dependencies hold", consistent);
}

## Anti-patterns to avoid

- **Don't invent categories without audit data.** Every category must trace to 3+ instances declaring it (per categorical-tag-applicability-pattern.md Rule 4). The Explore agent's findings drive vocabulary; resist adding "STRAT_CAT_FOO_USED_IN_VERSION_X" because a single edge case appeared.
- **Don't rename existing categories without alias.** Categories shipped at `.F.4b` are now consumer-referenced. Rename = alias-on-rename pattern (per Rule 3); cite the alias in the spec.
- **Don't skip the bitmap-overflow audit "because the asserts are simple".** Simple-but-missing is exactly the silent-truncation bug class. Audit pass is non-optional.
- **Don't fold categorical filtering into parser semantics.** Parser writes cfg fields regardless of applicability mask; filter is GUI-only. Breaking this rule = engine behavior depends on category metadata = bug class returns.
- **Don't conflate strategy categorical with op_mode categorical.** Two separate domains; each cfg field declares both independently.

## If something goes wrong

- **Audit agent finds 30+ proposed categories:** scope creep. Triage by tier — keep CORE (≤8) + SPECIFIC (≤16); defer remaining as EXPERIMENTAL or merge similar ones. Vocabulary discipline > completeness.
- **CI Test 2 (orphan cfg fields) fails:** some cfg row has `applies_to_strategy_cat == 0`. Fix by setting `STRAT_CAT_ALL` if truly universal OR refining to a specific category.
- **CI Test 3 (consistency) fails:** a strategy declares `USES_THOMPSON` without `USES_BANDIT`. Add the missing parent category to the strategy's mask (per Rule 7 anti-pattern: explicit redundant declarations).
- **Bitmap-overflow audit finds existing static_assert with WRONG bound:** verify the FOREACH_X_COUNT_VALUE is correctly defined; fix the count macro before fixing the assert.
- **Rollback:** `git reset --hard pre-v5.15.5.F.4h` (anchor at Step 0).
