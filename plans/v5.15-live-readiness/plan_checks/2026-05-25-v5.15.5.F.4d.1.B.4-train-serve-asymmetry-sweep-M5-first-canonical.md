### PARITY-031 — Per-core regime collapse at backtest feature collect

**Verification:**
- `Backtest/BacktestSharded.hpp:541` — `RegimeState<BACKTEST_FP> regime_state;` (SINGLE state, not array)
- `Backtest/BacktestSharded.hpp:548` — `Regime_Init(&fc_ctx.regime_state, (int)cfg.regime_hysteresis);` — uses GLOBAL `cfg.regime_hysteresis` not per-core
- `Backtest/BacktestSharded.hpp:607` — `Regime_Classify(&fc->regime_state, &sig, fc->cfg);` (single state writer)
- `Backtest/BacktestSharded.hpp:612` — `ctx.current_regime = fc->regime_state.current_regime;` (single state reader; N→1 collapse)
- Live-side `CoreFrameworks/EngineSharded.hpp:3194` — `state.cores[c].regime_state.current_regime` (per-core)

**Verdict:** **OPEN-PENDING `.B.4`** — finding REPRODUCED.

**Structural-extract impact at `.B.4`:** Per plan body Pre-coding Concern #6, `fc_ctx.regime_state` becomes `[MAX_EXECUTION_CORES]` array; ~30 LOC backtest-side wiring (not in helper itself; the FeatureCollectCtx + on_slow_path lambda live in BacktestSharded.hpp). **This is the only finding NOT closed by helper-extract alone — it requires structural array-ification of `fc_ctx.regime_state` in addition to helper migration.**

**Pre-coding concern (NEW for plan body Phase B):** Backtest collects features in the on_slow_path lambda which iterates by tick (not by core). To populate per-core `regime_state[c]`, the lambda needs to identify WHICH core's regime to update per slow-path firing — currently `ShardedBacktest_RunTick` fires the lambda once per slow-path cycle (not per-core). Two options:
- **Option A (plan body current):** array-ify `fc_ctx.regime_state[MAX_EXECUTION_CORES]`; lambda loops cores internally per cycle. Adds N×Regime_Classify calls per slow-path firing.
- **Option B (alternative — NOVEL):** call `EngineCommon_SlowPathCycleOneCore` which calls `Regime_Classify` per-core for live (already inside RebuildOneCore at live side); backtest's on_slow_path lambda then READS `state.cores[c].regime_state.current_regime` directly. Removes duplicate classification; trusts the shared helper to populate. **This is the CORRECT closure** — the gap exists BECAUSE backtest uses `EventLoop_RebuildAllParameters_PerCore` (centralized AllCores walk) which populates `state.cores[c].regime_state.current_regime` per-core SAME AS live — but the lambda then OVERRIDES with its OWN `fc_ctx.regime_state` rather than reading per-core. Closing it = delete `fc_ctx.regime_state`; read from `state.cores[c].regime_state[c]` directly.

**Amend plan body Pre-coding Concern #6:** Prefer Option B (delete fc_ctx.regime_state; read state.cores[c].regime_state per-core in lambda). Closes PARITY-031 BY-CONSTRUCTION via existing live-side per-core population. ~10 LOC delete + ~5 LOC read change (not ~30 LOC array wiring).
