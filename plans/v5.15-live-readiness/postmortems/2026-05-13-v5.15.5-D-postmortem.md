## Pattern B captured for future codification

**Pattern:** "Fast-path companion accessor for canonical runtime parameter" — when a public API accepts a runtime parameter `k` (or similar) that's almost always one canonical value at the production caller, expose a `_Fast` companion accessor that returns the cached/derived result for the canonical value (no runtime branch); keep the general API for non-canonical callers (e.g., tests with k=2).

**First application:** `BookImbHistory_MeanShortFast(s)` (this ship) vs `BookImbHistory_MeanShort(s, int k)` (existing API).

**Promotion trigger:** 2nd application of this pattern surfaces. At that point, codify via the pattern-codification-lifecycle.md 7-stage process. Until then, the pattern lives in v5.15.5.D's commit/postmortem context.

## Lessons learned

### "Marginal" framings are effort-avoidance

Pre-coding consult included an option-comparison where I dismissed the 56 B / core padding overhead as "marginal" and the layout-puzzle as "not worth the complexity." Operator pushback ("whenever I push back we later find something that would need this so why not?") triggered a rigorous re-analysis. The rigorous answer turned out to confirm 56 B is structural minimum — but the dismissive framing was the issue, not the conclusion.

**Going forward:** when an option is dismissed with "marginal" or "not worth", surface the explicit math instead. The conclusion may still be the same, but the operator-trust + future re-derivation cost are different.

### offsetof on multi-arg template types needs typedef

`offsetof(BookImbalanceHistory<64, 1024>, sum)` fails because the preprocessor sees the comma in `<64, 1024>` as splitting macro args. Fix: typedef the template instantiation first (`using BookImbHistDefaultT = BookImbalanceHistory<64, 1024>;`). Reserved identifier rule: avoid leading underscore + capital (`_BookImbHistDefault` is reserved by the C++ standard; use `BookImbHistDefaultT` form instead).

Pattern: any layout lock on multi-arg template instantiation gets a typedef alias.

### `<cstddef>` should be explicit for offsetof

GCC transitively includes offsetof through other headers, but clangd (LSP) doesn't. Explicit `#include <cstddef>` standardizes behavior across both. Cost is essentially zero; benefit is clean LSP diagnostics + portability across STL implementations.
