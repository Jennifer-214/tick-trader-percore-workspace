## Design space + future-oriented choices

### Decision A — Subfolder pattern (settled at umbrella)

Per umbrella sub-master Decision A: subfolder named after original + top-level shim. **CHOSEN.**

### Decision B — Lambda hoisting vs lambda-in-place

Each lambda inside `EngineSharded_Run` has two extraction options:

| Option | Description | Trade-off |
|---|---|---|
| **(a) Hoist to named function** | Each lambda becomes a `template<unsigned F> void EngineSharded_Async_FanOut(...)` (or similar) in `Async.hpp`; called from `_Run` body | Captures become args (~5-15 args per fn); proven pattern via .B.4 EngineCommon |
| (b) Keep inline lambda in Run.hpp | All lambdas stay inside `_Run` body; sub-files mostly empty (placeholder) | NOT a real split; defeats the purpose |
| (c) Hoist to template lambda variables in sub-file | `auto fan_out = [...](){...};` at namespace scope in sub-file | Lambda captures = empty; all state passed by reference args; valid but unusual style |

**CHOSEN: (a) Hoist to named template functions.** Proven pattern at .B.4 EngineCommon extract (M5 first canonical). Cost: each lambda's captures (~5-15 references) become explicit function args. Sister to `EngineCommon_BootPerCore` + `EngineCommon_SlowPathCycleOneCore` shape.

**Lambda count verified at audit (2026-05-27 trace-deps):** 5 lambdas + 1 capture-free inline helper:

| Lambda | Captures | Estimated args | Target sub-file |
|---|---|---|---|
| `fan_out` (line 1303) | 21 by-ref + 4 by-value = **25** | ~12-14 (refs become `&arg` params) | Async.hpp |
| `copy_file` (line 1757; capture-free) | 0 | 2 | Async.hpp (or stays inline in fan_out body) |
| `drain_with_submit` (line 1970) | 4 by-ref | 4-5 | Async.hpp |
| `drain_post_fill` (line 2126) | 3 by-ref | 3-4 | SlowPath.hpp |
| `drain_manual_closes` LIVE (line 2155) | 5 by-ref+ptr | 5-6 | SlowPath.hpp |
| `drain_manual_closes` NO-OP (line 2221) | 0 (one-liner `[](){}`) | 0 | SlowPath.hpp (merged with LIVE per Decision H) |

`fan_out` is the largest at 25 captures — accepted as-is per operator directive ("we arent targeting exact numbers, just as long as this gets done and is more maintainable"). If Phase A.2 CSV enumeration finds natural seams inside fan_out body, sub-functions are acceptable but not required.

**BENCH template parameter scope (NEW 2026-05-27 PM per dod-audit finding):** Each hoisted helper function is declared `template<unsigned F> void EngineSharded_Async_<name>(...)` WITHOUT the `BENCH` parameter that the parent `EngineSharded_Run<F, BENCH>` carries. This is CORRECT because all Live/Backtest dispatch inside the lambdas is driven by `cfg.lifecycle_cfg_flags` BITMAP checks, NOT the BENCH template parameter. Phase A.2 CSV must verify for each lambda that BENCH is not referenced inside its body (spot-check the 5 largest at minimum).

### Decision C — Static globals placement (AMENDED 2026-05-27 PM per 3-agent audit convergent finding — CRITICAL)

Four file-static globals exist:
- `g_engine_sharded_shutdown` (currently `static volatile sig_atomic_t`; line 107)
- `g_sharded_order_lat` (currently `static ShardedOrderLatency`; line 119)
- `g_engine_sharded_gui_quit_ptr` (currently `static volatile sig_atomic_t*`; line 128)
- `g_engine_drainer_cycle_hist` (currently `inline LatencyHistogram`; line 377 — already correct)

**CRITICAL FINDING (3-agent + bug-check + trace-deps convergent):** Current `static` keyword on header-only globals would give EACH TU its own private copy when sub-files are header-only. Result: signal handler + drainer + producer thread + main would see DIFFERENT instances of `g_engine_sharded_shutdown` → silent shared-state corruption.

**Decision (AMENDED):** ALL 4 globals declared as C++17 `inline` variables (NOT `static`). C++17 inline-variable semantics = single shared storage across all TUs that include the header within the same program. Line 377's existing `inline LatencyHistogram g_engine_drainer_cycle_hist{};` IS the proven precedent — extend to all 4.

**Post-split shape:**
```cpp
// Boot.hpp
inline volatile std::sig_atomic_t g_engine_sharded_shutdown = 0;
inline volatile sig_atomic_t* g_engine_sharded_gui_quit_ptr = nullptr;

// Run.hpp
inline ShardedOrderLatency g_sharded_order_lat;

// Async.hpp
inline LatencyHistogram g_engine_drainer_cycle_hist{};   // already inline at line 377
```

**Why `inline` not `extern + define-once`:**
- All sub-files are `.hpp` headers (NO `.cpp` definitions); the `extern` + define-once pattern works for `.cpp` modules but BREAKS for header-only code
- C++17 `inline` variable: single canonical storage across all TUs by language standard; clean ODR by construction
- No designation of "primary sub-file" needed; each global lives in its semantic sub-file
- Sister discipline to test_common.hpp `inline int tests_failed = 0;` established at .B.5 WIP-B1 (2 canonical applications → Stage 3 first canonical of NEW DESIGN_SPEC `cpp17-inline-variable-for-header-shared-state.md` at ship close)

**FUTURE-MAINTAINER WARNING:** If anyone later refactors any of these back to `static` (e.g., "to match other files") — they will SILENTLY break shared-state correctness. Cross-thread access requires single instance; `static` in header gives per-TU instances. NEW DESIGN_SPEC codifies the discipline at ship close.

### Decision D — Include order in shim

The shim's `#include` order determines compilation order. Required order:
1. `Boot.hpp` first (globals + signal handler context referenced by others)
2. `Async.hpp` second (drainer + producer threads; called from Run)
3. `SlowPath.hpp` third (per-core slow-path body; called from Run)
4. `Run.hpp` last (the orchestrator; uses everything above)

Verification at Phase A: ensure NO sub-file references symbols from later sub-files in shim order. /trace-deps audit catches this.

### Decision G — SH_* color macro discipline (NEW 2026-05-27 PM per dod-audit finding)

`DumpLatency` template (lines 295-321) is wrapped by 9 `#define SH_*` color macros (lines ~2746) + 9 matching `#undef` (lines ~2954). The macros are locally scoped — defined-used-undefined within a single function's scope.

**Decision:** `DumpLatency` template + its 9 SH_\* macros + matching `#undef` form an **atomic extraction unit** that moves to `Run.hpp`. Do NOT hoist SH_\* macros to the shim or split them across sub-files — they're self-contained terminal-color formatting helpers used only by DumpLatency.

### Decision H — `drain_manual_closes` GUI vs NO-OP variant merge — RESTORED (operator clarification 2026-05-27 PM)

Operator clarified rework discipline: "reworking is fine, assuming it doesnt break anything, and allows for better maintainability going forward per design philosophy."

Current code (lines 2155-2221) has TWO variants of `drain_manual_closes` differing only by `#ifdef USE_IMGUI_GUI` gate:
- LIVE variant (line 2155): Full 68-line slot-walker with partial-exit logic + OMS_PushExitForSlot + bitmap operations
- NO-OP variant (line 2221): One-liner `[]() {}`

**Decision:** At Phase B Step B.4 (SlowPath.hpp creation), MERGE the two variants into a SINGLE hoisted GLOBAL helper `EngineSharded_SlowPath_DrainManualCloses<F>(...)` with the `#ifdef USE_IMGUI_GUI` gate moved INSIDE the function body. The merged function is GLOBAL in dispatch shape (called once per drainer cycle; walks all cores internally via bitmap) — matches sister `EngineCommon_SlowPathCycleAllCores` cohort from .B.4.

**Signature shape:**
```cpp
template<unsigned F>
void EngineSharded_SlowPath_DrainManualCloses(
    EventLoopState<F>& state,            // contains state.cores[N] (iterated internally)
    OrderManagerState<F>& oms,
    const ControllerConfig<F>& cfg,
    std::atomic<double>& last_price,
    TUISharedState* shared_ptr           // nullable; #ifdef USE_IMGUI_GUI gates body usage
) {
#ifdef USE_IMGUI_GUI
    // walks state.cores[c] for all c via bitmap iteration
    // 68 lines of slot-walker + partial-exit + OMS_PushExitForSlot
#endif
    // implicit no-op under non-GUI build (function body empty after preprocessor elision)
}
```

**Why merge fits design philosophy:**
- Single source of truth (1 function definition vs 2 `#ifdef`-gated bodies)
- Consistent with `.B.4` EngineCommon dual-cfg pattern (`BootPerCore` already conditionalizes cfg-flag inside body)
- Easier grep + future modification (touch one place instead of two)
- Future-extensible (if a 3rd build mode added later, pattern extends naturally)
- Sister to `EngineCommon_SlowPathCycleAllCores` GLOBAL-dispatch shape (called once per cycle; walks cores internally)

**Cost:** ~30 min careful extraction (captures → args; preserve `#ifdef` placement inside function body). Refactor risk LOW (mechanical pattern; proven at `.B.4`; build catches mistakes immediately).

### R1 — Lambda hoisting captures incomplete (silent runtime bug)

**Mitigation:**
- Per `feedback_enumerate_helper_signature_args_before_extract` (M6 discipline): enumerate EVERY capture for EACH lambda BEFORE writing the hoisted function signature; save as Phase A.2 CSV; operator review before Phase B
- Build catches missing args (compile error if hoisted function references undeclared name)
- TSan + ASan catch any runtime aliasing issues with reference args

### R2 — Forward-decl ordering breaks compile

**Mitigation:**
- Shim include order strict: Boot → Async → SlowPath → Run
- `/trace-deps` audit at Phase A catches symbol-not-yet-declared references
- Each Phase B sub-step builds incrementally (catch order issues per-file, not at final integration)

### R3 — Template instantiation point shifts → silent behavior change

**Mitigation:**
- All sub-files header-only with `inline` / `template<>` discipline preserved
- ODR via `#pragma once` + `inline` keyword on free functions
- `/dod-audit` Phase A catches missing `inline` markers

### R4 — Static global duplication (multiple definitions)

**Mitigation:**
- Decision C: each global defined ONCE in primary sub-file
- Other sub-files use `extern` decl + linker resolves
- Alternative: C++17 `inline` variable for shared globals (avoids extern dance)
- Build catches duplicate definitions immediately

### R5 — Hot path timing change from sub-file boundaries

**Mitigation:**
- `tools/calls_graph_diff.sh verify` at Phase C confirms hot path symbol locations unchanged
- HOT path code (BG_Evaluate / SG_Evaluate / ExecutionCore_Tick) lives in `ExecutionCore.hpp` + `Strategies/`, NOT in EngineSharded.hpp; not touched by this ship
- Slow-path-cycle body is moved but compile-unit-as-header preserves inline (same as pre-split)

### R6 — First-canonical pattern risk

**Mitigation:**
- Phase D viability gate before `.B.7` planning unlocks
- Plan body documents pattern shape; if amendments needed, codify in file-size-split-discipline.md v1.1 BEFORE `.B.7-.B.10` apply

### R7 — calls_graph_diff.sh might not exist OR be stale

**Mitigation:**
- Verify tool exists + functional at Phase A (read-only check)
- If missing, generate via `tools/gen_calls_graph.sh` (if exists) OR document workaround at Phase C verification
