## Why this subplan exists

Audit gate for `.F.4c.3` (2026-05-15) caught a CRITICAL scope error in the parent plan: I'd assumed `symbol` lived on `ControllerConfig<F>`, but the field is actually on `BinanceConfig` (`DataStream/BinanceCrypto.hpp:64`) + `BacktestCfg`. Plus the per-core registry needs `KIND_STRING` infrastructure that doesn't ship until `.F.4e`. The parent plan defers symbol axis migration to this follow-up subplan.

Operator intent (Caramel 2026-05-15):
> *"I'm willing to defer changing symbol until later, since this is free tick level data, and most tick data will be the same so its not that important tbh, later on it should be per-core"*

The architectural direction is locked (symbol becomes per-core). The implementation waits for KIND_STRING infrastructure + the multi-symbol DataStream readiness.

---

## Scope (to be locked at audit gate of THIS subplan, AFTER `.F.4e` lands)

1. **Migrate `symbol` from `BinanceConfig` / `BacktestCfg` to `PerCoreCfg<F>`** (per-core authoritative). Add as a KIND_STRING row in `FOREACH_PER_CORE_CFG_FIELD`.
2. **Boot-time uniformity enforcement** until multi-symbol DataStream support ships: all active cores must share the same `symbol`. Boot fails with clear error if cores have mismatched symbols. Operator gets a single uniform symbol per engine; the cfg surface is per-core-ready when DataStream is.
3. **DataStream constraint** preserved: producer thread still subscribes to ONE Binance WS feed; the per-core symbol cfg is operator-facing future-proofing.
4. **UI design** for symbol entry — OPEN; pick one at audit:
   - **(a) Per-core CAPS text-entry**: operator types `BTCUSDT` in `[core 0].symbol=` line. Simple, flexible, allows any operator-typed string. Risk: typos that silently mis-subscribe to a non-existent ticker.
   - **(b) Dropdown of validated Binance trading pairs**: GUI fetches from Binance `/api/v3/exchangeInfo` endpoint at boot; Settings panel renders a dropdown; cfg file stores the selected symbol string. Prevents typos. Operator UX cleaner.
   - Recommendation: **(b)** when fully wired (requires periodic refresh of supported-symbols list + cache). **(a)** as fallback when DataStream is offline / `/exchangeInfo` unavailable.

5. **Migration of `BinanceConfig.symbol` consumers** at:
   - `DataStream/BinanceCrypto.hpp:64` (declaration)
   - `EngineSharded.hpp:560/589/714/...` (~10 sites consuming `cfg.symbol` indirectly via BinanceConfig)
   - Backtest path: `BacktestCfg.symbol` similarly migrates
   - **Per-symbol consumer function signature discipline (NEW, inherited from `.F.4c.3` cfg-scope-discipline § "Consumer function signatures"):** any new per-symbol consumer fn (e.g., `PerSymbol_BuildIngestPipeline`) takes `const PerSymbolCfg<F>* symbol_cfg` single-param; per-symbol reads go through `symbol_cfg->X`. Genuinely-global reads stay caller-resolved as scalar args. Class 25 (Scope-erosion in per-core consumer) generalizes to per-symbol consumers — same anti-pattern shape, same structural prevention.

6. **Stamp body**: per-core stamp's `symbol` field now sourced from `cfg.cores[c].symbol` (was global). Layer 5b hash recomputed.

7. **Cfg.example update**: new operator-facing example shows `symbol` inside `[core N]` sections, not at global top.

8. **Test fixture migration**: ~4 sites in `tests/controller_test.cpp` reference symbol cfg; mechanical update.
