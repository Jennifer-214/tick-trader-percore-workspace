## Implementation plan

### Step 0 — Audit overlay concept feasibility

```bash
# Check if any "overlay" / "patch" / "override" pattern exists in
# feature registry already
grep -rn "overlay\|feature_override\|patch_features" \
    ML_Headers/ Backtest/ 2>/dev/null
```

If overlay pattern partially exists → align with it. If absent →
truly new (we'll define the sidecar format here).

### Step 1 — Define overlay-patch sidecar format

File: `tools/feature_overlay.py` (NEW, Python trainer side)

Sidecar format (`<model>.overlay.json`):
```json
{
  "version": 1,
  "base_registry_hash": "0x<hex>",
  "overlays": [
    {"feature_name": "ror_slope", "lookback_override": 256},
    {"feature_name": "vwap_dev", "disabled": true}
  ]
}
```

Trainer computes:
- Layer-1 = base FEATURE_REGISTRY_HASH (existing)
- Layer-2 = SHA256(canonicalized overlay JSON)
- Layer-3 = SHA256(layer1 || layer2)

Writes all three to stamp body.

### Step 2 — C++ side: load + verify overlay sidecar

File: `ML_Headers/FeatureRegistryOverlay.hpp` (NEW)

```cpp
struct FeatureOverlay {
    char overlay_path[256];
    char layer2_hash_hex[65];   // SHA256 → 64 hex chars + null
    char layer3_hash_hex[65];
    int  num_overlays;
    int  loaded;                 // 0 = no overlay (stamp's
                                  //     has_overlay_hash=0 path)
};

inline int FeatureOverlay_Load(FeatureOverlay* fo,
                                const char* path);
inline int FeatureOverlay_VerifyAgainstStamp(
    const FeatureOverlay* fo,
    const char* stamp_overlay_hash,
    const char* stamp_effective_hash,
    int strict_mode);  // 0=warn, 1=refuse
```

### Step 3 — Stamp body extensions (Surface G)

Two new fields in stamp body emit + verify:
- `has_overlay_hash` (uint8_t) + `overlay_hash[65]` (char)
- `has_effective_hash` (uint8_t) + `effective_hash[65]` (char)

Legacy stamps: both `has_*` = 0 → loader skips overlay check
entirely (single-layer FEATURE_REGISTRY_HASH check is sole
protection, as today).

### Step 4 — Boot-time loader integration

File: `CoreFrameworks/EngineSharded.hpp` (boot ML model load)

After `verify_model_stamp` succeeds, additionally:
- If `stamp.has_overlay_hash`: try to load `<model>.overlay.json`
  sidecar; compute layer-2 + layer-3; compare; WARN/REFUSE per
  cfg `held_out_gate_strict`
- If sidecar missing but stamp claims overlay → CRITICAL log; treat
  as REFUSE under strict mode (consistent with scaler sidecar v5.9.3a)

### Step 5 — Cfg field

```cpp
// v5.14.3 — overlay drift policy reuses existing
// cfg.held_out_gate_strict (no new flag needed)
// EXTENDS the strict-mode contract to overlay sidecar verification
```

### Step 6 — Tests

- Layer-2 hash stability: same overlay JSON (different field order) →
  same SHA256 (canonicalization works)
- Layer-3 = SHA256(layer1 || layer2) verified
- Stamp body round-trip: write all three hashes → parse → bytewise
  equal
- Loader: stamp has overlay hash + matching sidecar → PASS
- Loader: stamp has overlay hash + missing sidecar + strict=1 →
  REFUSE; strict=0 → WARN
- Loader: stamp has overlay hash + sidecar exists but layer-2
  mismatch + strict=1 → REFUSE; strict=0 → WARN
- Legacy stamp (has_overlay_hash=0) loads cleanly with overlay
  check skipped
