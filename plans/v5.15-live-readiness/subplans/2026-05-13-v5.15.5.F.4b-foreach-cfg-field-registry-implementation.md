## Step 2 — Add tt:: dispatch namespace + KIND_DOUBLE/_PCT specializations (~150 LOC)

**File:** `CoreFrameworks/CfgFieldDispatch.hpp` (NEW; sister to CfgFieldRegistry.hpp)

Contents:
```cpp
namespace tt {
    // Parser (text → cfg field)
    template <CfgFieldDescriptor::Kind K>
    inline void cfg_parse_field(Cfg* dst, const CfgFieldDescriptor& desc, const char* val);

    template <> inline void cfg_parse_field<CfgFieldDescriptor::KIND_DOUBLE>(
        Cfg* dst, const CfgFieldDescriptor& desc, const char* val);
    template <> inline void cfg_parse_field<CfgFieldDescriptor::KIND_DOUBLE_PCT>(
        Cfg* dst, const CfgFieldDescriptor& desc, const char* val);

    // Save (cfg field → text)
    template <CfgFieldDescriptor::Kind K>
    inline void cfg_save_field(FILE* fp, const Cfg* src, const CfgFieldDescriptor& desc);

    template <> inline void cfg_save_field<CfgFieldDescriptor::KIND_DOUBLE>(...);
    template <> inline void cfg_save_field<CfgFieldDescriptor::KIND_DOUBLE_PCT>(...);

    // Render (Dear ImGui)
    template <CfgFieldDescriptor::Kind K>
    inline bool cfg_render_field(double* val, const CfgFieldDescriptor& desc);
}

// Field offset table (compile-time):
inline size_t cfg_field_offset(const char* name) { /* lookup via string compare or constexpr map */ }
```

**Critical implementation detail — field offset access:**
The dispatch needs to write to `cfg->X` given a name string. Three options:

- **Option A (offsetof + reinterpret_cast):** generate `cfg_field_offset_table[]` at compile time via X-macro: `X(_, name, ...) { #name, offsetof(Cfg, name) },`. Parser does `*reinterpret_cast<double*>((char*)cfg + offset) = v;`. Cleanest; ~5 ns per access.
- **Option B (member pointers):** generate `double Cfg::* member_ptr` table per field. Requires per-Kind table; more boilerplate but type-safe.
- **Option C (if-else chain on name strcmp):** parser body does `if (strcmp(name, "X") == 0) cfg->X = v;`. Defeats the pattern (manual list); reject.

**Recommendation:** Option A. Document caveat: assumes Cfg field is at a POD-compatible offset (no virtual inheritance, no vtable). Already true (Cfg is plain struct).

## Anti-patterns to avoid

- **Don't migrate all 213 fields at once.** Sub-ship .F.4b is DOUBLE only; .F.4c is INT/INT_ENUM/BOOL; .F.4d is STRING. Stagger to keep PRs reviewable.
- **Don't delete the manual parser for unmigrated fields.** Keep the manual remainder until ALL kinds covered.
- **Don't optimize the descriptor lookup yet.** A flat array search is fine for ~250 entries; promote to perfect hash only if profiling shows it matters.
- **Don't add CI script yet.** Until ALL fields migrated, parser has both registry + manual paths; CI script would false-flag. Add at .F.4d-or-later when manual paths gone.
- **Don't add new cfg fields during this migration.** Adding fields + migrating same time = harder bisect. Migrate first, then add new.

---

## If something goes wrong

- **Build fails on `static_assert(sizeof(CfgFieldDescriptor) <= 64)`:** the union grew too large. Drop the `clamp_min` / `clamp_max` from `as_double` (move to separate sparse table indexed by FIELD_IDX) OR pack more aggressively (use uint16_t indices into string table).
- **Backtest determinism breaks:** registry's parse path uses different defaults than manual parser. Audit each migrated field's default value vs original.
- **CGui field offsets are wrong:** `offsetof()` returns the WRONG offset if Cfg has inheritance / virtual members. Verify Cfg is plain struct (no inheritance).
- **Macro expansion errors:** the X-macro tuple-arity must match across all consumer macros. Check that every consumer macro takes exactly 7 args (`kind_token, name, label, section, meta, payload, tooltip`).
- **Rollback:** `git reset --hard pre-v5.15.5.F.4b` (anchor created at Step 0).
