## TL;DR (executive summary)

This is the BOUNDARY ship. Engine becomes headless service; viewers become separate binaries; per-node configs become first-class filesystem layout; ML training moves to CLI; documentation push lands all operator-facing docs.

**Six major axes:**

1. **Engine binary stripped of GUI.** Dear ImGui code archived to `legacy/engine_gui/`. fox-engine binary becomes the headless service; no GUI dependency.

2. **State publication via mmap'd shared memory.** Engine writes state to shared memory region per state-publish protocol. Multiple concurrent read-only viewers attach.

3. **Command channel via Unix domain socket.** fox-cli verbs send commands; engine validates + applies (with safety constraints; e.g., no strategy change while positions open).

4. **Per-node config files first-class.** `configs/clusters/<exchange>/{cluster.cfg, credentials/, nodes/node_<id>/{core,strategy,ml,observability}.cfg, notes.md}`. Hot-reload via SIGUSR1 (Layer 1 of hot-reload discipline).

5. **fox-tui + fox-cli + foxml-train.** 3 NEW binaries. fox-tui = notcurses-based viewer; fox-cli = control commands; foxml-train = CLI ML training tool (replaces foxml_suite GUI).

6. **Documentation push.** DESIGN_PHILOSOPHY.md amended (D-46); CLAUDE.md updated; NEW: DEPLOYMENT_GUIDE.md + OPERATOR_MANUAL.md + ARCHITECTURE_OVERVIEW.md + GLOSSARY.md + INCIDENT_RUNBOOK.md + STRATEGY_LIFECYCLE.md + DR_TESTING.md + CONTRIBUTING/ (subdir; per-task guides). Substantial operator-facing documentation.

**Plus infrastructure additions:**
- Prometheus /metrics localhost-only endpoint (Grafana scrape via SSH-tunnel)
- systemd unit template (deployment-agnostic; production install via copy)
- Crash recovery via mmap state file + on_crash_restart_action policy (per D-47)
- Audit log structure (JSONL + optional SHA-256 chain; categorized files)
- Boot-time preflight check (extends LiveReadiness_Verify v5.15.2)
- Engine time sync (Binance /time drift detection)
- Webhook alerts framework (Slack/Discord/email integration)
- Hot-reload Layer 1 (config reload via SIGUSR1; slow→hot seqlock parameters)

**Hot path UNTOUCHED.** Trading flow is unchanged from `.E.1`. This ship is about external boundaries (engine→operator surface).

**No backwards compat for cfg format.** Migration tool (`fox-migrate-cfg`) provided one-shot at deployment; operator runs once. Old engine.cfg won't parse with new engine.

Per D-46 (Documentation deliverables comprehensive). Operator-facing surface excellence; future-Caramel + hedge-fund-visibility audience need comprehensive docs.

This ship is the boundary where the engine becomes proper infrastructure. Without it, the multi-exchange + sub-accounts work from `.E.1` is operationally clunky.

## Architecture deep-dive

### Headless engine boundary

```
fox-engine binary (systemd service; runs 24/7):
  - All trading flow (from .E.1: per-node hot + slow; per-cluster shared resources; aggregator)
  - All exchange adapters
  - All account state
  - mmap state-publish to /dev/shm/fox-engine-state OR /var/lib/fox/state/state.mmap
  - UDS command channel at /var/run/fox/engine.sock (production) OR ~/.local/share/fox/engine.sock (dev)
  - Prometheus /metrics endpoint at 127.0.0.1:9091 (localhost-only)
  - Audit log writers to /var/lib/fox/audit/ OR ~/.local/share/fox/audit/
  - Webhook alerts emitter (cfg-driven URL list)
  - NO GUI dependency (engine_gui code archived to legacy/)
  - NO foxml_suite dependency (replaced by foxml-train CLI)

fox-tui binary (operator-attached when needed):
  - notcurses-based TUI
  - Reads mmap state-publish (lock-free; seqlock for consistency)
  - Multiple concurrent fox-tui instances OK (read-only)
  - vi-style keybindings (h/j/k/l + colon commands; operator-customizable)
  - Display: global dashboard + per-cluster panels + per-node panels
  - No engine modification capability (read-only)
  - Detaches cleanly (SIGINT; engine continues)

fox-cli binary (operator-attached when needed):
  - Connects to UDS command channel
  - Sends commands per verb set
  - Validates before send (e.g., refuses strategy-change-with-open-positions)
  - Returns engine's response
  - Suitable for scripting (idempotent; exit codes)
  - ⚠️ **OPEN — D-241: does the verb set include a manual exit-adjust (TP/SL) verb?** The GUI-drag adjustable TP/SL is hard-deprecated with the GUI (D-26) + is ALREADY inert on the sharded path (TD-184 — drag writes the display level `pos->take_profit_price`, not the hot-gate `core->live_tp`/`live_sl`). So in the decoupled world it's a verb-or-nothing choice: **(A)** drop it — TP/SL fully engine-managed, NO exit-adjust verb (matches autonomous-shard direction); **(B)** keep it as a `fox-cli adjust-exit` verb whose engine-side application IS the TD-184 wiring (`core->live_tp`/`live_sl` on the per-node exit path + ratchet re-anchor), under this channel's validate-before-apply safety model + reconciled with TD-189's live-multiplier storage convergence. **Decide before locking the D-52 verb set.** → decision-log D-241; TD-184 (.E.1 in-process fix is the same wiring, command-triggered).

foxml-train binary (operator-attached when training models):
  - CLI tool for ML training pipeline
  - Reads training config (configs/training/<name>.training.cfg)
  - Runs feature compute + label compute + split + train + stamp
  - Outputs model to models/<run_id>/
  - Independent of engine (doesn't connect to UDS or mmap)
  - Suitable for cron / CI / scripted training
```

### mmap state-publish protocol

```cpp
// CoreFrameworks/StatePublish.hpp (NEW)

// State-publish region layout (mmap'd; size = ~1 MB; cache-line aligned)
struct alignas(64) StatePublishRegion {
    // === HEADER (versioning + meta) ===
    alignas(64) struct {
        uint32_t protocol_version;             // bump on breaking change
        uint32_t engine_software_version;      // matches SOFTWARE_VERSION_STRING
        char engine_version_string[64];        // matches ENGINE_VERSION_STRING
        std::atomic<uint64_t> last_update_us;  // monotonic timestamp; bumped per cycle
        std::atomic<uint64_t> writer_seqlock;  // for cross-region consistency reads
        uint32_t deployment_id;                // unique per server (cfg-driven; default hash of hostname)
        uint32_t cluster_count;
        uint8_t _padding[24];
    } header;

    // === GLOBAL STATE (aggregator's published state) ===
    alignas(64) struct {
        FPN<F> total_realized_pnl;
        FPN<F> total_open_notional;
        FPN<F> total_capital_allocated;
        FPN<F> total_drawdown_current;
        FPN<F> total_drawdown_peak;
        uint64_t total_fills;
        uint8_t global_kill_flag;
        uint8_t _padding[7];
    } global;

    // === PER-CLUSTER STATE ===
    alignas(64) struct ClusterPublish {
        char name[32];
        ExchangeEnum exchange_id;
        uint8_t enabled;
        uint8_t kill_flag;
        uint16_t node_count;
        uint32_t rate_tokens_available;
        uint32_t rate_window_used;
        FPN<F> realized_pnl;
        FPN<F> open_notional;
        FPN<F> drawdown_current;
        uint64_t fills;
        uint64_t connection_uptime_us;
        uint32_t reconnect_count;
        uint64_t last_disconnect_us;
        uint8_t _padding[16];
    };
    ClusterPublish clusters[NUM_EXCHANGES];

    // === PER-NODE STATE ===
    alignas(64) struct NodePublish {
        char cluster_name[32];                  // "binance" / "alpaca" / "ibkr"
        uint32_t node_id;
        char symbol[16];                        // "BTCUSDT" / "TSLA"
        char strategy_name[32];                 // "momentum" / "ml" / "simple_dip"
        uint32_t variant_id;
        NodeMode mode;                          // backtest|paper|live|shadow
        uint8_t kill_flag;
        uint16_t _padding1;
        FPN<F> capital_allocated;
        FPN<F> realized_pnl;
        FPN<F> open_notional;
        FPN<F> drawdown_current;
        uint64_t fills_count;
        uint64_t wins_count;
        uint64_t losses_count;

        // Position state (current; if any)
        uint8_t has_open_position;
        uint8_t position_side;                  // 0=flat 1=long 2=short
        uint16_t _padding2;
        FPN<F> position_qty;
        FPN<F> position_entry_price;
        FPN<F> position_unrealized_pnl;

        // Latency histogram (per-node hot path tick-to-decision)
        uint64_t latency_hot_p50_ns;
        uint64_t latency_hot_p99_ns;
        uint64_t latency_hot_p9999_ns;

        // Slow path latency
        uint64_t latency_slow_p50_ns;
        uint64_t latency_slow_p99_ns;
    };
    NodePublish nodes[MAX_NODES];

    // === AUDIT EVENT RING (recent events for fox-tui "watch" mode) ===
    alignas(64) struct {
        std::atomic<uint64_t> write_idx;
        AuditEventCompact events[AUDIT_EVENT_RING_SIZE];
    } audit_ring;
};

// Writer (engine):
void StatePublish_Cycle(EngineState<F>& state) {
    StatePublishRegion* region = state.publish_region;
    // Bump writer_seqlock to odd (signal "in progress")
    region->header.writer_seqlock.fetch_add(1, std::memory_order_acq_rel);

    // Update all fields (single writer; OK)
    region->header.last_update_us.store(NowUs(), std::memory_order_release);
    // ... copy aggregator state to global ...
    // ... copy cluster states ...
    // ... copy node states ...

    // Bump writer_seqlock to even (signal "consistent")
    region->header.writer_seqlock.fetch_add(1, std::memory_order_release);
}

// Reader (fox-tui):
void StatePublish_Read(const StatePublishRegion* region, ViewerSnapshot& snap) {
    uint64_t seq1, seq2;
    do {
        seq1 = region->header.writer_seqlock.load(std::memory_order_acquire);
        // Copy entire region into snap (fast memcpy; ~1MB; ~50μs)
        memcpy(&snap, region, sizeof(StatePublishRegion));
        seq2 = region->header.writer_seqlock.load(std::memory_order_acquire);
    } while (seq1 != seq2 || (seq1 & 1) != 0);
}
```

**Pattern compliance:**
- H6: cache-line aligned (alignas(64) on each cluster of fields)
- H3: no mutex; seqlock pattern for multi-reader consistency
- H9: byte-preservation for inter-process consistency (mmap is shared memory; no serialization)
- Multi-viewer concurrent attach: N readers OK; seqlock guarantees consistency per read

### UDS command channel

```cpp
// CoreFrameworks/CommandChannel.hpp (NEW)

enum CommandVerb {
    CMD_PAUSE_NODE,            // pause specific node (cluster_name/node_id)
    CMD_RESUME_NODE,           // resume specific node
    CMD_HALT_CLUSTER,          // halt all nodes in cluster
    CMD_RESUME_CLUSTER,        // resume cluster
    CMD_HALT_ALL,              // global emergency stop
    CMD_RESUME_ALL,            // resume from halt
    CMD_TRANSFER_FUNDS,        // internal-transfer between sub-accounts (.E.5+)
    CMD_RELOAD_NODE_CONFIG,    // SIGUSR1 equivalent for one node
    CMD_RELOAD_CLUSTER_CONFIG, // SIGUSR1 equivalent for cluster
    CMD_SET_KILL_THRESHOLD,    // set kill threshold (global / cluster / node)
    CMD_DUMP_STATE,            // debug dump of specific node/cluster/global
    CMD_DUMP_METRICS,          // metrics history (--since)
    CMD_RECONCILE_NODE,        // force reconcile against exchange
    CMD_RECONCILE_CLUSTER,     // force reconcile all cluster's nodes
    CMD_ADD_NODE,              // boot a new node into cluster (.E.X future; or restart-required)
    CMD_REMOVE_NODE,           // gracefully stop + remove node
    CMD_MODEL_SWAP,            // swap ML model file for node
    CMD_ROLLBACK_STRATEGY,     // revert to previous strategy variant (.E.X)
    CMD_WATCH_NODE,            // tail per-node events (streaming response)
    CMD_BACKUP_STATE,          // operator-triggered state snapshot
    NUM_COMMAND_VERBS
};

struct Command {
    uint32_t verb;             // CommandVerb
    uint32_t arg_count;
    char args[MAX_COMMAND_ARG_BYTES];  // serialized args
    uint64_t request_id;       // for response correlation
};

struct CommandResponse {
    uint32_t request_id;
    uint32_t status;           // 0=OK; >0=error code
    char response_body[MAX_RESPONSE_BYTES];  // serialized response
};

// Engine-side command channel listener
void CommandChannel_Listen(EngineState<F>& state, int uds_fd) {
    Command cmd;
    while (read(uds_fd, &cmd, sizeof(Command)) > 0) {
        CommandResponse resp = {};
        resp.request_id = cmd.request_id;

        // Validate first (e.g., refuse strategy-change-with-open-positions)
        if (!CommandChannel_Validate(cmd, state, &resp)) {
            write(uds_fd, &resp, sizeof(CommandResponse));
            continue;
        }

        // Dispatch via table (NOT branchy switch; per H7 even though slow-path)
        CommandHandlers[cmd.verb](state, cmd, &resp);

        write(uds_fd, &resp, sizeof(CommandResponse));
    }
}
```

## Design space + future-oriented choices

### Decision A: mmap region path

| Option | Description | Verdict |
|---|---|---|
| (a) /dev/shm/ (tmpfs) | RAM-backed; ultra-fast; ephemeral | rejected — lost on reboot; no crash recovery |
| **(b) /var/lib/fox/state/state.mmap (disk-backed)** | Persistent across reboot | **CHOSEN** — crash recovery natural; mmap'd region still cache-resident in practice |
| (c) Both (state in /var/lib/fox; transient metrics in /dev/shm) | Hybrid | rejected — complexity without benefit at v5.X scale |

### Decision B: UDS socket path

| Option | Description | Verdict |
|---|---|---|
| (a) /tmp/fox-engine.sock | Ephemeral | rejected — /tmp permissions issues; world-writable risk |
| **(b) /var/run/fox/engine.sock (production) OR ~/.local/share/fox/engine.sock (dev)** | OS-conventional paths | **CHOSEN** — proper systemd integration; user-namespace for dev |
| (c) Configurable via cfg | Operator choice | combined with (b) as default; cfg-overridable |

### Decision C: fox-tui rendering library

| Option | Description | Verdict |
|---|---|---|
| (a) ncurses | Most-portable; old standard | rejected — limited modern terminal features |
| **(b) notcurses** | Modern; sixel graphics; truecolor; mouse | **CHOSEN per D-16** — best modern terminal; actively maintained |
| (c) Build-from-scratch | Full control | rejected — wheel-reinvention; notcurses solves it |

### Decision D: Prometheus endpoint binding

| Option | Description | Verdict |
|---|---|---|
| (a) 0.0.0.0:9091 (all interfaces) | Direct scrape from anywhere | rejected — firewall hole; insecure |
| **(b) 127.0.0.1:9091 (localhost-only)** | Local scrape only | **CHOSEN per D-19** — SSH-tunnel for remote; secure by default |
| (c) UDS-only | No HTTP endpoint | rejected — Prometheus needs HTTP; UDS isn't supported |

### Decision E: foxml-train invocation model

| Option | Description | Verdict |
|---|---|---|
| (a) Long-running daemon with REPL | Interactive | rejected — Jupyter handles interactive; CLI handles production |
| **(b) One-shot CLI per training config** | Production-suitable | **CHOSEN per D-6** — scriptable; CI/cron-friendly; reproducible |
| (c) Engine-integrated (in fox-engine process) | Shares state | rejected — training is heavy; shouldn't compete with live trading |

### Decision F: Documentation file format

| Option | Description | Verdict |
|---|---|---|
| (a) Markdown (current) | Standard; reviewable | **CHOSEN** — consistent with existing DOCS/ |
| (b) RST + Sphinx | Auto-generated site | rejected — overkill for personal project; markdown sufficient |
| (c) Wiki-style (Confluence/Notion) | External service | rejected — vendor lock-in; git-tracked is canonical |

### Decision G: GUI deprecation handling

| Option | Description | Verdict |
|---|---|---|
| (a) Soft deprecation (still builds; warns at startup) | Gradual phase-out | rejected — maintenance burden; ambiguity |
| **(b) Hard deprecation (archived to legacy/; not in build)** | Clean break | **CHOSEN per D-26** — power-user-first; no GUI dep going forward |
| (c) Keep maintained as one of many viewers | Multi-viewer support | DEFERRED — fox-tui covers needs; revisit if operator wants graphical viewer |

### Decision H: Crash recovery default action

| Option | Description | Verdict |
|---|---|---|
| **(a) resume (read state; reconcile; continue)** | Trust-but-verify | **CHOSEN per D-47** — default; safest given reconcile-against-exchange |
| (b) cancel-all (cancel orders; keep positions) | Cautious | available via cfg; operator chooses |
| (c) flatten (force-close everything) | Most cautious | available via cfg; operator chooses |

### R3 — Documentation scope substantial (8 NEW docs)

**Risk:** documentation deliverables may stretch ship effort estimate.

**Mitigation:** documentation drafted from existing context (CLAUDE.md + DESIGN_PHILOSOPHY + this conversation + decision log); not greenfield writing; high-density planning material translates well to docs.

**Severity:** MED-LOW

### R4 — Hot-reload safety

**Risk:** SIGUSR1 hot-reload during active trading may cause subtle state inconsistencies.

**Mitigation:** atomic apply (rollback on validation failure); strategy parameter changes go through slow→hot seqlock (existing pattern); only "safe" cfg changes hot-reloadable; refuses dangerous changes (e.g., exchange binding change requires restart).

**Severity:** MED

### R5 — fox-tui first-time notcurses integration

**Risk:** notcurses library learning curve; terminal compatibility quirks.

**Mitigation:** notcurses well-documented; Caramel familiar with terminal-heavy ops; tested in common terminal emulators (kitty, alacritty, xterm).

**Severity:** LOW-MED

### R6 — Engine_gui archival completeness

**Risk:** GUI code may have dependencies that leak into engine code beyond expected boundaries.

**Mitigation:** comprehensive grep for ImGui includes / SDL includes / OpenGL includes; ensure no residual GUI dependencies in fox-engine; per-file review of any cross-references.

**Severity:** LOW
