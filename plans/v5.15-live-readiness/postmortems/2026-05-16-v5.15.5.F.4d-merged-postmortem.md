## Decisions captured

### Decision 1 — Option G merge ratified at coding time

Prior session's pre-coding finalization had multiple iterations through Options A→C→G2→G3→G4 landing at Option G (merge `.F.4c.4` + `.F.4d` scopes). This session's coding work confirmed Option G's discipline was right — the bandit/thompson cohort's first canonical application of FOREACH_BANDIT_SIDE + Pattern 5 path consolidation + sub-struct expansion all benefited from being shipped together. Splitting would have required parallel infrastructure work in each ship.

### Decision 2 — Per-core arrays on shared OmsState (§ F architectural correction)

Sidecar F.1 originally suggested `void* ezoo_ref` + `const void* core_cfg_ref` single-pointer fields on OrderManagerState<F>, with boot wiring `state.cores[i].oms.ezoo_ref = ...`. Coding revealed `state.cores[i].oms` doesn't exist — OmsState is engine-wide single instance (line 662 of EngineSharded boot), not per-core CoreContext member. Corrected design: per-core ARRAYS `ezoo_refs[MAX_EXECUTION_CORES]` + `core_cfg_refs[MAX_EXECUTION_CORES]` on shared OmsState, indexed by Order::core_id at consumer site (sister to per-slot last_exit_fee[] + bandit_reward_bps[] sibling-array pattern). 16-byte overhead → 256-byte overhead per OmsState; alignment-neutral (between sink-fn pointers + destructor; no cluster anchor affected).

**Lesson:** Sidecar design samples need verification against actual struct layouts. Future sidecars should grep target struct ownership before writing code samples.

### Decision 3 — Sidecar M.2 macro-nesting fallback to hand-write

Sidecar M.2 proposed `_CALIB_PERARM_COL_FOR_ARM(X, arm_idx)` helper macro with `arm##arm_idx` token-paste. Per C preprocessor rules, `arm_idx` in a `##` context is NOT substituted before paste — yields `arm_arm_idx` literal rather than `arm0`. Indirection via CONCAT helper would work but adds cognitive load. Chose hand-write 32 rows for robustness + auditability (sidecar M.2 fallback path).

**Lesson:** Per `feedback_evaluate_options_on_robustness_latency_design_not_time` — robustness > elegance. The 32-line registry is verbose but bulletproof; macro-nesting + token-paste indirection is elegant but fragile to compiler-version edge cases. Hand-write wins for hot-path-adjacent registries.

### Decision 4 — Fold-in scope reality after Caramel's "fold all 3 in"

After my audit surfaced TECH_DEBT-082/-083/-084 as fold-in candidates with honest cost picture (082 ~2-3h + 083 ~30min + 084 ~6-10h cascade rename), Caramel confirmed "fold all 3 in". The cascade rename of TECH_DEBT-084 turned out to be the biggest cost driver (200+ refs across 14 files + persistence path back-compat alias) — but the work was mechanical with sed+word-boundary regex; 3174/0 tests stayed GREEN throughout. The pre-tag checkpoint commit (`16c03e3`) before TECH_DEBT-084 cascade provided rollback safety. Net: all 3 closed cleanly; sprint state simplifies (TECH_DEBT-082 closes `.F.5` charter completely so `.F.4f` cleanup ship gets smaller).

**Lesson:** Per CLAUDE.md "Executing actions with care" — pre-tag checkpoint before high-blast-radius mechanical work (cascade renames + 100+ ref edits) bounds rollback cost. Worth the extra commit.

### Decision 5 — Thread A FULL deferred to .F.4d.1 dedicated ship

After audit surfaced Thread A framework consolidation residual (DERIVED_FILTER framework + 24-row migration + sidecar override + bit-packed inventory + CI Checks 9-12 + Layer 5b + ML_CFG_FLAG sig migration + fixture regression — ~15-25h focused work), Caramel's perspective shift acknowledged multi-month project arc. Chose: ship `.F.4d` with honest scope (Thread B FULL + Thread A foundation + 3 fold-ins) + log Thread A FULL as TECH_DEBT-085 + dedicated .F.4d.1 ship.

**Lesson:** Per `feedback_no_defer_for_effort` AND `feedback_evaluate_options_on_robustness_latency_design_not_time` — both apply here. Effort isn't the deciding factor (don't defer because it's hard); scope reality IS the deciding factor (Thread A FULL is multi-day work; forcing into single session = compromised quality + compaction risk). Honest scoping > heroic single-session push.
