## §3 The 9 fields that FIGHT the rule = the E.1.2/E.1.3 design decisions (each is a wording gap)

**AXIS legend:** A = "owner" under-defined (aggregates / derived / pipeline / contested) · B = replication motive too narrow (omits publish + per-node-locality + DOWNWARD coarse→fine) · C = copy-replica vs recompute-replica unspecified · D = orthogonality + SSoT-flip.

### HIGH (capital-correctness teeth)

- **Fight #4 — `live_tp` (hot) vs `take_profit_price` (persist): same value, TWO independent computations, diverges under slippage [AXIS C].** `ExecutionCore.live_tp` = `tick.price + tick.price*tp_pct` (`ExecutionCore.hpp:543`); `Position.take_profit_price` set by drainer from `o->intended_tp` (`OrderManager.hpp:1201/1360`), fixed at submit from the *event* price. Code EXPLICITLY acknowledges divergence: `OrderManager.hpp:1195` "expected-entry intended_tp — post-A9 they diverge under slippage". This is the recompute-replica drift `feedback_single_source_the_computation_not_just_the_mode` + D-190 forbid. **→ MANDATE: a replica is a COPY/tracks the owner; never an independent re-derivation.** (Also the E.1.3 ExecutionCore-mirror↔drainer-book coherence surface.)
- **Fight #5 — `realized_pnl`/`balance`: co-equal authority TODAY, and "coarsest" points at the WRONG owner [AXIS A].** `oms->realized_pnl` written by `handle_sell_fill` (`:1250`) AND split per-node into `node_realized` (drainer accum + `EventLoopState_ReconstructPerCoreFromEventLog :835`). Two writers, two homes → "no duplicated authority" violated by current code (the E.1.3 O(1)-aggregator target). The trap: "owner = coarsest unit it varies with" picks **deployment** (the account total exists there); intended design is **node owns, deployment derives by sum**. **→ owner = the FINEST tier at which the value is INDEPENDENTLY DETERMINED (leaf authority); coarser tiers DERIVE by aggregation, never co-write.**

### MED

- **Fight #1 — `trading_mode`: contested/unlocked variance-unit (the SHADOW wedge) [AXIS A].** Live consumers ALL deployment/boot — `LiveReadiness :250`, `NormalizeForMode :2179`, `IsLiveCapital :2213`. **No per-node override key (grep clean).** Plan relocates to **cluster** (`:2208` "global cfg → resolved cluster cfg"; E.1.2 OUTBOUND `:64`). But SHADOW = "live data + simulated fills" (`:43`) is a per-node *execution* property; cluster-homogeneity holds only because a cluster = one subaccount/venue binding. "Shadow-test node 3 while siblings 0-2 trade live in the same cluster" → trading_mode becomes per-node. **→ distinguish owner = "coarsest unit it CAN vary with (capability)" vs "DOES vary with (current config)"; resolve SHADOW against the cluster-binding. Today: cluster-owns (homogeneous); SHADOW is RESERVED/unimplemented.**
- **Fight #2 — `node_dd_pct`: derived field, no independent owner, yet persisted [AXIS A].** "display field, recomputed each rebuild" (`:468`) — pure fn of (node_peak_balance, current_value) — but raw-persisted (`:213`). (Every `ShardedSnapshot` per_node double, `:490-496`, same category.) **→ add a 3rd category: derived (recompute | cached); a cached derived field names its inputs + must be re-derivable on load.**
- **Fight #6 — Kill-switch family: three owner-tiers for ONE concept + DOWNWARD mirrors [AXIS B].** Node owns execution kill (`NodeStateFlagRegistry.hpp:75`); deployment owns the account breaker (`oms_state_flags` kill + `flatten_pending` + `recovery_until_us`); E.1.2 `NodeState.kill_flags` = "per_node / per_cluster_mirror / global_mirror atomics" (plan `:71`) — cluster/global kill mirrored DOWN onto the node so the per-node hot gate reads it locally (the H22-purity mechanism). **→ bless downward (coarse→fine) replication explicitly.**
- **Fight #7 — Display/snapshot replicas: a motive the wording omits (COLD, not hot) [AXIS B].** `PerNodeSnap.state_flags` NODE_KILL_TRIPPED (`:98`) mirrors execution KILL_TRIPPED; `ShardedSnapshot` doubles mirror Money. Motive = cross-thread publish / 30 Hz GUI decouple, NOT hot-access. **→ motive set = {hot-access | cross-thread-publish | per-node-locality}.**
- **Fight #3 — `intended_tp/sl/qty`: ownership MOVES along a lifecycle pipeline [AXIS A].** `NodeContext.intended_tp` (`:329`) → `SubmitCommand.intended_tp` (`OrderManager.hpp:153`) → `Order.intended_tp` (`Order.hpp:185`) → `Position.take_profit_price`/`original_tp`. A pipelined value has a SEQUENCE of authorities at the same variance-unit. **→ add a pipeline-staged / lifecycle-handoff category (one authority live at a time; NOT duplicates).**

### LOW

- **Fight #8 — `owner_node_id` under K=1 redundant with the slot index (SSoT-flip by phase) [AXIS D].** Under K=1 `Position[i]` is owned by node `i` by the bitmap construction. Field is load-bearing only at boot-reconcile (slot empty → field is SSoT, `per-node-position-ownership-model.md:46`) + at K>1. Authority FLIPS by phase. **→ name the canonical SSoT (the field) + its fast-path derivation (slot==node).**
- **Fight #9 — Cluster identity stored at two tiers (`ClusterState` + per-node `NodeState.binding`) [AXIS B].** cluster_id/subaccount_id/client_order_id_prefix cluster-owned but copied onto each node's `binding` for local drainer/adapter access — same downward cold-locality replication as #6/#7. Clean ONLY if downward+non-hot replication is blessed. (0-hit; wording decision must precede E.1.2 landing it.)

## §4 Where the owner axis already WINS (calibration)

- **Three "peak"s, three owners** — `oms->ks_peak_balance` (deployment), `NodeContext.node_peak_balance` (node), D-206 Position peak (position). The owner axis dissolves a naming collision. VALIDATES.
- **GateParameters → ExecutionCore seqlock** — textbook escape-hatch (owner=node/slow, replica-to-hot, not persisted). Clean.
- **The 9 Position PERSIST fields** — registry-generated serializer, one drainer-writer, append-only wire. Exactly the prescription.
- **`take_profit_price` proves orthogonality [AXIS D]** — owner=position ⊥ tier=hot ⊥ thread=slow-writer/hot-reader ⊥ wire=persist. "Hot AND persisted" is the NORMAL case, not a tension; the only real tension is when the hot replica RE-DERIVES (Fight #4).

## §5 Novel alternative considered (4-pillar discipline)

**Reframe to a per-field 3-tuple `(authority-tier, replica-set, derivation)`:** authority-tier = single writer / leaf SSoT; replica-set = explicit copy-targets each tagged `{hot|publish|locality}`, copy-only; derivation = `recompute` (default) | `cache(inputs…)`. Dissolves Fights #2/#4/#5/#7 in one shape; the registry already emits it. **Verdict: stronger but heavier — do NOT replace the framing; FOLD the four clarifications (A/B/C/D) into the H22/decision-time-binding spec bodies, keeping "finest tier of independent determination" as the headline. The 3-tuple becomes the registry ENCODING of those clauses, not the operator-facing rule.**
