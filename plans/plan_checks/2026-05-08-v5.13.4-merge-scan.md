## Findings

### 1. ATOMIC UTILITY REUSE — GREEN

All four new exit_* functions properly REUSE underlying primitives:

- `_InitExitBandits` → `Bandit_Init()`
- `_SaveExitBanditState` → `Bandit_SaveJSON()`
- `_LoadExitBanditState` → `Bandit_LoadJSON()`
- Reward attribution block → `Bandit_Update()` directly
- Bundle-ID safety: `EnsembleModelZoo_ComputeBundleId()` for both
  buy + exit (prevents model-swap state pollution)

**Cost savings:** Zero overhead for disabled cfg; active path
reuses proven hot-code paths.

### 2. SAVE/LOAD DUPLICATION CANDIDATE — YELLOW (acceptable)

`SaveExitBanditState` and `LoadExitBanditState` are near-identical
to `SaveBanditState` and `LoadBanditState`. Could be unified via
parameterization. Counter-argument: separate functions provide
clear intent (buy vs. sell, fewer parameters). Duplication < 50
lines and intentionally parallel.

**Verdict:** EXTENDS_EXISTING — acceptable for clarity.

### 3. REWARD ATTRIBUTION SHAPE MISMATCH — GREEN (intentional)

Buy-side `TradeCloseReward`: walks reward_ring backward, applies
win/loss binary (±50bps × mult).

Exit-side counterfactual: per-slot capture, computes hypothetical
TP-hit P&L vs. actual, difference = reward.

**Different data flow + different reward model.** Extracting
shared skeleton would obscure intent.

### 4. STATE-FIELD STRUCT vs. PARALLEL ARRAYS — GREEN (current acceptable)

Current: `int8_t last_exit_predicted_arm[16]` +
`int8_t last_exit_predicted_regime[16]` (parallel arrays).
Alternative: `struct { int8_t arm; int8_t regime; } [16]` (struct
of arrays).

Trade-off: struct saves ~0ns on access (modern CPUs load both
anyway), marginally improves cache locality. Adds indirection.
Current matches existing OMS pattern (`last_exit_was_predicted[]`
+ `last_exit_predicted_p[]`).

**Verdict:** parallel arrays acceptable; struct refactoring
deferred to v5.13.X cleanup if profiling shows need.

### 5. PERIODIC SAVE HOOK — YELLOW (deferred feature)

Buy-side has periodic save (`MaybeSaveBanditPeriodic`) after every
N trade-closes. Exit-side saves only at shutdown.

**Intentional deferral** per v5.13.4.C commit message: operator
opts to study learning curve before committing to periodic save.
Shutdown-only save sufficient for MVP.
