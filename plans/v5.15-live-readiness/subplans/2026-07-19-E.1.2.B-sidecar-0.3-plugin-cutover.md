## 2. The closable filter — fixes a LIVE bug, not just ASSERT drift

`enclosing_block` (`tagcontext.lua:18-35`) treats every `UNIT` member as a block-opener and scans forward for `[END_X]`; on no-match it runs to `i+2000` and **returns nil**, aborting the upward search.

- **Live bug today (missed by the investigation, found by the adversary):** `FILE` (163 openers / 0 closers) and `MACRO` (19 / 0) are in the current hardcoded set but are **not closable** → a cursor in a file-header region already scans the whole buffer for a nonexistent `[END_FILE]` and returns nil. **This is broken now, not hypothetically.**
- **ASSERT would make it worse:** inside-block `[ASSERT]` is CANONICAL (D-340; `in-code-documentation-schema.md:559-564`) — e.g. `OmsExitPredictorMetaRegistry.hpp` `[REGISTRY]`@76 / inline `[ASSERT]`@115-124 / `[END_REGISTRY]`@141; `NodeCtxInitRegistry.hpp` `[ASSERT]`@245,259 inside `[FUNCTION]`191-267. Corpus: **138 `[ASSERT]`, 0 `[END_ASSERT]`.** A membership-only ASSERT fix regresses every unit containing an inline assert.
- **THE FIX (adversary's simplification):** build the opener set as **closable-only** — `scope_openers := { t : unit_types[t].closable }` (the 6 types). One filter, applied once at attach, off the already-CI-gated `closable` column. Not "add ASSERT then branch per line."

## 3. Design (Option A — confirmed sound by the sweep)

**New `lua/fox-symdeps/nodemodel.lua`** — the single plugin-side node-model SSoT:
- locates foxtag, runs `grammar --json` once at attach via the existing `runner.lua:7` (`vim.system`, async) + `vim.json.decode`;
- memoizes `{type → closable}`; exposes `is_unit(t)` / `closable(t)` / `scope_openers()`.
- Both `tag_grammar_adapter.parse` and `tagcontext.enclosing_block` require it.

**Why not fold it behind `tagadapter.install()` (Option B):** `enclosing_block` is CORE and runs *before* any adapter install (the menu path, `init.lua:208`; the null adapter no-ops until `tagadapter.lua:22`). Routing core grammar through the optional derived-facts adapter's install lifecycle is a **dependency inversion**. Option A's +1 file < Option B's coupling cost.

**`tagadapter.install()` gets wired live** from `setup()` (it is currently **dormant** — referenced only by a doc-comment and the test fake, so the real adapter never runs). Separate concern from the node-model; both land this ship.

### 3a. foxtag discovery — **REFINEMENT 1 (adversary-required)**
**NOT a fixed script-relative anchor.** The `foxtag_client.py:21` analogy is invalid: the Python client is permanently co-located with `tools/foxtag/`; **the plugin is not** — `README.md:48` documents a lazy.nvim remote install cloning to `~/.local/share/nvim/lazy/`, where `../../foxtag/foxtag` resolves nowhere. A bare anchor ships a silent latent break (Lua — no compile error) on the published path.

**Resolution order:** `opts.foxtag_bin` (config — matches the existing `pack_dirs`/`doc_dirs`/`template_args` pattern, and honors the provider architecture that keeps trader-specific paths OUT of the publishable core) → `PATH` lookup → script-relative anchor **last resort only**.

### 3b. Unavailable-foxtag behavior — error handling, NOT a fallback
**No bundled node-model copy.** foxtag is V1's core, not an optional dep; "not built yet" is a *setup* state, not an operating state, and a bundled copy would re-create the Class-18 mirror this ship deletes. (The `foxtag_client.py` fallback is disanalogous — it exists because Python is the *outgoing authority mid-migration*, D-349, not because the core might be absent.)

What ships instead (~table stakes, not a fork):
- **silent probe at setup** (async, no boot-time nagging);
- **fail at point-of-use** — one clear message when a tag-nav feature is invoked and unavailable: `tag-nav needs foxtag — run bash tools/foxtag/build.sh`;
- **re-probe, never cache a permanent failure** (foxtag built *after* nvim attached must recover);
- `:checkhealth` carries the detail (house style — `health.lua:32,38` degrade-with-warn for rg/treesitter).

Degraded scope = the tag-aware subset only (`:FoxSymdepsDerived`, `:FoxSymdepsMenu`, tagwriter seed). Dependency trees / byte-layout / consumers / notes are unaffected (clangd + treesitter + `gen_code_map` sourced).

### 3c. Out of scope — `format_derived` (confirmed by the sweep)
`format_derived`/`verify` (`tag_grammar_adapter.lua:63-92`) render the `[DERIVED]` axes from `facts.lua`; they consume no node-model. The 0.1.5 envelope carries **no per-unit-type / per-plane axis-SET payload** (`unit_types` schema is only `{name, closable}`), so their axis-hardcode **cannot** be retired now. **Home it explicitly** (D-365's "read foxtag OR earn a parity section") as a tracked residual mirror → folds into the ship that grows a plane→axis-set payload.

## 4. Parity + the delete gate — **REFINEMENT 2 (adversary-required)**
