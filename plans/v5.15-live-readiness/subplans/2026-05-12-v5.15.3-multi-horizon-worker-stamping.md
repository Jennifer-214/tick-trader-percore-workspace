## Why this subplan exists (root-cause reframe post-audit)

The original v5.15.3 scope was based on the "missing grid_member_count"
boot warning, with a proposed `stamp_emit_for_horizon` helper for
multi-horizon. The /parity-check audit (PARITY-021 HIGH) caught that
the root cause was different:

- **Multi-horizon DOES stamp via the RFV chain** —
  `mh_run_one_horizon_fv` → `Backtest_RunFullValidation` at
  `Backtest/BacktestPanels.hpp:3633`. The infrastructure exists.
- **The bug:** `inf.grid_member_count` / `inf.grid_member_idx` /
  `inf.horizon_count` are **never populated** by any production caller.
  They're orphan placeholders in `FOREACH_STAMP_BOUND_MODEL_CONST_PRE_CFG`
  at `StampBoundModelConstRegistry.hpp:337-341`.
- **train_model_worker_fn ALSO has a related latent bug** (PARITY-020 HIGH):
  it lacks the `STAMP_CFG_AUTOPOPULATE` call that
  `Backtest_RunFullValidation` has. **22 cfg-bound fields silently
  absent from Train Model stamps.**

The proper structural fix (Caramel framing 2026-05-12 — "this seems
like avoiding effort in favor of a solution im gonna fix later
anyways"): **extract the canonical stamp emit chain from RFV into a
shared helper.** Both `train_model_worker_fn` (single-horizon) AND RFV
(multi-horizon via mh_run_one_horizon_fv) call the helper. Asymmetry
ELIMINATED. PARITY-020 closes as side-effect (helper has AUTOPOPULATE
built in). PARITY-021 closes via plumb-through of
`req_grid_member_count` etc. through `FullValidationResults`.

**Plus the unrelated-but-bundled landmine close:** v5.11.45's
forced-serial multi-horizon workaround replaced with proper
`setenv("OMP_NUM_THREADS", "1", 1)` at `foxml_suite.cpp:main()` BEFORE
any pthread spawns (CLAUDE.local.md "Known landmine" 2026-05-07; proper
fix documented but deferred since).

## Trade-off acknowledged (libgomp setenv impact)

The unconditional `setenv` at `main()` affects ALL XGBoost in foxml_suite.
Per audit OpenMP-consumer audit, XGBoost is the SOLE OpenMP consumer in
our code (no `#pragma omp` outside the v5.11.44 hotfix).

| Path | Pre-fix | Post-fix |
|---|---|---|
| Single-horizon training (Train Model button) | ~4x faster via OpenMP histogram-build parallelism | ~3-4x slower (single-threaded XGBoost) |
| Multi-horizon parallel (Train Multi-Horizon button) | UNUSABLE (segfaults; forced serial by v5.11.45) | Works (N pthreads × single-thread XGBoost = N cores in parallel) |
| Run Full Validation | OpenMP-parallel | Single-threaded |
| Walk-Forward | OpenMP-parallel | Single-threaded |

**Net effect:** grid-training-heavy workflows GAIN throughput
(multi-horizon parallel works); single-horizon training loses
single-machine speed BUT operator can switch to multi-horizon for
larger grids.

**./engine (live binary) UNAFFECTED** — engine doesn't run XGBoost
training; inference is single-threaded per CLAUDE.md item 18.

Caramel approval 2026-05-12: shift toward headless workflows + grid
training is the strategic direction; this trade-off is acceptable.

## .A — Extract Stamp_AssembleAndEmit helper from RFV + quarantine broken AUTOPOPULATE macro

### Step 0: verify PARITY-022 (STAMP_MODEL_CONST_AUTOPOPULATE expansion)

Per /parity-check PARITY-022 finding, the macro at
`ML_Headers/StampBoundModelConstRegistry.hpp:680-689` is self-referential:

```cpp
#define STAMP_MODEL_CONST_AUTOPOPULATE_ONE(name, group, presence, type, fmt, default_val, get_value, emit_when, doc) \
    if (emit_when) {                                                       \
        STAMP_AUTOPOPULATE_SET_HAS_##group(name);                          \
        if constexpr (std::is_array_v<type>) {                             \
            strncpy((inf).name, (get_value), std::extent_v<type> - 1);     \
            (inf).name[std::extent_v<type> - 1] = '\0';                    \
        } else {                                                           \
            (inf).name = (type)(get_value);                                \
        }                                                                  \
    }
```

Registry tuples pass `inf->X` as the `get_value` column (verified at
`StampBoundModelConstRegistry.hpp:360-361`, :431-432, etc.), so the
expansion becomes `(inf).xgb_train_nthread = (int)(inf->xgb_train_nthread)` —
self-referential no-op. The macro has 0 production callers today; bug
is latent.

**Verification command:**

```bash
# Confirm 0 production call sites (latent bug):
rg -n "STAMP_MODEL_CONST_AUTOPOPULATE\b" \
   --type cpp --type-add 'cpp:*.hpp' . | grep -v "^.*\.hpp.*://"
# Expected: only the macro definition itself; no call sites
```

### Step 0.5: structural disposition of the broken macro

Per CLAUDE.md item 19 (structural fix preferred when bug class can
recur) + Caramel's "structural fixes, not deferring because effort"
principle:

**Decision:** The macro is SEMANTICALLY WRONG for model-const fields.
Model-const fields (timestamp, run_name, grid_member_count, etc.) come
from training-time CALLER ARGS, not cfg auto-derivation. They should be
manually populated from `StampArgs` (caller's responsibility). The
`STAMP_CFG_AUTOPOPULATE` macro (production-tested; cfg-bound fields)
handles the cfg subset. STAMP_MODEL_CONST_AUTOPOPULATE was speculative
infrastructure that didn't match the actual use case.

**Action: quarantine the broken macro to prevent future misuse.**
Replace its body with a static_assert that emits a clear error message:

```cpp
// In ML_Headers/StampBoundModelConstRegistry.hpp at line 601:
//
// v5.15.3.A — STAMP_MODEL_CONST_AUTOPOPULATE QUARANTINED.
// The macro is semantically wrong for model-const fields (which come
// from caller's StampArgs, not cfg auto-derivation). PARITY-022 caught
// that the expansion was self-referential ((inf).X = (type)(inf->X))
// because registry tuples pass inf->X as get_value column.
//
// Helper Stamp_AssembleAndEmit (v5.15.3.A) manually populates
// model-const fields from StampArgs. Future architectural-field
// AUTOPOPULATE work needs a separate registry column for the value
// source — not addressed in v5.15. Captured as TECH_DEBT-036
// (architectural-field AUTOPOPULATE redesign).
#define STAMP_MODEL_CONST_AUTOPOPULATE(inf, meta, now_us)                            \
    static_assert(false,                                                              \
        "STAMP_MODEL_CONST_AUTOPOPULATE is QUARANTINED (PARITY-022; v5.15.3.A). "    \
        "Model-const fields populate manually from StampArgs in callers like "        \
        "Stamp_AssembleAndEmit. See TECH_DEBT-036 for architectural-field "          \
        "AUTOPOPULATE redesign.")
```

### Step 2: extract Stamp_AssembleAndEmit function

```cpp
// Extracted from BacktestEngine.hpp:1039-1220 RFV emit chain.
// Walks both X-macro registries via AUTOPOPULATE; populates per-call
// fields explicitly. ONE canonical assembly path used by 3 callers:
//   - train_model_worker_fn (single-horizon training via BacktestPanels)
//   - Backtest_RunFullValidation (single-horizon validation OR multi-horizon
//     when called via mh_run_one_horizon_fv with req_grid_* set)
//   - (future via TECH_DEBT-034) batch CLI invocations

template <unsigned F>
int Stamp_AssembleAndEmit(
    const char* output_stamp_path,
    const ControllerConfig<F>& cfg,
    const StampArgs<F>& args,
    const char* hmac_secret,
    int hmac_enabled) {

    StampInferenceCfgInputs inf = {};

    // CFG-bound fields auto-flow from registry (PARITY-020 close: this
    // is the call that was missing from train_model_worker_fn pre-v5.15.3).
    STAMP_CFG_AUTOPOPULATE(inf, cfg);

    // Model-const fields: manually populated below (NOT via the broken
    // STAMP_MODEL_CONST_AUTOPOPULATE macro — PARITY-022; quarantined at
    // .A Step 0.5). Mirrors RFV's existing manual approach at
    // BacktestEngine.hpp:1039+ (canonical reference). Future AUTOPOPULATE
    // redesign tracked as TECH_DEBT-036.

    // Per-call fields (not registry-driven; vary per training run):
    if (args.horizon_ticks > 0) {
        STAMP_SET(inf, label_lookahead_ticks);
        inf.label_lookahead_ticks = args.horizon_ticks;
    }
    if (args.horizon_tp_pct > 0.0f) {
        STAMP_SET(inf, label_tp_pct);
        inf.label_tp_pct = args.horizon_tp_pct;
    }
    if (args.horizon_sl_pct > 0.0f) {
        STAMP_SET(inf, label_sl_pct);
        inf.label_sl_pct = args.horizon_sl_pct;
    }

    // Grid identification (PARITY-021 close: these are the orphan-
    // placeholder fields in FOREACH_STAMP_BOUND_MODEL_CONST_PRE_CFG
    // that no production caller populated).
    STAMP_SET(inf, grid_member_count);
    inf.grid_member_count = args.grid_member_count;
    STAMP_SET(inf, grid_member_idx);
    inf.grid_member_idx = args.grid_member_idx;
    STAMP_SET(inf, horizon_count);
    inf.horizon_count = args.horizon_count;

    // XGBoost hyperparams (operator snap from panel)
    STAMP_SET(inf, xgb_hyperparams);
    inf.xgb_max_depth = args.snap_max_depth;
    inf.xgb_learning_rate = args.snap_learning_rate;
    inf.xgb_n_estimators = args.snap_n_estimators;
    inf.xgb_subsample = args.snap_subsample;
    inf.xgb_colsample_bytree = args.snap_colsample_bytree;
    inf.xgb_min_child_weight = args.snap_min_child_weight;
    inf.xgb_seed = args.snap_seed;
    {
        static const char* tree_method_choices[] = { "hist", "exact", "approx", "auto" };
        int tm_idx = (args.snap_tree_method_idx >= 0 && args.snap_tree_method_idx < 4)
                     ? args.snap_tree_method_idx : 0;
        size_t tmln = strnlen(tree_method_choices[tm_idx],
                              sizeof(inf.xgb_tree_method) - 1);
        memcpy(inf.xgb_tree_method, tree_method_choices[tm_idx], tmln);
        inf.xgb_tree_method[tmln] = '\0';
    }

    // Build flags + label registry hashes
    STAMP_SET(inf, build_flags_hash);
    inf.build_flags_hash = tt::BUILD_FLAGS_HASH();
    STAMP_SET(inf, label_registry_hash);
    inf.label_registry_hash = LABEL_REGISTRY_HASH();

    // Scaler binding (if provided)
    if (args.scaler_sha256_hex && args.scaler_sha256_hex[0]) {
        STAMP_SET(inf, scaler);
        inf.feature_scaler_present = 1;
        size_t shn = strnlen(args.scaler_sha256_hex,
                             sizeof(inf.scaler_sha256) - 1);
        memcpy(inf.scaler_sha256, args.scaler_sha256_hex, shn);
        inf.scaler_sha256[shn] = '\0';
    }

    // Run identification
    if (args.run_name && args.run_name[0]) {
        STAMP_SET(inf, run_name);
        size_t rnln = strnlen(args.run_name, sizeof(inf.run_name) - 1);
        memcpy(inf.run_name, args.run_name, rnln);
        inf.run_name[rnln] = '\0';
    }

    // Output count from label_kind
    STAMP_SET(inf, model_num_outputs);
    int K = LabelType_NumClasses(args.label_kind);
    inf.model_num_outputs = (K >= 2) ? K : 1;

    // Model-const architectural fields (manually populated; mirrors
    // RFV's existing manual approach at BacktestEngine.hpp:1039+).
    // training_timestamp_us, run_name, environment_meta group fields.
    // PARITY-022 broken AUTOPOPULATE macro NOT used.
    STAMP_SET(inf, training_timestamp_us);
    inf.training_timestamp_us = tt::WallClock_Now_us();
    // (run_name already populated above when args.run_name non-empty)
    // (environment_meta group fields: populated below if cfg.held_out_gate_strict
    //  per existing RFV chain — extracted unchanged)

    // Emit stamp body via existing emit function
    return stamp_write_for_model(
        output_stamp_path, inf, hmac_secret, hmac_enabled);
}
```

int main(int argc, char *argv[]) {
    // v5.15.3.C — XGBoost+libgomp+pthread segfault landmine fix
    // (CLAUDE.local.md "Known landmine" 2026-05-07; v5.11.45 forced
    // serial multi-horizon as workaround → REMOVED in v5.15.3.C).
    //
    // Root cause: libgomp's parallel-region setup uses shared

    // OpenMP parallelism (~3-4x slower); parallel multi-horizon now
    // runs N horizons safely (N-x speedup via pthread). Net
    // throughput favorable for grid-training-heavy workflows.
    //
    // ./engine (live binary) unaffected — engine doesn't run XGBoost
    // training; inference is single-threaded per CLAUDE.md item 18.
    setenv("OMP_NUM_THREADS", "1", /*overwrite=*/1);

    // v5.11.0.A — Suite does FP math during model training...
    tt::engine_set_mxcsr_ftz_daz();

    /* rest of main unchanged */
