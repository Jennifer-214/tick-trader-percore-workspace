## Architectural significance

The CfgFieldDescriptor schema LOCKS at this ship — subsequent sub-ships only add rows; no schema changes after `.F.4b`. This is the "design upfront + ship in waves" decision (Caramel 2026-05-14).

The 12-column Option D tuple shape:

```
X(KIND_TOKEN, name, label, section, meta, payload, tooltip,
  applies_to_strategy_cat, applies_to_op_mode_cat, applies_to_regime_cat, applies_to_risk_cat,
  lives_in_struct)
```

The `Kind` enum is METADATA-ONLY (drives GUI presentation hints); type dispatch happens via `tt::cfg_*_field<T>` with `T` deduced from the destination field. This separation extinguishes the Class 23 anti-shape at the API surface.

Locale-immunity is a bonus side effect of the migration: previously-locale-dependent save paths for migrated fields now use pinned C locale via the registry's save dispatcher.

## Lessons learned (from commit body + plan amendment)

### Pre-coding audit gate is load-bearing for MED-HIGH ships

The 5-audit synthesis surfaced 2 CRITICAL + 7 HIGH findings BEFORE coding started. Plan body was rewritten 2026-05-14 to address all CRITICAL + HIGH + MED + LOW. This pattern was retroactively codified in `DESIGN_SPECS/audit-driven-pre-coding-gate.md`.

### "Design upfront + ship in waves" beats incremental schema migration

The descriptor schema design at `.F.4b` includes all 5 future LivesInStruct values + all metadata bits planned through `v5.15.6` even though only STRUCT_CFG rows ship at `.F.4b`. This locks the schema once; subsequent sub-ships add rows without schema changes. Eliminates the "redesign-the-schema-each-time" rework risk.

### 3-barrier structural fix discipline

Each barrier is independently verifiable via grep + compile-time check:
- Barrier 1: API surface grep (no `reinterpret_cast` / `void*` in dispatch header).
- Barrier 2: Caller grep (no offset arithmetic in extractors).
- Barrier 3: Compile-time `static_assert` (type-family check fails for non-recognized types).
