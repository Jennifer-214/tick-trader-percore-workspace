## Theme

Audit Part 12 + §9/§11 of the rules doc define the **table-stakes HFT init invariants**: TCP_NODELAY (no Nagle), mlockall (no swap), FTZ/DAZ (no FPU subnormal stalls), PGO/LTO (compiler-aligned hot paths). Without these, every downstream v5.11 ship measures on a noisy baseline and can't trust its own latency numbers. Ship first so v5.11.1+ measurements are clean.

Part 3 (architectural invariants verify) folds in here as "check-only" — this ship is the right time to lock in `static_assert(!std::is_polymorphic<T>::value)` for key structs since the rules-doc §2 claim is currently runtime-only enforcement.

## Phase A — FTZ/DAZ in `main()` (`v5.11.0.A`)

**Audit:** Part 12.3 — Denormal stalls cost up to 100× FPU throughput. Triggered by exp-decay math in ML inference + EMA paths.

**Rules ref:** §9 — "The `main()` function must configure the CPU's `MXCSR` register to flush subnormal floating-point numbers to zero."

**AMENDED 2026-05-06 (readiness P1.1):** Extract a shared helper rather than inlining the two macros at one site only. Engine main + every test binary's main must share the MXCSR state, otherwise snapshot tests for `Features_PackAll` silently diverge from engine runtime when feature values land in subnormal territory. (Real train-serve parity drift surface, not hypothetical.)

**Step 0:** Create `CoreFrameworks/SystemInit.hpp` with a single helper:

```cpp
// CoreFrameworks/SystemInit.hpp
// Small helpers shared across all engine binaries' main() entry points.
// Keep this header tiny — it ships into engine, controller_test,
// parity_harness, and foxml_suite. No transitive deps allowed beyond
// system headers.
#pragma once
#include <xmmintrin.h>
#include <pmmintrin.h>

namespace tt {

// Flush-to-Zero + Denormals-Are-Zero. Required for sub-microsecond
// determinism in any path that touches floating-point math (ML inference,
// EMA decay, FlowFeatures, RegimeSignals). Must be called from EVERY
// binary's main() — engine, controller_test, parity_harness, foxml_suite —
// or train↔serve parity drifts in subnormal territory.
//
// Audit: LATENCY_OPTIMIZATION_AUDIT.md Part 12.3
// Rule:  STRATEGY_AND_CODING_RULES.md §9
static inline void engine_set_mxcsr_ftz_daz() {
    _MM_SET_FLUSH_ZERO_MODE(_MM_FLUSH_ZERO_ON);
    _MM_SET_DENORMALS_ZERO_MODE(_MM_DENORMALS_ZERO_ON);
}

} // namespace tt
```

**File:line targets (helper call sites):**
- `main.cpp:120` — first executable line in `main()` (after copyright fprintf at 120-121); call `tt::engine_set_mxcsr_ftz_daz();`
- `tests/controller_test.cpp:1424` — first line inside `int main()` at 1423; call helper before any test runs
- `tests/parity_harness.cpp:120` — first line inside `int main(int argc, char** argv)` at 119
- `foxml_suite.cpp:86` — first line inside `int main(int argc, char *argv[])` at 85

**Include path varies by binary (re-readiness 2026-05-06 catch):**
- `main.cpp` + `foxml_suite.cpp` (top-level): `#include "CoreFrameworks/SystemInit.hpp"` (descending, no `..`)
- `tests/controller_test.cpp` + `tests/parity_harness.cpp` (in tests/ subdir): `#include "../CoreFrameworks/SystemInit.hpp"` (ascending, with `..`)
- This matches existing patterns in each file's other includes; verify with `grep '#include "CoreFrameworks' main.cpp foxml_suite.cpp tests/*.cpp` before Phase A coding.

**Verification:**
- Boot smoke: probe MXCSR via `_mm_getcsr()` and assert FTZ bit (`0x8000`) + DAZ bit (`0x40`) set.
- Add to `tests/controller_test.cpp` EXTENSIBILITY block: `static int test_mxcsr_ftz_daz()` smoke. Runs `_mm_getcsr()` and asserts both bits set. This test now actually verifies the engine's MXCSR state because controller_test main() also calls the helper at line 1424 → snapshot tests run under same MXCSR as engine.

**Risk (subnormal-flush PnL drift):** Models trained PRE-FTZ may have learned to discriminate on subnormal-range feature values that now flush to 0. Backtest replay before/after FTZ enabled should show ≤1bp cumulative PnL drift over 1M ticks; if drift > 1bp, the trained model is sensitive to the change and retrain is required. **Phase A sub-ship gate must include this replay-drift check** in addition to the test suite. Operator decision: which existing trained model serves as the drift-calibration reference?

**Caveat (operator-side, Linux only):** If the engine spawns threads via `pthread_create`, each new thread inherits the parent's MXCSR per Linux kernel pthread semantics. Setting once in main() suffices on Linux. macOS/Windows have different inheritance — out of scope; defer to v5.11.0a operator runbook.

**Sub-ship gate:** `./build.sh test` baseline 1636/0 (+1 new MXCSR test) + replay-drift check ≤1bp. Tag `v5.11.0.A`.

## Phase B — mlockall + RLIMIT_MEMLOCK preflight (`v5.11.0.B`)

**Audit:** Part 12.2 — Page swapping stalls cost hundreds of microseconds. mlockall locks all pages into physical RAM.

**Rules ref:** §9 — "The engine must call `mlockall(MCL_CURRENT | MCL_FUTURE)` on boot."

**HFT suggestion (annotated review):** Verify `RLIMIT_MEMLOCK` via `getrlimit` BEFORE calling `mlockall`. If the soft limit is too low, mlockall fails silently or partially — a non-locked engine is a "zombie" engine in HFT. Explicitly check return value + `exit(1)` on hard failure (with a clear stderr message telling the operator how to raise the limit).

**AMENDED 2026-05-06 (readiness P1.2):** Original draft inserted mlockall at main.cpp:128-130 (post-cfg-load). That fires BEFORE the `freopen(log_file)` redirect at main.cpp:141, so a fatal mlockall failure prints to terminal stderr that headless/systemd operators never see. Move the call to AFTER the log redirect so the failure reason lands in `logging/engine.log`. Trade-off: cfg-parsing memory isn't locked. Acceptable — cfg is parsed-and-discarded outside the hot path.

**Step 0:** Add `#include <sys/mman.h>` + `#include <sys/resource.h>` + `#include <errno.h>` + `#include <string.h>` (for `strerror`) to `main.cpp`.

**File:line targets:**
- `main.cpp:41-43` — add `<sys/mman.h>`, `<sys/resource.h>`, `<errno.h>`, `<string.h>` to the include block (existing block: Licensing.hpp, stdio.h, stdlib.h)
- `main.cpp:148` — insert AFTER the `freopen(log_file)` block ends at line 147 (closing brace of `if (bcfg.log_file[0])`), BEFORE the sharded dispatch at line 159. This way:
  - Operator's `logging/engine.log` captures any mlockall warning or fatal message.
  - mlockall locks all post-redirect allocations (the bulk of engine state) into RAM.
  - cfg-load memory at lines 128-129 stays unlocked, but it's parsed-and-discarded; not a hot-path concern.

**Code shape (canonical, ~25 LOC):**
```cpp
// Post-cfg-parse, pre-thread-spawn: lock all pages into RAM.
// Failure modes:
//   1. RLIMIT_MEMLOCK too low → mlockall returns -1 with EAGAIN.
//      We probe the limit first and emit a clear error.
//   2. CAP_IPC_LOCK missing on non-root → mlockall returns -1 with EPERM.
//      Operator must run with appropriate caps or as root.
// Either way, an HFT engine that can't lock its memory is a fail-fast condition.
{
    struct rlimit rl;
    if (getrlimit(RLIMIT_MEMLOCK, &rl) == 0) {
        // Heuristic: need at least the engine's typical resident size.
        // 256 MB is generous for current sizing; alarm if soft limit is below.
        const rlim_t kMinMemlock = 256ULL * 1024 * 1024;
        if (rl.rlim_cur != RLIM_INFINITY && rl.rlim_cur < kMinMemlock) {
            fprintf(stderr,
                "[v5.11.0] WARNING: RLIMIT_MEMLOCK soft limit is %llu bytes, "
                "want >= %llu. mlockall may fail. Raise via "
                "`ulimit -l unlimited` or /etc/security/limits.conf.\n",
                (unsigned long long)rl.rlim_cur, (unsigned long long)kMinMemlock);
        }
    }
    if (mlockall(MCL_CURRENT | MCL_FUTURE) != 0) {
        fprintf(stderr,
            "[v5.11.0] FATAL: mlockall failed: %s. "
            "Engine cannot guarantee deterministic latency without locked pages. "
            "Run with CAP_IPC_LOCK or as root, and ensure RLIMIT_MEMLOCK is raised.\n",
            strerror(errno));
        return 1;
    }
}
```

**Verification:**
- Boot smoke: returns 0 on dev box (operator's typical ulimit -l is unlimited). Verify in `tests/` — though hard to test in unit suite; integration-test only.
- Test addition: a unit test that calls a wrapped helper (`bool engine_lock_pages_or_warn()`) and asserts it returns true on the dev box. If the helper exits on fail, the test won't assert in-process; just verify it doesn't `exit(1)` under default ulimit.
- Non-test verification: run `./bin/engine` once, observe boot stderr shows no mlockall warning + cat /proc/<pid>/status | grep VmLck shows non-zero locked pages.

**Risk:** Medium. RLIMIT failure mode is a real concern on shared CI environments. The exit-on-fail rule per HFT-suggestion is correct for production, but may need a `--allow-unlocked-memory` cfg flag if dev box ulimits become tedious. **Decision:** ship without the override flag; operator can `ulimit -l unlimited` once. If CI fights this, add the flag in v5.11.0e or a follow-up.

**Sub-ship gate:** `./build.sh test` 1636/0 (or 1622/0 if test added), boot of `./bin/engine` shows no mlockall warning. Tag `v5.11.0.B`.

**Audit:** Part 12.1 — Nagle's algorithm buffers outgoing packets up to 40ms before transmit. On order submit this is catastrophic.

**Rules ref:** §9 — "All TCP sockets must be initialized with TCP_NODELAY."

```cpp
// Disable Nagle: order packets must hit the wire immediately. Without this,
// TCP can buffer for up to 40ms waiting to coalesce — catastrophic for HFT.
int one = 1;
if (setsockopt(sockfd, IPPROTO_TCP, TCP_NODELAY, &one, sizeof(one)) < 0) {
    fprintf(stderr, "[%s] setsockopt(TCP_NODELAY) failed: %s\n",
            "BINANCE", strerror(errno)); // [REST] for OrderAPI variant
    // Continue: not fatal, but log it. NIC behavior varies; some OSes are
    // already TCP_NODELAY-by-default on certain interfaces.
}
```

**Risk:** Low. TCP_NODELAY is a well-understood, idempotent option. Worst case: log noise if the OS rejects the option (it won't on Linux).

## Phase D — PGO + LTO build orchestration (`v5.11.0.D`)

**Audit:** Part 12.4 — PGO and LTO can eliminate cold branches and align hot instruction streams.

**Rules ref:** §9 — "Production binaries must be built with `-O3`, `-march=native`, Link-Time Optimization (`-flto`), and ideally Profile-Guided Optimization (PGO)."

**Current state:**
- `CMakeLists.txt:11` engine — `-O3 -march=native -funroll-loops -flto` (LTO already on)
- `CMakeLists.txt:93` engine_gui — same
- `CMakeLists.txt:138` foxml_suite — same
- `CMakeLists.txt:171` controller_test — same
- `CMakeLists.txt:196` parity_harness — same
- Result: LTO is already in place across all targets. **Only PGO needs orchestration.**

**Step 0:** Add a CMake option `option(USE_PGO_GENERATE "Build with -fprofile-generate (collects profile data)" OFF)` and `option(USE_PGO_USE "Build with -fprofile-use (consumes profile data)" OFF)` near `CMakeLists.txt:18-25` (where existing options live).

**Step 1:** In each target's compile_options block, conditionally append `-fprofile-generate=<dir>` or `-fprofile-use=<dir>` based on the options.

**Step 2:** Add a `build_pgo()` function to `build.sh` (after `build_engine` at line 100) that:
1. Builds engine with `-DUSE_PGO_GENERATE=ON` → `build_pgo_gen/`
2. Runs a representative backtest (`./bin/engine backtest.cfg` on a fixed CSV) to generate `.gcda` files
3. Builds again with `-DUSE_PGO_USE=ON` → `build_pgo/`
4. Updates bin/ symlinks

**Step 3:** Add `pgo` to the case dispatch at `build.sh:174-213` (case at 174, `esac` at 213).

**Code shape (CMakeLists.txt extension, ~10 LOC):**
```cmake
# v5.11.0.D — Profile-guided optimization
option(USE_PGO_GENERATE "Build with -fprofile-generate (instrumented)" OFF)
option(USE_PGO_USE "Build with -fprofile-use (consumes .gcda profile)" OFF)
set(PGO_PROFILE_DIR "${CMAKE_BINARY_DIR}/pgo_profile" CACHE PATH "Where .gcda files live")

function(apply_pgo_flags target)
    # PGO orchestration is GCC-specific (-fprofile-generate/-use syntax).
    # Clang LTO PGO uses -fprofile-instr-generate / -fprofile-instr-use with
    # different filename conventions. Pin to GCC for now; revisit if operator
    # switches toolchains. Silently no-op for non-GCC compilers.
    if(NOT CMAKE_CXX_COMPILER_ID STREQUAL "GNU")
        return()
    endif()
    if(USE_PGO_GENERATE)
        target_compile_options(${target} PRIVATE -fprofile-generate=${PGO_PROFILE_DIR})
        target_link_options(${target} PRIVATE -fprofile-generate=${PGO_PROFILE_DIR})
    elseif(USE_PGO_USE)
        # Note: NOT using -fprofile-correction. We want fail-fast on stale
        # profile data — operator should always train on the same SHA. If
        # a future workflow legitimately needs to ignore mismatches (e.g.
        # cross-version PGO reuse), document the rationale before enabling.
        target_compile_options(${target} PRIVATE -fprofile-use=${PGO_PROFILE_DIR})
        target_link_options(${target} PRIVATE -fprofile-use=${PGO_PROFILE_DIR})
    endif()
endfunction()

# At end of each add_executable section:
apply_pgo_flags(engine)
apply_pgo_flags(engine_gui)
# (skip controller_test + parity_harness — they're test infra, not perf-critical)
```

**Code shape (build.sh extension, ~30 LOC):**
```bash
build_pgo() {
    [[ "$CLEAN_FLAG" == "--clean" ]] && rm -rf build_pgo_gen build_pgo
    PROFILE_DIR="$(pwd)/pgo_profile"
    mkdir -p "$PROFILE_DIR"

    echo "[pgo] step 1/3: instrumented build"
    cmake -B build_pgo_gen -DCMAKE_BUILD_TYPE=Release -DUSE_PGO_GENERATE=ON \
          -DPGO_PROFILE_DIR="$PROFILE_DIR"
    cmake --build build_pgo_gen -j"$JOBS" --target engine

    echo "[pgo] step 2/3: training run"
    if [[ ! -f data/pgo_train.csv ]]; then
        echo "[pgo] WARNING: data/pgo_train.csv not found; skipping training run."
        echo "[pgo] Operator: provide a representative tick CSV at data/pgo_train.csv."
        return 1
    fi
    # Run engine in backtest mode against the training CSV.
    BACKTEST_TICKS=data/pgo_train.csv ./build_pgo_gen/engine backtest.cfg

    echo "[pgo] step 3/3: profile-use rebuild"
    cmake -B build_pgo -DCMAKE_BUILD_TYPE=Release -DUSE_PGO_USE=ON \
          -DPGO_PROFILE_DIR="$PROFILE_DIR"
    cmake --build build_pgo -j"$JOBS"
    link_cfg build_pgo
    update_bin_links
    echo "[pgo] PGO build done at build_pgo/"
}
```

**Verification:**
- Build the PGO binary, run a 10M-tick backtest replay, compare p99 vs the non-PGO `-O3 -flto` baseline. Expect 2-8% improvement on hot paths.
- **Cross-build determinism:** open thread #2 from `plans/SESSION_HANDOFF_2026-05-06.md` says v5.10.0b not yet verified across two builds. Use this ship as the validation: run the v5.9.2 replay-determinism test under both `-O3 -flto` AND `-O3 -flto -fprofile-use`. Bytewise output must match.
- Test addition: smoke-only — verify the `pgo` build target exists and the cmake options compile without error. Full PGO orchestration is integration-tested manually.

**Risk:** Medium. PGO runs require representative training data. If `data/pgo_train.csv` doesn't exist, PGO orchestration warns + skips — not a regression for non-PGO users.

**Caveat (operator):** PGO build takes ~3× the wall-clock of a normal build (instrument → train → rebuild). Not the default; opt-in via `./build.sh pgo`.

**Sub-ship gate:** `./build.sh test` (non-PGO baseline) passes 1636/0 unchanged. `./build.sh pgo` produces a `build_pgo/engine` binary if `data/pgo_train.csv` exists. Cross-build determinism test passes. Tag `v5.11.0.D`.

**Step 0:** Run audit greps as written in the master plan:

**Step 1:** Add `static_assert(!std::is_polymorphic<T>::value)` at the bottom of headers that define key state structs. **Placement rule:** insert immediately after the struct's closing brace + semicolon, BEFORE any free-function definitions in the same header that take the struct as a parameter. This ensures the assertion sits at a fully-formed type point and is co-located with the contract it enforces. Suggested sites:
- `CoreFrameworks/ExecutionCore.hpp` — after the `struct alignas(64) ExecutionCore { ... };` closing at line ~140 (concrete line TBD; spot-check at write time): `static_assert(!std::is_polymorphic<ExecutionCore<64>>::value, "ExecutionCore must remain non-polymorphic — Part 3 invariant (rules §2)");`

`ExecutionCore<64>` is the canonical instantiation across the engine (per `constexpr unsigned FP = 64;` in main.cpp:51). The static_assert needs `<type_traits>` included; add at file top alongside existing includes.

This bakes the runtime-only "no virtual" claim into a compile-time assertion. Future PR that adds a virtual function fails at compile.
