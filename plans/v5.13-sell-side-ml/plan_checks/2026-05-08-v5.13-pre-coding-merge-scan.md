### 8. **ConfigLoadRole audit (buy_class_idx assignment in CoreModelZoo_TryLoadRole)**

**Status:** FUNCTIONING for buy-side; ASSUMPTION for exit-side  
**Files affected:** `ML_Headers/CoreModelZoo.hpp:1277-1290` (primary-role assignment post-load)  
**Plan audit item:** v5.13.0 Step 0 checklist item #1

**Current flow:**
1. `CoreModelZoo_TryLoadRole(..., role="exit", ...)` calls ModelStamp verifier
2. ModelStamp includes model metadata (num_outputs, label_kind, etc.)
3. Loader returns success/fail; handle is populated
4. Primary-role assignment block (1255-1290) checks which role got loaded; assigns primary_handles accordingly
5. For barrier: if num_outputs >= 2, set buy_class_idx = 1 (peak class for PEAK_VALLEY_STABLE)

**Question for v5.13.0 audit:** Does exit_predictor benefit from the same class aliasing?

**Analysis:**
- Exit models are TRAINED on exit probability (binary class typically: exit vs hold)
- PEAK_VALLEY_STABLE 3-class barrier models: class 0 = valley, 1 = peak, 2 = stable
- Exit model: likely class 0 = "don't exit (hold)" or "exit" depending on label_kind
- **If exit model is BINARY:** buy_class_idx should be set to the "exit" class (typically 1)
- **If exit model is TERNARY (unlikely):** operator convention determines class

**Recommendation:**
- Step 0 audit MUST confirm: what label_kind do operator-trained exit models use?
  - If binary → set buy_class_idx = 1 (exit class)
  - If ternary → document operator convention in stamp + loader logic
- Add to v5.13.0.A step: "Audit ModelStamp for exit models in test fixtures; verify buy_class_idx assignment"
- If ModelStamp.label_kind says "exit", loader should automatically infer class (vs requiring operator hand-coding)

**Priority:** MEDIUM (uncertainty about training convention; early audit avoids ship blocker)  
**Effort:** ~5 min grep test fixtures + 5 min decision
