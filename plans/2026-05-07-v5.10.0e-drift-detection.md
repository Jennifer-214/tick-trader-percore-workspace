# v5.10.0e — Drift detection / model retirement (runtime IC monitoring)

**Date:** drafted 2026-05-02; ships after v5.10.0d
**Branch:** `feat/v5.10.0e-drift-detection` (new)
**Predecessor:** v5.10.0d
**Effort estimate:** 4-5 hours
**Hot path:** UNTOUCHED (drift check is slow-path; kill_switch trip is rare)

## Theme

v5.10 design Idea #3. Live engine monitors model prediction quality
(via `ConfidenceScorer` IC) over a rolling 24h window. If IC drops
below operator-configured floor for sustained period, log CRITICAL
and optionally trip kill_switch.

Closes the gap between "model loaded and predicting" and "model
predictions still match reality." Feature distributions can shift
mid-deployment (regime change, market structure change); current
engine has no mechanism to detect or react.

## Items

### #3 — Drift detection cfg + rolling IC + auto-kill (4-5h)

**Phase 1 — Cfg fields (30 min):**

3 new cfg fields:

- `confidence_ic_floor` (float, default 0.02) — minimum acceptable IC
- `confidence_ic_floor_window` (int seconds, default 86400 = 24h) —
  rolling window for IC computation
- `auto_kill_on_drift` (int, default 0) — 0 = WARN only, 1 = trip
  kill_switch when IC below floor for sustained window

Add to `engine.cfg.example` + `backtest.cfg` with comments.

**Phase 2 — Rolling IC infrastructure (1-1.5h):**

`ConfidenceScorer` (ML_Headers/ConfidenceScore.hpp) currently computes
instantaneous IC from a small ring buffer. Extend with:

- Rolling 24h prediction history (configurable window)
- Per-tick IC update (slow-path; existing ConfidenceScorer_Compute
  cadence)
- Trailing-window IC: mean of IC values over the configured window

```cpp
struct ConfidenceScorer<F> {
    // existing fields
    ...
    // v5.10.0e — rolling IC for drift detection
    float ic_history[CONFIDENCE_IC_HISTORY_MAX];   // ring buffer
    int   ic_history_count;                          // <= window
    int   ic_history_capacity;                       // configurable
    float ic_history_mean;                           // current rolling mean
    uint64_t ic_below_floor_since_us;                // for sustained-breach detection
};
```

**Phase 3 — Boot wiring + auto-kill (1h):**

In slow-path tick handler (after `ConfidenceScorer_Compute` updates
IC):

```cpp
if (cfg.confidence_ic_floor > 0.0f &&
    scorer->ic_history_count >= scorer->ic_history_capacity) {
    if (scorer->ic_history_mean < cfg.confidence_ic_floor) {
        if (scorer->ic_below_floor_since_us == 0) {
            scorer->ic_below_floor_since_us = current_time_us;
        }
        uint64_t elapsed_s = (current_time_us - scorer->ic_below_floor_since_us) / 1000000;
        if (elapsed_s >= (uint64_t)cfg.confidence_ic_floor_window) {
            // Sustained breach
            Health_LogCriticalRateLimited(
                "[drift] core %d IC=%f below floor %f for %llds — model retired\n",
                core_id, scorer->ic_history_mean, cfg.confidence_ic_floor, elapsed_s);
            if (cfg.auto_kill_on_drift) {
                // Per /plan-check audit 2026-05-02: no named
                // EventLoopState_TripKillSwitch() exists. Set the
                // OMS field directly (matches v5.5.x kill_switch
                // mechanism).
                state->oms->kill_switch_tripped = 1;
            }
        }
    } else {
        scorer->ic_below_floor_since_us = 0;  // reset
    }
}
```

**Phase 4 — ML Status panel display (1-1.5h):**

Add row to `MLStatusPanel.hpp`:

```
Drift: IC=0.018 (24h avg) below floor 0.02 — 5h elapsed
       [auto-kill armed: NO]
```

Color: yellow when below floor but not sustained; red when sustained
breach; green when above floor.

**Phase 5 — Tests (1-1.5h):**

- Healthy IC (0.05) + floor 0.02 → no drift fired
- IC drops to 0.01 + floor 0.02 → ic_below_floor_since_us set
- Sustained 24h+ → CRITICAL log fires, kill_switch trips (if enabled)
- IC recovers above floor → ic_below_floor_since_us reset
- No false positives during warmup (IC undefined)

## Risk register

| Risk | Mitigation |
|---|---|
| Threshold tuning is empirical; default 0.02 may be wrong for some symbols | Default is observation-baseline; operator recalibrates per asset |
| False positives during warmup (IC undefined) | Skip drift check until `ic_history_count >= ic_history_capacity` |
| Sustained-breach window too aggressive (24h short on weekends) | Default is operator-tunable; defer wisdom to operator |
| auto_kill_on_drift trips during normal regime change → unwanted halts | Default off; operator opts in deliberately |
