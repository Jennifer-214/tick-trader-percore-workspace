## Theme

v5.11.62 shipped a TACTICAL patch: when a multi-horizon training run
saves models under role names other than `buy_signal`, the loader
memcpy's the ModelHandle struct from the source role array (e.g.
`ezoo->barrier[i]`) into `ezoo->buy_signal[i]` slot, marks the copy
as `borrowed=1`, and sets `buy_class_idx=1`. All call sites
(`buy_signal_count`, `MLStrategy`, `StrategyParameters`) work
unchanged.

The cleaner refactor (deferred from v5.11.62 ship): replace memcpy
alias with direct `primary_handles` indirection. Two ModelHandle
structs no longer reference the same XGBoost booster; loader picks
primary role at end of `LoadFromCfg`/`AutoDetect`; `MLStrategy.hpp`
predict path reads `ezoo->primary_handles` directly.

This is the v5.11.62 deferred-items entry that says
**"Re-trigger conditions: 1. Operator adds a 4th label kind whose
buy semantics aren't 'extract one class probability' (e.g. multi-
class exit signal that combines class probabilities..."** — Phase
3.A's composite-signal extraction is exactly that. Re-trigger fires.

## Phase A — `Model_Predict_AtClass` helper (`v5.12.3.E.1`)

**Goal:** Decouple class-extraction concern from role concern. New
helper that predicts at a specific class index.

```cpp
// ML_Headers/ModelInference.hpp adjacent to Model_Predict at :507
// v5.12.3.E: class-explicit predict. Strategy doesn't need to know
// role-name semantics; it just asks for "this model's class N".
template <unsigned F>
inline float Model_Predict_AtClass(ModelHandle<F>* m,
                                    const float* features,
                                    int num_features,
                                    int class_idx) {
    // ... existing Model_Predict body but use class_idx instead of
    // m->buy_class_idx for the final extraction
}
```

`Model_Predict` becomes a thin wrapper:
```cpp
template <unsigned F>
inline float Model_Predict(ModelHandle<F>* m,
                            const float* features, int num_features) {
    return Model_Predict_AtClass(m, features, num_features,
                                 m->buy_class_idx);

```

**Tests** (+2): `Model_Predict_AtClass(m, f, n, m->buy_class_idx)` =
`Model_Predict(m, f, n)` bytewise; class_idx out-of-bounds clamps to
buy_class_idx (defensive).

## Phase B — Loader picks primary role; populate `primary_handles` directly (`v5.12.3.E.2`)

**Goal:** End of `EnsembleModelZoo_LoadFromCfg` /
`EnsembleModelZoo_AutoDetectFromDir`, pick primary role + populate
`primary_handles` array. NO memcpy from source role to buy_signal
slot. NO `borrowed` flag needed.

**Step 0:** v5.11.62 already added these fields to `EnsembleModelZoo`
at `ML_Headers/CoreModelZoo.hpp:790`-area:
- `ModelHandle<F>* primary_handles;`
- `int primary_count;`
- `int primary_target_class;`
- `char primary_role_name[16];`

This ship POPULATES them properly (instead of the memcpy alias path).

```cpp
// ML_Headers/CoreModelZoo.hpp at end of LoadFromCfg / AutoDetectFromDir
// v5.12.3.E: pick primary role (no more memcpy alias)
if (ezoo->buy_signal_count > 0) {
    ezoo->primary_handles    = ezoo->buy_signal;
    ezoo->primary_count      = ezoo->buy_signal_count;
    ezoo->primary_target_class = 0;  // binary buy_signal class 0
    snprintf(ezoo->primary_role_name, 16, "buy_signal");
} else if (ezoo->barrier_count > 0) {
    ezoo->primary_handles    = ezoo->barrier;
    ezoo->primary_count      = ezoo->barrier_count;
    ezoo->primary_target_class = 1;  // PEAK class
    snprintf(ezoo->primary_role_name, 16, "barrier");
} else if (ezoo->regime_count > 0) {
    ezoo->primary_handles    = ezoo->regime;
    ezoo->primary_count      = ezoo->regime_count;
    ezoo->primary_target_class = 0;  // first class default
    snprintf(ezoo->primary_role_name, 16, "regime");
} else {
    // no models loaded; primary_handles stays nullptr
}
```

**Tests** (+4):
1. buy_signal role only → primary_handles points to buy_signal,
   primary_target_class = 0
2. barrier role only → primary_handles points to barrier,
   primary_target_class = 1
3. regime role only → primary_handles points to regime
4. multiple roles → buy_signal wins precedence

**Tag:** `v5.12.3.E.2`.

## Phase C — Replace `buy_signal_*` reads with `primary_*` (`v5.12.3.E.3`)

**Goal:** 5 call sites currently read `ezoo->buy_signal[i]` directly.
Replace with `ezoo->primary_handles[i]`. Per the deferred-items doc
enumeration, the touched files are:
- `ML_Headers/CoreModelZoo.hpp` — struct fields + LoadFromCfg/AutoDetect (already done by Phase B)
- `Strategies/MLStrategy.hpp` — predict path
- `Strategies/StrategyParameters.hpp` — Bandit dispatch
- `CoreFrameworks/ShardedSnapshot.hpp` — population of n_horizons
- `DataStream/EngineTUI.hpp` — PerCoreSnap field rename or addition
- `GUI/SettingsPanel.hpp` — Settings UI display

**WAIT — strategy code change?** Per v5.11.62 invariant, strategy
code MUST NOT change. Re-reading the deferred-items doc: the cleaner
refactor DOES touch `MLStrategy.hpp` / `StrategyParameters.hpp` to
use `primary_*` instead of `buy_signal_*`. That's **a 1-line rename
within strategy code**, not a logic change.

**Reconcile:** v5.11.62 invariant is "strategy code is role-AGNOSTIC"
— it doesn't know WHICH role is primary. Renaming `buy_signal` →
`primary` in strategy code is fine — the strategy STILL reads "the
primary handle list" without knowing what's behind it. The rename
makes the code MORE role-agnostic, not less.

**Step 0:** `git diff` on the 5 sites should show: identifier renames
only, no logic changes. Tests verify runtime is bytewise-preserved.

**Tests** (+3): bytewise output preservation across `/parity-check`;
strategy code edits are pure renames; predict-path produces same
output on same inputs.

**Tag:** `v5.12.3.E.3`.

## Phase D — Drop `borrowed` flag + memcpy alias (`v5.12.3.E.4`)

**Goal:** Now that all reads are via `primary_handles`, the memcpy
alias path in v5.11.62's loader is dead code. Remove it. Drop the
`borrowed` flag from ModelHandle (since no handle is ever a borrow
copy now).

**Risk note:** the `borrowed` flag is single-check-site
(`Model_Free`) per the deferred-items doc. Removing it touches that
single site: `Model_Free` no longer needs to skip dlclose'd
boosters. Mechanical change.

**Tests** (+2): `Model_Free` correctness on multiple roles loaded
(no double-free, no leak); `git grep "borrowed" ML_Headers/` shows
no remaining references.

**Tag:** `v5.12.3.E.4`.
