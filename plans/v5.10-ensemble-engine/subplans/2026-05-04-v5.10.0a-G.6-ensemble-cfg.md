## Theme

Cfg fields for the ensemble feature. Mostly fallbacks since G.5
auto-detects horizons from disk; these let operator tune behavior
per-core.

## Items

### #1 — Per-core fields (~30min)

Add to `ControllerConfig<F>::CoreOverrides` (extend the existing
`PER_CORE_OVERRIDE_FIELDS` X-macro per v5.8.1a registry pattern):

| Field | Type | Default | Purpose |
|---|---|---|---|
| `horizon_list` | string (CSV) | "" (empty) | Per-core horizon override. Falls back to global cfg.horizon_list. |
| `ensemble_blend_mode` | string | "weighted" | "weighted" / "selection". Selection = G.4 argmax-confidence; weighted = G.7 bandit blend. |

Adding to `PER_CORE_OVERRIDE_FIELDS(X)` X-macro:
```cpp
X(horizon_list, char[128], "")
X(ensemble_blend_mode, char[16], "weighted")
```

(X-macro auto-handles parser entries `core_N_<field>` per v5.8.1a.)

### #2 — Global fields (~20min)

Add to `ControllerConfig<F>` body:

| Field | Type | Default | Purpose |
|---|---|---|---|
| `ensemble_bandit_eta` | float | 0.1 | Bandit-Exp3 learning rate; higher = faster adaptation, more variance |
| `ensemble_min_warmup_predictions` | int | 100 | Per-regime predictions before weights trusted (uniform until then) |

Plus the parsing entries for `CFG_PARSE_*` macros in
`ControllerConfig_Load`.

### #3 — engine.cfg.example documentation (~10min)

New section in `engine.cfg.example`:

```ini
#==============================================================================
# MULTI-HORIZON ENSEMBLE (v5.10.0a.G.5+)
#==============================================================================
# When you train N models for different forward-tick horizons (Train Multi-
# Horizon button in foxml_suite), engine boot auto-detects them from disk
# IF the model dir is set. Engine then blends per-tick predictions across
# all N horizons via Bandit-Exp3 weighted average, with per-regime weights
# that learn from actual outcomes.
#
# Default empty horizon_list = single-model deployment (no ensemble; bytewise-
# identical to pre-v5.10.0a behavior).

# Comma-separated forward-tick horizons (1..1,000,000 ticks each, max 8).
# Empty = single-model. Operator setting populates global; per-core override
# via core_N_horizon_list.
horizon_list=

# Per-core override (when non-empty, takes priority over global horizon_list)
# core_0_horizon_list=100,500,1000

# Per-core blend mode: weighted (default; bandit) or selection (argmax confidence)
# core_0_ensemble_blend_mode=weighted

# Bandit learning rate. Higher = faster adaptation, more variance.
# Range: 0.01-1.0; default 0.1 is conservative.
ensemble_bandit_eta=0.1

# Per-regime predictions before bandit weights trusted (uniform during warmup).
# Lower = trust faster, higher noise; higher = slower convergence, less noise.
ensemble_min_warmup_predictions=100
```

## Risk register

| Risk | Mitigation |
|---|---|
| Cfg field name conflict with v5.10.0a-bugfix2's UI horizon_csv | UI field is `state->ui_horizon_csv` (TrainingPanel); cfg field is `cfg.horizon_list` — different namespaces |
| Per-core override doesn't fall through to global | Test G.6.6 verifies fallback; uses `cfg.core_overrides[i].horizon_list[0] != '\0' ? ... : cfg.horizon_list[]` pattern |
| String-typed cfg fields awkward for X-macro | `char[16]` / `char[128]` are POD-able; X-macro handles fixed-size char arrays via `strncpy` parser |
