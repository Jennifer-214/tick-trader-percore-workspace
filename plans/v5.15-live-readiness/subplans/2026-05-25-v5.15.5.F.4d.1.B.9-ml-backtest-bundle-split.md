## Design space + future-oriented choices

### Decision A — CoreModelZoo sub-file boundaries

| Sub-file | Owns | Estimated LOC | Dependencies |
|---|---|---|---|
| `Types.hpp` (CONDITIONAL — only if struct defs exceed natural sub-file scope) | `CoreModelZoo<F>` + `EnsembleModelZoo<F>` struct definitions | ~200-400 | None |
| `BuyBandit.hpp` | `_InitBandits`, `_SaveBanditState`, `_LoadBanditState`, EXP3 reward path | ~500-700 | Types |
| `ExitBandit.hpp` | `_InitExitBandits`, `_SaveExitBanditState`, `_LoadExitBanditState` — sister to BuyBandit per buy/exit symmetry | ~500-700 | Types |
| `Thompson.hpp` | Thompson bandit init / Save / Load (both sides) + sample logic + posterior update | ~500-700 | Types |
| `Ensemble.hpp` | EnsembleModelZoo orchestration + hot-swap dispatcher (single-zoo + ensemble) | ~600-900 | Types + BuyBandit + ExitBandit + Thompson |
| `PostLoad.hpp` | FOREACH_ENSEMBLE_POST_LOAD walker + per-row PostLoadSetup applications | ~300-500 | Types + Ensemble |

**Buy/Exit/Thompson axis decision:**

Could organize differently:
- (a) Per-side files (Buy.hpp + Exit.hpp; each contains EXP3 + Thompson for that side)
- **(b) Per-algorithm files (BuyBandit.hpp + ExitBandit.hpp + Thompson.hpp)** ← CHOSEN — axis = algorithm; preserves sister symmetry between BuyBandit ↔ ExitBandit (CLAUDE.md sister pattern); Thompson is algorithmic-orthogonal
- (c) Single Bandits.hpp + Thompson.hpp (collapsed) — rejected; single Bandits.hpp would exceed threshold

### Decision B — Types.hpp inclusion (conditional)

If `CoreModelZoo<F>` + `EnsembleModelZoo<F>` struct definitions are ~200-400 LOC, extract to `Types.hpp` (cleanest dependency: included first). If smaller (~100-200), inline at top of `Ensemble.hpp` (acceptable; reduces sub-file count by 1).

Decided at Phase B Step B.1 after measuring.

### Decision C — BacktestEngine sub-file boundaries

| Sub-file | Owns | Estimated LOC | Dependencies |
|---|---|---|---|
| `Run.hpp` | `Backtest_RunFullValidation` orchestrator (RFV main entry; per-horizon dispatch) | ~800-1,200 | Split + StampEmit |
| `Split.hpp` | `HeldOutSplit` + `ValidationSplit` helpers (train/test/heldout slicing) | ~400-600 | None internal |
| `StampEmit.hpp` | RFV stamp emit pathway (calls `tt::stamp_write_for_model` per horizon; uses `STAMP_MODEL_CONST_AUTOPOPULATE`) | ~400-600 | Split (uses split bounds for stamp metadata) |

Shim include order: `Split.hpp` (no deps) → `StampEmit.hpp` (depends on Split) → `Run.hpp` (depends on both).

### Decision D — Persistence file path discipline

CoreModelZoo writes persistence files:
- `buy_thompson_state.json` / `exit_thompson_state.json` (per `.F.4d.1.A.7` rename per TECH_DEBT-084)
- `buy_bandit_state.json` / `exit_bandit_state.json` (per side)
- `ensemble_state.json` (per ensemble)

These file path constants stay with their owning sub-file (BuyBandit.hpp / ExitBandit.hpp / Thompson.hpp / Ensemble.hpp). NO Common.hpp for paths — each side owns its constants.

**Verify Phase A:** `rg "\.json" ML_Headers/CoreModelZoo.hpp` enumerates all persistence paths; verify each lands in correct sub-file per Decision A.

### Decision E — Friend declaration audit (M1 per .B.6 codification)

CoreModelZoo<F> may friend Thompson types or Ensemble accessors. Phase A audit:
- `rg "friend" ML_Headers/CoreModelZoo.hpp Backtest/BacktestEngine.hpp`
- Resolve any cross-sub-file friend pairs per Decision E from `.B.8` (refactor or co-locate)

### Decision F — Template instantiation across sub-files

CoreModelZoo<F> + EnsembleModelZoo<F> templated on F (FPN<64>). Member functions distributed across sub-files. Template instantiation happens per-TU per `#include` chain.

**Risk:** If BuyBandit.hpp defines `CoreModelZoo<F>::SaveBanditState`, that definition must be visible at instantiation site. Shim re-export ensures visibility — any TU including the shim sees ALL member function definitions.

**Mitigation:** Phase B build verify after each sub-file extract catches any instantiation gap immediately.

### Decision G — Decoupling positioning

`CoreModelZoo/Ensemble.hpp` becomes natural training-binary boundary at v6.0 (per decoupling roadmap). `BacktestEngine/StampEmit.hpp` becomes the training-side wire-format boundary.

**Positioning:** ⬆️ POSITIVE for v6.0 viewer split.
