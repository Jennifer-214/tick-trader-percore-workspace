### Decision 9 — Per-core gate semantics (REFRAMED at v1.2 — ARCHITECTURAL CLARIFICATION, NO ACTION)

v1.1 framed this as a Class 18 closure (flat-vs-per-core fields treated as parallel duplication; Decision = DELETE flat fields). **Coding-time investigation at Step 0 reversed the framing — the duality is INTENTIONAL, not Class 18.**

**Architectural pattern at `ControllerConfig.hpp:200-224`** (documented in the source):
- **Global flat fields** (e.g., `cfg.risk_degradation_curve` at `:710`, `cfg.bandit_algorithm` at `:1319`, `cfg.ridge_lambda` at `:806`): the BASE cfg
- **Per-core fields** in `PerCoreCfg<F>` (auto-gen from `FOREACH_PER_CORE_CFG_FIELD`; stored in `cfg.cores[N]` array): OVERRIDE values
- **Override semantic:** `0 = inherit global cfg.<field>; non-zero = override that core`
- Engine consumer at strategy execution time reads `(cfg.cores[N].<field> != 0) ? cfg.cores[N].<field> : cfg.<field>` (effective value)

**Stamp emit is engine-wide.** `Stamp_AssembleAndEmit<F>(const ControllerConfig<F>& cfg, ...)` at `ML_Headers/StampHelper.hpp:140` takes only the global `ControllerConfig<F>`. No `core_id` parameter; no per-core scope. Training (`Backtest/BacktestPanels.hpp:3206+` `train_model_worker_fn`) is engine-wide; uses `results->config_used` = global cfg snapshot. Models are then DEPLOYED per-core (via `core_N_model_dir=...` cfg) but training + stamping is global.

**Conclusion:** flat fields are the canonical global cfg surface that stamp emit walks. Legacy `FOREACH_STAMP_BOUND_CFG` row at `StampBoundCfgRegistry.hpp:148` reads `cfg.risk_degradation_curve` flat directly — that's intentional + correct for "training-time engine-wide cfg snapshot". The new framework's `cfg.<name>` access pattern at `CfgGateRegistry.hpp:211-223` preserves this semantic.

**HIGH-CONV-E reframe rationale:** the audit's "if core-1 has bandit_algorithm=4 but global=0, stamp won't emit thompson_exp3_blend_alpha for core-1 → silent training/serving drift" example assumes per-core training emits per-core stamps. **Per-core training doesn't currently exist** — all training is engine-wide; stamps reflect global training cfg. Per-core override applies at RUNTIME strategy execution, not at stamp emit.

**No action needed at `.B.2`.** Architecture is correct as-is. v1.2:
- **REMOVES Step 1.5 entirely** (flat-field deletion would have BROKEN engine-wide stamp emit semantic + legacy walker access pattern)
- **ADJUSTS Step 5.0 macros** `COHORT_GATE_SOFTRISK_ENABLED` → `(cfg.risk_degradation_curve != 0)` + `COHORT_GATE_BLENDED_STATE_4` → `(cfg.bandit_algorithm == 4)` — flat access matching legacy `FOREACH_STAMP_BOUND_CFG` emit_when col semantic
- **DOCUMENTS the override-inherit pattern** explicitly in `cfg-scope-discipline.md` amendment at ship close (so future audits don't misread the same way)

**Future-feature note (not deferred debt):** If per-core training is ever added (each core trains its own model with effective cfg), `Stamp_AssembleAndEmit` would gain a `core_id` parameter + walk per-core effective cfg (combining global + per-core override). That's a future architectural addition, not deferred debt for `.B.2`. Documented in postmortem only.
