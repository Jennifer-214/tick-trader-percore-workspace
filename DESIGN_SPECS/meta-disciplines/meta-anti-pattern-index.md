# Meta anti-pattern index (the META parallel of RECURRING_BUG_PATTERNS)

**What this is.** A single greppable HOME for NON-code recurring errors — the mistakes made in *audit-reasoning, planning, and workspace-hygiene*, plus *cascade-propagation* misses — with the same scan parity that CODE anti-patterns have via `DOCS/RECURRING_BUG_PATTERNS.md` (Classes 1-36) + `/bug-check`. Landed at `.E.0.2` (D-75/D-76); it is the catalog half of the meta-error-tracking subsystem.

## It is an INDEX, not a new class-series (Decision A)

This catalog does **not** re-number or duplicate the meta-disciplines that already exist. It **aggregates + points to** them, and **adds** the org/planning/workspace shapes that lacked a home:

| Existing meta-shape family | Canonical home | Relationship here |
|---|---|---|
| **M1-M7** audit-methodology gaps | `DOCS/DESIGN_PHILOSOPHY.md` § 11.5 | POINTED-TO (no re-number) |
| **B14-B19** implementation-blindspot pillars | `meta-disciplines/implementation-layer-blindspot-taxonomy.md` | POINTED-TO |
| **Workspace-hygiene checks** | `/capture-audit` (11 checks) + `/metadata-audit` | POINTED-TO |
| **Cascade / sister-cohort** | `feedback_sister_cohort_amendment_completeness` + M7 | POINTED-TO (CP-1 makes it mechanical) |
| **NEW org / planning / workspace / audit-reasoning shapes** | *here* | INDEXED (entries below) |

Why an index, not a parallel registry: per `canonical-sister-extension-discipline` + `feedback_framework_layer_payoff_diminishing_returns` — re-numbering M/B would be a duplicate registry (Class-21-shaped at the meta layer). The index gives scan parity *without* the duplication.

Why private (Decision B): unlike `RECURRING_BUG_PATTERNS.md` (public; code patterns are safe to publish), this index references private `plans/` / `handoffs/` / `decision-logs/` and internal process → it lives in `DESIGN_SPECS/meta-disciplines/` (private via the workspace), alongside the M1-M7 narrative. The *parity* with the code catalog is in STRUCTURE + FUNCTION (a scannable catalog with a scan), not in location.

## Schema

Each NEW entry: **ID** (category-prefixed — `AR` audit-reasoning / `PL` planning / `WH` workspace-hygiene / `CP` cascade-propagation) · **Shape** · **Existing home** (memory / M-N / B-N / Class-N, or NEW) · **Detection** (mechanical grep | reflection prompt) · **Enforced by** (which mechanism) · **Source**. Each per-shape detail carries a **False-positive surface** (M3 — distinguish a legitimate sibling from the anti-pattern). Pointed-to M/B entries keep their own IDs; this index only references them.

## How the three mechanisms share this schema

- **Piece 3 — `/close-session` harvest (WRITES).** At session close, the structured-reflection Stage runs the AR/PL/WH/CP prompts; recurring shapes → new rows here (or a recurrence bump + a new Source line on an existing row). The session's own pushbacks/errors are the highest-signal seed corpus (`feedback_operator_pushback_as_audit_signal` § generative dimension — this seed cohort is 3/5 from one hour of `.E.0.1` pushback).
- **Piece 2 — `/capture-audit` Check 12 (READS the CP rows).** CP-1 is the mechanical one: on a sentinel-block amendment, grep its key terms across the corpus → flag un-propagated refs.
- **Piece 4 — hardened `/precoding-audit-gate` (READS all rows as checks).** Mechanical rows (CP-1/WH-1/WH-2) run as deterministic Stage-0 greps; reflection rows (AR-1/AR-2) run as the verification/completeness-critic pass prompts. As the harvest grows this table, the gate auto-gains coverage — the memory→catalog→gate→harvest loop.

## Per-shape detail (+ false-positive surface, M3)

### AR-1 — categorical risk-dismissal over an un-enumerated set
A risk is judged "low likelihood" or scope is bounded by asserting a property over a *set* whose members were never listed and checked. The real risk hides in the unverified member. **Fix:** enumerate the set, verify each, name any non-conformer. **False-positive surface:** a set that is *genuinely* enumerated + verified (then the categorical claim is sound) — AR-1 is only the *un*-enumerated case. Sister: Class-33 (consumer-enumeration) lifted to the risk-assessment layer.

### AR-2 — over-generalized spec/definition
A spec or gate definition encodes a universal ("all ops", "every field", "always identical") that was never checked against the actual set, so a member silently violates it. **Fix:** enumerate at definition time; scope the claim to the verified members. **False-positive surface:** a universal that IS exhaustively true by construction (e.g. a `static_assert` over a closed enum) — not over-generalized. An instance of AR-1 at the spec layer.

### CP-1 — cascade-not-propagated
An amended decision/spec/definition leaves stale references in sibling docs (handoffs, decision-logs, plans, memories) that still cite the old form. **Fix:** the `/capture-audit` Check 12 mechanical scan. **False-positive surface:** a term legitimately referenced in many places that does NOT need updating (a historical-record citation, a postmortem describing the old state) — Check 12 must distinguish "stale forward-looking ref" from "truthful historical record" (sister to `feedback_archived_changelog_preservation_discipline` + `feedback_terminology_evolution_bridge_not_history_rewrite`).

### WH-1 — memory-link convention drift
`[[slug]]` cross-links written with the front-matter `name:` form (kebab) when resolution is by *filename* (`feedback_*` / `user_*` / `project_*`). **Fix:** grep `[[...]]` tokens; flag any that don't match a memory filename. **False-positive surface:** an intentional forward-link to a not-yet-written memory (the memory system explicitly allows `[[name]]` that doesn't resolve yet) — flag as INFO, not error.

### WH-2 — stale index pointer
An always-loaded index (MEMORY.md, CLAUDE.local.md sprint-state, MASTER) names a state that the latest ship/decision superseded. **Fix:** diff the index's claimed state against `Version.hpp` / HEAD / latest ship. **False-positive surface:** an index intentionally describing a frozen baseline (a "last shipped" anchor) rather than the live tip.

### WH-3 — independent double-capture / parallel-artifact duplication *(harvest 2026-05-31)*
Two parties (operator + agent, or two agents) independently create a doc/artifact for the SAME content — each doing document-as-you-go in good faith — producing a DUPLICATE that then drifts (a SSoT violation at the doc layer; Class-21-shaped at the doc layer). **Fix:** before creating a capture doc, grep for an existing one (check-for-existing); on a detected collision, consolidate to the SUPERSET + delete the lesser dup; surface at close/sync. **False-positive surface:** two artifacts that merely LOOK similar but are legitimately distinct — e.g. a predecessor ship's `.E.0.1` new-fn-designs sidecar vs THIS ship's `#11` one (different ships, both canonical) — WH-3 is only the SAME-content duplication, not same-shape-different-scope siblings. Sister: `single-source-of-truth-discipline` + `canonical-sister-extension-discipline` + WH-1/WH-2 (the workspace-hygiene family). Source: this close — the dated-vs-undated new-function-designs sidecars (caught at the pre-sync sweep, not before).

### PL-1 — under-applied auto-pick-future-oriented *(first harvest entry)*
Defaulting to the lighter/faster structural option when the corpus's own principles already imply the heavier/more-structural one — leaving the operator to surface it. **Fix:** at a structural fork, explicitly check the corpus (D-73 / guard-matrix / heavier-default / `feedback_auto_pick_future_oriented`) BEFORE recommending the lighter default. **False-positive surface:** when the lighter option is genuinely correct because the heavier one is over-engineering past the inflection (`feedback_framework_layer_payoff_diminishing_returns`) — PL-1 is *only* mis-defaulting AGAINST a corpus principle, not every time the lighter option wins. Home: `feedback_auto_pick_future_oriented` (violation-direction sibling).

### PL-2 — agent-self-skip of a thorough step *(harvest)*
Skipping a review/audit/check because the AGENT judges it redundant/trivial/already-covered — the efficiency-instinct quietly erodes coverage and the un-covered part stays unverified (a hole). **Fix:** thorough steps fire by DEFAULT; skip ONLY on explicit operator instruction (a flag / stated "skip it"); a review fires on UN-reviewed work regardless of prior passes on OTHER work. **False-positive surface:** an operator-EXPLICIT skip (`--no-review`, "skip this") is legitimate — PL-2 is *agent*-discretion skip, not operator-discretion. Home: `feedback_never_skip_thoroughness_unless_explicit`; sister: `feedback_heavier_default_audit_posture_for_capital` (light is earned) + AR-1 (verify before you conclude).

### AR-3 — documentation-accepted-as-verification *(harvest 2026-05-30)*
A load-bearing invariant is asserted in a comment/doc and treated as evidence it holds — but no code establishes it AND no guard enforces it, so it "works" only by ambient luck. **Fix:** load-bearing invariants get a guard (CI / `static_assert` / runtime), never a comment; at audit, flag any comment-asserted invariant lacking establishing-code + a guard (= the guard-coverage-matrix "no convention-only on critical surfaces" discipline). **False-positive surface:** a comment *describing* an invariant that IS established + guarded elsewhere (documentation, not the sole mechanism) — AR-3 is only the *unbacked* assertion. CODE-side sibling: the phantom-invariant Class in RECURRING_BUG_PATTERNS. Source: the locale `"engine boot pins LC_NUMERIC"` comment with no boot pin + no guard (D-92).

### AR-4 — verification-by-proxy *(harvest 2026-05-31)*
A guard or CI check is judged to WORK because it was exercised a way that isn't its real trigger — invoked
directly rather than through the real git hook, or seen GREEN-on-clean rather than watched FAIL on an
injected regression. So a dead guard reads as live (the worst kind: it reports safety while providing
none). **Fix:** verify a guard by watching it go RED on its target regression, through its REAL trigger;
ship every standing gate with a negative self-test that does exactly that — `tools/check_determinism_selftest.sh`
is first canonical (injects each determinism regression, asserts the gate RED, AND checks `core.hooksPath`
still points at the tracked hook so the §3 config-drift can't recur). **False-positive surface:** a guard
whose real trigger genuinely IS direct invocation (an on-demand tool with no hook) — then direct invocation
is the real trigger and there's no proxy. AR-4 is only the *mismatch* between the verification path and the
real one. Sister: AR-1 (conclusion-before-verification — AR-4 is its CI-guard special case); CODE-side it
pairs with Class 38 (phantom invariant — a guard that doesn't guard is a phantom in executable form).

### AR-5 — evidence-destroying instrumentation *(harvest 2026-06-09, A.5 close)*
The measurement pipeline itself discards the evidence it summarizes: a count, verdict, or tail survives,
but the lines that JUSTIFY it are transformed or gone — so a surprising result can't be inspected, a wrong
one can't be falsified, and (worst case) the instrumentation MANUFACTURES a phantom (the `rg -rln`
display-replacement read as a live file-rewriter). Thrice in one close-out, three costumes, one shape.
**Fix:** capture full, THEN summarize — `cmd > log 2>&1` (or `tee`) first; every count/tail/grep derives
from the kept artifact; never put a lossy transform (`| rg -c`, `| tail`, `--replace`) in the capture path.
Verify the VERIFIER's invocation (flag parsing, cwd, ignore-rules) before believing surprising output.
**False-positive surface:** a summarizing pipe over output that IS separately kept (tee'd, task-logged, or
re-derivable from an idempotent re-run at zero cost) is fine — AR-5 is only when the summary is the SOLE
survivor of evidence that mattered. Sisters: AR-1 (summarize-and-drop — there the AUTHOR drops members;
here the PIPELINE does), AR-4 (verification-by-proxy), `feedback_paste_tool_output_dont_summarize`.

### AR-6 — shared-epoch/theme mistaken for shared-root (false-cluster) *(harvest 2026-06-10)*
Collapsing DISTINCT findings into ONE cluster / ONE fix because they share a remediation EPOCH (all land at the same ship) or a THEME (all "concurrency near the OMS"), when their ROOT MECHANISMS differ — so a single fix-shape gets proposed for items that each need a different one, mis-routing the fixes. **Fix:** before asserting a cluster or shared-root, name EACH member's actual mechanism + verify the proposed fix closes EACH; a shared epoch/theme is NOT a shared root. Read each member's code; don't infer the root from the grouping. **False-positive surface:** items that genuinely DO share a root+fix (verified per-member) are a legitimate cluster — AR-6 is the UN-verified collapse, not every grouping. Sister: AR-1 (property over an un-enumerated SET — the risk-DISMISSAL variant; AR-6 is the constructive CLUSTER variant), AR-2 (over-generalized spec/definition), `adversarial-multi-agent-audit-methodology.md` (a 3-agent refute is what catches it). Source: `.E.0.10` 2026-06-10 — agent lumped persist-8 (stale-flag) + conc-5 (SPSC-ring race) + persist-dod-1 + kill-switch (torn-read) into "one root, one seqlock fix"; only the latter two shared the root (a seqlock fixes neither persist-8 nor conc-5). Operator pushback ("are you making stuff up?") + a 3-agent refute caught it; corrected in the register + `cross-thread-multiword-read-consistency-discipline.md` § "What this is NOT."

### AR-7 — structural-pattern false-completeness *(harvest 2026-06-10)*
Trusting a structural pattern (registry / SSoT helper / walker / auto-flow) to give TOTAL coverage, and missing what lives OUTSIDE its reach — open-coded siblings the SSoT doesn't capture, pointer-target state a value-field registry can't see, separately-allocated state a reset loop doesn't touch. The pattern's completeness is only for what it INDEXES; the gap is the un-indexed neighbor. **Fix:** when auditing a registry/SSoT/walker for completeness, explicitly enumerate what it CANNOT reach (grep for open-coded instances of the same computation; list pointer-targets / separately-allocated state) — coverage-of-the-indexed is NOT coverage-of-the-class. **False-positive surface:** a pattern verified to be the SOLE site (no out-of-reach neighbors) is genuinely complete — AR-7 is trusting completeness without checking the perimeter. Sister: AR-1 (categorical claim over an un-enumerated set — AR-7 is the structural-pattern specialization), AR-6 (false-cluster — both are "the grouping/pattern misled me"), M1 (sister-registry parity), `feedback_single_source_of_truth_discipline`. Source: `.E.0.10` — D-190 (P&L gross open-coded OUTSIDE the `Money_FillGross` SSoT) + persist-8 (the ExecutionCore hot mirror is a pointer-target OUTSIDE the `CORE_CTX_RESET` value-field registry). 2 instances, same shape: the structural pattern looked complete; the gap was the thing outside its reach. (Harvested at the `.E.0.10` close adversarial audit — the register named it a candidate but the first close pass harvested only AR-6.)

### AR-8 — self-attested verification (declaring "verified" from a self-check) *(harvest 2026-06-11)*
Declaring work VERIFIED / "adversarially verified" / done on the strength of a SELF-check — the maker grading its own artifact — without the INDEPENDENT refute (a fresh agent prompted to FIND/REFUTE, which the maker does not grade). A self-check (and a green test) confirms the happy path; it says nothing about COVERAGE or about the values the maker never thought to question. The self-check confirms; only an independent adversary refutes. **Fix:** verification of judgment/capital/correctness work is INDEPENDENT BY DEFAULT — a fresh FIND/REFUTE agent (or N-of-M quorum) the maker doesn't grade; "I verified" is not a verification, the independent pass is. Self-check is the opt-out: operator-explicit OR in-line-justified with a stated reason. **False-positive surface:** a genuinely MECHANICAL check (a deterministic tool, a re-run of a frozen golden) is verified by RUNNING it, not by an independent agent (`feedback_independence_for_judgment_not_mechanical`) — AR-8 is the JUDGMENT surface (test completeness, finding-correctness, claim-soundness) where self-attestation masquerades as verification. Sister: AR-3 (documentation-accepted-as-verification), AR-4 (verification-by-proxy), `feedback_passing_test_is_not_verification`, `feedback_adversarial_framing_default_for_checks`, **TECH_DEBT-164** (the structural enforcement — adversarial-default wiring + auto-fire on capital-done). Source: `.E.0.10` 2026-06-11 — oms-ts-1 declared "adversarially verified" from a self-check; a 3-agent INDEPENDENT refute (fired only when the operator said "run an adversarial audit") found 3 coverage gaps (D-190 overclaim, unasserted maker/taker bucket, no loss/sign case). THIRD instance in one session (doc-restructure, skill-cohort, oms-ts-1) — each caught only by operator pushback, which IS the signal that the verification must be DEFAULT-ON, not operator-triggered.

### AR-9 — propose-new-infra-without-enumerating-the-sister *(harvest 2026-06-11)*
Proposing or building NEW infrastructure (a skill / registry / tool / doc) to solve a problem WITHOUT first enumerating the existing sisters that may already solve it or be the right EXTENSION point — so a parallel mirror gets built where an extension was owed (the Class-21 anti-pattern at the apparatus layer). **Fix:** before proposing new infra, grep for sisters + READ the candidates; EXTEND if ≥50% overlap + same consumer behavior; a genuinely-new build carries an explicit "sisters considered + why none fit" note. **False-positive surface:** a truly novel capability with no sister IS a legitimate new build — AR-9 is the UN-checked proposal, not every new artifact. Sister: `feedback_audit_canonical_sister_before_new_infra`, `feedback_plans_cite_sister_registry_inspection`, AR-8 (both are "a loaded discipline lost to momentum" — the M7 theme; the canonical-sister memory existed but didn't fire until pushback). Source: `.E.0.10` 2026-06-11 — nearly built a NEW `/adversarial-audit` skill (task #9) when `/second-opinion` (independent challenge) + `/precoding-audit-gate` Stage 3.5 (N=3 quorum) + the methodology spec ALREADY provided the refute, and TECH_DEBT-164 already named the real gap (wire the default into the existing skills). Operator pushback ("aren't the other checks adversarial by design?") applied the sister-check; re-scoped task #9 from build-new to wire-existing.

### PL-3 — severity-as-skip-license *(harvest 2026-05-30)*
Treating a finding's non-CRITICAL severity as permission to DROP it (no disposition) rather than as urgency/sequencing — silently accruing tech-debt under a severity label. **Fix:** every finding at every severity carries exactly one disposition (fix-in-ship / fold-to-task / ledger-with-ID / document); severity gates urgency + sequencing, never whether-to-address. **False-positive surface:** an operator-EXPLICIT "drop it / won't-fix" is a legitimate (documented) disposition — PL-3 is the *silent* drop. Home: `feedback_address_med_low_findings_not_just_high_crit`; structurally enforced at `/precoding-audit-gate` Stage-4 (disposition-per-finding). Sister: PL-2 (self-skip of a STEP; PL-3 is self-skip of a FINDING's disposition).

### PL-4 — premature-defer / optionalize-owed-work *(harvest 2026-05-31)*
Framing an owed step or follow-up as "optional / later / track-for-later," or surfacing it as a decidable fork, when the corpus standard already settles that it should be done-or-properly-tracked now — making the operator re-assert "close it 100% / why is this a question / document-as-you-go." The defer-framing reads as effort-avoidance even when not intended. **Fix:** when an item is OWED, default to doing it (or capturing it with a real home), not surfacing it as an optional fork; reserve forks for genuine scope choices the operator owns. **False-positive surface:** a genuinely-optional scope choice the operator OWNS, surfaced as a choice, is legitimate — PL-4 is optionalizing the OWED, not presenting real choices. Home: `feedback_no_defer_for_effort` + `feedback_document_as_you_go_over_catch_at_end`; sister: PL-1 (structural-option mis-default), PL-2 (step-skip), `feedback_listen_and_execute_simply` (the over-fork manifestation). **SHARPENED (#11 design close, 2026-05-31):** the severity ADJECTIVE itself — "minor" / "lower-priority" / "nit" — is the *laundering word* that precedes the un-owed defer; **watch for the adjective before the defer.** Shared detection surface with PL-3 (severity-as-skip-license). Source: the #11 fee-asset F-B handling — agent echoed the gate's "lower-priority" label + surfaced the fix as deferrable ("keep on radar"); operator: "that just sounds like tech debt we're leaving because we're calling it minor... more work now = less later." **SHARPENED (`.E.0.10` close, 2026-06-11) — the ADJACENCY-defer sub-shape:** deferring a NEWLY-FOUND fix to a later plan because the plan TOUCHES that surface (adjacency) rather than because the plan's DESIGN would REDO it (subsumption). "Plan X reworks this file" is the #1 false defer-license; folding a finding into a plan TRACKS it, it does NOT defer the fix. Structural fix landed: `feedback_opportunistic_tech_debt_closure` bidirectional amendment + `feedback_fold_findings_into_destination_plan` clarifier. Source: `.E.0.10` money-hunt — 8 fixes deferred on adjacency, operator caught ×2, 6 were durable (closed in-ship), only A2/A4-decimal genuinely D-123-subsumed.
