## Theme

Add an explicit "is this price move backed by volume?" feature to
`FOREACH_FEATURE`. Captures the manipulation-vs-real-flow signal
that XGBoost can learn implicitly today (via deep tree splits) but
better as a clean engineered feature.

## Background — current feature pack analysis

`ML_Headers/FeatureRegistry.hpp:294` (`FOREACH_FEATURE`) has 34
features. By category:

**Pure-volume features (7):**
- VOLUME_SLOPE — regression slope of volume
- VOLUME_DELTA — volume change last vs avg
- VOLUME_AVG — mean volume, short window
- CUMDELTA — rolling cumulative buyer-vs-seller (signed delta)
- FLOW_10S, FLOW_1M, FLOW_5M — signed-volume EWMA at 3 timescales
- LARGE_TRADE_Z — z-score of current trade size

**Explicit price↔volume interaction (1):**
- VWAP_DEV — price deviation from volume-weighted avg

**Pure-price features (~26):** SHORT_SLOPE, SHORT_R2, SHORT_VARIANCE,
LONG_SLOPE, LONG_R2, LONG_VARIANCE, VOL_RATIO (despite name —
PRICE variance ratio), ROR_SLOPE, EMA_SMA_SPREAD, PRICE_STDDEV,
PRICE_AVG, EMA_ABOVE_SMA, MID_SLOPE, MID_R2, HOUR_SIN, HOUR_COS,
VOL_REGIME_RAT, TICK_RATE_Z, DIST_TO_HIGH, DIST_TO_LOW,
BOOK_IMB_MEAN_SHORT, BOOK_IMB_MEAN_LONG, BOOK_IMB_DRIFT, SPREAD_BPS,
SPREAD_ZSCORE.

**Gap identified:** while the pack has rich volume features, the
ONLY explicit price↔volume joint feature is VWAP_DEV (price relative
to volume-weighted avg). XGBoost CAN learn that
"PRICE_SLOPE > 0 AND CUMDELTA > 0 = real upmove" via tree splits but
that costs depth + amplifies noise vs an engineered "divergence"
feature.

## Proposed features (operator picks one or both)

### Option A — DELTA_DIVERGENCE (simplest)

```c
// signed: 0 = aligned (real); ±2 = inverted (manipulation suspected)
static inline float ML_Compute_DeltaDivergence(const FeatureComputeCtx<F>& ctx) {
    int sign_price  = (FPN_ToDouble(ctx.short_slope) > 0.0) ? 1
                    : (FPN_ToDouble(ctx.short_slope) < 0.0) ? -1 : 0;
    int sign_volume = (FPN_ToDouble(ctx.cumdelta_recent) > 0.0) ? 1
                    : (FPN_ToDouble(ctx.cumdelta_recent) < 0.0) ? -1 : 0;
    return (float)(sign_price - sign_volume);
}
```

Returns:
- **0**: price + volume direction match (real move)
- **+2**: price up, volume net selling (suspicious — wash / spoof)
- **-2**: price down, volume net buying (capitulation? operator
  buying dip behind retail panic? — also informative)
- **+1 / -1**: one side flat (transitional)

Adds 1 new row to FOREACH_FEATURE; uses existing CUMDELTA + short_slope
state from RollingStats. ~20 LOC of compute fn.

### Option B — MOVE_VOLUME_CONFIRMATION (continuous)

```c
// continuous: high = strong move backed by heavy volume
static inline float ML_Compute_MoveVolumeConfirmation(const FeatureComputeCtx<F>& ctx) {
    double slope    = fabs(FPN_ToDouble(ctx.short_slope));
    double stddev   = FPN_ToDouble(ctx.price_stddev);
    if (stddev < 1e-9) return 0.0f;
    double price_z  = slope / stddev;  // z-score of move magnitude
    double vol_avg_short = FPN_ToDouble(ctx.volume_avg_short);
    double vol_avg_long  = FPN_ToDouble(ctx.volume_avg_long);
    if (vol_avg_long < 1e-9) return 0.0f;
    double vol_ratio = vol_avg_short / vol_avg_long;
    return (float)(price_z * vol_ratio);
}
```

High when:
- Price moved a lot relative to recent stddev (z-score ≥ 1)
- AND volume is up vs baseline (vol_ratio > 1)

Captures "strong move + heavy volume = breakout conviction." More
nuanced than Option A. ~30 LOC compute fn.

**Operator choice at re-trigger time:** ship A (cheap, sign-only),
ship B (continuous, more nuanced), or ship BOTH (A=manipulation
flag, B=conviction signal — different roles).

## Re-trigger conditions

From v5.12 Phase 4.A paper-test data:

1. **High false-positive rate on 3-class barrier in low-volume
   conditions.** If paper-test logs show that PEAK predictions in
   low-volume periods (e.g. weekend, off-hours) lose money more often
   than in high-volume periods, the model is misreading thin-volume
   noise as signal.
2. **Specific manipulation events.** If operator observes spoof /
   wash events where price signal fired but volume didn't confirm
   (and the trade lost money).
3. **A/B test signal.** Train two models — one with current 34
   features, one with 35 (current + DELTA_DIVERGENCE). Compare on
   held-out + walk-forward. If 35-feature model has materially better
   precision on manipulation-sensitive periods → ship.
