## What we discovered (Explore agent audit)

Engine has 213 cfg fields. SettingsPanel exposes 90. **123 missing.** Cause: 6-site mirror drift class (parser, panel, save/load, per-core override, drift check, declaration) that recurred every minor version since v5.12.

Categorization done in the umbrella plan. Per-core override cohort audit: 13 fields graduate to PER_CORE_OK (was 8 in initial estimate; cohort framework surfaced 5 more).

**Big latency opportunity surfaced:** slow-path cfg read amplification. ~60 scattered cfg reads per slow-path cycle per core × 16 cores = 100-400 ns/cycle/core warm, up to 2 μs cold. Fix: ResolvedCoreCfg struct (cache-line-aligned, HOT-first) at slow-path entry. Estimated 160-640 μs/sec warm budget recovered; up to 3 ms/sec cold-start surge.

## What can go wrong (defenses already laid)

- **Macro expansion errors:** consumer macros must take exactly 7 args. Plan calls this out explicitly.
- **Cfg field offset mismatch:** offsetof() requires plain struct (no virtual inheritance). Cfg is plain; verified.
- **Backtest determinism breaks:** registry parser must reproduce manual parser's default values byte-identical. Plan adds roundtrip parity test before declaring complete.
- **Build pain across 5 binaries:** sub-ship scope intentionally narrow (DOUBLE only) so blast radius is small per .F.4b.
