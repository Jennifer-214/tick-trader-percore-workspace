**Sub-concern from Caramel framing — PARITY-032 branchless-gating effectiveness at -O2:**

Plan body Step B.3 sketch: `uint64_t bo_mask = -(uint64_t)(!FPN_IsZero(cfg.cores[c].breakeven_on_profit_threshold) ? 1 : 0); if (bo_mask) EventLoop_BreakevenOnProfit(...);`

**EFFECTIVENESS ANALYSIS:**

This sketch has a **structural problem**: the `if (bo_mask)` is STILL A BRANCH. The mask compute is branchless, but the call gate isn't. At -O2, the compiler will compile this to:
```
test %rax, %rax
je .skip_breakeven  // <-- branch
call EventLoop_BreakevenOnProfit
.skip_breakeven:
```

This is identical to `if (!FPN_IsZero(...)) EventLoop_BreakevenOnProfit(...)` — the mask compute is dead-stripped or no-op-optimized to the same branch. Branch prediction kicks in for threshold=0 cohort (consistently taken-skip) so the actual cost is ~1-3 cycle taken-prediction hit + ~5ns for the predicate evaluation; the operator's mental model of "5ns added for default cohort" is approximately correct in practice but for the WRONG REASON (branch prediction, not branchless mask-select).

**True branchless alternatives:**
1. **Always-call with internal branchless gating** — make `EventLoop_BreakevenOnProfit` itself branchless on its first-line; early-return-via-mask. Cost ~5ns for early return (no branch on caller side); ~50-200ns for cohorts that actually use the feature. Cleaner.
2. **fn-pointer table** — `EventLoop_BreakevenOnProfit_real` vs `EventLoop_BreakevenOnProfit_noop`; resolve at boot per `cfg.cores[c].breakeven_on_profit_threshold > 0`. Pay 1 indirect call (~3ns mispredict-rare) for both cohorts; zero branch per cycle.
3. **cmov-style call** — not possible in C++ for function calls; only for values.

**Action: AMENDMENT-HIGH.** Plan body Step B.3 PARITY-032 mitigation needs to be revised. Current sketch is NOT branchless at -O2; effectively a plain `if` branch with extra mask-compute that the compiler will optimize away. Per H20 + Class 28 — proposed mask-gate is hand-wave-equivalent. Real options:
- (a) Refactor `EventLoop_BreakevenOnProfit` to always-call + internal early-return-via-mask (preferred per H20 + branchless-dispatch-discipline.md). Caller pays unconditional call overhead (~3-5ns); callee's first line is branchless early-return for threshold=0 cohort.
- (b) Fn-pointer table at boot (boot-time-only dispatch resolution per `branchless-dispatch-discipline.md` decision matrix exception 1). Stored alongside other per-core fn pointers (oms.on_entry_fill_emit / on_exit_fill_emit precedent at EngineSharded.hpp:716-717).
- (c) `__builtin_expect(threshold == 0, 1)` hint to predictor (cheap; explicit annotation; H20 decision matrix exception 2). 

Caramel decides which option. Operator pushback on Class 28 sister anti-pattern likely caught this if v1.6 wasn't yet re-audited.
