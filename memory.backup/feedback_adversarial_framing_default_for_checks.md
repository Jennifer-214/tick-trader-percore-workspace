When running ANY audit/check/review, frame it ADVERSARIALLY by default: prompt the agent(s) to FIND the bug / REFUTE the claim / prove the code wrong / default to suspicion — NOT to "verify it's correct." A confirmatory pass rationalizes its way to GREEN; an adversarial pass hunts. Prefer MULTIPLE independent adversarial agents (different lenses/scopes) over one — they cross-check each other, and their DISAGREEMENT is signal.

**Why:** operator-stated preference (2026-06-10) — "checks should mostly be adversarial, they seem to perform better." Borne out the same session: 3 independent adversarial agents swept the money path for D-190-class (parallel-derivation) divergences. They (1) CONFIRMED the fix complete (no sibling ULP divergences in steady-state) — a clean verdict that means more BECAUSE it came from agents trying to break it; (2) CROSS-CHECKED each other — Agent 1 rated a warm-restart fee-replay HIGH (claimed `core_realized` vs `realized_pnl` diverge by the full fee), Agent 3 REFUTED it by reading the actual callers (both replay folds pass a ZERO fee rate → both gross-of-fee → they agree), so Agent 1 was over-rated; (3) surfaced a genuine latent item (the folds ignore the stored booked fee `e.fee`). A single confirmatory pass would have rubber-stamped clean or propagated Agent 1's false-HIGH.

**How to apply:** (1) audit/review prompts say "FIND / REFUTE / prove-wrong / a false 'clean' is the worst outcome," never "confirm it's right." (2) For capital/determinism surfaces, run ≥2-3 independent adversarial agents with distinct scopes; treat disagreement as signal — resolve it by reading the disputed code YOURSELF (anti-self-attestation applies to the agents too: they can over-rate, Agent 1 did). (3) A clean verdict from an adversarial pass is worth more than from a confirmatory one. **BINDING DEFAULT (2026-06-11) — adversarial is opt-OUT, not opt-in.** Independent-refute is the default for ALL judgment verification; self-check is the exception, taken only operator-explicitly OR with an in-line stated reason (e.g. "mechanical re-run of a frozen golden, no judgment"). The burden is on REMOVING the adversary, not adding it. Why binding: opt-in adversarial loses to momentum on BOTH sides (operator-must-notice + agent-must-choose) — it failed 3× in one session (doc-restructure / skill-cohort / oms-ts-1), each caught only by operator pushback; the recurrence IS the signal that verification must be default-ON, not triggered. This memory is the POLICY (always-loaded); the structural enforcement is **TECH_DEBT-164** (adversarial-default wired into the audit skills + auto-fire on the capital-work-done surface) — the wiring is the M7 piece that makes it fire without anyone remembering. Recurring error-shape: meta-anti-pattern-index **AR-8** (self-attested-verification).

**Sharpening (2026-06-12, A25 — adversarial-verify DECISIONS, not only findings/tests; the PROPOSER misses their own cascade).** A25: the proposer recommended option (A) relocate a helper to a shared header; an INVESTIGATIVE agent independently endorsed a relocate path TOO; only the independent ADVERSARIAL pass caught (A) was a `DESIGN_PHILOSOPHY:726`-forbidden 24-TU wide cascade — and it had been SKIPPED until operator pushback ("did you run adversarial agents?"). Two lessons: (1) the adversarial pass applies to a fix/design DECISION (esp. one proposing infrastructure/relocation), not only to code findings + tests; (2) an investigative pass is NOT a substitute — it shares the proposer's frame and can endorse the same blind spot. Structural close = **TECH_DEBT-178** (a combined investigate→adversarially-refute DECISION-check skill so the adversarial half auto-fires — the same momentum-skip this memory names, now at the decision surface).

**Further sharpening (2026-06-12, the TD-178 dogfood — the cross-check RESOLUTION step + the shared-blind-spot limit; AR-11 / D-207).** Building the skill did not make me immune. Dogfooding `/decision-check` on A25, two independent agents DISAGREED on a code fact (does the sharded trail read `original_tp`?) and I resolved the disagreement BY FIAT — picking the convenient narrative (narrow-fix, no struct growth) — the EXACT Stage-3 violation the skill encodes. Worse, BOTH agents shared a blind spot (missed the per-strategy `*_ExitAdjustSharded` dispatch), so even their AGREEMENT would have been wrong. Two lessons: (1) when independent checks disagree on a FACT, the resolution is mechanical — READ the disputed code, never pick the cleaner story (self-attestation re-enters at the resolution step); (2) independent agents CAN converge on the same wrong answer (a shared frame/blind-spot is the limit of the adversarial-default) — agreement is corroboration, not proof. Codified as **AR-11** (meta-anti-pattern-index) + a structural `/decision-check` Stage-3 hardening (factual disagreement ⇒ mandatory orchestrator code-read; agreement ⇒ spot-check for a shared frame). Recurrence in the very session the skill was built = the M7 signal that the code-read must be mechanical at the resolution step, not memory-reliant.

**Further sharpening (2026-06-20, the 8-agent state-audit — re-ground an agent's EVIDENCE, not just its VERDICT).** A single dispatched agent's CONCLUSION can be correct while its supporting EVIDENCE (cited file:lines, severity, the SET it claims) is loose or wrong — and acting on the EVIDENCE (vs the verdict) propagates the error. This session: the doc-currency agent's verdict "PARITY-009..018 are all resolved" was CORRECT, but its cited evidence ("the audit log resolves 009..018") was overstated — the log only covered 013-018; 009-012 were confirmed only by CODE-grounding (grepping that the `PostLoadSetup` fix actually shipped). Flipping 009-012 closed on the agent's say-so would have been the [[feedback_tag_disposition_at_fix_time]] reconstruct-by-archaeology anti-pattern. Sisters this session: the rename agent FOUND the `node_id` on-disk fact but mis-FRAMED its severity ("collision" — actually the plan's OWN helper commit's intended namespace); an Explore sub-agent rated experiments-refs "CRITICAL", the parent down-graded to MINOR after verifying gitignored. **Lesson:** before ACTING on a load-bearing agent claim, re-ground its EVIDENCE against code (grep/read the real artifact) — act on the VERIFIED evidence, not the CITED evidence; a right verdict can rest on wrong evidence.
