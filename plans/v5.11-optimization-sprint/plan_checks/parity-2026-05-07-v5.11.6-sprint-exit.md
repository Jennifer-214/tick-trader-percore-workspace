## NEW finding class — InitArena lifecycle (v5.11.6.A specific)

### Finding 7a: Engine restart re-allocation semantics
**VERDICT: PASS**

PortfolioController_Init (line 451-459, PortfolioController.hpp) handles engine restart (24h Binance reconnect) correctly:

```cpp
if (!ctrl->rolling_long) {
    ctrl->rolling_long = (RollingStats<F, 512>*)alloc_or_arena(...);
    ...
}
*ctrl->rolling_long = RollingStats_Init<F, 512>();  // ← reinit contents
```

On restart, the pointer already exists (arena-allocated at first boot). The `if` check skips re-allocation and just re-initializes contents. Memory is REUSED. This avoids arena exhaustion across hundreds of restarts over an engine's lifetime.

✓ **Semantics verified CORRECT.**

### Finding 7b: InitArena_Destroy ordering vs per-struct Free
**VERDICT: PASS** (with ordering clarification)

Comment at line 3186-3189 (EngineSharded.hpp) states:
> "destroy the init-time arena AFTER all threads have joined and all per-struct cleanup (which checks InitArena_Owns) has run."

Timeline of shutdown (lines 3184-3275):
1. Line 3184: `OrderManager_Shutdown(&oms)` (no InitArena_Owns call)
2. Line 3195: `InitArena_Destroy(&g_init_arena)` ← **ARENA DESTROYED HERE**
3. Lines 3251-3267: BinanceAdapter/UserData/Reconciler shutdowns
4. Lines 3273-3275: **`Strategy_FreePerCore` calls InitArena_Owns check**

**⚠ RISK IDENTIFIED — SEVERITY: HIGH**

The Strategy_FreePerCore loop (line 3274) happens AFTER InitArena_Destroy (line 3195). If a strategy state is arena-allocated, the InitArena_Owns check will read a nullptr global and return 0, causing the Free path to call `delete` on what's now invalid memory (already-unmapped arena region).

**RECOMMENDED FIX (Effort: 10 min):**
Move the Strategy_FreePerCore loop (lines 3273-3275) to BEFORE InitArena_Destroy (line 3195). Exact placement: immediately after OrderManager_Shutdown (after line 3184).

```cpp
OrderManager_Shutdown(&oms);

// v5.4.0 Phase 1.3 — release per-strategy state BEFORE arena destroy
for (int c = 0; c < state.registered_count; ++c) {
    tt::Strategy_FreePerCore(&state, c);
}

// v5.11.6.A — destroy the init-time arena AFTER all per-struct cleanup
...
InitArena_Destroy(&g_init_arena);
```

**Status:** This is a deferral from the comment's own specification, not an implementation error. The code works today because Strategy_FreePerCore on the first engine run hits the malloc fallback (no arena), so free() is called successfully. But the invariant is violated. Must fix before multi-restart or dynamic engine reset features land.
