## Findings (severity-ordered)

### MEDIUM — Step 7.1 / 7.2 / 7.3 struct-gen architectural decision unresolved at plan time (Approach A / B / C)

- **Surface:** Plan body Steps 7.1 / 7.2 / 7.3 + design note at line 576-581
- **Pattern reference:** `DESIGN_SPECS/framework-patterns/type-trait-dispatch-via-tt-namespace.md` § "Y3 dispatch caveat (where tt:: differs)" + `metadata-bit-driven-derived-filter-framework.md` Option E
- **Symptom:** The struct-gen at `ModelInference.hpp:1199`/`:1643` for `StampInferenceCfgInputs`/`ModelStampResult` walks FOREACH_STAMP_BOUND_CFG to emit `uint8_t has_<name>; <type> <name>;`. The plan body proposes 3 candidate approaches (Approach A macro-level filter, B unconditional generation, C defer to `.B.3`) and defers the decision to coding time. This is a substantial architectural choice — preprocessor filtering on `meta & STAMP_BOUND_CFG_DERIVED` has known token-paste corner cases (cf. metadata-bit-driven-derived-filter-framework.md Option A rejection). Same problem class.
- **Concrete risk:** if Approach A is selected and token-paste fails for OR-expression metadata (e.g., `STAMP_BOUND | STAMP_BOUND_CFG_DERIVED | WARN_ON_CLAMP`), coding time discovers the failure and forces mid-Step pivot to Approach B/C — burns the audit-update-implement-ship cycle's "decided in planning, mechanical at coding" property.
- **Suggested fix (plan amendment):** Pre-decide. The existing infrastructure at `CfgFieldRegistry.hpp:1075-1090` (`cfg_compute_mask<Bit>` + per-bit mask arrays + `CFG_FIELD_FOR_EACH_SET_BIT`) only handles RUNTIME iteration, not COMPILE-TIME struct-gen filtering. Two structurally clean paths:
  - **Path 1 (Approach B): unconditional generation.** Generate all 80 `uint8_t has_<name>; <type> <name>;` fields. Pay the memory cost (~80 bytes for has_flags + ~24×80 = 1.9KB for FPN values worst-case). Avoids preprocessor games. Aligns with existing `StampInferenceCfgInputs` shape that already has many `inf.<name>` fields. The 1.9KB struct stays in `.bss` (cold-init); no hot-path cost.
  - **Path 2 (Approach C): defer to .B.3.** `.B.2` keeps `FOREACH_STAMP_BOUND_CFG` alive for struct-gen at `:1199`/`:1643`; `.B.3` legacy empty-out converts to compile-time filter in one shot. Defensive ordering (sister to Decision 3 in plan body).
- **Recommendation:** Operator decision at triage. If Path 1 (unconditional generation), the plan body needs a Step 7.1 amendment explicit about generation policy. If Path 2 (defer to `.B.3`), plan body needs a NOT-IN-SCOPE addition for struct-gen migration. Either is fine; ambiguity at coding time is not.
- **Severity rationale:** MED (not CRITICAL because the plan body explicitly flags this as TBD; not LOW because struct-gen approach choice changes ~80 LOC at minimum + affects Step 9 test scope). Pattern auto-decidability test (feedback_auto_pick_future_oriented): trade-off SHARP between memory cost (Path 1) vs sub-ship scope (Path 2); not obviously future-oriented either way without operator preference. Surface for triage.
