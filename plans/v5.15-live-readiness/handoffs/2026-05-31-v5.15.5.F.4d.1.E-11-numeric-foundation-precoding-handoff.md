## 2. The 4 resolved forks (the architectural decisions — D-122/123/124)

**C1 = A (HOIST) — D-122.** Which body does binary `<2,64>` inherit? → HOIST the FP64 `__uint128_t` int128 double-width mul into the template as the **shared mul primitive** for BOTH radices; radix-specific ONLY in the reduce step (`>>FRAC` binary / `/10^FRAC` decimal). Binary is **byte-identical to the `.E.0.1` golden BY CONSTRUCTION** (it IS the certified arithmetic) → zero feature-model retrain, zero binary-golden regen. `FPN_Sqrt<64>` stays generic (F-056). Rejected B (generic-for-binary): empirical-bet on generic≡native + latency regression (word-array vs native uint128) + two mul machineries + would drag features into the epoch (no end-goal gain). Rejected C (full rewrite, D-99). **Effort-checked: A is the substantial-work option; the harder alts are harder-AND-worse.**

**B-ε (folds into C1):** native-128 is the **COMPUTE** policy; **stored/wire/snapshot stays the canonical 2-word 24B layout** (else binary byte-identity breaks). C1 + B-ε are ONE storage decision.

**Golden-lifecycle refinement of D-100 (D-122):** two foundations applied to the golden — the **binary** side uses ONE FIXED golden (`.E.0.1` FP-golden) continuously, NO regen (structural byte-preserving refactor); the **money** side has no pre-existing golden, so a characterization baseline guards run-to-run REPRODUCIBILITY continuously (re-frozen at each deliberate money-behavior change), and the CORRECTNESS-validated golden is frozen ONCE at lock-in vs the external oracle. determinism ≠ correctness; both needed, in order.

**C4 + C3 = decimal `OrderResult`, source-exact — D-123.** Binance sends fill fields as JSON **strings** (`"L"`/`"l"`/`"n"`), currently `extract_double`'d (lossy at string→double, BEFORE any cast). Fix: parse `string→decimal` directly at the adapter; carry decimal on `OrderResult`. C3 folds in: the commission `"n"` is a string → parse→decimal→**book the reported value** (source-exact, D-106; F-A confirmed LIVE currently COMPUTES `notional*fee_rate` at `OrderManager.hpp:1142-1144`). **`.E.1` inherits the decimal-`OrderResult` adapter contract** (captured for `.E.1` in the decision log).

**H2 = `ema_price` is a BINARY FEATURE — D-124.** Consumer trace: every `ema_price` consumer is a signal/feature (MeanReversion/EmaCross/RegimeDetector `ema_sma_spread`/FeatureRegistry), NONE is money. So binary `<2,64>`; the money→binary cast is at the price-ingress to the rolling/feature domain (the D-103 boundary already in the blast radius — `RollingStats_Push`), NOT a new one. Kills the producer-path decimal-libcall latency concern (hft-F2). One-directional (ema never flows back to money).

## 3. Step-5 design-pass agenda (the resume work — D-93 new-fn design-audit)

Design these NEW functions (careful algorithm design; Caramel wants her eyes on the framings). All on boot/parse/slow-path or the rare-entry hot-mul — H11+DOD apply, H7-strict-branchless does NOT (a parser/canonicalizer has inherent loops):

1. **The unified `FixedPoint<RADIX, FRAC>` template** — radix-agnostic ops REUSE the certified bodies; the int128 shared-mul (C1=A hoist) with radix-specific reduce; `static constexpr SCALE = RADIX^FRAC`; FRAC = bits (radix 2) / digits (radix 10), O-3. Storage: native-128 compute / canonical-2-word stored (B-ε). H12 explicit `_padding`+`static_assert` (the decimal struct flows into fingerprint/stamp/snapshot — bite C5/dod-CRITICAL).
2. **Canonical rounding helper** (C2 / D-105) — ONE rounding mode applied at EVERY money mul/div INCLUDING replay; branchless (a `+(rem!=0)` mask term, not an `if`). NB rounding is **INTRODUCE not swap** (the 42 sites currently TRUNCATE — accounting-CRITICAL); regen the money golden at the D-100 epoch.
3. **Branchless `divmul_pow10`** (H1) — the `/10^FRAC` reduce as a magic-number reciprocal-multiply, NOT the `__udivti3` libcall (hft-F1 empirically confirmed the libcall). This is the latency-load-bearing one.
4. **Source-exact decimal `FromString`** — digit-accumulate into the scaled int (exact AND simpler than the binary POW10_RECIP path); used at the parse sites + the C4 fill adapter.
5. **Explicit `to_binary()` / `to_decimal()` casts** (O-1) — single-source, named, deterministic; the ~12 D-103 boundary sites become compile-errors-until-written (strong typing).
6. **`FPN_Quantize`** (D-104) — tick/lot at order submit, **+ MIN_NOTIONAL enforcement** (bite B-α: currently only `lot_step_size` is rounded; min_notional is parsed but not enforced) + exact qty→wire string.
