## What shipped

### v5.15.3.A.0 — STAMP_MODEL_CONST_AUTOPOPULATE quarantine

PARITY-022 root cause: the macro expansion was self-referential
(`(inf).X = (type)(inf->X)`) because the registry tuple's `get_value`
column passed `inf->X` references intended for struct-field generation,
not runtime population. The macro had been defined v5.14.8.0 but
never invoked from production; the v5.15.3 plan initially called for it.

Fix: replaced macro body with
`static_assert(false, "QUARANTINED ...")`. Any future production
caller invocation fires a compile-time error pointing to TECH_DEBT-036.

### v5.15.3.A.1 — `tt::Stamp_AssembleAndEmit<F>` canonical helper

NEW `ML_Headers/StampHelper.hpp` (~330 LOC):

- `template <unsigned F> struct StampArgs` — POD struct with default
  member init (CLAUDE.md item 27 padding determinism applies; single-
  horizon-friendly defaults: `grid_member_count=1`, `idx=0`,
  `horizon_count=1`, `snap_train_nthread=1`, optional fields empty).
- `template <unsigned F> StampWriteResult Stamp_AssembleAndEmit<F>(path, secret, cfg, args)` —
  orchestration helper that:
  1. Walks `STAMP_CFG_AUTOPOPULATE(inf, cfg)` for cfg-bound fields
  2. Manually populates cfg-derived inference_cfg_*/fees/bandit_blend_ratio
     fields (these live in FOREACH_STAMP_BOUND_MODEL_CONST, not
     FOREACH_STAMP_BOUND_CFG — see TECH_DEBT-037 for the taxonomy
     deferral)
  3. Manually populates per-call model-const fields from StampArgs
     (xgb_hyperparams, label_params, grid_member, scaler binding,
     run_name, expected_*)
  4. Resolves caller-default fallbacks (today's ISO date if
     `args.trained_on_iso` empty; FEATURE_REGISTRY_HASH() + ENGINE_VERSION_STRING)
  5. Calls `stamp_write_for_model` with assembled `inf`

New DESIGN_SPECS pattern: `DESIGN_SPECS/orchestration-helper-with-pod-args-pattern.md`.
One level above autopopulate-companion-macro pattern (the helper internally
calls AUTOPOPULATE + adds per-call population + external call).

### v5.15.3.C — libgomp landmine fix at process entry

Added at `foxml_suite.cpp:main()` as FIRST line BEFORE any libgomp init:

```cpp
setenv("OMP_NUM_THREADS", "1", /*overwrite=*/1);
```

`#include <stdlib.h>` for setenv.

Sets process-global single-thread mode before any pthread spawns.
libgomp inherits the env var at its first init (which happens at
first XGBoost call). Eliminates the shared-pool race that prior
workarounds (v5.11.44 per-pthread `omp_set_num_threads(1)` +
v5.11.45 forced-serial clamp) couldn't fully prevent.

**Closes CLAUDE.local.md landmine "XGBoost + libgomp + pthread parallelism"
(set 2026-05-07).**

Removed:
- v5.11.45 forced-serial clamp at `BacktestPanels.hpp:3886+` (now
  `mh_max_threads<=0` correctly means "auto = fully parallel")
- v5.11.45 CRITICAL WARN log (libgomp race no longer exists)

Kept (defensive):
- v5.11.44 per-pthread `omp_set_num_threads(1)` call (comment updated
  to reflect it's belt-and-suspenders after process-global setenv)

Trade-off: forces ALL XGBoost in suite to single-thread mode. Fine
because (a) v5.11.41 already pins `xgb_train_nthread=1` for bytewise
determinism in multi-horizon; (b) Train Model panel's serial mode
benefits negligibly from libgomp threading vs determinism risk;
(c) per-horizon pthread parallelism in `mh_per_horizon_parallel_worker`
is now safe (single-thread XGBoost per pthread = no libgomp shared
state to collide on).

## What surprised me

### 1. STAMP_MODEL_CONST_AUTOPOPULATE was QUARANTINED, not just defective

The v5.15.3 plan initially called for STAMP_MODEL_CONST_AUTOPOPULATE
as the structural fix for per-call model-const population. Pre-coding
`/parity-check` discovered the macro was self-referential. Switched
to manual per-call population from StampArgs (passed via POD struct).

This led to the orchestration-helper-with-pod-args pattern as a
formal companion to the autopopulate-companion-macro pattern (one
level above; closes "did caller wire everything?" class on top of
the autopopulate's "did caller call AUTOPOPULATE?" class).

### 2. cfg-derived inference_cfg_* fields live in MODEL_CONST registry, not CFG

v5.14.8.A.merged classified `inference_cfg_*` (cfg-DERIVED but
training-time-captured) as model-const. STAMP_CFG_AUTOPOPULATE
doesn't reach them; helper has to manually `inf.X = cfg.X` for ~8
fields. Captured as TECH_DEBT-037 (LOW severity; manual works
today; future consolidation candidate).

### 3. Caramel pushed back on direct-patch (Option B) → Option A helper extraction

Initial recommendation was Option B (1-line `STAMP_CFG_AUTOPOPULATE`
add at train_model_worker_fn + 3 plumbing fields). Caramel: "we
should do A right, like its the full fix isnt it? and is a structural
fix rather than apatch?"

Lesson re-confirmed (4th recurrence per `feedback_no_defer_for_effort`):
when the structural fix is in scope of the sub-plan, do the structural
fix. Direct patch was effort-avoidance dressed as "smaller scope".

### 4. PARITY findings this sprint are LESS severe than earlier sprints

PARITY-020 was tagged HIGH at audit time but actual blast radius is
lower than PARITY-002 through -008 (those silently broke entire
field categories of drift detection; PARITY-020 silently broke 22
fields but only on Train Model panel path, not the canonical
Full Validation path). PARITY-021 is observability-only (boot log
warning). PARITY-022 was inert (zero callers).

Pattern: the recurring-bug-classes are structurally extinguished;
remaining items are defensive cleanups, observability gaps, deferred
infrastructure. Trajectory matches what you'd expect from a maturing
codebase.
