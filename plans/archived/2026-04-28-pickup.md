## 2. W/L classification with split partial outcomes (medium, decision first)

**Question:** when leg A TPs and leg B SLs, what's the W/L count?

Currently per-leg: A=TP, B=SL → 1W + 1L. Inflates trade count, hides whether the *idea* worked.

**Three options:**

| Option | Semantics | Cost |
|---|---|---|
| 1. Per-leg (current) | A=TP, B=SL → 1W + 1L | none |
| 2. Per-trade by net P&L | A+B summed → 1W if net>0, 1L if net<0 | medium — pair legs at display or new counters |
| 3. Per-trade with split bin | TP/TP, TP/SL, SL/TP, SL/SL | larger — new per-core counters + snapshot bump |

**Recommendation:** option 2 in the GUI Stats / Per-Core P&L panel (matches trader semantics — "did this idea make money"), keep CSV at per-leg granularity (forensic). Option 3 is nice-to-have for tuning `tp2_mult` later.

**Decide first**, then implement. Don't start coding until you've picked.

## 3. TP/SL geometry tuning (do this with the backtest harness, not by guessing)

**Symptom:** session W/L = 0/4. Every closed trade tripped SL. TPs sit ~38σ from entry on the current regime — unreachable in RANGING.

**Why we shouldn't just lower the cfg values:** numbers that fit RANGING break in TRENDING/VOLATILE. Tuning to the last 2 hours of price = smallest possible sample.

**Right approach:**
1. Run `backtest.cfg` sweep: grid over `take_profit_pct` × `stop_loss_pct` × `tp2_mult` on a realistic data chunk (multi-day, multi-regime)
2. Score by risk-adjusted return + win rate, not raw P&L
3. Pick combo that's robust across regimes, not optimal for one

**Eventually (separate, larger):** convert TP/SL to stddev-scaled (`tp = entry + k*σ_short` from RollingStats). Auto-adapts to regime. Most strategies should probably do this — check which already do vs which use fixed pct.

**Don't start tonight.** Needs measurement, not vibes.
