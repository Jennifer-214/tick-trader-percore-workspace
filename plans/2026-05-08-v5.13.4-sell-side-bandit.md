## Counterfactual reward formula (MVP)

When MLStrategy fires early exit (last_exit_was_predicted == 1):

```
Given:
  entry_price, exit_price (actual fill)
  tp_pct (configured TP for this trade — comes from GateParameters
          at entry time; stored on Position struct)
  qty, fees (taker rate)

Hypothetical "would-have-held-to-TP" P&L:
  hypothetical_tp_price = entry_price * (1 + tp_pct)
  hypothetical_pnl = (hypothetical_tp_price - entry_price) * qty - 2*fees
                   = entry_price * tp_pct * qty - 2*fees

Actual P&L (already computed in HandleFill):
  actual_pnl = (exit_price - entry_price) * qty - 2*fees

Counterfactual reward (basis points relative to entry notional):
  diff = actual_pnl - hypothetical_pnl
  notional = entry_price * qty
  reward_bps = (diff / notional) * 10000

  Negative if exit was premature (held would have been better).
  Positive if exit avoided a loss (held would have lost vs early exit).
```

**Risk + mitigation:** "would have held to TP" is OPTIMISTIC — assumes
TP would have hit before SL. Real counterfactual requires forward
price-path inspection (possible in backtest, hard live). MVP uses
optimistic assumption; v5.13.X refines if paper-test reveals
systematic exit-bias from the optimism.

**Acceptance:** the optimistic assumption biases exit_bandit AGAINST
firing exits (since hypothetical_pnl is always positive when TP would
hit, making reward usually negative). This is OK for v5.13.X
calibration — operator can scale reward by a confidence factor
later. Document the bias in commit + master plan.

Mirror of existing `EnsembleModelZoo_InitBandits`:
```cpp
template <unsigned F>
inline void EnsembleModelZoo_InitExitBandits(EnsembleModelZoo<F> *ezoo,
                                              double exit_lr) {
    if (ezoo->exit_predictor_count == 0) {
        ezoo->exit_bandits_initialized = 0;
        return;
    }
    for (int r = 0; r < REGIME_COUNT; ++r) {
        Bandit_Init(&ezoo->exit_bandits[r], ezoo->exit_predictor_count,
                    exit_lr);
    }
    ezoo->exit_bandits_initialized = 1;
}
```

Call from EngineSharded boot AFTER EnsembleModelZoo_LoadFromCfg
populates exit_predictor_count (mirrors existing InitBandits call
site).

### Step 4 — Reward attribution in HandleFill (per-slot + flatten-aware)

File: `CoreFrameworks/OrderManager.hpp` (OrderManager_HandleFill, exit branch)

**GAP-CLOSE (audit 2026-05-08):**
1. Per-SLOT (not per-core) `last_exit_was_predicted` array (added in
   v5.13.0 Step 4). Indexed by portfolio slot (0..15).
2. **Distinguish flatten-exits from predicted-exits.** When v5.12.1.A's
   emergency flatten fires (`oms->flatten_pending == 1`), the exit was a
   SAFETY action, not a strategic ML decision. Don't credit exit_bandit
   for safety actions — that pollutes the bandit reward signal.

Existing flow (buy_bandit attribution) stays. Add exit-side branch:
```cpp
// v5.13.4 — exit-side bandit reward attribution.
// Conditions for crediting exit_bandit:
//   - cfg flag enabled
//   - per-slot flag was set by MLStrategy at predict time
//   - exit_bandits actually initialized (exit models loaded)
//   - NOT a flatten-induced exit (safety event; don't pollute bandit)
int slot_idx = (int)o->core_id;  // OMS uses core_id as slot index
int is_predicted_exit = (slot_idx >= 0 && slot_idx < MAX_PORTFOLIO_POSITIONS)
    ? oms->last_exit_was_predicted[slot_idx] : 0;
int is_flatten_exit = (oms->flatten_pending.load(std::memory_order_acquire) == 1);

if (cfg.exit_bandit_enabled
    && is_predicted_exit
    && !is_flatten_exit
    && ezoo && ezoo->exit_bandits_initialized) {

    // Counterfactual: would-have-held-to-TP P&L (optimistic; see plan note)
    FPN<F> tp_pct = state->cores[logical_core].pending_params.tp_pct;
    FPN<F> entry_p = oms->portfolio.positions[slot_idx].entry_price;
    double tp_d = FPN_ToDouble(tp_pct);
    double entry_d = FPN_ToDouble(entry_p);
    double qty_d = FPN_ToDouble(fill_qty);
    double notional = entry_d * qty_d;
    double hypothetical_pnl = notional * tp_d - 2.0 * notional * fee_rate;
    double diff = realized_pnl - hypothetical_pnl;
    double reward_bps = (notional > 1e-9) ? (diff / notional) * 10000.0 : 0.0;

    // logical_core for regime + bandit arm lookup (with partials,
    // both slots of a core share regime + arm choice from same predict)
    int logical_core = oms->partial_exit_enabled ? (slot_idx >> 1) : slot_idx;
    int regime = state->cores[logical_core].regime_state.current;
    int chosen_arm = state->cores[logical_core].last_exit_arm;
    Bandit_Update(&ezoo->exit_bandits[regime], chosen_arm, reward_bps);
}

// Clear single-use flag regardless of whether reward was attributed
// (predicted-exit fired but cfg disabled OR flatten suppressed → still
// clear so next predicted exit on this slot starts fresh).
if (slot_idx >= 0 && slot_idx < MAX_PORTFOLIO_POSITIONS) {
    oms->last_exit_was_predicted[slot_idx] = 0;
}
```

**Threading contract:** `last_exit_was_predicted[slot]` is per-slot
single-writer (slow-path MLStrategy thread for the slot's owning core)
+ single-reader (drainer thread in HandleFill). uint8_t writes are
atomic on x86. Mirrors existing `kill_switch_tripped` pattern. No
explicit atomic needed.

## Latency analysis

- Default cfg (exit_bandit_enabled=0): ~0ns (cfg flag check at fill time;
  fill is rare event; cost amortized)
- cfg=1, exit fired: ~50ns (counterfactual math + Bandit_Update)
- cfg=1, exit not fired: ~5ns (cfg flag + last_exit_was_predicted check)

Drainer thread cost (post-fill); not on hot path; not on slow-path
critical predict cycle. Within budget.
