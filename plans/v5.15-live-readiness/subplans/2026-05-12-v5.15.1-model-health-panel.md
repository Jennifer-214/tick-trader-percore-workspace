## Why this subplan exists

The `./engine` boot log review 2026-05-11 surfaced 5 silent failure
modes that are detected internally but never visible to the operator at
runtime: feature_hash drift, label_hash drift, build_flags drift, scaler
binding drift, stamp HMAC not verified, model age beyond
`model_max_age_hours`, cfg binding drift. v5.14.8 added FOREACH_FAILURE_MODE
infrastructure + 7 entries; v5.15.1 extends it with **7 new BIT_FLAG drift
entries** + introduces the **Model Health CollapsingHeader** that surfaces
each failure mode to the operator.

Bundled: **TECH_DEBT-028** — 4 PerCoreSnap bool-as-uint8 fields
(`ml_scaler_present`, `drift_breached`, `drift_kill_tripped`,
`core_kill_tripped`) migrated to existing `state_flags` uint16_t bitmap.
This isn't a new bitmap; it's reuse of the v5.14.9.B.2-established
`PerCoreStateFlagsRegistry.hpp` cluster. Cohort consistency wins per the
cfg-flag-eligibility-criteria cohort-audit rule.

### Step 2: detection wiring via consolidation + new arch-field registry

Per /merge-scan HIGH-1 finding: existing X-macro drift loop at
`CoreModelZoo.hpp:206-225` ALREADY walks FOREACH_STAMP_BOUND_CFG +
compares stamp_value vs cfg + increments `sr.inference_cfg_drift_count`.
**Consolidate** the CFG_BINDING_DRIFT bit-set INTO that existing loop
instead of creating parallel detection. Arch fields (feature_hash,
label_hash, build_flags_hash, scaler_hash) get a NEW
`FOREACH_ARCH_FIELD_DRIFT` registry because they're not CFG-bound.

```cpp
// NEW MemHeaders/ArchFieldDriftRegistry.hpp
// X-macro registry for architectural-field drift detection. Adding a
// new arch-field drift check = 1 row.
#define FOREACH_ARCH_FIELD_DRIFT(X)                                                          \
    /* X(name, stamp_field_expr, runtime_value_expr, fail_bit) */                            \
    X(feature_hash,        sr.feature_registry_hash,        FEATURE_REGISTRY_HASH(),         \
                           FAILURE_FEATURE_HASH_DRIFT)                                       \
    X(label_hash,          sr.label_registry_hash,          LABEL_REGISTRY_HASH(),           \
                           FAILURE_LABEL_HASH_DRIFT)                                         \
    X(build_flags_hash,    sr.build_flags_hash,             tt::BUILD_FLAGS_HASH(),          \
                           FAILURE_BUILD_FLAGS_DRIFT)                                        \
    X(scaler_feature_hash, sr.scaler_feature_registry_hash, h->scaler.feature_registry_hash, \
                           FAILURE_SCALER_DRIFT)

// In ML_Headers/CoreModelZoo.hpp at TryLoadRole post-verify_model_stamp:

// (1) Walk arch-field drift registry (NEW; one chokepoint per item 9).
#define X(name, stamp_field, runtime_value, fail_bit) \
    if ((stamp_field) != (runtime_value)) { \
        FAILURE_SET(pc, fail_bit); \
        sr.inference_cfg_drift_count++; \
    }
FOREACH_ARCH_FIELD_DRIFT(X)
#undef X

// (2) Existing CFG drift loop at CoreModelZoo.hpp:206-225 — add aggregate
//     CFG_BINDING_DRIFT bit-set inside (per /merge-scan HIGH-1
//     consolidation). The loop already counts drift; just OR-set the
//     bit once after the loop:
if (sr.inference_cfg_drift_count > 0) {
    FAILURE_SET(pc, FAILURE_CFG_BINDING_DRIFT);
}

// (3) Single-fact checks (not registry-driven):
if (sr.has_hmac_unverified) {
    FAILURE_SET(pc, FAILURE_STAMP_HMAC_NOT_VERIFIED);
}
if (sr.has_training_timestamp_us && cfg.model_max_age_hours > 0) {
    uint64_t age_hours = (now_us - sr.training_timestamp_us) / (3600ULL * 1000000ULL);
    if (age_hours > cfg.model_max_age_hours) {
        FAILURE_SET(pc, FAILURE_MODEL_AGE_WARN);
    }
}
```

**Wins from consolidation:**
- Closes Class 18 mirror (was 2 parallel drift detection paths; now 1
  existing CFG loop + 1 new arch registry + 2 single-fact checks)
- Future arch-field drift check = 1 row in FOREACH_ARCH_FIELD_DRIFT
- Future CFG-bound field drift = 0 LOC (existing CFG loop already handles)
- Per CLAUDE.md item 9 (NaN-free chokepoint precedent): one chokepoint
  per concern, not scattered checks
- Per CLAUDE.md item 16 (reuse-audit): consolidates with existing X-macro
  loop instead of creating parallel detection

// alignas(64) per per-snapshot-cluster-layout-pattern.md (v5.14.10.0

### Header design

```cpp
// In GUI/MLStatusPanel.hpp:
// Summary: count of tripped drift bits + max severity
uint16_t drift_mask = FAILURE_MASK_FEATURE_HASH_DRIFT
                    | FAILURE_MASK_LABEL_HASH_DRIFT
                    | FAILURE_MASK_BUILD_FLAGS_DRIFT
                    | FAILURE_MASK_SCALER_DRIFT
                    | FAILURE_MASK_CFG_BINDING_DRIFT
                    | FAILURE_MASK_STAMP_HMAC_NOT_VERIFIED
                    | FAILURE_MASK_MODEL_AGE_WARN;
int tripped = __builtin_popcount(pc.failure_flags & drift_mask);
const char *summary_color = tripped == 0 ? "GREEN" :
                            (pc.failure_flags & (FAILURE_MASK_FEATURE_HASH_DRIFT
                                              |  FAILURE_MASK_LABEL_HASH_DRIFT
                                              |  FAILURE_MASK_SCALER_DRIFT)) ? "RED" : "YELLOW";
char header_label[64];
snprintf(header_label, sizeof(header_label),
         "Model Health (%d/7 drift) %s##core_%d", tripped, summary_color, core_idx);

if (ImGui::CollapsingHeader(header_label)) {
    // Per-row render: for each FOREACH_DRIFT entry, show severity + label
    // + at-load value + current value side-by-side
    FOREACH_FAILURE_MODE_IN_GROUP(GROUP_DRIFT, X_RENDER_DRIFT_ROW)
}
```

X_RENDER_DRIFT_ROW macro auto-generates 1 ImGui::Text row per entry,
reading the at-load uint64 from PerCoreSnap + computing current via the
runtime registry hash + diffing.

## Data-Oriented Design pass

(Reproduced from MASTER §v5.15.1 with implementation specifics.)

| DOD concern | Implementation |
|---|---|
| **PerCoreSnap alignas(64) preserved** | v5.14.10.0 baseline preserved; new drift cluster has its own `alignas(64)` boundary + static_assert(offsetof) |
| **Failure-mode bitmap headroom** | 2 + 7 = 9 of 16 bits; static_assert at FailureModeRegistry.hpp:212 still passes |
| **TECH_DEBT-028 bitmap** | 4 bool-as-uint8 fields merged into existing state_flags uint16_t (6 + 4 = 10 bits used); saves 3 bytes per PerCoreSnap (4 bytes → existing uint16_t reused) |
| **New value-fields cluster** | 5 uint64 + 4 padding fields = 64 B aligned; explicit padding fields ensure deterministic layout (CLAUDE.md item 27); cluster sized to fit cache line cleanly |
| **Cross-thread sharing** | slow-path writes drift cluster at model-load chokepoint; GUI reads via existing double-buffered TUISnapshot publication; no new sync infrastructure |
| **Branchless multi-flag check** | header summary uses single `__builtin_popcount(failure_flags & drift_mask)` + single AND comparison for color dispatch; no scattered branches |
| **Latency impact (CLAUDE.md item 17)** | **No hot/slow-path additions.** Drift detection chokepoint at `CoreModelZoo_TryLoadRole` is BOOT-time only (runs once per handle load; not on slow-path tail). Drift bits are SET at boot + persist until next model-load; no runtime re-checking. PerCoreSnap populator writes for new value fields happen on slow-path tail at snapshot publish (same cadence as existing populator; +5 uint64 writes ≈ ~5ns added to existing ~100ns snapshot copy; well within 100us slow-path budget). GUI render is GUI-thread only; never touches engine threads. NO HOT_PATH_CHANGELOG entry needed; the +5 uint64 writes are a trivial addition documented inline. |
| **Branchless discipline (CLAUDE.md item 18)** | All new failure-mode checks use `FAILURE_IS_SET(flags, MASK_X)` = single uint16 AND + branch. State_flags reads via `STATE_FLAG_IS_SET` = same shape. Aggregate "any drift?" check uses single AND-mask (`flags & drift_mask`) — branchless multi-flag predicate. |
