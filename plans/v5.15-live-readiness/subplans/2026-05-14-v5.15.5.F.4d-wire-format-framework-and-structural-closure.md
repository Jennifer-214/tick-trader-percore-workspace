## Why this ship exists

Per **Option D+** restructure (locked 2026-05-14 after `/precoding-audit-gate` Layer-1 orchestrator synthesis): the STAMP_BOUND derived filter cutover was originally bundled into `.F.4c` but the audit gate surfaced 5 convergent findings establishing it's its own **wire-format-affecting structural-fix ship** of substantial size:

1. **Class 21 risk (parallel descriptors)** at the derived-filter surface — naive STAMP_BOUND cutover would create dual SoT (FOREACH_STAMP_BOUND_CFG + FOREACH_CFG_FIELD with STAMP_BOUND metadata bit)
2. **HMAC chain byte preservation** is at risk during cutover — Layer 5b methodology required
3. **Bitmap-resident bool fields** in `cfg.ml_cfg_flags` need two-source variant (cannot trivially become KIND_INT rows)
4. **12+ consumer-site migration** required (drift check, struct gen, parser, autopopulate, stamp helper, count tests, CfgDriftCheckRegistry)
5. **v5.14-era stamp fixture** needs procurement + commit (round-trip HMAC regression test)

Plus 4 frameworks must be codified concurrently (Stage 2 → Stage 3 in one ship per `pattern-codification-lifecycle.md`):
- `metadata-bit-driven-derived-filter-framework.md`
- `meta-registry-pattern-for-codebase-registry-discipline.md`
- `sidecar-override-pattern-for-registry-auto-flows.md`
- `framework-composition-overview.md`

Plus 5 new hard invariants H14-H18 codify at this ship + CLAUDE.md item 31 (Framework-driven extensibility) + DESIGN_PHILOSOPHY § 1.5 codification.

Plus full cfg field audit (~113 manual fields classify into true-cfg / runtime-derived / per-core override storage) + X-macro struct generation closes reverse-drift class structurally.

**Result:** this ship is the most ambitious sub-ship in the `.F.4` umbrella by ~3× (LOC + structural impact). MED-HIGH risk; full pre-coding audit gate fires before code lands.

### Step 1.D — Storage-width TYPE-signal mechanism for X-macro struct generation (~50-100 LOC; DESIGN PENDING PRE-CODING AUDIT GATE)

**Design pending.** Storage-width Kind sub-tokens REJECTED per H13/H14 (consolidation decision 2026-05-14 — Kind is GUI presentation metadata, NEVER drives storage; would re-open the Class 23 anti-shape door).

The X-macro struct generation at Step 5 needs per-row storage-width info to emit typed `ControllerConfig<F>` struct fields (`int32_t max_hold_ticks = 0;` vs `int64_t param_max_age_ticks = 0;` vs `uint8_t require_mlockall = 0;` etc.). Signal mechanism MUST NOT be Kind value reads.

Candidate approaches for `.F.4d` pre-coding audit gate to evaluate against H13/H14 + future-row ergonomics + row-tuple readability:

| # | Approach | Shape | Trade-offs |
|---|---|---|---|
| (a) | New TYPE column added to X-macro row tuple | 13-col: `X(KIND, name, ..., TYPE_I32, ...)` | Explicit column for storage type; +1 col on every row including non-INT (slight waste); scannable |
| (b) | Payload-macro variants for INT (preliminary recommendation) | `INT_I32(d, min, max)` / `INT_I64(...)` / `INT_U32(...)` / `INT_U64(...)` / `INT_I8(...)` — mirrors existing `DBL(...)` / `DBL_PCT(...)` precedent | No column count change; payload macro carries type signal alongside values; non-INT kinds unaffected; pattern-symmetric to `.F.4b` shipped |
| (c) | Side table indexed by row name | `g_cfg_storage_widths[]` indexed by `FIELD_IDX_*`; X-macro walker reads via offset | Decouples width from row tuple; two sources to keep in sync (drift-risk per Class 21) |

**Preliminary recommendation (locks at audit gate):** approach (b). Cleanest separation — Kind = GUI metadata; payload macro = (storage-width signal + default/clamp values). Mirrors `DBL_PCT` precedent. No column count change.

`tt::cfg_parse_field<T>` / `tt::cfg_save_field<T>` continue to dispatch via type-trait (`std::is_signed_v<T>`/`std::is_unsigned_v<T>`/`sizeof(T)`) — NO Kind value reads (per H13). Storage-width-specific clamps come from `std::numeric_limits<decltype(cfg.name)>` at the X-macro extractor site, not from `desc.kind`. The TYPE-signal exists only for X-macro **struct generation** (compile-time only), never for runtime parse/save/render dispatch.

## Anti-patterns to avoid (highlights)

- **Class 14 (Plan API drift):** every API reference in this plan verified at audit gate. DELETE-stale-don't-preserve-with-notice discipline applies post-amendment.
- **Class 18 (Mirror-incomplete):** AUTOPOPULATE single-walker design closes function-composition mirror; 12+ consumer-site migration verified via test fixtures.
- **Class 19 (Hardcoded enum names):** STAMP_BOUND-flagged INT_ENUM fields (bandit_algorithm / barrier_blend_mode / risk_degradation_curve) MUST use X_GEN_LABEL extern reuse (from `.F.4c` precedent).
- **Class 21 (Parallel descriptors):** legacy `FOREACH_STAMP_BOUND_CFG` aliases to derived filter (not parallel); `FOREACH_CFG_DRIFT_CHECK` wide variant aliases to sidecar (not parallel); both DEPRECATED at this ship.
- **Class 23 (Type-erased reinterpret_cast):** 3-barrier prevention intact at every NEW tt:: dispatch extension (DriftOverride accessors stay branchless; sidecar lookup is direct array access via FIELD_IDX; no void*+offset).
- **Sidecar over-reach:** if a 6th drift-override case emerges that doesn't fit `severity + category + compare_kind + eps_idx`, audit whether `DriftOverride` struct needs extension OR a function-pointer column is warranted. Default: extend struct (within reserved bits).
- **Two-source variant overuse:** the bitmap-bool two-source dispatch is for the SPECIFIC case of STAMP_BOUND bools in `cfg.ml_cfg_flags`. Don't reach for two-source for other derived filters unless they have identical bitmap-resident-bool shape.

## If something goes wrong

- **Build fails on framework macro instantiation:** verify all 3 DERIVED_FILTER_DECLARE_* macros expand correctly via dummy invocation at Step 1.A entry; check parameter token-paste in Y3 dispatch macros
- **Layer 5b hash test fails (locked hash mismatch):** synthetic populate may have missed a field; OR a STAMP_BOUND row order changed accidentally. Investigate before re-locking the constant. **Don't blindly update LOCKED_STAMP_BOUND_DERIVED_HASH_V5_15_5_F4 without verifying intentionality.**
- **v5.14 round-trip HMAC fails:** parser or emit drifted from v5.14 byte layout. Diff canonical body bytes pre-vs-post; locate the field that emits differently; investigate (locale issue? format string? Surface G `has_*` missing? bool→int promotion via bitmap dispatch?)
- **Cfg struct sizeof changed:** X-macro generation produced different struct layout than expected. Diff field declarations + TYPE-signal-to-storage-width mapping (per Step 1.D resolution); verify all manual fields preserved per `MANUAL_FIELDS_INVENTORY.md`.
- **Bit-packed DriftOverride accessor returns wrong value:** verify bit-shift constants match struct layout; check `flags` byte initialization in `EMIT_DRIFT_OVERRIDE_INIT` macro.
- **Class 21 audit flag (parallel registry residue):** wide-variant `CfgDriftCheckRegistry` not actually superseded; verify all 19 entries migrated (14 standard via AUTOPOPULATE + 5 custom via sidecar = 19) + manual walker DELETED.
- **Rollback:** `git reset --hard pre-v5.15.5.F.4d` (anchor at Step 0.A). Note: if v5.14 fixture file added + committed, may need `git rm tests/fixtures/v5_14_stamp_canonical.bin` post-reset.
