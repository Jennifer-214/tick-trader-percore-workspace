## Implementation plan

### Step 1 — Stale-model age check (.E; was v5.14.8.A in original plan)

File: `ML_Headers/CoreModelZoo.hpp` (LoadFromCfg or _TryLoadRole)

**v5.14.8 amendment 2026-05-09:** ModelHandle is FLAT (no nested `.stamp`
sub-struct). New stamp body fields land as direct fields via
`FOREACH_STAMP_BOUND_MODEL_CONST` registry-driven X-macro generation
(see v5.14.8.0 for registry definition). Field access syntax is
`m->training_timestamp_us`, NOT `m->stamp.training_timestamp_us`.

```cpp
// v5.14.8.E — stale-model gate. Reads training_timestamp directly
// (FLAT field on ModelHandle, generated by FOREACH_STAMP_BOUND_MODEL_CONST
// registry — see ML_Headers/StampBoundModelConstRegistry.hpp).
// Applies cfg policy: max_age_hours=0 disables; strict_mode=1 → REFUSE,
// strict_mode=0 → WARN.
inline int CoreModelZoo_CheckStaleModel(
    const ModelHandle<F>* m,
    uint64_t now_us,
    uint64_t max_age_hours,
    int strict_mode) {
    if (max_age_hours == 0) return 0;  // disabled
    if (!m->has_training_timestamp_us) return 0;  // legacy stamp (registry has_* flag)
    if (m->training_timestamp_us == 0) return 0;  // sentinel
    uint64_t age_us = now_us - m->training_timestamp_us;
    uint64_t age_hours = age_us / (3600ULL * 1000000ULL);
    if (age_hours > max_age_hours) {
        Health_LogCriticalRateLimited(
            "[stale_model] %s is %lluh old > max %lluh",
            m->stamp.run_name, age_hours, max_age_hours);
        return strict_mode ? -1 : 0;  // REFUSE in strict; WARN otherwise
    }
    return 0;
}
```

Cfg field: `cfg.model_max_age_hours` (default 0 = disabled).

## FOREACH_FAILURE_MODE scope (NEW-1 investigation + pseudo-registry decision 2026-05-09)

**/parity-check NEW-1 (HIGH) finding:** Original amendment claimed
FOREACH_FAILURE_MODE auto-generates ML Status panel branches. Investigation
of `GUI/MLStatusPanel.hpp` (existing 5 failure-mode branches) showed
panel branches are CONTEXTUAL — placement in panel layout, custom
tooltips, severity-color choice depend on context. Cannot fully
auto-generate.

**Operator decision 2026-05-09 (Option 2 — pseudo-registry full
conversion):** Adopt **pseudo-registry pattern** that auto-generates
the mechanical 3 sites AND drives the panel branch from registry-defined
constants (severity color, format string, tooltip text). Panel branch
PLACEMENT stays hand-placed but BRANCH BODY consumes registry data.
All 4 sites benefit.

**X-macro tuple shape (with storage_class + group_id; bit-packed flags per data-oriented design):**

```cpp
// MemHeaders/FailureModeRegistry.hpp:
//
// Tuple: X(name, storage_class, severity, format_str, tooltip_str, group_id)
//   - name: PerCoreSnap field/flag name + populator suffix
//   - storage_class: BIT_FLAG / COUNTER_U32 / PERCENT_U8
//     - BIT_FLAG: auto-allocates to next available bit in failure_flags bitmap (uint16_t; up to 16 flags)
//     - COUNTER_U32: standalone uint32_t field (incrementing event counter)
//     - PERCENT_U8: standalone uint8_t field (0-100 progress indicator)
//   - severity: SEV_RED / SEV_YELLOW / SEV_SAND (maps to FoxmlColors via SEVERITY_COLOR macro)
//   - format_str: printf-style label (e.g., "model: LOAD FAILED", "stale: %u feat")
//   - tooltip_str: multi-line operator guidance
//   - group_id: 0 for standalone; same non-zero value for fields shown together
//
// BIT-PACKED RATIONALE (data-oriented design per CLAUDE.md item 1):
//   Binary flags pack into single uint16_t failure_flags field. Same
//   shape as Portfolio uint16_t bitmap. Wins:
//   - Memory: 16 binary flags in 2 bytes (vs 16 bytes per-flag uint8_t)
//   - Branchless multi-flag check: (flags & (MASK_X | MASK_Y)) — single
//     uint16_t compare vs N separate field reads
//   - Atomic multi-flag updates: __atomic_fetch_or (vs N separate stores)
//   - Single-word "any failure?" check: (failure_flags != 0)
//
// Auto-generates (3 mechanical sites):
//   - PerCoreSnap struct field (failure_flags bitmap + standalone counter/percent fields)
//   - MASK_##name constants for BIT_FLAG entries (auto-allocated bit positions)
//   - FAILURE_IS_SET / FAILURE_SET / FAILURE_CLR macros for ergonomic access
//   - Populator helper (called from slow-path)
//   - Health_LogCriticalRateLimited rate-limit static
//
// Drives (1 hand-placed site):
//   - ML Status panel branch — panel reads SEVERITY_COLOR(severity),
//     FAILURE_MODE_LABEL(name), FAILURE_MODE_TOOLTIP(name) constants;
//     placement + condition logic stays hand-coded; combined-display
//     handled via group_id iteration.

#define FOREACH_FAILURE_MODE(X)                                                  \
    X(ml_model_load_failed,     BIT_FLAG,    SEV_RED,    "model: LOAD FAILED",   \
      "ML strategy was selected but no model could be loaded.\n"                 \
      "Stamp validation failed, role file missing under any name "               \
      "(buy_signal/barrier/regime), or held_out_gate_strict=1\n"                 \
      "with mismatched registry hash. Check the boot log for details.\n"         \
      "Operator action: verify cfg path + retrain if needed.", 0)                \
    X(ml_scaler_load_failed,    BIT_FLAG,    SEV_YELLOW, "scaler: LOAD FAILED",  \
      "Scaler sidecar present in stamp but failed to load.\n"                    \
      "Check sidecar file exists at stamp's claimed path + scaler_sha256\n"      \
      "matches. Engine falls back to identity scaler (predictions degraded).", 0)\
    X(warmup_progress_pct,      PERCENT_U8,  SEV_SAND,   "warmup: %u%%",         \
      "Per-core slow path is still gathering rolling samples.\n"                 \
      "Model + features won't fire predictions until rolling\n"                  \
      "count reaches min_warmup_samples. Once 100%%, expect a\n"                 \
      "boot-time stderr line confirming readiness.", 0)                          \
    X(ml_nan_feature_events,    COUNTER_U32, SEV_YELLOW, "feat: %u",             \
      "Total feature-pack NaN/Inf events on this core.\n"                        \
      "Triggers when Features_PackAll's two-layer guard catches NaN/Inf\n"       \
      "(FPN saturation past 1e15 OR IEEE-754 isnan/isinf post-cast).\n"          \
      "Counter increments per skipped prediction cycle.", GROUP_NAN_EVENTS)      \
    X(ml_nan_prediction_events, COUNTER_U32, SEV_YELLOW, "pred: %u",             \
      "Total prediction NaN/Inf events on this core.\n"                          \
      "Triggers when Model_Predict returns NaN/Inf (degenerate model OR\n"       \
      "post-scaler-apply NaN propagation).\n"                                    \
      "Counter increments per skipped prediction cycle.", GROUP_NAN_EVENTS)      \
    /* v5.14.8.E new failure mode: */                                            \
    X(stale_feature_events,     COUNTER_U32, SEV_YELLOW, "stale: %u feat",       \
      "Total events where a feature's source data exceeded its\n"                \
      "max_staleness_minutes threshold and the feature was skipped\n"            \
      "(zero sentinel written). Indicates feature pipeline drift\n"              \
      "or stalled data source. Investigate if counter grows steadily.", 0)

// Auto-generated PerCoreSnap section (illustrative):
//   uint16_t failure_flags;              // BIT_FLAG entries (up to 16)
//   uint8_t  warmup_progress_pct;        // PERCENT_U8
//   uint32_t ml_nan_feature_events;      // COUNTER_U32
//   uint32_t ml_nan_prediction_events;   // COUNTER_U32
//   uint32_t stale_feature_events;       // COUNTER_U32
//
// Auto-generated bitmap mask constants (BIT_FLAG entries get auto-allocated bit positions):
//   static constexpr uint16_t MASK_ml_model_load_failed  = (1u << 0);
//   static constexpr uint16_t MASK_ml_scaler_load_failed = (1u << 1);
//   /* future BIT_FLAG entries get bits 2-15 */
//
// Ergonomic API (auto-generated):
//   #define FAILURE_IS_SET(snap, name) ((snap).failure_flags & MASK_##name)
//   #define FAILURE_SET(snap, name)    ((snap).failure_flags |= MASK_##name)
//   #define FAILURE_CLR(snap, name)    ((snap).failure_flags &= ~MASK_##name)
//
// Slow-path populator usage:
//   if (model_failed) FAILURE_SET(snap, ml_model_load_failed);
//
// Branchless multi-flag check at panel:
//   if (snap.failure_flags & (MASK_ml_model_load_failed | MASK_ml_scaler_load_failed)) {
//       // any model-related failure — single uint16_t compare
//   }
//
// Branchless "any failure?" gate:
//   if (snap.failure_flags) { ImGui::Begin("Failures"); ... }
```

**Memory savings (today + future):**
- Today: 1 byte saved (2 BIT_FLAG entries × 1 byte → 2 bits in 1 uint16_t)
- Future at 16 BIT_FLAG entries: ~14 bytes saved per core (16 × uint8_t = 16B → 1 × uint16_t = 2B)
- 16 cores × 14 bytes = 224 bytes saved system-wide; cache-line alignment benefits compound

**Group_id mechanism:** `GROUP_NAN_EVENTS` is an enum constant (defined
in FailureModeRegistry.hpp). Panel iterates registry entries by
group_id; entries with same non-zero group_id are displayed TOGETHER on
one line (e.g., "nan: feat: %u, pred: %u"). Standalone entries (group_id=0)
get their own branch. Future combined-display groups = 1 new GROUP_X
constant + entries with that group_id.
