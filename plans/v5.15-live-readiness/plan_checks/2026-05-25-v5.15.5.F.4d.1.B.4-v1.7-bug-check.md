**NEW-1 SUBSTANTIVE finding (D1-B scope/state mismatch — HIGH):**

v1.7 plan body proposes adding 1 row to `FOREACH_SLOW_PATH_GATE` at lines 648-654:

```cpp
X(ENGINE_WIDE, BREAKEVEN_ON_PROFIT,
  BITMAP_IS_SET((_gate_cfg).lifecycle_cfg_flags, MASK_LIFECYCLE_CFG_BREAKEVEN_ON_PROFIT),
  "breakeven-on-profit lifecycle event ...")
```

scope = `ENGINE_WIDE` — semantically aligned with the predicate (`cfg.lifecycle_cfg_flags` is engine-wide `uint8_t` at `ControllerConfig.hpp:567`; verified per-core mirror exists at :1469 but ENGINE_WIDE is the right scope for the rule).

But at line 640 the proposed read site is:

```cpp
if (BITMAP_IS_SET(state.cores[c].gate_state.flags, MASK_BREAKEVEN_ON_PROFIT)) {
    EventLoop_BreakevenOnProfitOneCore(state, cfg, current_price, c);
}
```

**This combination IS A NEW CLASS 14 INSTANCE** (fabricated structure-field access). Verified at HEAD `09204b3`:

- `CoreContext<F>::gate_state` (PER_CORE state at `ControllerEventLoop.hpp:269`) — type `SlowPathGateState` — holds PER_CORE entries set by `SLOW_PATH_GATE_AUTOPOPULATE_PER_CORE`
- `EventLoopState<F>::global_gate_state` (ENGINE_WIDE state at `ControllerEventLoop.hpp:784`) — type `GlobalGateState` — holds ENGINE_WIDE entries set by `SLOW_PATH_GATE_AUTOPOPULATE_ENGINE_WIDE`

Existing canonical patterns confirm:
- `ControllerEventLoop.hpp:2344` reads `state->global_gate_state.flags, MASK_LAZY_REBUILD_ACTIVE` (ENGINE_WIDE entry → global_gate_state)
- `ControllerEventLoop.hpp:3558` reads `state->global_gate_state.flags, MASK_WS_FLATTEN_ACTIVE` (ENGINE_WIDE entry → global_gate_state)
- `StrategyParameters.hpp:1414`, `:1515`, `:1534` read `gate_state->flags` (PER_CORE entries → per-core gate_state)
- `ShardedSnapshot.hpp:568` reads `state->cores[i].gate_state.flags, tt::MASK_LADDER_ACTIVE` (PER_CORE entry → per-core gate_state)

The discipline is binary: ENGINE_WIDE entries read from `state.global_gate_state.flags`; PER_CORE entries read from `state.cores[c].gate_state.flags`. v1.7's combination (ENGINE_WIDE scope + per-core read site) is structurally inconsistent.

**Resolution paths (operator triage required):**

- **(R-A) Keep ENGINE_WIDE scope (semantically right per cfg shape); fix read site to `state.global_gate_state.flags`** — matches existing canonical pattern; SlowPathCycleOneCore body accesses engine-wide state once per cycle per core (cheap; same as per-core gate read). Recommended per sister-canonical-pattern fit.
- **(R-B) Change scope to PER_CORE; predicate reads `(_gate_cfg).lifecycle_cfg_flags` (engine-wide, but evaluates same per-core)** — predicate is structurally OK since cfg.lifecycle_cfg_flags is global byte; per-core cache adds redundant bookkeeping for no semantic gain but type system is satisfied. Less natural.
- **(R-C) Direct read (no registry row) following existing :3799 wrapper pattern** — `if (!BITMAP_IS_SET(cfg.lifecycle_cfg_flags, MASK_LIFECYCLE_CFG_BREAKEVEN_ON_PROFIT)) return;` at top of body. Skips D1-B entirely. Architectural retreat from "use existing slow-path-gate-registry-pattern" framing.

R-A is the structurally-clean fix and preserves D1-B intent. R-B is structurally-OK but introduces redundant per-core cache. R-C abandons D1-B premise (no longer reuses existing registry pattern; just direct wrapper pattern).
