```cpp

//
//   NAME           — diagnostic label; derives canonical wire-format key (lowercase)
//   type           — C++ type for tt::cfg_drift_compare<T> dispatch
```

## Templated Helper: cfg_drift_compare<T>

Proposed helper for type dispatch:

```cpp
namespace tt {
    template <typename T>
    inline bool cfg_drift_compare(const T& stamp_val, const T& cfg_val) {
        if constexpr (std::is_array_v<T>) 
            return strncmp(stamp_val, cfg_val, std::extent_v<T>) != 0;
        else if constexpr (std::is_floating_point_v<T>) 
            return fabs(stamp_val - cfg_val) > 1e-6;
        else 
            return stamp_val != cfg_val;
    }
}
```

**Assessment:**

| Criterion | Status |
|---|---|
| **Type dispatch via if-constexpr (not Y3)** | ✓ CORRECT — Different branches (strncmp vs fabs vs !=) have incompatible syntax per type. Y3 dispatch would require C-string strncmp in same TU as scalar ==; that's invalid syntax. if-constexpr is the right mechanism. Pattern mirrors CLAUDE.md item 23 (tt::stamp_parse_field<T> precedent). |
| **Floating-point comparison threshold (1e-6)** | ⚠ REVIEW — 1e-6 absolute threshold assumes cfg values are ~1.0 scale. For ml_tp_pct / ml_sl_pct (likely 0.0-1.0 range), 1e-6 is suitable. If future drift entries use vastly different scales (e.g., 10000+ values), re-tune. Consider relative epsilon or per-entry threshold column. **For v5.15.5.A.7, 1e-6 is acceptable; note as future refinement.** |
| **char[N] strncmp no null-terminate check** | ⚠ VERIFY — strncmp compares up to extent bytes. If char[N] fields are not reliably null-terminated, this could compare garbage. Audit: are stamp char[N] fields guaranteed null-terminated on read? **Action: verify at implementation time.** |

**Verdict: ACCEPTABLE.** if-constexpr dispatch is canonical. Floating-point threshold reasonable for v5.15.5 scope.

## Refinement 1: Document Dual-Axis Dispatch Semantics

**Action:** Add a comment block above FOREACH_CFG_DRIFT_CHECK defining the 4 possible (severity, category) combinations and their meanings.

```cpp
//======================================================================================================
// [SEVERITY × CATEGORY MATRIX]
//======================================================================================================
// Y3 dispatch on two axes; defines 4 possible combinations:
//
//   WARN_ALWAYS × CROSS_BINARY:
//     Increments tier2_count. Gated by !acknowledge_cross_binary_version_drift.
//     Example: model_format_version mismatch (v5.14 vs v5.15 stamp body change).
//
//   WARN_ALWAYS × INFERENCE_CFG:
//     Increments tier2_count. Gated by !acknowledge_inference_cfg_drift.
//     Example: feature mask, label params change (retraining produces different inference).
//
//   REFUSE_STRICT × CROSS_BINARY:
//     Increments tier1_count + tier1_refused_count (if strict mode). Refuses load.
//     Example: stamp format incompatible (high-risk change).
//
//   REFUSE_STRICT × INFERENCE_CFG:
//     Increments tier1_count + tier1_refused_count (if strict mode). Refuses load.
//     Example: critical cfg drift (would silently change model behavior).
//
// Future entries must fall into one of these 4 cells. If a new entry would
// require a 5th semantic (e.g., WARN_IF_OPERATOR_ACKNOWLEDGES), add a new
// severity/category value to the registry + define new handlers.
```

**Benefit:** Future maintainers understand the 2D design space; won't accidentally create invalid (severity, category) pairs.

## Refinement 2: Floating-Point Comparison Threshold Documentation

**Action:** Add threshold + rationale to cfg_drift_compare<T> or a constants section.

```cpp
namespace tt {
    // Floating-point drift detection epsilon. Used for cfg fields like
    // ml_tp_pct, ml_sl_pct that are typically [0.0, 1.0] or percentage scale.
    // Absolute threshold suitable for normalized values; consider relative
    // epsilon for future drift entries with vastly different scales
    // (e.g., market-price-indexed fields >> 1.0).
    constexpr double CFG_DRIFT_FLT_EPSILON = 1e-6;
    
    template <typename T>
    inline bool cfg_drift_compare(const T& stamp_val, const T& cfg_val) {
        if constexpr (std::is_array_v<T>) 
            return strncmp(stamp_val, cfg_val, std::extent_v<T>) != 0;
        else if constexpr (std::is_floating_point_v<T>) 
            return fabs(stamp_val - cfg_val) > CFG_DRIFT_FLT_EPSILON;
        else 
            return stamp_val != cfg_val;
    }
}
```

**Benefit:** Explicit threshold is tunable; future migration to relative epsilon is straightforward.

## Q5: Future-proof: should FAILURE_MASK_* be auto-generated from registry, or hand-coded?
