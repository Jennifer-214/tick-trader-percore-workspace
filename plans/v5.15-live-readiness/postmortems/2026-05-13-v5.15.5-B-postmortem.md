## What surprised

**1. EventLoopState size estimate was 15× off in the handoff.** The audit synthesis "Correction 3" claimed `sizeof(EventLoopState<64>) ≈ 13-18 KB`. Live measurement: **273536 B = 267 KB**. The handoff was twice-stale. Live-captured the actual numbers via the new permanent layout-fingerprint probe at `controller_test main()`. Lesson: `feedback_compaction_degrades_treat_handoffs_as_hints.md` is load-bearing; verify sizes before reorg decisions.

**2. Option B+ (.B.2 with registry from the start) was BETTER than the original .B.2 + .B.4 split.** Caramel pushed back on the manual-migration shape: "could it benefit from a registry?" Yes — and shipping `FOREACH_GATE_DIAG_PAIR` + `FOREACH_DISPLAY_META_FIELD` in `.B.2` instead of deferring registry work to .B.4 closed the Class-18 mirror structurally (1 registry row vs 5 manual sites per new gate diag) AND made .B.4 a no-op (subsumed). Lesson: when a registry candidate surfaces during a related ship, fold the registry into the ship rather than deferring. CLAUDE.md item 19 (structural fix preferred) wins here.

**3. The `mctx->model_load_failed` pointer dereference required a small API change.** `.B.3` bit-packing migrated `model_load_failed` to a CoreContext bitmap bit. Bits are not addressable; the existing `MLBuildContext.model_load_failed` was `int*`. Changed to plain `int`-by-value (copy current bit state at the slow-path ml_ctx wiring site). Read-only semantics preserved; 1 dereference removed per cycle. Pattern: when migrating an addressable scalar to a bitmap bit, check pointer-based consumer APIs for similar value-copy refactors.

**4. The .B.7 AUTOPOPULATE multi-target dispatch shape was a NEW pattern.** Existing AUTOPOPULATE companions (`STAMP_CFG_AUTOPOPULATE`, `STAMP_MODEL_CONST_AUTOPOPULATE`) target a SINGLE production caller. `.B.7` introduced the first MULTI-TARGET pattern: same registry + helpers serve BOTH `EventLoopState_Init` (boot init) AND the paper-reset path in `EngineSharded.hpp`. The dual-registry split (INIT vs RESET) captures the semantic invariant — operator MUST consciously decide "does this new per-core field reset between sessions?" at registry-add time. Cleaner than a single `AUTOPOPULATE` that masks the decision.

**5. Loop fusion (`.B.8`) is bytewise-safe with careful state_flags ordering.** Pre-.B.8 the bitmap-consistency loop ran BEFORE the per-core publisher loop. State_flags reset MUST happen before any STATE_FLAG_SET. When merging, the reset moves to Layer 1 of the fused body (still BEFORE other STATE_FLAG_SET calls in Layer 4). Verified via 3027-test regression. Pattern: when fusing loops, audit ordering invariants on shared write targets.

**6. ControllerEventLoop.hpp net LOC grew +90, not the estimated +250.** AUTOPOPULATE consolidation (`.B.7`) absorbed ~145 LOC of init/reset body into 1-line macro calls; the reorg + registry headers + comments added ~235 LOC. Net: +90 LOC. The plan's pre-ship "~3800 LOC" estimate was over-cautious by ~160 LOC. Lesson: AUTOPOPULATE companion macros can produce NET shrink even when the registry header is large, because the savings at multiple call sites exceed the header overhead.

## What didn't surprise

- All pattern applications matched the documented DESIGN_SPECS exactly (ND1, ND2, ND3, cache-layout-discipline, bitmap-flag-api, x-macro-registry-with-presence-dispatch, autopopulate-pattern-for-production-caller-class, structural-fix-preferred-decision-framework). The doc-first workflow (DESIGN_SPECS written before each first-reference) paid off — implementation was mechanical translation from documented contract to code.
- Persistence wire format preservation was straightforward via the field-by-field fwrite pattern. No `SHARDED_SNAPSHOT_VERSION` bump needed; pre-.B saved snapshots load on post-.B binaries and vice versa.
- Tests at 3026 → 3027 (+1 for the `mctx.model_load_failed` int-by-value verification in `.B.3`). No test count CHANGES due to refactors — existing tests exercise the migrated surfaces transparently.

## Cumulative wins

- **Memory:** CoreContext per-slot 17 KB → 7 KB (-58%); cores[16] array 273 KB → 116 KB (saved ~158 KB engine-wide).
- **Bandwidth:** ~20 MB/s saved at snapshot publish (`.B.8` loop fusion) + ~50-150 µs/sec saved engine-wide on lazy-rebuild gate (`.B.1` hoist) + ~96-288 µs/sec saved on snapshot publish cross-thread invalidation (`.B.2` alignas isolation).
- **Branch quality:** 4-way data-dependent hour-of-day mispredict class eliminated (`.B.5` SESSION_BY_HOUR). Bitmap migrations preserve branch behavior. No new mispredict classes added.
- **Structural closure:** 9 Class-18 mirror classes closed via 5 new X-macro registries + 1 dual-registry pair + 2 AUTOPOPULATE companion macros + 1 templated-helper allocator dispatch. Future per-core field additions are ONE-row registry edits — no manual cross-site sync required.
- **Pattern catalogue extended:** Codebase now has 5 distinct X-macro registry variants field-validated (boolean-bitmap, float-cohort, enum-dispatch, mixed-storage-class, template-parameterized) + first multi-target AUTOPOPULATE dispatch + first decision-first cluster layout (ND3) + first cross-thread cluster isolation (ND1) + first display↔execution registry (ND2).
