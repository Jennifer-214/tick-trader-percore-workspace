## Phase D — Hot-path item (CAREFUL) (~1-2h)

### v5.11.20 — Branchless ring buffer commit (~1-2h)

v5.11.1 item 4. Current ExecutionCore_Tick uses a branch on the
trade-event push path:

```cpp
if (can_enter || can_exit_a || can_exit_b) {
    SPSCRing_TryPush(...);
    head++;
}
```

Replacement: unconditional push + branchless head advance:

```cpp
TradeEvent ev = {...};
SPSCRing_TryPush(&trade_event_ring, ev);  // ring slot written unconditionally
head += (uint64_t)(can_enter | can_exit_a | can_exit_b);  // bitmask advance
```

The branchless form ALWAYS writes to the next ring slot but only
ADVANCES the head pointer when there's a real event. Reader sees
only the advanced slots; unadvanced slots may contain stale data
but are never read.

Step 0: read current ExecutionCore_Tick implementation. Confirm
the only branch on event-push is the one above (vs branches on
gate evaluation which are template-elided post-v5.11.1).

Step 1: write the branchless form. Verify the trade-event ring's
read-side discipline: reader uses `head` as the producer cursor;
unadvanced slots are not read.

Step 2: bench gate. p99 must NOT regress over 10M-tick replay.

**Tests:** +2-3 (no-event tick produces no observable side effect
on reader; can_enter|can_exit_a|can_exit_b mask is correctly
formed; head advance equals event-fired count over a synthetic
10k-tick run).

**Tag:** `v5.11.20`. Pre-tag `pre-v5.11.20`. **HOT PATH TOUCHED**
— first such ship since v5.11.1. If bench shows regression, revert.

## Phase E — MPSC drain queue (v5.11.5 item 2) (~1-2 days)

**Real perf benefit:** ~80ns drainer-thread win + eliminates
N×SPSC empty-poll variance at order-arrival. Bounded but real.

### v5.11.21 — MPSC drain queue replacing N×SPSC fan-in (~1-2 days)

Currently `OMS_DrainSubmit` iterates `MAX_EXECUTION_CORES` SPSC
queues and pops from each. With ≤16 cores, that's 16 cache-line
reads per drain cycle even when most queues are empty. Replace
with one MPSC queue (Vyukov bounded MPSC or Michael-Scott
unbounded MPSC).

Step 0: pick the algorithm. Recommend **Vyukov bounded MPSC**
(Dmitry Vyukov's design): producers do an atomic exchange on the
write pointer + a relaxed store on the slot; consumer does a
relaxed load + atomic compare-and-swap on the read pointer. Lock-
free + wait-free for the producer in steady state.

Step 1: implement `MPSCRing<T, N>` in `CoreFrameworks/MPSCRing.hpp`.
Header-only, templated on T + N (power of 2). API:
```cpp
bool MPSCRing_TryPush(MPSCRing<T, N>* r, const T& item);  // multi-producer
bool MPSCRing_TryPop(MPSCRing<T, N>* r, T* out);           // single-consumer
size_t MPSCRing_Depth(const MPSCRing<T, N>* r);
```

Step 2: replace `submit_queues[MAX_EXECUTION_CORES]` (in
OrderManagerState) with single `submit_queue` of type
`MPSCRing<SubmitCommand<F>, OMS_SUBMIT_QUEUE_SIZE * 16>`.

Step 3: update push site. Currently per-core code calls
`SPSCRing_TryPush(&oms->submit_queues[core_id], cmd)`. Now:
`MPSCRing_TryPush(&oms->submit_queue, cmd)`.

Step 4: update OMS_DrainSubmit. Replace N-loop with single
TryPop loop:
```cpp
SubmitCommand<F> cmd;
while (MPSCRing_TryPop(&oms->submit_queue, &cmd)) {
    OrderManager_Submit(oms, cmd.core_id, ...);
    drained++;
}
```

Step 5: stress test. Spawn N=4 producer threads + 1 consumer
in a unit test, push 100k commands per producer, verify all
400k arrive at consumer with no loss + arrival ordering
preserved per producer.

**Tests:** +6-8 (single-producer single-consumer correctness,
4-producer stress, MPSC retry path under contention,
bytewise arrival ordering vs scalar reference,
empty-queue TryPop returns false, overflow TryPush returns false
+ doesn't corrupt state).

**Tag:** `v5.11.21` + `pre-v5.11.21` rollback anchor.
**HIGH RISK** — touches OMS critical path. Do NOT skip the stress
test before merging.

## Phase F — MAP_HUGETLB on InitArena (~30 min)

### v5.11.22 — MAP_HUGETLB opt-in for InitArena (~30 min)

**Real perf benefit:** ~512× fewer TLB entries for the InitArena
(8 MB / 2 MB hugepage = 4 entries vs 2048 for 4KB pages). Reduces
TLB-miss tail latency on slow-path RollingStats access by ~5-10ns
per miss in worst case.

Step 0: add cfg field `init_arena_use_hugepages` to ControllerConfig
(default 0 — opt-in, since hugepages require system config).

Step 1: in EngineSharded `InitArena_Create` call site, branch on cfg:
```cpp
int flags = MAP_PRIVATE | MAP_ANONYMOUS | MAP_POPULATE;
if (cfg.init_arena_use_hugepages) flags |= MAP_HUGETLB;
g_init_arena = tt::InitArena_Create(8 * 1024 * 1024, flags);
```

Step 2: extend InitArena_Create signature to accept extra mmap flags
(currently hardcoded). Default-arg the new parameter for backward compat.

Step 3: on MAP_HUGETLB failure (no hugepages reserved on the system),
fall back to non-HUGETLB MMAP with a stderr WARN. Engine continues
without TLB optimization but functional.

Step 4: document in `DOCS/OPERATOR_DEPLOYMENT.md` how to reserve
hugepages: `echo 4 > /proc/sys/vm/nr_hugepages` (4 × 2 MB = 8 MB to
fit the InitArena) + the cfg flag.

**Tests:** +2 (cfg field round-trip; mmap fallback path when MAP_HUGETLB
fails — synthetic test by setting flags to invalid combo).

**Tag:** `v5.11.22`. Low risk (opt-in flag; default=0 preserves
existing behavior).

## What's NOT in this plan (genuinely no perf benefit at current code)

These remain genuinely deferred:

- **AVX-512 FPN<256>/<512> vectorization** (v5.11.2 item 3) — engine
  uses `FPN<64>` (2 limbs). AVX-512 (8 lanes) provides no benefit
  on 2-limb operands; vector lanes 2-7 would be wasted. Only
  meaningful if we ever switch to FPN<256>+ which we don't currently
  use anywhere.
- **AVX-512 mask comparisons in hot-path** (v5.11.1 items 2-3) —
  PAIR_BRANCHLESS template dispatch (v5.11.1.2) already eliminated
  the leg-A/leg-B branches via compile-time elision. Adding
  `_mm512_cmpge_epu64_mask` on top wouldn't speed up the already-
  branchless code. Mark as "same goal, different approach — accepted
  divergence."
- **Bandit_Update AVX-512** (v5.11.7 item 2) — Exp3-IX algorithm
  updates only the played arm per call (single-element write).
  AVX-512 doesn't apply without changing the algorithm to "EXP3
  with reward 0 for unplayed arms" — a semantic change to the
  algorithm, not just a vectorization. Mark as "mis-spec'd in
  master plan."
- **ML AOT compile** (v5.11.8) — speculative, slow-path component,
  multi-day. Operator preference 2026-05-08: skip.
- **All multi-exchange items** (simdjson, parser pattern, 2nd-
  exchange architecture) — wait for actual 2nd exchange.
- **io_uring / kernel-bypass** — wait for colo.
