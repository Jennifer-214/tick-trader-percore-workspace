After implementing (and BEFORE committing), run a single **V-class** verification pass — the post-coding complement to the pre-coding I-class (investigative) + A-class (adversarial). The V-class RUNS the dedicated skills + gates on the ACTUAL shipped code, not the design:

- build (all touched targets: test + gui + suite), char-tests green
- **sanitizers (asan + ubsan), built FRESH from current source** — the gate most likely to be skipped + most likely to catch a latent bug; a per-IMPLEMENTATION run, NOT deferred to ship-close. **CRITICAL: the instrumented binary MUST be (re)built from CURRENT source before the run** — a stale `build_asan/` lies in BOTH directions (false-green on an unfixed bug; false-RED on a fixed one) because it reports on code it never compiled. `run_sanitizer_suite.sh` now rebuilds each lane first (`.E.0.10` anti-stale gate); never trust a sanitizer verdict from a binary nothing guaranteed-fresh (a "green/red from a stale artifact" ≠ verified — sibling of [[feedback_passing_test_is_not_verification]])
- `calls_graph_diff` (hot-path UNTOUCHED) + `check_session_docs` (doc-CI)
- the DOMAIN audit skills on the SHIPPED code (`/dod-audit` / `/hft-audit` / `/accounting-audit` / `/ml-audit` as the surface matches) — verify the CODE matches the design the pre-coding audits blessed
- returns a Definition-of-Done verdict (M8): code+producer / test-per-fix / sanitizers / hot-path / parity / promises-honored / docs-indexed / meta-codified

**Why:** the M8 close-out discipline says a ship TERMINATES only when an enumerated DoD is verified — the V-class IS that verification, applied per-implementation. Caught at A6 (2026-06-15): ASan (run as the careful path) surfaced a PRE-EXISTING latent heap-use-after-free (TECH_DEBT-202, the OMS async-writer-not-joined UAF) that the normal suite missed + that ASan-at-ship-close-only would have deferred to the .E.0.10 close. The gap: sanitizers + domain-audits-on-shipped-code were AD-HOC (depended on the implementer remembering to run them), not a codified post-implementation pass. Structural-enforcement-when-memory-insufficient (M7): make it a pass, not a habit. **Meta-lesson (`.E.0.10`, dogfooding the V-class on TD-202's OWN fix):** the V-class's sanitizer step itself gave a false verdict — `run_all_tests --full` ran a prior-session `build_asan/` (never rebuilt; its abort cited a pre-edit line number), reporting the UAF the fix had already closed. The gate that runs a pre-built binary is only as fresh as whoever last built it. STRUCTURAL fix: `run_sanitizer_suite.sh` now rebuilds each lane from current source before running (guarded on `build.sh` presence so the hermetic self-test still runs its stubs). The V-class verifies the SHIPPED code — so its inputs (the instrumented binaries) must BE the shipped code, freshly compiled (the `.E.0.6` clean-rebuild-unmasks-stale-cache lesson, now enforced at the sanitizer gate).

**How to apply:** after a substantive implementation, before commit, run the V-class — a single pass composing the gates + the surface-matched domain skills, returning the DoD verdict.
