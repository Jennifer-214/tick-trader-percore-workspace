## Theme

Parity-check at v5.10 close found that v5.10.0d's `LABEL_REGISTRY_HASH` and v5.10.0a.G.2's `grid_member_count` stamp body fields are **structurally dead in production** — the verifier supports them, tests pass with synthetic inputs, but ZERO production callers populate the emit side OR pass the expected hash to the consume side.

Same regression class as v5.9.5b (`Backtest_RunFullValidation` passing `nullptr` for `inf` despite all 10 inference cfg fields existing in the schema). Section L of `/parity-check` now catches this; v5.10 was authored before Section L was added.

This ship closes the silently-disabled protections by plumbing `inf.has_*` flags through the production emit sites + adding the missing positional args at the production consume sites + emitting + validating `grid_member_count` per-horizon at the AutoDetect call sites.

## Phase B — `grid_member_count` AutoDetect consistency validator (`v5.10.1.B`) — Option C

**Audit:** Finding #2 (CRITICAL) — parser + emitter + struct exist; ZERO production callers emit (only `tests/controller_test.cpp:13751`); `EnsembleModelZoo_AutoDetectFromDir`'s docstring (CoreModelZoo.hpp:1093-1114) describes a consistency check that's not implemented.

**Scope (post-readiness 2026-05-06):** Ship the **AutoDetect consistency validator only** (consume-side). Defer multi-horizon trainer stamp emission to v5.10.X. Reasoning:

- Spot-check confirmed `Backtest_RunFullValidation` (BacktestEngine.hpp:1019-1184) takes a single `int horizon` parameter and emits ONE stamp per call (no horizon loop).
- The actual multi-horizon trainer `train_multi_horizon_worker_fn` (BacktestPanels.hpp:2817-3063) does NOT call `stamp_write_for_model` at all — it writes a tiny `summary.txt` per role at line 3017-3027 but no stamp/signature/registry-hash. **Multi-horizon ensemble dirs deployed today contain unstamped models.**
- Wiring `stamp_write_for_model` into `train_multi_horizon_worker_fn` is a 3-5h architectural effort (full inf struct build + scaler binding + held-out fields + label registry hash + grid_member_count). Out of v5.10.1's scope.
- The validator (consume-side) lands as a **safety net** for when emission is wired later. On currently-deployed (unstamped) ensembles, validator hits the back-compat path: WARN-but-load. On future stamped ensembles, validator enforces consistency.
- This closes the docstring gap at CoreModelZoo.hpp:1093-1114 + closes the consume-side parity loop ("verifier-side validation now exists").

**Step 0:** Locate `EnsembleModelZoo_AutoDetectFromDir` at `ML_Headers/NodeModelZoo.hpp:1120-1232`. Currently calls `EnsembleModelZoo_LoadFromCfg` (line 1211) which loads per-horizon handles. Add validator AFTER this call.

### B.1 — Validator approach (boundary-stable)

**ModelHandle does NOT have a `stamp_result` field** (verified 2026-05-06 readiness — handle has selectively-flattened `stamp_inf_*` fields, no `grid_member_count` field, no full `ModelStampResult` retained). Two approaches:

| Approach | Pros | Cons | Verdict |
|---|---|---|---|
| Add 3 fields to ModelHandle (`has_grid_member_count`, `grid_member_count`, `grid_member_idx`); init in `Model_Init`; copy from sr in `CoreModelZoo_TryLoadRole` | Clean reuse pattern (matches existing stamp_inf_* fields) | Cascade across struct decl + init + load + 4 ezoo arrays + ~30 LOC plumbing | Breaches CLAUDE.local.md "boundary-stable refactor" rule for marginal gain |
| **Re-parse stamp file inside the validator** — call `verify_model_stamp` again on each handle's `model_path` to extract `grid_member_count` | No struct changes; respects boundary-stable rule (no cascade) | Wasteful: re-opens stamp file at boot (one-time cost; ~ms not μs) | **Recommended.** Boot-time only; cost negligible |

**Recommendation:** Re-parse approach. Per CLAUDE.local.md memory `feedback_reduce_touch_sites.md`: "default to keeping public types unchanged + doing new behavior INSIDE the function." This validator is a one-time boot validation; re-parse cost is irrelevant for boot path.

### B.2 — Validator code shape

**~50 LOC inserted between CoreModelZoo.hpp:1217 (post-LoadFromCfg) and the function's existing log+return at ~1225:**

```cpp
// v5.10.1.B — Implement the consistency check the docstring describes
// (lines 1093-1114). Walks all loaded handles and verifies they agree on
// grid_member_count. Re-parses each stamp via verify_model_stamp (boot-time
// only; boundary-stable per CLAUDE.local.md rule).
{
    int agreed_count = -1;
    int legacy_count = 0; // count of handles missing grid_member_count
    int total_handles = 0;

    for (int role = 0; role < 4; ++role) {
        ModelHandle<F> *role_arr;
        int count;
        switch (role) {
          case 0: role_arr = ezoo->buy_signal;     count = ezoo->buy_signal_count;     break;
          case 1: role_arr = ezoo->barrier;        count = ezoo->barrier_count;        break;
          case 2: role_arr = ezoo->regime;         count = ezoo->regime_count;         break;
          case 3: role_arr = ezoo->exit_predictor; count = ezoo->exit_predictor_count; break;
        }
        for (int h = 0; h < count; ++h) {
            const ModelHandle<F> *m = &role_arr[h];
            if (!m->loaded || m->model_path[0] == '\0') continue;
            ++total_handles;

            // Re-parse stamp file from disk to extract grid_member_count.
            // Wasteful (re-opens file) but boundary-stable (no ModelHandle
            // schema change). Boot-time only; not on hot path.
            ModelStampResult sr = verify_model_stamp(
                m->model_path, secret, gap, MODEL_FORMAT_VERSION,
                FEATURE_REGISTRY_HASH(), LABEL_REGISTRY_HASH());
            if (!sr.has_grid_member_count) {
                ++legacy_count;
                continue; // back-compat: legacy + unstamped multi-horizon models
            }
            if (agreed_count < 0) {
                agreed_count = (int)sr.grid_member_count;
            } else if ((int)sr.grid_member_count != agreed_count) {
                fprintf(stderr,
                    "[ensemble_auto_detect] REFUSED: handle role=%d h=%d "
                    "stamps grid_member_count=%u; expected %d. "
                    "Mixed-training-run ensemble.\n",
                    role, h, (unsigned)sr.grid_member_count, agreed_count);
                EnsembleModelZoo_Free(ezoo); // unwind partial load
                return 0; // refuse — match function contract (returns "total loaded")
            }
        }
    }
    if (agreed_count > 0) {
        fprintf(stderr,
            "[ensemble_auto_detect] OK: %d/%d handles agree on grid_member_count=%d\n",
            (total_handles - legacy_count), total_handles, agreed_count);
    } else if (legacy_count > 0) {
        fprintf(stderr,
            "[ensemble_auto_detect] WARN: %d/%d handles missing grid_member_count "
            "(unstamped multi-horizon model OR pre-v5.10.0a.G.2 ensemble); "
            "consistency check skipped. "
            "TODO(v5.10.X): wire stamp_write_for_model into "
            "train_multi_horizon_worker_fn to emit stamps.\n",
            legacy_count, total_handles);
    }
}
```

**Field-name verification (readiness audit P2.4):** `ezoo->exit_predictor` (NOT `ezoo->exit`); count fields are `buy_signal_count` / `barrier_count` / `regime_count` / `exit_predictor_count` (verified at CoreModelZoo.hpp:614 and surrounding struct decl).

**Return-value contract (readiness audit P2.5):** `EnsembleModelZoo_AutoDetectFromDir` returns "total models loaded" (lines 1166, 1192, 1128 all return 0 on failure). REFUSE path returns 0 (NOT -1) to match contract; callers gate on `n_loaded > 0`.
