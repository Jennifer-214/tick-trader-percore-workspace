## Theme

`EventLoop_RebuildOneCore` (`CoreFrameworks/ControllerEventLoop.hpp:1768`)
runs every poll cycle, rebuilding regime + strategy parameters even
when the slow_state hasn't changed materially. Estimated 30-50% of
slow-path cycles are no-ops on a stable regime; current code rebuilds
anyway.

Ship: dirty flag set by `EventLoop_UpdateRollingStateOneCore`
(`:1657`) when slow_state changes materially; consumed-and-cleared by
`EventLoop_RebuildOneCore`. If 0 on entry, return early after
republishing previous parameters with new `publish_tick` (Phase 1.B
compatibility — staleness gate would false-fire otherwise).

## Phase A — `slow_state_dirty` flag + cfg (`v5.12.2.B.1`)

**Goal:** Add a dirty flag to per-core slow_state. Set by
update-rolling-state when material changes detected; consumed by
rebuild.

**Step 0:** Add field to `CoreSlowState` (per-core slow state owned
by `state.cores[c].slow_state`; per CLAUDE.md item 4 "Per-core data-
plane: each engine owns its rolling/regime/flow state v5.1.2+"):

```cpp
// CoreFrameworks/ControllerEventLoop.hpp adjacent to existing CoreSlowState
// (v5.1.2+)
// v5.12.2.B: dirty flag for lazy rebuild. Single-writer (owning core's
// slow-path); no atomic needed — slow-path is single-threaded per core.
int slow_state_dirty;
```

**Cfg fields** in `ControllerConfig.hpp`:
- `int lazy_rebuild_enabled;` (default 0 = always rebuild = current
  behavior. Operator flips to 1 after parity validation.)
- `uint64_t lazy_rebuild_force_period_ticks;` (default 10000 =
  100 × poll_interval. Worst-case rebuild cadence even with zero
  material change.)
- `FPN<F> lazy_rebuild_price_threshold_pct;` (default 0.0005 =
  0.05%. Minimum price change to mark dirty.)

**Setting the flag:** `EventLoop_UpdateRollingStateOneCore`
(`:1657`) — after each `RollingStats_Push`, check the conditions:

```cpp
// v5.12.2.B: detect material change worth rebuilding for
// 1. price moved >= threshold since last rebuild
// 2. tick gap > 1s (regime might have shifted during quiet)
// 3. regime hint shift (any of the regime classifier's threshold
//    fields on slow_state changed since last rebuild)
FPN<F> price_change_pct = FPN_Sub<F>(rs->price_avg,
                                     slow_state->price_at_last_rebuild);
price_change_pct = FPN_AbsDivBy<F>(price_change_pct, slow_state->price_at_last_rebuild);
int dirty_price = FPN_MagGe<F>(price_change_pct,
                               cfg.lazy_rebuild_price_threshold_pct);
int dirty_gap = (now_us - slow_state->us_at_last_rebuild) > 1000000;
int dirty_regime_hint = (slow_state->regime_hint_dirty_bit != 0);

slow_state->slow_state_dirty |= (dirty_price | dirty_gap | dirty_regime_hint);
```

**Tests** (+3): dirty-on-price-change; dirty-on-gap; dirty-on-regime-
hint-shift.

**Tag:** `v5.12.2.B.1`.

## Phase B — `RebuildOneCore` lazy-skip + republish-tick (`v5.12.2.B.2`)

**Goal:** When dirty flag = 0 on entry, skip the heavy rebuild but
STILL republish the parameters (with current tick as new
publish_tick) so v5.12.1.B's staleness gate doesn't false-fire.

**CRITICAL FORWARD DEP:** v5.12.1.B added `publish_tick` to
`ParameterSlot<T>` and the hot-path staleness gate that fires
`SHALT_PARAM_STALE` when `now_tick - publish_tick > max_age`. This
ship MUST keep `publish_tick` fresh on lazy-skip cycles, else the
gate false-fires during legitimate quiet periods.

**Step 0:** Edit `EventLoop_RebuildOneCore` at
`CoreFrameworks/ControllerEventLoop.hpp:1768`. At function entry:

```cpp
// v5.12.2.B: lazy-skip when slow_state hasn't changed materially
if (cfg.lazy_rebuild_enabled && slow_state->slow_state_dirty == 0) {
    // Skip the rebuild but republish prior params with current tick.
    // Reads current params from slot, writes them back with new
    // publish_tick. The seqlock-paired write ensures hot-path readers
    // see (same payload, fresh tick) atomically.
    GateParameters<F> current_params;
    ParameterSlot_Read(&state->core_param_slots[c], &current_params);
    ParameterSlot_Write_AndPublishTick(
        &state->core_param_slots[c],
        current_params,    // unchanged payload
        now_tick);          // refreshed publish_tick
    return;
}

// dirty flag set: do full rebuild + clear flag
slow_state->slow_state_dirty = 0;
slow_state->price_at_last_rebuild = rs->price_avg;
slow_state->us_at_last_rebuild = now_us;

// ... existing rebuild body unchanged below ...
```

**Tests** (+4):
1. always-dirty mode (lazy_rebuild_enabled=0 OR threshold=0 → current
   behavior preserved bytewise on 10M-tick replay)
2. always-clean mode (threshold=∞ → rebuild only on time-bound
   forcing; parity drift after N cycles measured + logged)
3. publish_tick freshness on skip path (slow-path skipped → next
   hot-path read sees fresh tick → SHALT_PARAM_STALE NOT raised)
4. Multi-core: dirty flag is per-core, no cross-core leakage

**Tag:** `v5.12.2.B.2`.

## Phase C — Time-bound force rebuild (`v5.12.2.B.3`)

**Goal:** Even with zero material change, force a full rebuild every
`lazy_rebuild_force_period_ticks` so we don't miss an undetected
regime drift. Worst-case: one missed regime shift per
`force_period_ticks`.

**Step 0:** Add to `RebuildOneCore` entry, BEFORE the lazy-skip
predicate:

```cpp
// v5.12.2.B.3: time-bound force rebuild. Even if "clean", rebuild
// every force_period_ticks to bound worst-case missed regime shift.
uint64_t cycles_since_last_rebuild = now_tick - slow_state->tick_at_last_rebuild;
if (cycles_since_last_rebuild >= cfg.lazy_rebuild_force_period_ticks) {
    slow_state->slow_state_dirty = 1;  // force-mark dirty
}
```

`tick_at_last_rebuild` is updated when the dirty flag is cleared (=
when a real rebuild happens, NOT on republish-tick path).

**Tests** (+2):
1. Force-rebuild fires at exactly `force_period_ticks` after last
   real rebuild
2. Synthetic regime-shift test: regime change at tick T → rebuild
   happens within `force_period_ticks` of T worst case (regime
   classification correctness preserved within this bound)

**Tag:** `v5.12.2.B.3`.
