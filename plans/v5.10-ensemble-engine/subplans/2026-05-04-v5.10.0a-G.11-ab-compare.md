# v5.10.0a.G.11 — A/B comparison mode (ensemble vs single-model)

**Date:** drafted 2026-05-04
**Branch:** `feat/v5.10-foundation`
**Predecessor:** v5.10.0a.G.10
**Effort estimate:** ~2-3h
**Hot path:** UNTOUCHED (slow-path A/B logging only)

## Theme

Operator confidence-builder: when ensemble mode is active, optionally
ALSO run a single-model predict per slow-path (using a "control"
model path), log which prediction would-have-been-better on each
closed trade. After a week of paper-trading: "ensemble outperformed
single-model by X bps" or "didn't help; revert."

This is a DIAGNOSTIC ship — operator opt-in for validation. Does NOT
change deployment behavior; just logs the comparison.

### #3 — A/B predict + log (~1h)

In `MLStrategy_BuySignal` (post-ensemble-predict):
```cpp
if (state->ab_control_model && Model_IsLoaded(state->ab_control_model)) {
    float control_pred = Model_Predict(state->ab_control_model,
                                        state->feature_buf, n);
    // Log to ring buffer alongside ensemble predictions
    ezoo->ab_control_predictions[ezoo->reward_ring_head] = control_pred;
}
```

At trade-close (G.8 hook): when looking up entry-time prediction
record, ALSO look up control prediction. Log which was correct:
```cpp
double ensemble_correct = ((ensemble_pred > 0.5) == (pnl_dir > 0)) ? 1.0 : 0.0;
double control_correct  = ((control_pred  > 0.5) == (pnl_dir > 0)) ? 1.0 : 0.0;
fprintf(stderr, "[ab-compare] core %d trade closed; ensemble=%s "
                "(pred=%.3f), control=%s (pred=%.3f), pnl_bps=%.2f\n",
        core_id,
        ensemble_correct ? "✓" : "✗", ensemble_pred,
        control_correct  ? "✓" : "✗", control_pred,
        realized_pnl_bps);
// Increment counters
ezoo->ab_ensemble_wins += ensemble_correct;
ezoo->ab_control_wins += control_correct;
ezoo->ab_total_trades++;
```

## Risk register

| Risk | Mitigation |
|---|---|
| Control model bloat (extra ModelHandle per core) | Operator opt-in; default empty path = no allocation |
| A/B predict adds latency | Same scaler reuse pattern as G.7's per-horizon caching; control prediction is 1 extra Booster call |
| Control model fingerprint mismatch with ensemble's | Diagnostic-only; mismatched scalers/features still produce a number; operator interprets the comparison knowing the divergence |
| A/B counters race-by-thread | Single-writer (slow-path); same pattern as bandit_state writes |

## Verification

- ML Status panel A/B section shows running counts + recommendation
- Switch operator deployment based on A/B verdict
