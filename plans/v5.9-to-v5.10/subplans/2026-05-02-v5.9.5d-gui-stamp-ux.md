# v5.9.5d — GUI stamp UX hardening (3 HIGH-severity fixes)

**Date:** 2026-05-02
**Branch:** `feat/v5.9-ml-hardening`
**Predecessor:** v5.9.5c (bash CLI parity)
**Effort estimate:** ~1.5h
**Hot path:** UNTOUCHED (suite GUI panels only)

## Context

v5.9.5c closed the bash CLI parity gap. v5.9.5b closed the
in-process auto-stamp gap. Both closed `Backtest_RunFullValidation`'s
auto-stamp end-to-end. **But the GUI workflow has 3 HIGH-severity
operator-visible gaps** that defeat Jenny's "not relying on CLI as
backup" bar:

1. Train Model scaler_sha256 only logged via `fprintf(stderr, ...)`
   → invisible inside foxml_suite
2. Train Model status doesn't tell operator the next step (Run Full
   Validation to auto-stamp)
3. Verify Stamp button shows only "OK/FAIL" — not what's actually
   in the stamp body

This ship closes those three. **Defers** the architectural Fix #4
(Run Full Validation persisting + binding scaler) to v5.10 — that's
a design call about whether RFV should duplicate Train Model's
scaler-persist or pick up an existing sidecar from a prior Train
Model run.

## Scope

### Fix #1 — Train Model: scaler SHA visible in GUI

Add `train_scaler_sha256_hex[80]` field to BacktestPanelsState (or
appropriate worker-shared state). Populate from `train_model_worker_fn`
post-Persist. Render in Training panel result section after
training completes.

Operator sees: `scaler: <hex>` (copyable label) in the Training
panel, not buried in stderr.

### Fix #2 — Train Model: "next step" guidance

Append a hint to the Train Model status message when scaler is
persisted:

- Current: `"Model saved to <path> [+scaler]"`
- New:     `"Model saved to <path> [+scaler] — next: Run Full Validation to auto-stamp"`

When scaler is NOT persisted (degenerate case):
- Current: `"Model saved to <path>"`
- New:     `"Model saved to <path> — next: Run Full Validation to auto-stamp"`

One-line change in `train_model_worker_fn` status emit.

### Fix #3 — Verify Stamp: show recorded fields

Currently shows: `"OK — engine=<version> registry=<hash>"` on
success.

New: show via tooltip OR expandable inline tree the full stamp
body recorded values:

- engine_version (already shown)
- feature_registry_hash (already shown)
- gap, gap_threshold, held_out_metric (training metrics)
- training_poll_interval (if `has_training_poll_interval=1`)
- model_num_outputs (if `has_model_num_outputs=1`)
- scaler_sha256 (if `has_scaler_fields=1`)
- inference_cfg summary (if `has_inference_cfg=1`):
  `confidence_threshold_scale`, `barrier_gate_enabled`,
  `confidence_hard_block_threshold`, `held_out_fraction`,
  `freshness_tau`
- bandit_blend_ratio (if `has_inference_cfg_bandit=1`)
- fee_rate_maker/taker (if `has_inference_cfg_fees=1`)

Implementation: extend `stamp_verify_msg` from a single string to a
structured display. Either:
- (A) Stretch the existing `char stamp_verify_msg[128]` to a larger
  buffer with multi-line content rendered via ImGui::TextWrapped,
  OR
- (B) Add a new `ModelStampResult stamp_verify_full` field that
  Verify Stamp populates; the Models panel renders fields when
  present.

(B) is cleaner — preserves existing single-line summary AND adds
a "Stamp details" expandable section.

## Rollback

If any of the 3 fixes regresses Train Model or Verify Stamp:
revert to `pre-v5.9.5d`. Hotfixes are independent, so one fix
can be reverted while keeping the others if necessary.

## Why this should ship before merging to main

- Closes the operator-visible workflow break (Train Model → no
  scaler hex visibility = operator must drop to terminal).
- Verify Stamp is the operator's main audit tool; minimal output
  defeats the purpose.
- All 3 fixes are display-only (no math, no hot path, no parity
  surface change). Risk-bounded.
