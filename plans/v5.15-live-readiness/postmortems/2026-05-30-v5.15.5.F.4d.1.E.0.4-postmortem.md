# Postmortem — v5.15.5.F.4d.1.E.0.4 — doc/meta-system rollout (TECH_DEBT-115 memory slice)

**One line:** brought the ~85 `memory/*.md` into the structured tag/frontmatter system so the existing `check_doc_metadata` machinery covers them — closing the CP-1 (sister-link asymmetry) + WH-1 (name-slug link drift) meta-error family **mechanically (red build)** for memories. META; no engine code; bodies byte-identical.

## What shipped

- **85 memories migrated** to the canonical schema: harness-native `name`/`description`/`metadata.type` PRESERVED (the recall system reads them), with doc-system `tags` + `sister_specs` nested **under `metadata:`** (rewrite-durability — the harness canonicalizes extras there).
- **CP-1 closed by construction** — `sister_specs` derived from inline `[[links]]` as an UNDIRECTED graph (auto-reciprocated): 0 asymmetries. The guard still catches future MANUAL asymmetry.
- **WH-1 closed** — name-slug `[[links]]` (often unprefixed kebab, e.g. `[[plan-right-not-fast]]`) resolved to filenames via suffix-matching; 4 genuine dangling forward-refs left as INFO.
- **Tags** — 3-5 concern tags/memory (finer, per operator) + **10 NEW concern tags** registered in `doc-tag-vocabulary.md`.
- **NEW reusable infra:** `tools/migrate_memory_frontmatter.py` (idempotent; undirected-graph sister derivation; `--set-tags`; **R6-void by preserve-all-fields**) + `tools/memory_tags.json` + memory template + `/doc-create memory` wired.
- **`check_doc_metadata` extended:** machine-portable memory-dir resolver (`$FOXML_MEMORY_DIR` + derived default; multi-machine/grid-ready) + memory scan root + dual-tree `sister_specs` resolution + `.md`-tolerant bidirectional + `--memories` guard, **wired into `/capture-audit` Check 12**.
- **`rebuild_doc_indexes` + `/find` include memories** (TAG_INDEX: 85 memories, 177 tag-refs). `doc-frontmatter-convention.md` Stage 2→3.

## Key decisions (D-89)

The plan was GREEN at the design-shape level; grounding Phase A in the actual checker + live files surfaced 3 implementation-detail forks (the readiness/blindspot layer working):

1. **Machine-portable memory-dir resolver** (operator: design for >1 computer / SSH-grid) — env override + derived default, not a `$HOME` hardcode. Cross-node memory *sync* itself = forward-promise.
2. **One unified `sister_specs` field** (operator: "naming semantics") — not separate `sister_memories`; checker resolves each ref against both the memory tree and `DESIGN_SPECS/`.
3. **New/extended infra blessed when it compounds** (operator) — dropped the "pure-reuse, zero-change" framing; honestly EXTENDED the one checker.

Two self-derived calls (flagged, not vetoed): doc-system fields **nest under `metadata:`** for harness-rewrite durability (and the flat parser surfaces them as top-level for free → no parser change); `sister_specs` is an **undirected related-graph** (optimized for agent navigation per operator).

## Residual risks / monitor

- **R6 (harness rewrite) — MANIFESTED at close-session dogfood + CLOSED structurally.** Writing a NEW memory via the agent `Write` tool triggered the harness to re-serialize its frontmatter inline→BLOCK-style YAML (flat parser reads block `tags:` as empty → *silent* tag loss; the guard even went green on the broken file). Caught only because the harvest dogfooded a real `Write` (and the operator's "are you sure?" prompted the harvest). **Fix:** `check_doc_metadata` + `migrate_memory_frontmatter` made block-tolerant (read inline AND block; helper `collapse_block_lists` canonicalizes); `tools/test_memory_guard.py` permanent regression fixture (5/5). **Key finding:** the harness normalizes *agent-Write'd* memory files, NOT Python/helper writes — both forms now validate identically. Textbook case for dogfooding the actual *creation* path, not just the migration path.
- **Flat-parser coupling** — metadata-nesting relies on `check_doc_metadata`'s flat line-parser; a real-YAML upgrade needs explicit memory `metadata.*` flatten (breadcrumb in code).
- **Body `[[links]]` kept name-slug** (WH-1 closed in frontmatter, cosmetic in prose); **`sister_specs` capture inline links only** (conceptual `**Sister:**`-prose sisters not captured); **cross-node sync** deferred; **`MEMORY.md` index** not reconciled (likely next helper extension). Full list in the plan's "Known limitations / monitor".
