## TL;DR

**Layer 2 of hot-reload discipline** (Layer 1 = config reload via SIGUSR1 from `.E.2`). Strategies compile to shared libraries (`.so` files); engine `dlopen`s + holds function pointer; SIGUSR2 → reload-and-swap atomically. Per-node slow-path picks up new strategy pointer at next cycle.

**Power-user feature** (per D-8). Most operator needs satisfied by Layer 1 config reload (~95%). Layer 2 covers the rare case of swapping strategy CODE without engine restart.

**Five major changes:**

1. **Per-strategy .so build target.** build.sh adds per-strategy .so targets (e.g., `libstrategy_momentum.so`, `libstrategy_ml.so`).

2. **Dynamic strategy loading.** Engine boot loads .so via dlopen; resolves symbols (strategy_init / strategy_evaluate / strategy_close); stores function pointers in per-node hot cluster.

3. **Atomic strategy pointer swap.** SIGUSR2 → load NEW .so; atomic_exchange pointer; OLD .so kept until next slow-path cycle entry (grace period); then dlclose OLD.

4. **H7 hot path preservation.** Hot path reads `node.hot.strategy_fn_ptr` (atomic; cached); branchless dispatch. Same shape as `.E.1` fn-pointer-table; just pointer values can change.

5. **State migration handling.** When strategy swapped, OLD strategy's state must be preserved or cleared. Per `feedback_audit_canonical_sister_before_new_infra` — strategy state machine + per-node Position state stays; only function pointer changes.

## Architecture deep-dive

### dlopen lifecycle + ABI stability

**The challenge:** Strategy code lives in a `.so` (shared library). Engine loads it at boot via `dlopen`. To hot-reload, engine needs to:
1. Load NEW `.so` while OLD `.so` still active
2. Atomically swap the strategy function pointer (publish to per-node hot path)
3. Wait for grace period (ensure hot path no longer references OLD)
4. Close OLD `.so` via `dlclose`

This is the standard "atomic pointer swap with grace period" pattern, used in many production systems (Linux kernel RCU; many JIT compilers; etc.).

**ABI contract (CRITICAL for stability):**

```cpp
// In ALL .so files; extern "C" for stable C ABI (no name mangling; no v-table dependency)

extern "C" {
    // REQUIRED exported symbols per strategy .so:

    // Initialize per-node strategy state (called once per node at load OR reload)
    // Returns opaque pointer to strategy-specific state struct
    // params: StrategyParameters<F> from cfg
    // Returns NULL on failure
    void* strategy_init(const void* params);

    // Evaluate per-tick on hot path (CRITICAL latency; branchless preferred per H7)
    // state: pointer returned by strategy_init
    // tick: per-tick context
    // Returns TradeDecision (BUY/SELL/HOLD with sizing)
    TradeDecision strategy_evaluate(void* state, const void* tick);

    // Slow-path rebuild (called at slow-path cadence; can be branchy)
    // state: pointer returned by strategy_init
    // rebuild_context: slow-path rebuild input
    void strategy_rebuild(void* state, const void* rebuild_context);

    // Close + free per-node strategy state (called at unload OR engine shutdown)
    void strategy_close(void* state);

    // Strategy metadata (for engine to query without loading state)
    const char* strategy_name(void);
    const char* strategy_variant_id(void);   // e.g., "momentum_v3.1"
    uint32_t strategy_abi_version(void);     // bump on signature changes

    // OPTIONAL exports (engine queries existence via dlsym):
    // void strategy_state_serialize(void* state, void* out_buf, size_t* len);
    // void* strategy_state_deserialize(const void* in_buf, size_t len);
}
```

**ABI version check at load:**
- Engine has compile-time `ENGINE_STRATEGY_ABI_VERSION` constant
- Each `.so` exports `strategy_abi_version()` returning its ABI version
- On dlopen: verify match (or compatible range)
- Mismatch → refuse load + alert operator

This catches the case where engine has been updated (ABI bumped) but operator forgot to rebuild strategy `.so`.

### Dynamic strategy loading

```cpp
// CoreFrameworks/StrategyLoader.hpp (NEW)

// Per-strategy contract (extern "C" for stable ABI)
extern "C" {
    typedef void* (*strategy_init_fn)(const StrategyParameters<F>& params);
    typedef TradeDecision (*strategy_evaluate_fn)(void* state, const TickContext<F>& tick);
    typedef void (*strategy_close_fn)(void* state);
}

struct StrategyHandle {
    void* dl_handle;                          // dlopen return
    strategy_init_fn init_fn;
    strategy_evaluate_fn evaluate_fn;
    strategy_close_fn close_fn;
    void* per_node_state;                     // strategy-specific state (allocated via init_fn)

    uint64_t loaded_at_us;
    char source_path[256];                    // .so file path; for re-load
};

int StrategyLoader_Load(const char* so_path, StrategyHandle* handle) {
    handle->dl_handle = dlopen(so_path, RTLD_NOW | RTLD_LOCAL);
    if (!handle->dl_handle) return -1;

    handle->init_fn = (strategy_init_fn)dlsym(handle->dl_handle, "strategy_init");
    handle->evaluate_fn = (strategy_evaluate_fn)dlsym(handle->dl_handle, "strategy_evaluate");
    handle->close_fn = (strategy_close_fn)dlsym(handle->dl_handle, "strategy_close");

    if (!handle->init_fn || !handle->evaluate_fn || !handle->close_fn) {
        dlclose(handle->dl_handle);
        return -2;
    }

    strncpy(handle->source_path, so_path, sizeof(handle->source_path) - 1);
    handle->loaded_at_us = NowUs();
    return 0;
}
```

### Atomic pointer swap with grace period (the heart of hot-reload)

**Why grace period is essential:**

Without grace period:
1. Engine atomic_exchange function pointer (OLD → NEW)
2. dlclose(OLD .so) immediately
3. Hot path mid-evaluation with OLD strategy code... CRASH (use-after-free)

With grace period:
1. Engine atomic_exchange function pointer (OLD → NEW)
2. Wait for grace period (1 slow-path cycle minimum; ensures hot path has read fresh pointer)
3. Call OLD strategy_close (frees state)
4. dlclose(OLD .so)

**The single-reader-per-pointer guarantee:**

Per-node hot path is THE ONLY reader of `node.hot.strategy_evaluate` pointer (single-reader; lock-free). Hot path reads the atomic at the TOP of each tick processing; subsequent operations within that tick use the cached value.

So if we swap the pointer between ticks (during slow-path cycle), the next hot-path tick reads the NEW pointer. The OLD pointer is no longer referenced after the next-slow-path-cycle boundary.

**Grace period implementation:**

```cpp
void NodeSlowPath_HandleSIGUSR2_StrategyReload(NodeState<F>& node, const char* new_so_path) {
    // Phase 1: Load NEW .so
    StrategyHandle new_handle;
    if (StrategyLoader_Load(new_so_path, &new_handle) != 0) {
        LOG_ERROR("Failed to load new strategy: %s", new_so_path);
        return;
    }

    // Verify ABI compatibility
    if (new_handle.abi_version_fn() != ENGINE_STRATEGY_ABI_VERSION) {
        LOG_ERROR("Strategy ABI mismatch: engine=%u, so=%u",
                  ENGINE_STRATEGY_ABI_VERSION, new_handle.abi_version_fn());
        StrategyLoader_Unload(&new_handle);
        return;
    }

    // Phase 2: Initialize new strategy with current params
    new_handle.per_node_state = new_handle.init_fn(&node.hot.params);
    if (!new_handle.per_node_state) {
        LOG_ERROR("New strategy init failed");
        StrategyLoader_Unload(&new_handle);
        return;
    }

    // Phase 3: Save OLD state for grace-period cleanup
    StrategyHandle old_handle = {};
    old_handle.dl_handle = node.hot.strategy_dl_handle;
    old_handle.evaluate_fn = node.hot.strategy_evaluate.load(std::memory_order_acquire);
    old_handle.close_fn = node.hot.strategy_close_fn;
    old_handle.per_node_state = node.hot.strategy_state.load(std::memory_order_acquire);

    // Phase 4: ATOMIC SWAP (publish NEW pointer)
    // After this point, next hot-path tick sees NEW
    node.hot.strategy_evaluate.store(new_handle.evaluate_fn, std::memory_order_release);
    node.hot.strategy_state.store(new_handle.per_node_state, std::memory_order_release);
    node.hot.strategy_dl_handle = new_handle.dl_handle;
    node.hot.strategy_close_fn = new_handle.close_fn;
    node.hot.strategy_variant_id = new_handle.variant_id_fn();

    // Phase 5: Grace period (wait for hot path to see new pointer)
    // Per-node hot path reads atomic at tick entry; one tick = guaranteed see-new
    // Conservatively: wait 1ms (much more than any tick budget)
    // OR: track tick counter; wait until tick_counter has incremented N times
    WaitForGracePeriod(node, /*tick_count=*/2);

    // Phase 6: Clean up OLD
    old_handle.close_fn(old_handle.per_node_state);  // free state
    dlclose(old_handle.dl_handle);                   // unload .so

    LOG_INFO("Strategy hot-reload complete: node=%u, variant=%s",
             node.binding.subaccount_id, new_handle.variant_id_fn());
    MetricsCounter_Increment("fox_strategy_hot_reload_success");
}

void WaitForGracePeriod(NodeState<F>& node, uint32_t tick_count) {
    uint64_t baseline = node.hot.tick_counter.load(std::memory_order_acquire);
    while (true) {
        uint64_t current = node.hot.tick_counter.load(std::memory_order_acquire);
        if (current >= baseline + tick_count) break;
        // Slow-path is calling this; producer hot-path runs in parallel
        // Just yield/sleep tiny amount
        usleep(100);  // 100μs
    }
}
```

```cpp

struct NodeState {
    alignas(64) struct {
        // ... existing ...
        std::atomic<strategy_evaluate_fn> strategy_evaluate;  // ATOMIC
        std::atomic<void*> strategy_state;                    // ATOMIC
    } hot;

// Hot path reads atomic pointer; branchless dispatch (H7 preserved)
TradeDecision NodeHotPath_Evaluate(NodeState<F>& node, const TickContext<F>& tick) {
    strategy_evaluate_fn evaluate = node.hot.strategy_evaluate.load(std::memory_order_acquire);
    void* state = node.hot.strategy_state.load(std::memory_order_acquire);
    return evaluate(state, tick);  // function call; branchless
}

// SIGUSR2 handler (in slow-path context; per-node)
void NodeSlowPath_HandleSIGUSR2(NodeState<F>& node, const char* new_so_path) {
    // Load NEW .so
    StrategyHandle new_handle;
    if (StrategyLoader_Load(new_so_path, &new_handle) != 0) {
        LOG_ERROR("Failed to load new strategy: %s", new_so_path);
        return;
    }

    // Initialize new strategy with current params
    new_handle.per_node_state = new_handle.init_fn(node.hot.params);

    // ATOMIC SWAP — hot path sees old until this point; new from now on
    strategy_evaluate_fn old_evaluate = node.hot.strategy_evaluate.exchange(
        new_handle.evaluate_fn, std::memory_order_acq_rel);
    void* old_state = node.hot.strategy_state.exchange(
        new_handle.per_node_state, std::memory_order_acq_rel);

    // Grace period: wait one slow-path cycle to ensure hot path no longer references old
    // (Hot path read atomic at cycle entry; slow-path cycle ends → hot has fresh pointer)
    WaitForSlowPathCycleEnd();

    // Clean up old strategy
    node.hot.strategy_close_old_fn = ...;  // stored separately for cleanup
    node.hot.strategy_close_old_fn(old_state);
    dlclose(node.hot.dl_handle_old);
}
```

### Per-node strategy state preservation discipline

**What gets preserved across swap (engine-owned; NOT in .so):**
- Per-node Position state (NodeState.drainer_state.orders + open_position)
- Per-node CoreContext (NodeState.slow_account; P&L; balance; etc.)
- Per-node kill flags
- Per-cluster shared state (rate budget; aggregator state)
- Aggregator state (totals; running aggregates per D-54)

**What gets reset across swap (strategy-owned; in .so):**
- Strategy internal state (e.g., EMA values; ML model predictions cache; bandit arms)
- Strategy variant tagging (variant_id field changes to new variant)

**Hybrid case: strategy state that's "useful to preserve" but not engine-owned:**

Example: Momentum strategy's `last_signal_direction`. Strategy could:
- Option A: Re-initialize from cfg (fresh start; may cause incorrect signals for a few ticks)
- Option B: Implement `strategy_state_serialize` + `strategy_state_deserialize` (OPTIONAL exports); engine pickles state across swap
- Option C: Read engine state to reconstruct (e.g., from recent fills)

Most strategies: Option A is fine. Power-user can implement Option B if needed.

```cpp
// Optional: strategy provides serialize/deserialize for state continuity across swap

// In OLD .so:
extern "C" void strategy_state_serialize(void* state, void* out_buf, size_t* len);

// In NEW .so:
extern "C" void* strategy_state_deserialize(const void* in_buf, size_t len);

// In engine swap logic:
uint8_t state_buf[4096];
size_t state_len = sizeof(state_buf);

if (old_handle.serialize_fn && new_handle.deserialize_fn) {
    old_handle.serialize_fn(old_handle.per_node_state, state_buf, &state_len);
    new_handle.per_node_state = new_handle.deserialize_fn(state_buf, state_len);
} else {
    // Fall back to init from cfg
    new_handle.per_node_state = new_handle.init_fn(&node.hot.params);
}
```

## Honest risks (with worked examples)

### R1 — Use-after-free on strategy state during swap

**Risk:** Hot path is mid-evaluation when atomic swap happens. Hot path has a cached pointer to OLD strategy_state. Engine calls strategy_close(OLD) + dlclose(OLD .so). Hot path returns from old_evaluate → use-after-free.

**Worked example:** Hot path is evaluating a momentum strategy at tick T. Reads atomic pointer at T_start = old_evaluate. Slow-path swap happens at T_start + 100ns (atomic_exchange). Hot path completes evaluation at T_start + 500ns; returns. If dlclose happens at T_start + 200ns: UAF when hot path returns (function epilogue references freed code).

**Mitigation:**
- Grace period waits for hot path tick_counter to increment 2+ times after swap
- Hot path reads atomic at tick entry → fresh pointer on next tick
- 2-tick grace period guarantees no in-flight evaluation using OLD pointer
- Conservative: WaitForGracePeriod also has 1ms timeout fallback

**Verification:**
- Chaos test: 10000 rapid swaps with active trading; verify zero UAF (ASAN)
- Static analysis: TSAN run during chaos test

**Severity:** HIGH (potential UAF if grace period miscalculated; well-mitigated by 2-tick grace + tick_counter discipline)

### R2 — ABI version mismatch silent breakage

**Risk:** Operator rebuilds strategy .so against newer engine; new engine has same ABI version but adds optional features that strategy uses. Old engine still loads new .so successfully but optional features fail silently.

**Worked example:** Engine v0.1.0 has ABI version 1. Operator updates engine to v0.1.1 (still ABI 1; minor change) and updates strategy.so to use new optional feature (state-serialize). Operator runs OLD engine v0.1.0; loads NEW strategy.so. Engine doesn't have state-serialize support; silently uses init-from-cfg path. Strategy operator unaware of feature degradation.

**Mitigation:**
- ABI version bumps on EVERY semantic change (not just signature change)
- Optional features have explicit dlsym check + feature flag exposure to operator
- Boot-time log reports which optional features detected per loaded strategy
- DOCS/CONTRIBUTING/add-strategy.md documents ABI bump discipline

**Severity:** MED (silent degradation vs catastrophic; documented)

### R3 — State assumption mismatch (open positions)

**Risk:** NEW strategy assumes flat positions but operator has open positions. NEW strategy.init_fn doesn't query existing positions; treats node as fresh. Subsequent tick evaluations make wrong decisions (e.g., "open position" when one already open).

**Worked example:** Operator swaps momentum strategy with new variant. Node has open BTCUSDT long. NEW init_fn doesn't see this; sets internal "is_in_position = false". Next tick: NEW strategy considers entering BTCUSDT long (already in!). Submit fails OR over-leverages.

**Mitigation:**
- Strategy.init_fn receives QueryAPI argument (read-only access to node state)
- Strategy queries existing positions via QueryAPI
- DOCS/CONTRIBUTING/add-strategy.md documents requirement: "NEW strategy MUST handle non-flat state"
- Optional: strategy_state_serialize + deserialize preserves continuity

**Severity:** MED (operator-impact bugs; documentation + API support)

### R4 — dlclose timing race

**Risk:** Strategy_state cleanup must happen BEFORE dlclose (state functions live in .so; once closed, calling them = UAF). Sequence must be precise.

**Worked example:** Engine atomic-swaps to NEW. Waits grace period. Calls strategy_close(old_state) — this calls into OLD .so's strategy_close function. Engine then calls dlclose(OLD .so) — code unloaded; if strategy_close ran another async callback or background thread... UAF.

**Mitigation:**
- Strict sequence: grace period → close_fn(state) → wait for close_fn return → dlclose
- Strategy.strategy_close MUST be synchronous (no background threads)
- DOCS/CONTRIBUTING/add-strategy.md documents this requirement
- Verified via chaos test (rapid swaps; ASAN)

**Severity:** MED-HIGH (well-mitigated by discipline + verification)

### R5 — Operator-facing complexity + accidental destabilization

**Risk:** Hot-reload is POWER USER feature. Operator misuse (frequent swaps; wrong .so path; swap during critical trading window) destabilizes engine.

**Worked example:** Operator runs `fox-cli reload-strategy momentum --new-binary new.so` during high-volatility moment. New strategy has subtle bug; engine starts losing money. Operator can rollback but takes 30s to realize.

**Mitigation:**
- fox-cli requires explicit confirmation: `--confirm` flag
- Rollback verb: `fox-cli rollback-strategy <node>` (reverts to previous variant)
- Engine maintains previous .so reference + state continuity hooks for emergency rollback
- DOCS/OPERATOR_MANUAL.md documents safe-swap procedures
- Strongly recommend: test new strategy via paper mode for 1+ session before live swap

**Severity:** MED (operator-impact; well-documented; rollback supported)

### R6 — .so file rebuild + deployment synchronization

**Risk:** Operator updates strategy code in Strategies/Momentum.hpp; runs `./build.sh strategies`; new .so written. Engine still has OLD .so loaded. Operator must explicitly trigger reload via fox-cli.

**Worked example:** Operator's mental model: "I rebuilt .so; engine should pick up automatically." But engine doesn't watch .so files. Operator triggers swap manually; otherwise OLD continues running.

**Mitigation:**
- DOCS/OPERATOR_MANUAL.md explicit workflow: rebuild → fox-cli reload-strategy
- fox-tui shows currently-loaded strategy variant_id (so operator can verify after swap)
- Engine logs strategy loaded path + timestamp (audit trail)
- Optional future: inotify-based auto-reload (deferred; risky without explicit operator action)

**Severity:** LOW-MED (workflow discipline)

### R7 — Memory leak across many swaps

**Risk:** Each swap allocates + frees memory; subtle leak across 1000s of swaps could accumulate.

**Worked example:** Engine runs 90 days; operator swaps strategy 200 times. Each swap leaks 1KB (small bug in close_fn). After 90 days: 200KB leaked. Modest but problematic if accumulated.

**Mitigation:**
- ASAN + valgrind verification at chaos test (10000 swaps; zero leak target)
- Memory tracking: Prometheus metric `fox_strategy_hot_reload_total_swaps` + `fox_engine_resident_memory_bytes` (track for trends)
- Operator alert on memory growth > 1MB/day baseline

**Severity:** LOW (well-tested; observable)

### R8 — Strategy state corruption from concurrent access

**Risk:** Hot path reads strategy_state while slow-path swap is mid-write to strategy_state. Atomic store should prevent torn writes BUT atomic on void* is single 8-byte write on x86_64; safe.

**Worked example:** N/A (atomic store of pointer is guaranteed; we've already addressed)

**Mitigation:** Atomic pointer store + load semantics from C++11 std::atomic. Single 8-byte write on x86_64. No tearing possible.

**Severity:** LOW (architectural guarantee)
