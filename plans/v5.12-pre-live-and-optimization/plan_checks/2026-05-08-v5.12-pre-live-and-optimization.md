### Strategy Code Renaming Reconciliation (3.E)

**Finding:** v5.12.3.E plans to rename `buy_signal` → `primary` in Strategies/MLStrategy.hpp and Strategies/StrategyParameters.hpp.

**Master invariant claim:** "Strategy code unchanged per v5.11.62 invariant."

**Reconciliation:** The v5.11.62 invariant is "strategy code is role-AGNOSTIC" — it doesn't know WHICH role (buy_signal, barrier, regime) is the primary model list. The rename `buy_signal` → `primary` in strategy code INCREASES role-agnosticity (code now reads `ezoo->primary_handles` instead of `ezoo->buy_signal`), making the strategy's model-selection logic independent of role naming.

**Assessment:** This is NOT a violation of the invariant; it's a CLARIFICATION of the invariant. The sub-plan 3.E acknowledges this correctly: "strategy code MUST NOT change" means "no logic changes" — renames that increase abstraction are fine. The post-ship verification (`git diff Strategies/` shows renames only, zero logic edits) will confirm.

**Status:** **YELLOW on wording** — the master plan's phrasing "Strategy code unchanged" is technically true (logic-wise) but could confuse a reader. Recommend re-reading the v5.11.62 invariant definition during coding: "strategy code is role-AGNOSTIC" allows renames that remove role-specific names. Document in commit message.
