### 1. Ridge (v5.14.0) + Composite-Confidence (v5.14.1) overlap?

NO — independent concerns. v5.14.0 reads `ezoo->reward_ring` for
N×N prediction-prediction correlation matrix (Cholesky input);
v5.14.1 reuses `RollingIC` + `RollingRMSE` for scalar confidence
components. Both leverage v5.13.6 rolling-buffer pattern; keep
separate (different math domains). REUSES_EXISTING.

### 2. Maker cancel-and-replace (.7) + Multi-mode reconcile (.4)?

PARTIAL shared primitives, different state machines.

- v5.14.4 boot-time one-shot reconcile uses
  `OrderManager_HandleFill` + `BinanceAdapter_CancelOrder`
- v5.14.7 drainer-thread per-cycle stale-limit scan uses same
  primitives PLUS per-order tracking (`Order.submit_us` +
  `cancel_after_us`)

Shared: `OrderManager_HandleFill`, `BinanceAdapter_CancelOrder`,
`Order.state` queries.

REUSES_HELPER. Logic kept separate preserves causality (boot-
reconcile vs timeout-expiry are orthogonal triggers).

### 3. 3-layer fingerprint (.3) + Stamp lineage (.8) shared helpers?

PARTIAL — same Surface G `has_*` flag pattern, different fields.
NO code duplication. Both add Surface G fields; established
pattern from v5.11.18a. SHA256 utility is stdlib; no custom hash.

REUSES_HELPER. Field separation preserves debugging isolation
(which subsystem drifted?).

### 4. Cfg field collisions?

NONE. 18 new cfg fields across 5 plans; clear naming prefixes:
`ridge_*`, `confidence_*`, `maker_*`, `model_max_*`. Field
`maker_cancel_after_ms` is LIMIT-order specific; no collision
with reconcile. CLEAN.
