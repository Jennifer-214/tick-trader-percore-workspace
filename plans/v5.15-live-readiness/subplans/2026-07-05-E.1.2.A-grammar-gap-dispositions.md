## The 7 grammar gaps

### 1. `[REGION]` sub-unit binding — **ADOPT** (the one genuinely-new granularity)
A struct's per-region (byte-range) / per-bit-slot facts (thread/sync/residency/occupancy) have nowhere structured to bind — they collapse to lossy scalars or un-greppable `[DIAGRAM]` prose = sprawl at region granularity. Grammar needs a level between block + inline-field-tag: `[REGION]_[name]_[byte-range]` (+ a per-bit-slot form) scoping its own `[THREAD]`/`[SYNC]`/`[RESIDENCY]`/`[BIT_OCCUPANCY]`.
- **Plugin support:** HALF-THERE. It already has per-field offsets (`recordlayout.field_size`) + the byte-map render. NEEDS: a **region-grouping overlay** (parse `[REGION]` byte-ranges → named regions on the byte-map + bind per-region facts). New render field in the fact record; data already exists. **Additional field: `regions[]` in facts.lua.**

### 2. `[INSTANTIATION]` — **ADOPT** (distinct DERIVED pin, sibling of `[BUILD]`)
`template<unsigned F>` units have no single instr-count — RollingStats co-lives at W∈{128,256,512,1024}, each a different asm. `[BUILD]` pins the *compiler*; this pins the *template args*, and must express a **SET** (a single-string `[BUILD]` can't). Systemic — even the spec's own Regime_Classify example silently has it. Refute-target considered (fold into `[BUILD]`): rejected — different axis + needs a set.
- **Plugin support:** PARTIAL. `asmexplorer` compiles "the whole buffer, `Foo<64>` as used" — handles ONE instantiation. NEEDS: **multi-instantiation measurement** (compile+measure each W in the set). **Additional field: `instantiations[]` + multi-compile in asmexplorer.**

### 3. Registry→registry topology — **DERIVED-TAG** (`[PARENT]`/`[CHILDREN]`/`[SIDECARS]`/`[OVERRIDES]`)
H16/H18/H19 (metadata-bit→cohort / sidecar-override / parent-level) have no home; only H15 (`[ENROLLED]`) does. Reproducible from MetaRegistry LEVEL/PARENT + FIELD_IDX + if-constexpr filters → fits fork-b cleanly (the cfg-registry agent self-validated this: `[ROW_COUNT]` already flags live 88-vs-79 drift). No grammar change — new DERIVED tags + generator + CI.
- **Plugin support:** NEW DISPLAY, facts from existing CI. The plugin doesn't parse registries today, but `tools/check_meta_registry.py` already computes the topology → plugin **displays** the facts + renders a `[registry-tree]` `[DIAGRAM]`. **Additional: a registry-tree render + consume check_meta_registry output.**

### 4. `[COMPLEXITY]` — **ADOPT** (curated COMPUTE axis)
Amortized/worst-case trip-count (RollingStats "O(1) amortized / O(W) worst" from 3 data-dependent deque pops) — the load-bearing p99 fact for an H8 kernel that `[SIZE]_[instr]` (straight-line) and `[BRANCHES]` (branch-class) both miss. Refute-target (just `[COMMENT]` prose / a `[TAG]_[AMORTIZED]` value): rejected — a structured `[COMPLEXITY]_[amortized../worst..]` is greppable ("show me every O(W) kernel") + carries the bound; prose/flat-tag lose that. Curated (a tool can't infer the amortized bound).
- **Plugin support:** DISPLAY-ONLY (curated). No new derivation. Optional advisory: cross-check the declared bound against the loop/branch structure. **No new field required.**

### 5. `[APPLY_AFTER]` — **ADOPT** (curated sequencing axis)
Walker last-wins expansion ORDER is capital-bearing ("early apply re-arms the founding bug", FOREACH_PER_NODE_ARRAY_OVERRIDE) and lives only in `[WHY]` prose today — the drift-prone situation the schema exists to kill. `[APPLY_AFTER]_[<other-walker>]` makes it queryable + CI-checkable.
- **Plugin support:** DISPLAY + optional ordering-edge in the graph-walk lens (planned). **No new derivation.**

### 6. `[MUTATES]` / `[WRITE_SET]` — **DERIVED-TAG** (materialize compact, full-set on hover)
The write half of the graph — a `void` fn mutating ~25 fields of `*rs` has no slot (`[UPSTREAM]`/`[CONSUMERS]` = reads-in + callers). Refute-target (25-field list is bulky → plugin-live-only per D-307): partial-adopt — materialize a **compact** `[MUTATES]_[N fields]` (+ key ones), full set on plugin hover, to avoid a bulky drift-prone comment.
- **Plugin support:** STRONG — ALREADY THERE. `writers.for_struct` tracks "every reference's enclosing function, **read OR write**" (the density lens). The write-set is already derivable. **Just expose it as `[MUTATES]`; no new capability.**

### 7. `[WIRE_VERSION]` + `[PAIRED_BUMP]` — **DERIVED-TAG under `[REFERENCE]`**
"What do I bump if I touch it" — Position is jointly gated by SHARDED=10 AND CONTROLLER=14 (paired bump, D-302); already drifted live (comment PORTFOLIO=6, ledger=7). Materialize the SET of gating versions + a paired-bump note, CI-checked vs `identifier_ledger.txt`. Borderline category vs DERIVED-under-`[REFERENCE]` → recommend the latter (reuses `[REFERENCE]` grammar).
- **Plugin support:** NEW DISPLAY, facts from a CI tool. Needs a persist-site→version map (a small tool) + ledger cross-check; plugin displays + links to the ledger row. **Additional: a persist→version mapping tool; plugin display only.**

### Clarifications — **BLESS** (no new category; the structure already holds)
- (a) **multiple `[DIAGRAM]_[kind]` per block** — Order needs byte-map + bit-map; MetaRegistry a registry-tree; SHALT a precedence-ladder. Spec says "a `[DIAGRAM]` body" (singular) — bless plural + new kinds.
- (b) **`[DIRECTIVE]` on an X()-row inside `[CODE]`** — per-row tombstones (SHALT).
- (c) **`[CODE]`/`[END_CODE]` for non-contiguous units** — Order = consts + struct + accessors across 3 regions; SHALT's real artifacts (generated enum/name-table/static_assert) sit OUTSIDE the macro. Decide: multiple framed segments per unit, or the consts/accessors get their own sub-blocks.
- **Plugin support:** the `[DIAGRAM]` renderer needs multiple-kinds-per-unit + new kinds (registry-tree, precedence-ladder, code→semantics table). New render kinds.

## Two cross-cutting refinements (ADOPT — they resolve real conflicts the scan exposed)

### A. Preserve-voice **CARVE-OUT** — DERIVED-class facts are REGENERATED, never relocated
Position carries a STALE hand byte-map (24B/192B, survived the 16B flip, contradicts its own `static_assert(==128)`) *alongside* the current one; MetaRegistry's "Row shape: X(name,LEVEL,PARENT,description)" is a structural fact masquerading as prose (already drifted 8-col vs 4-col). Preserve-voice says relocate verbatim; DERIVED says regenerate. **Resolution: a stale hand-fact is BOTH → the conversion DROPS it, never relocates it.** Carve-out: **byte-maps / sizes / versions / row-shapes / any DERIVED-class fact are TOOL-REGENERATED; only rationale / history / author-voice is preserved verbatim.** (No plugin impact — conversion rule.)

### B. Unit-level `[LAT_EXEMPT]` for non-latency code — suppress the DERIVED latency quartet
For a 60Hz GUI render fn (EngineHeader_Render), `[SIZE]_[instr]` has no generator, `[SIMD]` is noise, `[BRANCHES]_[H7/H20 meter]` is actively misleading. Non-hot/non-capital units carry a unit-level `[LAT_EXEMPT]` → suppress the DERIVED latency quartet + skip the conformance generator + CI does NOT flag the omission. (Proportionality — no forced hot-path ceremony on support code.)
- **Plugin support:** the HUD suppresses the latency quartet for `[LAT_EXEMPT]` units. Display logic.
