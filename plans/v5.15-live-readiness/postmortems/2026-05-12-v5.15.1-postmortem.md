## What worked

1. **Reuse of existing state_flags bitmap (TECH_DEBT-028).** The migration didn't create a new bitmap surface — it extended the existing PerCoreStateFlagsRegistry. Cohort homogeneity preserved per the CLAUDE.local.md going-forward rule 2026-05-11. The migration was 4 X-macro registry rows + per-site STATE_FLAG_* dispatch. Mechanical + bounded.
2. **Single-chokepoint drift detection.** ALL drift bits get set at TryLoadRole post-verify. CLAUDE.md item 9 (NaN-free chokepoint precedent) applied directly. Future arch-field drift checks = 1 row in FOREACH_ARCH_FIELD_DRIFT. Future CFG-bound drift = 0 LOC (existing CFG loop already counts).
3. **MASTER `_hot_pad1` repurposed for drift_flags_at_load.** v5.15.0 left 16B of explicit padding in ModelHandle's HOT cluster. Repurposing 2B of that for `drift_flags_at_load` cost zero alignment churn — static_assert(sizeof % 64 == 0) still holds; offsetof(target_classes) == 64 still holds. The padding-as-headroom story the previous postmortem promised paid off in the next ship.
4. **/merge-scan HIGH-1 consolidation lived as design constraint.** The CFG_BINDING_DRIFT bit is OR-set INSIDE the existing CFG drift loop, not parallel detection. Single source of truth for CFG drift; the new arch registry handles only arch-field cases. Pattern matches the audit-driven design discipline.
5. **Sanitizer reruns are part of muscle memory now.** TSan + ASan kicked off in background after each sub-tag, finished before commit. Zero hot/slow-path concern flagged.

## What surprised

1. **Plan-stale field name: `sr.scaler_feature_registry_hash` doesn't exist.** The correct check is `sr.feature_registry_hash != h->scaler.registry_hash` (scaler binding integrity). FeatureStandardizer's field is `registry_hash` not `feature_registry_hash`. The subplan was written from a spec with slight naming drift. Adjusted at code-time via direct field-name verification. Lesson: stale-claim audit checks at coding time still find drift even after pre-coding /readiness ran.
2. **PerCoreSnap drift cluster scope-cut.** Original .B.2 plan had a 6-uint64 alignas(64) drift cluster on PerCoreSnap for at-load diagnostic values. Discovered mid-coding that 2 of those values (feature_registry_hash + label_registry_hash) aren't persisted on ModelHandle (only on ModelStampResult during load; not in stamp body registry). Would have required adding runtime-only fields to ModelHandle. Cut to just `handle_training_timestamp_us` (8B). Drift BITS + panel tooltips were sufficient operator signal. At-load diagnostic display deferred to v5.15.1.post or v5.15.2.
3. **8 DashboardPanels.hpp sites for core_kill_tripped.** All `pc->core_kill_tripped` (consistent prefix). replace_all was safe — no `xpc->` variants. Per the v5.14.9.F.2 replace_all-mangling-2-shapes lesson, I verified the prefix consistency first.
4. **Anchor test required including ArchFieldDriftRegistry.hpp in controller_test.cpp.** First build failed at `FOREACH_ARCH_FIELD_DRIFT_COUNT == 4` because the registry header wasn't transitively imported. Added explicit include. Macro-as-namespaced-symbol mistake too (`tt::FOREACH_PER_CORE_STATE_FLAG_COUNT` is wrong since COUNT is a macro, not a tt:: namespaced constant).
5. **Faster than estimate (2h vs 3-4h).** The patterns were so well-established from v5.15.0 + v5.14.9.B.2 + v5.14.8.B that coding was mostly mechanical extension. The audits/plans front-loaded the design work.

## Decoupling-roadmap positioning

**POSITIONING: ⬆️ POSITIVE.** Drift state is publication-only:

- ShardedSnapshot writes drift bits into PerCoreSnap.failure_flags at slow-path tail.
- GUI reads via the existing double-buffered TUISnapshot publication. No new sync infrastructure introduced.
- Per-core drift bits are a single uint16_t with BITMAP_IS_SET access — mmap-friendly. A future external monitoring process (Rust/Python/Grafana) reads the bitmap directly without GUI build deps.
- `MemHeaders/ArchFieldDriftRegistry.hpp` is a new X-macro registry following the v5.14.8.B + v5.14.9.B.2 pattern. Adding a new drift check = 1 row.

No anti-breadcrumbs. No callback registries with fn pointers. No in-process-only state. No new sync infrastructure.
