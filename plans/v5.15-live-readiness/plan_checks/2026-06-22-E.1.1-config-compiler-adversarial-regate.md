## HIGH findings (resolve before coding)

### F-A [HIGH · capital] The per-node parser is the real surface, and ③ as scoped does NOT close the silent-wrong-capital class it exists for. (A-1 ⊕ A-2 convergent; code-verified)
Two parsers, opposite validation semantics:
- **Registry path** `CfgFieldDispatch.hpp:87-103`: `Money_FromString` → WARN on flags → **clamp to descriptor min/max**. (The design's "clamp-and-warn" baseline lives ONLY here.)
- **Per-node hand-rolled path** `ControllerConfig.hpp:2839-2929`: `strncmp(key,"node_",5) && strstr(key,"_suffix")` → `Money_FromString(val).value` — **`.flags` discarded, NO clamp.** Consumption `Run.hpp:923-925` / `Async.hpp` is lower-floor-only (no upper clamp).

Verified failure scenarios (real code):
- `node_0_risk_pct=999` → 9.99 → `Run.hpp:924 node_balance = total_balance * 9.99` → **999% live allocation to node 0.**
- `node_0_max_drawdown_pct=999` → threshold 9.99, but `node_dd_pct ≤ 1.0` (ratcheted, `ControllerEventLoop.hpp:2901-2921`) → `Money_Gt(≤1.0, 9.99)` never trips → **per-node kill switch silently dead.**
- `node_0_stop_loss_pct=banana` → flags discarded → `Money{0}` → resolver sees IsZero → **per-node SL silently disabled.** This is the EXACT "stop-loss-typo case" D-242:1567 cites as ③'s founding reason.
- `node_0_risk_pct_typo` → `strstr` substring-matches `_risk_pct` → accepted as recognized, `atoi("0_risk_pct_typo")=0` → **writes node-slot 0's risk from a typo'd key.**

**Why ③-as-designed can't catch this:** ③'s mechanism is **key-match** ("fault = no branch matched"), and the cascade SSoT F1 + D-242 explicitly defer "the semantic value-validation sweep → E.2." So a malformed VALUE on a recognized KEY passes ③ clean; and the `strstr` matcher means even the KEY check under-fires. D-242's prose ("unparseable value → ERROR") **overstates what ③ delivers** — ③ closes silent-wrong-KEY, not silent-wrong-VALUE. The cited precedent `ConfigField_Set` (`BacktestEngine.hpp:2240-2301`) uses exact `strcmp` — so "align with ConfigField_Set" is false until the matcher is fixed. Both ⊆ guards (F4 + C-2) are unsound over a substring matcher (Class-51 vacuous-green risk).

**This is the foundational scope decision (see § Decision).** Fix direction (both agents converge): exact-suffix-match (fold the 7 `strstr` branches into the `:2929` exact-match dispatch — the suffix-extraction idiom already exists there; zero latency cost, boot parser) + capital value-validation for the 4 capital fields.

### F-B [HIGH · determinism] `cfg_load_fault_flags` in `ControllerConfig` enters the model SHA-256 fingerprint. (A-4; code-verified)
`ControllerConfig.hpp:347-351` (struct's own comment) + `Fingerprint.hpp:180` (`SHA256_Update(&s, cfg_ptr, cfg_size)`) + `BacktestPanels.hpp:3157` + `BacktestSharded.hpp:122 (config_used = cfg)`: the struct is hashed RAW into the model lineage, re-checked at serve. The design's "not wire → zero byte-equivalence impact" conflated network-wire with byte-equivalence (it IS H9/H12). No live models (epoch-free), but a WARNING-config that proceeds with a fault bit set bakes `!=0` into `config_used` → two behavior-identical configs fingerprint differently (silent lineage non-determinism).
**Fix (mandatory):** keep ONLY a 4-byte gate-summary in the struct, **guaranteed 0 on a no-ERROR load** (or exclude from the hash + assert `config_used.cfg_load_fault_flags==0` at every `Fingerprint_Compute`); the readout error/warning LIST lives **stack-local in `ControllerConfig_Load`** (not a struct member — else 3KB rides the fingerprint + hot-reload bulk-copy + GUI mirror). **GOLDEN-REGEN owed** for the one-time `sizeof` shift (`Backtest/CLAUDE.md` discipline).
**TECH_DEBT (related):** `ControllerConfig` has NO `static_assert(sizeof==N)` despite being fingerprinted (Check-K gap) — a silent perturbation isn't caught by a size assert. Home as debt (not a ③ blocker).
