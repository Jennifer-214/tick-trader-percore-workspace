## Step 8 — Spearman IC (v5.14.1.E; NEW)

**Pre-existing-work audit:**
- `RollingIC` (Pearson) at `ML_Headers/ConfidenceScore.hpp:56-100` — pattern to mirror
- `RollingIC_Push` + `RollingIC_Compute` — current Pearson API
- v5.10.0e drift detection consumes `RollingIC_Compute` directly — NEEDS BACKWARD COMPAT (default cfg keeps Pearson; Spearman is opt-in)

**TRULY NEW:**
- `RollingICSpearman` struct (mirrors RollingIC; rank-correlation kernel)
- `RollingICSpearman_Init` + `_Push` + `_Compute`
- `cfg.confidence_ic_variant` enum (0=Pearson default, 1=Spearman)
- `ConfidenceScorer.spearman` field (parallel to existing `.ic` Pearson)
- v5.10.0e drift detection: extend to read whichever variant cfg selects (refactor `DriftHistory_Push` to take a `double current_ic` param; current site computes from `.ic`; new wiring computes from `.spearman` when cfg=1)

**Implementation:**
- Rank computation: maintain rolling buffer of (prediction, actual) pairs; on Push, sort + assign ranks (1-indexed); compute Pearson on ranks (= Spearman). O(N log N) per push at N=window (typically 50-200); ~5-10µs slow-path cost.
- Better than Pearson for non-linear monotonic prediction-return relationships. More robust to outliers.

**LATENCY:** Pearson is O(1) Welford-style; Spearman is O(N log N) per push. ~10x slower per push but still well within slow-path budget. Per-cycle cost only on PUSH (post-trade-close), not per-tick.

**Drift detection wiring (verified 2026-05-08 plan-check trace):**

Existing v5.10.0e site at `CoreFrameworks/ControllerEventLoop.hpp:1292-1296`:
```cpp
if (drift_floor > 0.0) {
    double ic_now = RollingIC_Compute(&ctx.confidence.ic);
    DriftHistory_Push(&ctx.drift_history, ic_now, now_us);
    ...
}
```

`DriftHistory_Push` accepts a precomputed `double ic_now` value;
caller chooses which IC variant to compute. The refactor for
.E is LOCAL (single call site; ~3-line change):
```cpp
double ic_now = (cfg.confidence_ic_variant == 0)
    ? RollingIC_Compute(&ctx.confidence.ic)            // Pearson (default)
    : RollingICSpearman_Compute(&ctx.confidence.spearman);  // Spearman opt-in
DriftHistory_Push(&ctx.drift_history, ic_now, now_us);
```

No deeper refactor needed (single site; cfg-gated; default
preserves v5.10.0e behavior bytewise). Same pattern at the
sister site at line 1446 (DrainPostFill wrapper).

**Tests (~6):**
- Spearman of monotonic non-linear pair (e.g., y = x²) ≈ 1.0; Pearson would be ~0.7
- Spearman with ties: ranks averaged correctly
- cfg.confidence_ic_variant=0 (default) → drift detection uses Pearson (bytewise-identical to v5.10.0e)
- cfg=1 → drift uses Spearman; v5.10.0e gate semantics preserved

## Step 9 — Portfolio turnover tracking (v5.14.1.F; NEW)

**Pre-existing-work audit:**
- `ConfidenceScorer` struct (extension target; same as composite confidence work above)
- Existing `core_wins` / `core_losses` per-CoreContext counters at `EventLoopState` (sister diagnostic; no overlap)
- v5.13.0.B `last_exit_predicted_p[]` per-slot (different shape; per-fill not rolling)

**TRULY NEW:**
- `RollingTurnover` struct on ConfidenceScorer:
  - rolling buffer of "top-K picks" each window step (e.g., last 100 ticks: top 3 model arms by predicted prob)
  - rank-set-difference metric: `|top_K(t) ∆ top_K(t-1)| / K` where ∆ is symmetric difference
  - High turnover → unstable model (top picks shifting frequently); LOW turnover → stable convictions
- `ConfidenceScorer.turnover` field
- Cfg: `cfg.confidence_turnover_window` (default 100), `cfg.confidence_turnover_topk` (default 3)
- Surface to PerCoreSnap for GUI display: `pc.ml_portfolio_turnover` (operator visibility)

**Implementation:**
- Per slow-path cycle when ML enabled: extract top-K arm indices from `weights_buf[]`
- Push to rolling ring buffer
- Compute symmetric difference between consecutive top-K sets via bit-mask (8-arm fits in uint8_t)
- O(K log K) per push; sub-µs at K=3

**LATENCY:** Per-cycle cost ~100ns (sort top-3 + bit-mask diff). Sub-100ns slow-path overhead. Hot path UNTOUCHED.

**Tests (~5):**
- Stable picks (same top-3 every cycle) → turnover ≈ 0
- Random picks (top-3 shuffles each cycle) → turnover ≈ 1.0
- Top-K with K=1 degenerates correctly (single-arm = either same or different = 0 or 1)
- Default cfg (window=0): no-op; turnover stays 0
- PerCoreSnap surface populated in TUI_CopySnapshotSharded
