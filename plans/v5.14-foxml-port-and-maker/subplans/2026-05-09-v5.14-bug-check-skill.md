## Why this exists

`DOCS/RECURRING_BUG_PATTERNS.md` already documents 13 bug classes
with detection greps, prevention recipes, known instances. Today
the doc is read manually before / during sprints. Operator
preference 2026-05-08: mechanize it via a skill that:

1. Loads `RECURRING_BUG_PATTERNS.md` into context
2. Runs each Class's "Detection" grep against the codebase
3. Reports any new instances of known bug classes
4. Emits a verdict (NEW INSTANCES / CLEAN) per class

This complements (does not replace) `/readiness` + `/parity-check`
+ `/merge-scan`. Those audit a planned change; `/bug-check` audits
the EXISTING codebase for instances of known patterns. Run cadence:
every sprint kickoff + every multi-week refactor + on-demand when
operator suspects a regression.

## Scope (MVP)

- Read `DOCS/RECURRING_BUG_PATTERNS.md` (~13 classes, growing)
- For each class with a "Detection:" code-block, execute the grep/
  awk script
- Distinguish:
  - **Known instances** (file:line already listed in the doc) →
    skip
  - **New instances** matching the signature → report as candidate
    bug
  - **No matches** → CLEAN
- Report format: 1 line per class (CLEAN / NEW INSTANCE @ file:line
  / SKIPPED — no detection script).
- Save report to `plans/plan_checks/bug-check-<YYYY-MM-DD>.md` +
  print to stdout.

## Invocation

- `/bug-check` — full audit (all classes)
- `/bug-check class_13` — focused scan for Class 13 only
- `/bug-check live` — only classes tagged "Surface: live engine /
  hot path / slow path"
- `/bug-check ml` — only classes tagged "Surface: ML / training /
  scaler / stamp"

## Detection script invariants

For the skill to work, every Class entry's "Detection:" section
must contain executable shell snippets (grep / awk / find). The
v5.13.5.B Class 13 entry is the canonical shape. Future Class
additions need similar runnable detection.

(Alternative: declarative pattern table in YAML/TOML loaded by the
skill — but this fragments the docs. Embedded scripts in the
markdown is simpler.)
