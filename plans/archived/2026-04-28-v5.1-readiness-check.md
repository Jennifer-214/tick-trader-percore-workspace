### 6. Multi-threading correctness ✅ FIXED

Original sub-plan was vague on per-tick vs per-cadence. Clarified:

**Per-tick fields** (currently updated in producer's `fan_out`):
- `ema_price`, `cumdelta_state`, `flow_state`, `large_trade_state`,
  `tick_rate_state`

**Per-cadence fields** (currently updated in slow-path body):
- `rolling_short`, `rolling_long`, `rolling_medium`, `rolling_baseline`,
  `regime_ror`, `book_imb_history`, `spread_state`

**Post-refactor write topology**:

| Field group | Writer (centralized) | Writer (per_core_slow) |
|---|---|---|
| Per-tick × N copies | Producer's fan_out (loops c=0..N) | Producer's fan_out (loops c=0..N) |
| Per-cadence × N copies | Producer's slow-path (loops c=0..N) | Per-core slow-path c writes its own |

**Reader of state.cores[c].slow_state**:
- centralized: producer (single thread)
- per_core_slow: producer writes per-tick fields → per-core thread c reads
  them (cross-thread). Per-core thread c writes per-cadence fields → per-core
  thread c reads them (same thread).

**Cross-thread access** (per_core_slow only, per-tick fields):
- Producer is single-writer per copy
- Per-core thread c is single-reader of its own copy
- Same eventual-consistency semantics as today's shared design — torn FPN
  reads theoretically possible on weak architectures, benign on x86 (word-
  aligned reads).

**Documented as accepted divergence** with `memory_order_relaxed` reads
on slow-path side. New invariant in CLAUDE.md (see item 8).

### 8. Docs + invariants ⚠️ GAPS

Three new invariants must land in `CLAUDE.md` Safety Invariants section:

**Invariant A** (item 1): Lifecycle Bitmap Single-Writer
> `paused_engines_mask` bits are GUI-thread single-writer. Slow-path c
> reads bit c only with relaxed ordering. Single-writer single-reader
> per bit means no atomic operations needed beyond the volatile load.

**Invariant B** (item 4): Per-Core Data-Plane Single-Writer
> Each core's `slow_state` is owned by exactly one writer:
> - Per-tick fields: producer thread (writes to all N copies in fan_out)
> - Per-cadence fields: producer thread (centralized) OR per-core slow-
>   path thread c (per_core_slow)
>
> Cross-thread reads (producer-written per-tick fields read by per-core
> threads in per_core_slow) are eventually consistent. Acceptable
> because slow-path cadence (~100 ticks) makes the staleness window
> << relevant signal duration. Documented as `memory_order_relaxed` reads.

**Invariant C** (item 5): Per-Section Latency Stats Single-Writer
> Each `CoreContext::slow_path_breakdown[section]` is single-writer
> (the slow-path thread that runs that section, identified by core_id).
> Centralized: producer is the writer for all cores. per_core_slow:
> per-core thread c writes only c's breakdowns.

Comments to remove/rewrite:

  ownership model.
