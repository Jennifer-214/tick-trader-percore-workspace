## What we found — Path γ structural critique

### Finding 1 — Spec missed the existing canonical mechanism

`DESIGN_SPECS/framework-patterns/metadata-bit-driven-derived-filter-framework.md` was drafted at v5.15.5.F.4d planning (2026-05-14). The mask infrastructure landed at `.F.4c.3` (~2 weeks earlier, lines 1020-1159 of `CfgFieldRegistry.hpp`). The spec enumerates 4 mechanism options (A: preprocessor filter / B: runtime walk / C: per-row token / D: PRE/POST split) — none of them is the actual canonical mechanism in code.

The spec's "Stage 3 ACTIVE" status was promoted at `.F.4d` ship close 2026-05-16, but `.F.4d` only RESERVED the STAMP_BOUND_CFG_DERIVED bit — no actual derived filter framework was built. "Stage 3 ACTIVE" is aspirational, not actual. Spec promotion was premature; corrected at this session.

**Codebase reality (Option E):**
- `FOREACH_METADATA_BIT(X)` at `CfgFieldRegistry.hpp:1064-1075` — X-macro registry of metadata bits (11 currently enrolled: RESTART_REQUIRED, SAFETY_CRITICAL, DEPRECATED, STAMP_BOUND, HIDDEN_BY_DEFAULT, IS_SECRET, IS_BOOT_ONLY, AFFECTS_STAMP_PARITY, LOG_VALUE_FORBIDDEN, HAS_SIDE_EFFECT, WARN_ON_CLAMP)
- `cfg_compute_mask<Bit>(arr)` at `:1039` — `constexpr` compile-time mask producing `CfgMaskArray<N_WORDS>` `.rodata` constant
- Auto-generated `g_global_cfg_<lname>_mask` + `g_per_core_cfg_<lname>_mask` arrays at `:1079-1088`
- `CFG_FIELD_FOR_EACH_SET_BIT(mask, idx, body)` at `:1150-1159` — branchless `__builtin_ctzll` iteration (single TZCNT on Haswell+)
- Live consumer at `GUI/SettingsPanel.hpp:1100, 1136` (both global + per-core walkers in production GUI Settings panel)
- Plus composition layer at `:1162-1257` (`g_*_cfg_render_mask` = `~(boot_only | hidden_by_default)`; `g_*_cfg_save_mask` = `~has_side_effect`; `g_*_cfg_cli_explain_mask`) — 3 existing canonicals of an unspoken **composed-filter-mask** pattern

The comment at `:1020-1022` states the framework discipline explicitly:
> "Per CLAUDE.md framework discipline (item 31): adding a new metadata bit = 1 row in FOREACH_METADATA_BIT below; mask arrays auto-generate for BOTH registries via X-macro instantiation pass."

## 4 gaps identified (NEW bug class candidates)

These are gaps in Path γ as-drafted — Path γ closes 6 known bug classes (11/14/18/21/22 + preserves 16) but introduces 4 candidate gaps that need explicit mitigation OR TECH_DEBT logging:

### Gap 1 — Composition discipline blindspot (candidate bug class)

**Bug shape:** "Added metadata bit X. Composed mask Y (`render_mask` / `save_mask` / `cli_explain_mask`) didn't get audited for include/exclude. GUI/save/CLI silently includes/excludes wrong rows."

**Mitigation:** `composed-filter-mask-pattern.md` DESIGN_SPEC includes "composition audit checklist" — for each new bit, walk every existing composed mask + record explicit include/exclude/skip decision. Could add `CFG_COMPOSE_AUDIT_DECISIONS` X-macro registry pairing each (composed_mask, metadata_bit) cell with explicit token; CI verifies coverage.

**Address at `.A`?** YES — fold into the new composed-filter-mask DESIGN_SPEC + add `CFG_COMPOSE_AUDIT_DECISIONS` X-macro at the same time. Path γ+ Level 2 scope.

### Gap 2 — Consumer existence enforcement

**Bug shape:** "Added metadata bit X → `g_*_cfg_x_mask` auto-generates in `.rodata`. Zero consumers read it. Silent dead infrastructure; tooltip says feature exists but no behavior attaches."

**Mitigation:** Stage 7 wider audit — Python CI tool scans for `g_*_cfg_<bit>_mask` references; reports orphan masks. Could land as part of TECH_DEBT-058 (REGISTRY_TOPOLOGY auto-gen).

**Address at `.A`?** NO — out of scope. Open TECH_DEBT-NEW-A.

### Gap 3 — `.F.4e` consumer verification

**Bug shape:** "`.F.4e` plan promises 5 GUI metadata consumers; ships framework discipline but consumer behavior missing. CI checks pass; GUI shows nothing."

**Mitigation:** `.F.4e` plan body verification gate adds grep for `g_*_cfg_(hidden_by_default|restart_required|safety_critical|is_secret|deprecated)_mask` usage in non-CfgFieldRegistry consumers. Mechanical; <5 min at ship close.

**Address at `.A`?** NO — note in `.F.4e` planning. Open TECH_DEBT-NEW-B as planning reminder.

### Gap 4 — Spec-vs-code drift detection (META)

**Bug shape:** "DESIGN_SPEC describes mechanism Y. Codebase has better mechanism Z (because spec was drafted before Z landed). New ships re-derive or build parallel to Y, leaving Z under-leveraged. Specs accumulate aspirational text."

This IS how we got here. The metadata-bit-driven-derived-filter-framework.md spec missed Option E. How many other Stage 2/3 ACTIVE specs have similar drift? Don't know without sweep.

**Mitigation:** Stage 7 wider audit — scan all Stage 2/3 ACTIVE specs (~25-30 docs) for spec-code alignment. ~2-3h focused. Codify periodic spec-code reconciliation as cadence discipline.

**Address at `.A`?** NO — substantial separate work. Open TECH_DEBT-NEW-C; addressed at `.F.4f` cleanup OR separate audit ship. **Phase 2 of this session's audits PARTIALLY addresses this via D4 dimension.**
