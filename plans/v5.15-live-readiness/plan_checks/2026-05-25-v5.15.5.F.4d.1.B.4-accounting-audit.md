# /accounting-audit — v5.15.5.F.4d.1.B.4 (train-serve execution-layer parity helper extract)

**Plan body:** v1.0 draft (2026-05-24) — DRAFT, awaits Phase A gate.
**Scope:** verify the proposed `EngineCommon_BootPerCore` + `EngineCommon_SlowPathCycleOneCore` shared-helper extract does NOT regress money-tracking surfaces. Particular focus on PARITY-030 (BNB fee discount LIVE-only) closure mechanism.

---

## Verdict: YELLOW — proceed with 3 amendments

Plan body design is sound — helper extract closes PARITY-030 structurally by construction (BOTH callers run the same helper → BOTH apply BNB discount). Class 27 closure pattern (Order::pre_resolved sub-struct binding at OrderManager_Submit) is preserved at the helper boundary; OMS still has zero scalar fee_rate fields; HandleFill still reads from `o->pre_resolved.fee_rate`. H4 (FPN-only accounting) preserved — helper extract is BOUNDARY-STABLE so no math-typed body churn happens at the move.

**3 amendments needed:**
1. **A1 (HIGH)** — Plan body MUST explicitly cite that `cfg.pay_fees_in_bnb` block at `EngineSharded.hpp:690-699` MUTATES `cfg.cores[c].fee_rate_*` IN PLACE; this mutation must happen BEFORE any `Order_BindPreResolved()` call site reads `cfg.cores[c].fee_rate_*`. Helper boot-order discipline currently implicit in Phase B/C; needs an explicit boot-order assertion in Decision B(b) cfg-flag-branch column + Step B.1.
2. **A2 (MED)** — Plan body Decision B(b) wording "cfg flag branches at boot time" is ambiguous about IDEMPOTENCY. If `EngineCommon_BootPerCore` is invoked once per core (per the `for (int c = 0; c < num_cores; ++c)` loop pattern), then the BNB-discount inner-loop at EngineSharded.hpp:692 (`for c in MAX_EXECUTION_CORES`) would 4x-discount cfg if naively folded inside the per-core helper. Plan body must clarify the BNB discount is APPLIED ONCE GLOBALLY (outside the per-core helper, OR inside with explicit "first-core-only" guard) — NOT once per helper invocation.
3. **A3 (MED)** — Plan body Phase C.6 parity_harness extension must add an EXPLICIT BNB-discount fee-accounting regression test (drive `pay_fees_in_bnb=1` cfg through both backtest + live boot; verify per-fill `o->pre_resolved.fee_rate` matches 0.75 × original cfg value; assert `oms->total_fees` math matches BPS-for-BPS). Without this, the structural close has no LIVE regression catch beyond visual code review.

### 7. Backtest↔live accounting parity — YELLOW (per Verdict header)

**Plan body claim:** PARITY-030 closes by-construction at helper extract; both callers run the same helper → both apply BNB discount.

**Verification:**
- ✅ Structural design sound — helper extract IS the right shape for the PARITY-030 close.
- ❌ Cfg-flag-branch DETAIL underspecified in plan body Decision B(b). The current LIVE `cfg.pay_fees_in_bnb` block (`EngineSharded.hpp:690-699`) MUTATES the cfg struct itself in-place (not a per-Order pre_resolve at submit). It must run ONCE GLOBALLY BEFORE the per-core loop that submits Orders — NOT once per core inside `EngineCommon_BootPerCore`.
- If naively folded inside per-core helper invoked N times: N=4 → 0.75⁴ = 0.316 effective rate (3.16x under-discount). Catastrophic accounting bug.
- Plan body acknowledges "Helper signature stability" pre-coding concern #1 + "Boot order preservation" #2; doesn't explicitly call out the BNB MUTATION-ONCE invariant.

**Risk:** MED-HIGH if A1 + A2 amendments not applied; LOW if applied.

**Punchlist (the 3 amendments from Verdict header):**
- **A1 (HIGH):** Plan body Step B.1 + Decision B(b) cfg-flag-branch column MUST add explicit "BNB-discount block MUST execute ONCE GLOBALLY before per-core helper loop; mutating `cfg.cores[c].fee_rate_*` in-place; subsequent `Order_BindPreResolved` reads from post-discount values." OR alternative shape: move BNB discount into Order_BindPreResolved itself (read `cfg.pay_fees_in_bnb` flag + apply 0.75 multiplier inline at bind time). The alternative is structurally cleaner (BNB becomes a per-Order decision-time-binding concern; cfg is never mutated in-place) but changes Order_BindPreResolved signature.
- **A2 (MED):** Plan body must enumerate which existing boot work LIVES INSIDE the per-core helper (per-core OMS init, per-core regime init, per-core strategy init) vs OUTSIDE (BNB discount global, kill_switch global, depth WS global, trade log global). Currently plan body groups all boot work into "EngineCommon_BootPerCore"; needs split between `EngineCommon_BootGlobal` (once) + `EngineCommon_BootPerCore` (per c in 0..num_cores).
- **A3 (MED):** Phase C.6 parity_harness extension must add explicit BNB-fee regression test (drive `pay_fees_in_bnb=1` through both paths; assert per-fill fee = 0.75 × baseline; assert `oms->total_fees` matches).

## Top 3 accounting concerns

1. **BNB-discount mutation-once invariant (A1 + A2):** the existing LIVE `pay_fees_in_bnb` block at `EngineSharded.hpp:690-699` mutates cfg in-place ONCE before per-core loop. Plan body must surface this discipline explicitly OR refactor to per-Order decision-time-binding (move BNB read into Order_BindPreResolved). Naive helper fold = N-times-applied = 3.16x under-discount catastrophe at N=4 cores. HIGH severity if missed at Phase B.
2. **Fee-floor cross-path symmetry verification (Phase A finding):** `EngineSharded.hpp:1456-1467` runs per-core TP-floor sanity check (TP ≥ 3 × fee_rate_taker). Need to verify backtest has equivalent OR Phase A logs as NEW PARITY entry for helper to absorb.
3. **parity_harness BNB regression test (A3):** Phase C.6 lists parity_harness extension for `engine_arch=per_core_slow` test sweep but doesn't enumerate BNB-fee test case. Plan body must add explicit `pay_fees_in_bnb=1` cohort to the regression suite OR the structural close has no live regression catch.
