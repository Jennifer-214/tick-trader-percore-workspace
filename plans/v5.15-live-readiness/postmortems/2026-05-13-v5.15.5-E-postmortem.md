## Lessons learned

### Structural fix unblocks layered discipline

Pre-.E.0, the v5.14.1.F design note explicitly froze ConfidenceScorer's sizeof due to PortfolioController's raw fwrite. This froze the LAYOUT for years. The structural fix (FOREACH registry + AUTOPOPULATE helpers + shadow-load migration) unblocked .E.A through .E.D's cache-layout discipline.

**Lesson:** when a struct has a "do not modify" design comment, investigate WHY. The structural answer may unlock everything downstream of that constraint.

### Audit-driven scoping pre-coding

Pre-coding audit verified:
- breach_first_us is genuinely display-only (zero read sites) → safe to extract.
- AoS interleave access sites are bounded to 3 (DriftHistory_Push + CheckBreach + ShardedSnapshot aggregate sum) — clean migration.
- Composite-mode fields' wall-clock + EWMA state is stale on reload → re-init from cfg is correct (legacy raw-fwrite was over-persisting).

Each finding shaped the implementation. Skipping audit would have hidden these decisions inside the code with no rationale.

**Lesson:** for ships expanding beyond local edits, pre-coding audit catches assumptions before they harden into commits.

### Class-18 mirror closure compounds value

Closing the PortfolioController ↔ ShardedSnapshotPersist mirror in `.E.0` made the RollingIC ≅ RollingRMSE mirror closure in `.E.C` straightforward (just refactor 2 structs to use RollingWindow<T, N>; FOREACH paths are already abstracted). Each mirror closure makes the NEXT one easier.

**Lesson:** structural fixes are TRANSITIVE-VALUE: closing one mirror reduces the cost of closing adjacent mirrors. Bundle when feasible.

### FP non-associativity caveat for sliding-window pattern

RollingRMSE uses `double` (not FPN<F>); sliding-window running-sum doesn't preserve bytewise identity with the walked path. Test uses 1e-12 tolerance (well below typical squared-error magnitudes). For surfaces that need TRUE bytewise determinism, the pattern still requires FPN<F> (like BookImbHistory in .D.B).

**Lesson:** sliding-window pattern's "bytewise parity discipline" is conditional on associative arithmetic (FPN). For double-precision aggregates, tolerance comparison is the correct test shape.
