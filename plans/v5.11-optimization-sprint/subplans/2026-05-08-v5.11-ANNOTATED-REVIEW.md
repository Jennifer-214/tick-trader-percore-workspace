# v5.11 Annotated Architectural Review

**Purpose:** This document provides surgical, rule-aligned annotations for every ship in the `v5.11` Master Plan, highlighting specific implementation details to maximize HFT determinism.

---

### v5.11.0 — System Foundation
*   **Rule Alignment:** Section 9 & 11 (System Ops & Hardware Tuning).
*   **Annotation:** When implementing `mlockall`, also verify the process's `RLIMIT_MEMLOCK` (via `getrlimit`). If the limit is too low, `mlockall` will fail silently or partially. 
*   **HFT Suggestion:** Explicitly check the return value of `mlockall` and call `exit(1)` on failure. A non-locked engine is a "zombie" engine in HFT.

### v5.11.1 — Hot Path AVX-512
*   **Rule Alignment:** Section 4 & 5 (Branchless & AVX-512).
*   **Annotation:** Use `_mm_prefetch((const char*)&core->param_slot.seq, _MM_HINT_T0)` at the very top of `ExecutionCore_Tick`. This hides the ~100ns latency of the atomic acquire load required to start the Seqlock read.
*   **Annotation:** In the branchless ring buffer commit, use a single bitwise OR for the fire flags: `uint64_t fired = (can_enter | can_exit_a | can_exit_b) != 0;`. This ensures only one branch-free data dependency.

### v5.11.2 — Slow Path O(1) Regression
*   **Rule Alignment:** Section 5 & 7 (AVX-512 & Cache Locality).
*   **Annotation:** When implementing the "Idea 5" Feature Mask, use `_mm512_mask_blend_epi64`. Unconditionally compute every feature, then apply the `feature_mask` as the SIMD blend mask. This satisfies the requirement without adding a single `if` statement to the slow path.
*   **Annotation:** The reciprocal LUT (`RECIP_LUT[129]`) should be `alignas(64)` to ensure it occupies exactly two cache lines and doesn't bounce.

### v5.11.3 — TUISnapshot Seqlock & Async Log
*   **Rule Alignment:** Section 3 & 8 (Lock-Free & Jitter).
*   **Annotation:** Pin the new background I/O thread to a dedicated "Housekeeping" core (e.g., Core 0). Never let it share a physical core (SMT sibling) with an execution core, as the `fwrite` syscalls will evict the execution core's L1/L2 caches.

### v5.11.4 — Parsing SIMD
*   **Rule Alignment:** Section 6 (O(N) Parsing).
*   **Annotation:** For `simdjson`, reuse the `dom::parser` and `dom::element` objects across iterations to avoid internal buffer reallocations. 
*   **HFT Suggestion:** Call `parser.allocate(MAX_MSG_SIZE)` once at startup.

### v5.11.5 — OMS Variance
*   **Rule Alignment:** Section 3 & 4 (Lock-Free & Branchless).
*   **Annotation:** For the adaptive spin-wait, use a "decaying pause": start with 10 `_mm_pause()` iterations, then 50, then 100, before falling back to `futex`. This optimizes for the "immediate message arrival" case common in bursts.

### v5.11.6 — Allocator Unification
*   **Rule Alignment:** Section 1 & 10 (Zero System Allocators & Huge Pages).
*   **Annotation:** Use `madvise(arena, size, MADV_HUGEPAGE)` immediately after the `mmap`. This hints to the kernel to collapse the page tables immediately.
*   **HFT Suggestion:** Implement a `G_LOCKDOWN_MEMORY` flag. Once the engine enters `CONTROLLER_ACTIVE`, any subsequent call to `malloc` or `buddy_alloc` should trigger a `SIGABRT` or a critical warning. This prevents "leak variance."

### v5.11.7 — Bandit AVX-512
*   **Rule Alignment:** Section 5 (AVX-512).
*   **Annotation:** Use `_mm512_maskz_exp_pd` (masked-zeroing exponent) to only calculate exp for active strategy arms, skipping the expensive FPU work for zero-weighted or disabled strategies.

### v5.11.8 — ML AOT Compile
*   **Rule Alignment:** Section 2 & 7 (Zero VTables & Cache Locality).
*   **Annotation:** Use `.p2align 6` (64-byte alignment) for the entry point of the generated AOT inference function. This ensures the first instruction block of the model logic always hits a new I-cache line, preventing cross-line instruction fetch stalls.

## Missing Optimizations (Add to backlog)

The current plan is world-class, but it's missing three final "ultra-metal" optimizations:

1. **Instruction Alignment Audit:** Hot path functions (`ExecutionCore_Tick`) and slow-path loop entries should be explicitly aligned to 64-byte boundaries via `__attribute__((aligned(64)))` or assembly labels.
2. **Bit-Field Bit-Shifting:** Where strategies use booleans (e.g., `is_buy`, `is_sell`), replace them with a single `uint8_t flags` and use bit-shifts. This allows the compiler to use `test` and `setz` instructions more efficiently than multiple boolean byte-loads.
3. **Write-Combining Buffers:** For the `OrderEventLog` background thread, ensuring that memory writes to the ring buffer use non-temporal hints (`_mm_stream_si128`) can prevent polluting the execution core's cache with data that is only intended for the I/O thread.
