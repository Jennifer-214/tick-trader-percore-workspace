## 7. Pre-coding concerns to surface (raised at convene before this handoff)

These are NOT blocking; they're observations to keep in mind during coding:

### 7.1 — Wire-format byte preservation under Phase L X-macro auto-gen

Phase L uses framework's `populate_stamp_cfg_from_derived` which is byte-preserving by construction (same locale pin, same `%.17g` format, same `tt::cfg_emit_field<T>` path). But Step 1.6.4 ACTUALLY CHANGES THE EMIT SOURCE from caller-supplied `inf` to engine-side `cfg`. Tests that pre-populated `inf` (v5.14.1.B.3.E test block; ~10-15 fields) need migration to cfg setup. **Sister benefit: extensibility test pattern REPLACES those tests with X-macro walker that auto-validates per-row round-trip; net effect is test consolidation, not just migration.**

### 7.2 — CLI flag naming reconciliation at L2 coding-time

Bash script `tools/stamp_model.sh:109-147` uses kebab-case flags (`--confidence-threshold-scale`); master cfg registry uses snake_case (`confidence_threshold_scale`). **Decision deferred to L2 coding-time** per plan body Step 1.6.8' L2 interaction annotation. Recommended approach: standardize on snake_case (registry-native) + deprecation alias layer in CLI binary main() that translates kebab→snake with one-line stderr warning. Operator scripts using legacy kebab flags continue working during retention period (TECH_DEBT-110 deletion target).

**Verify first via:** read `tools/stamp_model.sh:109-147` getopt loop to enumerate which flags are kebab vs snake.

### 7.3 — Stamp body source-of-truth semantic shift (inf → cfg)

When Step 1.6.4 migrates emit from inf-driven to cfg-driven, the OPERATOR-MENTAL-MODEL changes:
- **Pre-migration:** "Stamp captures whatever the CALLER populated in inf" (test-friendly; caller can set arbitrary values)
- **Post-migration:** "Stamp captures whatever's in cfg at emit time" (production-correct; cfg IS the source of truth for derived fields)

Per `cfg-derived-consumer-framework.md` v1.3 § "Emit-side source-of-truth discipline" — review that section pre-coding. Tests that pre-set inf for migrated consumers will silently pass build BUT may produce false-positive test pass when checking stale inf values vs cfg-at-emit-time values.

### 7.4 — TYPE-SENSITIVE Pillar B8 catch surface

Engine HEAD has 44 TYPE-SENSITIVE compile errors in `tests/controller_test.cpp` from Step 1.6.3 struct-gen migration (LANDED WIP-checkpoint 6). These resolve at Step 1.6.4 (when legacy emit walker eliminated). Visible during cascade; **NOT coding-time blockers** (engine + 3 other binaries CLEAN). Per `/blindspot-scan` Pillar B8 (TYPE-SENSITIVE consumer classification): expect more TYPE-SENSITIVE issues to surface during Phase F coding; per-site `FPN_FromDouble<64>()` / `FPN_ToDouble()` wraps mitigate (see WIP-checkpoint 6 commit for prior 27 sites).
