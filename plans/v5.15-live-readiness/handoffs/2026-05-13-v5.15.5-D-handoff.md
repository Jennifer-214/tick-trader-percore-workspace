**Goal:** understand the access pattern for each FlowFeatures struct.

For each of the 4 structs (BookImbalanceHistory, FlowState, LargeTradeState, SpreadState):
1. `grep -rn "<StructName>\b" CoreFrameworks/ ML_Headers/ DataStream/ GUI/` — find all usage sites
2. Classify: single-instance OR per-core array? Hot-path read or slow-path read? What fraction of fields per read?
3. Compute current sizeof + offset of hot fields (read code; check existing tests for size locks)
4. Decide which design spec applies:
   - **Single-instance struct → `cache-layout-discipline-for-hot-side-structs.md` Rules 1-5**

## Pattern application decision tree

For each FlowFeatures struct, work through the tree:

```
Is this struct in a per-core/per-slot ARRAY accessed via sparse iteration (bitmap-driven)?
├── YES → hot-side-array-element-alignment-for-sparse-access.md
│         (alignas(64); ensure sizeof multiple of 64; hot-field subset in first cache line)
│
└── NO  → Single-instance struct?
          │
          ├── Touched per-cycle in hot/slow path?
          │   ├── YES → cache-layout-discipline-for-hot-side-structs.md
          │   │         (Rules 1-5; HOT/WARM/COLD tiering; extract display-only)
          │   │
          │   └── NO  → No specific cache spec needed; verify no false-sharing if cross-thread
          │
          └── Cross-thread published (GUI snapshot)?
              └── YES → per-snapshot-cluster-layout-pattern.md
                        (alignas(64) cluster boundaries by concern; false-sharing prevention)
```

Most FlowFeatures structs are likely **single-instance per-core** (FlowState lives on slow_state of CoreContext). So `cache-layout-discipline-for-hot-side-structs.md` Rules 1-5 is the likely primary spec.

## Risk areas — verify these in pre-coding

1. **FlowState lives on slow_state (`CoreContext::slow_state`)** — check whether it's mutated by hot path. If hot path writes/reads, cache discipline is critical. If only slow-path access, less critical.
2. **Sliding-window stats** — FlowFeatures uses rolling-window math; verify it aligns with `sliding-window-online-statistics-pattern.md` if found.
3. **GUI display** — if FlowState's fields are read by GUI (e.g., FlowFeaturesPanel.hpp), cross-thread snapshot publishing applies. Need cluster discipline OR double-buffer.
4. **No FPN-precision math changes** — per CLAUDE.md item 25 byte determinism + FUTURE_ML "FPN<32> rejected for BTC" note (added in .C.5). Keep FPN<64> wherever it's already used. DO NOT introduce FPN<32> in .D.
