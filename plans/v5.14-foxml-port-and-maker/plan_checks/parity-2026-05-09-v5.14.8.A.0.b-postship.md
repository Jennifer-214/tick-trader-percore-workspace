### BitmapMacros.hpp Safety Review ✓ PASS

**Findings from MemHeaders/BitmapMacros.hpp:**

1. **Predicate-return consistency:** All predicate macros explicitly return `bool` via `!= 0` pattern:
   - `BITMAP_IS_SET: (((field) & (mask)) != 0)` — line 58
   - `BITMAP_ANY: (((field) & (mask_set)) != 0)` — line 69
   - `BITMAP_ALL: (((field) & (mask_set)) == (mask_set))` — line 75
   - `BITMAP_NONE: (((field) & (mask_set)) == 0)` — line 80
   
   **Rationale documented:** Line 47-52 — prevents int-truncation bug when uint64_t bitmap with top-bit-only set is used in int context. Explicit bool return sidesteps entire class. GOOD.

2. **Macro argument safety:**
   - All user-facing macros use `(field)` + `(mask)` parenthesization. No double-evaluation risk.
   - Helper macros (BITMAP_BIT_U16/32/64) use `(n)` parenthesized; safe for nested use.
   - Atomic variants use `__atomic_*` intrinsics directly; no user argument re-evaluation.

3. **Atomic memory ordering:**
   - Default `__ATOMIC_RELAXED` is documented as correct for observability flags (line 156-159).
   - Explicit `_ORDER` variants provided for callers needing stricter orders. GOOD.

4. **Atomic return semantics:**
   - `BITMAP_ATOMIC_SET/CLR/TOGGLE` return prior value (via `__atomic_fetch_*`); not used in provided code but interface is sound.
   - Atomic predicates (`BITMAP_ATOMIC_IS_SET/ANY`) load + return bool; consistent with single-thread variants.

**Result:** No C-preprocessor footguns detected. Macro design is hygienic and type-safe.
