## Theme

Cross-build determinism. v5.10 design Idea #11. Within-build,
v5.9.2's replay-determinism test verifies bytewise identity. But
across builds (different compiler / -O level / FMA support), IEEE-754
double additions can reorder, producing different RegimeSignals
values → silently different predictions.

`RollingStats`, `RegimeSignals`, `RORRegressor`, `FlowFeatures` use
`double` today. ~500 LOC of double math to convert to FPN<F>. After
conversion: bytewise identical across any compiler/flags.

## Risk register

- High-risk refactor: ~500 LOC double → FPN; potential precision
  bugs that pass tests but fail in real backtests
- All existing models invalidated (must retrain) — operator coordination
- FPN sin/cos for hour-of-day signals: not first-class.
  **DESIGN GATE LOCKED 2026-05-02 (operator decision):**
  - **CHOSEN: FPN-native polynomial approximation.** ~3-4h impl;
    100-150 LOC; reusable for any future FPN trig needs (additional
    use cases pay back the investment). Bytewise deterministic at
    runtime by definition (FPN integer math, no IEEE-754).
  - **Implementation:**
    - Range reduction: `x mod 2π` via branchless FPN_Sub iterations
      (`while (x > π) x -= 2π`)
    - Taylor series for `sin(x)` in `[-π, π]`: 5-7 terms
      `sin(x) ≈ x - x³/6 + x⁵/120 - x⁷/5040 + x⁹/362880`
    - `FPN_Cos(x) = FPN_Sin(x + π/2)` — single helper
    - Compile-time FPN constants for divisors (6, 120, 5040, ...)
  - **Epsilon-bound test (B.1 gate):** FPN_Sin must agree with IEEE-754
    `sin` within 1e-6 over `[0, 2π]` for representative inputs
    (timestamps in milliseconds-since-midnight).
  - **Fallback:** if polynomial fails epsilon bound for some input
    range, ship lookup table (1440-entry precomputed FPN array;
    23KB; ~30 min). Polynomial preferred but lookup is a known-good
    backup if precision issues surface.
  - **v5.11 NOT NEEDED** for FPN trig — primitives ship in v5.10.0b.
  - File: NEW `ML_Headers/FPN_Trig.hpp` (~150 LOC + 30 LOC tests)

## Verification

- Reference model retrained matches per-core P&L within epsilon

## Lower-cost alternative

Per design notes line 484-490: pin compiler flags into stamp
fingerprint (already covered by v5.9.5h #10 build_flags). Strictly
weaker (refuses load on mismatch but doesn't enable cross-build
inference) but ~3h instead of 2-3 days.

If operator deems cross-build deployment a hypothetical concern not
a current need, defer FPN-end-to-end to v5.11+ and just rely on
build_flags refusal.
