## Why this ship exists

E.1.2.A locked `[SCHEMA]_[v1.0]`, built the foxtag fact-core (11 commands, byte-identical parity vs Python), and converted the whole corpus (100% green, HARD-zero). But the system's founding thesis — *one core, N consumers, none rolls its own* — is realized only in the **core**, not the **consumers**. Three independent surveys (2026-07-19) converge on the same root:

- The **nvim plugin makes zero foxtag calls** — it is a native-Lua *mirror*: the parse rule re-implemented in Lua (`tag_grammar_adapter.lua:19-57`), the `UNIT` set hardcoded in **two** copies (`tag_grammar_adapter.lua:27`, `tagcontext.lua:9-10`), the DERIVED formatter duplicated in two more, and the one real adapter seam (`tagadapter.install`) **never called from `setup()`** → dormant. A textbook Class-18 second-implementation.
- **14 tools roll their own repo-root** instead of importing `check_doc_metadata.ENGINE` — and one of them, `check_conversion_completeness.py:32` (`ENGINE = Path("/home/caramel/code/FoxML_Trader_v2")`, no env override), is a **portability-dead HARD CI gate** running green only because this machine's path matches the literal (verified 2026-07-19). A `feedback_machine_portable_resolver_for_committed_tool_paths` violation sitting under a green gate.

The felt problem that triggered D-372 — *"we have all this great tooling but it feels like none of it matters"* — is **uneven consumption**: strong in CI, absent in the plugin. So V1 is redefined (D-372, §8.6): **the whole toolchain, pervasively consumed from ONE core, live on the surface that fits each capability** (CLI · local-CI · plugin-as-non-CLI-app · doc-viewer · AI-plane). The cost of NOT doing it: continued drift (the plugin's own docs have *already* drifted from its own code — `TAG-INTEGRATION.md` says `[DATA_SIZE]`/`[DEP_CHAIN]`, the code emits `[SIZE]`/`[UPSTREAM]`), and the tooling never pays back into engine velocity because it isn't *used where the work happens* (the editor).

**Why now / why before more engine work:** operator decision (2026-07-19) — the toolchain is the *lens* for the SoA relayout + the rest of E.1's live-enable work; building the lens first, then resuming engine surgery through it. Each increment is independently usable on engine code the day it lands, so it reinvests into engine velocity incrementally rather than deferring payoff to 1.0.

**The gate consequence (named explicitly per `feedback_surface_foundational_decisions_not_just_tactical`):** E.1.2.A already gates "the resumption of E.1.2 SoA + all more-complex work." E.1.2.B inherits that gate — the full toolchain V1 now sits in front of resuming the SoA relayout and the rest of E.1's live-enable trajectory. This is the operator's deliberate defer-the-engine call, made structural — not a silent scope expansion.

## Ship type + end goal + acceptance criteria

**Plan type:** `mixed` — dominant mode is `refactor` (close the Class-18 plugin mirror + the root-resolver straggler class + the doc-drift class, structurally), with `feature` segments (new editor-native surfaces: tag-trees, doc-viewer, gate-verdicts, AI-plane).

**Ship end goal (1 sentence):** *Make every toolchain surface (CLI · local-CI · plugin · doc-viewer · AI-plane) a thin consumer of the one core, versioned as a coherent product `0.x → 1.0.0`, so the in-code `[SCHEMA]` documentation is authored, verified, navigated, and kept-synced from a single fact-producer — the "code becomes the IDE" endgame, felt in the editor.*

**How this contributes to the sprint MASTER goal:** the sprint end-goal is "make the codebase more maintainable for future development." E.1.2.B delivers the *operational* half of that — the tooling that keeps the (now-converted) in-code docs honest + navigable as the engine evolves, and the lens through which the remaining E.1 structural work (SoA relayout, per-cluster purity) is done.

**Acceptance criteria (verifiable at `1.0.0` close):**

- **One core, zero re-implementations:** the import-from-core lint is GREEN (no tool rolls its own repo-root); the plugin makes ZERO hand-rolled grammar parses (consumes `foxtag` for grammar/units/layout).
