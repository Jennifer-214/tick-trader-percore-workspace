## Why this subplan exists

ModelHandle survived v5.14.8.A.merged's Option 1 stamp body unification
as an asymmetric struct. ModelStampResult + StampInferenceCfgInputs got
registry-driven + bit-packed `has_flags` via STAMP_SET(); ModelHandle
stayed manual with **14 uint8_t `has_*` direct fields** + inconsistent
prefix policy across groups (`stamp_inf_*`, `stamp_xgb_*`,
`stamp_label_*`, `stamp_*`).

In parallel, `verify_model_stamp` is the asymmetric mirror of the stamp
emit path: stamp emit walks FOREACH_STAMP_BOUND_MODEL_CONST + AUTOPOPULATE
(registry-driven); the parser is still a ~700 LOC if-else chain over ~30
stamp body keys. Adding a new key requires manual `else if (strcmp(...))`
branch on the parse side AND a registry entry on the emit side — Class 18
mirror.

**Closing both in one ship** because they share the same surface (`ML_Headers/ModelInference.hpp`) + the same caller set (every site that
reads ModelHandle.has_* or populates it from the parser). Two-ship
sequencing would touch ModelHandle twice. Per CLAUDE.md item 19
(structural fix preferred when bug class can recur), the combined ship
extinguishes the Class 18 mirror at the source/sink boundary AND closes
TECH_DEBT-014.

### Step 1: design has_* bit positions + MASK_* constants

**Two approaches; recommend Option A (named MASK constants):**

**Option C (FINAL per /dod-audit HIGH-2):** ALIGN with existing
`MASK_STAMP_HAS_<NAME>` from ModelStampResult — SHARE bit positions
so the parser dispatch table writes BOTH structs from the SAME mask
column. Single source of truth; saves a redundant mask column in the
parser dispatch table.

```cpp
// In ML_Headers/StampBoundModelConstRegistry.hpp (already exists at line ~567):
// MASK_STAMP_HAS_<NAME> constants are the canonical bit positions for
// ModelStampResult.has_flags uint64_t. Defined via FOREACH expansion order.

// In ML_Headers/ModelInference.hpp near ModelHandle:
// v5.15.0 — ModelHandle.has_flags uses SAME bit positions as
// ModelStampResult.has_flags (Option C from /dod-audit; closes the
// dispatch-table-double-write asymmetry that /dod-audit HIGH-2 flagged).
//
// Why shared positions: verify_model_stamp parser refactor (.B) writes
// BOTH StampResult.has_flags AND ModelHandle.has_flags from the SAME
// dispatch table row. Aligned bit positions mean the parser does
// `result.has_flags |= mask; handle.has_flags |= mask;` with ONE mask
// column. Misaligned would require TWO mask columns.

// HANDLE_HAS / HANDLE_SET / HANDLE_CLR macros REUSE STAMP_HAS_<NAME>
// constants directly — no separate MASK_HANDLE_HAS_* namespace:
#define HANDLE_HAS(h, name)  BITMAP_IS_SET((h).has_flags, MASK_STAMP_HAS_##name)
#define HANDLE_SET(h, name)  BITMAP_SET((h).has_flags, MASK_STAMP_HAS_##name)
#define HANDLE_CLR(h, name)  BITMAP_CLR((h).has_flags, MASK_STAMP_HAS_##name)
```

**Verdict:** **Option C.** Shared bit positions via reuse of canonical
`MASK_STAMP_HAS_*` constants. Aligns with CLAUDE.md item 16 (reuse-audit)
+ item 21 (AUTOPOPULATE consistency) + item 22 (PRE/POST registry split
preservation). Closes /dod-audit HIGH-2 finding.

### Step 2: struct rewrite via FOREACH expansion

```cpp
// ModelHandle becomes:
struct alignas(64) ModelHandle {
    // HOT CLUSTER (cache line 1: read in slow-path inference dispatch)
    void *handle;                          // 8 B — XGBoost booster ptr
    int   backend;                         // 4 B
    int   num_features;                    // 4 B
    int   num_outputs;                     // 4 B
    int   buy_class_idx;                   // 4 B
    int   normalizer;                      // 4 B (enum)
    double normalizer_param;               // 8 B
    uint64_t has_flags;                    // 8 B (REPLACES 14 uint8_t has_*)
    int   scaler_load_failed;              // 4 B
    int32_t _hot_pad0 = 0;                 // 4 B (explicit padding determinism)
    // = 56 B used; 8 B reserved (next slot in line 1)

    // Cache line 2-N: scaler + warm fields (read in slow-path inference; not hot)
    tt::FeatureStandardizer scaler;        // ~600 B; spans many lines

    // Cache line N+: stamp-derived value fields (read at boot WARN/REFUSE)
    // Generated via FOREACH_STAMP_BOUND_MODEL_CONST (filtered for handle-relevant
    // entries via PRESENCE column STAMP_HANDLE_GEN_INCLUDE / SKIP_HANDLE token-paste).
    FOREACH_STAMP_BOUND_MODEL_CONST(EXPAND_HANDLE_FIELD)

    // COLD CLUSTER (cache line K: char[256] paths, char[64] run_name; rarely read)
    char model_path[256];
    char training_fingerprint[65];
    char run_name[64];
};
static_assert(sizeof(ModelHandle) % 64 == 0,
              "ModelHandle MUST be cache-line sized for slow-path inference dispatch");
```

**EXPAND_HANDLE_FIELD macro:** walks FOREACH_STAMP_BOUND_MODEL_CONST,
emits typed value field per entry, SKIPS the per-entry `has_*` (since
they're now in has_flags). Uses PRESENCE column (`STAMP_HANDLE_GEN_INCLUDE`
vs `SKIP_HANDLE`) to filter — not every stamp body field appears on
ModelHandle (some are emit-only, like environment_meta which is forensic).

## .B — verify_model_stamp parser refactor

### Step 0: enumerate parser key list

```bash
# Extract all parsed keys (left-hand of strcmp checks)
rg -n "strcmp\(key, \"[^\"]+\"\) == 0" ML_Headers/ModelInference.hpp | head -50
```

**Expected:** ~30 keys (cfg-bound subset already handled by
FOREACH_STAMP_BOUND_CFG via X-macro; remaining ~30 are
architectural/model-const subset that overlaps FOREACH_STAMP_BOUND_MODEL_CONST).

### Step 1: dispatch-table design

```cpp
// Near top of verify_model_stamp:
struct StampParserEntry {
    const char *key;                                              // wire key
    void (*parser_fn)(ModelStampResult&, const char *val);        // parses string val into result
    uint64_t mask_bit;                                            // STAMP_HAS_<NAME> mask to set
};

// Generated via FOREACH_STAMP_BOUND_MODEL_CONST + FOREACH_STAMP_BOUND_CFG:
static constexpr StampParserEntry stamp_parser_table[] = {
    FOREACH_STAMP_BOUND_MODEL_CONST(EXPAND_PARSER_ROW)
    FOREACH_STAMP_BOUND_CFG(EXPAND_PARSER_ROW)
    {nullptr, nullptr, 0}  // sentinel
};
```

**EXPAND_PARSER_ROW macro** uses the existing `tt::stamp_parse_field<T>`
templated helper at `ML_Headers/StampBoundModelConstRegistry.hpp:680+`
(per CLAUDE.md item 23 type-trait dispatch) — generates per-T parser
lambda that handles char[N] strncpy vs scalar cast at compile time.

### Step 2: parser body refactor

Existing `verify_model_stamp` if-else chain becomes a single dispatch
loop walking `stamp_parser_table`:

```cpp
// Replaces ~700 LOC of if-else with ~40 LOC dispatch:
while (read_kv_line(file, key, val)) {
    bool matched = false;
    for (const StampParserEntry *e = stamp_parser_table; e->key; ++e) {
        if (strcmp(key, e->key) == 0) {
            e->parser_fn(result, val);
            result.has_flags |= e->mask_bit;
            matched = true;
            break;
        }
    }
    if (!matched) {
        // Future-compat: unknown key = WARN log, keep loading
        log_warn("verify_model_stamp: unknown key '%s' (forward-compat)\n", key);
    }
}
```

**Lookup cost:** ~30 string compares per stamp key worst-case (linear
scan); ~25us total at boot per cfg. Acceptable per CLAUDE.md item 18
(boot-only; not slow-path / hot-path). Perfect-hash dispatch deferred to
TECH_DEBT-022 (boot perf optimization; not in scope here).

### Step 3: verify byte-equivalence

The parser refactor MUST produce **bytewise-identical
ModelStampResult/ModelHandle state** as the pre-refactor parser for
every valid stamp body. Verification: synth representative stamp body
(all 30+ fields populated) → parse via OLD code path (rollback anchor)
→ parse via NEW code path → memcmp on result struct + scaler binding
char[65] equality + char[64] run_name equality. Bytewise-identical OR
document expected differences.

## Data-Oriented Design pass

(Reproduced from MASTER §v5.15.0 with implementation specifics.)

| DOD concern | Implementation in this subplan |
|---|---|
| **alignas(64)** | declared on ModelHandle struct definition + static_assert(sizeof(ModelHandle) % 64 == 0) at end of struct |
| **Bit-packed has_flags** | 14 uint8_t has_* → 1 uint64_t with named MASK_HANDLE_HAS_* constants; saves 13 bytes per handle (14 → 8 = 6 bytes saved; +7 bytes from removed padding between scattered uint8 fields) |
| **Hot/warm/cold cluster** | hot 64 B (booster ptr, has_flags, num_*, has_flags), warm (scaler ~600B), cold (paths, run_name) — measured + verified static_assert(offsetof) per `per-snapshot-cluster-layout-pattern.md` |
| **Padding determinism** | `int32_t _hot_pad0 = 0;` after num_outputs / buy_class_idx to fill 64 B cleanly; struct used in HMAC round-trip test (.C Test 1) so explicit padding required per CLAUDE.md item 27 |
| **AVX-512 byte-determinism** | N/A (no SIMD on ModelHandle directly) |
| **Latency impact (CLAUDE.md item 17)** | **Latency-neutral.** ModelHandle is read by slow-path inference dispatch (existing consumer); migration reshapes reads from `if (h.has_X)` (single byte-load + branch) to `BITMAP_IS_SET(h.has_flags, MASK_X)` (single uint64-load + AND + branch). Compiler generates equivalent code path; same cycle count. NO new slow-path consumers added. NO HOT_PATH_CHANGELOG entry needed. Verified via diff of `BG_Evaluate / SG_Evaluate / ExecutionCore_Tick` (must be zero changes per "Hot path UNTOUCHED" gate). |
| **Branchless discipline (CLAUDE.md item 18)** | All HANDLE_HAS / HANDLE_SET / HANDLE_CLR are single-instruction mask ops via the BITMAP_* API; no branches introduced. The 14 has_* read sites compile to the same instruction pattern post-migration. Parser dispatch table walk is BOOT-only (not slow/hot path) so the linear-scan strcmp loop is not a latency concern (boot budget ~25us total per CLAUDE.md item 18 trade-off). |
