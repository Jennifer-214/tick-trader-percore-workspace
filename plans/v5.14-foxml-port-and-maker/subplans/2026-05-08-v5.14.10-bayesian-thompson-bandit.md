## Why both algorithms; why dual mode

| | Exp3-IX (current) | Thompson sampling (new) |
|---|---|---|
| Strategy | Exponential weights, deterministic | Bayesian, randomized |
| Best for | Stationary reward distributions | Non-stationary / noisy rewards |
| Convergence | Faster | Slower but more natural exploration |
| Replay determinism | Yes (deterministic update math) | Yes (seeded mt19937_64) |
| Cost per cycle | ~50ns | ~80ns (RNG draws) |
| Memory | ~0.5KB per BanditState | ~0.5KB per ThompsonBanditState |

Crypto markets are NON-STATIONARY (regime shifts; alpha decay);
Thompson's natural exploration may outperform Exp3 here. Operator
paper-tests both via `cfg.bandit_algorithm=2` dual mode → per-fill
telemetry records which algorithm picked which arm → offline
analysis decides winner.

## Implementation plan

### Step 1 — ThompsonBanditState struct + math kernel

File: `ML_Headers/ThompsonBandit.hpp` (NEW; parallel to BanditLearning.hpp)

```cpp
// Per-arm Gaussian conjugate posterior. Reward updates use the
// closed-form posterior mean update for known-variance Gaussian:
//   precision_post += precision_obs (= 1.0 / reward_variance)
//   mu_post = (precision_old * mu_old + precision_obs * reward) / precision_post
// This is the natural Bayesian update; deterministic given inputs.
struct ThompsonBanditState {
    double mu_post[BANDIT_MAX_ARMS];
    double precision_post[BANDIT_MAX_ARMS];
    uint64_t total_pulls[BANDIT_MAX_ARMS];
    int n_arms;
    double mu_prior;          // operator-tunable; default 0.0
    double precision_prior;   // operator-tunable; default 1.0
    double precision_obs;     // observation precision; default 1.0
    uint64_t rng_state;       // mt19937_64 internal state for Gaussian draws
};

// Sample one draw per arm from posterior; return argmax index.
// Uses Box-Muller for std::normal_distribution alternative
// (deterministic; seeded by rng_state).
inline int Thompson_Sample(ThompsonBanditState* tb);

// Update posterior given observed reward for `arm`.
inline void Thompson_Update(ThompsonBanditState* tb, int arm, double reward);

// Compute posterior probabilities (P(arm has highest mean)) via
// N=128 Monte Carlo draws. Used for telemetry only — Selection
// uses Thompson_Sample directly.
inline void Thompson_GetProbabilities(ThompsonBanditState* tb, double* probs_out);
```

### Step 3 — ML_BuildParameters dispatch

In the existing weighted-blend path:
```cpp
double weights_buf[ENSEMBLE_HORIZON_MAX];
int chosen_arm = -1;

switch (config->bandit_algorithm) {
case 0: // Exp3 (default; bytewise-identical to pre-v5.14.11)
    Bandit_GetProbabilities(&ezoo->bandits[regime_id], weights_buf);
    break;
case 1: // Thompson sampling
    chosen_arm = Thompson_Sample(&ezoo->thompson_bandits[regime_id]);
    // Pure-selection mode: weights = one-hot at chosen_arm
    for (int i = 0; i < ezoo->primary_count; ++i)
        weights_buf[i] = (i == chosen_arm) ? 1.0 : 0.0;
    break;
case 2: // Both — Exp3 weights, Thompson sample for telemetry
    Bandit_GetProbabilities(&ezoo->bandits[regime_id], weights_buf);
    chosen_arm = Thompson_Sample(&ezoo->thompson_bandits[regime_id]);
    // Telemetry: log Exp3 weights + Thompson choice per fill
    // (uses calibration log v5.13.0.B with new columns)
    break;
}
```

## Latency analysis

**Slow-path (per ML cycle):**
- Default cfg (bandit_algorithm=0): ~5ns enum check + Exp3 path unchanged
- cfg=1 (Thompson): ~80ns (N=8 Gaussian draws via mt19937 + Box-Muller
  + argmax reduction). RNG state update is sequential but cheap.
- cfg=2 (Both): ~130ns (Exp3 + Thompson; both run for telemetry)
- Hot path UNTOUCHED.

**AVX-512 opportunity (deferred to v5.16+):** Vectorize 8 Gaussian
draws via SVML `_mm512_*_normal` (intrinsic-equivalent). Cost
reduction ~2x. Marginal vs slow-path budget.

**Replay-determinism:** Thompson uses mt19937_64 with cfg-set seed.
Identical seed + identical reward sequence → identical sample
sequence. Bytewise-deterministic across runs.
