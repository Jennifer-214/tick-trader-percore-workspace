## Findings

### Atomic / clock / cfg redundancies — NONE

No new atomic fields, clock reads, or cfg loops modified.

### 1. `parse_int_csv` λ vs. `parse_pct_csv` λ — DUPLICATES_EXISTING

Two lambdas with identical control flow shape (95% overlap),
differing only in value type + range check:
- `parse_pct_csv`: float, [0.0, 100.0]
- `parse_int_csv`: int, [0, LABEL_COUNT)

**Merge proposal:** `parse_csv_generic<T>()` template. Cost is
high relative to benefit (breaks render-loop lexical locality;
only 3 call sites; ImGui render-frame is "per-frame cheap").

**Recommendation:** DEFER to v5.14+ if more CSV parsers appear.

### 2. Snap broadcast-or-match loop: TP/SL vs. label_kind — DUPLICATES_EXISTING

Identical nested ternary + array-fill logic for three snapshots in
the same click handler (TP, SL, label_kind).

**Merge proposal:** Extract `snap_broadcast_or_match<T>()` template.
Saves ~9 lines; adds ~2 lines template + 3 calls (net ~−5 LOC).
Clarity gain by naming the pattern.

**Recommendation:** PROPOSE for next refactor. Not blocking
v5.13.5. High-value if a 4th per-horizon CSV appears.

### 3. Alignment predicate: train_lk vs. train_tp/train_sl — DUPLICATES_EXISTING

Identical predicate shape repeated three times:
```cpp
bool train_X_aligned = (train_X_n <= 1) || (train_X_n == eff_horizon_count);
```

**Merge proposal:** Lambda `is_aligned(count)`. Saves ~3 lines;
clarity gain by naming "alignment" concept.

**Recommendation:** PROPOSE; lower priority than #2.

### State-field reuse — NEW / JUSTIFIED

All four new TrainingPanelState fields (ui_training_side,
ui_label_kind_csv, ui_label_kind_per_horizon[],
ui_label_kind_per_horizon_count) are orthogonal to existing state
and correctly initialized. Snap fields on MultiHorizonWorkerArgs +
MultiHorizonParallelJob follow the established pattern.

### Cross-plan merge candidates — NONE

v5.13.5 is self-contained UI feature for v5.13.0 (engine) +
v5.13.4 (bandit). No plan-to-plan merges.

### Branches — CORRECT

Two new data-dependent branches; both in slow paths with high
prediction accuracy. Branchless alternatives would add overhead.
