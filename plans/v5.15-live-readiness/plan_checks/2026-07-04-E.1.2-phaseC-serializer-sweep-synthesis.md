# E.1.2 Phase C — serializer-registry pre-coding sweep (synthesis)

**Verdict: NOT code-ready as-specified.** The cohesion gate validated the PATTERN (hybrid flat-registry + delegates + count-lock = right shape). This deep 4-agent sweep validated that too but found the IMPLEMENTATION carries a coherent set of drop-surfaces the pattern-level check couldn't see — and, on THIS exact ship, a **triple-vacuity** where all three structural safety nets are simultaneously blind. Good news: one stronger-and-simpler guard (a persist-layout hash) dominates all three partial mechanisms AND closes a known M7 hole (D-208 / TD-180). Every major finding is convergent across ≥2 agents.

## Convergent findings (severity-ordered)

### 1. [CRITICAL — M7 hole] Triple-vacuity on this ship's exact wire delta (A2 capstone; I2 corroborates)
E.1.2's per-node wire delta is **size- AND count-canceling**: drop `node_dd_pct` (Money, −16B, −1 row) + add `partner_pending_pnl` (Money, +16B, +1 row) = **net 0 bytes, net 0 rows.** So on this ship, simultaneously:
- a size→version guard (BLK-3/TD-180) is vacuously green (net 0);
- `static_assert(FOREACH_NODE_PERSIST_FIELD_COUNT == N)` is vacuously green (−1 +1 = N);
- the Save→Load round-trip gate is vacuous (symmetric drop — finding 5).

All three green while the per-node wire SEMANTICS change (the offset that held `node_dd_pct` now holds `partner_pending_pnl`; everything after shifts). Only the dev *remembering* to bump SHARDED saves it — a convention, not a forced function. This ship bumps (safe), but a future size-neutral/count-neutral swap re-opens the identical hole = D-208's known "size-pin RED-builds but nothing forces the VERSION bump" M7 candidate.
**FIX (dominates all three):** a **persist-layout hash** — a `constexpr` hash of the concatenated `(name, type, wire-order)` over the FULL persist walk (flat rows + every delegate row) + `static_assert(persist_layout_hash == EXPECTED_FOR_V11)`. Any add / drop / reorder / **size-neutral swap** flips the hash → compile error → forces the bump. Strict superset of count-lock + size-guard. Recommend it REPLACE "OMS-precedent count-lock" as the PRIMARY forcing function (keep per-registry count-locks as cheap local tripwires).

### 2. [HIGH] The interleave — "flat + delegates" reorders 3 doubles → silent D-110 (I1 + A1)
The 24 flat scalars are NOT wire-contiguous: 21 precede `regime_state`+`pnl_feeder`, then **3 flat doubles (`staged/active/last_confidence`, save `:244-246`) sit BETWEEN the feeder and confidence delegates.** A "flat registry (all 24) then call delegates" hoists those 24 bytes before `regime_state` → 24-byte silent reorder = exactly the "reorder keeps sizeof but must FAIL" case (accept-crit `:58`). OMS's precedent is purely flat, so it doesn't demonstrate the ordered-interleave NodeContext needs.
**FIX:** a SINGLE ORDERED registry — each row carries a KIND ∈ {SCALAR, BIT, DELEGATE, PAD}; emission order == row order == hand-loop order by construction. DELEGATE rows ARE the sub-walker invocations at their wire positions; PAD rows emit/skip the interstitial 1B/3B pad (rows 4, 22 in the map). Subsumed into the layout-hash of finding 1.

### 3. [HIGH] Per-delegate drop-blindness — count-lock necessary-but-insufficient (A1 + I2 + A2)
A parent flat count-lock counts only the ~24 scalars → blind to THREE delegate drops (A2, named): (a) drop a row from `FOREACH_CONFIDENCE_PERSIST_FIELD` (confidence has **no** count-lock — grep-confirmed) → parent count unchanged → uncaught (the `node_gross_wins→$0.00` class re-introduced at the delegate seam); (b) delete the delegate CALL (`ConfidenceScorer_FieldwiseWrite` line) → not a registry row → entire sub-block vanishes uncaught; (c) drop a hand-written `regime_state`/`pnl_feeder` field — they are NOT registries today.
**FIX:** (i) convert `regime_state` + `pnl_feeder` to field-by-field persist registries (mirror the `confidence` delegate); (ii) a `_PERSIST_COUNT` static_assert on EACH (regime/feeder/confidence — add the missing confidence one); (iii) a WALK-COMPLETENESS check (every enrolled persist registry is actually invoked — no count-lock catches a dropped CALL). The layout-hash subsumes (i)+(ii) IF it walks INTO the delegates.

### 4. [HIGH] The v5.11.15 commit-leak — naive auto-commit re-opens a known bug (A1)
`strategy_id` + `strategy_state_kind` are PERSIST-but-DELIBERATELY-DON'T-COMMIT (read off the wire, consuming bytes, but NOT applied — `:502` "intentionally NOT restored"; `:539` `(void)`). The comment `:506-538` documents that RESTORING `strategy_state_kind` is the **v5.11.15 leak** (kind/state mismatch → `Strategy_FreePerCore` leaks the state pointer). A naive registry auto-commit (`ctx.field = s.field`, as `OMS_PROJECT_PERSIST_COMMIT`) re-restores it → re-opens the leak. OMS's binary PERSIST kind can't model this.
**FIX:** an explicit **PERSIST_NO_COMMIT** kind (or a sidecar commit-override per H18) for `strategy_id`/`strategy_state_kind`. Also model the commit-side specials: `resolved_strategy_id` IS committed; kill needs BIT set/clr; confidence needs the `RecomputeRunningSums` tail.

### 5. [HIGH] The gate is vacuous against the drop class (A1 + I2 + A2)
Byte-compare / round-trip ALONE is blind: (a) under-populated fields (a field left at 0 is invisible when dropped); (b) symmetric registry drop (save+load symmetric → round-trip PASSES); (c) same-commit golden regen (the golden rebuilt in the drop commit lacks the field → PASSES — "a golden regenerated in the act it polices is not a golden"). `±USE_NATIVE_128` is ORTHOGONAL (both builds drop the same field → byte-identical); the plan conflates encoding-determinism with field-completeness.
**FIX — the gate is a LAYERED net, not one check:** (i) a FROZEN golden file committed to the repo, regenerated ONLY behind a reviewed version-bump gate (not blindly in the drop commit); (ii) a full-poison fixture — EVERY persisted field (all confidence + regime + feeder + `partner_pending_pnl`) populated with DISTINCT non-zero per-node-keyed values (distinct → a reorder/swap also diverges); (iii) a value-round-trip (`Money_Eq` per field — catches a drop the memcmp misses); (iv) a positive control (mutate one restored field → assert re-Save differs — Class-51 teeth); (v) a wire-length pin (cheap first tripwire); (vi) [novel, adopt] registry-driven population (walk the persist registry to poison each field → a NEW field is auto-exercised). Keep `±USE_NATIVE_128` as the ENCODING gate, not the drop gate.
