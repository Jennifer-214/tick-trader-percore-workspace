## Q1 — TERMINAL definition, accumulation fields, weighted-avg mechanics

**Terminal taxonomy (DESIGN-GAP — the plan never defines "terminal", and the venue cannot deliver most terminal states at HEAD).** Verified at HEAD:

- `ud_parse_execution_report` (`BinanceUserData.hpp:311-383`) **returns 0 for every non-TRADE execution type** (`:320-323` — `x != "TRADE"` → drop). Venue CANCELED / REJECTED / EXPIRED executionReports (incl. a MARKET order's partial-fill-then-EXPIRED final event on a thin book) **never become Commands**. `X` is read only on TRADE events: `order_complete = (X=="FILLED")` (`:351-357`); `PARTIALLY_FILLED`, and everything else, → 0.
- `ORDER_CANCELED`/`ORDER_TIMEOUT`/`ORDER_UNKNOWN` are **never set anywhere** (comprehensive grep: enum `Order.hpp:70-72` + `Order_IsTerminal` only).
- `Order_IsTerminal` (`Order.hpp:414-421`, FILLED|REJECTED|CANCELED|TIMEOUT) is **dormant** — its comment claims "Used by OrderManager_Tick to decide whether to free the slot", which is false at HEAD (the free at `OrderManager.hpp:1414-1415` is unconditional inline). It is the natural terminal predicate for the fix; the comment becomes true only when S-2 lands.
- REST adapter failure → `ORDER_REJECTED` (`:1401`). REST MARKET success returns **cumulative** `executedQty`/`cummulativeQuoteQty` and never parses the response `status` field (`BinanceOrderAPI.hpp:531-540`).

**Required decision (terminal taxonomy table, per source):** terminal = {FILLED via `X` on TRADE events} ∪ {REJECTED via REST failure} ∪ {CANCELED/EXPIRED via **parser extension** forwarding non-TRADE terminal exec types as a terminal command} ∪ {TIMEOUT via the Q3 reaper}. If the parser extension is deferred, the reaper is the ONLY path that ever frees a cancel/expire-stranded slot — say so explicitly.

**Accumulator placement (DESIGN-GAP).** `Order<F>` already carries `filled_qty` ("running total across partials") and `avg_fill_price` ("weighted across partials") — the comments (`Order.hpp:178-179`) promise accumulation the code never implements (overwrite at `OrderManager.hpp:1369-1370`). The S-2 design needs NEW fields (per Q4: `acc_net_qty`, `acc_net_notional`, `acc_fee_quote`; + `last_trade_id` per the dedup note below; sticky fallback bit fits `flags_packed` bits ≥26). Any 16B addition **breaks `static_assert(sizeof(Order<64>)==256)` at `Order.hpp:403`** and the HOT-3-line/COLD-1-line cluster doc (`:153-163`) + OrderPool footprint. **Not named anywhere in the plan** — the plan names only OrderEvent's cascade (S-4). Order is NOT persisted (no `orders[]` in `ShardedSnapshotPersist.hpp`) so this is layout-discipline, not wire — but per the plan's own R1 lesson ("the relocation set is a tool output, not a paragraph") it must be an enumerated row: new sizeof constant + cluster re-derive + rationale-string update.

**Weighted-avg mechanics (DESIGN-GAP — the three B1 directives are not independently composable).** B1 says "book converted fee + deplete received qty + weighted avg price" without a formula. PnL-identity analysis: with booked qty `q_net = Σ(lᵢ − nᵢ·[N==base])` and booked entry fee `Σ(nᵢ·pᵢ)`, the engine's `net = (X − avg)·q_net − fees` equals true economics **only if `avg = Σpᵢ·(lᵢ − nᵢ·[N==base]) / q_net`** (deplete-then-weight). The gross-weighted alternative (`Σpᵢlᵢ/Σlᵢ`) leaves a residual `Σnᵢpᵢ − avg·Σnᵢ` (second-order: fee × price-dispersion) that double-counts part of the base fee. **Required:** pin the deplete-then-weight formula (exact identity, costs nothing); rounding = one `#4` half-even mul per fill (`pᵢ × net_lᵢ`) into an exact-sum accumulator, ONE `#7` decimal Div at terminal-book (half-even) → `avg`. This makes P3's dependency on P1's #7 Div explicit (currently unconnected in the plan).

## Q2 — Paper-fill trap (V2)

Verified: paper synthetic fill `memset`s the result (`OrderManager.hpp:993`) → `order_complete=0` → state PARTIAL (`:1383`) → `total_filled` **never increments for paper orders** (`:1384-1386`) → slot survives only because of the unconditional free. The plan names the trap + "paper-fill regression guard" (B1 S-2; acceptance row) but **never picks the fix shape**. **Recommended decision:** paper emits `order_complete=1` at the synthetic-fill build (`:993-996` cluster) — semantically correct (a paper fill IS the complete order), one line, and makes paper exercise the SAME terminal path as a live FILLED (no special-case in keep-slot logic). Rejected alternative: `free when FILLED OR !live_trading` (forks the terminal condition; paper stops exercising the live path). **Behavior change to name:** paper orders begin counting `total_filled` (pre-existing counter bug silently fixed — sweep consumers). **Regression test design (concrete):** (a) paper submit → exactly one book + `order_bitmap` returns to 0 + `total_filled`+1; (b) leak canary — N paper round-trips → bitmap 0 (a terminal-only-free regression fails in one iteration); (c) live-sim multi-fill — 3 TRADE events (2× PARTIALLY_FILLED + 1 FILLED) → ONE terminal book with accumulated totals, fills 2-3 not dropped; (d) partial-then-REJECTED → terminal-book partial-so-far + free.

## Q3 — Timeout/orphan reap

**No reap path exists at HEAD** (verified: `ORDER_TIMEOUT` never set; `submitted_at_us` consumers are event-log timestamps only — `:649/:666/:1300/:1408`; no deadline scan in `OrderManager_Tick`; `last_update_us` exists on Order, written nowhere meaningful). Today the unconditional free masks the absence. **Under keep-slot-until-terminal it becomes a liveness bug the fix itself introduces:** Q1 shows venue cancel/expire/disconnect deliver NO terminal event → the slot leaks **permanently**; `MAX_INFLIGHT_ORDERS=16` (slot = id bits 63..60) → each leak permanently shrinks the order pool → submit starvation. **The reaper is a MANDATORY in-ship component of S-2, not hardening.** Required design: `OrderManager_Tick` deadline scan (drainer cadence; `now − last_update_us > cfg deadline` for non-terminal states ≥ SUBMITTED — touch `last_update_us` on every fill event); action = terminal-book the partial-so-far through the SAME terminal-book path → `ORDER_TIMEOUT` → free → FailureModeRegistry counter + reconcile true-up (REST order-status query; `Reconcile.hpp` is the sister). **Partial-SELL terminal needs its own named decision:** `Portfolio_CloseSlot` is all-or-nothing — booking a partial SELL closes the whole slot while the venue still holds the remainder (position divergence). Options: (i) close-at-accumulated-avg + immediate reconcile-driven correction; (ii) escalate to the `ShardedLiveSafety` orphan/flatten path (`:77/:204` sisters). Pick one.

**Adjacent gap the keep-slot design arms (NEW finding):** WS `t` (trade id) is parsed but **never consumed** — `BinanceUserData.hpp:479-488` captures `trade_id` into a local and drops it; no dedup table exists. At HEAD duplicate executionReports (WS reconnect replay) are absorbed by the free-after-first-fill; under keep-slot they **double-accumulate**. Same shape for mixed REST+WS: REST returns CUMULATIVE qty while WS delivers per-fill increments — both-deliver = double-count once the slot survives (today masked by the ACK-only path `:1362-1367` + first-fill free). **Required:** per-order `last_trade_id` (8B, monotonic-skip) on the Order accumulator block + a stated source-of-truth rule (WS-active ⇒ REST results are ACK-only, fills accumulate from WS only).

## Q4 — Commission accumulation + qty-depletion flow

Direction (per-fill convert-then-sum at each fill's own price, D-173) is right and matches the venue's per-fill `n`/`N`. Gaps: **(a) the converted sum has no named home** — it must live on the Order accumulator block (Q1), booked at terminal as the `entry_fee`/`exit_fee` arg into the existing sinks (`Portfolio_OpenSlot` entry_fee `:1166-1168`; `total_fee` → `net` → balance `:1212-1215`). **(b) The depletion→Portfolio trace is unstated:** `Portfolio_OpenSlot` gets qty from `handle_buy_fill`'s `fill_qty` arg = whatever `HandleFill` passes — the design must state the terminal-book passes `acc_net_qty` (depleted), which then flows correctly into exit sizing (`handle_sell_fill` uses position `qty_snap` `:1190/:1207`, so exits sell the depleted qty — oversell closed). **(c)** Per-fill conversion rounding must be pinned (#4 half-even on `nᵢ × pᵢ`); the deplete-then-weight identity (Q1) is the consistency contract. **(d)** Oracle/test row: hand-computed multi-fill mixed-asset fixture (quote-fee SELL + base-fee BUY + degrade-fallback fill) balancing to the penny — extends the D-100 recorded-fills rows already named.

## Q5 — Degrade path (D-173 flagged computed-fallback + halt-new-entries)

The right primitive EXISTS and is exactly shaped for this: **`ExecutionCore::permission`** (`ExecutionCore.hpp:100`, alignas(64), own cache line; hot path `can_enter = !active & permission & bg_fires` `:25`) — gates ENTRIES only; SG exits / TimeExit / TrailingSL unaffected. The legacy `kill_switch_active` (`PortfolioController.hpp:153`) is the WRONG vehicle (controller-legacy + flatten semantics; degrade ≠ flatten). **Unnamed in the plan:** the detection runs on the DRAINER (fill processing) but `permission` is written by the per-core SLOW path → needs a drainer→slow-path carrier. Sister at HEAD: the WS-staleness emergency-flatten CAS flag (`OrderManager.hpp:562`). **Required design:** sticky atomic flag on `OrderManagerState` (CAS-set when the runtime `N`-convertibility guard fails) → per-core slow path reads at rebuild → `permission=0` **account-wide** (BNB shortfall is account-level, not per-core — state the scope) → entries halt, exits run. **FailureModeRegistry rows** (`MemHeaders/FailureModeRegistry.hpp:123` FOREACH_FAILURE_MODE; storage classes BIT_FLAG/COUNTER_U32/PERCENT_U8): `commission_degraded` BIT_FLAG SEV_RED (operator-must-intervene, sticky) + `commission_fallback_fills` COUNTER_U32 SEV_YELLOW (per-fill fallback count) — matches the existing vocabulary exactly. **Also decide re-arm:** operator-ack vs boot-clear (recommend: sticky until restart + RED tile; no silent self-re-arm).

## Q6 — OrderEvent fee field + replay

**Core design delivers.** Verified: `OrderEvent` `OrderEventLog.hpp:79-92` (no fee field); both folds recompute (`:656-657/:675-676` from a single global `fee_rate` param; CEL `:860-877` from `effective_cores`); boot-Init passes nullptr → zero fees (`ControllerEventLoop.hpp:951-953` verbatim). Adding the booked decimal fee + replay-reads-event makes the event log the fee chokepoint: CEL's nullptr-cfg boot context becomes fully correct (the cfg array fed ONLY fee recompute), the 3-way rate asymmetry (HIGH-2) collapses, and `Portfolio_FromEventLog`'s `fee_rate` param goes dead (remove + sweep callers/tests). **Old-log rejection confirmed:** loader `:498-512` checks magic `OMSEL01` + `fpn_width` + `entry_size`; the fee field changes entry_size (144→160 by standard layout) AND S-4 flips magic → `OMSEL02` (H21 tombstone) — double net. `OrderEvent_MakeFill` memsets (`:570-571`), so padding stays deterministic; re-derive the explicit `_pad` per H12 with the new field (today ~10B of padding @38-47 is implicit — make it explicit while touching the struct).

**Defect 1 — B2↔S-3 internal contradiction:** B2 still enumerates the four replay fee-muls (`OrderEventLog.hpp:656-657/675-676`, `ControllerEventLoop.hpp:863/877`) as #4-rounding-helper routing targets, but S-3 DELETES those computations (replay reads `e.fee`). Amend B2: mark them S-3-superseded; #4 routing remains for computed paths only (paper/backtest fills, legacy mode-0 `:1923/:1967`, ExitBuffer estimate).

**Defect 2 — epoch-marker commit-binding is ambiguous:** the V4 class ("same-size semantic flip silences size-keyed guards") arms at each surface's FIRST radix flip. Execution sequence: P2 = money-site migration (flips OrderEvent/snapshot money semantics), P3 = fee field + OMSEL02, P4 = versions 14/10/7 + STAMP v3. S-4's "SAME COMMIT as the first money type flip" is stated for snapshot versions only. In a multi-commit ship, P2-only commits load pre-epoch artifacts cleanly into a semantically-flipped engine — the exact V4 hazard, intra-ship. **Required decision:** land ALL epoch markers (14/10/7 + OMSEL02 + STAMP v3 + test floors) in the FIRST commit that flips ANY money semantics (markers-first is safe and simplest), or per-surface pin each marker to its surface's flip commit. **Also name the event-log policy under S-2:** ONE `OEVT_FULL_FILL` at terminal carrying accumulated totals + booked fee (both folds unchanged — they're FULL_FILL-only at `:645`/`:850`; recommended) vs per-fill `OEVT_PARTIAL_FILL` records (`=2`, enum slot reserved "phase 06"; folds must change). The terminal-book design implies the former; the plan is silent.

## Q7 — Reported≠computed differential

S-20's disposition says "numeric tolerance stated for the paper-vs-live fee differential (MED-4)" — but **no tolerance value or fixture shape exists in the plan or synthesis** (grep: zero hits for tolerance/ULP beyond the S-20 sentence itself). Acceptance has "one reported≠computed case" with no construction. **Required concrete spec (D-100 oracle rows):** per-fill `|computed_roundUP − reported_converted| ≤ K·10⁻⁸`, K documented per asset case — quote-fee: K small (rounding-mode delta only); base-fee: K covers the ×fill_price conversion; BNB: excluded (fallback-flagged, counted not compared). The fixture: venue round-UP at asset precision vs engine half-even on a value that splits them (constructible). Drift in this differential doubles as the venue fee-schedule-change detector — it must FAIL loud, not inform.
