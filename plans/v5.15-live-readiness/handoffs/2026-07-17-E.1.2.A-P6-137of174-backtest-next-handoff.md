   - D-326: a fence-top comment run whose next code is the unit's OWN signature → relocate VERBATIM into `[COMMENT]`; different-sub-part / member banners STAY in the fence.
   - `[DERIVED]` quartets: AUTHOR then true via `check_cache_layout.py --fix`; unprobeable structs (templates etc.) → D-327 gap-note form.
   - `[OVERVIEW]` prose must NOT mention bracketed category tokens (validator collision); `[COLUMN]` legends: count = tuple arity, spell `[type]` not `[TYPE]`.
   - `[SEAM]_` is a TOP-LEVEL line; single-token bracket headings become `[SECTION]_[name]`; section prose stranded above an opener gets a thin `//----` closing bar.
   - Tooltip/string-literal content + in-macro backslash-continued comments are **CODE BYTES** — never edit in a docs pass (the P6.106 lossless-FAIL lesson).
4. **Verify chain, in order:** `lossless.py <file>` → `check_code_tag_blocks.py --paths <file>` → `check_cache_layout.py --fix` + gate → **full battery** → `./build.sh test`.
5. **Commit per batch** with rot enumeration, **gate→commit chained with `&&`** so a red BLOCKS the commit.
