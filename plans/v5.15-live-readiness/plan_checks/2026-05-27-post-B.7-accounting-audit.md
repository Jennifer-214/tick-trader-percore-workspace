# /accounting-audit report — 2026-05-27 — post-v5.15.5.F.4d.1.B.7 sister-bug surface check

## Headline

**YELLOW verdict.** Four NEW HIGH-severity Class 26 instances surfaced in slow-path **fee-floor compute paths** — all reading `cfg.fee_rate_taker` (GLOBAL) while in per-core scope where `cfg.cores[core_id].fee_rate_taker` is the authoritative value. Same family as `.B.7` `partial_exit_pct` / `tp2_mult` bugs but at a different surface (fee-floor SL/TP cap formulas, NOT entry-qty / TP2 computation). All findings are in SHARDED slow-path code that has per-core context in scope but reads the legacy global scalar.

**Effect masking:** these silently miscalibrate the ratchet-SL fee-floor cap + TP fee-floor cap per-core. Surfaces only when per-core `fee_rate_taker` values DIFFER (e.g., operator sets `core_2_fee_rate_taker=0.0015` for testing high-fee tier). With uniform per-core fee_rate_taker (=== global), all 4 instances are value-equivalent and bug is invisible.

**Distinction from `.B.7`:** the `.B.7` fix was `cfg.cores[i]` with WRONG-index variable (`i` = inner ring-pop counter). These findings are `cfg.fee_rate_taker` (UNINDEXED — reading the legacy global field instead of per-core). Same Class 26 family, different sub-shape. Sister evolution of the same migration gap from `ea08210` mechanical migration cohort.

**Class 27** scan: 1 LOW finding — vestigial `DrainerConstants.fee_rate_taker_d` field still populated at line 100 but UNREAD by any production code post-`.F.4c.3` WIP2d-1.B.1 cache deletion. Dead state, no Class 27 hazard at runtime but discipline candidate.

**H4 enforcement:** all flagged double/float storage of accounting values verified DISPLAY-ONLY (`EventLoopAggregates`, CSV emit, GUI snapshot fields, stderr exit-diag logs). All accounting STORAGE paths use FPN<F>. ZERO H4 violations.

**Backtest↔live parity:** `BacktestSharded` shares `EngineCommon_ApplyBnbDiscount` + per-core `cfg.cores[c].fee_rate_*` flow with LIVE. No parity drift at fee/commission/slippage surface. `BacktestEngine` (legacy `Backtest_Run`) uses single-cfg PortfolioController flow — separate architecture, separate cfg semantics, no cross-path drift to fix.

**Atomicity:** `oms->balance` + `oms->realized_pnl` writes confirmed single-writer (drainer thread). Per-core `core_realized` / `core_peak_balance` confirmed single-writer (per-core slow-path). No race.

### [HIGH-1] Class 26 — `cfg.fee_rate_taker` read in `EventLoop_TrailingSLRatchetOneCore` (per-core context) — `CoreFrameworks/ControllerEventLoop.hpp:3605-3606`

- **Severity:** HIGH — silent slow-path SL ratchet fee-floor miscalibration per-core
- **Category:** Cat 2 — per-core / per-instance fee_rate + commission indexing
- **Class:** Class 26 — global consumer reading per-core field

**Symptom:**

```cpp
// EventLoop_TrailingSLRatchetOneCore signature:
inline void EventLoop_TrailingSLRatchetOneCore(EventLoopState<F>* state,
                                                 const ControllerConfig<F>& cfg,
                                                 const RollingStats<F, W>& rolling,
                                                 double current_price,
                                                 int core_id) {   // <-- per-core context IN SCOPE
    double stddev_d     = FPN_ToDouble(rolling.price_stddev);
    double trail_dist_d = stddev_d * FPN_ToDouble(cfg.cores[core_id].sl_trail_mult);    // CORRECT — per-core
    double hold_thresh  = FPN_ToDouble(cfg.cores[core_id].tp_hold_score);               // CORRECT — per-core
    // ...
    double fee_taker_d = FPN_ToDouble(cfg.fee_rate_taker);                              // LINE 3605 — GLOBAL (WRONG)
    if (fee_taker_d <= 0.0) fee_taker_d = FPN_ToDouble(cfg.fee_rate);                   // LINE 3606 — GLOBAL fallback (WRONG)
    double fee_floor_pct = 3.0 * fee_taker_d;
```

`core_id` is in scope at line 3585. Lines 3587-3588 correctly read `cfg.cores[core_id].sl_trail_mult` + `cfg.cores[core_id].tp_hold_score`. Lines 3605-3606 read the global `cfg.fee_rate_taker` / `cfg.fee_rate` — should be `cfg.cores[core_id].fee_rate_taker` / `cfg.cores[core_id].fee_rate`.

**Root cause:** Same `.F.4c.3` WIP2d-1.B.1 migration cohort as `.B.7` Async.hpp bugs. The fee_rate per-core migration touched OMS scalar fields + several call sites; this fee-floor compute site was missed (no comprehensive grep verified all `cfg.fee_rate_taker` UNINDEXED reads when global → per-core happened).

**Effect:** Slow-path ratchet-SL cap formula `entry × (1 - 3 × fee_rate_taker)`. When per-core `fee_rate_taker` differs across cores, the cap on a higher-fee core uses the GLOBAL (lower) fee_rate_taker → cap is too loose → ratchet pushes SL closer to entry than safe → SG-fired exits at near-breakeven gross become NET-NEGATIVE for that core. Effect is direct realized-P&L drift per-core.

**Fix shape:**
```cpp
double fee_taker_d = FPN_ToDouble(cfg.cores[core_id].fee_rate_taker);
if (fee_taker_d <= 0.0) fee_taker_d = FPN_ToDouble(cfg.cores[core_id].fee_rate);
```

Sister to `.B.7` Async.hpp:814+853 fix — single-substitution `cfg.X` → `cfg.cores[core_id].X` within per-core scope.

**DESIGN_SPEC reference:** `cfg-scope-discipline.md` (per-core fields read via core_id index, never as scalar) + `decision-time-data-binding-pattern.md` § Class 26 sister surface

**CI gap:** Check 9 (paired-access mismatch) catches `cfg.core_overrides[X]` + `cfg.cores[Y]` mismatches but does NOT catch `cfg.fee_rate_taker` UNINDEXED reads at per-core consumer sites. New detection signature needed: flag UNINDEXED `cfg.fee_rate*` / `cfg.slippage_pct` / `cfg.*_pct` reads inside functions taking `core_id` / `slot` parameter.

### [HIGH-4] Class 26 — `resolved_cfg.fee_rate_taker` read in `EventLoop_RebuildOneCore` GUI diag capture (per-core context via `slot`) — `CoreFrameworks/ControllerEventLoop.hpp:3042-3043`

- **Severity:** HIGH — affects GUI display + diagnostic accuracy; SISTER to fee-floor cohort even though display-facing
- **Category:** Cat 2 — per-core fee_rate indexing
- **Class:** Class 26 (display-drift variant — display reads global while execution path reads per-core, GUI panel shows wrong fee floor)

**Symptom:**

```cpp
// EventLoop_RebuildOneCore body; slot IN SCOPE (outer loop)
FPN<F> fee_taker = !FPN_IsZero(resolved_cfg.fee_rate_taker)                          // LINE 3042 — GLOBAL resolved (WRONG when per-core)
    ? resolved_cfg.fee_rate_taker : resolved_cfg.fee_rate;                           // LINE 3043 — GLOBAL fallback

    state->cores[slot].pending_params.tp_pct;
```

Important nuance: `resolved_cfg = ControllerConfig_ResolveForCore(*config, slot)` at line 2315. ResolveForCore merges `PerCoreOverrides<F>` into the global ControllerConfig but `fee_rate_taker` is NOT in `PER_CORE_OVERRIDE_FIELDS` macro list — verified via `ControllerConfig.hpp:119` (only `fee_floor_mult` is in RAW slot). So `resolved_cfg.fee_rate_taker` after ResolveForCore is the GLOBAL fee_rate_taker, identical to `cfg.fee_rate_taker`. Per-core fee_rate_taker is held in `cfg.cores[slot].fee_rate_taker` (separate per-core struct), NOT merged into `resolved_cfg` top-level.

Sister-pattern at line 3061 correctly uses `&resolved_cfg.cores[slot]` for Strategy_TpFloor — proving the right shape is available.

**Effect:** GUI panel diag_tp_pct_floor displays WRONG fee floor when per-core fee_rate_taker differs. Display-only (no execution drift) — but inconsistent with execution path that uses per-core via `Strategy_TpFloor` → `core_cfg->fee_rate` at line 3061. Operator sees one fee floor in GUI, execution computes another. M3 "display↔execution divergence" anti-pattern at fee-floor surface.

**Fix shape:**
```cpp
FPN<F> fee_taker = !FPN_IsZero(resolved_cfg.cores[slot].fee_rate_taker)
    ? resolved_cfg.cores[slot].fee_rate_taker : resolved_cfg.cores[slot].fee_rate;
```

**Severity note:** Severity HIGH because GUI/execution divergence at fee_floor diagnostic confuses operator triage; could lead to wrong operator response when paper-test fee values differ across cores. NOT silent accounting drift in pnl path.

## Sister-bug surface for `.B.7` cohort

The `.B.7` ship hotfixed 2 Class 26 instances at Async.hpp:814+853 (`cfg.cores[i]` WRONG-INDEX bug). This audit surfaced the **other half of the cohort** — 4 sites where `cfg.fee_rate_taker` was MISSED IN MIGRATION (the per-core registry exists but consumer still reads legacy global field).

**Migration cohort timeline:**
- `.F.4c.3` WIP2d-1.B.1 (2026-05-15): per-core fee_rate migration. OMS scalar fields DELETED. Decision-time binding via Order::pre_resolved.fee_rate landed. Order_BindPreResolved propagated.
- `ea08210` (.F.4c.3 Phase 2): "18 mechanical migrations" of `cfg.X` → `cfg.cores[i].X`. **2 wrong-index bugs introduced** (Async.hpp 814+853 → `.B.7` fix).
- **Audit gap from `ea08210`:** the mechanical migration touched `cfg.X` references that needed `[i]` indexing, but did NOT touch UNINDEXED `cfg.X` reads in fee-floor compute paths that needed `cfg.cores[c].X` migration. The 4 HIGH-* findings are this audit gap surfacing.

**Why detection signatures missed these:**
- Class 26 grep checks `cfg.cores[\w+]` for wrong-index symbol. Doesn't fire on `cfg.fee_rate_taker` (no array indexing at all).
- Class 27 grep checks scalar cfg-mirror fields on subsystem state. Doesn't fire on consumer-side reads.
- Check 9 paired-access detection checks `cfg.core_overrides[X]` + `cfg.cores[Y]` mismatch. Doesn't fire when neither array indexer is present.
