# v5.9.5i — Operator audit views (cfg enforcement + ML Status row + Stamps Inspection)

**Date:** 2026-05-02 (drafted; ships after v5.9.5h validation)
**Branch:** `feat/v5.9-ml-hardening`

**Effort estimate:** ~7-9h

## Theme

**"Operator can see and enforce stamp ↔ runtime cfg drift."**
v5.9.5h made hyperparams stamp-bound + load-WARN'd. v5.9.5i extends
the same treatment to v5.9.2b's 6 inference cfg fields (which are
stamped + parsed but never compared at load) and gives operators a
full-table audit view of all stamped models.

## Items

### #12 — Load-time enforcement of stamped inference cfg (4-6h)

Currently `verify_model_stamp` parses `inference_cfg_*` fields into
`ModelStampResult` but `CoreModelZoo._TryLoadRole` never compares
them to runtime cfg. v5.9.2b's "stamp-bound" wording was actually
"stamp-recorded" only.

**3-tier strict mode** (matches v5.9.3a scaler pattern):

| Field | Strict mode | Default mode | Suppress |
|---|---|---|---|
| `freshness_tau` | REFUSE | WARN | `acknowledge_inference_cfg_drift=1` |
| `confidence_threshold_scale` | REFUSE | WARN | same |
| `barrier_gate_enabled` | REFUSE | WARN | same |
| `confidence_hard_block_threshold` | WARN | WARN | same |
| `bandit_blend_ratio` | WARN | WARN | same |
| `fee_rate_maker/taker` | WARN | WARN | same |
| `held_out_fraction` | (not enforced — training-side only) | — | — |

**Files:**
- `CoreFrameworks/ControllerConfig.hpp` — add cfg field
  `acknowledge_inference_cfg_drift` (int, default 0)
- `ML_Headers/CoreModelZoo.hpp` — extend `_TryLoadRole` post-verify
  with comparison loop (~50 LOC)
- `tests/controller_test.cpp` — 6+ tests (per-field mismatch,
  strict-mode behavior, suppression flag)
- `DOCS/CLAUDE_ML_INVARIANTS.md` — update "stamp-bound" wording
  to reflect actual enforcement

**Existing-dependency claims:**
- `verify_model_stamp` already parses fields → `ModelStampResult`
  (ModelInference.hpp:838-885)
- 3-tier pattern established by v5.9.3a scaler (CoreModelZoo.hpp:200-244)
- `acknowledge_cross_binary_version_drift` (v5.9.4) precedent for
  suppression cfg flag

### #16 — ML Status panel: recorded cfg row (1-2h)

Engine_gui's `MLStatusPanel.hpp` shows model load state, scaler,
prediction, NaN counters. Add an expandable "Stamp recorded cfg ▾"
section showing the stamp's recorded fields with runtime-vs-stamp
drift indicators.

**Render shape:**
```
ML Status — Core 0
  Model: aggressive/buy_signal.bin (LOADED)
  Scaler: applied (registry_hash=0x...)
  Last prediction: 0.62 (threshold: 0.55)
  Confidence IC: 0.034
  ...

  Stamp recorded cfg ▾
    confidence_threshold_scale: 2.0 (stamp) | 1.5 (runtime) ⚠ DRIFT
    barrier_gate_enabled:       1   (stamp) | 1   (runtime) ✓
    freshness_tau:              300 (stamp) | 300 (runtime) ✓
    training_poll_interval:     100 (stamp) | 100 (runtime) ✓
    model_num_outputs:          3   (stamp) | 3   (runtime) ✓
    scaler_sha256:              0x4f2c... (truncated, click to copy)
    ─── XGBoost hyperparams (v5.9.5h) ───
    subsample:                  0.8 (stamp) | 0.8 (runtime) ✓
    ...
```

**Files:**
- `GUI/MLStatusPanel.hpp` — extend rendering (~80 LOC addition)

**Data source:** `ModelHandle` already has stamp-derived fields
(v5.9.4a: `training_poll_interval`, `stamp_model_num_outputs`).
v5.9.5h adds the hyperparams. v5.9.5i extends with the inference cfg
fields.

**Existing-dependency claims:**
- MLStatusPanel.hpp:32-150 — panel exists, established render flow
- ModelHandle struct (v5.9.4a + v5.9.5h fields)
- Runtime cfg accessible via existing `g_cfg` or panel arg

### #14 — Stamps Inspection panel (2-3h)

New stateful panel registered via `FOREACH_PANEL` X-macro (v5.8.4b).
Walks `models/*/`, parses every stamp, renders sortable table. Lives
in foxml_suite (operator audit tool).

**Table columns:**
| Model | Stamp | Engine ver | Registry hash | Gap | Scaler | num_outputs | Cfg drift |
|---|---|---|---|---|---|---|---|
| aggressive | ✓ OK | 5.9.5h | 0xfc91... | 0.018 | ✓ | 3 | (none) |
| baseline | ✓ OK | 5.9.4a | 0xfc91... | 0.024 | ✗ | 1 | (none) |
| peakvalley3c | ✗ FAIL | 5.9.2b | 0xfc91... | 0.052 | ✓ | 3 | gap_threshold |
| experimental | ⚠ stale | 5.8.10 | 0xab12... | 0.015 | ✗ | 1 | feature_registry_hash |

Click row → expand to v5.9.5d "Stamp details" tree (reuse).

**Filters:**
- All / OK only / FAIL only / missing-stamp
- Sort by any column

**Files:**
- NEW: `GUI/StampsInspectorPanel.hpp` (~250 LOC)

  stamp-load logic into a shared helper (already does the work;
  just refactor for reuse)
- `foxml_suite.cpp` — register panel via FOREACH_PANEL + dock layout

**Existing-dependency claims:**
