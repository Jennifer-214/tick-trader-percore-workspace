## Goal

Pack 6 K-state cfg enums into a single `uint16_t k_state_word` field within `ResolvedCoreCfg`. Apply CLAUDE.md item 30 (multi-bit state encoding) inference API. Convert switch-on-enum predicates to branchless mask-based predicates where applicable.

**Estimated savings:** 4-22 bytes per ResolvedCoreCfg × 16 cores = 64-352 bytes; plus ~1-2 ns/predicate (branchless vs switch). 1st CLAUDE.md item 30 application after codification.

## Key changes

1. **Define K-state shifts + masks** in `ResolvedCoreCfg.hpp`:
   ```cpp
   // Total: 11 bits in uint16_t k_state_word
   constexpr uint16_t K_BANDIT_ALGO_SHIFT     = 0;
   constexpr uint16_t K_BANDIT_ALGO_MASK      = 0x0001;  // 1 bit (2 states)
   constexpr uint16_t K_ENGINE_ARCH_SHIFT     = 1;
   constexpr uint16_t K_ENGINE_ARCH_MASK      = 0x0002;  // 1 bit (2 states)
   constexpr uint16_t K_RISK_CURVE_SHIFT      = 2;
   constexpr uint16_t K_RISK_CURVE_MASK       = 0x000C;  // 2 bits (4 states)
   constexpr uint16_t K_BARRIER_BLEND_SHIFT   = 4;
   constexpr uint16_t K_BARRIER_BLEND_MASK    = 0x0070;  // 3 bits (5 states; 3 reserved)
   constexpr uint16_t K_REGIME_CURR_SHIFT     = 7;
   constexpr uint16_t K_REGIME_CURR_MASK      = 0x0180;  // 2 bits (4 states)
   constexpr uint16_t K_REGIME_PROP_SHIFT     = 9;
   constexpr uint16_t K_REGIME_PROP_MASK      = 0x0600;  // 2 bits (4 states)
   ```
2. **Add `k_state_word` field** to `ResolvedCoreCfg` cache line 0 (HOT — read every cycle).
3. **Populate k_state_word in `ResolveCoreCfg`:**
   ```cpp
   resolved->k_state_word =
       (MBS_PACK(K_BANDIT_ALGO_SHIFT,   cfg->bandit_algorithm) |
        MBS_PACK(K_ENGINE_ARCH_SHIFT,   cfg->engine_arch) |
        MBS_PACK(K_RISK_CURVE_SHIFT,    cfg->risk_degradation_curve) |
        MBS_PACK(K_BARRIER_BLEND_SHIFT, cfg->barrier_blend_mode) |
        MBS_PACK(K_REGIME_CURR_SHIFT,   regime_state_current) |
        MBS_PACK(K_REGIME_PROP_SHIFT,   regime_state_proposed));
   ```
4. **Replace switch-on-enum predicates** with branchless mask-based predicates:
   - **Set membership** (e.g., "regime ∈ {RANGING, MILD_TREND}"): `MBS_IN_SET(resolved.k_state_word, K_REGIME_CURR_MASK, K_REGIME_CURR_SHIFT, (1 << REGIME_RANGING) | (1 << REGIME_MILD_TREND))`
   - **Equality**: `MBS_EQ(resolved.k_state_word, K_RISK_CURVE_MASK, K_RISK_CURVE_SHIFT, RISK_CURVE_LINEAR)`
   - **Get state for dispatch table lookup**: `MBS_GET(resolved.k_state_word, K_BARRIER_BLEND_MASK, K_BARRIER_BLEND_SHIFT)` returns 0-4 indexing dispatch table
5. **Audit callers** for the 6 fields:
   - `bandit_algorithm`: ~5 call sites (Bandit_Update, ConfidenceScorer dispatch, etc.)
   - `engine_arch`: ~3 sites (boot dispatch, slow-path init)
   - `risk_degradation_curve`: ~3 sites (risk_factor compute)
   - `barrier_blend_mode`: ~5 sites (TP/SL blend dispatch, per-horizon barriers)
   - `regime_state_*`: ~10+ sites (strategy dispatch, gates, etc.)
6. **Verify backtest byte-identical:**
   ```bash
   ./bin/foxml_suite --batch ...
   cmp paper_runs/backtest_run.bin baseline_k_state_pre.bin
   ```

## Key concerns / pitfalls

- **Bytewise determinism gate.** Switch-on-enum can dispatch DIFFERENTLY than mask-based set membership if branches have side effects. Audit each switch carefully — most are pure dispatch (no side effects) so the change is bytewise equivalent. **Specifically: if any switch case computes a value via FPN multiplication / accumulation, the mask-based equivalent MUST preserve the same arithmetic chain.**
- **The `multi-bit-state-encoding-pattern.md` design spec was codified 2026-05-13** (CLAUDE.md item 30, just-added). This is the FIRST application. Read the spec's "decision tree" + "implementation checklist" sections before coding.
- **Reserved bits (3 reserved in K_BARRIER_BLEND):** if barrier_blend_mode adds a 6th state later, fits without re-layout. Document this in `ResolvedCoreCfg.hpp` comments.
- **MBS_* macros location:** define in `MemHeaders/BitmapMacros.hpp` (sister of `BITMAP_*` already there per CLAUDE.md item 20). Add `MBS_PACK / MBS_GET / MBS_EQ / MBS_IN_SET / MBS_SELECT_EQ` per the design spec inference API.
- **Future extension:** if a 7th K-state field appears later, the cohort migration applies again. Promote the pattern to a CLAUDE.md cross-link after 2+ applications.
