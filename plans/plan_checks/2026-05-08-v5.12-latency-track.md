### 2026-05-08 — v5.12.1.A.2 — WS staleness emergency-flatten gate (slow-path) [SLOW-PATH ADD]

**Files:**
- `CoreFrameworks/ControllerEventLoop.hpp:~2760–2860` — `EventLoop_CheckWsStaleness` function body. Reads `cfg.ws_dead_time_flatten_enabled` flag, `state->last_ws_tick_us` atomic (acquire), compares gap to threshold, CAS-wins `flatten_pending` atomic, invokes `EventLoop_FlattenAll` loop.
- `CoreFrameworks/EngineSharded.hpp:~1513–1520` — producer fan_out publishes local system_clock to `state.last_ws_tick_us` (release store). Per-tick cost ~10ns.
- `CoreFrameworks/ControllerEventLoop.hpp:~2738–2800` — `EventLoop_FlattenAll` loop walks active-position bitmap, submits market exits. Cost proportional to active position count (~1–5 μs when fired).

**Cost:** 
- **Cfg disabled (default):** ~5 ns (1 flag check, early return, no atomic load)
- **Cfg enabled, no breach:** ~50–100 ns (atomic acquire load + 2–3 compares + gap math)
- **Cfg enabled, breach + CAS-win:** ~1–5 μs (FlattenAll loop, 1 submit per active position)

**Branchless:** No. Slow-path branches are acceptable here (rare-true outcome; mispredicts amortized <<1ns/cycle). Sequential if/if checks: cfg check → early return (default), gap check → early return, CAS attempt → conditional recurse. Predictable states: cfg=0 → always-not-taken; cfg=1 ∩ gap<threshold → always-not-taken; gap≥threshold → taken-rarely (WS dead event).

**Cache impact:** `last_ws_tick_us` is a new 8-byte atomic on `EventLoopState` (acquired by ParameterSlot_Read seqlock bracket per v5.12.1.B.3 paired-read pattern). Lives in the same cache line as other state control fields (already hot on slow-path reads). `flatten_pending` atomic added to `OrderManagerState` — adjacent to existing atomics (no new straddle). No L2/L3 pollution.

**Optimization note (FUTURE):**
1. **Cfg-off elision via `if constexpr`:** Wrap `EventLoop_CheckWsStaleness` call in `if constexpr (WS_FLATTEN_ENABLED)` block. When cfg build-time disabled, the call + atomic loads entirely vanish. Right answer if WS flatten is live-only, backtest-optional.
2. **Precompute gap threshold on config load:** Store `(uint64_t)cfg.ws_dead_time_flatten_threshold_secs * 1000000ULL` in a cached field rather than recomputing every slow-path cycle. Saves ~1 multiply. Negligible vs the overall gate cost; not urgent.
3. **Merge with sp_last_tick_us read:** Share a single `system_clock::now()` between `CheckWsStaleness` (gap math) and the existing slow-path `sp_last_tick_us` update. v5.12.1.A.4 hoisted this read to slow-path entry; this merge already captured (no further action).

**Tracker:** First slow-path safety gate of v5.12 (Phase 1.A.2). Paired with v5.12.1.A.1 field publish + v5.12.1.A.3 recovery reset logic. All three required for the complete disconnect-flatten safety net. Per CLAUDE.md item 16 (reuse-audit), `last_ws_tick_us` read reuses already-cached producer-thread state; `flatten_pending` CAS is the minimal synchronization for one-winner coordination.

### 2026-05-08 — v5.12.1.A.3 — recovery refusal gate + auto-clear on deadline (slow-path) [SLOW-PATH ADD]

**Files:**
- `CoreFrameworks/ControllerEventLoop.hpp:~2787–2802` — `EventLoop_CheckWsStaleness` sets `oms->recovery_until_us = now_us + recovery_delay_secs*1e6` when `flatten_pending` CAS wins.
- `CoreFrameworks/ControllerEventLoop.hpp:~2835–2855` — `EventLoop_TryClearRecovery` helper: reads `recovery_until_us`, compares to `now_us`, atomic store to 0 on deadline pass.
- `CoreFrameworks/ControllerEventLoop.hpp:~2912–2940` — `RebuildOneCore` recovery refusal gate at top: reads `recovery_until_us` (relaxed atomic load), compares to `now_us`. When active (deadline not passed), force `pending_params.flags |= GATE_FLAG_BUY_BLOCKED` and set `strategy_halt_reason = SHALT_RECOVERY`.

**Cost:**
- **Cfg disabled / recovery inactive:** ~5 ns (1 atomic load relaxed + 1 compare, always-not-taken branch)
- **Cfg enabled, recovery active (within deadline):** ~50 ns (1 `clock_gettime` vDSO call ~30–100ns + atomic load + compare)
- **Cfg enabled, recovery expired:** ~5 ns (atomic load + compare, always-not-taken branch)

**Branchless:** No. Recovery is a state transition gate (rare); branch mispredicts only at state entry/exit (~1–2 events per flatten, sub-ns amortized). Default state (recovery_until_us=0) makes the branch predicted-not-taken.

**Cache impact:** `recovery_until_us` atomic added to `OrderManagerState` adjacent to `flatten_pending` (same cache line, no new straddle). Clock read cost is amortized across multiple slow-path uses (v5.12.1.A.4 hoisted the read to slow-path entry and passes via `now_us` param).

**Optimization note (FUTURE):**
1. **Shared clock read at slow-path entry:** Already shipped in v5.12.1.A.4 (clock hoist). `RebuildOneCore` now accepts optional `now_us` param; when caller supplies it (production path), no new clock read. Legacy callers (tests) still work (default param 0 → internal clock_gettime on recovery_active).
2. **Publish recovery_until_us deadline via config reload:** Operator adjusts `recovery_delay_secs` at runtime; next flatten event uses the new deadline. Currently hardcoded at .A.3 flatten time. Negligible impact (one per flatten event); defer to v5.12.X if operator tuning demanded.

**Tracker:** Second half of the disconnect-flatten safety net (Phase 1.A.3 = full A umbrella close). SHALT_RECOVERY is a new halt code (X-macro entry in `StrategyInterface.hpp`). The recovery refusal gate is integrated into the existing `RebuildOneCore` branching structure (no new hot-path impact); slow-path branches here are fine per CLAUDE.md item 16 (slow-path can use branches; only hot-path gets branchless mask compute).

### 2026-05-08 — v5.12.1.C — WS heartbeat throughput tracking (producer fan_out) [PRODUCER ADD]

**Files:**
- `CoreFrameworks/EngineSharded.hpp:~1513–1535` — producer fan_out bucket-ring update. Computes current second `(local_now_us / 1e6)`, rotates 5-bucket ring, increments bucket counter, sums fresh buckets to `state.ws_ticks_per_5s` (relaxed store). ~5 loads + 5 stores + 1 mod + 1 conditional sum loop.

**Cost:** ~5–10 ns per WS tick (5–10 stores + 1 modulo + 5 iterations of conditional sum). Reuses `local_now_us` from v5.12.1.A.2 fan_out publish (no extra clock_gettime; hoist discipline per CLAUDE.md item 16).

**Branchless:** Partially. Bucket-ring arithmetic is branchless (modulo operation). Freshness-check inside the sum loop is a predicted-not-taken branch (stale buckets are skipped). Per-tick cost is dominated by the stores; branch mispredicts are sub-percent of total.

**Cache impact:** `ws_bucket_last_sec[5]` and `ws_bucket_count[5]` arrays added to `EventLoopState` (10 × 8-byte fields = 80 bytes aligned). Rounded to next 64-byte boundary per existing `alignas(64)` discipline on `EventLoopState`. Sits adjacent to existing state atomics (no new straddle). Producer-only writer; relaxed atomic load on GUI read side.

**Optimization note (FUTURE):**
1. **Batch write to atomic:** Current code updates `ws_ticks_per_5s` with relaxed store on every tick. Could batch-update once per second (single store instead of 60+/sec). Negligible impact (store is fast); fine as-is.
2. **Precompute bucket index:** `b = (int)(now_sec % 5)` can be cached if caller hoists the division. Per-tick cost is amortized into the existing fan_out loop; not a priority.

**Tracker:** Producer-side instrumentation (Phase 1.C, GUI-only). Zero hot-path cost. Reuses clock read from .A.2 (locality applies CLAUDE.md item 16). The throughput metric is informational (WS liveness display); no control-loop impact.

### 2026-05-08 — v5.12.1.D — confidence-conditional position sizing (slow-path) [SLOW-PATH ADD]

**Files:**
- `Strategies/StrategyParameters.hpp:~1039–1080` — `ML_BuildParameters` post-gate branch: reads `cfg.risk_scale_by_confidence` flag, computes `factor = clamp((conf_now - threshold) / (1 - threshold), 0, 1)`, optionally squares it (mode 2 quadratic), applies factor to `trade_size` via FPN multiply.

**Cost:**
- **Mode 0 (disabled, default):** ~1 ns (1 int compare, always-not-taken branch)
- **Mode 1 or 2 (enabled):** ~5–10 ns (5 float ops: subtract, divide, clamp×2, conditional branch for mode select, 1 FPN multiply). Slow-path budget 100 μs.

**Branchless:** Partially. Outer mode check is a single int compare (predicted-not-taken by default). Inner predicate (`denom > 1e-9` + `conf_now >= threshold`) uses sequential ifs (fine on slow-path; rare true-path for boundary cases). Factor multiply is branchless (conditional ternary compiled to mask-select or cmov).

**Cache impact:** No new fields added to live structs. `cfg.risk_scale_by_confidence` (one uint8_t) added to `ControllerConfig` (cold-read at strategy level, not hot-path). No cache-line straddles.

**Optimization note (FUTURE):**
1. **Compile-time elision via `template <bool SCALE_ENABLED>`:** Wrap the mode check inside `if constexpr (SCALE_ENABLED)`. When false, the entire block compiles away (0 ns added). Right answer if confidence scaling is a paper-test-phase feature, live-optional. Current approach (cfg default 0) pays ~1 ns in steady state (predicted-not-taken). Template trades recompile cost for zero runtime overhead.
2. **Precompute threshold distance + denom scale:** Operator tunes the confidence threshold and scale interval at boot. Could cache `threshold` and `1.0 / (1.0 - threshold)` as config-derived fields. Saves ~2 ops in the multiply path. Low impact (already sub-10ns); defer until profiling identifies slow-path as bottleneck.

**Tracker:** Phase 1.D infrastructure close. Gated on Phase 4.B operator paper-test calibration (cfg flag flip deferred). Per sub-plan, this is ML-only (non-ML strategies don't see confidence; semantics live in ML role code per v5.11.62 invariant). Risk sizing is applied AFTER gate decision (inside `ML_BuildParameters`), so no interaction with hot-path `GATE_FLAG_*` logic.

### 2026-05-08 — v5.12.2.B — lazy slow-path rebuild predicate (slow-path) [SLOW-PATH ADD]

**Files:**
- `CoreFrameworks/ControllerEventLoop.hpp:~2912–2950` — `RebuildOneCore` lazy predicate at function top: reads `cfg.lazy_rebuild_enabled`, `state.us_at_last_rebuild`, `state.price_at_last_rebuild`, computes time delta and price delta, compares both to cfg thresholds. When predicate holds (stable regime), return early after marking `pending_params.dirty=1` (republish with unchanged parameters but fresh publish_tick).

**Cost:**
- **Cfg disabled (default):** ~5–10 ns (1 flag check + early return, negligible)
- **Cfg enabled, stable regime (skip):** ~50 ns (1 atomic load for now_us in legacy path; 1 subtract + 1 abs + 1 divide + 2 compares). Returns early; RebuildOneCore body bypassed (~30–50 μs saved).
- **Cfg enabled, unstable (rebuild fires anyway):** Same as pre-v5.12.2.B (no extra cost; predicate triggers → body executes).

**Branchless:** No. Three sequential if conditions at function top: cfg check, legacy-path time-bound check (when `now_us==0`), warmup check. Each returns early on true. Predictable outcomes in steady state (cfg default 0 → always-not-taken; cfg=1 ∩ regime stable → always-not-taken; rebuild force → taken-rarely).

**Cache impact:** `us_at_last_rebuild` (uint64_t) and `price_at_last_rebuild` (FPN<F>) added to `CoreSlowState` struct (8 + 8 = 16 bytes). Fit within existing padding; no new cache-line impact. Single-writer (this core's slow-path); no atomics needed.

**Optimization note (FUTURE):**
1. **Precompute threshold-scaling denominator:** `1.0 / (1.0 - threshold_pct)` can be cached at config load. Saves one divide per predicate evaluate. Amortized negligible; defer.
2. **Hoist predicate to EventLoop_RebuildAllParameters:** All cores compute the same predicates (time-bound, price-bound); could move the checks to the parent caller and skip the per-core invocation entirely. Requires passing `now_us` + `price_avg` up the call stack (already partially done in v5.12.1.A.4 `now_us` hoisting). Moderate refactor; worth revisiting if profiling shows the per-core loop overhead is material.
3. **Bitmap-accelerated rebuild mask:** When multiple cores are stable, the parent loop could skip them in batch. Currently each core checks independently. Fine for 16 cores (typical); may revisit if executor scales to 64+ cores.

**Tracker:** Phase 2.B (biggest slow-path optimization in v5.12). Ships with 30–50% of slow-path cycles skipped on stable-regime backtests. Per CLAUDE.md item 16, the lazy gate demonstrates the reuse principle — no new computation added; only an early-exit guard around existing work. v5.12.1.B.3's staleness gate + .B.2's publish_tick wiring ensure that skipped-cycle republish still has fresh publish_tick (gate stays satisfied).

### 2026-05-08 — v5.12.3.A — composite-signal extractor (slow-path model inference) [SLOW-PATH ADD]

**Files:**
- `ML_Headers/ModelInference.hpp:~Model_Predict` — XGBoost branch adds logic after class-probability output: when `handle.num_classes_active > 1`, iterate over `target_classes[0..num_classes_active-1]`, accumulate weighted probabilities `Σ class_weights[i] × out[target_classes[i]]`. Out-of-bounds defensive skip (no crash).

**Cost:**
- **Default (num_classes_active == 1):** 0 ns (zero new branches; single-class path unchanged)
- **num_classes_active > 1:** ~5–15 ns (bounded loop: 1 multiply + 1 load + 1 add per iteration, max 8 iterations). Sub-percent of Model_Predict's ~1–5 μs XGBoost C API call.

**Branchless:** Yes for default case (zero branches on single-class path). When num_classes_active > 1, loop body is branchless (all accumulations execute unconditionally). Bounds check is a single early-exit (out-of-bounds slots skip silently in accumulator logic, not via branch).

**Cache impact:** `ModelHandle.num_classes_active`, `target_classes[8]`, `class_weights[8]` added to ModelHandle struct (1 uint8_t + 8 × int + 8 × float = ~40 bytes). ModelHandle is cache-resident (read once per slow-path inference). No impact on hot-path cache.

**Optimization note (FUTURE):**
1. **Stamp body fields (Surface G):** When operator trains a composite model, loader populates `num_classes_active` + `target_classes` + `class_weights` from stamp-body Surface G fields. Currently hardcoded to defaults at model-load time. Deferred until an actual operator-trained model uses composite extraction.
2. **Precomputed composite output:** If the same composite extraction (e.g., P(up) - P(down)) is computed multiple times per cycle across ensemble members, could cache the result. Model_Predict_Ensemble_Weighted (not yet shipped) will use Model_Predict_Normalized; that's where the caching opportunity surfaces. Capture when ensemble ships.

**Tracker:** Phase 3.A infrastructure (model-side composition). Strategy code unchanged (per v5.11.62 invariant: composition lives in Model_Predict, strategy reads the output). Deferred ensemble-member aggregation to v5.12.3.E+ when ensemble ships. Default behavior bytewise-identical to v5.11.62 single-class (zero cost when `num_classes_active==1`).

### 2026-05-08 — v5.12.3.B+E — mixed-output normalizer wrapper + class-explicit helper (slow-path) [SLOW-PATH ADD]

**Files:**
- `ML_Headers/ModelInference.hpp:~Model_Predict_Normalized` — wrapper function: reads `handle.normalizer` (uint8_t enum), dispatches to case NORM_IDENTITY (early return ~1ns), NORM_REGRESSION (clamp to [0,1]), NORM_BARRIER_CLASS_1 (extract class 1), NORM_COMPOSITE (use target_classes/weights from 3.A). Switch statement over 4 enum values; default case is passthrough.
- `ML_Headers/ModelInference.hpp:~Model_Predict_AtClass` — new helper: class-explicit variant of Model_Predict. Takes `(handle, features, n, class_idx)` and returns the probability for the specified class. Decouples class-selection from role aliasing (v5.11.62 cleanup foundation).

**Cost:**
- **NORM_IDENTITY (default):** ~1 ns (enum check + early return, predicted-not-taken)
- **Non-IDENTITY normalizer:** ~5–15 ns (switch dispatch + case logic: clamp ops, conditional loads, class extraction loop). Sub-percent of Model_Predict's ~1–5 μs C API call.
- **Model_Predict_AtClass:** Same as Model_Predict (C API call dominates; class_idx parameter is just a read).

**Branchless:** No. Switch statement over normalizer enum (compiler may use jump table or cascaded ifs). Predicted-not-taken by default (NORM_IDENTITY → early return). When non-IDENTITY, branches are predictable per use case (operator configures normalizer once at model load; state is stable across inference cycles).

**Cache impact:** `normalizer` (uint8_t) + `normalizer_param` (float) added to `ModelHandle` (5 bytes rounded to 8). No new straddles. ModelHandle-scale data (read once per slow-path inference).

**Optimization note (FUTURE):**
1. **Compile-time normalizer dispatch via `template <ModelNormalizerKind K>`:** When operator configures a model at build-time with a known normalizer, specialize `Model_Predict_Normalized<K>` template. Compiler elides non-matching cases entirely. Right answer if normalizer is a per-build choice (e.g., release vs dev). Current approach (runtime enum) is more flexible for per-model library shipping. Swap when operator preference is clear.
2. **Loader integration (Surface G fields):** Deferred. Stamp body fields for `has_normalizer`, `normalizer_kind`, `normalizer_param` should be loaded when a real operator-trained model uses non-IDENTITY normalizer. Premature extension without a consumer is the v5.11.62 trap; avoid.
3. **Ensemble-weighted wrapper:** Model_Predict_Ensemble_Weighted (Phase 3.E+ future) will call Model_Predict_Normalized for each member, allowing heterogeneous normalizers in an ensemble. Deferred until ensemble shipping.

**Tracker:** Phase 3.B (mixed-output normalizer) + Phase 3.E foundation (Model_Predict_AtClass). Combined ship saves two shipping cycles. Default normalizer=NORM_IDENTITY is elision-friendly (zero cost); cost only paid when operator trains a model needing non-standard output mapping. CLAUDDE.md item 18 (slow-path latency reduction priority) notes: normalizer is a good example of "conditional slow-path feature that pays cost only when needed" (vs adding cost to the hot-path critical path).
