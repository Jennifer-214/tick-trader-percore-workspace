### EnsembleModelZoo size%64 — exact sizing required (plan acknowledges; need numeric verification at Step 0.A)

**Severity:** **MEDIUM** (compile-time `static_assert` catches violation; no silent breakage)

**Site:** `ML_Headers/CoreModelZoo.hpp:1075-1078` — existing `static_assert(sizeof(EnsembleModelZoo<64>) % 64 == 0)`

**Sizing calculation:**
- `sizeof(ThompsonBanditState)` = 8 × 8B (mu_post) + 8 × 8B (precision_post) + 8 × 4B (total_pulls) + 4B (n_arms) + 4B (_padding) + 8B (mu_prior) + 8B (precision_prior) + 8B (precision_obs) + 8B (rng_state) = **192 bytes** (3 cache lines exactly)
- `NUM_REGIMES` × 192 = (typically 5) × 192 = **960 bytes** added
- 960 / 64 = 15 → mod-64 = 0 ✓

**Plan adds:** `alignas(64) ThompsonBanditState thompson_exit_bandits[NUM_REGIMES]` + `int last_predicted_exit_thompson_arm`

The `int` member is 4B; it sits next to existing `int last_predicted_thompson_arm` (line 984 area). Layout impact: need 4B-padding mate (or another `int`) to keep alignment intact. Plan's "If size%64 not preserved, add explicit `_padding<N>` member" is correct but vague.

**Fix path:** Step 0.A.b sizing verification MUST emit the EXACT byte count post-add + state the explicit padding (e.g., `int32_t _padding_thompson_exit = 0;` paired with `last_predicted_exit_thompson_arm`). Plan should not leave this as "verify at coding time" — pre-coding sizing math + explicit padding declaration belongs in the plan body.

**Status:** OPEN (annotate plan with exact byte count + padding member before Step 0)

### Calib log caller-scope contract — `core_cfg` not in current `OrderManager_HandleFill` scope

**Severity:** **MEDIUM** (compile error at expansion site; not a silent parity issue but a build-blocker for Step 6 / § M)

**Site:** Plan § M extends `FOREACH_CALIB_LOG_COL` with `core_cfg`, `ezoo`, `regime`, `chosen_arm`, `reward_bps`, `active_state`, `exp3_probs[]` variables. The macro is consumed in `OrderManager_HandleFill` SELL handler.

Per `CalibLogColRegistry.hpp:19-24` "caller scope contract":
> Row-write expansion expects these variables in scope (matches OrderManager_HandleFill calibration log body at OrderManager.hpp:991-1019 BEFORE this refactor): `uint64_t ts_us, int pslot, uint8_t pred_flag, double pred_p, double entry_d_calib, double exit_d_calib, double gain_pct, double pnl_bps, OrderManagerState<F>* oms`

Plan's new columns reference `core_cfg`, `ezoo`, `regime`, `chosen_arm`, `reward_bps`, `active_state`. **These are NOT in the current HandleFill scope at lines 991-1019.** The plan's Pattern 5 sink-fn `real_calib_emit` takes them as parameters (§ F: `int regime, int chosen_arm, double reward_bps, int active_state`), which is fine — but the new `FOREACH_CALIB_LOG_COL` expansion happens INSIDE `real_calib_emit`'s body, not at the HandleFill site. The caller-scope contract docstring at the top of `CalibLogColRegistry.hpp` becomes wrong for this expansion site.

**Decision required:**
- (A) Plan body documents that `FOREACH_CALIB_LOG_COL` is now consumed in TWO places: legacy `OrderManager.hpp:991-1019` (only the original 9 cols) + new `real_calib_emit` (all 31 cols). The single registry must work in both scopes.
- (B) Split the registry: `FOREACH_CALIB_LOG_COL_LEGACY` (9 cols at HandleFill) + `FOREACH_CALIB_LOG_COL_BANDIT_EXTENSION` (22 cols at real_calib_emit only). Composed at header-emit time.
- (C) Refactor `OrderManager_HandleFill` SELL handler to call `ezoo->on_trade_close_calib_emit(...)` instead of inlining the old fprintf; the macro is consumed at the sink-fn body only.

**Recommendation:** (C). The plan's Pattern 5 sink-fn-pointer architecture IMPLIES this — the old inline calib log path becomes a `noop_calib_emit` site replaced by the fn-pointer indirect call. Plan body needs to explicitly say "OrderManager.hpp:991-1019 OLD calib log fprintf BLOCK is DELETED + replaced by `ezoo->on_trade_close_calib_emit(...)` call". Currently the plan implies this but doesn't make it explicit.

**Byte-preservation impact:** legacy 9-column shape MUST stay valid for the case `cfg.bandit_algorithm == 0 AND calibration_log_file == nullptr`. Plan's `noop_calib_emit` emits NOTHING — same shape as today (no row emitted; file stays empty). But for `cfg.bandit_algorithm == 0 AND calibration_log_file != nullptr`, `real_calib_emit` emits ALL 31 columns including bandit fields that will be all-zero (per-arm Thompson posteriors at prior values). This is the documented "emit-always-when-enabled" directive — operator parsers reading 9-column shape break. **Plan needs to explicitly state: existing operator parsers (downstream of `calibration_log_file`) MUST be updated to parse 31 columns OR ignore extra cols.**

**Fix path:** Plan body amendment in § M + § F:
1. Document the OrderManager.hpp:991-1019 deletion (~30 LOC removed)
2. Document the caller-scope contract migration in `CalibLogColRegistry.hpp` doc block
3. Add downstream parser advisory to FEATURE_LOOKUP entry
