### [SISTER-COHORT B11-adjacent] [HIGH] Phase A scope enumeration may miss non-conventional iterator names + lambda/template/macro per-core contexts

**Surface:** Plan Step A.2 regex `'for\s*\(\s*int\s+(slot|c|core_id|i)\s*=\s*0'` whitelists 4 symbols. Step A.2 fn-parameter regex `'inline.*\((.*)(core_id|slot|c)\)'` whitelists 3.

**Gap shapes:**
1. **Lambda-captured per-core context** — `[core_id](){ ... cfg.fee_rate_taker ... }` inside slow-path body. Grep finds the lambda decl line but body-scope detection is single-pass — may miss reads inside multi-line lambda bodies if the enclosing fn signature doesn't match the parameter regex. Worked sister: see `.B.6` Phase B.2 `fan_out` lambda hoist (Class 35 + B18 pillar).
2. **Template instantiation** — per-core template fn `template<int N> ... cfg.X` where N is core_id at compile time. Phase A grep won't catch the template body if expansion happens via X-macro registry. Sister surface: `FOREACH_PER_CORE_CFG_FIELD` walker bodies.
3. **Macro expansion** — per-core macros like `BG_EVALUATE_CORE(N)` expanding to cfg reads. Phase A textual grep misses macro-body reads.
4. **Non-conventional iterator names** — for-loops using `idx` / `pos` / `n` / `k` / `core` (no `_id`) / `worker` / `dispatcher_idx` etc. Plan whitelist `{c, core, core_id, slot, i}` excludes all of these. The whitelist is also INCONSISTENT — fn-param regex omits `i` while for-loop regex includes it.

**Suggested action:**
- Phase A.2 broaden fn-parameter regex to `(core_id|core|slot|c|i|idx|pos|n|k|worker)` PLUS member-fn `this->core_id` access
- Phase A.2 add lambda body extraction: for each `[capture-list]...{ body }` capturing per-core symbol, scan body for unindexed cfg reads
- Phase A.2 add macro body extraction: for `FOREACH_PER_CORE_*` X-macro and any `*_PER_CORE(*)` macros, scan expansion bodies
- Phase A.4 add NEW classification category "TEMPLATE-INSTANTIATION-PARAM" + "MACRO-EXPANSION-BODY" + "LAMBDA-CAPTURE-BODY" so each is explicitly triaged
- Lock fn-param regex whitelist + for-loop regex whitelist to SAME 6-symbol union (consistency)

**Cross-ref:** operator brief point 7 (Phase A cohort enumeration completeness gap); `feedback_enumerate_consumers_before_registry_row_deletion` (consumer-side analog); sister to M6 body-content enumeration
