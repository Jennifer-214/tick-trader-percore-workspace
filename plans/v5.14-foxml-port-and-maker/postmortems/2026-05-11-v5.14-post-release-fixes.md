## v5.14.post1 — `train_model_worker_fn` stamp body migration gap

**Tag:** `v5.14.post1` (engine HEAD post-fix)
**Date:** 2026-05-11
**Discovery:** Caramel's `./build.sh gui suite` run flagged 12 compilation errors in `Backtest/BacktestPanels.hpp:3208-3257`. Build had passed `./build.sh test` previously (the test target compiles `controller_test` + `engine` but NOT `foxml_suite`, which is where `BacktestPanels.hpp` is consumed).

**Root cause:** Missed migration site from v5.14.8.A.merged Option 1 unification. The v5.14.8.A.6 "~14 caller files mechanical find/replace" sweep missed `BacktestPanels.hpp:train_model_worker_fn` — that function was still using pre-merge `StampInferenceCfgInputs` field names (`has_inference_cfg`, `confidence_threshold_scale`, `held_out_fraction`, `scaler_sha256_hex`, etc.) when the canonical post-merge names had moved to `inference_cfg_*` prefix + bit-packed `has_flags` via `STAMP_SET()` macro.

**Why it stayed hidden through v5.14.9/.10/.11:** The intervening 3 sprints all built `./build.sh test` for verification (2904 tests pass). None ran `./build.sh gui suite` as part of sprint-close audits. The migrated struct's NEW shape compiled fine in the test binary (no consumers there); BacktestPanels.hpp wasn't compiled until `foxml_suite` link, which requires the `gui` or `suite` build targets.

**Fix:** Mirror `Backtest/BacktestEngine.hpp:1147-1220` (`Backtest_RunFullValidation` — the sibling that WAS properly migrated). 11 `has_*` direct field writes → `STAMP_SET()` macro calls; 4 cfg fields prefixed with `inference_cfg_`; 1 field renamed (`has_num_outputs` → `STAMP_SET(model_num_outputs)`); scaler sha256 binding refactored from char* assignment to `memcpy` + null-terminate on char[65].

**Verification:**
- `./build.sh gui suite` → both `engine_gui` + `foxml_suite` link cleanly
- `./build.sh test` → 2904/2904 tests pass
- `./build.sh tsan asan all` → all clean
- No HMAC chain concern (field rename in C struct doesn't change canonical body emit string; wire format byte-equivalence at the stamp body TEXT level is preserved)

**Surface inventory after fix (wider sweep):**
- `Backtest/BacktestEngine.hpp:1152` — `Backtest_RunFullValidation`. Already migrated (canonical reference).
- `Backtest/BacktestPanels.hpp:3211` — `train_model_worker_fn`. **Now migrated.**
- No other production callers found via grep across the repo.
- Test usage of direct `inf.has_*` writes was searched and found CLEAN (tests use `STAMP_SET` / `STAMP_HAS`).

**False-positive ruleouts:**
- `tt::FeatureStandardizer sc.has_scaler = 1;` in tests → different struct (FeatureStandardizer; field is direct uint8_t by design); not a migration site.
- `ModelHandle h.has_training_poll_interval = 1;` in tests → ModelHandle has direct `uint8_t has_*` fields by design pending **TECH_DEBT-014** (ModelHandle X-macro migration; deferred). Not a current-day issue.

## Going-forward learnings (no formal TECH_DEBT entry needed; codify directly if/when next mechanical migration happens)

1. **Sprint-close audits should include `./build.sh gui suite tsan asan all`**, not just `./build.sh test`. The gui/suite targets compile a wider set of consumer headers (BacktestPanels.hpp, GUI panels, training UI) that test targets skip. v5.14.8.A.6's mechanical migration sweep would have caught this site at first attempt if the verification step had been the wider build. **Action:** for future X-macro-driven struct migrations, the verification anchor is `./build.sh gui suite tsan asan all`, not `test`.

2. **Mechanical find/replace sweeps need a per-site verification list, not just "rebuild and see if test passes".** The v5.14.8.A.6 sprint noted "~14 caller files migrated mechanical find/replace" but the verification was implicit. A future "migration sweep" sub-ship should enumerate sites explicitly (grep -l, save list, tick each off as migrated), then verify with the wider build.

3. **Class 18 mirror-prevention via registry IS working as designed.** This bug was NOT a structural failure; the FOREACH_STAMP_BOUND_MODEL_CONST + STAMP_CFG_AUTOPOPULATE patterns extinguished the FIELD-ADDITION class. What recurred was the MIGRATION class — a one-time mechanical sweep gap. The structural fix did its job; the mechanical sweep's verification didn't. Distinct concerns.
