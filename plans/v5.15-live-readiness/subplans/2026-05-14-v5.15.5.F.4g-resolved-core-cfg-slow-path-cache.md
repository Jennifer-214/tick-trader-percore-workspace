```cpp
#pragma once
#include "../FixedPoint/FixedPointN.hpp"
#include "../CoreFrameworks/CfgFieldRegistry.hpp"

template <unsigned F>
struct alignas(64) ResolvedCoreCfg {
    // ============================================================
    // CACHE LINE 0 (HOT — read every slow-path cycle) — 64 bytes
    // ============================================================
    FPN<F>   ml_buy_threshold;            // 24 bytes (FPN<64> = 24B)
    FPN<F>   ml_tp_pct;                   // 24 bytes

    uint8_t  gate_cfg_flags_resolved;     // 1 byte

    uint8_t  risk_cfg_flags_resolved;     // 1 byte
    uint8_t  ops_cfg_flags_resolved;      // 1 byte
    uint16_t k_state_word;                // 2 bytes (.F.4f populates; placeholder = 0 here)
    uint8_t  _pad_line0[8];               // pad to 64B

    // ============================================================
    // CACHE LINE 1 (WARM — read most cycles) — 64 bytes
    // ============================================================
    FPN<F>   confidence_freshness_tau_secs;       // 24
    FPN<F>   confidence_hard_block_threshold;     // 24
    FPN<F>   bandit_blend_ratio;                  // 24 — oops, exceeds 64
    // ^^^^^^^ TODO: re-layout if 3× FPN<64> = 72 bytes exceeds line 1 budget.
    //         Either move bandit_blend_ratio to line 2, or split into uint16_t storage.
    uint8_t  _pad_line1[N];               // adjust per actual layout

    // ============================================================
    // CACHE LINE 2 (COLD — rare paths) — 64 bytes
    // ============================================================
    FPN<F>   ridge_lambda;
    FPN<F>   ridge_cost_penalty;
    FPN<F>   ridge_min_ic_floor;
    uint8_t  _pad_line2[N];               // pad to 64B

    static_assert(sizeof(ResolvedCoreCfg<F>) == 192,
                  "ResolvedCoreCfg<F> must be exactly 3 cache lines (192B) "
                  "for AVX-512 batch-load future-work (per CLAUDE.md item 25). "
                  "Adjust field layout if violated.");
};
```

**Critical: FPN<64> is 24 bytes (not 8 like double).** Per CLAUDE.local.md hot-path discipline doc. 3× FPN<64> = 72 bytes per cache line; line 1 (WARM) needs careful layout to fit 2 FPNs + scalars + padding within 64B.

## Step 2 — AUTOPOPULATE resolved struct fields (~50 LOC)

Per `DESIGN_SPECS/slow-path-cfg-resolution-cache-pattern.md` § "Resolution body":

```cpp
// CoreFrameworks/ResolvedCoreCfg.hpp

// Token-paste dispatch on per-core override metadata:
#define RESOLVE_VAL_PER_CORE_OK(name, cfg, core_idx) \
    ((cfg)->core_##name##_override_set[core_idx] ? (cfg)->core_##name[core_idx] : (cfg)->name)

#define RESOLVE_VAL_NONE(name, cfg, core_idx) (cfg)->name

// Y3 dispatch: which resolution path to use based on metadata bit
#define RESOLVE_DISPATCH_HAS_PER_CORE(name, cfg, core_idx)  RESOLVE_VAL_PER_CORE_OK(name, cfg, core_idx)
#define RESOLVE_DISPATCH_NO_PER_CORE(name, cfg, core_idx)   RESOLVE_VAL_NONE(name, cfg, core_idx)

// Per-Kind population:
#define RESOLVE_CFG_LINE_KIND_DOUBLE(name, meta, cfg, core_idx, resolved) \
    (resolved)->name = FPN_FromDouble(RESOLVE_DISPATCH_##meta(name, cfg, core_idx));

#define RESOLVE_CFG_LINE_KIND_INT(name, meta, cfg, core_idx, resolved) \
    (resolved)->name = RESOLVE_DISPATCH_##meta(name, cfg, core_idx);

// ... etc per Kind ...

template <unsigned F>
inline void ResolveCoreCfg(const Cfg* cfg, int core_idx, ResolvedCoreCfg<F>* resolved) {
    #define X_RESOLVE(kind, name, label, section, meta, payload, tooltip, \
                       strat, op_mode, regime, risk, requires_cfg, lives_in) \
        /* Only resolve fields tagged for slow-path consumption — skip boot-only / monitoring */ \
        if constexpr (!((meta) & IS_BOOT_ONLY) && !((meta) & HIDDEN_BY_DEFAULT)) { \
            RESOLVE_CFG_LINE_KIND_##kind(name, meta, cfg, core_idx, resolved); \
        }
    FOREACH_CFG_FIELD(X_RESOLVE)
    #undef X_RESOLVE

    // Resolve bitmap flags via existing accessors:
    resolved->ml_cfg_flags_resolved       = Cfg_GetEffective_ml_cfg_flags(cfg, core_idx);
    resolved->gate_cfg_flags_resolved     = Cfg_GetEffective_gate_cfg_flags(cfg, core_idx);
    resolved->lifecycle_cfg_flags_resolved = Cfg_GetEffective_lifecycle_cfg_flags(cfg, core_idx);
    resolved->risk_cfg_flags_resolved     = Cfg_GetEffective_risk_cfg_flags(cfg, core_idx);
    resolved->ops_cfg_flags_resolved      = Cfg_GetEffective_ops_cfg_flags(cfg, core_idx);

    // k_state_word populated by .F.4f (placeholder = 0 here):
    resolved->k_state_word = 0;
}
```

**Branchy override per CLAUDE.md item 28:** `core_<name>_override_set[i]` is boot-set, never changes mid-session. Branch predictor learns it in first ~5 cycles; mispredict rate <1% steady-state. Branchy wins by ~1 cycle per resolve × 60 fields = ~20 ns per slow-path entry vs branchless mask-select.

HOT_PATH_CHANGELOG entry template:
```markdown
## v5.15.5.F.4e — ResolvedCoreCfg slow-path resolution cache

**Change:** introduced `ResolvedCoreCfg<F>` struct (3 cache lines, 192 bytes, HOT-first ordered).
`EventLoop_RebuildOneCore` resolves all needed cfg fields ONCE at slow-path entry instead of
~60 scattered `cfg->X` reads throughout the body.

**Cost (per slow-path entry per core):**
- Resolution body: ~60 cycles (~20 ns at 3 GHz)
- Per-core override branchy resolution: 60 branches × 1-2 cycles predicted = 60-120 cycles total (~20-40 ns)

**Savings (per slow-path entry per core):**
- Avoids 12-18 scattered cache line reads (cold path): 12-18 × 100 ns = 1.2-1.8 μs
- Avoids 12-18 scattered cache line reads (warm path): 12-18 × 4 ns = 48-72 ns
- Per-read override branch (60 fields × ~3 cycles) consolidated to 60 branches at resolve time = same total but cache-warm

**Net win: 10-30x** on cold path; ~2-3x on warm path. Slow-path p99 unchanged or improved.

**Cache impact:** ResolvedCoreCfg is per-thread local (slow-path thread); no cross-core contention. Adds 192 bytes per core × 16 cores = 3072 bytes total slow-path state. <1% of L1 budget per core.

**Future optimization paths** (see TECH_DEBT entries):
1. `__builtin_prefetch(&cfg->per_core_overrides[core_idx])` at slow-path entry (hides L2→L1 latency)
2. AVX-512 batch-load of ResolvedCoreCfg (3 × 64-byte cache lines = 3 uops vs ~24 scalar loads)
3. Epoch-compare delta-cache (skip resolution if cfg + override bits unchanged since last cycle)
4. K-state cohort multi-bit pack (`.F.4f`) — packs 6 enum fields into uint16_t (~22B saved per core)
```

## Anti-patterns to avoid

- **Don't touch hot path.** ResolvedCoreCfg is SLOW PATH ONLY. Hot path reads from `ExecutionCore::params` (already cached + published via seqlock). Verify no hot-path call inadvertently references `ResolvedCoreCfg`.
- **Don't introduce float in slow-path math.** Hot-path discipline requires FPN<F> for all math. ResolvedCoreCfg has FPN fields (converted once at resolution); slow-path body reads FPN.
- **Don't malloc anywhere in ResolveCoreCfg.** Stack-allocated `ResolvedCoreCfg<F> resolved;` only. No heap. Per coding rules.
- **Don't skip backtest determinism gate.** If divergence appears, investigate root cause before "fixing." A bug in the resolution body is silently corrupting runtime behavior; the byte diff IS the symptom.
- **Don't add prefetch as part of this ship.** Prefetch is a future optimization (logged in HOT_PATH_CHANGELOG + TECH_DEBT). Adding here = more complexity for the migration; defer to follow-on ship.
- **Don't reorder ResolvedCoreCfg fields after initial layout.** Cache-line locality is engineered; reordering = different cache behavior. If layout needs adjustment, profile first + document the reason.

## If something goes wrong

- **Backtest determinism breaks (cmp shows divergence):**
  1. Reproduce with single-symbol backtest (smaller diff to bisect)
  2. Add print statements to compare resolved->X vs cfg->X at first divergence point
  3. Common: FPN_FromDouble path mismatch. Verify resolution converts in registry order + matches manual conversion order.
  4. If can't identify root cause within 1 hour: rollback + investigate offline.
- **Slow-path p99 latency regresses by >10%:**
  1. perf record on slow-path; check for unexpected cache misses
  2. Verify ResolvedCoreCfg is aligned (alignas(64) holds; sizeof == 192)
  3. Check for resolved->X reads in code that should still use cfg->X (boot-only fields shouldn't be resolved)
- **tsan reports race:** ResolveCoreCfg writes to a per-thread local resolved struct; if tsan complains, look for accidental shared state (e.g., shared resolved buffer across cores). Each core's slow-path has its OWN resolved instance.
- **Downstream API update misses a consumer:** compile error reveals missing site. Update each occurrence; verify it reads only from resolved (not from cfg).
- **sizeof(ResolvedCoreCfg<F>) != 192:** layout exceeded 3 cache lines. Run `pahole`; identify which field pushed it over; either shrink or move to next line; iterate until 192.
- **Rollback:** `git reset --hard pre-v5.15.5.F.4e` (anchor at Step 0). Critical — slow-path code is load-bearing.
