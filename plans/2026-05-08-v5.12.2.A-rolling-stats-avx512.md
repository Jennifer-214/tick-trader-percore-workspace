## Phase A — `FPN_MagAddN<F=64>` AVX-512 (`v5.12.2.A.1`)

**Goal:** Vectorize the 64-word carry chain in `FPN_MagAddN`. Current
scalar implementation at `FixedPoint/FixedPointN.hpp:85` does carry
in a serial loop:

```cpp
template <unsigned F> inline void FPN_MagAddN(const uint64_t *a,
                                              const uint64_t *b,
                                              uint64_t *r) {
    uint64_t carry = 0;
    for (unsigned i = 0; i < F; ++i) {
        uint64_t sum = a[i] + b[i];
        uint64_t c1 = (sum < a[i]) ? 1 : 0;
        sum += carry;
        uint64_t c2 = (sum < carry) ? 1 : 0;
        r[i] = sum;
        carry = c1 | c2;
    }
}
```

**AVX-512 approach:** process 8 uint64 words at a time via `__m512i`.
Carry detection via `_mm512_cmplt_epu64_mask`. 8 cross-lane carry
propagations per outer iteration; 64-word total = 8 outer iterations.

```cpp
// FixedPoint/FixedPointN.hpp adjacent to scalar at :85
#if defined(__AVX512F__)
template <>
inline void FPN_MagAddN<64>(const uint64_t *a, const uint64_t *b,
                            uint64_t *r) {
    uint64_t carry = 0;
    for (int blk = 0; blk < 8; ++blk) {
        __m512i va = _mm512_loadu_si512((const __m512i*)(a + blk*8));
        __m512i vb = _mm512_loadu_si512((const __m512i*)(b + blk*8));
        __m512i vsum = _mm512_add_epi64(va, vb);
        __mmask8 c1 = _mm512_cmplt_epu64_mask(vsum, va);  // carry-out from a+b
        // ... add `carry` (from previous block) into lane 0; propagate
        //     carries within block via shift-and-add until stable
        // ... compute final block carry-out for next iteration
        _mm512_storeu_si512((__m512i*)(r + blk*8), vsum);
    }
}
#endif
```

**Bytewise determinism gate:** AVX-512 path must produce IDENTICAL
output to scalar path across boundary inputs:
- 0 + 0 → 0
- max + 1 → carry to next word
- (2^64-1) × 8 lanes + 1 → cascade through block boundary
- (2^64-1) × 64 → overflow at most-significant word

Test in `tests/parity_harness.cpp` with paired scalar/AVX-512 calls
on N random + boundary inputs; bytewise-equal required.

**Fallback:** when `__AVX512F__` not defined (build flag missing,
non-AVX-512 CPU), the scalar path stays. Boot-time CPU feature
detection via `__builtin_cpu_supports("avx512f")` selects path
explicitly. Logged once via `Health_Log(INFO)` at engine start.

**Tests** (+5):
1. Bytewise scalar-vs-AVX-512 equality on 1000 random pairs
2. Carry-chain correctness at 2^64-1 boundaries
3. Block-boundary carry propagation (lane 7 → lane 0 of next block)
4. AVX-512 path gracefully falls back when CPU lacks support
5. Boot-time logged decision visible in `Health_Log(INFO)`

**Sub-ship gate:** Tag `v5.12.2.A.1`.

## Phase C — Lemire divmod for `FPN_DivNoAssert` residuals (`v5.12.2.A.3`)

**Goal:** Apply Lemire divmod (multiply-by-reciprocal, multiword) to
the 1-2 sites/cycle remaining post-v5.11.2.A's reciprocal LUT.
~30-50% faster division on those sites.

**Sites identified:**
- `Strategies/RegimeDetector.hpp` `Regime_ComputeSignals` — R²
  computation requires variance/total_variance ratio
- `LinearRegression3X_Fit` — slope normalization

**Step 0:** Implement `FPN_DivNoAssert_Lemire<F>` adjacent to existing
`FPN_DivNoAssert` template in `FixedPointN.hpp`. Same signature; new
implementation path.

**Determinism gate:** Lemire path bytewise-identical to long-division
path on power-of-2 divisors; within ULP (1 unit in last place) on
non-power-of-2 divisors. Document the ULP tolerance as ACCEPTABLE
divergence per CLAUDE_REVIEW item #5 — slow-path tolerance, not
ML-parity-critical (regime classification is hysteresis-bounded).

**Tests** (+3): scalar reference divmod vs Lemire bytewise on 1000
random divisors; ULP tolerance documented; performance gate (≥30%
faster on benchmark loop).

**Tag:** `v5.12.2.A.3`.
