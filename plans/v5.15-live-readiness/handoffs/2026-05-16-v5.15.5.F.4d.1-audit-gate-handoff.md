## Critical design conversations (for cold-pickup understanding)

### Conversation 1 — Option F (Layer 5b at `.A`)

**Originally drafted:** LOCKED-hash-constant snapshot mechanism per `wire-format-byte-preservation-discipline.md` § 5b v1.0 text. Hash constant computed at ship time; updated manually per cohort migration in `.B` (6+ updates with CHANGELOG entries).

**Caramel's "magic number" pushback** caught the structural problem: LOCKED constant is a Class 18 mirror between source-code-defined hash + runtime walker output. Class 18 latent at hash-constant layer.

**Iterated through:**
- Path A: LOCKED hash constant (rejected — magic number; Class 18 mirror)
- Path C: fixture file as lock (rejected — still registry-of-bytes; "principle beats registry for ELIMINATING")
- Path D: CMake-generated header with hash (rejected — generated-files-in-git smell; still snapshot artifact)
- **Path F (chosen): structural invariant tests** — named assertions encoding canonical body intent at consumer site

**Resolution:** Each wire-format derived filter has a generic invariant runner (I1-I5: line count / format / locale-pin / row presence / canonical order) auto-generated by the framework macro + domain-specific invariants in the consumer header (I6 bitmap-bool ternary normalization; I7 cross-source presence). No magic numbers; no fixture files at `.A`; aligns with existing Layer 4 + `calls_graph_diff` + Check 7 patterns.

### Conversation 2 — β4 (cohort gate dispatch at `.B`)

**Originally drafted:** Option α inline cohort branches in `CFG_DRIFT_AUTOPOPULATE` callback (6 cohorts × ~3 LOC each).

**Caramel's "data-driven, not scared of taking longer" call** identified Class 19/14/18 latent at the inline-branch shape:
- Class 19: hardcoded enum names in callback
- Class 14: future contributor adds 7th cohort but forgets callback branch
- Class 18: registry says cohort via categorical bits but callback has parallel logic

**Iterated through sub-options of β:**
- β1: new column on `CfgFieldDescriptor` (rejected — violates sprint-wide schema lock)
- β2: derive from existing `applies_to_strategy_cat` bits (rejected — conflates two concerns)
- **β4 (chosen): sparse `FOREACH_DRIFT_GATE` sidecar + `DriftGateKind` enum + branchless fn-pointer dispatch table per H20 Pattern 1**

**Resolution:** New `MemHeaders/CfgDriftGate.hpp` lands at `.B` (~80 LOC). Sister to `FOREACH_DRIFT_OVERRIDE` at `.C` (separate concerns: GATE = cohort dispatch; OVERRIDE = custom semantics; per per-concern-separation discipline codified at `sidecar-override-pattern-for-registry-auto-flows.md` Stage 4). 5 cohort gate fns + 15-row sparse registry + 2 sparse arrays + branchless dispatch.

### Conversation 3 — CI tooling simplification (Check 9 → compile-time at `.A`; Check 11/12 dropped)

**Originally drafted:** `.D` ship adds 4 Python CI scripts (Check 9 H16 enforcement; Check 10 cohort eligibility; Check 11/12 placeholders for `.F.4e` GUI metadata).

**Caramel's "avoid CI template if possible" call** identified that Check 9 + Check 11/12 could be simplified:
- Check 9 → **compile-time H16 static_assert at `.A`** (X-macro reduction over `FOREACH_DERIVED_FILTER`; co-located with `MetadataFlag` enum). Strictly stronger: build-fails; can't bypass; aligned with existing codebase X-macro static_assert discipline.
- Check 11/12 → **DROPPED**. Bit reservation for 5 GUI metadata bits at `.D` would force `uint16_t → uint32_t MetadataFlag` upgrade (cache alignment investigation revealed: 2-byte `_reserved` field at `CfgFieldRegistry.hpp:173` already exists; upgrade is byte-equivalent struct size via Option Z2 reorder; safe for Layer 4 fixture round-trip). But the upgrade belongs WITH consumers at `.F.4e`, not orphan-work at `.D`.
- Check 10 → **KEPT** as Python tool at `.D` (per Caramel's "don't defer" directive); cohort eligibility audit is heuristic, not X-macro-reducible.

**Resolution:** `.D` ship scope shrinks ~2-4h → ~1-2h. `.A` ship adds H16 static_assert (Step 5b). `.F.4e` planning has uint32_t upgrade plan pre-documented (Option Z2).

### Conversation 4 — Cache alignment investigation (NOT a fork; just verification)

`CfgFieldDescriptor` has explicit `uint16_t _reserved = 0` field (line 173) intended for future flag headroom. Cleanest upgrade path at `.F.4e`: replace `uint16_t metadata_flags + uint16_t _reserved` with `uint32_t metadata_flags` via small field reorder. **Byte-equivalent struct size; ZERO Layer 4 fixture round-trip risk** (descriptor is runtime metadata, NOT wire-format). Documented in `.D` plan body forward-ref to `.F.4e`.

### Conversation 5 — ManualFieldInventoryEntry categories (`.C` revision)
